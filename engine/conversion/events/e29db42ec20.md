A working proof-of-concept exploit for DirtyDecrypt (DirtyCBC) has been publicly released by the Zellic and V12 security team, targeting a missing copy-on-write guard in the Linux kernel's `rxgk_decrypt_skb()` function. The exploit allows unprivileged local users to gain root by writing to shared page-cache pages belonging to privileged processes or sensitive files (`/etc/shadow`, `/etc/sudoers`, SUID binaries). Confirmed working on Fedora and mainline kernels; Arch Linux and openSUSE Tumbleweed are also vulnerable. Stable enterprise distributions (Debian, Ubuntu LTS, RHEL 8/9) are not affected under standard configurations (RxGK disabled). The same `esp4`/`esp6`/`rxrpc` module blacklist mitigation that protects against Dirty Frag and Fragnesia also covers DirtyDecrypt — but at the cost of breaking IPsec VPN and AFS. Kubernetes operators should note the exploit path enables container escape to full host root on affected nodes.
