Cyera researchers have disclosed a critical heap out-of-bounds read vulnerability in Ollama, the open-source local LLM runtime, tracked as CVE-2026-7482 with a CVSS score of 9.3. The flaw exists in the GGUF model loader and is triggered by processing a malicious model file with declared tensor offsets exceeding the actual file size, causing the server to read past the allocated heap buffer. An attacker can then exfiltrate the resulting file — containing stolen heap data — to a remote server using Ollama's built-in model push feature. The entire attack requires only three unauthenticated API calls. Ollama's default configuration launches without authentication and listens on all interfaces, meaning approximately 300,000 internet-exposed deployments are immediately exploitable. Stolen heap data may contain environment variables, API keys, tokens, developer prompts, code, and PII/PHI. Organizations should update to Ollama 0.17.1, restrict network access with firewalls, and place authentication proxies in front of deployments. Any instance previously accessible from the internet should be treated as compromised.
