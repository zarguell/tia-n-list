A maximum-severity vulnerability in the ChromaDB open-source vector database (14M monthly PyPI downloads) allows unauthenticated attackers to run arbitrary code on exposed servers. The flaw, tracked as CVE-2026-45829 and reported to ChromaDB on February 17, resides in the Python FastAPI server — the Rust frontend is not affected. The vulnerability exploits an authentication-ordering flaw: a vulnerable API endpoint marked as authenticated allows attackers to embed model settings before the authentication check fires. An attacker sends a crafted request forcing ChromaDB to load a malicious model from Hugging Face and execute it locally — by the time the server rejects the request (HTTP 500), the attacker's payload has already run. HiddenLayer researchers have been unable to contact the maintainer since February 17; 73% of internet-exposed instances run a vulnerable version per Shodan telemetry. Mitigations: use the Rust frontend, avoid exposing the Python API publicly, or restrict network access to the API port.
