TeamPCP's supply chain campaign, first documented in yesterday's digest as compromising 84 TanStack npm packages, has expanded dramatically. New analysis by CyberScoop reveals the attack used an "orphaned commit" technique — code pushed to a repository fork without a corresponding branch — to exploit overly broad permissions in GitHub Actions workflows. The malicious updates bypassed two-factor authentication and carried cryptographically valid provenance signatures, exposing a fundamental blind spot: current defenses verify where an update comes from, not whether the code inside is safe. The malware uses the Bun runtime to steal AWS, GCP, Kubernetes, and HashiCorp Vault credentials, embeds persistence hooks in VS Code and Claude Code configuration directories, and exfiltrates via the Session anonymous messaging network. It also self-propagates as a worm, spoofing activity to appear as automated commits from the Anthropic Claude bot. Separately, RubyGems has suspended new package registrations after hundreds of malicious packages were discovered flooding the registry — part of the same coordinated campaign targeting all major package ecosystems. Socket CEO Feross Aboukhadijeh noted: "You can pull a package from the registry, but you cannot automatically pull back the credentials it may have already stolen."
