A critical vulnerability in FreeBSD's default IPv4 DHCP client, dhclient(8), allows any attacker on the same broadcast domain to execute arbitrary code as root by operating a rogue DHCP server. The flaw stems from improper sanitization of embedded double quotes in the BOOTP file field, which gets written into the local DHCP lease file and executed with root privileges when the lease is reprocessed during reboot or network service restart. Discovered by Joshua Rogers of AISLE Research Team, the vulnerability affects all supported FreeBSD branches (15.0, 14.x, 13.5). The FreeBSD Project has released patches; administrators should update immediately via `pkg upgrade -r FreeBSD-base` (15.0) or `freebsd-update fetch && freebsd-update install` (other versions). Organizations should also implement DHCP snooping on managed switches to block rogue DHCP responses. Systems not using dhclient(8) are unaffected.
