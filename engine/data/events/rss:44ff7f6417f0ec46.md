TL;DR GitHub’s own runners do the scanning: React2STEAL uses GitHub Actions runners in hijacked accounts to scan for vulnerable Next.js servers and exploit React2Shell (CVE-2025-55182) and CVE-2025-29927. Stolen .env files land in public repos: On each compromised server, it collects environment variables, .env files, cloud and Kubernetes credentials, and AI provider keys. It then commits the stolen data to public GitHub repositories. Every reachable secret counts as exposed: Victims need to treat every secret their server process could access as exposed. GitHub account owners also need to revoke the credentials that allowed the attacker access. On Nov. 18, OpenSourceMalware published research on a campaign it named React2STEAL. They identified 45 repositories across 44 GitHub accounts that are actively running GitHub Actions workflows that scan the internet for vulnerable Next.js servers. Once a server is compromised, the stolen credentials are committed to public GitHub repositories. This is a perfect storm of attackers leveraging multiple factors against their targets: the vulnerabilities have been known for many months, the attacker is using someone else's infrastructure, and the stolen credentials are available to anyone who finds the repositories. The GitHub accounts behind the campaign have also appeared in earlier attacks. You can find the full research here .
