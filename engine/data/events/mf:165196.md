A newly documented Windows process injection technique can place and execute payloads inside a console application without calling the heavily monitored WriteProcessMemory and VirtualAllocEx APIs. The approach, dubbed console named-pipe injection, abuses redirected standard input to place attacker-controlled bytes into a child process’s memory before changing page protections and hijacking execution flow. Traditional remote process injection typically follows a highly recognizable sequence: an attacker opens a target process, allocates memory remotely with VirtualAllocEx , copies a payload using WriteProcessMemory , and starts or redirects a thread to execute the injected code. New Windows Process Injection Technique Because this allocate-write-execute pattern is widely abused, EDR platforms commonly generate high-confidence telemetry when these APIs are used across process boundaries. MITRE ATT&CK tracks the broader activity as Process Injection, technique T1055.
