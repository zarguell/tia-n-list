TL;DR What it is : SOPS encrypts the values inside YAML, JSON, ENV, and INI files and leaves key names readable, so encrypted secrets can live in Git. Key stores : AWS KMS, GCP KMS, Azure Key Vault, HuaweiCloud KMS, age, and PGP, plus HashiCorp Vault/OpenBao, with rules in .sops.yaml routing each file to the right key. What and when to use : age for local development and CI, cloud KMS or Vault for production, where IAM policies decide who can decrypt. Automation : GitHub Actions, Flux CD, helm-secrets, and KSOPS decrypt at build or reconcile time, so no plain text secret is committed. The limit : SOPS is not a secrets manager. Pair it with one for runtime access, and with secrets detection for leaks outside encrypted files. What Is SOPS? First, let's cut to the chase and address the elephant in the room: what is SOPS? Because an image is worth a thousand words, here it is illustrated (kudos to @sec_r0 for the artwork): Click to get the full-res PDF. SOPS, widely known as Mozilla SOPS, is an encrypted files editor. It handles encryption, decryption, and editing in one tool. The encryption keys stay in a key store of your choice: PGP (Pretty Good Privacy) / GnuPG, age, Amazon Web Services Key Management Service (AWS KMS), Azure Key Vault (Azure KMS), Google Cloud KMS, HashiCorp Vault / OpenBao, and HuaweiCloud KMS.
