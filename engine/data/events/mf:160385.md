A newly disclosed SQL injection vulnerability in GeoServer could allow unauthenticated attackers to access backend PostgreSQL databases and, in high-risk configurations, execute operating-system commands on database hosts. The issue affects GeoServer deployments using PostGIS-backed layers and originates in GeoTools, the library responsible for converting Common Query Language (CQL) filters into SQL queries. Research published by Melvin Lammerts after an August 12 disclosure by researcher @q1uf3ng found that the vulnerable jsonArrayContains filter function can place attacker-controlled data directly into a PostgreSQL jsonb_path_exists() expression. GeoServer SQL Injection Vulnerability The vulnerable behavior stems from GeoTools’ FilterToSqlHelper.java , where the jsonArrayContains implementation builds SQL using Java string formatting rather than safely parameterizing user input. The affected function was introduced to support PostgreSQL 12 and later JSON path capabilities. However, the attacker-controlled comparison value is inserted into a nested JSONPath expression without suitable escaping. This lets a malicious CQL filter break out of the intended SQL context and alter the resulting database query. Most GeoTools filter functions use parameterized statements, but JSONPath handling led developers to use string construction.
