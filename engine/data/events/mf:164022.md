Docker has released security fixes for two serious vulnerabilities in Docker Sandboxes that could allow a malicious guest environment to break workspace isolation and reach sensitive host-side resources. The flaws, tracked as CVE-2026-77179 and CVE-2026-79994, were fixed in Docker Sandboxes version 0.42.0, released on September 7. Docker Sandboxes isolate development agents, automated workflows, and untrusted workloads while allowing selective access to a host workspace. Critical Docker Sandboxes Flaw However, both newly disclosed issues stem from a time-of-check-to-time-of-use (TOCTOU) weakness involving filesystem path validation. In both cases, Docker Sandboxes validated that a requested pathname belonged to an approved shared workspace. A malicious process inside the sandbox could then alter part of that path, such as by replacing a directory with a symbolic link, before the host performed the subsequent file or socket operation. CVE-2026-77179 is the most severe issue and carries a Critical severity rating. It affects Docker Sandboxes versions 0.28.0 through versions prior to 0.42.0 on macOS. The vulnerability exists in the macOS virtio-fs host server, which could incorrectly follow symbolic links when reopening an unlinked file using a previously stored path. An attacker controlling code within a guest sandbox could race the host operation by replacing a parent directory after the original path had passed authorization checks.
