A newly disclosed AI security threat dubbed Workflow Identity Hijacking could let attackers extract sensitive enterprise data by submitting ordinary requests through public-facing channels such as support inboxes, web forms, GitHub issues, or shared documents. Unlike prompt injection attacks , the technique does not require adversaries to manipulate, jailbreak, or override a large language model’s instructions. Instead, it exploits a broken authorization boundary between an untrusted person who influences an AI workflow and the privileged identity the workflow uses to execute downstream actions. AI Workflow Identity Hijacking Security researchers at Noma Labs described a scenario in which an attacker sends a benign email to a company’s public support address asking for quarterly sales figures from the Finance Director’s latest email. The AI workflow receives the request, searches the internal mailbox using its configured permissions, and sends the answer back externally. The workflow behaves exactly as designed. The failure is that the external requester was never authorized to access the information.
