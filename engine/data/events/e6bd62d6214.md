A critical SQL injection vulnerability in ProFTPD's `mod_sql` extension allows pre-authentication remote code execution, authentication bypass, and privilege escalation. The flaw stems from how `mod_sql`-based logging handles `%` expansions (e.g., `%U` for username) in `SQLNamedQuery` directives — values beginning and ending with single quotes bypass SQL escaping entirely. An attacker can inject arbitrary SQL via a crafted `USER` command before ever authenticating. When ProFTPD connects to PostgreSQL with superuser privileges, the injection enables full RCE. ZeroPath estimates at least 1% of publicly accessible ProFTPD instances are vulnerable to pre-auth attacks. ProFTPD is bundled with cPanel, Plesk, DirectAdmin, ISPConfig, and Webmin, making this a significant supply-chain risk for shared hosting environments. Patch available in ProFTPD 1.3.9a (released April 27).
