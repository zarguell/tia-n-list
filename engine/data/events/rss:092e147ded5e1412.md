Threat actors have started targeting the recently disclosed Java4Shell vulnerability, as more vendors publish advisories detailing the flaw’s impact on their products. Tracked as CVE-2026-114938, Java4Shell is a memory corruption bug in the way OpenJDK 17.0.6 and newer handle Base64 data. Exploitation requires an x86-64 processor supporting AVX-512 VBMI, a feature found in newer Intel and AMD CPUs. ARM-based systems are not affected. Calif disclosed the bug on November 17, the same day Oracle and the OpenJDK project released patches. Calif said it achieved unauthenticated remote code execution (RCE) against the default configurations of Jira, Confluence, Jenkins, Keycloak and other enterprise applications. However, it noted that no single exploit works against all of them, and that each needs a tailored attack chain.
