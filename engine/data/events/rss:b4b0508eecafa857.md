Executive Summary Java4Shell (CVE-2026-114938) is a critical memory-corruption vulnerability in OpenJDK’s Base64 decoder. The researchers who found it rate it 9.2 under CVSS v4.0, and Oracle rates it 8.1 under CVSS v3.1. An attacker with no credentials can corrupt Java heap memory, read secrets from it, and reach remote code execution. Researchers demonstrated pre-authentication RCE on default installations of Keycloak, Jira, Confluence, Artifactory, Jenkins, and PingFederate. Unpatched OpenJDK builds from 17.0.6 onward, from any vendor, are affected when they run on x86-64 processors with AVX-512 VBMI, which includes Intel Xeon from Ice Lake through Granite Rapids and AMD EPYC from Zen 4 onward. Oracle released fixes on November 17, 2026, and a single JVM flag closes the exposure where patching has to wait. CISA has issued an alert urging organizations to patch immediately. Start with internet-facing identity, CI/CD, and collaboration systems, and assign an owner and a deadline to every system still unpatched. What’s at Risk A Critical Java Flaw Could Hand Attackers Your Identity and Build Servers. Java4Shell is in the Java runtime itself, so no application or library has to be at fault for a service to be exposed. The flaw sits in handwritten assembly that speeds up Base64 decoding with AVX-512 instructions.
