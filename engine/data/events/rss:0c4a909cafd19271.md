TL;DR Signatures aren’t enough: Signature checks via OIDC cover only 15% of leaked JWTs, and a valid signature names neither the service that issued a token nor whether that token still works. Attribution: 345 rules matched 86% of about 2.4 million tokens to a named service. Validation: Replaying each token against its service’s own API found 334,762 tokens still valid at check time. Detection coverage: GitGuardian now detects JWTs from 14 services and validates some of them. LinkedIn JSON Web Tokens (JWTs) leak more every year: the number found in public GitHub repositories doubled between 2025 and 2026. We traced leaked JWTs back to 345 services and got a definitive answer for 75% of attributed tokens. The first half of this post is hands-on. We take a Google id_token and validate it one command at a time, using curl , jq , openssl , and a few lines of Python. Each step shows the command and its output, so you can replay it on your own tokens. The second half shows how we scaled that process to 2.4 million leaked JWTs. JWT state of the art JWTs are a compact and widely used way of transmitting data between two parties. They sit at the center of authentication protocols such as OpenID Connect (OIDC), and they keep leaking, mostly in GitHub repositories. Counting those leaks, however, says little on its own.
