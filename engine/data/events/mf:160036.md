A newly identified version of the Kimwolf botnet is making distributed denial-of-service attacks harder to detect by making malicious traffic look like ordinary Chrome browser activity. Known as Kimwolf v7, the Android and IoT malware adds an HTTP/2 flood capability that builds browser-like request fingerprints, making it more difficult for defenders to separate attack traffic from real users. Kimwolf mainly targets Android TV boxes and set-top boxes. It is linked to the wider AISURU botnet operation, which initially focused on Linux IoT devices in 2024 before shifting toward Android-based targets in 2025. Researchers identified the v7 variant on February 3, 2026, following public reporting from several security organizations. The latest build focuses less on spreading and more on staying online and launching more effective DDoS attacks . It removes earlier scanner, exploit and brute-force components, suggesting that separate tools or loaders now handle initial infection while Kimwolf runs the botnet’s attack and command functions. Kimwolf Spoofs Chrome Fingerprints Kimwolf v7 includes a new HTTP/2 flood method built with the nghttp2 library. Unlike basic request floods, this method creates a fuller set of browser headers designed to resemble Chrome traffic . This can make automated filtering more challenging because the malicious requests may look similar to normal browser sessions at the protocol and header level.
