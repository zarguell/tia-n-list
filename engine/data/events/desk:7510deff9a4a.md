The vendor advisory behind CVE-2026-128138, published on GitHub on 2026-11-15 and credited to reporter kokomaru167, documents that the 3.10.3 remediation validates the options channel but appends the caller-supplied cmd list to the JVM command without checking that its first item is a Java main class. Two reachable paths are confirmed against the official nltk-3.10.3 wheel: nltk.internals.java(cmd=["-jar", external_jar]) and StanfordSegmenter(java_class="@argfile"), each executing a controlled external JAR in 3 of 3 runs while the same argfile token is rejected through options with a ValueError citing CVE-2026-12841 and CWE-88. Affected range is exactly 3.10.3 and the patched version is 3.10.4, with the note that importing NLTK alone is not remotely exploitable and that a child JVM runs with the privileges of the Python process.
