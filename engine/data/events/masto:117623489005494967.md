New version of KeePassXC (2.8.0): plenty of new features and fixes for serious security bugs (CVE-2026-69150). KeePassXC is a popular open source password manager that lets you safely store credentials on both Windows, Linux and macOS systems. It also integrates relatively easily with the most popular web browsers such as Mozilla Firefox, Google Chrome, Microsoft Edge, Chromium and Tor. What is more, it enables automatic filling of access data, which can serve as an additional line of defense against phishing attacks.

TLDR: KeePassXC has released a new version, 2.8.0, which introduces many changes and fixes. Bugs related to memory handling, browser integration and the handling of SSH keys stored in shared memory have been fixed. A number of new features have been deployed: remote database synchronization, the ability to generate SSH keys, autofill support in the Wayland environment, an improved password strength evaluation mechanism, better Passkey support and a new GUI based on Qt 6. A few days ago the software received a big update (to version 2.8.0), which brought a number of changes and fixes. Some of them fix serious security bugs related to database import, browser integration or SSH key handling. One of them received the identifier CVE-2026-69150, and further ones (four in total) are awaiting the assignment of CVE numbers.

The CVE-2026-69150 flaw occurs in the already old importer of KeePass 1 (.kdb) databases. The problem was that the application kept outdated pointers to entries in memory after metadata streams were deleted. As a result, an attempt to import a specially crafted .kdb file could result in the parseCustomIcons4() function being called on an already released area of memory, leading to a heap use-after-free vulnerability. The result? An immediate application crash, and in the worst case a theoretical possibility of arbitrary code execution (RCE), although at the moment no PoC has been presented. Other bugs detected in the same module were related to memory operations. Among them were an integer overflow and an out-of-bounds read (reading data outside the allocated memory buffer).

Further security bugs occurred in the module integrating the software with the browser, and more precisely in the way messages are exchanged (native messaging) between the plug-in and the main application. Due to the fact that browsers operate in an isolated environment, the KeePassXC plug-in has no direct access to the operating system. In order to be able to safely retrieve passwords from the KeePassXC program, it uses the native messaging mechanism - a special process is launched in the background, which mediates in sending encrypted messages. During encryption and decryption of messages KeePassXC allocates an appropriate buffer in RAM memory. The error was incorrect verification of the size of the processed packets, as a result of which the function wrote data outside the reserved memory area, thus overwriting adjacent cells (out-of-bounds write). In practice, the bug could lead to an application crash or to potential execution of malicious code (although this has not been confirmed).

It is worth paying attention to one more bug, related to the processing of SSH keys in the Windows version. The problem concerned integration with the SSH agent - Pageant. When passing a private key, KeePassXC used quite predictable names for the shared memory area (shared memory mapping) in which the key was saved. A potential attacker (another malicious process operating in the system with user privileges) could try to recreate the name of the allocated memory (especially if it was based on a constant pattern), and then read the data stored in it. As a result, a leak of the private SSH key could occur. The bug was fixed by randomizing a unique name of the shared memory each time. Thanks to this, no local process is able to predict where sensitive information is located in memory.

The Polish-language report covers the 2.8.0 release and the CVE-2026-69150 heap use-after-free in the KeePass 1 (.kdb) importer, plus an out-of-bounds write in native messaging and a predictable shared-memory name in Pageant integration. No proof of concept has been published for CVE-2026-69150.
