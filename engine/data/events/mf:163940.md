A critical vulnerability in the Issabel Framework could allow unauthenticated remote attackers to execute arbitrary operating-system commands on affected Issabel PBX deployments by exploiting a hard-coded JSON Web Token signing key. Tracked as CVE-2026-89026, the vulnerability affects Issabel Framework versions prior to commit b97dbaf0b71c1c36f841e672b664afbeb02773bd . The issue carries a CVSS v4 score of 9.3 and is classified as CWE-321, “Use of Hard-coded Cryptographic Key.” Issabel is an open-source unified communications and PBX platform built around Asterisk. Its Framework component provides web-facing management capabilities, including APIs used to interact with PBX functions. Issabel PBX JWT Key Flaw According to the vulncheck , the affected pbxapi/index.php implementation contained a hard-coded HS256 key used to sign and validate JWT bearer tokens. Because every vulnerable installation embedded the same signing key, an attacker could create a JWT the affected PBX API would accept as legitimate. This removes the need for valid Issabel credentials, a local foothold, or user interaction. The forged token can then be used against the framework’s pbxapi/manager/originate endpoint. That endpoint is intended to create call origination requests through Asterisk Manager Interface functionality.
