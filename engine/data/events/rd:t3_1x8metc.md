Every npm compromise alert starts the same way: someone greps the lockfile, and the room either panics or relaxes. Both reactions are premature. The lockfile tells you the bad version can resolve in your tree. It says nothing about whether a machine fetched it, and less about whether it ran. The questions that matter come after. Did any CI job install while that version was pinned? git log -S on the lockfile brackets your window, and npm ci installs exactly what the lockfile says. Did it execute? For install-time payloads that hinges on whether pipelines ran with --ignore-scripts, and teams set that flag in one pipeline and forget the other three.
