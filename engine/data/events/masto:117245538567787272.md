Opened a regular VBS file and found PowerShell, AES encryption, and MSBuild inside. A routine .vbs file landed in my hands. Nothing unusual at first glance. Upon opening it, the script turned out to be a multi-stage loader: the VBS dropper unpacks an encrypted PowerShell payload, decrypts it using AES, and then invokes MSBuild to compile and execute the final stage in memory. The use of MSBuild as a living-off-the-land binary allows the payload to bypass application whitelisting and script execution policies. This technique has been observed in multiple malware families since 2023 and continues to be effective in environments that do not monitor MSBuild invocations. The article walks through the deobfuscation steps and identifies the C2 communication pattern embedded in the final payload.
