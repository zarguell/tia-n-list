WordPress fixes a critical vulnerability (CVE-2026-87902). Several WordPress versions were affected by a critical flaw that could lead to remote code execution, and administrators now have a corrective update available. WordPress published version 7.1.2 of its CMS on September 22 to fix the critical vulnerability tracked as CVE-2026-87902, rated 9.2 out of 10 under CVSS 4.0. The flaw lies in page template resolution and can let an unauthenticated attacker cause the inclusion of a local PHP file readable by the server; in certain configurations that chain can end in remote code execution.

The vulnerability was found by security researcher Robert Ressl, who reported it to WordPress via HackerOne. His analysis, published after the fix shipped, details the exploitation conditions along with a laboratory proof of concept, though he did not test the chain against production WordPress sites. The problem sits in the get_page_template() function, which WordPress uses to determine which PHP template renders a page. Data taken from the request can, after several processing and decoding steps, be used to build a file path that escapes the theme's intended template directory, and reaching this functionality requires no WordPress account, session, or authentication token.

Exploitation is not automatic for every installation. The active theme must expose a directory structure that permits this template-resolution path, and a PHP file readable by the web server account must be available to turn the local inclusion into code execution. In his lab, Ressl used pearcmd.php, a PEAR component present in some PHP environments, and the resulting code ran with the web server account's rights, not system administrator privileges. He tested on WordPress 7.0.2 in isolated environments and notes his work says nothing about how many sites actually meet the required conditions.

WordPress backported the fix across all branches still receiving security updates, with corrected versions spanning 4.7.37 through 7.1.2; WordPress 4.6 and older no longer receive security fixes. Beyond the identified attack path, the patch adds a check that resolved templates stay inside the permitted directories, chiefly in wp-includes/template.php. CERT-FR issued an advisory on September 23 classifying the risk as remote arbitrary code execution and recommends applying the WordPress fixes. According to Patchstack, exploitation attempts began within hours of the update's release, with attack sequences probing whether the required conditions held before attempting to write PHP files to vulnerable servers. Administrators should install 7.1.2 or the corresponding branch fix immediately; checking PHP settings and files reachable by the web server account can narrow some exploitation routes but does not replace patching.
