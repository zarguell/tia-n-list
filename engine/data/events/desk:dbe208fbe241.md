The researcher publishing as MSNightmare created this repository on November 10, 2026 with the description 'Windows Common Log FileSystem Authentication 0day Local Privilege Escalation Vulnerability.' The write-up explains the flaw in clfs.sys: when a standard user creates a log and a privileged process is later coerced to open it, CLFS creates the missing .cnpf authentication (HMAC) file under the privileged context, and the file inherits the original DACL, yielding a SYSTEM shell. The PoC coerces Windows Defender to open the container via ServerMpUpdateEngineSignature, ships C++ source with a Visual Studio project, and was tested on Windows 11 26H2, 26H2 Experimental, and Windows Server 2025 Experimental. It notes the CLFS authentication mitigation rolled out on or after October 28, 2025, and gives a registry check at HKLM\SYSTEM\CurrentControlSet\Services\CLFS\Authentication\Mode where values 0 or 1 are vulnerable and 2 or 3 are not.
