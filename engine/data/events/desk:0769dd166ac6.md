Datadog Security Labs published the first public technical reproduction on November 11, 2026, one day after the vendor advisory. The team built a four-member replica set from official MongoDB Linux x86_64 binaries, planted two unauthenticated ping requests carrying readConcern.afterOpTime values as stale replication waiters, then triggered a failover so the behind member became primary. On MongoDB 8.0.34 the member exited catch-up twice in one millisecond, logged "Invalid access at address: 0" and "Got signal: 11 (Segmentation fault)" with a backtrace in CatchupState::abort_inlock(), and the mongod process crashed. The patched 8.0.37 run rejected the same unauthenticated requests with Unauthorized, the unpatched control run without planted requests stayed up, and the researchers did not achieve code execution.
