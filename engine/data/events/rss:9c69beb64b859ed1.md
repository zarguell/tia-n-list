Key Takeaways Public Amazon Machine Images (AMIs) speed up deployment, but anyone can publish one, so they should never be trusted based on their name or description alone. Malicious or misconfigured AMIs can carry vulnerable software, embedded malware, exposed credentials, or insecure configurations that compromise workloads as soon as they launch. The whoAMI attack, disclosed by Datadog Security Labs, shows how attackers can publish look-alike images that get picked up by pipelines that don’t verify the AMI owner. A single compromised source image can spread through Golden AMIs to every account, region, and workload built from it, and images that aren’t rebuilt regularly drift out of date. Validating image owners, rebuilding Golden AMIs regularly, using AWS Allowed AMIs, and continuously monitoring with Qualys TotalCloud help keep malicious and misconfigured images out of production. Introduction A developer or CI/CD pipeline searches for an Amazon Machine Image (AMI) using a familiar image name. If the workflow does not verify the image’s owner, it may select a malicious image that resembles a trusted one. This is the risk highlighted by Datadog Security Labs’ whoAMI research: an image-selection mistake can introduce a supply chain compromise before an application even starts running.
