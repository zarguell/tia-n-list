Microsoft has confirmed that a SharePoint Server vulnerability originally logged as a low-severity spoofing issue is, in fact, a high-severity remote code execution flaw that low-privileged, authenticated attackers can exploit to run arbitrary code on affected servers. The vulnerability, tracked as CVE-2026-65660, carries a CVSS score of 8.8 and stems from a code-injection weakness (CWE-94) in how SharePoint validates server-side controls against its SafeControls allowlist. Researcher Dinh Ho Anh Khoa of Viettel Cyber Security published details on September 22, 2026, showing that the root cause lies in ToolPane. Microsoft SharePoint Flaw GetPartPreviewAndPropertiesFromMarkup(), a function that parses Web Part markup submitted through pages such as AddGallery.aspx. SharePoint separates incoming markup into a “Register” block and a “Tag” block, verifying each independently with EditingPageParser.VerifyControlOnSafeList(). The flaw sits in the RegisterDirective.GetHtml() method, which writes attribute values into the reconstructed markup without escaping embedded quote characters. Because an attacker can smuggle unescaped double and single quotes inside an attribute like Src, they can break out of the intended directive and inject a second, attacker-controlled Register directive containing an arbitrary .NET namespace, splitting the payload across both markup blocks so that neither individual check catches the full malicious string.
