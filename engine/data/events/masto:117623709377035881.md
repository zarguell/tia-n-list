KeePassXC 2.8.0 has been released with a large set of changes and fixes for serious security bugs (CVE-2026-69150).

KeePassXC is a popular open source password manager that safely stores credentials on Windows, Linux and macOS. It integrates easily with the most common browsers, including Mozilla Firefox, Google Chrome, Microsoft Edge, Chromium and Tor, and it can autofill credentials, which adds a further line of defense against phishing.

TLDR: KeePassXC has published a new version, 2.8.0, which brings many changes and fixes. The release repairs bugs related to memory handling, browser integration and the handling of SSH keys stored in shared memory. It also ships a number of new features: remote database synchronization, SSH key generation, autofill support in Wayland environments, an improved password strength estimator, better passkey handling and a new Qt 6 GUI. A few days ago the software received a large update to version 2.8.0 with a set of changes and fixes. Some of them address serious security vulnerabilities related to database import, browser integration and SSH key handling. One of them was assigned the identifier CVE-2026-69150, and another four are awaiting CVE assignment.

CVE-2026-69150 affects the already aged KeePass 1 (.kdb) database importer. The problem was that the application kept stale pointers to entries in memory after metadata streams were deleted. As a result, importing a crafted .kdb file could cause the parseCustomIcons4() function to be called on already freed memory, leading to a heap use-after-free vulnerability. The effect is an immediate application crash and, in the worst case, a theoretical possibility of arbitrary code execution, although no proof of concept has been presented. Other bugs found in the same module were related to memory operations: an integer overflow and an out-of-bounds read.

Further vulnerabilities concerned the module that integrates the software with the browser, and more precisely the way messages are exchanged (native messaging) between the extension and the main application. Because browsers run in an isolated environment, the KeePassXC extension has no direct access to the operating system. To let it safely fetch passwords from KeePassXC, native messaging is used, with a helper process running in the background to relay encrypted messages. During encryption and decryption KeePassXC allocates a buffer in RAM. The bug was that the size of the processed packets was not verified correctly, so the function wrote data beyond the reserved memory area and overwrote adjacent cells, an out-of-bounds write. In practice the flaw could lead to an application crash or to potential code execution, although that has not been confirmed.

One more bug worth attention is related to handling SSH keys on Windows, specifically the integration with the Pageant SSH agent. When handing over the private key, KeePassXC used fairly predictable names for the shared memory mapping where the key was written. A potential attacker, meaning another malicious process running in the system with user privileges, could try to reconstruct the name of the allocated memory, especially if it relied on a fixed pattern, and then read the stored data. The consequence could be a leak of the private SSH key. The flaw was fixed by generating a unique random name for the shared memory on every use, so no local process can predict where the sensitive data resides in memory.

Besides the fixes, KeePassXC 2.8.0 adds remote database synchronization, SSH key generation, Wayland autofill support, passkey improvements and a Qt 6 interface.
