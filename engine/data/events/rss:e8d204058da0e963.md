TL;DR Coding agent security extends beyond generated code: Agents can read local files, use credentials, call APIs, and interact with systems that may never appear in a diff. Reach determines blast radius: A forgotten or over-scoped credential can give an agent far more authority than the task requires. Written rules need technical enforcement: Policies and rules files help shape agent behavior, but team-wide security needs boundaries that still hold when the model makes the wrong decision. AppSec needs a team-level approach: It’s important to understand how to evaluate agent risk and standardize protections without making developers solve the problem alone. Developers pushed 1.94 billion commits to public GitHub in 2025 , up 43% year over year. Coding agents are contributing to that acceleration, while also giving security teams new ways to review code at scale. But code review only sees what makes it into code. A coding agent running on a developer machine may also have access to environment variables, cloud configuration, shell history, local credentials, Model Context Protocol (MCP) configurations, and the tools connected to its session. It can read information, make decisions, and act on systems before anything reaches a pull request. For AppSec teams, that changes what needs to be secured.
