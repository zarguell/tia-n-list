Binary Ninja’s Time Travel Debugging integration is amazing . A common question I get asked is why you have to install WinDbg from within Binary Ninja instead of using an existing version from the Microsoft Store. The short answer is that the WinDbg DLLs in C:\Program Files\WindowsApps cannot be loaded by binaryninja.exe . But why not? Binary Ninja’s TTD integration uses Microsoft’s debugging engine. When we replay a trace, our debugger loads DLLs shipped with WinDbg, including dbgeng.dll , dbghelp.dll , dbgcore.dll , and dbgmodel.dll . This gives us WinDbg’s TTD backend inside Binary Ninja’s debugger UI. Modern WinDbg is distributed as an MSIX package through the Microsoft Store. On one of my test systems, its package was installed here: C:\Program Files\WindowsApps\ Microsoft.WinDbg_1.2606.22001.0_arm64__8wekyb3d8bbwe The package even contained the x64 debugging engine we needed: C:\Program Files\WindowsApps\ Microsoft.WinDbg_1.2606.22001.0_arm64__8wekyb3d8bbwe\ amd64\dbgeng.dll When I was originally developing the TTD integration, I tried to have binaryninja.exe load those DLLs directly.
