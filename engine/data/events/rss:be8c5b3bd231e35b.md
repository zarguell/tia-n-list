Threat actors are exploiting an unpatched vulnerability in the open source anti-CSRF library Idunno AntiCsrf for remote code execution (RCE), security researchers warn. AntiCsrf is a legacy ASP.NET module for WebForms applications that has no active maintainer and is no longer actively supported. The most recent version, 0.9.1 Beta, was released in December 2008. Tracked as CVE-2026-131914 (CVSS score of 9.3), the exploited security defect is described as an insecure deserialization bug in the processing of HTTP POST requests to ASP.NET WebForms endpoints. “Exploitation requires only a single HTTP POST request with no prior authentication or valid CSRF token. Active exploitation in the wild has been observed,” Google Cloud’s Mandiant warned on November 18. The flaw allows an attacker to supply any non-empty value in the CSRF cookie along with a Base64-encoded gadget chain to gain RCE in the context of the IIS worker process, Mandiant notes. According to preemptive cybersecurity firm WatchTowr, the issue exists because AntiCsrf does not perform sufficient checks on data from incoming form submissions before reconstructing it into program objects. “The vulnerable check runs before the application’s own page logic, so it can affect many pages on an affected site, not just ones that use a login form.
