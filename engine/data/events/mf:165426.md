A newly disclosed high-severity OAuth vulnerability in Anthropic’s official Model Context Protocol (MCP) Python SDK could allow a malicious MCP server to steal authentication material and take over user accounts. The flaw affects HTTP-based MCP clients using vulnerable SDK releases and OAuth providers, enabling attackers to obtain client secrets, authorization codes, and PKCE proof keys. The issue stems from a weakness in the SDK’s OAuth discovery logic. When an MCP client connects to a server requiring authentication, it must discover the legitimate authorization server and validate its identity before sending sensitive OAuth data. MCP Python SDK OAuth Flaw In vulnerable versions, an attacker-controlled MCP server can intentionally return a 404 response during modern authorization-server discovery, forcing the SDK into an unsafe fallback path. On that path, the SDK accepts OAuth configuration supplied directly by the MCP server without validating the authorization server’s issuer. The attacker can provide metadata that claims to belong to a legitimate identity provider, such as Okta, Google, or Microsoft Entra ID , while specifying an attacker-controlled token endpoint. The attack is particularly deceptive because the victim can still be shown a real login page hosted by the legitimate identity provider.
