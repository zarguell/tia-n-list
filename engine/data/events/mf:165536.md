A newly disclosed Linux kernel out-of-bounds write vulnerability, tracked as CVE-2026-72018, can be leveraged by a local attacker holding CAP_NET_ADMIN privileges to escalate to root. The flaw affects the DIBS loopback implementation used by the Shared Memory Communications Direct (SMC-D) subsystem and has received a CVSS 3.1 score of 7.8, rated High. The issue stems from a missing bounds check in the dibs_loopback driver’s move_data() routine. Linux Kernel Out-of-Bounds Write Flaw The vulnerable function copies data to a Direct Memory Buffer (DMB) through memcpy() but does not validate whether the supplied offset plus write length remains within the allocated DMB boundary. Shared Memory Communications (Source: xbow) SMC is an IBM-designed protocol intended to reduce data-copy overhead for high-throughput connections. While SMC-R uses RDMA-capable hardware, SMC-D is designed for shared-memory communication. Historically, SMC-D was closely associated with IBM Z environments and specialized ISM hardware, limiting routine audit coverage. The introduction of the dibs_loopback virtual transport, however, made relevant SMC-D paths reachable on standard x86 Linux systems without dedicated hardware. XBOW researchers found that attacker-controlled fields in the SMC Connection Layer Control handshake could influence buffer offset calculations.
