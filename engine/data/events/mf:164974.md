Cloudflare has remediated a cross-tenant data exposure vulnerability in its Containers platform that could have allowed one customer’s workload to recover residual disk data belonging to other customers sharing the same physical host. The flaw also affected Cloudflare Sandboxes and Browser Run, both of which rely on the same underlying Containers disk implementation. Security researcher Oren Yomtov of Accomplish responsibly disclosed the issue through Cloudflare’s HackerOne bug bounty program on September 4, 2026. Cloudflare Sandbox Escape Flaw Cloudflare said it found no evidence of malicious exploitation or customer data compromise after reviewing retained disk-I/O telemetry, and it completed fleet-wide remediation without requiring customer configuration changes. The issue was not a conventional container breakout or Firecracker microVM escape . Instead, it originated in the way Cloudflare provisioned storage for container root disks. Cloudflare runs every Container in a dedicated Firecracker microVM and presents its writable root disk as /dev/vdc . The platform uses Linux device mapper thin provisioning, known as dm-thin, to assign physical storage only when a virtual disk writes to an unmapped region. The affected pools used 64 KiB thin-provisioning blocks. A configuration setting, skip_block_zeroing , prevented dm-thin from clearing a newly allocated physical block before exposing it to a new container.
