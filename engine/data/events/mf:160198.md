A newly demonstrated “ Bring Your Own EDR ” attack can turn a legitimate SentinelOne endpoint agent into a privileged Trojan horse on Windows. Documented by Akamai, the technique abuses exposed administrative interfaces and trust relationships within the EDR stack to access Protected Process Light (PPL) processes and to execute unsigned code without a kernel exploit or a vulnerable driver. Presented at DEF CON 34 , the findings highlight a troublesome reality for defenders: endpoint security tools operate with exceptional privilege, making insecure local interfaces and weak installation assumptions unusually high-impact attack surfaces. Bring Your Own EDR Attack Weaponizes SentinelOne Akamai said the reported SentinelOne issue was fixed in Agent version 26.1.1. Windows Protected Process Light is designed to stop ordinary processes from reading, modifying, debugging, or terminating security-sensitive processes. Antivirus and EDR products commonly use the Antimalware-Light signer level, while components such as LSASS rely on related PPL protections. The research focused on exposed interfaces in the SentinelOne Component Object Model (COM). Shahak Morag identified the SentinelHelper.1 interface and a Dump method that could create process dumps for a supplied process identifier.
