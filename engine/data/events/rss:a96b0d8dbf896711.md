MCP Everything I've now tried building out several MCP's for tools that didn't have one, but had a CLI or a well documented API. This one is hard to screenshot, since an MCP isn't very visual, so instead i'll throw down some notes on how this has been. Difficulty - Generally, very easy. All you need is public documentation, any decent LLM and a valid API key, just throw it all into Claude and ask it to build you an MCP. Requires almost zero knowledge of how MCP should be structured or how it works. Caveats - Many. Though the MCPs generally "work" fine in the pure sense. There are many caveats that need to be modified as you go if you entirely vibe coded it. There often ends up being too many tools for your use case, or too many tools that lack good descriptions of how/when to use them. The tools are functional, but often end up being called at the wrong times by the LLM, leading to wasted API tokens and rabbit holes. Workarounds - Also many. I often now add MCP tools one-by-one as they're needed for my use cases. So I know exactly what the MCP contains, and exactly what API's it's using.
