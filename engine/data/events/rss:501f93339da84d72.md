Threat actors started exploiting a new zero-day vulnerability in N-able N-central hours after a disgruntled security researcher released it publicly. Dubbed 4EverAble2Shell, the security defect could allow unauthenticated attackers to gain remote code execution (RCE) with root privileges on N-central servers running the latest patches. The zero-day was dropped on GitHub by security researcher Sean Bales two days after N-able rolled out fixes for several other unpatched flaws he released publicly over the weekend . 4EverAble2Shell, Bales says, chains an exploit for a recent Apache Axis vulnerability ( CVE-2026-90436 , CVSS score: 9.8) with an exploit for an unspecified security hole in N-central deployments that have Legacy API enabled. The exploit chain targets the Axis bug to achieve RCE, and then attempts to elevate privileges to root and run a shell script. According to Bales, the exploit chain works against N-central servers that have been updated this week to 2026.4 HF2 (build number 2026.4.1.26), which contains fixes for the previously released Able2Shell zero-days. N-able reacted immediately to the new zero-days and restricted certain N-central features and integrations, including Legacy API and Intune integration. “Through our ongoing investigation today, we have identified additional indicators of compromise (IoCs) and are working closely with those specific customers to assess and mitigate any potential risks,” N-able said
