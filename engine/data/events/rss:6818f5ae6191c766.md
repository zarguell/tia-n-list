Two critical NGINX vulnerabilities dubbed "nginx2root" allow unauthenticated attackers to execute code remotely on vulnerable web servers, with researchers demonstrating how the flaws can be chained with a Linux kernel bug to gain root access. The two HTTP/2 vulnerabilities were discovered independently by researchers at Xint , Wiz , Ikotas Labs, Metnir, and Rapid7, while Xint also discovered three additional NGINX RCE flaws. Censys later reproduced the underlying memory corruption conditions in four of the five flaws through lab testing, but did not achieve remote code execution. The first of the two "nginx2root" flaws is CVE-2026-123007, a flow-control bug that can corrupt memory in an NGINX worker. It impacts all versions from 1.31.8 down to 1.9.5, released in 2015. Wiz demonstrated unauthenticated remote code execution on a server hosting ordinary static files over HTTP/2 with TLS, while Xint demoed root access by chaining it with a separate Linux kernel flaw. Xint says the separate vulnerability affects the Linux kernel's SCTP subsystem and can be used to escape an NGINX Docker container and gain root privileges on the underlying host. The second flaw is CVE-2026-123633, a use-after-free problem that affects NGINX when it accepts HTTP/2 connections and proxies requests to a backend.
