The fix for the cmd channel landed nearly three months before the CVE-2026-128138 advisory: PR #3771 was opened 2026-08-20 and merged the same day as commit 45a08fded8025c4920ea95a896438fcdbaafb03e, split out of PR #3753. The pull request states that internals.java() passes a caller-supplied cmd list straight to the Java launcher, which treats the first non-option token as the main class, so a cmd beginning with -jar, -version, -XX:OnError or an @argfile reopens the argument-injection class that the CVE-2026-12841 options allowlist was meant to close. The merged change raises a ValueError when the first cmd item starts with a dash or @ sign and blocks argfile references, and it ships in the 3.10.4 release line rather than in 3.10.3.
