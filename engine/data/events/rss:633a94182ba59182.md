OpenSSH has shipped an emergency release, version 10.6p2 , to stop a password bypass that lets a remote attacker log in to accounts that have no password set . The flaw, tracked as CVE-2026-123158 and nicknamed “sshole,” affects Linux systems that run OpenSSH on the musl C library with PAM disabled. That combination is the default openssh-server package on Alpine Linux. Alpine published fixed packages for every branch from 3.16 to edge on November 5, 2026, the same day as the OpenSSH release. No exploitation in the wild had been reported at release, but the OpenSSH team urged affected users to act immediately, and the bug is simple to trigger once its conditions are met. What Is the sshole Flaw (CVE-2026-123158)? sshole is a password authentication bypass in OpenSSH’s sshd that lets a remote attacker log in to accounts that have no password set. The flaw affects only Linux systems that run OpenSSH on the musl C library with PAM disabled, which is how Alpine Linux builds its default openssh-server package. The sshole bypass at a glance: one overlong password, root shell The exposed accounts are those whose password field holds only “*” , meaning no password was ever set.
