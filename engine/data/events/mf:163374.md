Threat actors are actively exploiting three vulnerabilities in JFrog Artifactory : CVE-2026-42016, CVE-2026-42018, and CVE-2026-82329 to bypass authentication, escalate privileges, and seize administrative control of exposed instances. The attacks pose a significant supply-chain risk because Artifactory commonly stores proprietary software packages, build artifacts, access tokens, repository credentials, and integrations used across development environments. Attackers with administrator access can tamper with software artifacts, steal credentials, deploy server-side plugins, and establish durable persistence. Hackers Exploit JFrog Artifactory Flaws Wiz observed attackers chaining CVE-2026-42018 and CVE-2026-42016 against self-hosted Artifactory deployments between August 15 and September 8. CVE-2026-42018 is an authentication flaw that can expose an internal anonymous-user token to unauthenticated remote requests, even when anonymous access is disabled. The attackers first sent a POST request to /access/api/v1/aws/token/ , including the trailing slash, to obtain an anonymous-user JWT with an HTTP 200 response. They then used that token in a POST request to /access/api/v1/tokens , exploiting CVE-2026-42016, a token scope-validation vulnerability. The flaw allows a valid but low-privileged token to be exchanged for an administrator-scoped token because Artifactory does not properly enforce the token’s intended authorization scope.
