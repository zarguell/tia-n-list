A second object will print a message through KERNEL32 , using exactly the same loader executable. a few words before we start A DLL is a linked PE image. A COFF object is input to a linker: it contains sections, symbols, unresolved references and relocation records. The object does not provide the DLL import directory, DllMain initialization contract or PE optional header used in the previous experiment. Microsoft’s PE/COFF specification describes both formats. We need a little linking work at runtime. Our loader will place sections in memory, assign addresses to symbols, resolve explicitly named DLL imports, patch references and call a selected C function.
