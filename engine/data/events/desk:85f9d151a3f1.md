An r/sysadmin post published at 04:50 UTC on 21 November 2026 reproduced Microsoft's customer security notification about the Entra Connect Health API flaw. The notice says the flaw was introduced on 23 July 2026, detected on 9 November, fixed server-side on 19 November, and that the 20 November investigation concluded unauthorized read-only access to tenant-level metadata had occurred with no configuration changes found. It lists exposed fields including technical contact and administrator email addresses, tenant ID, display name, initial domain, country code, region, license tier, directory synchronization status and last sync timestamp, onboarding status, and an expired legacy certificate returned in the pksCertificate field, while excluding passwords, hashes, tokens, valid keys and on-premises topology. Microsoft advised verifying the notice in Azure Service Health, checking the GetTenant and GetTenantPksCertificateDetails scripts, reviewing Entra audit and sign-in logs and Azure Activity Logs, and requiring phishing-resistant MFA.
