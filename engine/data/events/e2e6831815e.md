A critical vulnerability in Argo CD allows any authenticated user with read-only access to extract plaintext Kubernetes Secrets from the etcd datastore, including service account tokens, database credentials, API keys, and TLS certificates. Tracked as CVE-2026-42880 with a CVSS score of 9.6, the flaw exists in the ServerSideDiff endpoint, which fails to apply data-masking consistently. While other endpoints (GetManifests, PatchResource) properly strip secret values, ServerSideDiff returns raw, unmasked states when applications use the `compare-options` annotation with mutation webhooks enabled. The vulnerability affects Argo CD versions 3.2.0 through 3.3.8. A proof-of-concept exploit has been demonstrated. Patched versions 3.2.11 and 3.3.9 are available. Organizations running Argo CD in production should upgrade immediately and audit access logs for any unusual Secret retrieval patterns during the exposure window.
