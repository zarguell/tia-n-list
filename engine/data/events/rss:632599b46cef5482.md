Offensive AI is no longer a slide in a threat-landscape deck. It is sitting on attacker servers, wired to multiple LLM APIs, and probing production APIs at machine speed. ARTEX, an open-source agentic AI penetration testing framework developed in China, is the clearest example so far: a red-team tool that threat actors have adopted to automate reconnaissance, vulnerability probing, and exploitation end to end. For SOC analysts and detection engineers, ARTEX detection is a new kind of problem. There is no single malware family to fingerprint. Instead, you face an LLM-driven operator that adapts payloads, rotates techniques, and generates traffic volumes no human pentester could. This article walks through the ARTEX analysis available so far, the behaviors worth alerting on, and how to detect ARTEX across web, endpoint, and Linux telemetry. Get Started For Free ARTEX Analysis ARTEX went public on GitHub as Autumn-27/ARTEX on July 26, 2026, under AGPL-3.0. It is written in Go, runs a Next.js console on PostgreSQL, and sits on top of ScopeSentry, the same author’s asset-discovery platform ( Censys ). The architecture explains the telemetry you will see. A Planner agent turns an operator goal, such as “gain admin panel access,” into attack intents. Worker agents claim those intents, run tools like nmap, and write results back into an asset graph and an exploration graph.
