How a fraudulent video-conferencing update can turn legitimate remote administration software into an attacker-controlled foothold, potentially enabling a second-stage remote access Trojan Introduction A user attempts to access what appears to be a legitimate Google Meet session. Instead of joining a meeting, the user encounters a notification claiming that the installed version of Google Meet is no longer supported. The website offers an update that appears to be necessary before the meeting can continue. The user downloads a Windows Installer package named Google-Meet-0.1.76-x64.msi. What appears to be a routine software update is actually part of a potentially dangerous remote-access intrusion chain. The DFIR Report publicly disclosed indicators from an active investigation involving a counterfeit Google Meet website, a suspicious executable installed under a Google Meet-branded directory, and reported command-and-control (C2) infrastructure. Independent research from ScanMalware connects the same phishing infrastructure to a broader operation distributing remote monitoring and management (RMM) software. Related research published by Palo Alto Networks Unit 42 describes how similar access mechanisms are used to deploy a custom .NET remote access Trojan known as AgtaBackup RAT .
