Like a lot of people working with PHP applications, we’ve been looking at PHP2Shell and what we can do to help. The most useful advice is still to patch PHP. The vulnerabilities are in the runtime, and a WAF cannot fix that. But we also know that getting an update onto every server can take time. There are applications to check, owners to reach and deployments to work through. Since we maintain the SOCFortress WAF, we wanted to see whether there was something practical we could contribute from our side. We’ve put together a small PHP2Shell mitigation pack and made it publicly available. It includes optional WAF rules, a generator to scope them to your applications, installation instructions and the results of our testing. It’s a limited contribution. It won’t cover every way these vulnerabilities could be reached, and we don’t want anyone to install it and assume the problem is solved. Our hope is that it gives teams a few useful controls to evaluate as part of their response. PHP2Shell involves two vulnerabilities, CVE-2026–109618 and CVE-2026–109619, related to PHP memory handling and state carried between requests. They can lead to unauthenticated remote code execution. If you’re responsible for PHP applications, start with the PHP security advisory( https://www.php.net/archive/2026.php#2026-10-21-5 ), apply the appropriate updates and restart the workers serving your applications.
