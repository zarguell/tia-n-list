Windows, or more precisely, Windows and NTFS has — or rather _had_ ... more on that later — an extremely cool feature: Transactions on the file system. You can basically perform a bunch of operations, create files, modify files, delete files and then either "commit" all of it or "rollback" all of. The underlying Windows API functions belongs to something called "Kernel Transaction Manager" (KTM) and it's even cooler than _just_ atomic transaction on files: it allows operations on _resources_. Windows ships with two of those already integrated: the file system (TxF) and the Windows registry (TxR). But as a developer you can write a so-called "resource manager" offering your "thing" to KTM. There's probably some rich corporate history here that I'm completely ignorant to but I can only assume the hope of the team behind this was that KTM will at some point become standard for all kinds of components running on a Windows operating system: just imagine a database being integrated as well as, say, a queuing system. As a user of those transactions, you could de-queue a message and act on the database and KTM would promise that it either all worked or the message was never de-queued.
