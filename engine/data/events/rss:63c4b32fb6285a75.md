A heap overflow in Java’s Base64 decoder gives unauthenticated attackers code execution in Jira, Confluence and Keycloak, but only on servers whose processors support a specific set of vector instructions. Patch every affected Java runtime, and use the processor to decide which ones go first. On November 17, 2026, the research firm Calif disclosed Java4Shell, CVE-2026-114938 . It is a heap buffer overflow in the Base64 decoder that the HotSpot Java Virtual Machine (JVM) compiles for x86-64 processors. Calif researcher Quang Luong, with exploit improvements by Jenish Rakholiya, demonstrated unauthenticated remote code execution against default installs of Keycloak, Atlassian Jira, Atlassian Confluence, JFrog Artifactory, Jenkins and PingFederate. Calif published a self-contained proof of concept that triggers the bug and is holding back the per-product exploit chains. Oracle’s CVSS 3.1 score for CVE-2026-114938 is 8.1 (High), and Calif scores it Critical, CVSS 4.0 9.2. CISA issued an alert the same day urging immediate patching. As of November 18, 2026, the vulnerability is not in CISA’s Known Exploited Vulnerabilities (KEV) catalog , and Calif reports no exploitation in the wild. Patching Java fixes it
