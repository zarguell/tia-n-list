Amazon Security Lake stores your data in S3 as Parquet files in the OCSF schema, so you don’t download it directly. You query it. Use Amazon Athena with an UNLOAD statement and format = ‘JSON’: Athena writes the results as JSON lines to an S3 prefix you choose, and you download that. Security Lake tables live in a Glue database named amazon_security_lake_glue_db_ , one table per source. Security Lake centralizes CloudTrail, VPC Flow Logs, Route 53, Security Hub findings, EKS audit logs and third-party sources in one normalized format. Get Started For Free Before you start Query access. Use the Security Lake delegated administrator account, or a subscriber with query access. Access is governed by Lake Formation, so you need SELECT on the tables, plus Athena permissions and write access to an S3 bucket for the export. Find the tables. In Athena, open the database for your region. Table names follow the pattern amazon_security_lake_table_ _ _ , for example amazon_security_lake_table_eu_west_1_cloud_trail_mgmt_2_0. The region uses underscores. Partitions keep costs down. Tables are partitioned by region, accountid and eventday (YYYYMMDD). Athena bills by data scanned, so always filter on eventday.
