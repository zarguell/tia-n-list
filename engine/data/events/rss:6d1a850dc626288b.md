auditd writes to /var/log/audit/audit.log, readable only by root. The quickest export of a time window in the original format is: sudo ausearch --raw -ts yesterday > web-03_audit.log If /var/log/audit doesn’t exist, auditd isn’t installed. That’s the default on Debian and Ubuntu. The kernel’s audit events then go to the journal, where journalctl _TRANSPORT=audit finds them. auditd is Linux’s answer to “who ran what, and touched which file”: process execution, file access, permission changes and account changes, down to the syscall. Prime Core has 1350 detection rules for auditd data, mapped to 440 MITRE ATT&CK techniques. Among them: malicious shell use (T1059.004), planted SSH keys (T1098.004) and permission changes on sensitive files (T1222.002). Get Started for Free Before you start Is it running, and what is it recording? systemctl is-active auditd sudo auditctl -l Red Hat-family systems install auditd by default; Debian and Ubuntu need the auditd package. If auditctl -l prints No rules, you still get a baseline of logins, authentication and SELinux denials. You won’t get command execution or file-access records, though, because nobody asked for them. Root only. /var/log/audit is locked down tightly, so plan on sudo. Rotation is auditd’s own. auditd rotates its log itself, based on max_log_file and num_logs in /etc/audit/auditd.conf, into audit.log.1, audit.log.2, and so on. Older history sits in those files.
