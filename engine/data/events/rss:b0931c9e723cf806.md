Threat actors have been exploiting a critical-severity vulnerability in Perforce Puppet to execute code on vulnerable servers. Puppet is an infrastructure-as-code (IaC) and configuration management platform that uses a client-server architecture for device management. Tracked as CVE-2026-115731 (CVSS score of 9.4), the exploited security defect is described as a deserialization of untrusted data issue in the report processing of Puppet Enterprise and Puppet Core, leading to remote code execution (RCE). It allows clients that have a certificate signed by the Puppet certificate authority (CA) to send reports containing malicious payloads that would be executed on the server with the service user permissions, putting managed systems at risk. “A successful attack could expose the server’s certificate-signing key, allow an attacker to issue trusted certificates, and enable changes to software and configuration delivered to managed systems on their next Puppet run,” Perforce explains in an advisory . Unauthenticated attackers could obtain a certificate if the CA auto-signs requests without performing strong verification. Administrators are advised to turn off auto-signing and enforce strong validation to ensure only trusted systems and authorized users can receive certificates.
