Microsoft has confirmed that customers may experience authentication issues after installing November security updates that address a high-severity remote code execution vulnerability. Tracked as CVE-2026-118737 , this security flaw was found in the Windows Remote Procedure Call Runtime and stems from a timing-dependent authentication weakness that unauthenticated attackers can exploit to remotely execute code without user interaction on unpatched systems. Microsoft says the November security updates represent the first phase of NTLM message-signing improvements, which reduce exposure to relay attacks by ensuring authenticated NTLM sessions always establish a cryptographic session key and negotiate real message signing. However, as Microsoft explained in an updated support document, the new security improvements introduced to address this vulnerability may also cause authentication failures on patched devices. "Microsoft is aware of compatibility issues affecting some third-party apps and devices, including authentication proxy servers, single sign-on (SSO) solutions, and application packaging solutions that use NTLM authentication," it said. "This issue can occur when such a proxy device does not correctly implement the NTLM protocol. For example, an affected device might set the NTLMSSP_NEGOTIATE_TARGET_INFO flag in its CHALLENGE_MESSAGE but provide an empty or incomplete TargetInfo field."
