Overview A mismatch between Apple File System (APFS) filesystem and path resolution for multiple applications allows attackers to bypass security exclusions using alternative Unicode spellings. By supplying an alternative Unicode spelling or case-folded variant (such as ß versus ss ) that bypasses the application's file write checks, a local attacker can overwrite files wherever the process has write permissions, potentially leading to data corruption, configuration hijacking, or code execution. Multiple vendors have assigned CVEs and issued patches to address this flaw. Description Several archive tools, packaging systems, and runtimes enforce exclusion filters using pathname comparisons that do not match the underlying filesystem's resolution behavior. By using a byte-for-byte comparison (such as ß versus ss ), rather than full case folding, a vulnerable application can be tricked into silently overwriting protected files. This vulnerability exposes backup tools, forensic workflows, and CI/CD pipelines to unauthorized file modification.
