Upstream fix for CVE-2026-99288, authored by Hyunwoo Kim on 30 October 2026 and committed to mainline on 3 November 2026. The commit message explains that TCP established ehash lookups are lockless and the socket caches use SLAB_TYPESAFE_BY_RCU, so memory can be reused before an RCU reader that kept its old address has finished. After a tuple match, __inet_lookup_established() and __inet6_lookup_established() take a reference and repeat the tuple check but never check whether the replacement object is hashed, so a lookup can return a SYN cookie request socket whose rsk_listener is NULL; tcp_v4_rcv() then reads sk_state through that NULL listener and panics. The fix adds the missing hashed check on both IPv4 and IPv6 paths and drops the reference to restart the lookup.
