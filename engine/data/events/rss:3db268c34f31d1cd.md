Fresh security updates for the Ruby programming language resolve seven vulnerabilities in its regular expression engine and in the case conversion of strings. Proof-of-concept (PoC) code demonstrating remote code execution (RCE) exists for five of them. At the top of the list sits CVE-2026-132825 (CVSS score of 7.4), described as a heap-based buffer overflow in the case conversion of strings that could potentially lead to RCE in certain scenarios. Dubbed Ruby2Shell , the flaw impacts character case-conversion operations. In some single-byte encodings, including ISO-8859-1 and Windows-1252, when changing the case of a string, Ruby may end up writing one byte past the output buffer. “For example, converting the German character ß to uppercase produces SS. In affected code, Ruby checks that sufficient space exists for one byte but writes two, potentially corrupting adjacent heap memory,” Previdian explains. Veria Labs reports that, in default Ruby configurations, unauthenticated attackers could trigger the security defect from Rails, classic-style Sinatra, and potentially other frameworks. According to preemptive exposure management firm WatchTowr , “any Ruby application that changes the case of external text in a single-byte encoding” is affected by the vulnerability.
