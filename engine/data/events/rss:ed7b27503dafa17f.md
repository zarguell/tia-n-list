Threat actors began targeting Plex2Shell, a chain of four Plex Media Server vulnerabilities, one day after technical details and a working exploit went public. The researcher who found the Plex2Shell bugs released a write-up and proof-of-concept (PoC) code on October 16. Tracked as CVE-2026-96652, CVE-2026-96654, CVE-2026-96655 and CVE-2026-96656, the flaws can be combined to run arbitrary code on an exposed server without valid credentials. The code runs with the same privileges as the Plex service. The issues were reported to Plex on July 27, and the company confirmed them and awarded a bug bounty on August 4. On September 1, Plex announced it had already shipped fixes and asked server owners to upgrade. A different researcher caught the attacks by setting up an internet-facing Plex honeypot running a vulnerable release. Before October 17, the decoy had drawn largely reconnaissance scans and generic attack attempts. “As of this morning (Oct 17th), I finally saw in the wild exploitation,” the researcher wrote. The attackers used the publicly released exploit, the researcher said, though they may have tweaked the code. The attackers were observed dropping a cryptocurrency miner built on XMRig. Later that day, a second program called myawesomeproxy also appeared on the honeypot.
