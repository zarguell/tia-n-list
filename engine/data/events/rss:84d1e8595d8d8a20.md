An 11-year-old Linux kernel vulnerability, dubbed NoisyTCP , affects almost all Linux distributions and lets attackers crash systems running Nginx, Apache, and SSH servers with default configurations. According to Hyunwoo Kim, the security researcher who discovered it , this pre-authenticated remote corruption flaw (tracked as CVE-2026-99288 ) stems from a NULL pointer dereference weakness in the Linux kernel's TCP networking subsystem. Unauthenticated attackers can trigger it remotely via maliciously crafted TCP packets that exploit the timing between SYN cookie handling and socket hashing to crash the kernel and operating system on targeted servers. However, while CVE-2026-99288 exploits cause a kernel panic and take down the host, they don't allow threat actors to alter data or gain arbitrary code execution. Kim added that although attackers can exploit this vulnerability against any Linux system that receives TCP packets directly and runs Nginx, Apache, or an SSH server, "the race window is narrow, so triggering it against a quiet bare-metal server can take a long time." "Due to a race condition during lockless socket lookups, recycled socket memory can be accessed before it is properly initialized and hashed. A remote attacker could exploit this issue by generating network traffic that drives socket reuse, triggering a NULL pointer dereference and kernel crash that results in a Denial of Service (DoS)," the Red Hat security team explained .
