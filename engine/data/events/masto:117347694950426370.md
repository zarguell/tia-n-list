A team at Graz University of Technology's Institute of Information Security has demonstrated that the file notification systems of Windows, Linux, Android, and macOS leak user activity through side channels, and that on Linux password prompts can be faked. The work is documented in the paper "File Notification Attacks: Templating and Exploiting Side-Channel Leakage from the File-Notification Systems on Linux, Windows, and macOS", available at https://inoti.fyi.

File notification systems report to the system and applications when files are created, deleted, opened, closed, or modified. The team found that apps or other users on the same system can eavesdrop on these notifications without administrator rights, needing only read permission on certain folders. That exposes the names of all files and subfolders within, even when the files themselves deny read access. File contents remain hidden on all systems; only file names and the fact that changes occurred are visible, which is still enough to reconstruct the behavior of users, the system, and applications. On Windows, the researchers bypassed access restrictions through the notification system of the unprotected parent directory: monitoring events on C:\ exposed every filesystem event in all subfolders. Because browsers like Firefox create a folder named after each visited site that needs local storage, browsing history is visible in real time. On Linux, the team used inotify to observe keystrokes inside a read-protected file by watching its readable parent folder; while the exact keys remain unknown, inter-keystroke timing attacks, which have existed for over two decades, extract information from the timing alone. On the KDE Plasma desktop they placed a fake password window over the real one when a polkit authorization prompt appeared, capturing the password the user then typed, and this works under Wayland as well. On Android, where the FUSE system is meant to stop apps reaching other apps' data, the team gained visibility into WhatsApp folders. macOS is covered by the same attack template.

The exposure requires no privilege escalation, only co-residency on the system with read access to a parent folder, which is a common app sandbox situation. Watch for vendor patches or guidance around notification permissioning, and for the polkit overlay technique to show up in Linux malware.
