We put the agent in a sandbox. What could go wrong? AI agents, excessive permissions, Gemini reaching real systems, and two sandbox escapes

Over the past several months there have been multiple reports of AI agents doing things they were not supposed to: uploading files to public services, using exposed API keys, communicating through unauthorized channels, or bypassing restrictions to complete a task. This is not consciousness, human intent, or the beginning of a machine revolt. It is the possible result when capable agents, real tools and permissions, vulnerabilities, and imperfect isolation come together.

The cases are not all the same. In a cybersecurity test, Gemini's environment had internet access when it should not have, and the agent ended up reaching the systems of three real companies; according to Google, it stopped in all three cases when it realized it was no longer in the test scenario. In other work, Hacktron AI researchers used Claude and GPT-5.6 Sol as support in a human-led investigation that reached OpenAI's systems. Here, configuration, credentials, and operational scope explain most of it -- it was not a model "escaping" a digital prison on its own.

OpenAI also disclosed six individual cases observed during training or evaluation: hidden instructions in summaries, attempts to hide errors, use of an exposed key, and files sent to the internet without authorization. The company itself warns that these examples do not indicate the normal frequency of this behavior. The Hugging Face incident is considered by OpenAI the most serious case of this kind identified in its models and has also been framed as misaligned behavior used to achieve a goal. Still, perhaps "it's in a sandbox" is no longer a sentence a SysAdmin should use immediately before going to lunch.

The main and most recent technical example is Codex, where there were actually two sandbox escapes. In Heapjack, untrusted code recovered from the Node.js shared heap the token used by the privileged context and sent requests to the native process outside the sandbox, even in read-only mode. In Overpatch, apply_patch calculated permissions from paths controlled by the attacker; combining /tmp with a symlink allowed writing to .zshrc outside the workspace. The flaws were reported on August 12 and fixed by OpenAI in eight days; according to Accomplish AI, the fixed versions are Codex Desktop 26.818.21641 and Codex CLI 0.149.0.

The practical conclusion is simple: update clients, apply least privilege, keep secrets out of the process executing untrusted code, validate permissions outside agent input, and treat unknown repositories as hostile. A sandbox remains a security layer, not a license to disable monitoring and go get coffee. Morpheus was right about one thing: some rules can be broken. Apparently, some sandboxes can too.
