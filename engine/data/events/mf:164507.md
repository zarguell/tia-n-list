Attackers are increasingly targeting Active Directory domain controllers to steal credentials stored in the NTDS.dIT database. A recent simulation shows how threat actors can combine native Windows features, remote administration tools, and credential-dumping utilities to copy the Active Directory database and the SYSTEM registry hive before exfiltrating them. The NTDS.dit file holds critical domain identity data, including NTLM password hashes, Kerberos keys, account information, and password-history data. If attackers obtain both NTDS.dit and the SYSTEM hive, they may decrypt the database offline and gain access to credentials for every domain account. Attackers Extract NTDS Credentials The attack typically begins with initial access through spear-phishing emails, malicious Office files, LNK attachments, or trojanized software installers. Once a victim runs the initial payload, attackers may load a second-stage implant directly into memory to reduce disk-based evidence. End-to-end attack chain: From breach to exfiltration (Source: trellix) The malware then connects to a command-and-control server using encrypted traffic. Attackers attempt to elevate privileges to NT AUTHORITY\SYSTEM, allowing them to access protected processes and sensitive operating-system resources. At this stage, they may target LSASS memory to collect NTLM hashes and Kerberos tickets. Stolen credentials can then be reused for pass-the-hash or pass-the-ticket attacks.
