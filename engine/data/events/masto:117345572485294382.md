Hyunwoo Kim published details on openwall.com of a critical vulnerability, CVE-2026-89775, in the KVM subsystem for ARM64 in the Linux kernel. It allows escape from a virtual machine and access to host memory, potentially yielding control of the hypervisor and, in special cases, remote code execution on the host. Exploitation requires nested virtualization to be enabled, which is off by default on ARM64; that narrows the attack surface but not the severity where the feature is on, notably public clouds (AWS, Azure) and CI/CD test environments. Attacks using this flaw do not trigger standard detection mechanisms such as traps or VM exit events, so attacker activity is practically invisible to the hypervisor.

The root cause is in the handling of nested virtualization control structures, specifically TLB invalidation for the VNCR (Virtual Nested Control Register). When computing the size of the range to invalidate, the kernel reads the stage-1 page table walk level. When the Stage 1 MMU is disabled, KVM assigns the constant S1_MMU_DISABLED, equal to -127; the function pgshift_level_to_ttl() cast this value to u8 without warning and considered only its two lowest bits, producing 0. In the KVM structures, 0 denotes an unknown block size, and the invalidation was interpreted as a valid 0-byte range, so a stale mapping survived. An attacker gains read and write access to freed host memory that should be unreachable from the VM, without the hypervisor noticing, enabling kernel memory disclosure and potentially code execution. Because many Linux distributions ship /dev/kvm with 0666 permissions, the flaw also permits local privilege escalation on the host by an unprivileged user.

The vulnerable code entered in commit 7270cc9157f47 and was fixed in commit 8053393680d4. The fix is a kernel update, either upstream or via updated distribution packages; where an immediate reboot is not possible, temporarily disabling nested virtualization contains the risk.
