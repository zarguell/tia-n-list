PHP on Thursday rolled out a fresh set of security patches as part of its four-week update schedule, including fixes for seven critical-severity remote code execution (RCE) vulnerabilities. First in line is CVE-2026-115560 , which was publicly disclosed last month, two days after PHP2Shell patches landed. Residing in the session upload progress feature, it could be triggered to write attacker data using one session serialization format and then read it using another. “A mismatched decoder can interpret part of a session key as serialized object data. An application with a suitable object gadget chain can then execute code with the privileges of the PHP worker,” PHP’s advisory reads. Next in line is CVE-2026-129481 , described as a use-after-free that occurs after a session shutdown has been interrupted, and which PHP describes as an incomplete fix for CVE-2026-109619, one of the two PHP2Shell flaws fixed in October and now widely exploited. “An attacker who can cause an application’s session cleanup to fail in this way may corrupt memory or crash a reused PHP worker. The use-after-free could potentially lead to remote code execution, but code execution through this specific field has not been demonstrated,” PHP notes, adding that PHP 8.2 is not affected. Another use-after-free, CVE-2026-129182 , covers additional exploitation scenarios for CVE-2026-109619, an RCE via stale global state.
