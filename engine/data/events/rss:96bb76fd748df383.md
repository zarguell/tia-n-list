IntroductionOn November 17, 2026, security researchers from Calif.io publicly disclosed Java4Shell (CVE-2026-114938, CVSS v4.0: 9.2 Critical), a severe heap memory-corruption vulnerability in OpenJDK’s hardware-accelerated (intrinsic) Base64 decoder on certain CPUs. The disclosure coincided with coordinated advisories from the OpenJDK Vulnerability Group and Oracle’s November 17, 2026 security patch release.Because Base64 decoding is foundational to network protocols, this runtime-level vulnerability can be reached in enterprise applications that pass attacker-controlled input to the affected decoder. Calif.io demonstrated pre-authentication Remote Code Execution (RCE) in default configurations of Keycloak, Atlassian Jira, Atlassian Confluence, JFrog Artifactory, Jenkins, and PingFederate. Additionally, post-authentication RCE was achieved in Apache Kafka Broker, Apache Solr, Elasticsearch, Gerrit, and Netflix Spinnaker, as well as a client-side TLS exploit affecting Java clients connecting to a malicious server. Immediate patching for affected environments is strongly recommended, alongside other mitigation steps outlined in this advisory. Zscaler’s security team is actively analyzing this issue across both production and corporate environments. We will continue to update the Zscaler Trust post and this advisory as new information becomes available.
