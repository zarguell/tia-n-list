CVE-2026-82533: the flaw in DeepSeek Harness that gave AI agents the keys to their own sandbox. A local interface without authentication allowed sandboxed agents to disable their own restrictions with a single shell command. DeepSeek Harness, the open-source tool from DeepSeek for running coding agents locally, exposes a local web interface as a control panel for agent sessions. The vulnerability (CVSS 9.4, CWE-807) combines three weaknesses: no authentication on the local control-plane API, validation that trusts the client-supplied Host header instead of verifying the actual TCP connection origin, and the fact that the harness communicates the interface address and session ID to the agent itself. By spoofing the Host header, a compromised agent could reach the loopback interface and set the session to danger-full-access mode, eliminating filesystem sandboxing and disabling approval prompts. Versions 0.1.1-rc.2 and earlier are vulnerable. The fix introduces one-time-token authentication for the local interface. The vulnerability was also reported independently by community researchers on GitHub Discussions before the official report to VulnCheck. Similar patterns of unauthenticated local control-plane APIs have been found in other AI agent frameworks including LangChain, CrewAI, and Google ADK.
