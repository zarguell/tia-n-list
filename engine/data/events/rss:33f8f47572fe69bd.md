Java4Shell, tracked as CVE-2026-114938, is a heap overflow in Java's hardware-accelerated Base64 decoder. Researchers at Calif say it can let attackers without an account run code on Jira, Jenkins, Keycloak and other Java applications. Oracle and the OpenJDK project shipped fixes on Nov. 17, 2026, and CISA urged organizations to patch immediately. No exploitation in the wild has been reported. Patch it, but read the conditions before you rank it next to Log4Shell. The vulnerable code runs only on x86-64 servers whose processors support AVX-512 VBMI, so a server's exposure depends on its CPU as much as its Java version. The same container image can be vulnerable on one host and safe on the next, and that is the detail most patch plans will miss. Which Java versions and servers are affected? A server is exposed only when three conditions hold at once. 1. A vulnerable Java build. Java 17.0.6 and later on the 17 line, plus Java 21, 25 and 27 before the November fixes. Standard Java 8 and 11 don't contain the flawed code, but the Java SE 8 Performance Pack build 8u511b33-perf does, as do recent GraalVM builds. 2. The right CPU.
