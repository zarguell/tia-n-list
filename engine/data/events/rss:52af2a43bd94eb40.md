A newly disclosed vulnerability tracked as CVE-2026-123633 exposes certain NGINX reverse-proxy deployments to unauthenticated denial-of-service attacks and potentially remote code execution. The flaw is a use-after-free condition in NGINX’s HTTP/2 processing that can be triggered when the server proxies client requests to an upstream backend while a worker is running low on available connections. The vulnerability was disclosed alongside CVE-2026-123007 as part of a broader set of security flaws patched by the NGINX team on November 18, 2026. F5 assigns CVE-2026-123633 a CVSS v4.0 score of 9.2, Critical , while its CVSS v3.1 score is 8.1, High because exploitation requires a particular server state and configuration. Unlike CVE-2026-123007, which can affect HTTP/2-enabled NGINX instances serving ordinary static content, CVE-2026-123633 specifically targets reverse-proxy processing. An exposed server must have HTTP/2 enabled, forward requests to a backend server, and reach a state where available worker_connections are running low. Successful exploitation can crash NGINX worker processes or corrupt memory. Wiz researchers demonstrated that the vulnerability can be developed into unauthenticated remote code execution and confirmed an ASLR bypass in laboratory environments. Code execution occurs with the privileges of the NGINX worker process rather than automatically granting root access to the host.
