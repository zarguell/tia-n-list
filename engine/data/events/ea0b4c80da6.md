A logic flaw in the Linux kernel's `authencesn` cryptographic template, reachable via the `AF_ALG` socket interface and `splice()` system call, enables any unprivileged local user to gain full root access with a single 732-byte Python script using only standard library modules. Dubbed "Copy Fail," the vulnerability originates from a 2017 in-place optimization in `algif_aead.c` that causes page cache pages to be placed into a writable destination scatterlist, allowing a controlled 4-byte write into in-memory setuid binaries like `/usr/bin/su`. Because the kernel never marks corrupted pages as dirty for writeback, on-disk files remain untouched — defeating checksum-based integrity tools entirely. Confirmed exploitation on Ubuntu 24.04 LTS, Amazon Linux 2023, RHEL 10.3, and SUSE 16. Critically, Copy Fail functions as a **Kubernetes container escape primitive** because the page cache is shared across all processes on a host, including across container boundaries. A compromised container can corrupt setuid binaries visible to other containers and the host kernel. Three independent code changes from 2011, 2015, and 2017 converged to create this condition with no developer connecting their intersection for nearly a decade. Patched in the kernel on April 1 (CVE assigned April 22, public disclosure April 29). Immediate mitigation: `echo "install algif_aead /bin/false" > /etc/modprobe.d/disable-algif-aead.conf && rmmod algif_aead`.
