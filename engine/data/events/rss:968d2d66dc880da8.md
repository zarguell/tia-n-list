A quick use case for the new execution flow control feature If you have spent enough time writing SPL (10y here!), you have probably run into a familiar situation: you want to process events differently depending on what they contain. In a typical SPL pipeline, commands are executed sequentially, and filtering commands such as where and search can reduce the number of events passed to subsequent commands. Maybe you want to enrich events conditionally, or apply different transformations based on a field value. In classic SPL, you can often get the job done with eval, if(), case(). That works, but what if you want to control which block of code gets executed based on a field’s value, just as you would in a procedural programming language ? Enter SPL2’s if command. How does it work? The SPL2 if command was announced for Splunk Cloud Platform version 10.5.2605 on June 29, 2026, but I only became aware of it after seeing this LinkedIn post from Mikael Bjerkeland : SPL vs. SPL2: what actually changes? One important distinction: SPL already has an if() function . You do not need SPL2 to write conditional expressions. In classic SPL, you might use: | eval severity=if(status>=500, "high", "medium") The SPL above evaluates a condition and returns one of two values. For several conditions, you might use case()function. This is present in pretty much any modern piped language, including KQL . SPL2's if command works differently.
