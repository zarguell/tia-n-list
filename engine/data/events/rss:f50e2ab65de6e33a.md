After about seven months, one of my DGX Sparks started crashing under heavy load. It typically crashed after about two hours of sustained load (e.g., when running DeepSeek V4 Flash). At first, I thought it was an out-of-memory (OOM) error. I’d seen that error a couple of times before when I was running tools on the same host I used for inference. Occasionally, I’d forget to disable a cron job that ran a threat intelligence processing pipeline. When the job kicked off during inference, the host would throw an OOM error. Whenever one of these crashes occurred, I’d have an agent debug it. I keep a working directory specifically for debugging these kinds of issues. When a new issue comes up that I’d like an agent to debug, I create a folder with a descriptive name, cd into it, and start an agent. The benefit of this approach is that if the issue comes up again, I can resume the session and pick up where I left off. I’ve found that this saves a lot of time on recurring issues, especially networking problems. After a couple of sessions trying to track down the cause of these crashes with an agent, I decided to check the NVIDIA forums. If you haven’t visited them, they’re a gold mine of tips and ideas. One tip was to run NVIDIA’s DGX Spark Field Diagnostics tool to check for hardware failures. Sure enough, the tool identified a hardware issue.
