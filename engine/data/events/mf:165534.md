RATHat, an Android banking trojan, combines Google Gemini AI with Android Debug Bridge (ADB) abuse to steal credentials and give attackers remote access. Its malicious application acts as an entry point, deploying a separate service that operates outside the app’s normal lifecycle. The malware spreads through malicious advertising, SMS phishing, and deceptive download pages. Campaigns described in the supplied analysis target Europe, Latin America, and Southeast Asia. Earlier samples used cryptocurrency trading and streaming application disguises to persuade victims to install malicious APK files. Unlike a conventional banking trojan, RATHat does not depend entirely on permissions held by its installed application. It abuses Accessibility access to create an additional control layer through the device’s own debugging interface. RATHat Hijacks Android Devices The infection chain depends on the victim granting Accessibility Service access. RATHat then navigates Android settings, enables Developer Options and wireless debugging, and reads the pairing code displayed on screen. It pairs with the local ADB daemon without requiring an external computer. This connection provides shell access under Android’s UID 2000. Operators can then deploy a native Go service into /data/local/tmp . RATHat Architecture (Source: cleafy) The service runs separately from the application and maintains its own communication channel with the command-and-control infrastructure.
