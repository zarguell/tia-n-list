Key Findings CVE-2026-109618 and CVE-2026-109619, together called PHP2Shell, are flaws in the PHP interpreter itself. Every application on an affected build inherits the exposure regardless of framework, CMS or plugins. The PHP security team scored both at 9.2 on CVSS v4.0. A remote attacker with no credentials can run code as the web server worker account. PHP2Shell also includes an unauthenticated path that discloses live worker memory without executing any code. Exploitation started before the patch. Amazon Threat Intelligence recorded an attempt against its MadPot honeypots on October 17, four days ahead of disclosure, and now describes PHP2Shell as broadly exploited in the wild. Working exploits exist. Calif and Wiz each demonstrated pre-authentication RCE against current application releases. Most publicly circulating proof-of-concept code crashes workers rather than achieving execution, so attacker capability in the wild is unknown. Patching is the only complete fix. Fixed releases are 8.5.12, 8.4.27, 8.3.36 and 8.2.35, with source backports for 7.4, 8.0 and 8.1. PHP states its interim settings do not make an installation safe.
