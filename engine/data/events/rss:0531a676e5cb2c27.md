What Is Log Analytics? Log analytics is the practice of collecting, parsing, normalizing, and querying machine-generated event records to answer an operational or security question. In a SOC, that question is usually narrow: did this account authenticate from an unexpected source, did this host spawn an unusual child process, which API calls preceded the data transfer. The raw material is heterogeneous: Windows Security and Sysmon channels in .evtx files, Linux auth.log and journald output, firewall and proxy events in CEF, and cloud audit trails such as AWS CloudTrail or Microsoft Entra ID sign-in logs exported as JSON. A working log analytics pipeline has four stages: Collection. Export events from the source without losing fields or timestamps. Normalization. Map src_ip, IpAddress, and sourceIPAddress to one common schema. Detection. Run Sigma or vendor rules and tag every hit with MITRE ATT&CK techniques. Correlation. Group related hits into a timeline or attack chain that an analyst can validate. Why Log Analytics Matters for Detection and Response Logs are often the only record that survives an intrusion. EDR telemetry rolls over, memory is lost on reboot, and packet capture is rarely running when you need it. Windows Event IDs 4624, 4672, and 4688, or CloudTrail calls such as ConsoleLogin and CreateAccessKey, are typically the primary evidence for scoping an incident.
