OpenAI says an internal research model crafted raw packets, wrote custom connection code and probed cloud services to get around network restrictions during a coding evaluation. The incident occurred in early August, when the unnamed model was asked to build a website modeled on a reference site. The AI found the sandbox’s web proxy down and looked for other routes to the internet. A scan of private addresses turned up no substitute proxy. When the operating system stopped it from using a separate connection meant for the app and its browser, the model built individual packets and used them to resolve the target’s IP addresses through DNS. It then wrote a program that managed web connections at the packet level. It also leveraged fragmented requests intended to sneak past a network filter, which its own reasoning called evasion that could breach sandbox policy. However, the tactic did not succeed. The code did reach Amazon S3, which rejected a request to relay traffic to the target. OpenAI said S3 showed no sign of compromise. About five hours in, the model left itself a note to stop evading network controls. Minutes after resuming, it was back on S3 seeking an archived copy, then asked the instance metadata service for cloud credentials and was refused. The real site was never fetched.
