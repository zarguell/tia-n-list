Threat actors have escalated exploitation of a critical WordPress vulnerability, moving from reconnaissance activity to attempts to write attacker-controlled PHP files onto vulnerable servers. The flaw, tracked as CVE-2026-87902, affects WordPress versions 4.7.0 through 7.1.1 and can lead to remote code execution under specific theme and PHP configurations . WordPress fixed the issue in version 7.1.2 and released backported patches for supported branches down to 4.7.37. Hackers Exploit Critical WordPress Flaw The vulnerability stems from an unauthenticated path traversal issue in WordPress page-template resolution. An attacker can abuse the pagename parameter to make get_page_template() include a readable local PHP file outside the active theme directory. The advisory rates the vulnerability Critical, with a CVSS 4.0 score of 9.2, and identifies it as CWE-98, improper control of a filename used in a PHP include operation. Patchstack researchers first observed exploitation attempts on September 22, shortly after WordPress 7.1.2 was published. Initial requests focused on confirming whether vulnerable page-template inclusion was possible. Attackers targeted legitimate WordPress core files, including wp-links-opml.php , RSS feed files, wp-cron.php , wp-login.php , and install.php , using encoded traversal sequences within pagename .
