Today I want to continue that experiment with module overloading : place a complete PE image inside the image mapping of another DLL. As usual, the visible result will be a Meow-meow! message box with the =^..^= caption. This time the payload is a small DLL written in C. The host must prepare its imports and relocations before calling its entry point. a few words before we start The names module stomping , DLL hollowing , and module overloading overlap in different publications. In this post, I use the following distinction: function stomping - instructions at a selected function module stomping in trick 61 - instructions at the carrier DLL’s entry point module overloading here - the carrier’s mapped headers and section contents, using another PE image The important change is the payload format. Position-independent shellcode already contains instructions designed for its execution environment.
