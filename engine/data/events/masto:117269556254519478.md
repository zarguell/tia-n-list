Five minutes to become admin: the exploit chain that turns three JFrog Artifactory bugs into a Rust backdoor

A 24-day campaign documented by Wiz saw attackers chain three critical vulnerabilities in JFrog Artifactory to take administrator control of self-hosted instances and install persistent Rust backdoors. Between August 15 and September 8, 2026, the attack required less than five minutes from first HTTP request to a fully provisioned admin account.

The chain combines CVE-2026-42018 (an authentication flaw that returns a JWT for the internal anonymous user even when anonymous access is disabled), CVE-2026-42016 (insufficient token validation that allows escalation from low-privilege to admin scope), and CVE-2026-82329 (CVSS 9.8, a standalone authentication bypass that grants admin privileges with no credentials). Two of the three flaws had patches available before the campaign began, making this a patch-latency failure at scale.

Once admin access is obtained, attackers create persistent accounts with names mimicking legitimate service accounts (observed: 0xTerror, svc_*, labadmin_*, jfrog-distribution, jfrog-insight, repo-service), install malicious Groovy plugins for arbitrary code execution, and drop custom Rust backdoors with C2 capability in /dev/shm, /tmp, and /var/tmp. The attackers also extract Artifactory cluster join keys, potentially enabling persistence across distributed nodes.

Wiz and watchTowr measured 49 to 62 percent of internet-reachable Artifactory instances as vulnerable to at least one flaw. CISA added all three CVEs to KEV and gave federal agencies two weeks to patch. Patching closes the initial access vector but does not remove established backdoors, rogue admin accounts, or uploaded Groovy plugins. JFrog Cloud instances were patched by the vendor; this is a self-hosted problem.
