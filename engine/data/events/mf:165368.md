A DPRK-attributed malware campaign has added Ethereum transactions to its command-and-control (C2) system. The XCTDH campaign already used TRON and Aptos to locate malware payloads stored on BNB Smart Chain (BSC) . Its newer “HashHiding” channel uses ordinary Ethereum transfers to tell infected machines where to find the current C2 server. Ransom-ISAC first documented Cross-Chain TxDataHiding (XCTDH) in October 2025. OpenSourceMalware publicly described the recipient-address technique as “NullReceiver” in August 2026; Ransom-ISAC uses “HashHiding” to describe its role in this wider campaign. XCTDH Hides C2 On-Chain In the original XCTDH chain, malware reads a TRON transaction, with Aptos as a fallback. That transaction points to a BSC transaction whose input field contains encrypted JavaScript. The malware decrypts and runs the code. BSC therefore stores payloads, while TRON and Aptos act as indexes. HashHiding serves a different purpose, it stores an address, not malware code. In the September 2026 samples described by Ransom-ISAC, a JavaScript module called _Z scans Ethereum blocks for transactions from an operator-controlled wallet.
