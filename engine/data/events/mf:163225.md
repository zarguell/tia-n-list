Instead of sending victims to a hosted credential-harvesting page, the attackers generate the phishing page directly inside the victim’s browser using a blob URL. This technique makes detection harder because the phishing page does not exist as a normal internet-accessible webpage. Security tools cannot easily crawl, analyze, categorize, or blocklist it before a victim opens the link. The page is created temporarily in the browser’s memory during the attack session. The campaign also uses legitimate Microsoft services, including Microsoft OAuth redirects and Microsoft Teams domains, to make the attack chain appear more trustworthy. Victims may see Microsoft infrastructure in the browser rather than an unfamiliar phishing domain, reducing obvious warning signs. Browser-Embedded Phishing Pages Emerge The attack begins with a DocuSign-themed phishing email designed to look like a business document request. The message includes a calendar invitation file, which helps make the email appear routine and less suspicious. The calendar file itself does not directly contain a conventional phishing link. Instead, it points to a legitimate Microsoft OAuth endpoint.
