A critical vulnerability in the GoAhead embedded web server can allow revoked client certificates to remain valid during mutual TLS authentication, potentially giving previously trusted identities continued access to protected devices and services. Tracked as CVE-2026-115881, the flaw carries a vendor-assigned CVSS score of 9.1 and affects GoAhead versions 3.4.5 through 6.1.0 when the software uses its OpenSSL-compatible TLS backend with certificate revocation lists configured. The issue was fixed in GoAhead 6.1.1. GoAhead is an embedded web server commonly integrated into routers, printers, gateways, industrial systems, and other network-connected products. However, the vulnerability does not affect every GoAhead installation. Exploitation requires a specific mutual TLS configuration, and the affected population of commercial devices has not been established. The vulnerability stems from improper certificate revocation validation. GoAhead successfully loads a configured Certificate Revocation List (CRL) into OpenSSL’s certificate store, but fails to activate the OpenSSL flag required to enforce CRL checking. Consequently, a certificate explicitly marked as revoked can still complete authentication. For CVE-2026-115881 detection, security teams should combine software inventory, TLS backend identification, certificate telemetry, and monitoring of mutual TLS authentication.
