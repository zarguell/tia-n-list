A major public key infrastructure incident has triggered emergency security measures across browsers, programming language ecosystems, certificate stores, and software packages. Private keys associated with eight eMudhra intermediate certificate authority certificates were compromised, potentially allowing unauthorized parties to create certificates that could appear trustworthy to vulnerable clients. The incident affects six TLS intermediates used for domain-validated, organization-validated, and extended-validation certificates, along with two code-signing intermediates. Because an intermediate CA can issue certificates below a trusted root, possession of its private key creates a substantially different risk from the compromise of an ordinary website certificate. An attacker could potentially create fraudulent certificates that inherit trust from the affected chain. The Go Project responded by introducing CVE-2026-111943, which addresses cases where Go applications could continue trusting certificate chains containing the compromised intermediates. Go 1.26.10 and 1.27.3 add a denylist to crypto/x509, causing certificate verification to fail when one of the known untrusted intermediate keys appears in a chain. Security teams seeking CVE-2026-111943 detection opportunities should look beyond conventional vulnerability exploitation telemetry.
