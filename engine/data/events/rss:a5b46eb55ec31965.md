In a recent incident, visitors to websites run by some of the world’s best-known brands, including news publishers, banks, airlines, and software companies, were served malicious JavaScript. Most of those organizations never deployed bad code. The code came through a script they had deliberately chosen to trust, delivered by a widely used third-party web service. The attackers did not break into those websites. Instead, they exploited a weakness in the vendor’s platform to gain administrative control of some customer accounts, then modified the JavaScript those customers delivered through the vendor. The vendor’s CDN served the altered code to every visitor of an affected page. Researchers who analyzed the injected code found it running on many organizations’ websites. It was built to steal payment card details typed into on-page forms, tamper with cryptocurrency transactions, and send readable cookies to attacker-controlled servers. The lesson extends beyond one vendor: modern websites run code their owners did not write and often do not track. The hidden risk of third-party JavaScript Analytics, personalization, advertising, consent management, chat, and A/B testing all depend on external scripts. Each that points to another host lets that host run code in your visitors’ browsers with the same privileges as your own code.
