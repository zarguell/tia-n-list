The Trivy-LiteLLM Compromise Cascade The contemporary threat landscape reflects a sophisticated pivot in adversary doctrine: the subversion of trusted security and automation tooling to facilitate “meta-supply chain” attacks. By targeting the “scanners of the scanners,” threat actors effectively neutralize the security perimeter from within. This methodology bypasses traditional defenses by exploiting the inherent trust placed in the integrity of the CI/CD pipeline’s foundational components. The March 2026 campaign orchestrated by TeamPCP exemplifies this trend, leveraging a single upstream failure to trigger a multi-stage propagation that compromised not only LiteLLM but also the Telnyx Python SDK and Checkmarx KICS. The genesis of the breach involved an unrevoked automation token for the Trivy vulnerability scanner. Although rotated, the token remained functionally active for a 20-day window, allowing the adversary to force-push malicious code to the scanner’s published version tags. The telemetry suggests an unprecedented scope of exposure within the global AI-dependency graph due to an “unpinned dependency” flaw; LiteLLM’s build system utilized unpinned apt installs for Trivy, causing the compromised scanner to flow automatically into the production pipeline. During a critical 40-minute window in March 2026, the infected build process generated and published malicious versions of LiteLLM (1.82.7 and 1.82.8) to the Python Package Index (PyPI).
