Sysmon writes to its own event log channel. In Event Viewer that’s Applications and Services Logs → Microsoft → Windows → Sysmon → Operational . On the command line it’s Microsoft-Windows-Sysmon/Operational, and on disk C:\Windows\System32\winevt\Logs\Microsoft-Windows-Sysmon%4Operational.evtx. To export it, run this from an elevated prompt: wevtutil epl "Microsoft-Windows-Sysmon/Operational" C:\logs\sysmon.evtx If the channel doesn’t exist, Sysmon isn’t installed. On most machines it’s still a separate Sysinternals tool that someone has to deploy. Sysmon is the closest thing Windows has to a flight recorder. It captures process trees with full command lines and hashes, network connections per process, DNS queries, and file and registry changes. Sysmon logs only what its configuration tells it to. Without a config file, you get a small default set built around process creation. Most of the value comes from a tuned config, such as SwiftOnSecurity’s or Olaf Hartong’s sysmon-modular. To see the current one, run sysmon64 -c (the binary lives in C:\Windows ).
