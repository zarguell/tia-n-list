A newly disclosed class of vulnerabilities, dubbed GitSpawn, can allow a booby-trapped software repository to silently execute code on a developer’s machine the moment it is opened with an AI coding agent. The attack requires no prompt, approval click, or other user interaction. In some cases, the malicious command can run before a developer has authenticated to the coding platform . Security researchers at Manifold Security discovered the issue while investigating what command-line AI coding agents automatically do when they start inside a project directory. GitSpawn Flaws Let Malicious Repositories Execute Code According to the Manifold Security technical disclosure, nearly every agent examined performs background Git commands, including git status and git diff , to collect project context before responding to a user. This behavior is ordinary and normally harmless, but it can trigger Git to refresh its internal index. The risk comes from Git’s core.fsmonitor setting. The configuration option is intended to improve performance by allowing a repository to define a file-system-monitor helper program. Git can automatically launch that helper whenever it refreshes its index. However, Git reads the core.fsmonitor value directly from the repository’s local .git/config file. An attacker can therefore place an arbitrary command in a malicious repository’s Git configuration.
