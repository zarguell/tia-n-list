GitHub's Canonical pylxd advisory traces the flaw to `pylxd/client.py`, where WebSocket `ssl_options` omit server verification, CA trust and the pinned fingerprint before ws4py 0.6.0 creates a TLS context with hostname checks disabled and `CERT_NONE`. It states that an active network attacker can read command stdin and replace stdout/stderr without an LXD account or stolen client key, while explicitly not claiming arbitrary REST access or unconditional LXD code execution. The advisory marks pylxd versions through 2.4.2 vulnerable and 2.4.3 patched, with CVSS 3.1 7.4 High.
