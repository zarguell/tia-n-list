A newly disclosed cache poisoning technique dubbed cache key injection can enable attackers to bypass access controls, expose cached sensitive content, trigger denial-of-service conditions , and potentially plant stored cross-site scripting payloads in vulnerable Nginx deployments. The research, published by YesWeHack researcher Alex Brumen, shifts attention away from traditional web cache poisoning flaws involving unkeyed HTTP input. Instead, it targets the construction of the cache key itself, particularly configurations that concatenate multiple variable-length request components without delimiters. New Cache Key Injection Attack web caches (Source: yeswehack) Web caches store HTTP responses under keys assembled from selected request properties, often including the scheme, host, URI, query string, cookies, or headers. Nginx deployments may use a configuration resembling: proxy_cache_key "$scheme$proxy_host$uri$is_args$args$http_accept"; The danger is not that the resulting string is unhashed. Rather, it is that adjacent values are merged ambiguously. Yeswehack stated that two distinct requests can produce an identical final key when an attacker shifts characters between controllable fragments such as the URL path and the Accept header. For example, a legitimate request for / with Accept: */* can generate the same final key as a request for /* with Accept: /* , depending on the remaining key components.
