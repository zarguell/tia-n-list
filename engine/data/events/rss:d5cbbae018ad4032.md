Security researchers disclosed five vulnerabilities Tuesday in NGINX, the web server software that handles traffic for roughly a third of all websites, each with a working exploit. The most severe allows an unauthenticated attacker to run code on the server from anywhere on the internet, and in tests the researchers chained it with a separate Linux kernel flaw to take over the machine hosting the server entirely. F5, the company behind NGINX, released fixes Tuesday and published an advisory classifying the worst of the flaws, an integer underflow tracked as CVE-2026-123007, as critical, scoring 9.2 out of 10 on the CVSS scale. The problem sits in HTTP/2, the protocol NGINX uses to carry many requests over a single connection. HTTP/2 uses a credit system: the client grants the server permission to send a fixed amount of data. When a client cancels a request while its response data is still waiting to be sent, NGINX hands back that unused credit without checking whether the total now exceeds the protocol’s maximum. A later check subtracts the inflated number from the maximum using unsigned arithmetic, which cannot go negative, so the calculation wraps into an enormous value. That broken number is eventually treated as a negative response length, producing a memory buffer whose end pointer sits before its start, and a memory copy that spills outside its boundaries.
