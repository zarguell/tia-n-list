A newly disclosed chain of vulnerabilities in Telerik UI for ASP.NET AJAX can turn an unauthenticated AES-CBC padding oracle into remote code execution (RCE) on susceptible web applications. The issue affects Telerik UI for ASP.NET AJAX releases from 2010.1.309 through 2026.2.519; Progress Software says version 2026.2.708 (2026 Q2 SP1) prevents exploitation of the chain. Security researcher Marcio Almeida found that RadAsyncUpload processes encrypted client-controlled state using AES-CBC and PKCS#7 padding. Telerik UI Flaws Chain AES-CBC Padding Oracle The affected code exposes different behavior when ciphertext has invalid padding versus when it has valid padding but decrypts to malformed JSON. That distinction creates a padding oracle: an attacker can repeatedly modify encrypted data and use server responses, or response timing, to infer plaintext and ultimately construct chosen encrypted values without possessing the encryption key. The chain centers on RadAsyncUpload state, including the encrypted _serializedConfiguration and metaData fields. CBC encryption alone does not provide integrity protection. CBC chains (Source: tantosec) Because Telerik accepted tampered ciphertext before the patch, the oracle could be used to recover intermediate block values and forge parts of a configuration object.
