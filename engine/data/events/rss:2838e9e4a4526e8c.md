Security researchers on Tuesday published details of a critical flaw in Java, one of the world’s most used programming languages, that could let an attacker take over servers without a password. The group behind the find, Calif Research, said AI coding tools did much of the work. Oracle Corp. shipped a fix the same day it released a November update covering 652 flaws across its product line. The flaw is tracked as CVE-2026-114938 and nicknamed Java4Shell . It is a memory-corruption bug: code that writes data where it does not belong, which can crash a program or, at worst, let an attacker run their own commands. The buggy component is the Base64 decoder in OpenJDK, the free Java runtime that underpins software across banking, aviation and telecommunications, and that, by Calif’s count, runs at 90% of Fortune 500 companies. Calif rated the flaw 9.2 out of 10 on the CVSS scale, where anything above 9 counts as critical. The group said an unauthenticated attacker, one who needs no username or password, could corrupt a server’s memory, read nearby data in a manner similar to the 2014 Heartbleed bug, and escalate that access into full control. The bug lives in an unusual place: hand-written processor instructions that OpenJDK uses to make Base64 decoding faster. The optimization runs only on chips that support a feature set called AVX-512; ARM64 systems are unaffected.
