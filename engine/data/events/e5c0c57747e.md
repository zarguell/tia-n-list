Palo Alto Networks' Unit 42 disclosed a **bucket hijacking technique** affecting major cloud providers that exploits the global uniqueness of storage bucket names. An attacker who gains `storage.buckets.delete` permission can delete a victim's storage bucket, recreate it under their own account with the same name, and silently redirect active data streams — including cloud logging sinks, Pub/Sub subscriptions, S3 replication rules, and Azure Monitor diagnostic settings — to attacker-controlled infrastructure.

The attack was successfully simulated across:

- **Google Cloud**: Cloud Logging sinks, Pub/Sub subscriptions, Storage Transfer Service

- **AWS**: S3 bucket replication, Amazon Data Firehose destinations

- **Azure**: Cross-subscription storage account hijack via Azure Monitor diagnostics

Mitigations include VPC Service Controls (GCP), data perimeter SCPs (AWS), account regional namespaces (S3), strict IAM least privilege for delete operations, and robust monitoring for storage deletion API calls. No in-the-wild exploitation has been confirmed, but the attack's silent nature — the sink configuration appears valid after hijacking — makes detection particularly challenging.
