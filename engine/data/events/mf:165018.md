A newly disclosed high-severity vulnerability in Sudo could allow local unprivileged Linux users to bypass time-based restrictions configured in sudoers policies. Tracked as CVE-2026-96512, the flaw stems from Sudo’s handling of the attacker-controlled TZ environment variable when it evaluates command authorization windows defined with the NOTBEFORE and NOTAFTER tags. Red Hat is tracking the issue as Bug 2539327 and has classified it as high severity and high priority. The vulnerability affects Sudo versions from 1.8.20 through 1.9.17p2. Although an upstream fix has been committed, it was not included in a released Sudo version when the flaw was disclosed. Sudo Flaw Lets Unprivileged Users Bypass Time-Based Restrictions Sudoers policies can use NOTBEFORE and NOTAFTER to limit when users may execute commands with elevated privileges. Administrators commonly use the controls to enforce temporary administrative access, maintenance periods, emergency access procedures, and automatically expiring privileged permissions. The vulnerability lies in Sudo’s parse_gentime() function, which processes time values that do not contain an explicit timezone suffix, such as Z for UTC or a numeric UTC offset. The affected implementation relies on the standard C library mktime() function to interpret these timestamps. However, mktime() uses the process environment’s TZ variable to determine the timezone.
