AWS can automatically attach a restrictive quarantine policy to IAM users whose long-term access keys are exposed in public GitHub repositories, potentially limiting abuse within seconds of disclosure. Research published by Palo Alto Networks Unit 42 found that AWS applied its AWSCompromisedKeyQuarantineV3 managed policy just 10 seconds after researchers pushed an IAM access key and secret to a public GitHub repository. GitHub issued its own secret-exposure notification one second later, followed by AWS Health alerts, email notifications, and an AWS Support case. AWS Automatically Quarantines Exposed IAM Credentials The response mechanism is designed to reduce the window in which threat actors can exploit leaked credentials for cryptomining, privilege escalation , data theft, cloud resource abuse, or unauthorized AI-service consumption. Atatck Flow (Source: Palo Alto Networks) During Unit 42’s controlled test , an IAM access key was pushed to a public repository at 18:50:05 UTC. At 18:50:15, AWS CloudTrail recorded an AttachUserPolicy event that linked the AWSCompromisedKeyQuarantineV3 policy to the affected IAM user. The policy does not deactivate the access key outright. Instead, it uses explicit Deny statements to block selected high-risk actions. Under AWS IAM policy evaluation rules, an explicit deny overrides an explicit allow, meaning the policy can constrain a compromised identity even when it already holds broad permissions.
