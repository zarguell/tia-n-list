GitHub's reviewed advisory for CVE-2026-59822 says the MCP auth handler let failed LiteLLM key validation fall back to an empty UserAPIKeyAuth object, so an unauthenticated caller with an arbitrary Bearer token could establish an authenticated MCP session. It says an attacker could list and call configured MCP tools and reach connected services, and it fixes the issue in 1.84.0. As a stopgap, the advisory recommends disabling MCP routes or blocking /mcp/ and related endpoints at a reverse proxy or API gateway.
