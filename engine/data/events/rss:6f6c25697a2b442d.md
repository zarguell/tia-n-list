Static inspection by default, sandbox detonation when you need it, and your customer’s file never leaves your host. An alert fires. Attached to it is a file: a macro-laden doc, a dropped .ps1, something a user insists they never downloaded. And the question is always the same: What does this thing actually do? Until now, every answer had a catch. You could upload it to a public multi-scanner and quietly hand a customer’s file to the entire internet. You could spin up a sandbox by hand, if you had one, and shuttle results back and forth. Or you could eyeball it and hope. None of those belong in a SOC that takes multi-tenancy and data handling seriously. So we built something better. Today we’re introducing File Analysis in SOCFortress CoPilot , a new module that takes a suspicious file straight from an alert or a Velociraptor collection and returns a verdict you can act on and explain. It works in two tiers: Static inspection runs by default and never executes the file. Detonation is opt-in, for when you need to watch the file run. The first tier answers the question safely. The second shows you exactly what happens when the file fires. A quick note on the screenshots: Every image in this post comes from a run against win_obfuscated.ps1, a benign, non-destructive demo fixture we ship for exactly this purpose.
