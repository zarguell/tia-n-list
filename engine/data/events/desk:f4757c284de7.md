Published two minutes after the CVE-2026-128138 advisory in the same GitHub batch, this high-severity entry (CVSS 7.1) describes nltk.pathsec.ZipFile.extract opening each member target without checking whether it is a hardlink to a file outside the data root, so a local actor who can write inside a shared or predictable root such as the group-writable /usr/share/nltk_data pre-plants an in-root hardlink that nltk.download() then truncates and overwrites. Affected versions are 3.9.4 through 3.10.3 and the patched version is 3.10.4, so the November disclosure wave maps onto the release defenders should already be running.
