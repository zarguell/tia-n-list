For the last 90 days of management events, use the CloudTrail console ( Event history → Download events → JSON ) or aws cloudtrail lookup-events. For anything older, or for data events like S3 object reads, read your trail’s log files in S3. They sit under s3:// /AWSLogs/ /CloudTrail/ /YYYY/MM/DD/. CloudTrail is the audit log of your AWS control plane: every console login, every API call, every role assumption. In a cloud incident, it’s the first thing everyone asks for. Prime Core has 262 detection rules for CloudTrail, mapped to 177 MITRE ATT&CK techniques. Among them: misuse of cloud accounts (T1078.004), attackers switching off cloud logging (T1562.008) and data theft from cloud storage (T1530). Before you start Event history and trails are different things. Event history is always on and free. It keeps 90 days of management events, per region. A trail is something you configure: it writes to S3, keeps logs as long as you like, and can include data events. Check what you have: aws cloudtrail describe-trails aws cloudtrail get-trail-status --name IsLogging: false on a trail that should be running is a finding in itself. Regions matter. Event history is per region, and events from global services like IAM usually land in us-east-1. If you’re looking for a CreateUser call in eu-west-1, you won’t find it.
