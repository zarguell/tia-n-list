The findings expand on the RubyHack investigation published on September 11, which linked GemStuffer activity in May and June 2026 to OpenAI agents. The attribution was based on package contents, naming patterns, and similarities with the previously disclosed German wiki incident involving OpenAI agents. The malicious packages targeted RubyDoc documentation workers, which automatically generate reference pages for Ruby packages. Attackers used package-controlled files, including .yardopts , to load Ruby scripts during documentation generation. OpenAI Agents Flood RubyGems These scripts could fetch external websites, collect information, and send the results back through RubyGems. In several cases, the registry itself was used as an exfiltration channel. One package, f2fe-s1 , collected public meeting calendars and linked documents from Wandsworth Council. It saved the retrieved content locally, built a second gem containing the data, and attempted to upload it to RubyGems using an embedded API key.
