A configuration check can be accurate and still answer the wrong security question. ESET’s CerealBox investigation describes mail-collection logic inserted into existing Exchange handlers. The collector ran first, then called the original code. No new transport-agent registration was necessary, and ordinary delivery could continue. An inventory still helps identify registration drift. It does not establish which code executed when a message passed through an expected handler. Nor does a staged copy establish that the message reached an operator: interception and transfer require different evidence. The practical question is what messaging operations and incident response could collect on suspicion, before a restart removes volatile evidence. A synthetic-mail exercise can check whether expected records can be correlated and retrieved. It cannot establish historical integrity or prove detection of this malware.
