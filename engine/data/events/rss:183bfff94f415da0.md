PHP2Shell affects how PHP handles a request that runs out of memory or encounters a fatal error. If the failure interrupts an operation before it finishes, PHP can leave an array entry only partly initialized or retain a pointer to memory that is later freed. Request cleanup or a subsequent request can then use that invalid state, causing memory corruption that can lead to remote code execution. Some exploitation paths run while PHP processes incoming form data, before the application script starts. Others require successive requests handled by the same server process. Because the flaws are in PHP’s runtime, the engine that executes application code, application-level authentication and input validation cannot protect the pre-execution paths. Updating the application alone does not fix the underlying runtime. Vulnerability overview Disclosed on 21 October 2026, PHP2Shell groups two critical PHP vulnerabilities.
