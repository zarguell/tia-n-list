## Issues found

1. **Snapshot pin mismatch (snapshot_pin FAIL)**: The deployed STIX bundle hash (0f285856cf...) doesn't match the manifest's expected hash (7425390971...). Root cause: `build_bundle()` in `engine/snapshots.py` creates duplicate STIX objects when multiple CTI records reference the same malware/campaign/actor. The `objects.sort(key=lambda o: (o["type"], o.get("name", "")))` sort is stable but the relative order of duplicates depends on `records.items()` iteration order, which is non-deterministic. This means every CI build produces a different bundle hash. The deployed site is not broken (content is correct) but the integrity pin is invalid.

2. **Ingest noise flood**: 4 sources producing excessive volume with high drop rates. valtersit.com at 250 events/7d is the worst offender.

3. **Fragmentation false positive**: The 3 "other/2026-09" Patch Tuesday stories are genuinely different (legacy Windows CVEs, chipmaker advisories, virtualization RCE roundup) — not merge candidates. The fragmentation detector's `roundup_family` classifier is correct but the "other" bucket catches non-Patch-Tuesday stories that happen to mention "Windows CVEs." Consider tightening the classifier for the "other" family.

4. **Two genuine duplicate story pairs** flagged by duplicate_suspects but not merged (max 2 merges/run reserved for higher-priority items):
   - `google-fined-403-million-over-location-data-privacy-violations-h` / `discover-why-the-dpc-hit-google-with-a-403-million-euro-location` (jaccard 0.71)
   - `https-tech-insider-org-gyazo-data-br-each-23-6-million-users-202` / `the-page-at-3am-is-always-the-same-a-link-to-a-leak-site-and-a-s` (jaccard 0.67)

## Recommendations

1. **Fix snapshot non-determinism**: In `engine/snapshots.py:build_bundle()`, deduplicate STIX objects by `(type, name)` before serialization — keep the object with the most external_references (most complete ATT&CK mapping). This fixes the snapshot_pin check and makes builds reproducible.

2. **Throttle valtersit.com**: At 250 events/7d with 58% drop rate, this Mastodon feed is the single largest noise source. Consider reducing its ingestion frequency or applying a per-source rate limit in the social collector.

3. **Tighten roundup_family classifier**: The "other" bucket currently catches stories mentioning "Windows CVEs" even when they're about legacy exploitation, not Patch Tuesday roundups. Adding a requirement for month-reference or "patches/fixes" verb would reduce false positives in the fragmentation check.
