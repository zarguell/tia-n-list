Consider lowering `MASSTO_MAX_PER_HOST` for `www.valtersit.com` or adding `hugovalters` to the quota/skip list (77% drop rate after the 09-22 quota).
2. **Codify the re-report demotion rule in `score.py`**: 147/298 lifetime digest demotes are the same judgment ("new events are re-reports of already-covered coverage, no new victims/CVEs/infrastructure"). A deterministic novelty check — new events whose outlet re-hosts a URL cluster already attached to the story, with no new CVE/KEV/victim — would remove ~half the digest agent's override workload and make ranking reproducible.
3. **Regenerate or retire the 6 boilerplate analyses** flagged in Issues #2 (desk decision, not an agent fix).
4. **cronman publish-drift fix** (candidate for a future PR, not taken today because it touches safety-scoped staging logic): stage `kevrichment/data/index.json` whenever the SSVC/kev-verify stage rebuilds it (not only when records changed), and make `kev_burndown.py`'s completion path commit `KEV_ALWAYS_PATHS` before self-disabling. Also commit the two currently-dirty kevrichment files so the live dashboard stops serving 09-27 data.
