## Recommendations

1. **Codify the restatement penalty in score.py.** Over 8 digests: 232 demote overrides vs 11 promotes, and the modal reason is "newest items restate coverage from Nov N". The signal exists (rereports/zero_delta) but is not biting: today's demoted set includes stories with `rereports` in the tens still sitting above the digest gate. Consider a demote-shaped bonus/penalty for "newest event's source is a known reposter of an already-covered outlet", and measure whether the daily override count drops from ~29 toward single digits. That is the cheapest single quality lever available.
2. **Give the flood-entrant detector an age floor.** Require an entrant to have, say, >= 14 days of lifetime presence (or >= 2 consecutive audits) before the "share of lifetime in the window" arm fires. That would have kept 2026-11-06 and today's FAIL out of the ISSUES class while still catching the thehackerwire case it was built for (26/day, 94% kept, present for weeks). Alternatively document the expected false-positive rate so audits stop re-deriving it.
3. **Tighten the entity probe's shared-entity predicate** (or raise `max_out` handling to a settled-pairs cache with a stop condition once N consecutive days produce zero merges), so generic tokens stop generating same-value pairs like `control`/`white`/`pcs`. The 2026-10-17 identity-anchor redesign did this for the title probe; the entity probe still lacks the equivalent.
4. **Decide secquill.com / infonewscyber.fr deliberately.** Neither qualifies for a skip on today's numbers, and skipping removes corroboration (the art. 2 rule: traffic stays in the signal file either way). Recommend holding both as WATCH for one more audit and re-running the recount at the 13:39Z instant; if secquill's drop rate climbs past 80% on a second consecutive audit it enters `EVENT_SKIP_HOSTS` under the existing bot-feed arm, with `secquill@infosec.exchange` as the matching `MASTO_SKIP_AUTHORS` entry.
5. **Ghost-story housekeeping is due**: 784 eventless non-redirect stories (up from the count the store has carried for weeks). `engine/cleanup_ghosts.py` already exists for exactly this; running it on a quiet hour would keep the store honest without touching anything that renders.
