## Recommendations

1. **Codify re-report/zero-delta penalties in `score.py` rather than demoting 139 times by hand.** The digest agent demoted 139 stories in 21 days for "no new delta / restates"; `score_breakdown` already carries `zero_delta` and `rereports`, so the detector is undersensitive to social and masto re-posts. Tightening it (and the `single-source` case, 43 demotes) would shrink the override list to genuine judgment calls.
2. **Give the digest agent a promote budget.** Seven consecutive digests with zero promotes and 4 wildcards in 21 days means under-ranked but consequential stories (the DoppelCart / AI-agent class of pick) can sit uncovered indefinitely. A floor of one bench wildcard per digest, or a score.py boost for "never covered + KEV/attribution + multi-source", would restore the lift.
3. **Host-level skips for pure job-board feeds.** `blueteamjobs.com` (39 lifetime, 100% dropped), `jobicy.com` (134, 100%), `remotely` and `blueteamjobs@infosec.exchange` (16 decisions, 100% dropped each) plus `redhotcyber` (264, 100%): the triage layer throws all of it away. Skip at ingest to save triage budget; the noise check flags "sources clean" only because triage is absorbing the cost.
4. **Only one local `ssg.py` rebuild per day is worth the 9m26s**; run it detached (or after the hourly commit) so it cannot overlap the :13 hourly job.
5. **Retire the orphaned analyses left behind by merges.** Both merge losers kept their `.md` (`cybersecurity-issue-forces-...`, `the-hacker-news-one-extension-...`); the repo convention for retired analyses is `analysis/.rejects/`, and triage's merge path does not move them. A one-line rule in `triage.apply` (move `from`'s analysis into `.rejects/` on merge) would keep the analysis directory honest.
6. **Slug/title hygiene for rolling series.** Add a `retitle` action to the desk for stories whose newest analysis names a different product version or CVE than the title, so Issues 1 does not recur every Chrome and Firefox release.
