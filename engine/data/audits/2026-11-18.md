## Issues found

1. **KEV page missing for CVE-2026-115731** (the digest's third story promotes it). `kevrichment/data/cves/CVE-2026-115731.json` exists, is fully researched, `kev_date_added: 2026-11-17` — but it is **untracked**, absent from `kevrichment/data/index.json` (1786 indexed vs 1787 on disk), and `kev/cves/CVE-2026-115731/` 404s live. Root cause: the 2026-11-17T19:00 RECOVER found the previous run killed during `kev-agent` at 18:18:37Z; `revert_kev_worktree` restored `index.json` and dropped the CVE, the next pipeline run then reported `Processed: 0` ("SKIP no KEV update since last research"), and `_record_kev_evaluated` marked revision 2026.11.17 (1782) as done — so every later run logs "already processed", and the record can never be re-indexed. Cronman PR #107 fixes the class; it self-heals at the next catalog revision **only after that PR merges**. Until then the CVE stays invisible in the KEV section while the digest references it. Equivalent manual remedy (not applied — it is data surgery outside the fix license): delete the orphan record so `main.py` re-researches it on the next catalog change.
2. **`ingest_noise` FAIL — therecord.media stub feed.** 71% of 14 kept events are <200 chars because the feed ships one-paragraph teasers while the other sources ship bodies. PR #214 fixes future ingests; the ~80 stub events already in the store stay thin (they still carry usable leads, e.g. the Java4Shell CISA alert).

## Recommendations

1. **Merge cronman#107 and tia-n-list#214**, then confirm CVE-2026-115731 lands in `kevrichment/data/index.json` at the next catalog revision (check `kev/cves/CVE-2026-115731/` live and the KEV index listing). If it does not, delete the orphan record to force re-research.
2. **Codify the repeat-re-report penalty** in `score.py`: a story demoted by the digest on 3+ consecutive days with no new CVE, actor, victim count or IOC should carry a negative term (the `stale_demoted` data is already emitted by `audit.py`). That would retire the largest manual judgment class in the digest (14 slugs account for a large share of the 1,272 demotes).
3. **Fix the digest's search path** before it silently degrades a lead: alert when both queries on a digest run fail (the log already prints it; nothing pages on it).
4. **Either refresh or unpublish the 22 warn-stage legacy analyses**, at minimum the four named above. A stale analysis with no CVE is the kind of page a reader screenshots.
5. **Reject aggregator link-share mints in the id scheme**: a `malware.news` post that only carries an "Article link:" body should attach to the source story, not mint a numeric slug that ends up as a URL. (`11` was this exact case and cost a merge today.)
