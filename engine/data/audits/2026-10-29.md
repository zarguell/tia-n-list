## Issues found

1. **Digest withheld twice, published 8.5 hours late.** `CHECKER_BLOCKING=true` blocked on a
   deterministic acronym collision (`PHP` ⊂ `PHP2Shell`), not on a content defect. The site served
   2026-10-28 all morning.
2. **The LLM composition checker is dead.** `CHECKER_MODEL=mimo-v2.5` in `config/daily-digest.env`
   returns `410 ModelDeprecated: Model mimo-v2.5 has been deprecated. Use mimo-v2.6-flash instead`, so
   every run since at least today logs `CHECK: UNKNOWN empty checker output`. The maker/checker second
   opinion is not actually running; only the deterministic gates are. This needs a config change on
   cronman (checker model bump), which is outside this audit's fix license.
3. **Five live story pages serve placeholder analysis text** (see quality sampling), including a lede
   truncated mid-sentence on `critical-arbitrary-file-upload-flaw-in-gravity-forms-leads-to-re`.
   Public-facing.
4. **Block resolution is not recorded.** Today's withheld digest was un-blocked by an edit that left no
   trace in `logs/daily-digest/` or `state/decisions/decisions.jsonl`; the decision card still says
   "resolved: failed". Whatever path did that (manual edit or an agent outside the job wrapper) should
   go through the job so the ledger matches reality.
5. **`logs/daily-digest/2026-10-29.log` shows two `SKIP: already running` lines at 12:50:06 and
   12:51:37** from an invoker that never reached the job's own START line. Something is retrying
   `daily-digest` on a ~90s loop while the publish holds the lock; harmless today, but it will mask a
   genuine wedge next time.

## Recommendations

1. **Run `audit.py` detached, or with a longer budget.** Under this host's normal concurrent load it
   takes 4-7 minutes; a bounded 300s call returns nothing at all and looks like a silent failure. Same
   lesson already written down for the CTI PHASE2 re-runs.
2. **Codify the re-report demote in `score.py`.** 500+ of 865 logged overrides are "no new facts /
   re-report / CATCH-UP / restate". `audit_checks.stale_demoted_stories` already computes exactly that
   signal (latest event adds no new CVE/actor/victim/IOC); feeding it into scoring would stop making the
   digest agent hand-demote 25-43 stories per day and would tighten the events-per-story ratio.
3. **Skip the pure-noise feeds at ingest.** `blueteamjobs.com` (16 triage decisions, **100% dropped**,
   lifetime 47), `www.redhotcyber.com` (15 decisions, 100% dropped), and the handles
   `hypedupcat@infosec.exchange` (45 decisions, 96% dropped), `remotely` and `negativepid` (100%
   dropped) consume judge budget to produce nothing. `ingest_noise` passes its thresholds, so this is a
   hygiene suggestion, not a failure.
4. **Bump the checker model** (`CHECKER_MODEL` in `config/daily-digest.env` to `mimo-v2.6-flash`) so the
   second opinion is live again, and consider widening the watchlist-scope acronym guard: a 3-letter
   acronym match against a demoted story is the same false-positive class as the 2026-10-26
   "everyday word" fix, and it cost a full digest publish today.
5. **Add a placeholder guard to the analysis publish gate.** A 200-250 byte body containing
   "Covers CVEs and events" or "The story covers events tied to" should be treated as a missing
   analysis (do not render an Analysis section, or requeue the story) instead of shipping as prose.
