## Issues found

1. **Root cause (unfixed, code — outside the fix license): the deterministic hourly merge re-populates merged-away fragments.** `engine/merge.py` `match_story()` scores *all* stories including ones with `merged_into` set, and `main()` appends the matched event straight to the fragment instead of routing to the canonical. Both fragments above were merged previously (yesterday's audit even merged `microsoft-patches-398...` in its own decisions file) and re-accumulated fresh events within hours. This is a recurring loop: every matching article will resurrect the fragment as a live duplicate card; the audit keeps cleaning up the symptom. Needs a code fix.
2. **Fragmentation detector blind spot (recurring, second day in a row).** `audit.py`'s fragmentation check reported "no duplicate-story fragments" while two live duplicates sat on the homepage. Yesterday's audit flagged the same blind spot ("plugs N security holes"-class titles); today it also missed the `-2` suffix slug — the signature of `build_slug()` collision, where the LLM named a new story identically to an existing one. The `-N` suffix is a cheap, deterministic duplicate signal the detector should catch.
3. **CTI "stealth" tactic label is non-standard ATT&CK** — used on 16 records (e.g. T1574). Internally consistent; not a data error; noting for the record since the coverage matrix is public.
4. **BleepingComputer/SecurityWeek references 403 to bare curl** — bot-protection, sites confirmed up (pages 200 with a browser UA). Only relevant if a link checker runs with a bare UA.

## Recommendations

1. Fix `engine/merge.py`: in `main()`, when `match_story` returns a story with `merged_into`, resolve to that canonical before appending (or exclude `merged_into` stories from `match_story` candidates). This kills the recurrence; the safety net and audit shouldn't have to re-merge the same fragments daily.
2. Broaden the fragmentation detector: add a `-N`-suffix slug pattern (build_slug collision) and keep yesterday's suggested roundup-title patterns ("plugs N security holes", "fixes N flaws").
3. Consider scrubbing `first_seen`/`last_seen` on merged fragments so stale metadata can't re-enter hot lists even if a fragment is touched.
