## Recommendations

1. **Defang token-shaped strings at ingest/analysis-write time** (regex for
   `pk.`/`sk.`/`ghp_`/`github_pat_`/`AKIA`/JWT-shaped blobs → split or
   `[REDACTED]`). This both neutralizes GH013 push blocks and matches
   threat-intel publication convention. Highest priority — the block cost
   ~11 hours today and will recur.
2. **Skip or pre-filter the ENISA EUVD feed** (`euvd.enisa.europa.eu`):
   either drop the source, keep only CVSS ≥ 7, or cap per-day events. Also
   evaluate `radar.offseq.com` (new flood entrant) and `valtersit.com`.
3. **Codify the re-report demote into `score.py`**: 6/7 of today's digests'
   demotes (and most of yesterday's) cite "outlet re-report of already-covered
   facts". A novelty signal (near-dup of new events against already-covered
   story facts) would let the digest stop paying this judgment tax daily.
4. **Anchor the `triage_drift` pattern in `audit_checks.py`** to the actual
   `WARN: no keep/drop decisions recognized` line so agent narration cannot
   trigger the invariant (complementary to the opened PR).
5. **Boilerplate gate for analyses**: reject/queue-for-rewrite files matching
   "covers recent security developments", "This matters because it affects
   systems users rely on", or mid-sentence truncations; regenerate the three
   sampled stubs.
6. **Let the CTI pass drain**: raise the per-run record cap (12 → ~25) or
   allow a second pass while `cti-queue.json > 20`.
7. **Atomic JSON writes in the engine** (write tmp + `os.replace`) to kill
   torn reads like the manifest.json WARN; cronman's `lib/state.py` already
   does this — the engine should match.
8. **Explicitly design the prepublish-secret-redaction flow** (web session
   active): pushing through a scratch remote must never leave production
   `origin` diverted; add a guard or use an explicit `redact` remote instead.
9. **Operational follow-up**: restart/investigate the stuck cronman audit pi
   and the autodiag 1800s timeouts; prune stale stashes (Issue #9).
