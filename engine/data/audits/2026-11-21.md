## Recommendations

1. **Teach the merge path to handle detection artefacts.** Recurring from
   11-20 (Rec 1). Give `triage.py`/`absorb_cti_on_merge` the same treatment
   for `cti/<slug>.sigma|.yara|.splunk|.kql` that it already gives CTI JSON
   (absorb or archive into `cti/.archive/`), then merge the UAT-12643 pair.
   Until that lands, this one incident will keep costing a digest demote slot
   and two case pages.
2. **Codify the re-report penalty in `score.py`.** Recurring from 11-20
   (Rec 2). 30 of today's 33 overrides are demotes, most of them "newest
   material is a re-report with no new CVE/actor/victim count/IOC". A
   discriminator-delta penalty already exists in part (`zero_delta`,
   `rereports` counters in the breakdown); it needs to bite at the ranking
   stage, because the digest agent is still doing this filtering by hand
   every morning.
3. **Watch the two new firehose candidates.** `punkreport.sh` (72% dropped,
   7-day-old account) and `www.kbytechnologies.com` (58% dropped, 7-day-old).
   Neither trips the current junk thresholds; both are exactly the profile
   that produced the 2026-09-16 gamefan incident.
4. **Commit or ignore `kevrichment/data/quarantine/`.** Either add it to
   `.gitignore` (it is operational state) or commit it deliberately. Right
   now it shows as untracked dirt on every audit run and hides real data
   drift.
5. **Raise the CTI batch cap or accept the steady-state queue.** If 21
   pending should be zero, process more than 12 cases per pass; if not, the
   audit's ">20 pending" trigger should say "stuck, not steady" so no audit
   spawns a redundant multi-hour run.
