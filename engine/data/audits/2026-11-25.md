## Recommendations

1. Teach the deterministic dedup a shared-advisory signal, not just title tokens: both
   ROMULUS/Dell/TPM cases would have merged instantly on a shared canonical URL
   (same arxiv abs page, same DSA-2026-451, same securityonline article modulo utm
   params). `entity_dup_suspects` is doing the work `duplicate_suspects` should do for
   cold research re-reports, and cold pairs are exactly what the 0-score sweep misses
   when both sides score 0.0 rather than a mix of 0 and non-zero.
2. Decide the digest's structural contract in code. Every recent digest (11-23, 11-24,
   11-25) opens straight into `[NEW]` entries with no headline and no executive
   summary, and closes with a Watchlist. If the intended format is headline + exec
   summary + prose, the prompt has drifted for at least a week; if the `[NEW]`/`[REVISIT]`
   list is the intended format, say so in the template so future audits stop probing it.
3. The specificity lint has warned on 26 shipped analyses every run for at least five
   days (mostly no-CVE research and roundup pieces). Either grant an explicit
   research/roundup exemption or rewrite the set; a warn-stage rule that never
   resolves trains reviewers to ignore it.
4. `kevrichment/data/epss-history.json` is dirty in the working tree on an ongoing
   basis (1-line window update) and `kevrichment/data/quarantine/` is untracked,
   because the hourly stages only `kevrichment/data/runs/`. Either commit the EPSS
   window on the kevrichment cadence or gitignore the quarantine directory so the tree
   is not permanently dirty between publishes. Not fixed here: it is pipeline output,
   not audit output, and the site is not stale.
