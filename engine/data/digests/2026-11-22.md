[NEW] Dragos researchers led by HD Moore spent five months sending nearly two million prompts seeded with unique URLs, DNS names, and canary AWS credentials through AI routers and inference marketplaces, and caught three hosting providers reading customer prompts through ordinary request logging, in the [Dragos canary-token study](stories/dragos-canary-token-study-tracks-where-two-million-ai-prompts-le/). Requests marked Zero Data Retention were still fetched or forwarded to Chinese labs, and OpenRouter removed the three providers after being notified. Separate honeypot work from July 7 to November 7 saw attackers use 155 planted keys from 12,353 distinct IPs with a median theft-to-use time of 37 minutes, mostly for SES and SNS quota checks, plus S3 listing, Secrets Manager and Parameter Store lookups, and Bedrock enablement. Verify Zero Data Retention is enforced downstream and move leaked keys to automated revocation.

[NEW] CNN reported on November 17 that NSANet, the classified internal network used by the NSA, was down, with six people familiar confirming the outage and workers told to arrive at staggered times while backup networks kept urgent intelligence flowing to the president traveling in Asia, in the [NSA network outage](stories/highly-classified-nsa-communications-network-is-down-cnn-sources/). The agency said there was no evidence of a cyberattack and later described temporary degradation during scheduled routine maintenance with mission-critical capabilities intact, while officials testifying to the House Homeland Security Committee pointed to routine technical issues behind the recent run of outages. Watch for an NSA after-action statement confirming the maintenance account and whether any rushed patch contributed.

[NEW] GnuPG disclosed CVE-2026-129975, a double free in GPGME triggered by an OpenPGP key with a crafted very long user ID, in the [GPGME flaw advisory](stories/gnupg-warns-critical-gpgme-flaw-could-expose-app-data-via-malici/). The bug sits in read_status and read_colon_line in src/engine-gpg.c, where a 1,024-byte buffer grows by realloc but the new pointer is written back only at function end, so an early callback return leaves freed memory that is freed again on engine release. Johan Carlsson found it, GitLab notified GnuPG on November 12, and the November 20 advisory ships the fix in GPGME 2.3.1 with Debian DSA-6646-1 and updated Gpg4win, Desktop, and VS-Desktop packages covering all software using GPGME before 2.3.0 including static builds. No exploitation has been reported, so inventory every application carrying its own GPGME copy and patch to the fixed builds.

[NEW] NebuSec demonstrated a lab exploit chain against Meta Muse starting from a single attacker-controlled webpage opened by the assistant's bundled Chromium during PDF export, in the [Muse webpage hijack research](stories/a-single-malicious-webpage-let-researchers-hijack-meta-muse-and/). The PDF export path ran without an IPC sandbox, letting the researchers use a V8 issue for code execution inside the runtime container and then generated Linux kernel exploits to escape to root in the user VM, after which weak Sentinel egress enforcement allowed conversation history and stored memories to leave for an external server without an approval prompt. The work stayed inside one user VM with no hypervisor or cross-tenant escape, and Muse fixed the issues before publication. Treat the architecture lessons as the value here since there is no active campaign, and check that egress controls cannot be bypassed from outside the container.

[NEW] Signal added a control that stops AI agents from reading private chats through screenshots on Android and iOS, according to the November 22 writeup, in the [Signal agent screenshot block](stories/signal-blocks-ai-agents-from-reading-private-chats-via-screensho/). Coverage frames it as a product change against agent-driven screen capture rather than a patched software flaw, and the story lists no CVE. Watch whether the block holds across accessibility and capture path updates, since screenshot access lets a device-level agent read message content without any user forwarding it.

[NEW] Microsoft confirmed that the Entra Connect Health API was readable by unauthorized callers from July 23 until a server-side fix on November 19, with detection on November 9 and the investigation closing November 20, in the [Entra Connect Health exposure](stories/microsoft-confirms-entra-connect-health-exposure-of-tenant-metad/). Exposed tenant metadata included technical contact and administrator email addresses, tenant IDs, display names, initial domains, country codes, region, license tier, sync status with last sync timestamps, and onboarding status, plus a stale expired certificate in the pksCertificate field, while passwords, hashes, tokens, valid keys, topology, and subscription data were not exposed and no unauthorized configuration changes were reported. No customer patch applies, so confirm the tenant in Azure Service Health, run the read-only Connect Health scripts, review Entra audit and sign-in logs with Azure Activity Logs for anomalous administrator activity, and enforce phishing-resistant MFA on privileged accounts.

[NEW] Apache disclosed CVE-2026-133325 on November 19, a critical peer authentication bypass in Tomcat clusters secured with TLS 1.3 and TLS-PSK that lets an unauthenticated node join the cluster because the pre-shared-key path does not validate peer identity, in the [Tomcat cluster bypass](stories/apache-tomcat-cve-2026-133325-authentication-bypass-in-clustered/). Affected releases are 11.0.28 through 11.0.29, 10.1.62, and 9.0.124, with fixes pending in 11.0.30, 10.1.63, and 9.0.125 and TLS 1.2 with TLS-PSK as the interim mitigation. Exploitation needs network access to the cluster communication service and Apache reported no active exploitation, so restrict cluster ports, check membership logs for unexpected nodes, and apply the workaround until the fixed releases ship.

[NEW] Icelandic host 1984.hosting shut down every service on November 20 after what it and CERT-IS called a large, well-planned attack on its IT infrastructure, in the [1984 hosting shutdown](stories/large-scale-cyberattack-forces-icelandic-company-1984-ehf-to-shu/). RUV put the customer count in the tens of thousands and called 1984 probably the largest Icelandic web and email host with about 65 percent of customers abroad, while outlets reported smaller intrusion attempts starting November 14 that peaked November 19 and sites with Palestine-indicating domain names damaged first. Email and DNS were prioritized for return under special monitoring while web hosting, VPS, and the control panel stayed dark. No actor, ransom demand, CVE, entry vector, or data theft confirmation has been published, so read the status page rather than treating restoration as proof of integrity, rotate reused credentials and tokens, and check MX and NS records plus mail-forwarding and site files for unauthorized changes.

[REVISIT] Attackers breached a Russian organization through CVE-2026-76466, the CVSS 9.8 unauthenticated remote code execution flaw in clustered Cisco Expressway Core and Edge, soon after researcher Nicolas Krassas published a proof of concept and fleet detector, in the [machine-speed attacks assessment](stories/machine-speed-attacks-require-machine-speed-detection-and-respon/). Persistent cookies plus insufficient client certificate validation reach the database service and invoke RPC commands as root, Cisco fixed it in Expressway X15.5.20 with no workaround on X14 or earlier, and CISA added it to KEV in the November 20 batch. Prioritize the fixed release on exposed Expressway clusters and hunt for post-exploitation database and RPC traces, since the vendor text still says it is unaware of malicious use while incident reports say otherwise.

[NEW] RIKEN confirmed a cyberattack on November 13 that took Fugaku, Japan's flagship supercomputer, offline, with a November 22 follow-up describing a network intrusion with data leakage, in the [Fugaku intrusion](stories/riken-shuts-down-fugaku-after-status-dashboard-intrusion-and-ssh/). Intruders reached internal servers through the internet-facing status dashboard, and the source URL names SSH key theft as part of the intrusion. No CVE, actor attribution, or exposed record count has been published, so watch for RIKEN's own incident statement, confirmation of which keys were taken, and word on when Fugaku returns to service.
