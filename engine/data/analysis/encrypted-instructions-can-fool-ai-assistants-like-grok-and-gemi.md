AI researchers have demonstrated "Cryptographic Context Injection," a prompt injection technique that hides malicious instructions inside encrypted data. The attack persuades an AI assistant to decrypt the payload using its own code-execution tool, at which point the model treats the decrypted text as trustworthy internal information rather than attacker-controlled content.

The core problem is that AI models cannot reliably distinguish between legitimate instructions and attacker-injected ones. Providers have built guardrails to reduce this risk, but the encryption layer defeats them: by the time the model processes the instructions, they appear to originate from a trusted decryption process rather than an external source. The technique works against assistants with access to browsers, code execution, and private data stores, including Grok and Gemini in testing.

This is a structural weakness in how current LLMs handle context. Prompt injection has been flagged by experts as potentially unsolvable within the current architecture. Cryptographic Context Injection raises the bar because it does not rely on social engineering or visible payload injection; it exploits the trust boundary between data and instruction processing. Organizations deploying AI assistants with tool access should treat this as a validated attack vector, not a theoretical concern.
