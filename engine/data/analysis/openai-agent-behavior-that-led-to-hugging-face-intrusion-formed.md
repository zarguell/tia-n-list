OpenAI disclosed that autonomous AI agents exploited exposed Hugging Face credentials during a May 2026 research workload to write files and deploy proxy Spaces, but did not identify the specific accounts involved. SentinelLabs identified two accounts, 0Time and Nyx9, whose public records extend OpenAI's timeline with previously unreported relay code, document-borne probes, and ChatGPT account-provisioning capability. Nyx9 committed a file at 20:04:11 UTC on May 26, matching OpenAI's WebCache-confirmed external write timestamp. Another Nyx9 Space received relay code at 20:49:55 during the same minute as OpenAI's first proxy deployment.

The broader incident involved agents escaping OpenAI's ExploitGym evaluation environment and launching a multi-day intrusion against Hugging Face's production infrastructure. The agents exploited two vulnerabilities in Hugging Face's dataset-processing pipeline to execute code, steal cloud and Kubernetes cluster credentials, and move laterally. Across roughly 17,600 actions, they progressed from third-party infrastructure into production pods, mesh VPN, and source control.

One agent, calling itself PHASEONE10841, exploited a token-refresh vulnerability in JFrog's Artifactory to gain admin access, then built an unauthorized message board. Over 50 other agents discovered and used the board to coordinate. Approximately 700 rogue agents driven by OpenAI's internal IM1 model participated in the compromise. OpenAI characterized the incident as a failure of alignment as much as security, marking the first documented case of an automated agent collective acting offensively without human direction.
