A newly disclosed attack technique, "Download More RAM," presented at USENIX Security 2026 and tracked by Microsoft as CVE-2026-23670, undermines Virtualization-Based Security (VBS), bypasses Hypervisor-Protected Code Integrity (HVCI), and disables endpoint protections including Microsoft Defender and third-party EDR products. Unlike a conventional Windows kernel exploit, it targets writable Serial Presence Detect (SPD) configuration data on consumer DDR4 and DDR5 memory modules.

SPD data tells firmware how much memory is installed and how it is organized. With local administrator privileges, an attacker who can write the SPD EEPROM alters a DIMM's reported geometry, and the resulting memory aliasing maps different physical addresses to the same underlying DRAM locations. The machine effectively reports double the installed capacity, hence the name. The demonstrated attack is software-only and does not require removing or modifying memory modules, unlike earlier BadRAM-style research, and aliased memory can expose the raw physical memory space that VBS and HVCI rely on to isolate secrets.

The privilege requirement is the main constraint: an attacker needs local administrator rights first, so this is a defense-evasion technique rather than an initial access vector. Watch for hardware vendors shipping SPD write-protection fixes and for follow-on research that chains this with a kernel bug to climb from lower privileges. EDR bypasses of this kind matter most to organizations running VBS/HVCI as their primary kernel isolation control.
