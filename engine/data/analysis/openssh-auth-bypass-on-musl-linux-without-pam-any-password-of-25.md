OpenSSH 10.6p2, released 2026-11-05, ships a workaround for a pre-authentication sshd bypass on Linux systems built on musl libc without PAM, Alpine Linux among them. On accounts whose /etc/shadow password field is '*', any password of 257-1024 bytes authenticates, so root, key-only deploy users, LDAP accounts, and default users on Alpine cloud images accept any password of that length with no valid credential. Researcher Ozgün Kultekin of Wakefield disclosed the issue and said it has existed since 2016; his testing covered about 17,600 authentication attempts across twelve builds, and only the musl-plus-no-PAM combination accepted the long passwords. Alpine has pushed fixed OpenSSH packages for every supported release back to 3.16.

A successful attack gives anyone who can reach port 22 an authenticated session as an account that policy intended to be password-disabled, with no brute force and no failed-login events to trigger alerts. That makes the bypass invisible to the usual failed-authentication monitoring, and nothing in the event record shows any exploitation telemetry, so active use in the wild is unmeasured rather than absent. Exposure is broad by Alpine standards: every supported release back to 3.16 is affected, so older container images and cloud instances stay vulnerable until explicitly re-patched. This deserves attention beyond a routine patch announcement because the bug authenticates the attacker cleanly; the first defender-visible sign may be an unexpected active session instead of a crashing service.

Patch OpenSSH to 10.6p2 or install Alpine's fixed packages for all supported releases back to 3.16. Until patched, set PasswordAuthentication=no in sshd_config and restart sshd, or disable sshd entirely and restrict port 22 to trusted networks or a VPN. Hunt in /var/log/auth.log and sshd audit logs for successful password authentications against accounts with a '*' shadow field, especially long passwords of 257-1024 bytes, because the musl code path may not appear in PAM logs; alert on new sessions to root or disabled service accounts from unexpected source IPs.

Watch for confirmed exploitation telemetry from GreyNoise, Shodan, or honeypot networks, for a CVE assignment, and for a full fix beyond the 10.6p2 workaround. Also watch for exploit-kit integration now that disclosure is public; until then, prioritize internet-facing Alpine hosts running sshd on musl without PAM.
