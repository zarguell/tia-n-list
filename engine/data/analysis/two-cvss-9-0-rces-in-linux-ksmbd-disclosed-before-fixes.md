Two CVSS 9.0 remote code execution flaws in the Linux kernel's in-kernel SMB server, KSMBD, were disclosed on the public kernel mailing list before mainline fixes existed. ZDI-CAN-33774 is a race condition reachable without authentication on any host with KSMBD enabled on port 445. ZDI-CAN-33549 is an integer underflow in the SMB Direct (RDMA) path that requires an RDMA-capable network interface. Both were posted to the public list rather than the private security list, apparently by mistake, with Greg Kroah-Hartman responding to each report.

The pre-authentication vector in ZDI-CAN-33774 is the sharper edge: any internet-reachable Linux host running KSMBD on TCP 445 is exposed without credentials, and the public disclosure compresses the window between knowledge and patch to days. KSMBD is not the default Samba userspace server, but it ships in many distribution kernels and is enabled on appliances and small servers where operators may not track kernel advisories closely. That gap between "not default" and "widely deployed but unmanaged" is where this story earns its score.

Defenders should disable KSMBD where it is not required, restrict TCP 445 at the network boundary, and track the kernel 7.5 branch where a fix for ZDI-CAN-33549 is queued. Hunt for unexpected SMB sessions and RDMA traffic to port 445, plus kernel crash or oops traces in dmesg referencing ksmbd. Watch for a fast-tracked mainline patch and for any evidence of in-the-wild exploitation before fixes ship.
