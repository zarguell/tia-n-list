Symantec's Threat Hunter Team found a 41-module PowerShell toolkit running under a webshell on an IIS server at an unnamed major African stock exchange on September 20, 2026, from 08:44 to 08:47 UTC, a burst of 3 minutes 12 seconds. The modules pulled Group Policy Preferences passwords from SYSVOL, searched web roots and application directories for AWS keys and database connection strings, mapped IIS sites and application pools, and enumerated SharePoint, SCCM and TFS servers. Four modules tested the investment API with a guessed password, a reused bearer token and several API keys including a blank one, while others probed a securities depository gateway over IP with a manually set Host header and disabled certificate validation. Symantec called AI authorship likely because one scaffold and a DNS exfiltration loop were copied across all 41 scripts, but it could not identify a model or attribute the toolkit to a group.

That scaffold matters more than the AI label. Each module hex-encoded its output, split it into 50-character chunks and resolved each chunk as a subdomain under one token on the public oast[.]pro testing service, so the exfiltration trail sits in recursive resolver logs rather than web or proxy logs; a defender hunting only HTTP egress would see nothing. The sweep also followed access that Symantec traces to April 2026, when six persistence implants attributed with high confidence to Witchetty were already on the server, which makes this a late-stage action by an occupant rather than an entry event. Four modules against an investment API, a check on one investor's number, and interest in source code and employee data leave financial and espionage motives both open; Symantec could not confirm that any credential worked and found no privilege escalation or data theft.

Treat the IIS host as compromised since at least April 2026: pull it from service and hunt web roots and application directories for the shared error-handling line, try/catch, hex encoding, empty-output sentinel and byte-identical DNS loop. Rotate the bearer token, every tested API key, and any Group Policy Preferences password, AWS key or database connection string reachable from SYSVOL or the application directories; the blank key may have been a control and one module submitted an invalid credential deliberately, so neither alone proves a working secret. Review authentication at the investment API and depository gateway for 08:44 to 08:47 UTC on September 20, 2026, focusing on IP connections with a manual Host header and disabled certificate validation. No CVE or product version is attached to this intrusion, so there is no patch number to quote; keep ProxyShell and ProxyLogon patched on Exchange-facing systems given the 2022 Witchetty campaign against the same exchange, and use Symantec's protection bulletin for current detections.

The assessment changes if Symantec or the exchange confirms that a credential worked, identifies data that left through the DNS channel, or names the exchange and the affected accounts. It also changes if the toolkit is attributed to Witchetty rather than a second operator with the same access, or if the same scaffold appears at other market operators.
