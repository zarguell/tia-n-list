Security.com and Symantec reporting describes a credential-hunting intrusion at a major African stock exchange. Attackers ran a 41-module PowerShell toolkit under a webshell on an IIS server between 08:44 and 08:47 UTC, a span of 3 minutes 12 seconds. The modules tested credentials, a reused bearer token and API keys against the exchange's investment API and a securities depository gateway.

The toolkit's structure and code carried hallmarks of AI authorship, according to the reporting, but the available events do not name the exchange, identify the operators or confirm that any credentials were successfully used. The target set still matters: investment APIs and depository gateways sit close to trading and settlement workflows, so valid tokens there can offer more than ordinary network access. The speed of the module execution also points to scripted validation rather than interactive probing.

Watch for follow-up from Symantec or the exchange that names the victim, confirms the webshell path or lists any compromised accounts. Defensive priorities are the IIS webshell, the bearer token and API keys used in the tests, and any authentication logs from the two market-facing endpoints during the 08:44 to 08:47 UTC window.
