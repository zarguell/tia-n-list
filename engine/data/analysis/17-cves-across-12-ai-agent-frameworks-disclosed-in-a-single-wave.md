A coordinated disclosure on October 19-20, 2026 published 17 CVEs across 12 AI agent and LLM orchestration frameworks, and six of them are unauthenticated remote code execution at CVSS 9.8: Piflow 2.0.0-2.0.1 (CVE-2026-109442, POST /chat and /chat/stream reaching an unsandboxed shell tool), Langchain-Chatchat through 0.3.1.3 (CVE-2026-75128, POST /tools/call), DB-GPT through 0.8.2 (CVE-2026-77932 and CVE-2026-77933, mock admin role plus hardcoded MySQL root on port 3306), Letta through 0.16.8 (CVE-2026-77936, LETTA_SERVER_SECURE absent from default compose), and Cognition (no auth on REST/SSE). Five more sit at CVSS 8.8 behind an account that is sometimes self-registrable (JoySafeter, OpenSRE, Aix-DB, EvoScientist, Coze Studio), and the remainder are IDOR and isolation failures such as LangAlpha's shared Docker bridge. The common root cause is not a shared library but three repeated design choices: authentication defaults to off, tool execution is unsandboxed, and approval gates are missing or return True unconditionally.

The victim impact is direct host compromise from a single HTTP request, because these frameworks expose a chat or tool endpoint and let it reach the operating system with no credentials, no sandbox, and no human approval. The exposure is not theoretical for the six 9.8 flaws: any internet-facing Piflow, Langchain-Chatchat, DB-GPT, Letta, or Cognition endpoint is an unauthenticated shell, and DB-GPT additionally publishes MySQL root on all interfaces. What makes this cluster stand out among today's disclosures is that twelve independent projects with separate maintainers converged on the same insecure default pattern, so a defender who patches one product has not reduced risk across the others. The numbers matter: six unauthenticated RCEs, five authenticated RCE or approval bypasses at 8.8, and three design failures repeated in every product, with seven of the twelve projects having no published fix at disclosure time.

Patch where fixes exist: Cognition 0.13.0, EvoScientist 0.2.5, Langflow 1.12.5, OpenSRE 0.1.2026.10.20, and Coze Studio 0.5.0 and 0.5.2. For the seven without a published fix, put an authenticating reverse proxy in front of the agent API, bind DB-GPT's port 3306 and Letta's PostgreSQL port to localhost, replace the hardcoded DB-GPT MySQL root password, set LETTA_SERVER_SECURE explicitly, strip client-supplied tenant headers such as X-User-Id at the proxy, and place each tenant's sandbox on its own Docker network with inter-container traffic denied. Hunt for unauthenticated POST requests to /chat, /tools/call, and /api/v1/chat/react-agent, unexpected connections to TCP 3306 from outside the host or the dbgptnet bridge, MySQL authentication in container logs from unknown source IPs, and subprocess environments that inherit LLM API keys or database credentials. Remove execution tools such as the Langchain-Chatchat shell tool from the default registry unless the deployment requires them, and verify that approval gates are actually reached on the execution path rather than merely present in the codebase.

Watch for vendor advisories or releases that fix the seven remaining products, for CISA KEV or EPSS movement on these CVEs, and for exploitation telemetry tying the unauthenticated RCEs to scanning or to chaining of CVE-2026-77932 with CVE-2026-77933 for full host control. A second signal to track is whether shared-bridge and header-trust flaws such as LangAlpha's Docker bridge and Letta's X-User-Id bypass produce confirmed cross-tenant incidents, which would move those issues from design debt to active breach material.
