Zoom has patched four vulnerabilities that let a malicious meeting participant execute code on another attendee's device, crash their client, or access sensitive files. The most serious, CVE-2026-53413, is a zero-click remote code execution flaw in Zoom's annotation engine, rated high severity with a CVSS score of 8.3. It can be triggered without the victim clicking a link, accepting a prompt, or downloading anything, beyond joining the meeting.

The root cause is a missing bounds check in the annotation function of Zoom Clients, found by the research team A Security and dubbed Zoomsday. A zero-click RCE in a tool used for external and cross-organization meetings is a serious exposure: the victim cannot decline the interaction. Zoom has released updates, so the immediate action is to update all Zoom Clients and treat any meeting with untrusted participants as a potential delivery vector until patching is verified across the fleet.

Later reporting expands the flaw set to three annotation-data processing bugs, CVE-2026-53413, CVE-2026-53414, and CVE-2026-53415, with affected versions spanning Zoom Workplace before 7.1.5 and 7.0.6 depending on release branch, VDI Client for Windows before 7.0.11 and 6.6.16, Zoom Rooms before 7.1.5, and Meeting SDK before 7.1.5. Watch for exploit code in the wild now that the full affected version list is public, and confirm patching on VDI and Rooms deployments, which are easy to miss in a Zoom client update sweep.
