Security researchers at Hacktron disclosed a two-vulnerability chain that compromised OpenAI employees' ChatGPT and Codex accounts, providing access to OpenAI's internal GitHub monorepo. The attack combined a heap buffer overflow in libheif (an image decoding library used by Discourse, the platform running community.openai.com) with an SSO misconfiguration in OpenAI's identity infrastructure. The entire chain from initial discovery to internal repo access took less than 72 hours.

The libheif vulnerability existed because Discourse's Docker image, based on Debian 12, shipped libheif version 1.19.7, which contained an unpatched heap overflow. Discourse used ImageMagick to process HEIC files, exposing the vulnerable parser to attacker-controlled input. The researchers used Claude Opus 5 to develop a reliable exploit within hours of the model's release, achieving code execution on the Discourse forum. From there, the OpenAI SSO flaw allowed them to take over any active forum user's ChatGPT account without interaction, since the forum accepted OpenAI SSO logins and the SSO flow did not properly bind accounts.

The researchers demonstrated impact by opening a pull request in OpenAI's internal monorepo through a compromised employee's Codex account. OpenAI patched the SSO issue within 14 hours of disclosure and awarded a $6,500 bounty. Discourse patched the libheif issue and added ImageMagick sandboxing. The broader finding is that libheif, used across Slack, Meta, GitHub Enterprise, and many Node.js frameworks, had the same vulnerability class across multiple versions. Debian 13 also shipped the vulnerable version until August 8. The researchers spent under $3,000 in AI tokens across the entire campaign.
