Jellyfin 12.0, released September 7, patches multiple security vulnerabilities in the open-source media server. The most serious fixes address path traversal-style weaknesses that could let crafted requests access files outside intended directories, potentially exposing configuration data, credentials, or unrelated host files. For self-hosted media platforms where the server runs with broad filesystem access, this class of flaw is particularly risky.

Additional fixes cover cross-site scripting (XSS) in the web client that could let attacker-controlled JavaScript execute in other users' browser sessions, exposure of the setup wizard on misconfigured instances to unauthenticated re-execution, insecure plugin package handling that accepted packages with unsafe names, and incomplete enforcement of parental-control restrictions.

The update also includes database migrations and breaking API changes, so administrators should plan the upgrade carefully. Self-hosted Jellyfin instances exposed to the internet or shared across multiple users should prioritize this update, especially those running older versions where the XSS and file-access flaws could be chained for deeper compromise.
