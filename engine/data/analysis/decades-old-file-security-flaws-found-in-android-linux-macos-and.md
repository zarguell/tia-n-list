Researchers at Graz University of Technology presented "File Notification Attacks" at ACM CCS 2026, showing that the file-change notification systems built into Linux, Android, Windows, and macOS (inotify, FSEvents, ReadDirectoryChangesW, and siblings) leak other users' activity to any local process with read access to a watched directory. No elevated privileges are needed and file contents are never exposed, but file names and event timing reconstruct user, application, and system behavior. Demonstrations include cross-user inter-keystroke timing over SSH, visited-website identification, and on Android a no-permission app spying through per-app storage bypasses. Watching /dev input devices reveals when keys are pressed, and in tests with seven typists keystroke detection scored 93.1 to 100 percent.

Vendor responses are partial. Microsoft's fix for CVE-2025-21197 and CVE-2025-27738, shipped on or after April 8, 2025, adds a FILE_LIST_DIRECTORY access check before reporting changes, but it is disabled by default and must be enabled via the EnforceDirectoryChangeNotificationPermissionCheck registry or group policy value. Linux mainline commit 635bc4def026 from December 15, 2025 stops fsnotify ACCESS/MODIFY delivery to parent-directory watchers for special files such as /dev, yet events still flow via utimensat, so the mitigation is incomplete. NVD's CVE-2025-68788 record, published January 13, 2026, shows stable kernels unaffected only from 5.10.248, 5.15.198, and 6.1.160 onward, and Siemens flags the SIMATIC S7-1500 CPU 1518-4 PN/DP MFP up to V3.1.6 as affected.

The finding turns a routine OS feature into a side channel that survives sandboxing, since most Android attacks need no permissions at all. Watch whether Microsoft flips its fix on by default, how quickly industrial and mobile vendors backport the kernel fixes, and whether notification APIs gain mandatory access checks in future OS releases.
