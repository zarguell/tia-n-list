Researchers at Graz University of Technology documented how file-change notification APIs built into Linux, Windows, macOS, and Android leak other users' activity to any unprivileged local process. The work, "File Notification Attacks," was presented at ACM CCS 2026 and spans inotify, FSEvents, ReadDirectoryChangesW, and the Android per-app storage model. The attacker only needs read access to a watched folder, not to the files inside it: directory events reveal file names and event timing, which is enough to reconstruct what a victim is doing.

The demonstrated leaks are concrete. Watching the folders that hold keyboard device files exposes keystroke timing, and with seven test typists the attack detected keystrokes at 93.1 to 100 percent accuracy, enough to reconstruct typed text given two decades of keystroke-timing research. The same templating approach identifies application launches, visited websites, SSH sessions via cross-user inter-keystroke timing, USB usage, VPN activity, and printing. On Android, an app with no permissions can abuse per-app storage bypasses.

Vendor responses are uneven. Linux merged commit 635bc4def026 by Amir Goldstein on December 15, 2025, stopping fsnotify from delivering ACCESS/MODIFY events to parent watchers for special files such as /dev, with stable branches unaffected from 5.10.248, 5.15.198, and 6.1.160 onward; NVD tracks the issue as CVE-2025-68788 and Siemens flags the SIMATIC S7-1500 CPU 1518-4 PN/DP MFP at V3.1.6 and earlier. The Linux fix is explicitly partial, since utimensat still generates parent events. Microsoft documented the Windows side as CVE-2025-21197 and CVE-2025-27738 and shipped a FILE_LIST_DIRECTORY access check in updates from April 8, 2025, but it is disabled by default behind the EnforceDirectoryChangeNotificationPermissionCheck policy value, and Microsoft told researchers it does not consider the behavior a security vulnerability.

Watch whether organizations actually enable the opt-in Windows check, whether the remaining Linux event paths get closed, and whether Android addresses the permission-free variant. Multi-user servers, shared workstations, and converged IT/OT hosts running Siemens hardware have the most exposed threat model, since any low-privilege account or no-permission app becomes a surveillance implant.
