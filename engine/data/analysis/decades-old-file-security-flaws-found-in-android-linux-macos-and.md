Researchers from the Institute of Information Security at Graz University of Technology (Sudheendra Raghavena Neela, Xufan Zhao, Jeanette Angelika Wultsch, Hannes Weissteiner, Stefan Gast, Florian Draschbacher, Daniel Gruss) present "File Notification Attacks" at ACM CCS 2026 in The Hague, with the project documented at inoti.fyi, where coverage in English and French restates the core finding: the file notification systems in every major OS (Linux inotify, Android FileObserver, Windows ReadDirectoryChangesW, macOS File System Events) leak information about other processes' activity to any local process holding only read permission, no file contents required. The flaws date back roughly two decades, matching each API's introduction between 2005 and 2008.

The platform-specific findings are concrete. On Linux, watching a readable parent directory reports events on unreadable children, so a watcher on /dev/input or /dev/pts exposes cross-user inter-keystroke timing over SSH, and a watcher on /usr/bin/pkexec enables a fake password prompt over the real one on KDE Plasma under Wayland. On Android, FileObserver bypasses the FUSE per-app storage view, letting an unprivileged app log another app's private folder; demonstrated against WhatsApp, it reveals when images, videos, voice notes, and documents arrive, are sent, or are deleted, file names included. On Windows, a watch on C:\ reports full paths of every file touched system-wide regardless of permissions; against Firefox's per-site storage directories, an attacker can identify visited websites among the top 1000 with a 97.8 percent F1 score.

Mitigation is uneven. The Linux issue is assigned CVE-2025-68788 and partially mitigated (no access/modify events on character files) in kernels 5.10.248, 5.15.198, 6.1.160, 6.12.65, 6.6.120, and 6.18.3. Microsoft called the Windows behavior an undocumented feature, though an April 2025 fix by Sébastien Huneault provides an EnforceDirectoryChangeNotificationPermissionCheck registry policy that stays disabled by default, so the attacks work out of the box. Android and macOS have no fixes; KDE says focus-stealing prevention is not a security mechanism. The researchers state they are unaware of in-the-wild exploitation, and attacks need a local cross-user foothold or a supply-chain-compromised package. Watch for Windows users adopting the registry policy, Android patches, and the techniques showing up in infostealer or malware tooling.
