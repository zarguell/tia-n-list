ReliaQuest disclosed that Microsoft 365's RejectDirectSend protection can be bypassed by sending email with an empty SMTP envelope sender (MAIL FROM:<>). RejectDirectSend is an Exchange Online control designed to block unauthenticated Direct Send messages that claim to originate from an organization's own domain. The control checks the domain in the SMTP envelope sender. When the envelope sender is empty, there is no domain to evaluate, so the check passes silently. The visible From address can still display any trusted internal identity, such as an executive or IT support address.

In controlled testing, ReliaQuest sent two unauthenticated messages directly to an M365 tenant with RejectDirectSend enabled. Both used the same internal-looking From header, recipient, and SMTP session settings. The only difference was the envelope sender. Messages with an empty MAIL FROM bypassed the control entirely. This is not a software vulnerability in Microsoft's code but a design limitation in how the control evaluates Direct Send traffic.

Direct Send is commonly used by printers, scanners, and applications to relay messages within a tenant without requiring credentials. The bypass means that any external actor can craft phishing emails that appear to come from internal users, even with RejectDirectSend enabled. Organizations relying on this control as a phishing defense should evaluate additional mitigations, such as DMARC enforcement, external email tagging, or transport rules that inspect the actual connecting source rather than the envelope sender alone.
