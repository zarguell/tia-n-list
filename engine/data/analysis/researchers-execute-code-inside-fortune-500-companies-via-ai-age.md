Researcher Alon Hertz demonstrated a supply chain attack vector through llms.txt files, the emerging standard for guiding AI coding agents toward documentation and installation commands. In a controlled experiment, Hertz registered unclaimed package names referenced in official corporate llms.txt files and achieved code execution inside a Fortune 500 network within four minutes. The research surveyed 8,565 llms.txt files across 6,214 domains representing roughly 15,000 companies.

The critical flaw is not misconfiguration but abandonment: 237+ instances where official files instructed agents to install exact-match package names that were never registered by the vendor on PyPI, npm, RubyGems, NuGet, crates.io, or Packagist. Hertz claimed these names and embedded a benign phone-home beacon, with the first callback arriving from inside a Fortune 500 environment almost immediately. Expired subdomains on Render, Vercel, Fly, and Netlify were also exploitable.

This represents a new class of supply chain risk specific to AI-assisted development. Google has institutionalized llms.txt through a Lighthouse "Agentic browsing audits" category in Chrome DevTools, accelerating adoption. The attack surface is broad: any organization publishing llms.txt with references to unclaimed packages creates an execution path that AI coding agents will follow. Unlike traditional typosquatting, this abuse leverages the organization's own legitimate documentation as the attack vector.
