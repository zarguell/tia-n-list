GHSA-p4f5-76q4-ffq7 is a code-injection flaw in Vite's resolver, not in the static output of `vite build`. The `__vite-browser-external:` and `__vite-optional-peer-dep:` virtual modules embedded the URL-derived module ID without escaping, so a crafted request can inject JavaScript into code Vite trusts; the advisory classifies this as CWE-116 and rates it CVSS v4 9.1 with no CVE assigned. Published on 10 November 2026 and credited to g2hsec, spansh, martinpriest and zooyeon, it affects vite 4.0.0 through 6.4.5, 7.0.0 through 7.3.7, 8.0.0 through 8.3.6 and vite-plus up to 1.5.0, but only when the dev server is started with `--host` or `server.host`. Fixed versions are 6.4.6, 7.3.8, 8.1.7, 8.2.5, 8.3.7 and vite-plus 1.5.1, with the Vite 8 fix carried in Rolldown 1.2.17 or 1.1.7.

The score of 6.4 and single-source pickup understate a two-stage primitive: injected imports pass the `server.fs` allow list and make files outside the project readable, while Vite's eval path for `new Worker` and `import.meta.glob` executes the injected code in the Node process, with `globalThis.process.getBuiltinModule` defeating the blocked globals. A reachable dev server therefore hands over source, `.env` files, cloud credentials and SSH agent access, and a public PoC lowers the work to copying a request path. No count of exposed hosts appears in the reporting, so the denominator is unknown; the exposed set is developer laptops on shared networks, Docker and devcontainers with published ports, cloud IDEs and CI preview boxes, not the built site. It outranks other same-day items because the precondition is one config flag and the payload is a request, not a race or a user click.

Patch by the resolved version in each lockfile: `npm ls vite`, `pnpm why vite` or `yarn why vite` first, since frameworks pin their own Vite, then install the fixed line rather than trusting a top-level dependency. Until that is done, remove `--host` and `server.host`, bind to localhost, and put required LAN access behind an authenticated tunnel instead of a raw published port such as 5173; `vite preview` on a built bundle is safer for demos. Hunt proxy and dev-server access logs for request paths containing `/@id/__vite-browser-external:` or `/@id/__vite-optional-peer-dep:`, especially with embedded import statements or newlines, and for follow-on `/@fs/` reads of files that previously returned 403 Restricted. Treat any matching host as compromised and rotate credentials and keys readable by the developer account.

Two developments would change the assessment: a CVE assignment or KEV listing, neither present in the advisory, would move this into mandatory patch cycles; telemetry showing scans for the `__vite-browser-external` module ID would turn an exposed-host problem into active exploitation. That distinction matters because the separate CVE-2026-39364 Vite dev-server file-read campaign already produced about 35,325 scanning events in August 2026 in F5 Labs data, so the targeting pattern is established even though no exploitation telemetry for this GHSA has surfaced.
