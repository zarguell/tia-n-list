A critical buffer overflow in TianoCore EDK II's PXE network-boot driver, tracked as CVE-2026-97631 with a CVSS score of 9.5, allows an unauthenticated attacker on the network to execute arbitrary code before the operating system loads. The flaw sits in ICMP error handling in the NetworkPkg/UefiPxeBcDxe component: ICMP error messages longer than 504 bytes overflow a fixed buffer during IPv4 or IPv6 PXE boot, corrupting DXE-phase firmware memory. Because EDK II is the reference UEFI implementation behind most server firmware, the impact spans a large share of servers worldwide.

The bug is reported to have been present since around 2010. A GitHub security advisory published October 22, 2026 discloses the issue, and pull request #13200 in the edk2 repository documents the root cause. EDK II master as of September 14, 2026 is affected, and the advisory does not list an upstream patch yet. AMI reportedly proposed a fix before the planned coordinated disclosure, while TianoCore had aimed for a January disclosure.

The public write-ups note that an attacker able to send crafted ICMP error messages to a PXE-booting machine can run pre-boot code, and that the fix going public in a pull request months ahead of schedule accelerated exposure. Defenders should treat PXE network boot as high risk until firmware updates ship from their hardware vendors.
