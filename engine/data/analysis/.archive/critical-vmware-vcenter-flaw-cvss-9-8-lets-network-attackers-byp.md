Broadcom's VMSA-2026-0009, issued 19 November 2026, rates CVE-2026-123890 at CVSS 9.8: an authentication bypass in the VMware Directory Service reached through the vmdird DCE/RPC interface on port 2012. Research credited to Mandiant describes an unauthenticated SRP-6a session key disclosure using predictable UUIDv1 identifiers, which yields a session as administrator@vsphere.local on vCenter 7.x, 8.x, 9.0 and 9.1, including builds embedded in Cloud Foundation, vSphere Foundation and Telco Cloud. Broadcom reports no attacks and lists no workaround; the researcher timeline says ARMORY CASTLE, formerly UNC5221, ran the BONESAW exploit against vCenter in early September 2026. The July bug CVE-2026-59309 is a separate LDAP flaw on ports 389 and 636, so the July patches do not cover this one.

The gap between "no attacks reported" and September exploitation is the story. vCenter holds the keys to the ESXi estate: Mandiant observed BONESAW copying /storage/db/vmware-vmdir/data.mdb, extracting the STS SAML signing key and creating an SSO administrator, while SAWSNAKE forged assertions that bypass MFA. A flat management network is enough, because the actor reached vCenter from a compromised BeyondTrust appliance after scanning ports 9080, 5480 and 2012, so internet exposure is not the only risk. The July sibling flaw drew exploitation five days after disclosure across 361 IP addresses in 47 countries, and this bug was already in use for two months before its advisory. That history is why this outranks the other thirty items: a 9.8 control-plane bypass with demonstrated state-linked use and no fallback for systems that cannot patch immediately.

Patch to 9.1.1.0200, 9.0.2.0200, 8.0 U3m or VCF 5.2.5; vCenter 7.0 users need an extended support patch, and the updates are cumulative rather than available through Quick Patch. Teams partway through a VCF 9.1.1 upgrade must either move vCenter to 9.1.1 and apply 9.1.1.0200 there or wait for VCF 9.1.2, because 8.0 U3m and 9.0.2.0200 currently block that upgrade path. Restrict port 2012 to approved management hosts, block outbound Slack API traffic from the appliance, and forward VAMI and web logs off-box because the actor deletes on-appliance logs. Hunt for connections to 2012 from non-management addresses, reads of data.mdb, unexpected sps-*@vsphere.local administrators with Global Administrator, VAMI calls to /rest/appliance/access/ssh on port 5480, and the files ActiveSer.jsp, u.jsp, /tmp/123, /tmp/sss, /tmp/dbr and /usr/bin/vmtoolscs.

The assessment changes if Broadcom updates the advisory's exploitation status, if CVE-2026-123890 enters CISA KEV, or if public exploit code appears and port 2012 scanning rises. VCF 9.1.2 matters too: until it ships, the "Back-in-Time" upgrade trap gives operators a reason to leave a vulnerable appliance in place, and additional confirmed victims would move this from targeted espionage to a broader patch-and-evict event.
