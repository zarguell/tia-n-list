The FBI's FLASH-2026-111313-001, published November 13, 2026, describes ARTEX as an open-source Go framework that turns natural-language objectives into agent-executed reconnaissance, exploitation, privilege escalation and data theft, with Anthropic Claude, OpenAI GPT, DeepSeek, GLM, Grok and Kimi as interchangeable backends. The bureau dates criminal use to at least August 2026 and says some intrusions reached privileged access in under three hours. ARTEX was released on GitHub in July 2026 by a developer using the name Autumn-27, removed from the repository on October 8, 2026, and continues to circulate through community forks, localized builds, archived copies and a commercial ARTEX PRO edition. As of early November 2026, researchers counted more than 1,600 publicly exposed ARTEX consoles. The distribution model matters more than the exploit: a public repository and interchangeable model backends turn the framework into a shared criminal capability rather than one actor's tool.

The mechanism is orchestration, not a new exploit class, and the consequence is a decision window shorter than a human on-call rotation. The ConnectWise Cloud Backup compromise is the clearest case: Storm-0940 used ARTEX to accelerate scanning, password spraying and OAuth application abuse, then used application credentials that had already been granted to reach more than 2,250 downstream Microsoft 365 tenants without an interactive sign-in. Huntress counted at least 162 compromised tenants, and Microsoft telemetry recorded 151,000+ failed logons, a peak of 2,900 per minute on October 11, 327 accounts across eight organizations, and more than 200 successful sign-ins in under four minutes using four application credentials. The same framework powered the South Korean bank campaign that exposed roughly 67,000 people across at least seven financial institutions. The advisory's most important number is not the three hours but the 2,250 tenants: a vendor incident became a customer incident, and the customers who never touched ARTEX are the ones who inherit the access. That downstream blast radius is why this advisory matters more than the other AI-assisted intrusion stories of the week. The attack surface is the trust relationship, not the endpoint.

Defenders should start with identity telemetry, not malware signatures. Review service principal sign-ins, application credential additions and privilege changes in Microsoft Graph, follow ConnectWise's Cloud Backup containment guidance, keep affected applications disabled until restoration, and re-authorize tenants only through the new ConnectWise Cloud Backup for M365 application. Hunt for the ARTEX infrastructure CrowdStrike published: 38.244.50[.]120 on port 18899 with a /claude/CLAUDE.md file, the xcai[.]pro API proxy, and DeepSeek v4.1-flash, GLM-5.3 or Grok 4.6 in authentication and proxy logs. ConnectWise's initial status page listed 144.172.64.128 and the Python-urllib/3.12 and python-requests/2.31 user agents. The FBI's mitigations are rate limits on sensitive APIs, restricted access to cloud administration interfaces, and alerts for unusual bursts of automated requests, unexpected credential changes and large data transfers. If an ARTEX console is internet-exposed, assume the console is attacker-reachable and isolate it.

Two developments would change the assessment. The first is evidence that ARTEX forks such as Cairn or CyberStrikeAI, named in JPCERT/CC's October 23 update alongside nine attacker IP addresses, are being used in a second supply-chain compromise rather than direct intrusions; that would move the priority from perimeter hardening to software supply chain and OAuth consent governance. The second is disruption of the LLM API proxy layer, including xcai[.]pro and similar resellers, which raises the cost of running ARTEX at scale more than any single arrest. Until then, the FBI's warning that IP indicators go stale should be read as a statement about the tool's modularity: the infrastructure rotates, the orchestration layer does not.
