A threat actor operating under the handle "Satanic" published a 35 GB archive on a data-trading forum on August 18, 2026, containing Stripe secret API keys for 659 merchant accounts. The dataset covers 688,363 customers across 42 countries and includes 17,654 files: customer objects, charges, payment intents, checkout sessions, invoices, payouts, refunds, balance transactions, disputes, subscriptions, products, and pricing details. Records span January 2022 through June 2026. Of the 659 keys, 650 were live secret keys (sk_live) and nine were restricted keys. Metadata indicates 573 accounts could accept payments, 531 could make payouts, and 519 had both capabilities.

This is not a Stripe infrastructure breach. Attackers obtained merchant API keys through unknown initial access vectors, likely including infostealer infections on developer systems, keys committed to public repositories, exposed environment files, or compromised CI/CD logs. The keys were then used to pull data through Stripe's legitimate API. Researchers who reviewed the dataset confirmed its structure matches authentic Stripe API output but did not attempt live key validation or access merchant environments.

The leaked data does not contain raw card numbers (Stripe tokenizes those), but it does expose last four digits, card brands, expiry dates, funding types, issuing countries, and fingerprints. Combined with customer PII and transaction histories, this is sufficient fuel for targeted phishing, refund fraud, business email compromise, and payment-related social engineering at scale. With 519 accounts capable of both accepting payments and initiating payouts, attackers holding these keys could also create unauthorized charges or redirect funds before merchants rotate credentials.

What to watch: whether Stripe forces mass key rotation for the affected accounts, how quickly affected merchants detect and revoke the compromised keys, and whether the dataset spreads beyond the original forum post. The "free distribution" model (rather than sale) accelerates exposure, giving every copy-holder equal access. Any downstream use of these keys for unauthorized transactions will show up in merchant chargeback logs and Stripe's API abuse detection. The incident underscores that API key hygiene is a payment security control, not just a developer convenience issue.
