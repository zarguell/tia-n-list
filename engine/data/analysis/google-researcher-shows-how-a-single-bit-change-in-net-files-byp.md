Google Project Zero researcher James Forshaw published a write-up showing that a quirk in how the .NET Framework loads a program file let a local attacker run untrusted code past two Windows protections built to block it. The same loading behavior bypassed Oracle VirtualBox's process hardening on Windows hosts, tracked as CVE-2026-87268, and Windows code integrity, which is tracked under a separate identifier not given in the available event text. The reported trigger is a single bit change in a .NET file.

The condition is local, but the affected controls are the ones meant to keep untrusted binaries from executing and to harden a virtual machine process against a compromised host. No exploitation claim is reported. Watch for a CVE assignment for the code-integrity bypass, fixes or loading changes from Microsoft and Oracle, and the technical detail in Forshaw's write-up before judging real-world reach.
