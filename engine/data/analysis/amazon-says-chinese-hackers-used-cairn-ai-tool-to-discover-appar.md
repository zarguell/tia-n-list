Amazon Threat Intelligence assesses with moderate confidence that a Chinese-nexus actor used Cairn, an open-source autonomous penetration-testing framework, against universities in East Asia outside mainland China over roughly 48 hours starting September 8, 2026; the unauthenticated Cairn instance was found on September 10. The operator supplied target IP addresses and the goal to obtain shell access, and the agents planned and adjusted every step. A 16-hour, 148-action run against an unauthenticated Redis service included Log4Shell injection and SSRF mapping of a co-located Qdrant instance and failed, as did more than 30,000 credential guesses over six hours against a university GPU server after harvesting about 80 usernames from public directories. The success was MONAILabel: agents found a path traversal in an upload filename parameter, moved from API mapping to arbitrary file write in about 11 minutes, then wrote a Python reverse shell to sitecustomize.py and triggered a training endpoint to run it as root.

The important claim here is not that AI helped a hacker. It is that unknown-vulnerability discovery, exploitation and persistence happened inside one autonomous loop, and the victim's triage window was about 11 minutes. Amazon rated the bug a zero-day with high confidence because no advisory, issue, fix or prior database mention existed at discovery, and GitHub advisory GHSA-qc22-rmgc-vg94 now lists monailabel through 0.8.5 with authentication disabled by default under MONAI_LABEL_AUTH_ENABLE=False. That default makes ordinary research deployments exposed, not only careless ones. More telling, after the agents found the flaw the human supplied a proxy into a second university network running the same software, and Amazon infers the actor had already used the zero-day to compromise that server. Unit 42's CL-STA-1238 reporting, 25 operations against at least 19 organizations, and Google's aerospace intrusion show a repeatable capability rather than a lab curiosity.

Patch every MONAILabel instance by applying the change in Project MONAI pull request 1915 and the GHSA-qc22-rmgc-vg94 guidance; the advisory lists no patched package version and marks monailabel through 0.8.5 affected, so verify the running build rather than trusting a version string. Until that is confirmed, remove the datastore image and label endpoints from the internet, set MONAI_LABEL_AUTH_ENABLE=True, and restrict the API and training endpoints to known research networks. Hunt web and proxy logs for traversal sequences in the image parameter of datastore upload requests, unexpected writes to sitecustomize.py, Python processes spawned by training endpoints, and the September 8 to 10 addresses 142[.]4.98.145 and 142[.]4.107.34. Audit for publicly reachable Cairn panels and unauthenticated Redis or Qdrant services, the same exposure that let Amazon and NorForge reconstruct these operations.

The assessment changes if a patched MONAILabel release with a CVE is published and uptake is measurable across the affected research deployments, or if the same traversal appears in broad internet scanning rather than targeted university intrusions. Also watch for Cairn paired with ARTEX, Hexstrike or PentAGI in cases where agents carry lateral movement and exfiltration preparation without human direction; that would turn fast vulnerability discovery into sustained automated intrusion.
