Doctor Web reports a campaign that has run for about two years in which threat actors publish malicious GitHub repositories posing as security tools. The operation initially targeted cryptocurrency wallet users with blockchain games, bots and cheat tools, then pivoted to repositories for scan automation, security testing and log analysis aimed at cybersecurity professionals. More than 2,000 Windows systems have been compromised. Malicious code is hidden in Visual Studio project files through PreBuildEvent routines in .csproj files, in .suo files through PowerShell, and in .go and .py source files concealed behind long stretches of whitespace; some projects run the code before compilation.

The infection chain uses PowerShell to retrieve an encrypted download link for a modular Electron-based loader named Microsoft.exe, which establishes persistence, elevates privileges, disables Windows security and recovery features, and injects the next stage into legitimate processes. Final payloads include a backdoor, a clipboard clipper that replaces cryptocurrency wallet addresses, and a data-theft trojan. Doctor Web lists attacker infrastructure including muckanthropic.com, muckdeveloper.com and IP 130.12.182.172, with staging under C:\Users\Public\Pictures.

The targeting shift matters: victims are security professionals who are likely to run the tools with elevated privileges and to trust public repositories, and the hiding techniques are deliberately low-tech, relying on whitespace and build events rather than novel exploits. That makes manual code review essential before compiling or running unfamiliar utilities. Defenders should treat GitHub repositories as untrusted by default, inspect build scripts and project files for hidden code, and monitor for the Microsoft.exe loader and the named domains. The true victim count is likely higher than the 2,000 systems confirmed at the time of research.
