Dr. Web researchers identified a two-year-old GitHub campaign that has infected more than 2,000 Windows systems by publishing malicious repositories disguised as security scanners, scan-automation utilities, and log-analysis tools. The operation originally targeted cryptocurrency wallet users with blockchain games, game bots, and cheat tools built in Visual Studio, then pivoted toward information-security professionals with lures such as a fake Fscan output parser. Coverage from BleepingComputer, GBHackers, and Portuguese outlet TugaTech, plus Mastodon and Reddit reposts, all trace back to Dr. Web's November 5 investigation.

The technical tradecraft is the notable part. Malicious code is hidden in Visual Studio .csproj PreBuildEvent routines, .suo files, and whitespace-concealed Python and Go source, so victims can be compromised while compiling or running a tool they believe is legitimate. The infection chain uses PowerShell to pull an encrypted download link for a modular Electron-based loader called Microsoft.exe, which establishes persistence, elevates privileges, disables Windows security and recovery features, and injects next-stage payloads into legitimate processes; Dr. Web documents six evasion techniques in the loader's Mode3 mode. Final payloads include a backdoor, a clipboard clipper that swaps copied cryptocurrency wallet addresses, and a credential-and-data stealing trojan. Staging runs under C:\Users\Public\Pictures, with attacker infrastructure including muckanthropic.com, muckdeveloper.com, and IP 130.12.182.172.

The practical takeaway is that public source on GitHub is not a trust signal: a repository's visibility says nothing about its build scripts or dependencies. Defenders should treat unfamiliar security utilities as untrusted binaries, inspect pre-build events and hidden characters in source, and block the known domains and staging paths above. Watch for Dr. Web or GitHub to name additional poisoned repositories, since the campaign has already rotated lures once.
