Doctor Web reports a campaign that has run for about two years in which threat actors publish malicious GitHub repositories posing as security tools, initially targeting crypto wallet users with blockchain games and cheat tools before pivoting to scan automation, security testing, and log analysis utilities aimed at cybersecurity professionals. More than 2,000 Windows systems have been compromised. Malicious code is hidden in Visual Studio project files via malicious PreBuildEvent routines in .csproj files, in .suo files through PowerShell, and in .go and .py source files concealed behind long stretches of whitespace. The infection chain uses PowerShell to fetch an encrypted download link for a modular Electron-based loader named Microsoft.exe, which establishes persistence, elevates privileges, disables Windows security and recovery features, and injects next-stage malware into legitimate processes. Final payloads include a backdoor, a clipboard clipper that replaces cryptocurrency wallet addresses, and a data-theft trojan, with staging under C:\Users\Public\Pictures and attacker infrastructure including muckanthropic.com, muckdeveloper.com, and IP 130.12.182.172.

The campaign's shift toward security professionals is notable because the victims are likely to run the tools with elevated privileges and to trust public repositories. The hiding techniques are deliberately low-tech, relying on whitespace and build events rather than novel exploits, which makes manual code review essential before compiling or running unfamiliar utilities.

What to watch: defenders should treat GitHub repositories as untrusted by default, inspect build scripts and project files for hidden code, and monitor for the named loader and domains. The true victim count may be higher than the 2,000 systems confirmed at the time of research.
