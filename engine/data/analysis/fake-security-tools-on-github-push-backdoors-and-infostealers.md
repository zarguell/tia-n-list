A threat actor has spent roughly two years seeding GitHub with trojanized projects that now specifically target security practitioners. After an opening phase aimed at crypto wallet users through blockchain games, bots, and cheat tools, the lures pivoted to scan automation, security testing, and log analysis, including a fake parser for Fscan scanner output. The malicious code hides in Visual Studio project files, Python, and Go sources, often behind long runs of whitespace, and in some projects a PreBuildEvent routine executes the payload before compilation even finishes. The chain runs PowerShell staging scripts from paths such as C:\Users\Public\Pictures\t.ps1 to pull a modular Electron-based loader named Microsoft.exe, which persists, escalates privileges, disables Windows security and recovery features, and injects follow-on malware into legitimate processes. Doctor Web, whose November 5 advisory is the primary source here, counts more than 2,000 infected Windows PCs, and BleepingComputer names the final payloads as the AsyncRAT backdoor, a clipboard clipper swapping crypto wallet addresses, and an information stealer, with six evasion techniques documented in the loader Mode3 configuration.

The reason this story outranks the day's other malware reports is the victim profile. Compromising two thousand random endpoints is routine; compromising two thousand workstations belonging to penetration testers, SOC analysts, and system administrators is a credential-harvesting operation against the people who hold production access, client VPN sessions, and CI secrets. A researcher who clones a scanner utility onto a jump host or a laptop with stored cloud tokens hands the attacker exactly the access that phishing campaigns spend months trying to obtain, and because the payload arrives through a tool the victim chose to run, endpoint alerts get triaged as self-inflicted noise rather than intrusion. The whitespace concealment and pre-build execution also defeat the review this audience supposedly performs, since few engineers read raw project XML or scroll past page after page of blank space before building a helper script.

Defenders should treat every cloned security utility as untrusted code until proven otherwise. Before opening or building any borrowed project, inspect .csproj files for PreBuildEvent entries, check .suo files for embedded PowerShell, and scan .go and .py sources for abnormal whitespace blocks concealing code. Hunt researcher and admin hosts for the Microsoft.exe loader, PowerShell activity writing to C:\Users\Public\Pictures, disabled Windows Defender or recovery settings, and process injection from unusual parents, and block and search proxy and DNS logs for muckanthropic.com, muckdeveloper.com, muckcoding.com, muckduck.duckdns.org, and 130.12.182.172. Build unfamiliar tools in isolated VMs or sandboxes with no cached credentials, and rotate cloud, CI, and client credentials on any host found running the loader.

The assessment changes if Doctor Web or follow-on reporting names additional lure repositories or fresh infrastructure, since GitHub takedowns of the named Fscan parser repo will likely push the actor to mint new projects under new themes. A second shift to watch is telemetry showing infections outside Windows researcher machines or a revised victim count well above 2,000, either of which would indicate the campaign has broadened beyond its current niche.
