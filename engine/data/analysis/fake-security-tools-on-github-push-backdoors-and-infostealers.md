Attackers are seeding GitHub with trojanized security utilities to compromise the very people who hunt malware. BleepingComputer, citing Dr. Web research, describes a campaign running about two years that first lured crypto wallet users with blockchain games, bots, and cheat tools, then pivoted to fake scan automation, security testing, and log analysis projects. One lure posed as a lightweight parser for Fscan scanner output. Dr. Web counts more than 2,000 compromised Windows systems so far.

The tradecraft targets developers directly. Malicious code hides in Visual Studio project files, Python scripts, and Go sources behind long runs of whitespace, and in some Visual Studio projects a pre-build event runs the payload before compilation. The chain uses PowerShell to fetch an encrypted download link for a modular Electron-based loader named Microsoft.exe, which persists on the host, escalates privileges, disables Windows security and recovery features, and injects the next stage into legitimate processes. Dr. Web notes six evasion techniques in the loader Mode3 configuration. Doctor Web's own report now corroborates the campaign at the primary source: malicious GitHub projects posing as security scanners, test automation and log parsers, with payloads hidden in Visual Studio project files.

The risk is credential and access theft from high-value workstations. Teams should treat cloned security tools as untrusted code, review project files and build events before opening them in an IDE, and hunt for the Microsoft.exe loader behavior and disabled recovery settings on researcher and admin hosts. Watch for Dr. Web or BleepingComputer to name additional lure repositories or infrastructure, since takedowns of named repos typically push the actor to mint fresh ones under new themes.
