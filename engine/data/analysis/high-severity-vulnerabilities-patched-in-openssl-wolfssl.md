OpenSSL released security updates addressing 14 vulnerabilities, including CVE-2026-84782, a high-severity out-of-bounds read (CVSS 8.2) in the DTLS handshake retransmission code. The flaw allows a remote, unauthenticated peer to read leftover heap memory as plaintext DTLS handshake data or trigger a denial-of-service crash. It affects OpenSSL versions 4.0, 3.6, 3.5, 3.4, 3.0, 1.1.1, and 1.0.2. A second tracked vulnerability, CVE-2026-84783 (medium severity), allows an unauthenticated peer to crash a multi-threaded TLS client. The remaining fixes cover low-severity issues including excessive memory consumption, process crashes, DTLS 1.2 connection termination, QUIC server DDoS amplification, and timing side channels that could assist private key recovery.

This is a standard cryptographic patch cycle with one high-severity bug that is remotely exploitable over the network without authentication or user interaction. The DTLS exposure matters for VPN, VoIP, and IoT products that rely on OpenSSL's DTLS implementation. The medium-severity TLS client crash is less severe but still relevant for multi-threaded applications. The low-severity fixes are routine maintenance, though the side-channel issue could become significant if combined with other observations.

Defenders should upgrade OpenSSL installations to the latest patched releases and verify that DTLS-enabled services (VPN endpoints, VoIP gateways, IoT management interfaces) are covered. Watch for vendor security advisories from downstream products that bundle OpenSSL, especially in embedded and network appliances where update paths are slower than operating-system package managers. There are no reports of active exploitation of CVE-2026-84782, but the remote exploitability and absence of authentication requirements mean it should be treated as an immediate patch target.
