The OpenSSL 29 September 2026 advisory fixes 14 vulnerabilities, with CVE-2026-84782 (CVSS 8.2, CWE-125 out-of-bounds read) as the standout. The bug is in DTLS handshake retransmission: when a handshake message write suspends because the transport cannot accept more data, the retransmission timer can fire and reuse the same internal buffer without resetting the read position. The retransmitted message starts at the stale offset where the suspended write stopped, sending leftover heap data from another handshake message as plaintext DTLS content. In some cases the read runs past the allocated buffer, exposing heap-resident memory to the remote peer or crashing the process when it reaches unmapped memory. Affected releases span OpenSSL 4.0 before 4.0.3, 3.6 before 3.6.5, 3.5 before 3.5.9, 3.4 before 3.4.8, and the premium-only branches 3.0 before 3.0.23, 1.1.1 before 1.1.1zj, and 1.0.2 before 1.0.2zs. A second tracked issue, CVE-2026-84783, is a medium-severity use-after-free in the X.509 extension cache that can crash a multi-threaded TLS client when concurrent connections build chains to the same trusted CA. WolfSSL released a parallel patch cycle for roughly a dozen flaws, confirming this is not a single-vendor event.

A remote, unauthenticated peer can trigger CVE-2026-84782 over the network without user interaction, which makes it an immediate patch target rather than a routine maintenance item. The DTLS protocol is embedded in VPN endpoints, VoIP gateways, and IoT management interfaces, so exposure is not limited to traditional web servers. The CVSS 8.2 score reflects confidentiality impact (plaintext heap leakage) combined with availability impact (DoS crash), yet the event timeline shows no confirmed active exploitation as of 30 September 2026. The absence of exploitation telemetry is not a reason to delay: the vulnerability is remotely reachable, requires no authentication, and affects multiple long-term support branches that power embedded appliances and network gear where update paths are slower than OS package managers. The concurrent WolfSSL patch cycle means defenders must audit both libraries in any product that bundles both, not just one.
