Clop, also tracked as Cl0p, is exploiting CVE-2026-12569, a CVSS 9.3 unauthenticated remote code execution vulnerability in PTC Windchill PDMlink and FlexPLM, to deploy a custom JavaServer Pages web shell built specifically for the platform. The implant, analyzed by ReliaQuest, reads Windchill configuration files, decrypts encrypted values from the application keystore to harvest directory-management and LDAP manager credentials, enumerates file vaults, and exfiltrates engineering data without separate attacker tooling. The event record carries concrete indicators including the malicious request header X-windchill-req, known webshell paths such as /Windchill/login/7c0a0a34c9d8d53b.jsp, and the C2 IP 5.180.41.35; PTC's advisory confirms patches for versions including 13.1.3, 13.1.2, 13.1.1, 13.0.2, 12.1.2, 12.0.2, 11.2.1, 11.1 M020, and 11.0 M030, with exploitation reports dating back to June.

This is not a generic webshell repurposed for a new target; it is an application-specific evolution of Clop's mass-exploitation playbook, reflecting detailed knowledge of Windchill's internal APIs, database schema, and file-vault structure. The events note that previous Clop campaigns hit more than 2,770 organizations worldwide through MOVEit Transfer alone, and this campaign extends that same supply-chain extortion model to product lifecycle management systems that store pre-release designs, supplier data, and intellectual property. PTC reports over 30,000 global customers and more than 1,500 brand and retail customers using FlexPLM, concentrating exposure in aerospace, defense, automotive, and manufacturing sectors. The claim the timeline does not spell out on its own is that the attacker does not merely steal files but also decrypts keystore-stored credentials that could unlock connected enterprise services, turning a single PLM breach into a broader network foothold rather than a contained data-theft event.

Defenders should apply PTC patches immediately, specifically the SUP updates 13.1.3 and 13.1.2 or the standalone CPSXB patches for 13.1.1, 13.0.2, 12.1.2, 12.0.2, 11.2.1, 11.1 M020, and 11.0 M030, and restrict internet exposure of the Windchill login endpoint where operationally feasible. Hunt for POST requests to /Windchill/login/*.jsp matching 16-character lowercase hexadecimal filenames, for shorter six-hex variants, and for dpr_ prefixes, because legitimate Windchill traffic does not POST to that path. Block the C2 IP 5.180.41.35 at the perimeter, add WAF or IDS rules dropping requests containing the X-windchill-req header, scan filesystems under .../Windchill/codebase/login/ for suspicious .jsp files, and check for the file flst.txt in /tmp or the working directory as confirmation of attacker file-listing activity. Alert on multi-megabyte POST responses originating from .jsp files in the application tier, and hash-check suspicious shells against 55a1eb4c2d3da04376df39d7ba832569c6af1a37a0cf2b95f754ac898023a30c.

Watch for new webshell filenames beyond the currently known six, because the attacker names shells with 16 lowercase hex characters or dpr_ prefixes and may deploy new variants at any time. Monitor exposure metrics: Censys observed fewer than 100 internet-facing Windchill instances as of June 1, 2026, with a decline to a little over 80 by July 20, meaning remaining exposed systems face concentrated scanning. A second development that would change the assessment is confirmation of expanded exploitation through the additional vulnerabilities referenced in PTC's advisory, specifically the critical RCE CVE-2026-77645 (CVSS 9.0) and the high SSRF CVE-2026-77646 (CVSS 8.6), which could expand the campaign beyond the single CVE-2026-12569 chain currently in focus.
