Okta's threat intelligence team analyzed a 7 GB infostealer dump released on Telegram on August 2, 2026, containing data from 5,871 compromised machines across 162 countries. The dump included 44,791 unique JSON web tokens, of which 555 were linked to AI platform authentication. Among the targeted services: Google, Microsoft, Anthropic, Amazon, Cursor, Poe.com, Character.ai, and Pika AI. Of the total JWTs, 1,843 were still unexpired at the time of analysis, and 2,937 were encrypted JWEs, mostly set by OpenAI via NextAuth.js.

The core threat is session replay. A stolen JWT or JWE lets an attacker authenticate to an AI service as the victim, bypassing both passwords and MFA. Okta found 24 still-valid API keys for Google Gemini, OpenAI, Groq, and OpenRouter in the same dump, which could be used for LLMjacking: consuming model compute on someone else's bill or reselling access. Anti-detect browsers like Camoufox and automation tools like SeleniumBase can load stolen sessionStorage and localStorage data from files, and proxy configuration defeats impossible-travel detections.

The broader ecosystem is responding. Google's Mandiant team reported increased targeting of AI account credentials on cybercrime forums, with buyer demand spiking for Claude and Gemini access alongside IDEs like Cursor Pro and Devin. A black market vendor was spotted selling access to Claude, Cursor, ChatGPT, and Gemini with 24/7 support and money-back guarantees. Google has deployed Device Bound Session Credentials (DBSC) in Chrome to cryptographically bind session tokens to hardware, and IP allowlisting remains a partial mitigation. Organizations should treat AI service credentials with the same rigor as cloud IAM keys: short-lived tokens, scope minimization, and monitoring for anomalous API consumption.
