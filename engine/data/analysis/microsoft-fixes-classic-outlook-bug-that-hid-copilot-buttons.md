Microsoft has closed a regression in classic Outlook for Windows that removed the Copilot Chat and Copilot entry points from the side navigation and the ribbon for licensed users. The bug affects clients on build 20026.20182 and higher, and only users with a Copilot Chat (Basic) license or a paid Microsoft 365 Copilot (Premium) account. Microsoft traced it to a failure to retrieve required account information from the user's Outlook profile, specifically the MAPI property PR_PROFILE_USER_SMTP_EMAIL_ADDRESS_W in the null profile section, which kept the Copilot component from persisting its settings. A service change on June 29, 2026 appeared to fix it, the issue resurfaced after later updates, and Microsoft marked it fixed again with a support document last updated October 15, 2026 and news coverage on October 19, 2026.

This is an availability regression, not a security vulnerability, and that distinction matters on a day when the same vendor shipped a record 1,235 flaws in its November 2026 Patch Tuesday, including one actively exploited Outlook zero-day. The exposed population is narrower than the headline suggests: only organizations that both stayed on classic Outlook and updated to build 20026.20182 or later while holding Copilot licenses, and Copilot stayed reachable through Outlook on the web and the Microsoft 365 Copilot app, so no mailbox data was at risk. The real cost is help-desk churn and misdiagnosis, because the same symptom can be caused by licensing, Microsoft 365 app configuration, update channel, privacy settings, or other environmental factors, so a missing button should not be assumed to be this bug. That is the claim the event list does not spell out: triage should confirm build number, license tier, and profile state before escalating a Copilot outage ticket.

Defender actions are client-side and low risk. Update classic Outlook to the latest build and restart the client so the service change applies. If the client cannot be updated, revert to the previous Current Channel build 16.0.20026.20168, or create a new Outlook profile, or move affected users to new Outlook or Outlook Web Access. Also verify that Show Apps in Outlook is enabled under File, Options, Advanced, Outlook panes, since that separate setting can hide Copilot in the app bar. Microsoft's own guidance points to the Copilot troubleshooters and the how to find and enable missing Copilot button article for cases that are not explained by this regression.

Watch whether the regression resurfaces after future Current Channel updates, since it already did once after the June 29 service change. Also watch for reporting that conflates this button issue with the actively exploited Outlook zero-day in the November 2026 Patch Tuesday, because the remediation and risk profiles are different. A genuine change in assessment would require evidence that the profile-read failure exposes account data or that the same code path is reachable by an attacker, neither of which is indicated in the available reporting.
