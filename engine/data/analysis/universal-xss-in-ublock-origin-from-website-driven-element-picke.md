A write-up at iter.ca documents a one-click universal XSS in uBlock Origin's Firefox Manifest V2 element picker. The picker, used to click an element and block it, accepts messages from the page being visited. A newline in the opt field lets a malicious page add a second field, smuggling an extra filter or option past the picker's parsing. A separate report from securityonline.info describes the same flaw as allowing a site to hijack the Element Picker and inject trusted filter scripts.

Because the picker runs with extension privileges, controlling what it applies turns a block action into script execution in a privileged context. A user who opens the picker on a hostile page can be pushed into the exploit with one click. uBlock Origin shipped a fix, and iter.ca's advisories tell users to upgrade. The Firefox MV2 build is the affected path named in the research.

Watch for the exact newline-based injection string appearing in public exploit posts and for any indication that the MV3 extension shares the same opt parsing. Until the fix is deployed, treating element-picker use on untrusted pages as risky is the practical mitigation.
