Broadcom's VMSA-2026-0011, published November 24, lists 23 vulnerabilities across VMware ESX, vCenter, Workstation, Fusion and Avi Load Balancer. The headline flaw is CVE-2026-123903, a CVSS 9.8 authentication bypass in the VMware Directory Service (vmdir) behind vCenter Single Sign-On. It needs only network access to vCenter, with no privileges and no user interaction, and Broadcom has not described the root cause or request sequence. It is distinct from CVE-2026-123890, the vmdir zero-day a suspected China-nexus group exploited before the November 19 patch; builds installed last week for that flaw do not cover this one.

Two ESX flaws also score 9.8: CVE-2026-123910, a heap out-of-bounds write, and CVE-2026-123911, a use-after-free, both in the I/O filter service. CVE-2026-123912 is a CVSS 9.3 out-of-bounds write in the XHCI USB controller that needs local administrator rights on a guest and leads to code execution as the VMX process on the host, contained in the VMX sandbox on ESX but not on Workstation or Fusion. A separate vCenter issue lets an attacker with backup repository access write files as root. The Canadian Cyber Centre lists affected vCenter versions including 9.1.x before 9.1.2, 9.0.x before 9.0.2.0300, 8.0 before U3m and VCF 5.x before 5.2.5.

Patch planning should start with internet-reachable vCenter appliances and the ESXi 8.0 Update 3m build 25926933, which requires a host reboot and migration or shutdown of virtual machines. Watch for any report of exploitation of CVE-2026-123903, since the November 24 advisory carries no exploitation confirmation, and track follow-on vmdir bugs: this is described as the third vmdir authentication bypass Broadcom has fixed in 2026.
