Broadcom's VMSA-2026-0011, updated 24 November 2026, patches 23 flaws across VMware ESX, vCenter, Workstation, Fusion and Avi Load Balancer. The headline bug is CVE-2026-123903, a CVSS 9.8 authentication bypass in the VMware Directory Service behind vCenter Single Sign-On. Network access to vmdir over LDAP is enough to gain access without credentials or user interaction. The Canadian Centre for Cyber Security lists affected vCenter branches as 9.x before 9.1.2 and 9.0.2.0300, 8.0 before 8.0 U3m, and 5.x before 5.2.5. ESXi 8.0 Update 3m is build 25926933 and requires a host reboot with virtual machines migrated or shut down.

CVE-2026-123903 is a separate issue from CVE-2026-123890, the CVSS 9.8 vmdir bypass patched five days earlier and exploited as a zero-day by the suspected China-nexus ARMORY CASTLE group. Rapid7 describes the older flaw as RPC-reachable and the new one as LDAP-reachable, and validated a public proof of concept that bypasses authentication on the new bug. Broadcom reports no exploitation of CVE-2026-123903, lists no workaround, and says these vCenter updates are not eligible for Quick Patch. vSphere teams that installed last week's builds against CVE-2026-123890 are not covered, so inventory should be keyed to the new advisory rather than the previous one.

The ESX portion fixes three critical code execution flaws. CVE-2026-123910 and CVE-2026-123911 are CVSS 9.8 heap out-of-bounds write and use-after-free bugs in the I/O filter service, reachable over the network. CVE-2026-123912 is a CVSS 9.3 out-of-bounds write in the XHCI USB controller that requires local administrative rights on a virtual machine. Broadcom says ESX confines exploitation inside the VMX sandbox, while Workstation and Fusion can execute code on the host machine running the product. New CVE records in this window restate the I/O filter and XHCI impact; they do not add an exploitation claim. Watch for a KEV entry on CVE-2026-123903 and for patches applied to vCenter without the corresponding ESX and Workstation updates.
