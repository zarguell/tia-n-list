Broadcom's VMSA-2026-0011 bundles 23 VMware fixes, led by CVE-2026-123910, remote code execution in ESX, and CVE-2026-123903, an authentication bypass in vCenter, both rated CVSS 9.8. No active exploitation is asserted and no actor is named; neither CVE is in CISA KEV. The fixed builds named in reporting are vCenter 9.1.2, 9.0.2.0300 and 8.0 U3m, plus ESXi-9.1.2.0-25946735 for ESX 9.1.x and ESXi80U3m-25926933 for ESX 8.0; ESX 9.0.x remains patch pending.

This cycle crosses two control planes, so patching vCenter alone leaves the ESX host path open and patching hosts alone leaves a compromised management server intact. The 23-fix count and two 9.8 entries make it a full-estate maintenance window rather than a single-appliance alert, for every operator with a reachable vCenter or ESX deployment on the listed versions. No install-base count is carried, so exposure is defined by those versions and network reach, not by a headline victim total.

Patch vCenter to 9.1.2, 9.0.2.0300 or 8.0 U3m and ESX to 25946735 or 25926933 as applicable. Where ESX 8.x cannot be patched immediately, apply Broadcom's manual interim workaround in KB 463535 and restrict TCP/9080, the IOFilterVP service port named in that guidance, to management networks; keep ESX 9.0.x behind the same restriction until a build ships. Hunt for inbound connections to TCP/9080 and unexpected IOFilterVP service activity. No log path or named indicator is given in the available reporting, so generic endpoint checks do not establish coverage.

The assessment changes if Broadcom publishes the ESX 9.0.x fix, or if either CVE gains KEV status, confirmed exploitation telemetry, or a public researcher disclosure with technical detail. The remaining 21 fixes also matter if their details reveal another management-plane path that can be chained with the vCenter bypass.
