Broadcom's November 24 advisory VMSA-2026-0011 patches 23 flaws across VMware ESX, vCenter, Workstation, Fusion and Avi Load Balancer. The headline issue is CVE-2026-123903, a CVSS 9.8 authentication bypass in the VMware Directory Service (vmdir) behind vCenter SSO. Reaching vmdir over the network is enough to gain access without credentials. Rapid7 notes this LDAP-reachable bug is distinct from CVE-2026-123890, the RPC-reachable vmdir flaw patched in VMSA-2026-0009 five days earlier and exploited as a zero-day by a suspected China-nexus espionage group.

The ESX side carries three critical code execution issues: CVE-2026-123910 and CVE-2026-123911, both CVSS 9.8 heap out-of-bounds write and use-after-free bugs in the I/O filter service, and CVE-2026-123912, a CVSS 9.3 out-of-bounds write in the XHCI USB controller that needs local administrative rights on a virtual machine. Broadcom says host exploitation is contained in the VMX sandbox on ESX but can mean code execution on the machine running Workstation or Fusion. vCenter also gets fixes for three vmdir denial-of-service bugs, a vpxd script privilege escalation, arbitrary file writes while processing archives, a vDS policy enforcement failure, and a backup-repository flaw that allows root file writes.

Canadian Cyber Centre guidance lists fixed vCenter builds including 9.1.2, 9.0.2.0300, 8.0 U3m and 5.2.5; ESXi 8.0 Update 3m is build 25926933 and requires a reboot with virtual machines migrated or shut down. Rapid7 validated a public proof of concept for CVE-2026-123903 but found no public in-the-wild reports for it, so the risk is the gap between the two vmdir bugs: builds installed last week for CVE-2026-123890 do not cover the new one. Broadcom lists no workaround, and vCenter updates are not eligible for Quick Patch. Watch for exploitation reports, LDAP activity against vmdir, and confirmation that every vCenter branch has the new fix.
