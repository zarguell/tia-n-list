Broadcom's VMSA-2026-0011, updated on November 24, 2026, patches 23 flaws across VMware ESX, vCenter, Workstation, Fusion and Avi Load Balancer. The headline issue is CVE-2026-123903, a CVSS 9.8 authentication bypass in the VMware Directory Service, or vmdir, behind vCenter Single Sign-On. An attacker with network access to the LDAP service can gain access without credentials or user interaction. The Canadian Centre for Cyber Security lists affected vCenter branches as 9.x before 9.1.2 and 9.0.2.0300, 8.0 before 8.0 U3m, and 5.x before 5.2.5. ESXi 8.0 Update 3m is build 25926933 and requires a host reboot with virtual machines migrated or shut down.

CVE-2026-123903 is separate from CVE-2026-123890, the CVSS 9.8 vmdir bypass patched five days earlier and exploited as a zero-day by the suspected China-nexus ARMORY CASTLE group. Rapid7 distinguishes the older RPC-reachable flaw from the new LDAP-reachable issue and validated a public proof of concept that bypasses authentication on CVE-2026-123903. As of Rapid7's report there were no known public reports of exploitation of the new bug. Broadcom lists no workaround and says the vCenter updates are not eligible for Quick Patch, so builds installed for CVE-2026-123890 do not close this issue.

The ESX update also fixes three critical code execution flaws. CVE-2026-123910 and CVE-2026-123911 are CVSS 9.8 heap out-of-bounds write and use-after-free issues in the I/O filter service, reachable over a network. CVE-2026-123912 is a CVSS 9.3 out-of-bounds write in the XHCI USB controller that requires local administrative privileges on a virtual machine. Broadcom says ESX confines exploitation inside the VMX sandbox, while Workstation and Fusion can execute code on the host machine. Teams should inventory against VMSA-2026-0011 rather than the prior advisory and watch for in-the-wild use of the validated authentication-bypass proof of concept.
