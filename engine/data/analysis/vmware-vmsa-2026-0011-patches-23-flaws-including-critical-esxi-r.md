Broadcom's VMSA-2026-0011, notification 39626, updated November 24, covers 23 vulnerabilities in VMware ESX, vCenter, Workstation, Fusion and Avi Load Balancer. The two CVSS 9.8 entries are CVE-2026-123903, an authentication bypass in the vCenter VMware Directory Service (vmdir) that needs only network access to the appliance, and CVE-2026-123910, a heap out-of-bounds write in the ESX I/O filter service. CVE-2026-123911, also rated 9.8, is a use-after-free in the same service; CVE-2026-123912 is a 9.3 out-of-bounds write in the XHCI USB controller that requires local administrative rights on a guest. Three vmdir denial-of-service bugs, a vpxd script privilege escalation, an archive-processing arbitrary file write and a vSphere Distributed Switch policy enforcement failure are also in the vCenter set.

ESX code execution runs in the VMX process on the host, which Broadcom says contains exploitation in the VMX sandbox on ESX; Workstation and Fusion builds can execute code on the host machine instead. Coverage from The Hacker News and Infonewscyber describes CVE-2026-123903 as exploited as a zero-day, but the vendor text quoted here does not repeat that claim. GBHackers separately describes a vCenter flaw where an attacker with access to the backup repository can write files as root on the appliance, potentially reaching arbitrary code execution. Treat the in-the-wild reporting as unconfirmed from the primary material and prioritize the auth bypass and host-facing ESX bugs.

Fixed lines named in the Canadian Cyber Centre's AV26-1203 notice include vCenter 9.1.2, 9.0.2.0300, 8.0 U3m and 5.2.5 for vCenter 5.x. ESXi 8.0 Update 3m is build 25926933, shipped as an x86_64 ISO and an offline bundle; applying it requires a host reboot with virtual machines migrated or shut down, which will slow rollout. Watch for vendor confirmation of exploitation against CVE-2026-123903 and for follow-up fixes after this large update.
