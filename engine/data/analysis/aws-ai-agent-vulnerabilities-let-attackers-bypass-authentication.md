AWS Loom AI agent orchestration and Amazon SageMaker Unified Studio carry four flaws that allow authentication bypass, OAuth2 token and temporary cloud credential theft, internal service access, and arbitrary code execution in another user's SageMaker environment. The separate critical CVE-2026-104019 (CVSS 9.0) is an OS command injection in AWS SageMaker Distribution that lets project contributors run arbitrary code. These are not theoretical: the event list names concrete products, the CVSS 9.0 score, and the credential types exposed, so a successful attack means full environment compromise and cloud token exfiltration rather than a limited app-level breach.

The exposure is significant because SageMaker Unified Studio and Loom are open-source and cloud-connected; any contributor or attacker who can reach these endpoints can pivot from a single vulnerability to cross-user code execution and credential theft. The event count is small (two sources, one CVE), but the severity is high and the first_seen timestamp of 2026-10-03 is very recent, meaning defenders have little lag time before exploitation telemetry appears. The reason this story matters among others is the pairing of authentication bypass with arbitrary code execution in a shared cloud ML environment, which is a harder remediation path than a single product patch.

Patch the four AWS vulnerabilities via the vendor security bulletins; fix CVE-2026-104019 in AWS SageMaker Distribution; rotate any exposed OAuth2 tokens and temporary cloud credentials; restrict network access to Loom orchestration endpoints and SageMaker Unified Studio services; hunt for unexpected OS command patterns in SageMaker Distribution logs and anomalous OAuth2 token usage.

Watch for exploitation telemetry related to CVE-2026-104019 and any additional AWS bulletins that expand affected versions or confirm in-the-wild abuse.
