WatchGuard has patched three vulnerabilities in its access point platform, fixed in AP firmware 3.4.8 and disclosed September 28, 2026. Firmware versions 1.0 through 3.4.7 are affected. CVE-2026-86102 is an unauthenticated OS command injection in the internal management API service with a CVSS v4 score of 9.3: an attacker with network access to a vulnerable AP can run arbitrary shell commands with the privileges of the API service, no credentials or interaction required. CVE-2026-101891, also 9.3, is an improper access control flaw in the same API service that allows unauthenticated access. CVE-2026-87969, rated 8.6, is an authenticated command injection in the diagnostic CLI. The Canadian Centre for Cyber Security echoed the advisory as AV26-972 on September 29.

The serious scenario is an access point reachable from an untrusted, poorly segmented, or remote-access network, where the access control bypass and command injection chain gives a silent foothold inside the corporate network. Wireless infrastructure is frequently deployed on flat management VLANs and patched on slow cycles, which makes exposed AP management interfaces the practical risk.

There is no report of exploitation so far, so the window to patch is open. Watch for PoC code, mass scanning of WatchGuard AP management endpoints, and any vendor note on whether cloud-managed fleets auto-update. Organizations running WatchGuard APs should move to 3.4.8 and restrict management API reachability in the meantime.
