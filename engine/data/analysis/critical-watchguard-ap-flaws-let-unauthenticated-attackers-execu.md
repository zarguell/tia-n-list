WatchGuard published three PSIRT advisories for its AP line on 2026-09-28 at 16:51 UTC and shipped firmware 3.4.8 the same day. CVE-2026-86102 is OS command injection (CWE-78) with incorrect authorization (CWE-863) in the internal management API service: an attacker with network access to the AP runs arbitrary shell commands with the API service's privileges, no authentication and no user interaction. CVE-2026-101891, also 9.3 on CVSS v4.0, is improper access control (CWE-284, CWE-923) in that same API service and grants an unauthenticated attacker a valid API session; WatchGuard found this one internally. CVE-2026-87969 is command injection in the diagnostic CLI at 8.6, requiring an authenticated administrator, credited to Carlos Garrido of Pentraze Cybersecurity, with 86102 credited to Yukusawa. Affected firmware spans 1.0 through 3.4.7, and WatchGuard states it is not aware of any exploitation in the wild.

The two criticals compose a chain: 101891 mints the API session, 86102 converts it into a shell, so together they deliver unauthenticated command execution where each bug alone would rate lower. The geometry is what separates this from WatchGuard's Firebox history: CVE-2025-9242 and CVE-2025-14733 were internet-facing IKEv2 flaws that reached CISA's KEV catalog, the latter flagged for ransomware campaign use, while this management API is normally reachable only from inside the network. That makes exposure a segmentation question, and the common failure mode is flat wireless: guest and user VLANs that can route to AP management interfaces give any client-side device a path to unauthenticated shell on the appliance that bridges the wireless edge to the wired core. The installed base is every AP ever run on this firmware line, which is why this outranks the many 9.x CVEs published the same day.

Upgrade every AP to 3.4.8; the advisories list no workaround and mark everything from 1.0 upward as affected below that release. Until patching completes, fence the AP management interface into a dedicated management VLAN and verify that client SSID VLANs and remote-access paths cannot route to it, the untrusted, poorly segmented, or remote-access exposure condition the coverage names. The vendor publishes no IoCs and no indicators of attack for any of the three, so hunting is network-side: inventory deployed firmware versions, enumerate internal sources that initiated connections to AP management interfaces, and treat any API session established from a client VLAN as an anomaly worth chasing to the switch port. Keep 87969 in scope even though it is admin-only, because stolen AP administrator credentials make the authenticated prerequisite cheap.

The number to watch is the exploitation status. WatchGuard currently claims no awareness of in-the-wild use, but its Firebox record sets the clock: CVE-2025-9242 reached KEV eight weeks after its advisory and CVE-2025-14733 the same day as its own. A public PoC from Yukusawa or Pentraze would move the assessment immediately, and CCCS advisory AV26-972 is already circulating the trio to federal recipients, so triage pressure will build even without new technical facts. Either a KEV listing or credible exploitation telemetry converts this from routine patch cycle to emergency maintenance.
