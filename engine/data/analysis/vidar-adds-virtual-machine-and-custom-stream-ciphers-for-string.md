Zscaler ThreatLabz documented a significant evolution in Vidar, an information stealer first observed in 2018, as it adopted increasingly sophisticated string obfuscation to evade detection. From May through early September 2026, Vidar progressed from basic XOR encryption to ChaCha20 and finally to a custom virtual machine paired with a per-build stream cipher. The VM executes via a lightweight bytecode interpreter, and the stream cipher's operations change with each build, making static and automated analysis substantially harder.

The obfuscation timeline shows deliberate escalation: versions before 1.5 used single-byte XOR, version 1.5 adopted ChaCha20, and versions from 1.8 onward introduced the VM approach. The latest version (3.3) combines the custom VM with stream cipher operations that vary across builds, meaning each compilation produces a functionally identical binary with different string encoding. This per-build variation defeats signature-based detection and complicates reverse engineering, as analysts must reconstruct the VM's opcode set for each sample.

This evolution reflects a broader trend in information stealer development where authors invest heavily in analysis resistance. Defenders should rely on behavioral detection rather than string-based signatures, and sandboxes should ensure they execute Vidar samples long enough for the VM-based deobfuscation to resolve at runtime.
