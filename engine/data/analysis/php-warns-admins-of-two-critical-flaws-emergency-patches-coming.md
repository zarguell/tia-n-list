The PHP security team shipped an out-of-cycle security release on October 21 at 14:00 UTC fixing two critical flaws, CVE-2026-109618 and CVE-2026-109619, each rated 9.2 under CVSS v4.0 and tracked by researchers as PHP2Shell. Fixed versions are 8.5.12, 8.4.27, 8.3.36 and 8.2.35. Details of the pair leaked on October 20, one day before the coordinated date and two days before the originally embargoed date of October 22. PHP states there is no complete mitigation, so updating is the only safe option, and early claims of CVSS 10.0 and impact back to PHP 5 do not match the official rating and fix list. A separate report circulated on October 21 claims the patched PHP 8.5.12 build still appears vulnerable, which has not been confirmed by the project.

Both bugs share one root problem: PHP can leave memory in a corrupted state when a request ends abnormally. CVE-2026-109618 is out-of-memory handling that interrupts PHP while internal request data is only partially initialized, so request cleanup treats invalid data as valid, and it yields remote code execution as the web worker account. CVE-2026-109619 leaves request owned internal state alive after its backing memory is freed, so a later request handled by the same worker can reuse stale state, producing heap use after free, memory disclosure and remote code execution with worker privileges. Every PHP installation that serves web requests is in scope, including PHP-FPM, Apache with mod_php, php-cgi, FrankenPHP and LiteSpeed, and the PHP team considers risk highest for mod_php because an unauthenticated request can trigger the attack before any application code runs. Wiz reports achieving pre-auth remote code execution through the PHP engine itself across WordPress, Drupal and Joomla, which means patching the CMS or rebuilding a container image does not fix the underlying runtime.

Exploitation is already visible. Cloudflare says it detected attacks and pushed WAF rules at 03:02 UTC to block exploit traffic that can cause denial of service, remote code execution and data exposure, and a Romanian report describes multiple French, Dutch and Finnish government sites taken offline, with Cloudflare's Dane Knecht reporting the first attacks appearing. Reuters reported European government sites going offline, Sansec expected mass attacks within fifteen minutes of the release, and Sophos says a public proof of concept is circulating. CISA's October 21 alert states it had not observed exploitation as of publication but urges immediate updates to the four fixed versions, and the UK NCSC tells organisations in part 3 of its guidance to find every PHP installation they run, internet-facing first, including appliances and products that bundle it. Palo Alto Networks rates its exposure separately, marking the PAN-OS and Panorama management web interface affected with fixes to come and no known malicious exploitation against its products, while Imperva published a checker script that live-tests whether a site is exposed.

Watch how quickly the published proof of concept becomes mass scanning, whether CISA adds either CVE to the Known Exploited Vulnerabilities catalog, and how quickly distributions backport to end-of-life branches. CivicPlus kept its Web Open municipal website platform offline after a precautionary shutdown with no restoration estimate, which shows the operational cost of patching a large estate at speed. One governance detail worth noting: Chainguard published container images containing the fix at 07:41 UTC, more than six hours before the coordinated release, which let attackers study the patch in binary form while other PHP users were still waiting, and the PHP Foundation said so publicly.
