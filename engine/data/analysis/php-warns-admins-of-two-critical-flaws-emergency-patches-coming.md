PHP2Shell is the pair of runtime flaws CVE-2026-109618, an out-of-memory corruption bug, and CVE-2026-109619, a stale global state bug. Both are rated CVSS v4.0 9.2 and allow unauthenticated code execution with the PHP worker's privileges. The risk is highest for Apache with mod_php, where a request can reach the exploit path before application code runs. PHP-FPM, php-cgi, FrankenPHP and LiteSpeed installations are also in scope. Details leaked on October 20, and PHP released fixes a day early on October 21 in 8.5.12, 8.4.27, 8.3.36 and 8.2.35, with source backports for 7.4, 8.0 and 8.1.

Amazon's MadPot honeypots captured an exploitation attempt on October 17, four days before disclosure. Cloudflare saw thousands of attempts in the ten hours before the announcement and millions afterward. Adel Karimi confirmed successful RCE on October 24 against an Apache mod_php honeypot running PHP 8.4.26, recording 35 shells across three honeypots, an 800 KiB memory disclosure and a shell command about 1.6 ms after the final execution request. CISA added both CVEs to its KEV catalog on October 26 with an October 29 federal remediation deadline. Unit 42 counted more than 22.6 million internet-exposed instances in scope, and Censys tracked about 32 million vulnerable web properties. Wordfence had intercepted more than 74,000 exploit or probing attempts by October 23 but had not seen a confirmed compromise of a protected WordPress site as of October 28.

The November 19 update belongs to the same PHP exposure story but reports three additional critical advisories separate from the original PHP2Shell pair. PHP shipped 18 fixes in 8.5.13, 8.4.28, 8.3.37 and 8.2.36, including CVE-2026-115560, the session serializer mismatch RCE left for the normal cycle; CVE-2026-129289, a CVSS 9.2 PHP-FPM request-smuggling flaw affecting configurations that reuse backend connections; CVE-2026-129481, an incomplete fix for CVE-2026-109619; and phpAfterShell CVE-2026-126714, where an interrupted file-based session write leaves a hybrid session file that can become a deserialization primitive. The full phpAfterShell chain has not been published.

Patching is still the only complete defense, and installing a package does not help until every PHP worker restarts. The interim mitigation for the session issues is session.upload_progress.enabled=0. Watch for vendor backports and appliance firmware, since PAN-OS, QNAP, Cisco and industrial products embed PHP and cannot always be patched by the operator. The same release also fixed CVE-2026-129474 and CVE-2026-129496, use-after-free flaws in magic method backtraces and the timezone cache, so a package check should cover the full November set rather than only the named headlines.
