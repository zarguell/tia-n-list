The PHP security team shipped an out-of-cycle security release on October 21 at 14:00 UTC fixing two critical flaws, CVE-2026-109618 and CVE-2026-109619, each rated 9.2 under CVSS v4.0 and tracked by researchers as PHP2Shell. Fixed versions are 8.5.12, 8.4.27, 8.3.36 and 8.2.35. Details of the pair leaked on October 20, one day before the coordinated date and two days before the originally embargoed date of October 22, and watchTowr confirmed the CVE identifiers. Early posts from Florian Roth and a Hacker News thread claimed CVSS 10.0 and impact back to PHP 5, but the official rating is 9.2 and PHP 8.1 and older get no upstream fixes, so those estates need a distribution backport or a move to a supported branch.

Both bugs share one root problem: PHP can leave memory in a corrupted state when a request ends abnormally. CVE-2026-109618 is out-of-memory handling that interrupts PHP while internal request data is only partially initialized, so request cleanup treats invalid data as valid, and it yields remote code execution as the web worker account. CVE-2026-109619 leaves request owned internal state alive after its backing memory is freed, so a later request handled by the same worker can reuse stale state, producing heap use after free, memory disclosure and remote code execution with worker privileges. Every PHP installation that serves web requests is in scope, including PHP-FPM, Apache with mod_php, php-cgi, FrankenPHP and LiteSpeed, and the PHP team considers risk highest for mod_php because an unauthenticated request can trigger the attack before any application code runs. The flaws are credited to researchers from Calif, Wiz and OpenAI. Updating WordPress does not fix them, because the bugs are in PHP itself.

Exploitation is already visible. Cloudflare says it detected attacks and pushed WAF rules at 03:02 UTC to block exploit traffic that can cause denial of service, remote code execution and data exposure, Reuters reported European government sites going offline, Sansec expected mass attacks within fifteen minutes of the release, and Sophos says a public proof of concept is circulating. CISA's October 21 alert states it had not observed exploitation as of publication but urges immediate updates to the four fixed versions. The UK NCSC tells organisations to inventory every PHP installation including appliances that bundle it, apply the PHP team's hardening steps, take systems offline when patching is not possible, and inspect for backdoors before upgrading.

Watch how quickly the published proof of concept becomes mass scanning, whether CISA adds either CVE to the Known Exploited Vulnerabilities catalog, and how quickly distributions backport to end-of-life branches. One governance detail worth noting: Chainguard published container images containing the fix at 07:41 UTC, more than six hours before the coordinated release, which let attackers study the patch in binary form while other PHP users were still waiting, and the PHP Foundation said so publicly.
