The PHP security team warned administrators to prepare for emergency updates addressing two critical vulnerabilities, CVE-2026-109618 and CVE-2026-109619, each rated 9.2 under CVSS v4.0, after information about the flaws leaked ahead of scheduled disclosure. watchTowr confirmed the two CVEs are real RCE vulnerabilities in PHP that could let attackers run their own code on affected servers, reportedly affecting every PHP version from PHP 5 onward, and stated no in-the-wild exploitation had been reported as of October 21, 2026. Kevin Beaumont (GossiTheDog) posted that the CVEs leaked before a patch was available, and Florian Roth noted an RCE in PHP core with a CVSS 10.0 score, with patches only for PHP 8 since other versions reached end of life. PHP released the fixes on October 21 at 14:00 UTC.

The leak-ahead-of-patch dynamic means administrators had to react to partial, unverified information before official guidance, and the broad version range (PHP 5 onward) raises the exposure surface for legacy installs that no longer receive updates. Organizations running end-of-life PHP versions have no vendor patch and need compensating controls or migration.

Apply the October 21 updates immediately on PHP 8.x instances, and isolate or upgrade legacy PHP deployments that cannot be patched; monitor for exploitation now that details are public.
