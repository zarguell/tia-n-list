PHP's 21 October 2026 emergency release fixed the two PHP2Shell remote code execution flaws CVE-2026-109618 and CVE-2026-109619, each rated CVSS v4.0 9.2. CVE-2026-109618 is an out-of-memory handling bug that leaves request data partly initialized before cleanup treats it as valid; CVE-2026-109619 is a stale global state bug where request-owned memory survives into a later request on the same worker. Fixed releases are 8.5.12, 8.4.27, 8.3.36 and 8.2.35. The highest risk is Apache mod_php, where an unauthenticated request can reach the vulnerable path before application code runs. watchTowr confirmed the flaws after details leaked, Amazon's MadPot honeypots logged an attempt on 17 October before disclosure, and CISA added both CVEs to its Known Exploited Vulnerabilities catalog on 26 October.

The 18 November advance notice set the next regular security release for 19 November between 14:00 and 14:30 UTC, covering all supported PHP versions. Securityweek reports that one defect expected in that batch is CVE-2026-115560, a remote code execution issue in file-upload progress tracking disclosed on 23 October. PHP says it triggers only when an application sets session.serialize_handler to php_binary or php_serialize, switches to php at runtime with ini_set() before session_start(), and leaves session upload progress enabled. The PHP2Shell fixed releases do not address it; the stated mitigation is session.upload_progress.enabled=0. Whether the 19 November release fixes only that unusual configuration or carries further critical defects will be clear from the shipped version numbers and CVE mapping.

The unpatched tail is the practical exposure. Qualys found about 199,000 of 156 million PHP package installations with a known version patched in the first 12 hours after PHP2Shell, and Palo Alto telemetry put more than 22.6 million internet-exposed instances in scope. Reuters reported government sites in Europe going offline after disclosure, and Cloudflare counted millions of attempts after publication. For this hour, the action is to inventory PHP versions and mod_php use, apply the 19 November updates when they land, and audit the session configuration that makes CVE-2026-115560 reachable. Any confirmed exploitation of that third flaw would change the assessment from unusual configuration to a second emergency cycle.
