PHP2Shell remains the anchor for this long-running story. PHP shipped CVE-2026-109618 and CVE-2026-109619 on 21 October in 8.5.12, 8.4.27, 8.3.36 and 8.2.35 after details leaked a day early. Both unauthenticated RCE flaws are rated CVSS v4.0 9.2. CVE-2026-109618 involves out-of-memory corruption during request cleanup, while CVE-2026-109619 leaves stale global state that a later request on the same worker can use. Apache mod_php carries the highest risk, with a demonstrated exploit that runs before application code. Amazon's MadPot honeypots captured an attempt on 17 October, four days before disclosure, and Cloudflare later counted millions of attempts.

Success claims moved from scanning to evidence. Adel Karimi's honeypots running PHP 8.4.26 under mod_php logged 35 shells across three sensors on 24 October, with an 800 KiB decoded cookie dump and a function address derived from that dump appearing in the execution payload. Marcus Hutchins reviewed the trace as the strongest confirmation he had seen. CISA added both CVEs to KEV on 26 October with an October 29 federal remediation deadline. Censys at one point tracked 32.4 million PHP services on affected versions, and appliance vendors had to ship their own firmware fixes because embedded PHP cannot be patched by the operator.

The story continued with CVE-2026-115560, disclosed on 23 October and left for the regular release cycle. It needs an application that sets session.serialize_handler to php_binary or php_serialize, switches to php with ini_set before session_start and leaves session upload progress enabled. Disabling session.upload_progress.enabled was the mitigation, and the same setting applied to CVE-2026-109619. On 19 November PHP released 8.5.13, 8.4.28, 8.3.37 and 8.2.36, with reports ranging from 12 to 18 fixed issues and seven rated critical. The new set includes CVE-2026-115560, CVE-2026-129289, a PHP-FPM request smuggling RCE tied to reused backend connections, CVE-2026-126714, called phpAfterShell, plus use-after-free flaws CVE-2026-129474, CVE-2026-129496 and CVE-2026-129182, the last described as an incomplete fix for CVE-2026-109619. A late Secquill notice still described the November 19 release as scheduled and named only all supported versions, so it adds no fixed-version detail.

Watch which builds actually reach internet-facing workers, whether PHP processes were restarted, and whether the new session and FPM flaws produce exploit evidence like the October pair did. The recurring theme is that the runtime, not the application, carries the risk, so updating WordPress alone does not help.
