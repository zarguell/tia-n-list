The PHP project shipped emergency releases 8.2.35, 8.3.36, 8.4.27, and 8.5.12 on October 21, 2026, to fix two critical RCE vulnerabilities, CVE-2026-109618 and CVE-2026-109619, each rated CVSS v4.0 9.2. The flaws affect the PHP engine itself rather than a specific application, so WordPress, Drupal, Joomla, and custom services running vulnerable versions are exposed. Technical details leaked ahead of the coordinated disclosure, prompting PHP to move the release earlier; at patch time PHP had not confirmed the affected version range, though leaked reports claimed coverage back to PHP 5, and watchTowr attributed both to RCE.

Exploitation has progressed from scanning to confirmed compromise: Amazon Threat Intelligence observed attempts beginning October 17, 2026, four days before public disclosure, with widespread activity afterward, and researcher Adel Karimi reported honeypot evidence of successful exploitation against Apache running PHP 8.4.26, including memory disclosure and remote command execution, reviewed by Marcus Hutchins. Recorded Future noted public proof-of-concept exploits and active exploitation attempts. Researchers have not established that every observed attempt compromised a real server.

What to watch: patching of all PHP runtimes (including end-of-life 8.1 and earlier, which receive no upstream fixes), exploitation against unpatched hosts, and whether PHP publishes full technical details and a confirmed affected-version matrix. Upgrading legacy PHP versions remains a priority for internet-facing systems.
