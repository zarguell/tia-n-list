PHP2Shell is the pair of unauthenticated remote code execution flaws CVE-2026-109618 and CVE-2026-109619, both rated CVSS v4.0 9.2. Details leaked on October 20, a day ahead of PHP's emergency release at 14:00 UTC on October 21, which shipped fixes in 8.5.12, 8.4.27, 8.3.36 and 8.2.35. CVE-2026-109618 is an out-of-memory corruption chain where a fatal error leaves a hash table half initialised; CVE-2026-109619 leaves stale global state that enables heap use-after-free and memory disclosure. PHP-FPM, Apache mod_php, php-cgi, FrankenPHP and LiteSpeed were named as affected handlers, with the clearest exploit against mod_php where a request can trigger the bug before application code runs.

Exploitation began before the patch. Amazon Threat Intelligence recorded attempts on October 17, and a Perplexity honeypot captured successful RCE against Apache mod_php on PHP 8.4.26: an 800 KiB decoded cookie dump yielded a function address used in the next payload, and a shell command ran about 1.6 ms after the final request byte. CISA added both CVEs to KEV on October 26. Unit 42 counted over 22.6 million potentially vulnerable internet-facing instances, while Qualys reported only 199,000 of 156 million version-identified PHP installations patched in the first twelve hours.

Patch follow-up has not closed the file. The November 19 update shipped 18 CVEs in 8.5.13, 8.4.28, 8.3.37 and 8.2.36, including CVE-2026-129289, a CVSS 9.2 PHP-FPM request smuggling flaw, CVE-2026-129474, a use-after-free in magic method backtraces, CVE-2026-129496, a timezone cache use-after-free, and CVE-2026-129481, an incomplete fix for CVE-2026-109619 that does not affect PHP 8.2. The newest addition is phpAfterShell, CVE-2026-126714, a CVSS 9.2 flaw in the default file-based session handler: an interrupted write can leave a session file half old and half new, and some applications can turn that corruption into RCE. The October fix blocked object creation in the upload progress callback but not this path; the full exploit chain has not been published.

A separate PHP advisory quoted on November 20 warns that HTTP and FTP stream wrappers can send data without encryption when an HTTPS or FTPS URL uses an uppercase S in the scheme. Watch for unbackported PHP 7 and 8.1 hosts, embedded PHP in management interfaces, and appliances that cannot take upstream packages. Connection-reuse setups now need the November fixes as well as the PHP2Shell patches.
