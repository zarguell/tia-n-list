PHP's emergency security release on 21 October 2026 fixed two critical unauthenticated remote code execution vulnerabilities, CVE-2026-109618 and CVE-2026-109619, collectively called PHP2Shell. Both are rated CVSS v4.0 9.2. CVE-2026-109618 is an out-of-memory handling flaw that leaves request data partly initialized before cleanup treats it as valid; CVE-2026-109619 is a stale global state flaw in which request-owned memory survives into a later request on the same worker. Fixed versions are 8.5.12, 8.4.27, 8.3.36 and 8.2.35, with source-only backports for 7.4, 8.0 and 8.1 and no fix for PHP 5.4 through 7.3. The risk is highest for Apache mod_php, where an unauthenticated request can reach the vulnerable path before application code runs.

Technical details leaked on 20 October, a day ahead of the coordinated release. watchTowr confirmed the flaws were real and reproduced CVE-2026-109618; Amazon's MadPot honeypots recorded an attempt on 17 October, four days before disclosure, from a commercial anonymization network. Cloudflare reported millions of attempts after publication, and Palo Alto telemetry put more than 22.6 million internet-exposed instances in scope. Qualys found only 199,000 of 156 million PHP package installations with a known version patched in the first 12 hours. Perplexity's Adel Karimi later confirmed successful code execution against PHP 8.4.26 under Apache mod_php, with 35 shells launched across three honeypots on 24 October in a four-request chain matching the public proof of concept. CISA added both CVEs to the Known Exploited Vulnerabilities catalog on 26 October with a 29 October federal remediation deadline. A follow-up flaw, CVE-2026-115560, affects an unusual session configuration and is mitigated by setting session.upload_progress.enabled=0; it is not fixed by the PHP2Shell releases.

A separate development arrived on 18 November: the PHP security team issued an advance notice for its regular four-week release cycle, scheduling security updates for 19 November between 14:00 and 14:30 UTC and saying they will address vulnerabilities across all supported PHP versions. The notice does not name CVEs or say whether the upcoming fixes relate to PHP2Shell or to the partial configurations left by CVE-2026-115560. GBHackers and The Hacker News both carried the scheduling notice, and a Register comment piece treated it as another critical patch day. What to watch is the 19 November release itself: fixed version numbers and any CVE mapping will show whether this is routine maintenance or a second emergency round. Until then, the confirmed PHP2Shell exploitation and the large unpatched tail remain the concrete risk.
