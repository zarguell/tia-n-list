Two critical unauthenticated remote code execution flaws in PHP core, CVE-2026-109618 (out-of-memory corruption) and CVE-2026-109619 (stale global state leading to heap use-after-free), were each rated CVSS v4.0 9.2. They affect all PHP installations serving web requests across versions 5 through 8, with the highest risk on Apache configurations using mod_php, where an unauthenticated request can trigger the attack before any application code runs. The flaws were discovered by Calif, Wiz and OpenAI security researchers, and surfaced publicly when details leaked on social media ahead of the embargo on October 20, 2026.

The PHP security team released emergency fixes on October 21, 2026 in PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35, pulling the release forward from its planned date. End-of-life branches (8.1 and older) receive no upstream fixes, though minimal backports were published for PHP 7.4, 8.0 and 8.1 and some LTS vendors backport patches. PHP states there is no complete mitigation other than updating. Affected runtimes include PHP-FPM, Apache with mod_php, php-cgi, FrankenPHP and LiteSpeed.

CISA added both CVEs to the Known Exploited Vulnerabilities catalog after confirmed exploitation, with a federal patch deadline around October 29. Proof-of-concept exploits circulated before the patches landed; WatchTowr observed in-the-wild exploitation attempts at scale, including abuse of PHP's session upload-progress feature, and Cloudflare's CTO reported early attacks emerging. Separately, Eclypsium's InfraTrust Pulse warns that many network appliances embed PHP in their management interfaces, so customers cannot self-patch and must wait for vendor firmware, and recommends keeping PHP-backed management interfaces off the Internet until patched.

A third flaw, CVE-2026-115560, emerged after the emergency patches as another RCE tied to the session upload-progress area; The Register reported it will not receive an emergency fix. Some researchers also reported that PHP 8.5.12 may still be vulnerable. In a separate finding, SOCRadar identified PHP2Shell tooling on an operator's server but found no link between that tooling and a concurrent extortion campaign against Japanese real estate sites.
