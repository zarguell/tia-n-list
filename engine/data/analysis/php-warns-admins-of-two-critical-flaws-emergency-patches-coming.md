PHP's security team shipped emergency patches on October 21, 2026 for two unauthenticated remote code execution flaws tracked as CVE-2026-109618 and CVE-2026-109619, collectively called PHP2Shell. Each is rated CVSS v4.0 9.2 and affects PHP 5 through 8, with fixes in versions 8.5.12, 8.4.27, 8.3.36 and 8.2.35 plus source-only backports for older branches. The flaws leaked before patching, including CVE IDs and mitigation guidance shared with critical infrastructure providers, and several proof-of-concept exploits circulated, though the PHP team stated none were functional. Multiple firms (Cloudflare, Amazon, Hadrian, watchTowr, Previdian, Patchstack) saw exploitation attempts before disclosure, all tagged unsuccessful; Amazon Threat Intelligence traced attempts back to October 17, four days before patches landed. CISA added both flaws to the Known Exploited Vulnerabilities catalog on October 26 and set an October 29 remediation deadline for federal civilian agencies under Binding Operational Directive 26-04.

The CISA KEV designation raises the stakes for any organization running PHP, since unauthenticated RCE in the runtime itself exposes every site built on WordPress, Drupal and similar platforms regardless of application-level controls. A separate SOCRadar finding tied a weaponized PHP2Shell reproducer to an operator who ran an extortion campaign against Japanese real estate sites, though the tooling arrived only on October 21 and shows no link to those intrusions. Watch for whether CISA or vendors publish victim evidence behind the KEV listing, for any functional exploit code appearing now that patches are out, and for follow-on advisories from Cisco, Palo Alto and Schneider that could extend the affected surface beyond standard web stacks.
