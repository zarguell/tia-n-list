PHP's security team issued emergency updates on October 21, 2026 for two critical unauthenticated remote code execution vulnerabilities, CVE-2026-109618 (RCE via OOM corruption) and CVE-2026-109619 (RCE via stale global state), collectively known as PHP2Shell, each rated CVSS v4.0 9.2. The flaws are believed to affect PHP versions 5 through 8 and were patched in versions 8.5.12, 8.4.27, 8.3.36, and 8.2.35; all other versions are end of life but remain vulnerable, and the flaws date back to versions from 2004 onward. Information about the embargoed vulnerabilities leaked ahead of the scheduled disclosure, prompting PHP to accelerate the release from the planned date. watchTowr confirmed the flaws were real and urged administrators to patch, while Kevin Beaumont published the fixed versions and noted the highest risk for mod_php, where an unauthenticated request can trigger the attack before any application code runs. All PHP installations serving web requests, including PHP-FPM, Apache with mod_php, php-cgi, FrankenPHP, and LiteSpeed, were urged to update immediately. For CVE-2026-109619 the recommended mitigation is setting session.upload_progress.enabled=0 and restarting every worker, which blocks the confirmed session paths; PHP later disclosed a separate, lower-risk flaw, CVE-2026-115560, also mitigated by disabling session.upload_progress.

The impact is unusually broad because PHP powers content management systems, e-commerce platforms, and custom web services, and dependency scanners will not catch a runtime flaw. Amazon Threat Intelligence reported that its MadPot honeypot captured exploitation attempts on October 17, 2026, four days before public disclosure, with varied payloads and anonymization suggesting multiple actors; AWS CISO CJ Moses said PHP2Shell is now seeing broad exploitation attempts in the wild. Dataminr's TRACE team separately observed scanning, fingerprinting, and non-working exploits with no known compromises, while noting that working proof-of-concept code or successful exploitation could follow. NowSecure identified 426 Android and iOS applications whose backends are exposed to PHP2Shell, showing the risk extends to mobile clients through shared server-side code.

Response should prioritize upgrading to the fixed PHP versions, or applying the session.upload_progress mitigation where patching is not immediately possible, followed by restarting all workers. Because mod_php configurations allow pre-application exploitation, internet-facing PHP services should be treated as actively targeted. Teams should also inventory mobile application backends and any non-standard PHP builds, since all versions outside the four fixed releases remain vulnerable. CVE-2026-115560 is a separate issue that is not fixed by the emergency updates and should be tracked on its own.
