PHP Warns Admins of Two Critical Flaws: PHP2Shell (CVE-2026-109618, CVE-2026-109619)
On October 21, 2026 PHP released emergency updates (8.5.12, 8.4.27, 8.3.36, 8.2.35) for two critical unauthenticated remote-code-execution vulnerabilities in the PHP runtime, rated CVSS v4.0 9.2. CVE-2026-109618 exploits out-of-memory corruption; CVE-2026-109619 exploits stale global state. Both work before application code runs, affecting mod_php, PHP-FPM, php-cgi, FrankenPHP and LiteSpeed. Amazon Threat Intelligence recorded exploitation attempts on October 17, four days before disclosure, via its MadPot honeypot fleet, suggesting multiple actors already had working payloads. Cloudflare, watchTowr, Hadrian and Patchstack all reported scanning and exploitation attempts after the leak on October 20.
A third related issue (CVE-2026-115560) affects session upload progress and requires an unusual server configuration; PHP advised setting session.upload_progress.enabled=0 as mitigation. Organizations should patch immediately, restart workers after patching (older PHP processes may stay active in memory), and check logs from October 17 onward for multipart and session-upload-progress requests. Over 22.6 million internet-exposed PHP instances were potentially vulnerable according to Palo Alto Networks telemetry.
