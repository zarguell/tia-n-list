The PHP security team warned administrators to prepare for emergency updates to address two critical remote code execution vulnerabilities, CVE-2026-109618 and CVE-2026-109619, after details leaked ahead of the scheduled disclosure. Both were rated CVSS v4.0 9.2 and reportedly affect every PHP version from PHP 5 onward, with watchTowr confirming the flaws are real and urging administrators to patch. The PHP team scheduled the release for Wednesday, October 21, 2026 at 14:00 UTC, a day earlier than researchers under embargo had been working toward, and reserved the right to release earlier if details became public or evidence of active exploitation appeared. Kevin Beaumont listed fixed versions 8.5.12, 8.4.27, 8.3.36, and 8.2.35, noting all other versions are end of life but remain vulnerable and that the flaws date back to code from 2004. Florian Roth separately stated that only PHP 8 would receive patches because older branches had reached end of life. As of October 21, 2026 no exploitation in the wild had been reported.

The leak-before-patch dynamic is the core risk. With technical details circulating on social media and a CVSS 9.2 RCE in a runtime that underpins a large share of the web, the window between disclosure and mass exploitation is likely short. Organizations running end-of-life PHP branches face the hardest position, since no official patch will be issued for their versions and migration or virtual patching becomes the only remediation.

What to watch: whether proof-of-concept code is published and how quickly exploitation follows. Administrators should apply the available patches immediately, inventory end-of-life PHP installations, and consider web application firewall rules or network segmentation for systems that cannot be upgraded promptly.
