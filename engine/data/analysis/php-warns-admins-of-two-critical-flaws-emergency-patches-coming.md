PHP2Shell is the name for CVE-2026-109618 and CVE-2026-109619, two unauthenticated remote code execution flaws rated CVSS v4.0 9.2 that were leaked on October 20, 2026, a day before PHP's emergency release at 14:00 UTC on October 21. The bugs leave PHP memory corrupted when a request ends abnormally. One path is an out-of-memory corruption chain, the other a stale global state flaw enabling heap use-after-free and memory disclosure. Affected request handlers include PHP-FPM, Apache mod_php, php-cgi, FrankenPHP, and LiteSpeed. Emergency fixes shipped in 8.5.12, 8.4.27, 8.3.36, and 8.2.35.

Exploitation moved from probing to confirmed execution. Amazon recorded first attempts on October 17 from anonymized infrastructure, before disclosure. A honeypot run by Perplexity captured a successful attack against Apache mod_php on PHP 8.4.26, with an 800 KiB decoded cookie dump, a function address derived from that dump, and a shell command running about 1.6 ms after the exploit request. Marcus Hutchins called it the strongest confirmation he had seen. CISA added both CVEs to its KEV catalog and gave federal agencies until Thursday under BOD 26-04. Mirai botnet operators also folded the flaws into exploitation attempts.

Patch follow-up has continued. CVE-2026-115560, a session serializer mismatch disclosed on October 23, was not fixed by the October emergency releases, and admins were told to disable session upload progress where the configuration applies. The November 19 update fixed 18 CVEs in 8.5.13, 8.4.28, 8.3.37, and 8.2.36, including CVE-2026-129289, a CVSS 9.2 PHP-FPM request smuggling flaw in setups that reuse backend connections, and CVE-2026-129481, an incomplete fix for the PHP2Shell use-after-free. Watch for stale PHP 7 and 8.1 systems without vendor backports and for evidence of shells on hosts patched after the first probes.
