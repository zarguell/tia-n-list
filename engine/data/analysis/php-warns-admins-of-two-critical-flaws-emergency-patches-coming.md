The PHP story now spans two patch waves. On 21 October PHP fixed PHP2Shell CVE-2026-109618 and CVE-2026-109619, both rated CVSS 4.0 9.2, in 8.5.12, 8.4.27, 8.3.36 and 8.2.35. Amazon's MadPot honeypot captured exploitation attempts on 17 October, four days before disclosure, and CISA added both CVEs to KEV on 26 October. A honeypot running Apache mod_php with PHP 8.4.26 later produced a confirmed RCE with an 800 KiB decoded cookie dump and a shell command executed about 1.6 ms after the final request byte.

The 19 November release shipped fixes in 8.5.13, 8.4.28, 8.3.37 and 8.2.36. Aikido counted 18 CVEs across the core engine, session handling, PHP-FPM and CGI. CVE-2026-129289 is a PHP-FPM request-smuggling RCE rated CVSS 9.2 that matters where nginx, Apache, HAProxy or LSAPI reuse backend connections; standard configurations without reused connections are not affected. CVE-2026-115560 is a session serializer mismatch that writes attacker data with php_binary or php_serialize and reads it with php when a gadget chain exists. CVE-2026-129474 and CVE-2026-129496 are use-after-free flaws also described as possible RCE paths.

A newer flaw, phpAfterShell CVE-2026-126714, uses a partially overwritten session file to make PHP's default file-based session storage return attacker-chosen objects; code execution needs a suitable gadget chain in the application. CVE-2026-129481 is listed as an incomplete fix for the PHP2Shell session-shutdown issue, though PHP says code execution through that specific field has not been demonstrated. Watch for FPM connection reuse, session settings that leave upload progress enabled, bundled PHP runtimes and any exploitation reports tied to the November CVEs rather than the older pair.
