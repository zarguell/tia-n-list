PHP warned administrators of two critical out-of-cycle security fixes: CVE-2026-109618 (remote code execution via out-of-memory corruption, CVSS v4.0 9.2) and CVE-2026-109619 (remote code execution via session upload-progress corruption, also 9.2). Fixes were released in PHP 8.5.12, 8.4.27, 8.3.36, and 8.2.35. WatchTowr and CISA both confirmed active exploitation, with the flaws added to the KEV catalog shortly after disclosure. Dream researchers later linked these vulnerabilities to root-level firewall compromises.

The rapid progression from disclosure to confirmed in-the-wild exploitation, including government-affiliated targets, makes immediate patching essential. Unpatched internet-facing PHP instances are at high risk because the vulnerabilities are straightforward to exploit and have been incorporated into automated toolchains. Organizations relying on older PHP branches should evaluate upgrade paths, as the fixes cover versions back to 8.2.
