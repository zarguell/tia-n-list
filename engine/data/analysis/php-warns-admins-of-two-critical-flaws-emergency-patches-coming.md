PHP disclosed two critical remote code execution flaws after details leaked ahead of a scheduled security release. The flaws are tracked as CVE-2026-109618 and CVE-2026-109619, called PHP2Shell by researchers, and each was rated 9.2 under CVSS v4.0. CVE-2026-109618 involves out of memory handling that can interrupt PHP while internal request data is partly initialized, and CVE-2026-109619 involves stale global state that can survive after its backing memory is freed.

The PHP security team released an emergency update on October 21, shipping fixes in PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35, with source backports for older branches. Researchers at watchTowr reproduced one flaw and reported in the wild exploitation attempts against honeypots as early as October 17, four days before the patch. Wiz, OpenAI and Calif identified the issues in August, and OpenAI said given the severity and PHP widespread use it considered the issue one of the most impactful security issues in recent memory.

On October 23, PHP published an advisory for a further issue, CVE-2026-115560, in PHP session management that can allow remote code execution but requires an uncommon combination of server configuration and application behavior. Watch for the promised emergency patches and any confirmation of in the wild scanning.
