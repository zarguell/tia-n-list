PHP2Shell remains the core of this story: CVE-2026-109618, an out-of-memory corruption flaw, and CVE-2026-109619, a stale global state flaw, both CVSS 9.2, allow unauthenticated code execution as the PHP worker. Amazon MadPot saw an attempt on October 17, four days before disclosure; Cloudflare saw thousands of attempts in the ten hours before the announcement; Adel Karimi logged 35 shells across three honeypots on October 24 with an 800 KiB memory disclosure. CISA added both CVEs to the KEV catalog on October 26 with an October 29 federal deadline. Wordfence had logged more than 74,000 exploit or probe attempts by October 23 but had not confirmed a compromise of a protected WordPress site as of October 28.

The November 19 release added a second wave. PHP shipped 18 fixes in 8.5.13, 8.4.28, 8.3.37 and 8.2.36, including CVE-2026-115560, the session serializer mismatch RCE left for the normal cycle; CVE-2026-129289, a CVSS 9.2 PHP-FPM request-smuggling flaw affecting nginx, Apache, HAProxy and LSAPI setups that reuse backend connections; CVE-2026-129481, an incomplete fix for CVE-2026-109619; and phpAfterShell CVE-2026-126714, where an interrupted file-based session write leaves a hybrid session file that can become a deserialization primitive. CVE-2026-129474 and CVE-2026-129496 are use-after-free flaws in magic-method backtraces and the timezone cache. The full phpAfterShell chain has not been published.

A November 20 Wordfence write-up and a November 21 link spell out the practical test for CVE-2026-129289. Wordfence confirmed unauthenticated code execution in an isolated WordPress lab; the same test failed after PHP was updated and after web-server-to-PHP-FPM connection reuse was disabled. Standard nginx configurations do not enable that reuse by default, so exposure depends on hosting configuration rather than WordPress itself. Other events in the same window note that PHP's HTTP and FTP stream wrappers can drop encryption when an HTTPS or FTPS URL uses an uppercase S in the scheme.

Patching still requires restarting every PHP worker, and vendor backports can carry different version numbers. The interim mitigation for the session issues is session.upload_progress.enabled=0. Watch for appliance firmware from PAN-OS, QNAP, Cisco and industrial vendors that embed PHP, and for any report that phpAfterShell moved from a lab primitive to observed exploitation.
