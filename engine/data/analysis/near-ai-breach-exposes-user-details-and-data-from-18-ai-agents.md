Near AI disclosed on November 9, 2026 that an attacker reached its servers by exploiting a remote code execution flaw in SGLang, the open-source inference engine behind its deployment, and the intrusion on November 8 exposed account data for about 100 users plus data from 18 AI agents. The exposed agents sat on a legacy NEAR AI Agents deployment that ran outside the company's confidential computing environment, and their chat histories, settings, and logs were reachable. NEAR AI has since restored its Cloud service after containing the breach.

The user count is small, so the count is not the story; the story is that the compromised asset class was agents, not people. An agent's chat history, settings, and logs are a working map of the tools, prompts, and credentials it was authorized to use, and 18 of them fell outside the confidential computing boundary because they were legacy. That turns a 100-user incident into a lateral-movement problem: whoever holds those agent contexts can replay them against whatever those agents could reach. SGLang is also not a one-off target, since 2026 alone produced unauthenticated RCE disclosures including CVE-2026-3059 in the ZMQ broker, CVE-2026-5760 at CVSS 9.8 through a malicious GGUF tokenizer template, and CVE-2026-86793 as a SafeUnpickler bypass, so an unpatched build is close to one model load away from code execution.

Confirm the SGLang version on every inference host against the published advisories; 0.5.10 is the fix boundary for CVE-2026-3059, and anything older should be treated as exposed. Rotate the credentials and API keys reachable from the 18 affected agents, and audit their chat histories and logs for use after November 8, 2026. Keep the SGLang ZMQ broker and server ports on trusted networks rather than binding publicly, and treat every model file and weight source as untrusted input, since CVE-2026-5760 and the deserialization paths trigger on loading crafted model artifacts.

Watch for the specific CVE Near AI assigns to this intrusion, because the coverage to date describes only an RCE in SGLang, and whether the exploited build was already patched changes the remediation. Also watch whether other self-hosted inference operators on the same engine report exploitation, which would move this from one vendor's incident to a sector-wide pattern.
