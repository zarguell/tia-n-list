wp2shell is a pre-authentication RCE chain in WordPress Core, disclosed July 17, 2026 through coordinated advisories. CVE-2026-63030 (GHSA-ff9f-jf42-662q, Critical, CVSS 7.5) is REST API batch-route confusion introduced in WordPress 6.9; chained with CVE-2026-60137 (GHSA-fpp7-x2x2-2mjf, Moderate), a SQL injection in WP_Query's author__not_in parameter present since 6.8, it gives an anonymous attacker code execution on versions 6.9.0-6.9.4 and 7.0.0-7.0.1 with no plugins and no preconditions. The disclosure record behind this story is richer than its event trail shows: Searchlight Cyber researcher Adam Kues found the chain, the companion SQL injection is credited to TF1T, dtro, and haongo, and WordPress shipped 7.0.2 and 6.9.5 the same day, with 6.8.6 covering the SQL injection alone and nothing before 6.8 affected. Searchlight deliberately withheld technical details and launched the wp2shell.com exposure checker at disclosure, while forced auto-updates pushed the fixes to installations that accept them.

The severity here is the denominator, not the score. WordPress runs roughly 500 million sites, about 43 percent of the web, and the vulnerable path is reachable on default installs without a persistent object cache, which is most of them. Exploitation outran most patch cycles: public PoCs and first in-the-wild signs appeared within a day, Patchstack and Hexastrike honeypots recorded traffic the same weekend, and CISA put both CVEs in KEV on July 21, triggering federal remediation requirements. The GreyNoise report then changes the category of risk from opportunistic scanning to espionage: a single suspected Chinese-speaking operator, tracked since early June, active in a UTC+8 pattern and possibly linked to Acronis' Red Heron campaign, folded wp2shell into a broader campaign on July 20, three days after patches landed, and went on to compromise at least 49 organizations across 29 countries, stealing 18,566 records from one Western government body. The intrusion detail carries the real lesson: the actor dumped the user table for 13 administrator accounts, created a rogue admin with a backdated registration date, and profiled the Windows server for security tools and database software, so patching closes the entry path but not the foothold; every confirmed victim must treat credentials, plugin inventory, and database secrets as already burned.

Verification and containment are concrete. Confirm internet-facing sites run 7.0.2, 6.9.5, or 6.8.6 or later, and use Searchlight Cyber's wp2shell.com checker plus Cloudflare WAF rules, which cover all plans including free, as a stopgap. Where patching lags, block /wp-json/batch/v1 and ?rest_route=/batch/v1 at the WAF or install a plugin cutting anonymous REST API access, accepting both are temporary measures that break legitimate functionality. Hunt for unauthenticated POSTs to /wp-json/wp/v2/ and the batch endpoint carrying author__not_in or batch parameters, inventory wp-content/plugins for plugin-named files that are really PHP webshells, the range Wiz documented from one-liners to obfuscated CMSmap-style shells, and diff wp_users for administrators whose user_registered dates were edited after creation, the exact forgery GreyNoise observed. On any host showing those traces, rotate admin passwords and the database credentials stored in wp-config.php, which Wiz saw attackers retrieve through local file inclusion, and expect post-exploitation enumeration of local users, network services, and database software on Windows servers.

Two developments would move this assessment. Searchlight Cyber is still holding technical detail, so a full weaponized pre-auth exploit would collapse the current gap between crude PoCs that must crack extracted password hashes and the reliable single-request chain the advisories describe; a published technical writeup or Wiz and GreyNoise releasing shell and C2 signatures would similarly widen the hunting gap. Second, formal attribution linking the UTC+8 operator to Red Heron, or a rising count from 49 organizations and 18,566 records, would upgrade wp2shell from a mass-exploitation event to a named government-targeting campaign, changing it from a patch sprint into an incident-response problem for every federal system the KEV deadline covers.
