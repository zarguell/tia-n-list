Exim released version 4.100.1 on September 18, 2026, patching four vulnerabilities in the widely deployed mail transfer agent. The most serious is GCVE-25-2026-09-50-1, an out-of-bounds write and heap-corruption flaw in Proxy Protocol v1 handling (Exim 4.83 through 4.100). A remote attacker through a buggy or compromised upstream proxy can trigger a read of roughly 230 bytes beyond a heap allocation plus a single NUL-byte write. A second high-severity issue, GCVE-25-2026-09-55-1, affects Proxy Protocol v2 and involves use of uninitialized data in header processing, discovered by McCaulay Hudson of watchTowr.

The medium-severity SMTP smuggling flaw (GCVE-25-2026-09-56-1) impacts all Exim versions through 4.100. SMTP smuggling allows an attacker to inject messages that appear to originate from the mail server itself, bypassing spam filters and impersonating legitimate senders. A fourth issue, GCVE-25-2026-09-51-1, is a stack-data leakage condition. None of the four CVEs appear to be actively exploited in the wild based on available reporting, but the SMTP smuggling class of vulnerability has a history of rapid weaponization once PoCs emerge.

Exim remains one of the most widely deployed MTAs, particularly on Linux servers and hosting infrastructure. The Proxy Protocol flaws require specific configurations (enabled Proxy Protocol with an upstream proxy), limiting the blast radius. The SMTP smuggling issue is broader since it affects default configurations. System administrators running Exim should prioritize updating to 4.100.1, particularly if the server accepts connections from untrusted proxies.
