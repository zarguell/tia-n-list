Attackers are targeting AI API tokens through poisoned npm packages, turning developer build environments into credential harvesters. The stolen tokens are either abused directly or fed into underground transfer stations that resell discounted access to expensive AI models. The related AI token jacking model works the same way at scale: threat actors steal developer API keys for popular AI platforms, consume the victim's allocated model capacity, and resell that compute through gray-market proxy services, in at least one reported case leaving the victim with a seven-figure bill.

The risk is structural rather than exotic. Attackers do not need to break into an AI provider; they steal the keys legitimate developers already use. AI providers bill by usage, so a stolen key is a direct financial liability and the victim only notices after the bill spikes. Because the tokens ride through normal build and CI pipelines, the compromise vector sits exactly where most teams are not watching: package installs in automated environments.

Watch for disclosure of the specific package names and registry campaigns, which would let teams audit lockfiles and npm audit output. The defensive moves are immediate regardless: treat AI provider keys as high-value credentials, scope them to the minimum model and quota, rotate keys exposed in build logs, and add alerting on anomalous token spend. Token jacking converts a quiet credential leak into a large, visible bill, which is both the risk and the detection signal.
