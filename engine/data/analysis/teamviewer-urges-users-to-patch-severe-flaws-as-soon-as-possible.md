TeamViewer published bulletin TV-2026-1010 on September 29, 2026, Priority Important with a CVSS ceiling of 8.8, fixing five vulnerabilities in the Full Client and Host products behind TeamViewer Remote, Tensor, and ONE on Windows, Linux, and macOS. The severe one, CVE-2026-92370, is an improper access control flaw that lets an authenticated remote attacker bypass user-configured permission settings during session establishment and perform actions the victim's configuration explicitly denied, which the vendor says can lead to code execution. The other four are local: CVE-2026-19743, a path traversal in the local IPC service letting a low-privileged user write arbitrary files as NT AUTHORITY/SYSTEM or root (7.8); CVE-2026-92368, a heap-based buffer overflow in .tvs session recording playback on Linux and macOS (7.8); CVE-2026-92369, a TOCTOU race in the Windows installer rollback path ending at SYSTEM (7.3); and CVE-2026-92371, improper link resolution in Cloud Session Recording on Linux (7.0). NVD carried all five records on September 29, roughly twenty hours before the September 30 coverage, and the bulletin states TeamViewer is not aware of public disclosure or exploitation in the wild.

Remote access tooling is a foothold organizations approve on purpose, and CVE-2026-92370 attacks the one control that constrains a session once it starts, the permission configuration on the Host. Its CVSS vector, AV:N/AC:L/PR:N/UI:R, means the attack rides a normal session the user establishes or accepts rather than a wormable pre-auth path, so the exposed population is everyone running TeamViewer Host for unattended access or answering support connections, which in MSP and enterprise support estates means most managed endpoints. For those fleets the practical failure mode is that a single abused support account stops being limited by the permissions the endpoint owner denied and becomes unsupervised control of every endpoint that account dials into. The four local flaws then raise the ceiling: a low-privilege foothold as small as a phished user opening a crafted .tvs recording chains to SYSTEM through the IPC path traversal or the installer rollback race. A network-reachable permission bypass plus two separate roads to SYSTEM, in software commonly allowlisted through corporate firewalls by design, is what separates this from routine patch Tuesday volume.

Update every Full Client and Host to 15.82, including the legacy branches the bulletin patches separately: 15.64.8 for Windows 7 and 8 systems, 14.7.48855 on Windows, Linux, and macOS, and 13.2.36230 on Windows, 13.2.153995 on Linux, 13.2.153994 on macOS. Inventory first, because unattended Hosts installed on servers and jump hosts are the persistent half of the estate and rarely ride the same patch cycle as user laptops, and question whether a server should run TeamViewer at all. Until hosts are current, refuse session recordings from outside the team, since the .tvs parser executes in the player via the "Play or convert recorded session..." feature, and keep Host permission settings restrictive rather than permissive by default. The concrete hunt is version-based: enumerate endpoints running TeamViewer below 15.82 from software inventory or EDR, flag Host installs with unattended access enabled, and alert on fresh client installs in the weeks after patching, since downgrade or reinstall is the cheapest way an operator would keep a vulnerable build alive.

Two developments would change the assessment: public exploit code for the .tvs playback overflow or the IPC path traversal, which would convert the local bugs into commodity phishing payloads, and any report of the session permission bypass being used against support desks. The bulletin's no-exploitation claim dates to September 29 and is a snapshot, so a KEV listing or a follow-up TeamViewer bulletin revising that language is the trigger to move from routine patching to incident review.
