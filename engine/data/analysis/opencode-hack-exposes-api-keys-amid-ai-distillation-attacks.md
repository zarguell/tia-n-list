OpenCode, a model-agnostic open-source AI coding agent, confirmed that a legacy authentication subsystem was breached in a large-scale distillation attack that exposed stored API keys for Anthropic, OpenAI, and Google linked by 1.4% of Console users. The attack, disclosed on October 17, 2026, did not exploit a code vulnerability but rather targeted a retiring console system, meaning the mechanism was credential access rather than a software bug with a CVE. Users reported concrete harm: unauthorized charges exceeding $1,700 overnight and suspended Google Cloud projects, confirming that exposure translated directly to financial and operational damage.

What makes this story urgent rather than another routine breach notice is that the victim population is precisely developers who link high-value provider accounts into automation tooling. Only the subset of Console users with linked external providers was affected, yet for that group every stored key was at risk, and the attacker used a distillation pipeline rather than simple data theft, suggesting structured extraction rather than opportunistic scraping. The 1.4% figure is small in relative terms but absolute exposure depends on the total Console user base, and the $1,700 single-user charge demonstrates that attacker economics scale quickly when AI provider billing is involved.

Defenders should treat this as a key-rotation event first: revoke all Anthropic, OpenAI, and Google keys linked to OpenCode workspaces immediately, then review billing logs for unauthorized usage starting October 17, 2026. Because the breach involved a legacy system being decommissioned, organizations should audit any remaining OpenCode Console integrations and disable external provider linking until the retirement completes. Network restrictions should block unexpected outbound connections from developer workstations running the OpenCode desktop or terminal agent, and hunting should focus on billing anomalies rather than endpoint malware indicators since the mechanism was server-side credential access.

The assessment would change if the attacker publishes the stolen keys or if broader exploitation beyond the notified 1.4% is confirmed, or if OpenCode releases version-specific patches or a decommissioning timeline for the legacy console. Watch for updates to the maintainer disclosure regarding additional affected providers and any telemetry showing reuse of the exposed keys against other services.
