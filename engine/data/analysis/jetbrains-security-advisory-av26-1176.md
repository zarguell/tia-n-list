JetBrains TeamCity on-premises is affected by CVE-2026-132231, a remote code execution flaw reached through best-fit character mapping in Perforce settings. The JetBrains-assigned CVE record published at 17:07:48 UTC on 18 November 2026 puts affected builds below 2025.11.7 and 2026.1.3, and the indexed CVSS 3.1 vector is AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H with a base score of 9.9. Cyber Centre advisory AV26-1176, dated the same day, repeats those two version boundaries, while securityonline counts 21 fixed flaws in the update. Neither the advisory nor the dated CVE entry names an actor, victim, exploit code or scanning telemetry.

The sharper point is the gap between fix availability and disclosure. The 2026.1.3 release notes carry build 222742 dated 27 July 2026, but the CVE record for 132231 did not appear until 18 November, so this is an inventory problem as much as a patching scramble. A network-reachable, low-privilege path into Perforce configuration with changed scope means a single compromised TeamCity account can plausibly reach build resources beyond the server itself, including source material and artifacts handled by the pipeline. Exposure is measured by installed build number, not by a victim count, because no victim count exists in the two events or the dated records; the events do show two independent feeds carrying the advisory within twenty minutes, at 21:10 and 21:30 UTC.

Patch to 2026.1.3 or 2025.11.7 according to the branch in use, then verify the running build rather than trusting the advisory date, since sites that updated after 27 July may already be fixed without having tracked this CVE. Enumerate accounts allowed to edit Perforce VCS roots and the charset setting involved in best-fit mapping, and restrict the TeamCity web interface and agent traffic to trusted networks until the build check is complete. The hunt is configuration review: diff Perforce connection settings against the last known good state and check the JetBrains fixed security issues page for the mapping of CVE-2026-132231 to build numbers. No public IoC, exploit filename or telemetry field appears in the dated sources, so indicator-led hunting has no grounding here.

What would change the assessment is a vendor fixed-issues entry that confirms the CVE-to-build mapping, or a correction to the 21-flaw count and 9.9 vector. Exploitation telemetry tied to Perforce settings, a researcher disclosure with request detail, or a KEV listing would move this from high-impact inventory work to an active incident track. Until one of those appears, the defensible call is to treat every unpatched on-premises TeamCity server as exposed and every already-updated server as a verification task.
