Huntress analysis of an early August Akira intrusion, now covered by three outlets, shows how one missing MFA control escalates a credential spray into a full network compromise. On August 4 at 03:45 UTC, SonicWall SSL VPN logs recorded failed sign-in attempts against multiple accounts from several external IPs. At 03:52 UTC one attempt succeeded on a VPN account without MFA. Nearly two hours later the attacker used RDP to reach the domain controller, enumerated Active Directory users and computers, and moved to an application server. The affiliate used WinRAR to archive mapped file shares and the s5cmd command-line tool to upload the stolen data to an attacker-controlled S3 bucket.

The case also documents a practical anti-EDR technique. The attacker installed AnyDesk, added it to the Windows Safe Mode registry so it survives reboot, and forced the compromised host into Safe Mode with Networking, which disabled both the Huntress agent and Microsoft Defender real-time protection. Huntress says the host had no working EDR and blinded AV for about 10 minutes. The encryption stage then failed on virtual-memory errors in the stripped-down boot environment, but the actor had already stolen credentials and data, preserving leverage.

The pattern is consistent with Akira's wider playbook: MFA-less VPN access is the choke point, and data theft and credential collection continue even when encryption stalls. The Safe Mode reboot is a concrete detection signal for defenders, and a failed encryption attempt should not be read as a failed intrusion.
