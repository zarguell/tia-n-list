A Huntress-documented intrusion from early August 2026 shows how one missing control decides the outcome of an Akira ransomware attempt. At 03:45 UTC on August 4, attackers ran a credential spray against a SonicWall SSL VPN from several external IP addresses; at 03:52 one login succeeded on an account with no MFA. Within roughly two hours the operator had connected to the domain controller via RDP, enumerated Active Directory users and computers, and moved to an application server.

The attacker archived mapped file shares with WinRAR and uploaded the data with the s5cmd tool to an attacker-controlled S3 bucket, then installed AnyDesk. To strip protections, the host was forced to reboot into Safe Mode with Networking, which kept the Huntress agent and Microsoft Defender real-time protection from loading for about ten minutes; AnyDesk was added to the Safe Mode registry so it would start after reboot. Huntress notes this is the first documented Akira use of Safe Mode as an anti-EDR tactic.

Encryption ultimately failed: the constrained Safe Mode environment crashed the ransomware process tree with virtual-memory errors seconds after launch, but the data was already exfiltrated, preserving extortion leverage. Watch for further Safe Mode-based EDR evasion by Akira affiliates, and for MFA enforcement on exposed SSL VPN endpoints, which remains the single control that breaks this intrusion chain at step one.
