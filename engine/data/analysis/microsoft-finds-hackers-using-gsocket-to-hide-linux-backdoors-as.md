Microsoft Security Research (Yash Gund and Sumith Maniath) reports that multiple unrelated threat actors are abusing the open-source GSocket remote-access tool and its gs-netcat client to keep encrypted access to compromised Linux servers after administrators patch the original entry vulnerability. Microsoft Defender for Endpoint telemetry recorded a 356.2% increase in GSocket-related detections between March and August 2026, with web applications and hosting environments accounting for 87.1% of attributable incidents. Affected organizations were concentrated in education and research (30.7%) followed by technology and telecommunications (22.9%).

The technique relies on GSocket's relay design rather than attacker-owned infrastructure. Both the compromised host and the operator connect outbound to the shared Global Socket Relay Network, which matches the two sessions and brokers an end-to-end encrypted channel. Because no inbound listener or public IP is needed and network address translation does not block the connection, there is no attacker IP or domain to add to a block list, and the traffic blends with legitimate outbound activity. In some incidents the actors attempted to exploit CVE-2026-43284 (Dirty Frag) to escalate to root and disguised GSocket with kernel-thread-like process names, persisting through cron jobs, systemd units, and shell profiles.

Patching the initial vulnerability is not sufficient once GSocket is installed, so detection has to be behavioral. Defenders should hunt for unexpected gs-netcat binaries, process names masquerading as kernel threads, outbound connections to the Global Socket relay network, and unauthorized cron or systemd persistence, then remove the tooling and rotate credentials on affected hosts.
