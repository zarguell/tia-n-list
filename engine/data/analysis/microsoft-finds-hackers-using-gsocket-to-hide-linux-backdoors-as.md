In the report published November 11, Microsoft Security Research described multiple unrelated threat actors using GSocket, an open-source remote access tool, together with its gs-netcat client, to keep encrypted control of compromised Linux servers. Initial access comes through remote code execution in internet-facing web applications, after which the actors deploy GSocket and route its traffic through the shared Global Socket Relay Network. Both the victim host and the operator connect outbound to that relay, so no attacker-owned IP or domain exists, no inbound listener is needed, and NAT does not stop the channel. The actors disguise the tool with kernel-thread-like process names and persist through cron, systemd units, shell startup files, and redundant copies, and in some incidents attempted to exploit CVE-2026-43284, the Linux kernel flaw known as Dirty Frag, to escalate from the web-service account to root.

The point of this story is not that a remote access tool was abused. It is that patching the original vulnerability does not remove the actor. A web application compromise normally ends when the flaw is fixed, but GSocket converts that single compromise into access that outlives remediation, which means a clean patch report is not evidence of eviction. The relay model also defeats the first instinct of most incident response, which is to block the command-and-control address, because there is no attacker IP or domain to sinkhole. Microsoft Defender for Endpoint telemetry counted a 356.2% rise in GSocket-related detections from March to August 2026, with web applications and hosting representing 87.1% of attributable incidents and affected organizations concentrated in education and research at 30.7% followed by technology and telecommunications at 22.9%. The exposure that matters is any Linux host running a public PHP, Java, or Node web application, and the sector skew follows where such hosts cluster rather than deliberate targeting.

Defenders should treat patch verification as incomplete until persistence is ruled out. Remove gsocket and gs-netcat binaries and their associated files, then confirm that outbound connections to the Global Socket Relay Network have stopped. Inbound firewall rules will not see this traffic, so rely on egress filtering and outbound monitoring instead. Hunt the persistence the report names: cron entries, systemd units, shell startup files, and authorized_keys additions, along with processes masquerading with kernel-thread-style names, and look for the Defender detections labeled GsNetcat hacktool. Confirm CVE-2026-43284 is patched so privilege escalation to root is closed.

Two developments would change the assessment. If egress filtering that blocks the relay network proves broadly effective, the tool loses its central advantage and adoption should fall. If Dirty Frag exploitation becomes routine in these intrusions rather than occasional, the same activity shifts from persistent web-shell access to full root compromise, raising the response bar considerably.
