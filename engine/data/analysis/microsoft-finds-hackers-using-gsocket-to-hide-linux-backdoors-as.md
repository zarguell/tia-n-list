Microsoft reported on November 11, 2026 that multiple, unrelated threat actors are abusing GSocket, a legitimate open-source remote access tool, to maintain persistent access to compromised Linux servers. The key point is that attackers keep access even after administrators patch the vulnerabilities used for initial entry. Defender for Endpoint telemetry recorded a 356.2% increase in GSocket-related detections between March and August, concentrated in attacks against web applications and hosting environments.

GSocket is effective for persistence because of how it moves traffic. It lets an operator reach a host behind a firewall or NAT by intercepting network connections and replacing the conventional IP-layer transport with its own, routing traffic through the Global Socket Relay Network. Both the compromised host and the operator connect outbound to the relay, which matches the two sessions and brokers an end-to-end encrypted channel. The host needs no inbound listener, no public IP, and no dedicated command-and-control server. Attackers also disguised GSocket processes as legitimate system components to blend in.

That outbound-only design defeats the controls most defenders rely on. IP- and domain-based blocklists see only connections to relay infrastructure, and there is no inbound implant to find or a C2 domain to sinkhole, so evicting the tool after patching the entry vector is hard. The practical response is behavioral: monitor for unexpected outbound connections from server processes, flag unknown binaries masquerading as system components, and treat the presence of GSocket as evidence that an initial-access vulnerability was already exploited and that other implants may remain.
