LiteLLM 1.107.0 on PyPI shipped seven backdoored wheels (Linux, macOS, Windows) that install three extra files under litellm-1.107.0.data/purelib/ (cook.pth, cook.py, sitecustomize.py), which pip places on sys.path so they execute on every Python interpreter startup without any explicit LiteLLM import. The payload is a credential stealer plus a persistent backdoor: it collects SSH and GPG keys, AWS and other cloud credentials, browser passwords and cookies, shell history, and AI coding tool configs, and it runs a daemon that contacts the attacker's server every hour and executes whatever code is returned. The malicious release was built from a lookalike GitHub repository (Berri-AI/litellm) rather than the legitimate source tree, and the source distribution on PyPI did not contain the three payload files, so reviewers inspecting only sdist or a Git tag would miss it. PyPI removed 1.107.0 at 13:23 UTC on 2026-10-21, but the Docker images (latest, main-latest, main-stable on ghcr.io/berriai/litellm and variants) remained infected.

The blast radius is broader than a normal package compromise because cook.pth and sitecustomize.py fire on every Python process start on the host, meaning IDEs, pip invocations, and CI jobs are all execution points, not just applications that import LiteLLM. Any developer machine or build runner that installed 1.107.0 and subsequently ran Python is potentially compromised, regardless of whether the project ever imported the library. The three reporting sources (safedep.io, aikido.dev, research.jfrog.com) corroborate a real multi-vector incident spanning both PyPI and Docker Hub, so this is not a single-report anomaly; teams should treat installed-version inventories as the starting point, not import graphs.

Defenders should pin to 1.106.2, remove 1.107.0 and any cached wheels, and audit Python site-packages for cook.pth, cook.py, and sitecustomize.py artifacts. Rotate SSH keys, cloud credentials, browser-stored passwords, and any AI tool tokens present on affected hosts, and review shell history and CI secret stores for exposure. Hunt for the hourly backdoor daemon and outbound connections to the attacker's command server in process and network telemetry, and inspect Docker images by digest rather than tag, since latest and main-stable remained infected after PyPI removal.

The assessment changes if the malicious lookalike repository is found to have compromised additional releases beyond 1.107.0, if the command server is found to have returned destructive payloads rather than exfiltration-only code, or if downstream organizations report follow-on breaches from credentials stolen during the window between the 11:39 UTC upload and PyPI takedown.
