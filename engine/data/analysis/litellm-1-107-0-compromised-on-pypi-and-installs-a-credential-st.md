LiteLLM 1.107.0 and its official container images were compromised on PyPI and contained a credential stealer plus a backdoor. The malicious code runs during Python interpreter startup, so any Python process on an affected host, including pip and IDEs, could trigger it without importing LiteLLM. The payload steals SSH keys, AWS credentials, browser passwords, shell history, and AI tool configs, and a backdoor daemon executes attacker-supplied code roughly every hour.

Microsoft's analysis of the affected wheels identified two execution paths: a credential collector launched through a path extension and a Unix loader persisted via site configuration. The collector reached authentication material across developer tools, AI applications, cloud environments, browsers, and infrastructure, and a database module read credential and model-configuration records from the LiteLLM proxy. Endpoint behavior on Windows and macOS matched the recovered collector. Because even a routine pip invocation can activate the collector, investigators should not run Python or pip inside a suspect environment.

Response should focus on credential rotation, persistence hunting, and pinning to version 1.106.2. Organizations should treat any host that ran the affected release as fully compromised and avoid executing Python in those environments during triage.
