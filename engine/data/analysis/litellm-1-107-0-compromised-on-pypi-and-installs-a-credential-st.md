LiteLLM 1.107.0 was compromised on PyPI by Team PCP in March 2026. The malicious package installs a credential stealer and backdoor that activates on every Python startup, not only on LiteLLM import. It harvests SSH keys, AWS credentials, browser passwords, shell history, and AI coding tool configurations, then runs a daemon that executes attacker commands hourly. Organizations should pin to 1.106.2 and rotate cloud credentials, audit pipeline secrets, and review Kubernetes access as if the dependency chain was fully compromised.

CloudSEK analysis reconstructs exposure across more than 2,500 organizations and roughly 434,000 CI/CD pipelines worldwide. The short-lived malicious package created standing risk to cloud credentials, source repositories, Kubernetes environments, package registries, and AI services downstream of build and deploy chains. The concrete artifacts include the backdoor daemon, hourly command-and-control callbacks, and stolen secrets categories named in the event content.

Watch for further disclosure from the original RedTeam reporting and any vendor updates from LiteLLM or PyPI. The story carries 26 sources, no CVE, and a peak score of 8.0, confirming sustained attention rather than a single-day spike.
