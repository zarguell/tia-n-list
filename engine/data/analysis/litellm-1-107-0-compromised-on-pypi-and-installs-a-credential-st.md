On October 21, 2026, a compromised LiteLLM 1.107.0 release was published to PyPI and distributed via official container images, installing a credential stealer and backdoor. LiteLLM is a widely used Python SDK and AI gateway (61,800 GitHub stars, 92 million monthly PyPI downloads). The malicious wheels added three files (cook.pth, cook.py, sitecustomize.py) that execute during Python interpreter startup, so applications did not need to import LiteLLM to trigger the payload. Microsoft found two execution paths: a credential collector via a path extension, and a Unix-oriented loader persisted through site-specific configuration. The collector targeted authentication material across developer tools, AI applications, cloud environments, browsers, and infrastructure, and a separate module attempted to read credential and model-configuration records from the LiteLLM proxy.

The compromise began earlier: Socket recovered malicious GitHub Actions workflows executed in the BerriAI/litellm repository on October 10 and October 12, 2026, eleven days before the poisoned release. Microsoft notes endpoint observations on Windows and macOS matched the recovered collector's behavior, and that a routine Python invocation to install an unrelated dependency activated the collector on Windows. Investigators should not start Python or pip inside a suspect environment to check for the package.

What to watch: environments that installed litellm 1.107.0 or pulled affected container images; persistence via .pth/sitecustomize hooks; credential rotation for cloud, AI provider, and developer secrets; and whether additional malicious versions or maintainers' accounts were compromised.
