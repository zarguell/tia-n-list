On October 21, 2026, LiteLLM version 1.107.0 was published to the Python Package Index and Docker Hub as a trojanized release. The malicious packages shipped a credential stealer and a backdoor while application code stayed unchanged, adding only the cook.pth startup hook so the payload ran on interpreter start without importing LiteLLM. The stealer collected SSH keys, AWS credentials, browser passwords, shell history and AI coding tool configuration, and a database module read credential and model configuration records from the LiteLLM proxy. The backdoor ran as a daemon that executed attacker-controlled code every hour.

The release chain ran through stolen GitHub CLI OAuth tokens from three LiteLLM engineers, later tied to tokens exposed through Claude Code logging in an internal LiteLLM deployment. Attackers disabled branch protections, redirected the releaser to a lookalike repository and ran a compromised workflow, and Socket found malicious workflows inside the project on October 10 and October 12, an eleven day window before the poisoned release. Microsoft described two execution paths, a credential collector launched through a path extension and a Unix loader persisted through site configuration, and warned that starting Python or pip in a suspect environment can itself trigger the payload.

Response work centers on pinning to version 1.106.2 and rotating credentials reachable from affected hosts, including cloud, repository and AI provider secrets. Investigators should treat any host that ran the affected interpreter during the release window as compromised and audit pipeline secrets and Kubernetes access.
