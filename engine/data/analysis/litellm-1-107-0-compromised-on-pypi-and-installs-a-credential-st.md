LiteLLM 1.107.0 on PyPI was compromised to install a credential stealer and backdoor. The malicious package runs its payload on every Python startup on the affected host, not only when LiteLLM is imported, so any Python process on that machine is affected, including IDEs, pip, and CI jobs. It steals SSH keys, AWS credentials, browser passwords, shell history, and AI coding tool configs, and runs as a daemon that executes whatever code the attacker's server returns every hour. Users should pin to 1.106.2.

The incident is a supply chain compromise of a widely used LLM gateway library, which makes the blast radius large for teams running Python tooling in shared environments. Because the payload executes on interpreter startup, cleanup requires checking every Python environment on affected hosts, not just those that imported LiteLLM. Watch for follow-on use of stolen cloud and SSH credentials and new daemon processes reaching out to attacker infrastructure.

Defenders should verify installed versions across developer machines, CI runners, and containers, rotate any credentials present on those hosts, and block the attacker's command-and-control endpoints. Expect additional malicious releases or lookalike packages to follow, so treat PyPI installs for this package with extra scrutiny.
