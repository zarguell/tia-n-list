LiteLLM 1.107.0 on PyPI shipped seven backdoored wheels across Linux, macOS and Windows that install three extra files under litellm-1.107.0.data/purelib/, cook.pth, cook.py and sitecustomize.py, which pip places on sys.path so they execute on every Python interpreter startup without any explicit LiteLLM import. The source distribution on PyPI carried a tampered pyproject.toml but none of the payload files, so reviewers inspecting only the sdist or a Git tag would miss it. The first payload is a credential stealer that StepSecurity calls privcollect, and the second forks a background daemon that checks a GitHub dead drop every hour and runs whatever Python the attacker serves.

The attack came through the project's own publishing pipeline. Three engineers' GitHub accounts appear to have been used via stolen GitHub CLI OAuth tokens, with one account triggering the project-releaser workflow and another approving it, and LiteLLM says all involved tokens have been revoked. The project has not identified how the tokens were taken, has removed all but one unaffected user from its GitHub organization as a temporary mitigation, and has stripped trusted links to that organization from public registries so further malicious releases cannot be published. SafeDep, Socket, StepSecurity and Upwind are credited with the reporting, and the behavior matches the LiteLLM compromise seen in the TeamPCP supply chain attacks earlier this year, where the same path-file execution technique appeared.

The blast radius is broader than a normal package compromise because cook.pth and sitecustomize.py fire on every Python process start on the host, meaning IDEs, pip invocations and CI jobs are all execution points, not just applications that import LiteLLM. Any developer machine or build runner that installed 1.107.0 and subsequently ran Python is potentially compromised regardless of whether the project ever imported the library. The stealer harvests cloud tokens, developer accounts, private keys, AI tooling credential JSON files, Chromium and Firefox browser data and environment variables, and it reads a domain.txt file from the GitHub repository github.com/letters9813, running the same stealer against whatever domain it names before requesting that domain's codepy path. The package was quarantined on PyPI and the malicious Docker images were removed, but the hourly backdoor means a host that installed the wheel can still be told to run new code later.

Defenders should pin to 1.106.2, remove 1.107.0 and any cached wheels, and audit Python site-packages for cook.pth, cook.py and sitecustomize.py artifacts. Rotate SSH keys, cloud credentials, browser-stored passwords and AI tool tokens present on affected hosts, review shell history and CI secret stores for exposure, hunt for the hourly backdoor daemon and outbound connections to the attacker's command server, and inspect Docker images by digest rather than tag. The assessment changes if additional releases from the same hijacked accounts are found, if the command server is found to have served destructive payloads, or if downstream organizations report follow-on breaches from credentials stolen between the upload and the takedown.
