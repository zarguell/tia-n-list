On October 21, 2026, LiteLLM version 1.107.0 was published to PyPI and Docker Hub as a trojanized release in a supply-chain attack. The malicious wheels were live from 11:39 to 13:23 UTC and Docker tags until 14:20 UTC, with roughly 49,000 downloads estimated during the window. LiteLLM reports 92 million monthly PyPI downloads and 61,800 GitHub stars, so even a short exposure window matters. Attackers used stolen GitHub CLI OAuth tokens from three LiteLLM engineers to push the release through the official pipeline, after obtaining them from an internal LiteLLM deployment that was exposed to the public internet; the tokens were likely leaked by Claude Code embedding them in response bodies that were logged to LiteLLM logs. The attackers disabled branch protections, redirected the releaser to a lookalike repository, and ran a compromised workflow. Socket later recovered malicious workflows executed inside BerriAI/litellm on October 10 and October 12, establishing an eleven-day pre-attack window.

The malicious package dropped cook.pth, cook.py, and sitecustomize.py into the Python library directory, and Python startup hooks executed the payload whenever an interpreter started, without any import of LiteLLM. The collector targeted SSH keys, AWS credentials, browser passwords, shell history, and AI coding tool configs, along with cloud, developer, and infrastructure secrets; a separate database module read credential and model-configuration records from the LiteLLM proxy. On Linux and macOS an hourly remote-code loader ran as a daemon. Microsoft analyzed two execution paths, a credential collector via path extension and a Unix loader persisted through site-specific configuration, and noted that starting Python or pip in a suspect environment to check for the package could itself trigger the collector. Application security firms detected the release within six minutes. Private enterprise customers were not impacted.

Remediation centers on pinning to 1.106.2 and rotating all credentials reachable from affected hosts, including cloud keys, repository tokens, and AI provider secrets. Investigators should not execute Python or pip in suspect environments. Audit pipeline secrets and Kubernetes access, and treat any host that ran the affected interpreter during the window as compromised. The same campaign lineage includes an earlier March 2026 TeamPCP incident that used a Trivy token to publish malicious LiteLLM 1.82.7 and 1.82.8, which CloudSEK and Hudson Rock linked to exposure across more than 2,500 organizations and roughly 434,000 CI/CD pipelines.
