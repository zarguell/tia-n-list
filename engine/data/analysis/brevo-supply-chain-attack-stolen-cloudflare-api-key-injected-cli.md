Brevo confirmed that attackers stole a long-lived Cloudflare API key with full account permissions, which had been hardcoded in application source code. The attackers used it to create a malicious Cloudflare Worker that modified content at the CDN edge for approximately five and a half hours on September 14. The exposure window ran from 16:11 to 21:39 UTC. Affected properties included brevo.com, sendinblue.com, login/account/my/onboarding.brevo.com, and sibforms.com.

The Cloudflare Worker injected ClickFix scripts designed to distribute malware. Critically, it also modified Brevo's customer-embedded JavaScript: the Brevo forms script, the Brevo Conversations widget, and the Brevo SDK loader scripts. This means Brevo's own customers' websites were serving malicious content during the exposure window. The Worker stripped Content-Security-Policy headers at the edge, so origin servers and standard integrity checks did not detect the change.

Brevo says the API key may have been compromised as early as late August, though there is no evidence of prior malicious activity. The company removed the Worker and its routes upon detection. The core failure is a hardcoded secret with full API permissions in source code, a pattern that remains alarmingly common in SaaS platforms. The supply-chain blast radius is the real story: any site embedding Brevo JavaScript was distributing ClickFix malware to visitors.
