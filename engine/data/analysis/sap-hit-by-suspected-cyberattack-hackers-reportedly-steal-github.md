SAP has confirmed a cybersecurity incident involving its development infrastructure, after a German publication described an intrusion it dubbed Project Granite. The reports claim attackers obtained employee GitHub credentials, used them to copy and modify source code, and may have leaned on artificial intelligence to do it. SAP's confirmation covers the existence of an incident on development systems; the specifics of what the attackers reached remain disputed.

The gap between the two versions matters. The reporting that first circulated said GitHub access tokens and source code were stolen, but the publicly available portion of that report did not establish what the attackers actually accessed or whether they removed anything, and GBHackers flagged the token and source code claims as unverified. SAP has not published the scope of the affected repositories, the number of credentials involved, or whether customer-facing products or build pipelines were touched.

For anyone who consumes SAP software, the question is whether a compromised development chain could have introduced changes into shipped code, which is a materially different risk from a single stolen repository. Watch for SAP's own incident statement, a timeline for the GitHub token revocation, and any customer notification. Treat the AI framing as a claim from secondary reporting until the German original or SAP substantiates it.
