Todoist says an attacker used a stolen version-control credential between November 22 and 23, 2026 to alter automated workflows in three repositories, obtain an employee sign-in administrative credential and enter its cloud infrastructure. On November 23 the attacker exported email addresses, account creation dates and salted SHA1 password hashes for about 6% of users, retrieved Todoist API and Slack integration tokens for about 0.003%, and searched tasks or connected Outlook mailboxes for credential-like material affecting about 0.001% in each group. A smaller subset used stolen API tokens against Todoist’s `/sync` endpoint to read project, task and comment data. Todoist found no application-code changes and no sign-ins to the SHA1 accounts, but confirmed the data theft; it did not name an actor or assign a CVE.

The 6% figure understates the security problem: salted SHA1 permits offline password guessing, while the much smaller token groups confer direct access to live services and customer content. Turning a productivity app into a credential index can turn a narrow Todoist intrusion into second-order compromise of cloud, email and cryptocurrency accounts. Because the exposed groups overlap only minimally, an account with an unaffected password can still be exposed through a token, connected mailbox or secret stored in a task, so defenders must assess those paths separately.

There is no customer patch or hotfix version to install. Todoist retired SHA1 support, revoked affected API tokens, ended sessions, disabled the Outlook add-in, enforced short token TTLs and restricted remote command execution in its cloud. Customers should follow their incident email, reset any disabled Todoist password to a unique value, change reused passwords, and replace API tokens under Settings → Integrations → Developer; reconnect Slack or Outlook only as instructed, revoke and replace credentials stored in tasks or comments rather than deleting the text, and restrict public file links. For hunting, review version-control audit logs for automated-workflow changes around November 22 at 14:04 UTC, identity logs for administrative credential issuance and employee authentication-setting changes, and cloud audit logs for unexpected administrator accounts, new access keys, production database commands and `/sync` API use.

Watch for Todoist evidence of unauthorized sign-ins to the roughly 6% hash group, downstream misuse of tokens or secrets copied from tasks and Outlook, and any update on how the original version-control credential was stolen. Confirmed downstream use would turn the incident from a SaaS data breach into a broader credential-supply-chain event; an identified employee-device compromise would shift priority toward endpoint and developer-workstation controls.
