N-able confirmed unauthorized access to one server in the environment hosting Mail Assure and SpamExperts Hosted Cloud. The disruption started at 10:00 p.m. ET on 16 November and was first described as a platform configuration and service dependency problem; N-able reclassified it as a security incident at 10:05 p.m. ET on 17 November. The company disabled management UI and API access while inbound and outbound mail delivery and spam filtering kept running. The affected administrative plane spans the Americas, Asia-Pacific and Europe, and N-able says the incident is separate from the earlier N-central incident.

SecurityWeek reported on 20 November that the compromise was isolated to a single web server where an unauthorized party may have accessed credentials stored on the platform. N-able rotated internal platform credentials, revoked customer API tokens, invalidated OAuth tokens and reset local user passwords. It says it found no evidence of customer data compromise, but the portal and API remained disabled while restoration continued. Brotherly Technology recorded that as of 07:56 a.m. ET on 18 November the dashboard, quarantine, logging and mailbox synchronization were still being restored.

The practical risk sits in the management blind spot. MSPs lost quarantine, logging and mailbox synchronization while filtering continued, so delivery problems could go unseen during that window. Watch for revised forensic findings, any change to the no-evidence statement, and the return of dashboard and API access with concrete tenant guidance.
