On October 29, 2026, version 2.1.313 of the official Claude Code VS Code extension (anthropic.claude-code) was published to Open-VSX with a malicious loader embedded in its extension.js bundle, adding 66 lines of JavaScript that run an attacker script before the legitimate code. The payload establishes a persistent SSH backdoor by adding an attacker SSH key and opening a reverse tunnel, giving remote access to developer machines. The build propagated through Open-VSX and Cursor's mirrored marketplace, reaching up to 5,000 Cursor users during a window of roughly 11 hours on October 29. Because the extension auto-updates, affected installs pulled the trojanized build without any user action.

The extension has over 40 million installations, so even a short-lived malicious version exposes a large developer population along with their credentials, source code, and cloud keys. Anthropic replaced 2.1.313 with 2.1.314 roughly 8 hours later and removed the backdoored artifact without public notice, but the replacement does not remove the SSH backdoor or prior reconnaissance from already-infected systems. That gap between silent remediation and actual cleanup leaves compromised hosts reachable. The incident also highlights supply-chain risk in extension marketplaces that mirror each other.

Developers should check for version 2.1.313, remove unauthorized SSH keys, and inspect for reverse tunnels, treating any machine that ran the build as compromised and rotating secrets. Watch for Anthropic or Cursor post-incident guidance and for whether Open-VSX publishing or signing controls change. The skepticism raised about the scope of Step Security's impact numbers is worth monitoring as the affected-user count gets reconciled.
