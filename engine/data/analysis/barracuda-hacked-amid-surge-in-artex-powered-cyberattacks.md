Barracuda linked a November intrusion to ARTEX, an open-source AI pentesting framework now used in real attacks. An attacker used a cloud access key issued to a third-party AI vendor, accessed about 10 Barracuda cloud accounts over 44 hours on November 1 and 2, and was detected on November 4. Barracuda admitted it never retired the key after the vendor's project ended; the key was sitting in a configuration file in the vendor's GitHub repository. The intruder moved through data analytics systems, source-code repositories and Kubernetes clusters, searched for Ethereum keystore files, private keys and seed phrases, and tried to establish persistence. Barracuda says some XDR customers were told to replace integration credentials.

ARTEX was published on GitHub in July 2026 by developer Autumn-27 and uses planner and worker agents with a shared graph of assets and findings. The original repository was removed in October, but forks, ScopeWeaver variants and ARTEX PRO kept circulating. The FBI's FLASH-20261113-001 says multiple actors have abused ARTEX since August and links it to intrusions in finance, government, technology and healthcare. GTIG, Sophos, Unit 42 and Cisco Talos have documented automated Active Directory reconnaissance, Azure storage key harvesting, webshell deployment and exposure of hundreds of internet-facing ARTEX consoles. VAPOR PANDA is reported to have used ARTEX against more than 200 organizations.

The Barracuda case is a straightforward credential-lifecycle failure amplified by automation: a stale vendor key became a machine-speed intrusion during a wider surge in AI-assisted cyberattacks. Watch for more customer notices from companies that issued long-lived keys to AI vendors, additional ARTEX indicators from the FBI advisory, and whether the cryptocurrency searches point to a financially motivated actor or a diversion.
