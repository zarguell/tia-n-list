Barracuda has confirmed a cloud intrusion in which an attacker used a stolen cloud access key and the ARTEX AI penetration testing framework. The company says roughly 10 of its cloud accounts were accessed over a 44-hour period on November 1 and 2, with the intrusion discovered on November 4. The key had been issued to a third-party AI vendor for an earlier project and was never retired when the work ended. Barracuda believes it was stolen from that vendor in October and found it in a configuration file in the vendor's GitHub repository. From one compromised system the attacker moved through the data analytics environment, source code repositories and Kubernetes clusters. Commands targeting private keys, Ethereum keystore files and seed phrases suggest a financial motive, though Barracuda has not ruled out a diversion.

The wider ARTEX activity gives this breach context. The framework was published on GitHub in July 2026 under the name Autumn-27, is written in Go with an embedded Next.js console, and uses planner and worker agents for reconnaissance, exploitation and credential access. Its repository was taken down in October while forks, the ScopeWeaver variant and a commercial ARTEX PRO release continued to circulate. Google and Mandiant reported automated Active Directory reconnaissance, privilege escalation, Azure storage key harvesting and custom webshell deployment from late August. Unit 42 counted 609 internet-facing ARTEX hosts as of October, and Cisco Talos found it deployed alongside VShell, GoPhish and AdaptixC2 through Model Context Protocol extensions.

Attribution and victim reporting have accumulated quickly. Microsoft tied the mid-October ConnectWise Cloud Backup compromise to China-aligned Storm-0940, while CrowdStrike attributed an espionage campaign starting October 17 to VAPOR PANDA against more than 200 organizations. The FBI issued FLASH-20261113-001 on November 13 describing sectors targeted and intrusions reaching privileged access in under three hours. Amazon Threat Intelligence reported ARTEX agent requests captured by its MadPot decoys between October 3 and November 5, including stolen AI model keys fed back into the framework to fund further hunting.

For defenders, the concrete artefacts are the exposed vendor key, the GitHub configuration file that held it, and the behavioral pattern Unit 42 described: bursts of one to 14 requests about a second apart followed by 25 to 31 second pauses. Hunting should focus on first use of cloud keys from new IPs, canary usernames, write-then-delete storage tests, and public OpenAPI specifications or source maps on ARTEX-like services. Long-lived keys handed to contractors remain the entry point to watch.
