ENISA's EUVD database published a cluster of Netty decoder flaws on September 18, 2026, updated September 25: EUVD-2026-82873 in Netty's SmtpResponseDecoder (7.5), EUVD-2026-82870 in RedisArrayAggregator (7.5), and EUVD-2026-82864 in io.netty/netty-codec-memcache (6.5). The story's anchor entry, EUVD-2026-82862, covers a separate Quarkus HTTP security flaw at 7.5 that landed in the same cluster. Netty is the embedded networking layer under a large share of Java server software, so decoder flaws there are remotely reachable wherever those codecs parse untrusted protocol input.

The public records are thin: each entry carries a CVSS score and a one-line description, the feed posts truncate the technical detail, and none of these posts names a CVE id or a fixed version. That gap is the reason to keep this on the radar rather than the severity numbers alone; absence of a CVE mapping makes inventory and patch tracking harder for exactly the libraries most likely to be transitively pinned in application builds.

Watch for CVE assignments, the upstream Netty release notes that fix these decoders, and whether any of them maps to known exploitation. Java-heavy estates should check which Netty versions their dependency trees actually resolve to before the fix versions are announced, since transitive Netty dependencies are routinely invisible to asset inventories.
