Between October 14 and October 26, 2026, a threat actor used IAM credentials belonging to Qubole's AWS account 805246085872 to assume cross-account roles that customers had created for the vendor, then read data out of their environments. Wiz CIRT, working with Sentra and Mandiant, found the actor enumerated resources, pulled secrets from Lambda environment variables, Secrets Manager and SSM Parameter Store, validated the harvested credentials with TruffleHog, and exfiltrated S3 data, in some sessions downloading entire buckets.

The roles were the weak point. Customers create a role trusting the vendor account at onboarding and rarely remove it, so credentials from a dormant integration still worked. Sentra counted more than a dozen organizations compromised in a single campaign and about 100 passwords and keys read in seven minutes with zero write actions, and it traced the activity to a rented OVH server and the Mullvad VPN, with role session names following a quiam- prefix. Wiz also observed a separate October 8-11 campaign that used customer-owned AWS access keys, and it noted that a source-IP condition in the role trust policy would have blocked every role assumption it observed.

This is a third-party access problem, not an AWS compromise. Any SaaS integration that uses a cross-account role is only as safe as the vendor's credential hygiene and the customer's trust policy. Audit roles still trusting vendor accounts that are no longer in use, add source-IP conditions and External IDs, and alert on role assumption from unfamiliar networks. Qubole is owned by Idera, so customers of other Idera properties should assume the same exposure until they have checked those roles.
