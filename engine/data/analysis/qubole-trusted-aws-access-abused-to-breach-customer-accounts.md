Attackers broke into AWS accounts belonging to multiple Qubole customers between October 14 and October 26, 2026, stealing stored secrets and data, according to cloud security firm Wiz. The attacker used credentials for an AWS account that Qubole's platform uses to reach customer environments; Qubole, a data lake platform owned by Idera, operates inside customers' AWS accounts through IAM roles that trust Qubole's account. The compromise did not rely on a disclosed CVE, and how the attacker obtained Qubole's credentials has not been disclosed.

The attacker assumed Qubole roles that were largely unused but still trusted Qubole's account, so the AssumeRole requests succeeded with valid External IDs. It read Lambda environment variables, pulled secrets from Secrets Manager, read SSM Parameter Store values, and ran the recovered credentials through TruffleHog to test them. It then copied data out of S3, sometimes downloading an entire bucket in one session. Wiz's hunting guidance identifies Qubole's account 805246085872 and IAM principal AIDAJYRRH5Y3A7AAJM2HW, with role sessions whose names start with quiam-, as the markers to look for in CloudTrail logs from October 1 onward.

Sentra spotted the activity in several customer environments and alerted Wiz. Separately, from October 8 to October 11, an attacker used customers' own AWS access keys set up for Qubole to compromise a few victims' cloud environments; that activity has not been linked to the AssumeRole abuse. Any organization that has connected Qubole to AWS, even one that no longer uses it, should check CloudTrail for AssumeRole requests from account 805246085872 originating outside AWS, rotate secrets and parameters the role could reach, revoke active sessions, and remove unused Qubole roles or restrict their trust policies. Wiz notes a source IP condition alone would have blocked every role assumption observed.
