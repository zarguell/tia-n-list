GnuPG disclosed CVE-2026-129975, a critical double free in GPGME, on 20 November 2026. The library is what applications use to talk to GnuPG, and the trigger is an OpenPGP key with a crafted, very long user ID. Johan Carlsson found the bug; GitLab notified GnuPG on 12 November, and coordinated disclosure moved forward from 25 November because of a separate Ruby2Shell issue at GitLab.

The GnuPG bug task places the fault in read_status() and read_colon_line() in src/engine-gpg.c. A 1,024-byte status or colon-line buffer is grown with realloc(), but the new pointer is only written back to the engine context at the end of the function. An early return from a callback leaves the context holding freed memory, which is freed again when the engine is released. The advisory says application data can be exfiltrated, for example through signed data, and does not rule out remote code execution.

All software using GPGME before 2.3.0 is affected, including shared libraries, DLLs and static builds. GnuPG shipped 2.3.1 alongside Gpg4win 5.1.2 and updated GnuPG Desktop and VS-Desktop packages; Debian issued DSA-6646-1 with gpgme1.0 1.24.2-3+deb13u1 for trixie. Impact reaches mail and XMPP clients, Samba and Flatpak. Watch for downstream package updates and for untrusted keys with long user IDs reaching tooling that parses them.
