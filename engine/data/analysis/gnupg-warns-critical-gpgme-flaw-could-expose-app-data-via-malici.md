CVE-2026-129975 is a critical double free in GPGME, the library applications use to talk to GnuPG. A crafted OpenPGP key with a very long user ID is the reported trigger. The flaw sits in read_status() and read_colon_line() in src/engine-gpg.c: a local buffer starting at 1,024 bytes is grown with realloc(), but the new pointer is written back to the engine context only on success, so an early return leaves stale memory that is freed again when the engine is released. GnuPG's private task, opened 13 November and made public on 20 November, lists fix commits rM14499348b966 and rMb4358e92e33a and confirms the code was present from 1.18.0 through current master. Johan Carlsson found the bug; GitLab notified GnuPG on 12 November.

GnuPG says every application using GPGME before 2.3.0 is affected, including shared libraries, DLLs and statically linked copies, and issued 2.3.1 as the public fix because 2.3.0 was never released publicly. Gpg4win 5.1.2, GnuPG Desktop and VS-Desktop were updated alongside the library. The advisory says a malicious key can pull data out of an application, for example through signed data, and does not rule out remote code execution. Debian's DSA-6646-1 rates information disclosure, denial of service and possible arbitrary code execution, and fixes stable trixie with gpgme1.0 1.24.2-3+deb13u1. Affected software named in the reports includes mail and XMPP clients, Samba and Flatpak. Coordination moved from 25 November to 20 November because of a separate Ruby2Shell bug at GitLab, shortening the window for downstream builders. No victims or in-the-wild key have been reported.

The immediate task is inventory across processes that call read_status() or read_colon_line(), not just package-level patching: statically linked builds and bundled DLLs will not show up in a package query. Until hosts are on GPGME 2.3.1, gate keys arriving from keyservers or untrusted attachments, and watch allocator or crash telemetry in applications that parse untrusted keys. GnuPG published an attached patch for older versions that cannot move immediately, and says GPGMEPP and GPGMEQT do not need updating.

Watch for downstream advisories naming bundled GPGME versions, for a public trigger key, and for any report that the stale-pointer path is reachable with less than a crafted long user ID. A working exploit key or exploitation report would move this from a broad patching problem to incident response.
