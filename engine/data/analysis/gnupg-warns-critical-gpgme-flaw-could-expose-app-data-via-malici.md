GnuPG has warned about CVE-2026-129975, a critical double free in GPGME, the standard library that applications use to work with GnuPG. The trigger is a malicious OpenPGP key carrying an unusually long user ID. Parsing that key can corrupt memory in the calling application, and the GnuPG project says the flaw could be used to steal data from affected applications. Fixed releases are available.

Every piece of software that uses GPGME before version 2.3.0 is affected. That makes this a library-level problem rather than a flaw in one mail client: the two reports describe GPGME as the component behind most mail clients and other tooling that handles OpenPGP material. The risk sits where an application imports or inspects a key supplied by an attacker, with the oversized user ID driving the memory error. GnuPG rates the issue critical.

Watch for downstream advisories from software that bundles GPGME, and for any vendor reporting exploitation. The concrete remediation is GPGME 2.3.0 or a newer packaged build; until applications pick that up, importing untrusted OpenPGP keys with unusually long user IDs is the exposure path. Neither report describes victims, implants, or in-the-wild use, so this is a broad patching problem for the moment, not a confirmed campaign.
