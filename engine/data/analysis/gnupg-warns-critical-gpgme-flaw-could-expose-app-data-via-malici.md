GnuPG disclosed CVE-2026-129975 on 20 November 2026, a critical double free in GPGME, the library applications use to talk to GnuPG. The trigger is an OpenPGP key with a crafted, very long user ID. Johan Carlsson found the bug, GitLab notified GnuPG on 12 November, and coordinated disclosure moved from 25 November to 20 November because of a separate Ruby2Shell issue at GitLab.

The project's private bug task, public since 20 November, places the fault in read_status() and read_colon_line() in src/engine-gpg.c. A 1,024-byte status or colon-line buffer is grown with realloc(), but the new pointer is written back to the engine context only at the end of the function. Early returns from callbacks leave the context holding freed memory that is freed again when the engine is released. The advisory says application data can be exfiltrated, for example through signed data, and does not rule out remote code execution. Fix commits rM14499348b966 and rMb4358e92e33a are listed in the task; the code was present in 1.18.0 and later distribution releases through master.

All software using GPGME before 2.3.0 is affected, including shared libraries, DLLs and static builds. GnuPG shipped 2.3.1 with Gpg4win 5.1.2 and updated GnuPG Desktop and VS-Desktop packages, and Debian issued DSA-6646-1 with gpgme1.0 1.24.2-3+deb13u1 for stable trixie. Reach includes mail and XMPP clients, Samba and Flatpak. Watch for downstream package updates and for untrusted keys with overlong user IDs reaching any GPGME-backed parser; the covered reporting makes no claim of exploitation.
