CVE-2026-129975 is a double free in GPGME, the library applications use to talk to GnuPG. GnuPG's 20 November advisory and private bug task T8557 tie the trigger to an OpenPGP key with a crafted, very long user ID. The flaw sits in read_status() and read_colon_line() in src/engine-gpg.c: a 1,024-byte status and colon-line buffer is grown with realloc(), but the new pointer is written back to the engine context only at the end of the function, so an early callback return leaves freed memory that is freed again when the engine is released. Johan Carlsson found the bug; GitLab notified GnuPG on 12 November, the private task opened on 13 November, and coordinated disclosure moved from 25 November to 20 November because of a separate Ruby2Shell bug at GitLab.

The advisory says a malicious key can lead to application data exfiltration, for example through signed data, and does not rule out remote code execution. Debian's DSA-6646-1 lists information disclosure, denial of service and possible arbitrary code execution, and fixes stable trixie with gpgme1.0 1.24.2-3+deb13u1. GnuPG released GPGME 2.3.1 as the fix, with commits rM14499348b966 and rMb4358e92e33a, and shipped updated Gpg4win 5.1.2, GnuPG Desktop and VS-Desktop packages.

All software using GPGME before 2.3.0 is affected, including shared libraries, DLLs and statically linked builds. The affected code is recorded in 1.18.0 and later distribution releases through current master, and the impacted integrations include mail and XMPP clients, Samba and Flatpak. Coverage through 22 November was dominated by re-shares of the GnuPG list advisory and the Hacker News writeup. The fresh primary-source reposts add no victim report, exploit code or IOC beyond the advisory, so the operational question remains how quickly downstream distributions and bundled GPGME copies pick up 2.3.1.
