GnuPG rated CVE-2026-129975 critical: a double free in GPGME, the library applications use to talk to GnuPG, triggered by an OpenPGP key carrying a crafted very long user ID. Johan Carlsson found the bug and GitLab notified GnuPG on 12 November. Disclosure was pulled forward from 25 November to 20 November because of a separate Ruby2Shell issue at GitLab. GnuPG says application data can be exfiltrated through signed data and that remote code execution cannot be ruled out.

The private bug task, public from 20 November, places the fault in read_status() and read_colon_line() in src/engine-gpg.c. A local buffer used by the 1,024-byte status and colon-line readers is grown with realloc(), but the new pointer is written back to the engine context only at the end of the function. An early return from a status or colon callback leaves the context holding freed memory, which is freed again when the engine is released. Fix commits rM14499348b966 and rMb4358e92e33a address code present from 1.18.0 through current master.

GPGME 2.3.1 is the fixed release; everything using GPGME before 2.3.0 is affected, including shared libraries, DLLs and statically linked builds. Updated Gpg4win 5.1.2, GnuPG Desktop and VS-Desktop packages shipped alongside the library. Debian issued DSA-6646-1 for trixie with gpgme1.0 1.24.2-3+deb13u1. Mail and XMPP clients, Samba and Flatpak are named among downstream consumers, so the patch trail in those products is what to watch. No event in the file reports exploitation.
