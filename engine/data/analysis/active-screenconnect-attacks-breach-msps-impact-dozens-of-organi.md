ConnectWise is investigating a live malware campaign that abuses compromised ScreenConnect environments to push rogue remote-access clients onto customer devices. Huntress first flagged the activity, with its SOC starting to track it at roughly 17:47 UTC and reporting six compromised managed service providers, more than 286 affected endpoints, and 47 organizations impacted, a tally still climbing at the time of reporting. ConnectWise confirmed it is engaged and working the response with Huntress.

The core technique relies on ScreenConnect's Run Command functionality, which attackers use to deploy unauthorized ScreenConnect clients on managed endpoints. That gives intruders a remote-access channel living outside the legitimate MSP's own ScreenConnect tenant, so the rogue tooling does not appear inside the environment the MSP normally monitors. Huntress also described a second, potentially more damaging path in which an MSP technician's workstation can be compromised when the technician opens a ScreenConnect session against an already-infected customer device. It is not yet clear whether that reverse-pivot abuses legitimate ScreenConnect behavior or exploits a software flaw. No CVE has been tied to the campaign in the reporting so far.

ConnectWise has since moved to contain the abuse at the platform level, disabling five ScreenConnect extensions across roughly 400 environments after the attackers were found to have accessed ScreenConnect partner accounts. That step matters because it shows the intrusion reached the partner account tier rather than only individual tenant instances, which is consistent with the fan-out pattern rather than a single-customer compromise. Sophos is tracking related malicious ScreenConnect deployments, which suggests either a broader actor set or shared infrastructure being reused across campaigns.

ScreenConnect is widely deployed by MSPs and internal IT teams, so an intrusion into a single provider can fan out across many downstream customers, and the reported 47 affected organizations trace back to only six compromised providers. Watch for whether the reverse-pivot turns out to be a vulnerability in ScreenConnect itself, for the final victim tally, and for whether the extension disablement breaks the attackers' access or simply forces them onto unmanaged tooling. MSPs should review Run Command activity for clients deployed outside their own tenant, scrutinize technician workstations that have serviced customer devices, and check partner account access logs.
