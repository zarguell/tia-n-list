ConnectWise and Huntress are tracking an active campaign in which an intruder used access to multiple cloud-hosted ScreenConnect panels to push malicious commands to managed endpoints. Huntress counted at least 288 compromised hosts across 48 organizations and 6 managed service providers, with roughly a third hit in the first 10 minutes and all of them within about 90 minutes on November 11, 2026. The attacker used ScreenConnect's Run Command function to install rogue ScreenConnect clients, giving persistent remote access outside the legitimate MSP environment.

The deployed toolkit, which Huntress calls SCKit, provides persistent backdoor access, intercepts technician session cookies, and self-replicates by waiting for a technician to connect to a compromised endpoint, infecting that technician's workstation, then spreading to other sessions and panels. Affected builds include 26.6.6.9747 and 26.7.6.9783. Huntress traced initial access to RMM+, a third-party ScreenConnect extension that authenticates with a shared access key rather than the platform's MFA; in versions 1.0.31 and 1.0.32 that key defaulted to blank, effectively bypassing authentication. ConnectWise disabled five third-party extensions across roughly 400 partner environments and found no evidence of a compromise of its own infrastructure or of ScreenConnect itself.

The worm-like cross-host step leans on CVE-2026-84869 (CVSS 9.9), a previously patched flaw, to run code on a technician's workstation when they connect to an infected device. Huntress and Blackpoint Cyber say they have not observed successful exploitation of that flaw in these incidents, and Blackpoint confirmed the exploit failed against a patched client, so the CVE is not confirmed weaponized here. Defenders should audit and disable suspicious extensions, review Run Command and remote-command logs for unexplained activity, and treat any Windows Script Host or PowerShell execution in ScreenConnect audit logs as suspicious. Because SCKit can lie dormant until a technician connects, reimaging affected hosts is safer than assuming removal of the extension closes the door.
