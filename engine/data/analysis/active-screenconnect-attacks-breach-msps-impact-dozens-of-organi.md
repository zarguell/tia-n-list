ConnectWise is investigating an active campaign that uses compromised cloud-hosted ScreenConnect instances to deploy rogue remote-access clients to customer devices. Huntress, which first flagged the activity on November 11 around 17:47 UTC, tracked at least 6 compromised MSPs and 288 endpoints across 48 organizations, with all 288 hosts hit within about 90 minutes and roughly a third reached in the first 10 minutes. The attacker used ScreenConnect's Run Command feature to install attacker-controlled ScreenConnect clients on managed endpoints, creating persistent access outside the legitimate MSP environment.

Huntress calls the toolkit SCKit. It provides persistent backdoor access, intercepts technician session cookies, and self-replicates: it waits for a technician to connect to an infected endpoint, then infects that workstation and spreads to other sessions and panels. Initial access traced to RMM+, a third-party ScreenConnect extension that authenticates with a shared access key instead of ScreenConnect user accounts, roles and MFA; in versions 1.0.31 and 1.0.32 that key defaulted to blank. ConnectWise disabled five third-party extensions across roughly 400 partner environments as a precaution and told on-premises customers to disable them manually, while saying it found no evidence of a compromise of ConnectWise infrastructure or a vulnerability in ScreenConnect itself.

The affected builds include the latest releases 26.6.6.9747 and 26.7.6.9783. The worm-like technique is built around CVE-2026-84869, a previously patched ScreenConnect vulnerability that executes code on a technician's workstation when they connect to an infected device, but Huntress and Blackpoint Cyber say they have not observed successful exploitation and Blackpoint confirmed the exploit failed against a patched client. Related activity in August 2026 used a four-stage VBScript chain delivered through a modified ScreenConnect client that re-sent stagers to new Host sessions. MSPs and their customers should audit Run Command history, extension installations and authentication logs, disable or update RMM+, and treat any rogue client or unexpected script execution as grounds to reimage the host.
