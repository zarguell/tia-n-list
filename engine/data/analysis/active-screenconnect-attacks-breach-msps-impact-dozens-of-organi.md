ConnectWise is investigating a live malware campaign that abuses compromised ScreenConnect environments to push rogue remote-access clients onto customer devices. The activity was first flagged by Huntress, whose SOC began tracking it at roughly 17:47 UTC and reported six compromised managed service providers, more than 286 affected endpoints, and 47 organizations impacted, with the victim count still climbing at the time of reporting.

The core technique relies on ScreenConnect's Run Command functionality, which attackers use to deploy unauthorized ScreenConnect clients on managed endpoints. That gives the intruders a remote-access channel that lives outside the legitimate MSP's own ScreenConnect tenant, so the rogue tooling does not appear inside the environment the MSP normally monitors. Huntress also described a second, potentially more damaging path in which an MSP technician's workstation can be compromised when the technician opens a ScreenConnect session against an already-infected customer device. It is not yet clear whether that reverse-pivot abuses legitimate ScreenConnect behavior or exploits a software flaw.

ScreenConnect is widely deployed by MSPs and internal IT teams for remote management and troubleshooting, so an intrusion into a single provider can fan out across many downstream customers. That fan-out is what makes the campaign notable: the reported 47 affected organizations trace back to only six compromised providers. ConnectWise has confirmed it is engaged and working the response with Huntress.

Watch for whether the reverse-pivot turns out to be a vulnerability in ScreenConnect itself, which would raise the urgency for every MSP running cloud-hosted instances, and for the final victim tally, which Huntress expected to keep rising. MSPs should review ScreenConnect Run Command activity for clients deployed outside their own tenant and scrutinize technician workstations that have serviced customer devices.
