Threat actors are weaponizing legitimate ChatGPT shared-conversation URLs as social engineering lures. The attack chain starts with a real chatgpt.com shared page that displays a fabricated "high traffic" notice directing visitors to a backup site at openai-backup.one. That site impersonates OpenAI, Cloudflare, and Google, presenting a fake CAPTCHA verification that copies a PowerShell command to the victim's clipboard. This is a ClickFix technique: the victim is told to "prove they are human" by pasting and running the command.

The PowerShell loader pulls code from brmconfig.com, performs system fingerprinting, then chains into a second stage that delivers NetSupport RAT. An encrypted payload is concealed inside an MP4 file, decrypted at runtime. The campaign does not compromise the ChatGPT domain itself; it exploits the trust users place in chatgpt.com links to bypass skepticism that a standalone phishing URL would trigger.

This is significant because it turns a first-party SaaS platform into a distribution vector. Shared ChatGPT conversations are common in professional settings, so recipients are less likely to question the link. Defenders should monitor for clipboard-based PowerShell execution patterns and investigate connections to brmconfig.com and openai-backup.one. The use of encrypted payloads inside media files also complicates network-level detection.
