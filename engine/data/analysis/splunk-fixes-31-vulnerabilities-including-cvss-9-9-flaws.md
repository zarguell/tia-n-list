Splunk's October 2026 patch bundle fixes 31 vulnerabilities spanning Splunk Enterprise (advisory SVD-2026-1001, published 2026-10-21) and Splunk SOAR (SVD-2026-1011, published 2026-10-21). The three critical CVSS 9.9 entries are CVE-2026-76299 (improper access control in Enterprise REST APIs), CVE-2026-76302 (improper neutralization, CWE-707), and CVE-2026-76531 (CWE-552, files or directories accessible to external parties in SOAR 8.7.0). The event only names these three; the advisory tables show the full mapping, including CVE-2026-76268 (Patroni REST API missing authentication, CVSS 9.8) in Enterprise, which the headline omits entirely.

This is not a routine maintenance release. A CVSS 9.9 improper-access-control bug (CVE-2026-76299) in Enterprise allows non-admin, non-power users to access privileged functionality through REST endpoints, while the SOAR side (CVE-2026-76531) exposes files or directories to unauthorized actors. Given Splunk's role as a centralized log-analysis platform in many enterprise environments, a successful exploitation gives an attacker visibility into security telemetry, search job data, and potentially operating-system commands via the unauthenticated Patroni sidecar (CVE-2026-76268). The 31-bug count is real, but the headline risk concentrates in these three CVSS 9.9 entries plus the 9.8 unauthenticated RCE vector - a denser threat profile than a simple count suggests.

Defenders should upgrade Splunk Enterprise to 10.4.3, 10.2.7, 10.0.10, or 9.4.15 (depending on branch) and Splunk SOAR to 8.7.0. For environments that cannot patch immediately, disable the PostgreSQL sidecar (`disabled = true` in `[postgres]` of `$SPLUNK_HOME/etc/system/local/server.conf`) if Edge Processor, OpAmp, or SPL2 pipelines are not in use, turn off the Splunk Secure Gateway app when Splunk Mobile / Spacebridge / Mission Control are not required, and remove the `run_collect` capability from roles that do not need internal index access. Hunt for anomalous REST API access to `/services/search/jobs/` (related to CVE-2026-76269 and CVE-2026-76275 patterns) and unauthorized `scripted_lookup_raw_write` attempts; check advisory-splunk.com for updated CVE details because the event's 31-count aggregates multiple CWEs with heterogeneous impact.

Watch for two developments: first, whether Splunk updates the advisory to add in-the-wild exploitation indicators for the unauthenticated Patroni API (CVE-2026-76268, CVSS 9.8), which would raise the urgency beyond a standard hardening cycle; second, whether additional CVEs in the 31-bug bundle receive independent CVSS reassessments that shift the headline from a bulk count to a targeted critical-exposure narrative.
