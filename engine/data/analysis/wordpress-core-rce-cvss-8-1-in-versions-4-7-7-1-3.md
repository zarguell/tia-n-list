Attackers are actively targeting an unauthenticated remote code execution vulnerability in WordPress Core, tracked as CVE-2026-119977 with a CVSS score of 8.1. The flaw is a time-of-check time-of-use race condition in the core upgrade process, reported by Picus Security researcher Umut Bayram. During full-package updates WordPress stages installation files in predictable, web-accessible locations, and an attacker who probes those paths during the brief upgrade window can replace files such as wp-config.php and execute code.

The vulnerability affects WordPress versions 4.7 through 7.1.3 and was fixed in WordPress 7.1.4, released October 28, 2026, along with backported security releases for older branches. Wordfence telemetry recorded more than 58,000 blocked attacks within 24 hours and over 240,000 exploit attempts overall, with targeting starting the same day the flaw was disclosed. CISA added CVE-2026-119977 to its Known Exploited Vulnerabilities catalog on November 3, 2026, and ordered federal civilian agencies to remediate by November 6 under Binding Operational Directive 26-04.

Site owners should verify they are running WordPress 7.1.4 or the corresponding security release for their branch. Wordfence free users will not receive the protective firewall rule until November 27, so unpatched sites remain exposed in the meantime.
