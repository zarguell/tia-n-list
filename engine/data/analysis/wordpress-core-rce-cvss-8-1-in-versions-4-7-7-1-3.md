WordPress Core is under active exploitation for an unauthenticated remote code execution flaw tracked as CVE-2026-119977 (CVSS 8.1). The bug is a time-of-check time-of-use race condition in the upgrade process: during full-package Core updates, WordPress temporarily stages installation files in predictable, web-accessible locations, and attackers repeatedly probe staged paths such as setup-config.php while an upgrade is underway. Wordfence telemetry recorded more than 18,500 requests targeting those installer paths in the first 21 hours after disclosure, and blocked attacks reached nearly 59,000 within 24 hours.

The flaw affects WordPress versions 4.7 through 7.1.3, with fixes backported to eligible older branches; WordPress 7.1.4, released October 28, 2026, addresses it along with 21 other security vulnerabilities. CISA added CVE-2026-119977 to its Known Exploited Vulnerabilities catalog on November 3 and ordered U.S. federal civilian agencies to remediate by November 6. WordPress stresses that only the latest release is actively supported.

What to watch: exploitation requires timing against an in-progress upgrade, so the immediate exposure is sites running auto-updates or mid-upgrade on unpatched versions. Administrators should move to 7.1.4 now and confirm backported patches on older branches. Watch for confirmed compromises beyond blocked attempts, since the 58,693 figure reflects blocked requests rather than verified breaches.
