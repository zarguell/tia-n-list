CVE-2026-119977 is an unauthenticated remote code execution flaw in WordPress Core rated CVSS 8.1, caused by a time-of-check time-of-use race condition in the full-package upgrade process. During core updates WordPress stages installation files in predictable, web-accessible locations, and attackers can repeatedly probe those paths to reach installer components in the brief window while an upgrade is running. The vulnerability was reported by Picus Security researcher Umut Bayram and affects WordPress 4.7 through 7.1.3, with fixes backported to every supported branch down to 4.7.39.

Exploitation has moved beyond theory. Wordfence telemetry recorded more than 18,500 requests targeting staged setup-config.php paths in the first 21 hours after disclosure, and a separate count put blocked attempts at 58,693 within 24 hours. CISA added CVE-2026-119977 to the Known Exploited Vulnerabilities catalog on November 3, 2026, with a November 6 remediation deadline for federal civilian agencies. WordPress released 7.1.4 on October 28, 2026, addressing 22 security issues in total; Wordfence shipped a firewall rule the same day for Premium, Care, and Response customers, with Free users receiving it after the standard 30-day delay on November 27, 2026.

Site owners should verify their installation has reached 7.1.4 or the corresponding backported release for their branch and avoid running full-package core upgrades on internet-exposed sites until patched. Because exploitation targets the narrow upgrade window itself, administrators should schedule updates carefully, restrict access to staging paths where possible, and monitor for requests to installer components.
