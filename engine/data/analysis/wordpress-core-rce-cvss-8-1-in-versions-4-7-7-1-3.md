WordPress Core contains an unauthenticated remote code execution flaw in its upgrade process, tracked as CVE-2026-119977 with a CVSS score of 8.1. The vulnerability affects unpatched branches from WordPress 4.7 through 7.1.3. Wordfence researcher Istvan Marton reported that exploitation began on October 28, 2026, and attackers have since launched more than 240,000 exploit attempts. The flaw lies in the core upgrade path, where a full-package upgrade unpacks the installer into a predictable location on the web server, which attackers can use to achieve remote code execution without logging in.

The flaw is under active exploitation and was added to the CISA Known Exploited Vulnerabilities catalog on October 31, 2026. WordPress 7.1.4 addresses the issue, and the Canadian Centre for Cyber Security published advisory AV26-1117 on November 3, 2026. Because the bug is in the update mechanism itself, sites that have not moved to 7.1.4 are exposed each time an upgrade is triggered, and unauthenticated exploitation means no front-door access control slows an attacker down.

Site administrators should update to WordPress 7.1.4 immediately and confirm the running version across all instances. Federal agencies are bound by the CISA KEV entry. Watch for further WordPress security advisories and review access logs around upgrade events for unexpected file writes in the web root. The concrete artifact to track is CVE-2026-119977 with the fixed version 7.1.4.
