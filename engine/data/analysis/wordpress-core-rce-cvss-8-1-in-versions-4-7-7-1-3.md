WordPress Core is under active exploitation for an unauthenticated remote code execution flaw tracked as CVE-2026-119977, CVSS 8.1, affecting versions before 7.1.4. Picus Security researcher Umut Bayram found a time-of-check time-of-use race in the full-package upgrade path: during a core update the installer stages files in predictable web-accessible locations, and an unauthenticated attacker can replace the site's live wp-config.php mid-update. WordPress 7.1.4, released October 28, 2026, fixes this flaw along with 21 other security issues.

CISA confirmed active exploitation and added CVE-2026-119977 to its Known Exploited Vulnerabilities catalog on November 3, ordering federal civilian agencies to remediate by November 6. Attack volume is heavy: Wordfence telemetry cited in reporting shows 58,693 blocked attacks within 24 hours, a count of attempts rather than confirmed compromises. The cruel detail, noted in November 6 coverage, is that installing the fix itself opens the exposure window one last time on sites that update through the affected updater.

Administrators should move to 7.1.4 immediately and confirm backported patches on older branches. Watch for confirmed compromises beyond blocked probes, since the published counts reflect exploit attempts, and expect further reporting on how many sites were caught mid-upgrade.
