WordPress Core is under active exploitation for an unauthenticated remote code execution flaw tracked as CVE-2026-119977, CVSS 8.1, affecting versions 4.7 through 7.1.3. The bug is a time-of-check time-of-use race in the full-package upgrade path: WordPress stages installation files in predictable, web-accessible locations during an upgrade, and attackers probe paths such as setup-config.php while the upgrade is underway. WordPress 7.1.4, released October 28, 2026, fixes it along with 21 other security vulnerabilities.

CISA added CVE-2026-119977 to its Known Exploited Vulnerabilities catalog on November 3 and ordered federal civilian agencies to remediate by November 6. Wordfence telemetry recorded more than 18,500 requests against installer paths in the first 21 hours after disclosure, with blocked attacks near 59,000 within 24 hours, and reporting on November 6 confirms CISA's active-exploitation assessment. Sites running auto-updates are exposed while an upgrade is in progress.

Administrators should move to 7.1.4 now and confirm backported patches on older branches. Watch for confirmed compromises beyond blocked probes, since the request counts reflect attempted exploitation rather than verified breaches.
