A DFIR Report case study details a BumbleBee-to-Akira ransomware intrusion where the threat actor used wbadmin.exe to extract the Active Directory database (ntds.dit) along with SYSTEM and SECURITY registry hives via volume shadow copy backup. The command targeted C:\ProgramData as the backup destination, giving the attacker offline access to crack every domain password hash.

The intrusion began with SEO poisoning of a ManageEngine OpManager search on Bing, leading to a trojanized MSI that dropped BumbleBee via DLL side-loading of consent.exe and msimg32.dll. AdaptixC2 was then injected into a renamed Windows Address Book utility (AdgNsy.exe). The threat actor created backdoor domain accounts (backup_DA, backup_EA) with Enterprise Admin privileges, deployed RustDesk as a service, and used reverse SSH tunneling to proxy RDP through external infrastructure.

After extracting ntds.dit with wbadmin.exe, the attacker also dumped Veeam PostgreSQL credentials via psql and used lsassy to harvest LSASS memory from multiple hosts. Over 75GB of data was exfiltrated via FileZilla SFTP to a Ukrainian server (185.174.100.203) before Akira ransomware was deployed approximately 44 hours after initial access. The wbadmin.exe technique is notable for being a living-off-the-land approach that avoids dropping custom credential dumping tools.
