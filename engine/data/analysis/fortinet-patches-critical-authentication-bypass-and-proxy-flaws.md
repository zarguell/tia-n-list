Fortinet patched a batch of ten vulnerabilities including two critical authentication flaws now drawing attention. CVE-2026-84390, CVSS 9.6, is a static key JWT signing flaw in the FortiMonitorOnSight web portal that lets a remote unauthenticated attacker forge or reuse tokens and bypass GUI authentication. Affected versions are 7.2.0 through 7.2.2 and 7.2.4 through 7.2.7, with the fix in 7.2.8 or above. CVE-2026-84388, CVSS 9.1, is an improper authentication flaw in the Privileged Access Agent Chrome extension that can let a remote attacker proxy a victim browser traffic through attacker servers when the user visits a malicious site. Remediation requires FortiPAM 1.9.1 or 1.8.4 plus extension build 8.0.1.123 or later.

The Chrome extension flaw has the richer public record. Researcher James Arnott of Bay Area Labs found the extension, used by more than a million users, added any requested hostname to its trusted server list via a webRequest listener without checking the initiator, exposed external messaging to all URLs and skipped validation for non JWT tokens, and even allowed the page to click its own consent dialog. He reported it July 17, the fix shipped August 1, and he states there is no known real world exploitation. The batch also includes CVE-2026-39813 and CVE-2026-44277, rounding out a product line wide update.

Neither critical flaw is reported as exploited in the wild in the events read. Priority goes to internet facing FortiMonitorOnSight portals below 7.2.8 and to pushing the extension update through managed browser channels, since users cannot be relied on to update extensions manually. Teams should confirm FortiPAM server and extension versions together, because updating only one side leaves the proxy abuse path open.
