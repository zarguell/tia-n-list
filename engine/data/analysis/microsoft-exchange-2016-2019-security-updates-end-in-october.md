Microsoft has confirmed it will not extend the Extended Security Update program for Exchange Server 2016 and 2019 beyond October 2026, so these versions get their final security fixes that month and none after. Exchange 2016 ended mainstream support in October 2020 and Exchange 2019 on January 9, 2024, with the lifecycle record putting 2019's extended end at October 14, 2025, which makes the ESU window the only remaining source of patches. The pressure inside that window is concrete: CVE-2026-33824, a CWE-415 double free in Windows Internet Key Exchange Service Extensions rated Critical at CVSS 9.8 for unauthenticated remote code execution, was patched April 14, 2026 (KB5082198 on Windows Server 2016, KB5082123 on Server 2019) and landed in CISA's KEV catalog on August 19, 2026 as actively exploited. Exchange itself carries CVE-2026-62911, an elevation of privilege through capture-replay authentication bypass (CWE-294, tracked by ZDI as ZDI-26-538), published August 11, 2026 at CVSS 8.0 and demonstrated by Orange Tsai of DEVCORE at Pwn2Own Berlin 2026 on May 15, where three chained bugs reached code execution as SYSTEM for a $200,000 award.

The deadline matters because of what it does to the bugs, not to the calendar. Microsoft's FAQ for CVE-2026-62911 states that an attacker who exploits it can take over the mailboxes of all Exchange users, send and read mail, and download attachments, and ZDI notes the flaw chains with other vulnerabilities into SYSTEM code execution, the same end state the IKE double free reaches inside the OS on the same host. An un-migrated Exchange 2016/2019 server therefore runs two SYSTEM-class bugs on one box, one in the mail store and one in the network stack beneath it. The cadence already visible, an April advisory becoming an August KEV entry and a September 1 public PoC claiming a pre-auth chain through the Mailbox Replication Service Proxy, shows how fast a bug matures from patch bulletin to weapon, and after October every new Exchange 2016/2019 bug stays at the advisory stage permanently on servers that remain. That standing exposure, on top of a published and priced research path to SYSTEM on Exchange from a team that also took an Edge sandbox escape and a SharePoint chain at the same event, is what separates this from routine Patch Tuesday volume.

Inventory every on-prem Exchange 2016/2019 server now and plan migration to Exchange Online or Exchange Server Subscription Edition against the October deadline, treating the October release as the last fix that will ever arrive. Verify the August 11, 2026 Exchange security updates are applied and the underlying Windows hosts run KB5082198 or KB5082123 or a later rollup; until that is confirmed, apply Microsoft's mitigation for CVE-2026-33824 and block inbound UDP 500 and 4500 where IKE is unused, or restrict those ports to known peer addresses. Hunt the IKE attack using ZDI's signatures: an IKE_SA_INIT on UDP 500 or 4500 carrying the Microsoft Security Realm Vendor ID byte sequence 68 6a 8c bd fe 63 4b 40 51 46 fb 2b af 33 e9 e8, followed by a fragmented IKE_AUTH with an Encrypted Fragment payload (SKF, type 0x35), noting the four-byte non-ESP marker shifts offsets on port 4500, and treat IKEEXT service crashes as suspicious. On Exchange, the circulating PoC's chain targets MRSProxy with an authentication coercion step, so review front-end IIS logs for anomalous MRSProxy activity and session-replay patterns on servers still pending the August update.

Two developments would move this assessment. Independent validation of the CVE-2026-62911 PoC as a working pre-auth chain, or a KEV listing for the bug (MSRC marked Exploited: No on August 11), would turn a chained elevation of privilege into unauthenticated remote code execution across every unpatched server. ZDI's disclosure timeline records the vulnerability reported to the vendor on May 21, 2026, and when DEVCORE publishes its technical writeup the two companion bugs in the chain become public in detail, the same pattern that preceded the current PoC. The other thing to watch is October itself: whether the final Exchange 2016/2019 update ships on schedule, and which post-EoS bug appears first with no fix ever coming.
