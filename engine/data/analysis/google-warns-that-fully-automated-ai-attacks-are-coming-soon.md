Google Threat Intelligence Group's November 17 AI Threat Tracker reports the first case it has seen of a multi-agent framework running vulnerability discovery and exploitation with no human in the loop. The exposed staging server held a system called exploit_agent in its configuration, which compared web application code before and after patch announcements, inferred the likely flaw, drafted an exploit and executed it. The same server held victim data and scripts for internal reconnaissance, password guessing, webshell installation and removal of other attackers' webshells. Russian-language comments in the configuration pointed to auto-exploitation API keys, and victim data indicated French media, entertainment and education sites.

The wider report covers ARTEX, CAIRN, CyberStrikeAI, PentAGI and HexStrike AI used for multi-stage intrusions. CAIRN appeared in an attack on the US aerospace sector, and CrowdStrike saw open directories with Claude Code session histories and ARTEX configuration files in a campaign against South Korean financial organizations from late September to early October. The FBI's November 13 FLASH says ARTEX has been weaponized since at least August, with intrusions reaching privileged access in under three hours, personal data theft affecting about 67,000 people in South Korea, and access to more than 2,250 downstream ConnectWise Cloud Backup tenants. Listed indicators include 38.244.50[.]120, 199.19.95[.]66 through 199.19.95[.]68 and xcai[.]pro.

Google expects attacks needing little human interaction within three months and sophisticated fully autonomous attacks within six. That forecast is a judgment, but the observed artifacts are concrete: patch-diff pipelines, exposed agent consoles, stolen session histories and fast intrusion timelines. Watch for new forks after the original ARTEX repository was removed, further exposed consoles, and compressed bursts of iterative activity in endpoint and cloud logs that look unlike human-paced attack chains. The line between a research framework and an operational tool is thin here, since the same open-source projects appear in both defensive write-ups and confirmed intrusions.
