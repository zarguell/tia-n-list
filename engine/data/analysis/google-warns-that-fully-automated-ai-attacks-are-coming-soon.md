Google Threat Intelligence Group reports that threat actors have moved from using AI as a helper to running multi-agent offensive frameworks. The most concrete finding is exploit_agent, found on an exposed staging server. It compares web application code before and after a vendor patch, infers the vulnerability from the diff, drafts an exploit and executes it without a human at each step. The same server held exfiltrated victim data and scripts for internal reconnaissance, password guessing, webshell installation and removal of rival attackers' webshells. GTIG links the activity to Russian-speaking operators based on Russian-language code comments and an API key configuration for auto-exploitation, without naming a group or state. Victim data pointed to French media, entertainment and education sites.

The wider report names ARTEX, CAIRN, CyberStrikeAI, PentAGI and HexStrike AI as frameworks used by criminal and state-sponsored actors. CAIRN was used against a U.S. aerospace organization; suspected North Korean actors used Claude Code to deliver malware. The FBI's November 13 FLASH says ARTEX has been weaponized since at least August 2026, with intrusions reaching privileged access in under three hours, personal data theft affecting about 67,000 people in South Korea, and access to more than 2,250 downstream ConnectWise Cloud Backup tenants. BleepingComputer reported more than 1,600 exposed ARTEX consoles by early November. Listed indicators include 38.244.50[.]120, WISP nodes 199.19.95[.]66 through .68 and the reseller domain xcai[.]pro.

GTIG expects low-complexity attacks with little human interaction within three months and sophisticated fully autonomous agentic attacks within six months. That forecast is not evidence that such attacks already dominate, but the staged pipeline and the ARTEX victim counts show the scaling risk. Watch for compressed bursts of iterative activity, rapid patch-to-exploit turnaround on internet-facing applications, Entra credential additions and access to Kudu or cloud administration endpoints. The machine-speed window also puts a premium on reducing the time between patch release and remediation.
