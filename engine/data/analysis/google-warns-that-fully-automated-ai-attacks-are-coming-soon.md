Google Threat Intelligence Group's November 17 AI Threat Tracker says adversarial use of AI has crossed a threshold from prompting to autonomous multi-agent offensive frameworks. The clearest case is exploit_agent, found on an exposed staging server. GTIG says it compared code before and after patch announcements, identified the likely vulnerability, drafted an exploit and executed it without a human in the loop. The same server held victim data and scripts for reconnaissance, brute-forcing, webshell installation and removal of other attackers' webshells. Victim telemetry pointed to French media, entertainment and education sites.

The Record and SecurityWeek reported the same tracker on 17 November, naming ARTEX, CAIRN, CyberStrikeAI and PentAGI as frameworks used for multi-stage intrusions at higher operational velocity. Google attributes that operation to Russian-speaking operators based on Russian-language comments and configuration text, but did not name a group or state. The report also describes CAIRn use against a US aerospace target, and separately notes suspected North Korean use of Claude Code to deliver malware. GTIG names ARTEX, CAIRn, CyberStrikeAI and PentAGI as frameworks now used for multi-stage intrusions. It predicts that within three months, less sophisticated actors will be able to run attacks with little human interaction.

Other events in this cluster show how those frameworks are already supported by exposed infrastructure. CrowdStrike found open directories with Claude Code session histories and ARTEX configuration files from a campaign against South Korean financial organizations, including ARTEX host 38.244.50[.]120 and API reseller xcai[.]pro. BleepingComputer reported more than 1,600 exposed ARTEX consoles by early November. The FBI FLASH adds victims in South Korea, roughly 67,000 people affected, and access to more than 2,250 downstream ConnectWise Cloud Backup tenants.

The near-term watch items are whether the three-month prediction materializes in wider low-skill use, whether exploit_agent or similar frameworks appear in more incident response cases, and whether exposed console counts keep growing. Defensive attention should focus on the operational traces these tools leave: staged configuration files, rapid patch-diff to exploit cycles, compressed bursts of iterative activity and cloud administration endpoints.
