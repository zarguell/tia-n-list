Bitdefender found a denial-of-service flaw in Android, dubbed GhostMap, that a permissionless app can trigger without being launched. A malformed APK exploits a mismatch between two Android libraries that interpret ZIP compression methods differently, letting the file be mapped beyond its actual contents into unallocated memory; any process that reads the entry receives a SIGBUS and crashes, and a crafted app can loop the device into a persistent reboot. Bitdefender discovered it while analyzing an Android banking trojan that kept crashing emulators when reading an application resource, then built a proof-of-concept app with no executable code and no requested permissions.

The practical risk is availability rather than data theft: a malicious app distributed through any channel can brick a phone repeatedly with no user interaction beyond installation. Google has known about the issue since August but closed it as not reproducible and has not shipped a patch, so affected devices remain exposed and there is no vendor fix to deploy.

Watch for malformed APKs and apps that request no permissions yet crash system services on install, and monitor Google for a future Android security bulletin addressing GhostMap. Until a patch exists, restricting sideloading and vetting app sources is the main mitigation, and Bitdefender's report provides the technical detail needed to build detections for the ZIP parsing mismatch.
