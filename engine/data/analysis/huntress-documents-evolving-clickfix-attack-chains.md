Huntress published a study of how ClickFix tradecraft has moved past its original shape. The base technique is unchanged: a page tells the victim that something is broken, usually a CAPTCHA or a meeting-client error, and instructs them to paste a command into a Windows Run box or a PowerShell window. What Huntress newly documents is four follow-on chains built on top of that first paste: lateral movement inside the victim's network, payloads concealed in PNG files, Node.js based remote access trojans, and further stages layered on the same social-engineering entry point. The firm's own summary of the report names exactly those four chains.

The reason this matters is that ClickFix needs no software vulnerability, so patch management and endpoint exploit protection do nothing against it. Every additional chain increases the value of a single successful paste: an initial foothold that once ended in an infostealer now reaches host-to-host movement and a cross-platform RAT that runs wherever Node.js is installed, including developer machines that carry source code and cloud credentials. Hiding a payload in a PNG also defeats naive file-type and download inspection, because the image is a legitimate asset the page already loads.

Defenders should assume the clipboard is an attack surface. Block and alert on Run dialog and PowerShell invocations spawned from a browser process, treat any user-initiated paste of a script as a reportable event, and restrict outbound Node.js and script-host execution on workstations where it has no business role. Huntress has not published indicators of compromise for these chains in the material available here, so hunting has to lean on process lineage and on user reporting rather than on hash or domain matching.
