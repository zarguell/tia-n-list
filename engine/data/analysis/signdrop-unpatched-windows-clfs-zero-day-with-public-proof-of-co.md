SignDrop is an unpatched Windows CLFS local privilege escalation published on November 10, 2026 under the MSNightmare handle on GitHub, with no CVE, no coordinated disclosure and no patch. It turns Microsoft's own CLFS authentication mitigation into an attack surface: the exploit forces clfs.sys to create a .cnpf signature file as SYSTEM in an attacker-controlled location, producing a privileged file-creation primitive at an attacker-selected path. Because the resulting file keeps attacker-accessible security attributes, the exploit reopens it and replaces the CLFS-generated content with an embedded payload DLL, and Microsoft Defender's signature update RPC interface is used to trigger the CLFS log open under SYSTEM context, making Defender the bait handler.

The flaw matters because it promotes a standard user to NT AUTHORITY\SYSTEM on a component Microsoft hardened specifically to block the class of logic bugs caused by improper validation of CLFS data structures, bugs that accounted for 19 of 24 CLFS CVEs over five years. SignDrop abuses the signing mechanism itself rather than the data structures it was meant to protect, and a public proof-of-concept is already available, which lowers the barrier for reuse.

With no patch available, defenders should watch for .cnpf signature files created in attacker-controlled paths, abuse of Defender's signature update RPC, and unusual SYSTEM-context file creation on endpoints. Expect Microsoft to address this in an out-of-band or Patch Tuesday update, and treat any CLFS-related activity from unprivileged processes as suspicious until then.
