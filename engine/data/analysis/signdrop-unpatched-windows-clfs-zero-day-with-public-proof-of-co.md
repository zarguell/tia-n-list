SignDrop is an unpatched Windows CLFS local privilege escalation published on November 10, 2026 by the researcher known as MSNightmare, also called Nightmare Eclipse or Abdelhamid Naceri, who released proof-of-concept source code on GitHub under the handle MSNightmare. It elevates a standard user to NT AUTHORITY\SYSTEM by abusing the CLFS logfile authentication mitigation Microsoft added in late October 2025: when a user prepares a log and coerces a privileged process to open it, clfs.sys creates the missing .cnpf HMAC signature file under that privileged context, and the file retains the original DACL, giving the attacker a SYSTEM file-creation primitive at a chosen path. The exploit then reopens that .cnpf file and overwrites the CLFS-generated content with an embedded payload DLL, and it triggers the privileged CLFS log open by calling Microsoft Defender's signature update RPC interface, ServerMpUpdateEngineSignature, so Defender acts as both bait and accomplice. There is no CVE, no advisory, and no patch; the code was released without coordinated disclosure.

The exposure is broad because the mitigation it abuses ships in Windows 11 25H2 and later and Windows Server 2025, and the repository estimates roughly 80 percent of Windows installations are vulnerable depending on CLFS authentication mode, with registry values 0 or 1 affected and 2 or 3 not. Since the bug requires only local code execution as a standard user, any phishing payload, malicious insider, or compromised low-privilege account can become SYSTEM on a fully patched modern host, and the public proof of concept removes the research barrier. It is also a trust problem, not just a bug: the component Microsoft hardened to close a class of logic errors that accounted for 19 of 24 CLFS CVEs over five years is now the primitive, and the exploit rides on Defender's own privileged update path, so defenses that assume the hardened driver or the AV engine are trustworthy no longer hold. As of the available reporting, Cyderes compiled and tested the proof of concept and found no evidence of in-the-wild exploitation, but the absence of a CVE and patch means every exposed host stays exposed until Microsoft ships a fix.

With no patch available, treat any CLFS activity from unprivileged processes as suspicious and hunt for the artifacts the proof of concept leaves behind: .cnpf signature files created in attacker-controlled paths, SYSTEM-context shells or payloads launched shortly after Defender signature updates, and failed or anomalous Defender update events. Verify exposure by reading HKLM\SYSTEM\CurrentControlSet\Services\CLFS\Authentication\Mode, where 0 or 1 indicates an affected configuration and 2 or 3 does not. ThreatDefence published KQL hunts for unusual .cnpf files, SYSTEM shells, and Defender update failures, and notes Microsoft's next scheduled security updates land on December 8, 2026, so an out-of-band release before then is possible but not guaranteed. Reduce blast radius by limiting local code execution and standard-user write access on endpoints, and keep Defender and endpoint telemetry intact because the exploit depends on them.

Watch for Microsoft to assign a CVE and ship a patch or mitigation, for the first confirmed in-the-wild use of SignDrop against the Defender update path, and for the researcher's claim that the technique can disable other antivirus and EDR products to be validated or refuted. Any of those developments would move this from a theoretical, PoC-only risk to an active intrusion primitive, and would also indicate whether the CLFS authentication feature can be safely retained or must be disabled.
