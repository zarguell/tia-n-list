Google shipped Chrome 153 across desktop, Android, and iOS, formally moving the browser from a four-week release cycle to a two-week cadence. The change was previewed in March 2026 and arrives on schedule. Chrome's release rhythm has been accelerating for years: six-week cycles from 2010, four-week from 2021, and now two-week. The next release, Chrome 154, is already in beta and due September 22.

The security rationale is straightforward. Shorter cycles mean the window between a fix appearing in Chrome's source code and that patch reaching users shrinks. Google explicitly noted this matters as automated vulnerability discovery tools and community reports generate more fixes to ship. Smaller releases also make regression detection easier since each drop contains fewer changes, letting developers isolate breakage faster.

Enterprise users who cannot keep pace with biweekly updates can stay on Extended Stable, which delivers feature releases every eight weeks while maintaining weekly security patches. Google still recommends the two-week Stable channel as the more secure option for most organizations. This is a process change with real security implications: faster patch delivery is one of the few things that uniformly reduces attacker opportunity.
