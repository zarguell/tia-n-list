The mechanism is a mass exposure of valid secrets in public GitHub repositories, not a platform breach. Truffle Security scanned 224 million repositories and 58 billion files (crawl closed August 7, 2025) and identified 543,699 unique working credentials spread across more than 1.1 million files and repositories, including forks. The median time a single credential stayed publicly accessible was 784 days, about 10% were older than 6.3 years, and the oldest dated to 2009. Secret density climbed from 3.72 per million files in 2015 to a 2025 peak of 11.62. GitHub's Push Protection, introduced for Advanced Security in April 2022 and extended to public repos in May 2023, has not eliminated the problem; the scan found more than double the working credentials on GitHub (543,699) compared with Hugging Face (221,303) in August.

This is not abstract statistics. Every one of those 543,699 credentials is a live key that an attacker can copy directly from source code and reuse against production APIs, cloud consoles, or internal systems. The median 784-day exposure window means most victims have no idea their keys have been public for over two years, which eliminates any assumption that rotation was prompt. With copies in forks, deletion from the original repository does not remove access. The comparison to Hugging Face confirms the problem is systemic across public code hosts, not isolated to GitHub, which makes repository-level fixes alone insufficient.

Defenders should rotate any exposed keys immediately, not rely on Push Protection alone. The concrete telemetry to hunt is the secret patterns Truffle found: working credentials embedded in files across forks, with a density peak of 11.62 per million files in 2025. Check repositories cloned from public sources for embedded tokens matching the 2009-2025 age range, audit forks separately because copies persist there, and enforce Push Protection on all public repositories since it became available in May 2023. Monitor for reuse of old keys in authentication logs; a 784-day exposure implies attackers could have used them long before detection.

What would change the assessment: confirmation that Truffle's dataset missed active enterprise repositories or that GitHub's next update to Push Protection materially lowers the 11.62 per million files rate. Also, evidence of active exploitation using these exact 543,699 credentials in the wild rather than passive scanning.
