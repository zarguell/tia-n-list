Over 300 Tor exit relays were compromised in early October and repurposed as SSH man-in-the-middle nodes, redirecting password logins to attacker-controlled servers. The mechanism is not a product vulnerability with a CVE but infrastructure takeover: the relay operator (Zimmer, who ran the largest hijacked group) confirmed that copies of offline master keys were not actually offline, which allowed the attacker to redirect traffic. Events reference thehackernews.com reporting from 21 October 2026 that disclosed the scale, the Mastodon updates that added the key-management failure, and the cyberworldops.eu follow-up on 23 October linking the exposure to Heartbreaker ransomware context.

This is not a routine relay outage. Any user who accepted changed SSH host keys while routing through these relays during the window had credentials captured by the attacker, meaning the exposure is active and credential rotation is urgent, not preventive. The story carries a score of 5.4 with two independent sources, which places it above generic network news but below critical CVE-level alerts; the reason it matters is that SSH MITM through anonymizing infrastructure undermines both privacy and authentication in the same operation. Most coverage of Tor this week focuses on browser updates or policy debates, so a sustained, multi-day MITM campaign against exit nodes with confirmed master-key compromise is the outlier.

Defenders should rotate SSH keys and passwords for any session that traversed Tor exit relays between early October and 21 October, audit relay nodes for unexpected key configurations, and review SSH logs for host-key-change warnings paired with Tor exit IP ranges. The events specifically mention Zimmer's post-mortem on key management, so relay operators should treat master-key storage as a high-value target and enforce offline isolation with physical verification, not just policy labels.

Watch for a confirmed victim count from relay operators or a vendor advisory from the Tor Project that maps affected exit nodes by fingerprint, which would turn this from an exposure risk into a confirmed breach with targeted rotation lists. Another development that would change the assessment is evidence linking the captured SSH credentials to a specific ransomware deployment, such as the Heartbreaker family referenced in the 23 October follow-up.
