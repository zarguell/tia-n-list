The LiteLLM supply chain attack, first reported by Hudson Rock, has expanded into a multi-stage campaign affecting six high-profile organizations. TeamPCP orchestrated the breach in March 2026 by compromising the Trivy vulnerability scanner through an unrevoked automation token. Although the token was rotated, it remained functionally active for a 20-day window, allowing the adversary to force-push malicious code to Trivy's published version tags.

The attack exploited a critical flaw in LiteLLM's build system: unpinned apt installs for Trivy meant the compromised scanner flowed automatically into the production pipeline. During a 40-minute window in March 2026, the infected build process published malicious versions 1.82.7 and 1.82.8 to PyPI. The compromise propagated further to the Telnyx Python SDK and Checkmarx KICS, creating a cascading supply chain infection across the AI dependency graph.

Hudson Rock's analysis emphasizes the breaches were extremely difficult to avoid and exploited deep, trusted dependencies within standard DevOps pipelines, bypassing traditional security perimeters. The exfiltrated data has begun circulating among opportunistic cybercriminals. Organizations using LiteLLM, Trivy, or related dependencies should verify their build integrity and rotate any potentially exposed credentials.
