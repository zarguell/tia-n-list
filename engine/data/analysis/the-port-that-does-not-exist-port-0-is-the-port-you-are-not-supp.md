Researcher acid.vegas placed an IRC network on TCP port 0, a port that is not supposed to be used, then scanned all of IPv4 and found other listeners there. The findings were posted to r/cybersecurity by /u/acidvegas and linked from acid.vegas/blog/the-port-that-does-not-exist/. A Killbait write-up of the research highlights the most sensitive finding: corporate phone systems, specifically Avaya IP Office, are exposing detailed call logs through port 0.

The exposed data is SMDR (Station Message Detail Recording) output, including call start times, connected durations, caller and callee numbers, extension names, and internal addresses, streamed as comma-separated text without authentication. Killbait reports 21 hosts across ISPs in the UK, US, and South Africa were found streaming this data. The exposure stems from port-forwarding rules that leave the external port at 0; because port 0 is a valid socket number, anyone who connects can read the call logs, even though tools like netcat and telnet refuse to connect to it.

It matters because port 0 is widely assumed to be unused, so firewalls and monitoring often ignore it, and the call logs are a ready source for social engineering. Watch for whether the exposed Avaya systems are remediated, whether attackers begin using port 0 for covert traffic, and whether defenders start logging or blocking the port.
