Unsloth Studio, delivered through the standard unsloth Python package, had a critical arbitrary code execution vulnerability fixed in version 2026.6.9. The flaw was discovered by Pillar Security. A malicious Hugging Face repository could include a malicious auto_map entry in its config.json that pointed Transformers components such as AutoConfig to attacker-controlled Python files stored in the same repository. When the Studio backend inspected the model with trust_remote_code=True, the library downloaded and imported the supplied module, turning a routine metadata check into remote code execution. The vulnerability did not require loading model weights or starting inference; merely selecting the repository triggered execution.

The exposure is significant because Studio is included in pip install unsloth even though it is labeled beta, placing a vulnerable web interface inside AI development and fine-tuning environments that may process sensitive data. The exploitation path is straightforward and does not depend on a user taking unusual actions beyond selecting a model, which makes it a practical supply-chain threat in AI workflows where developers routinely pull public repositories.

Users should upgrade Unsloth to 2026.6.9 or later immediately. Defenders should audit environments for Studio installations, review which Hugging Face repositories have been loaded recently, and inspect for unexpected Python processes or files in directories associated with Studio. Watch for follow-up reports confirming whether this vulnerability has been exploited in active campaigns, and whether similar auto_map abuse patterns appear in other model-hosting interfaces.
