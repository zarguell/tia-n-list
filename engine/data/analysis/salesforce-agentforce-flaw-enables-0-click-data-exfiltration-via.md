SalesBleed is Zenity Labs' three-flaw chain against Salesforce Agentforce, refreshed in late September with a post walking through why the URL redaction failed. A hidden prompt injection in a lead submitted through the public Web-to-Lead endpoint stays dormant until an employee asks Agentforce to review the newest lead. The instruction then steers the General CRM subagent's Query Records tool from Leads into Accounts, and data leaves through an HTML img src tag whose hostname encodes the values into DNS queries to the attacker's authoritative nameserver. The Trusted URLs redaction layer missed the leak because its TLD allowlist omitted .fun, termination characters like curly and square braces were parsed differently by the redactor and the chat renderer, and redaction ran after the agent generated its output. A DNS label caps at 63 characters, so exfiltration ran as continuous bleeding queries that survive HTTP egress controls.

The third flaw lived in the Agentforce-Slack integration and enabled identity impersonation for phishing with no attacker account to trace. For agents published to Slack, link-preview unfurling automatically crawls any raw URL the hijacked agent prints, giving a second no-click exfiltration path that needs no image tag at all. Zenity reported the chain June 1, 2026, confirmed fixes August 19, and Salesforce said it found no evidence of exploitation in the wild.

The lesson generalizes past Salesforce. A redactor only works if it agrees with the renderer on where a URL ends, and allowing-list gaps of a single TLD undo the control entirely. Teams running Agentforce should confirm the August fixes are applied, and anyone modeling agent egress should treat DNS as a live channel and assume any URL the model can print will be fetched by something.
