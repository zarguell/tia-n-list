SonicWall advisory SNWLID-2026-0014 covers seven SonicOS vulnerabilities, the one CISA tracked into KEV being CVE-2026-19868, an authentication enforcement flaw in the SonicOS SSL-VPN service. It affects Gen7 builds 7.3.3-7015 and older and Gen8 builds 8.2.2-8015 and older, only where SAML is enabled for SSL-VPN logins. A user holding valid credentials for a secondary authentication method such as a local, LDAP, or RADIUS account can bypass SAML single sign-on and the MFA enforced through it, so a VPN login that should have passed through Okta or Microsoft Entra ID can succeed on a password alone. SonicWall PSIRT investigated a report of potential exploitation, CISA added the CVE to KEV on 6 November 2026, and SonicWall credits researcher Ryan Harris of Electronic Office with the discovery. The flaw is CWE-308 with CVSS 7.1 per SonicWall and 7.5 per CISA's enrichment, and the same release also fixes management-interface flaws CVE-2026-107154 and CVE-2026-107155 plus pre-authentication buffer overflows.

The exposure is not an unauthenticated internet-wide bypass: the attacker needs a working credential first. But stolen VPN passwords are plentiful, and SAML-enforced MFA is the control many shops rely on to make them useless, so removing that layer on an internet-facing SSL-VPN portal on port 4433 or whatever custom port is in use turns a leaked password into an internal session. The blast radius is the set of SonicWall Gen7 and Gen8 firewalls running vulnerable builds with SSL-VPN and SAML both enabled, which in practice includes many MSP and enterprise remote-access deployments. This story earns attention over the routine CVE noise because it is actively exploited, it defeats the MFA layer rather than a single password, and CISA set a 20 November 2026 remediation deadline for federal civilian agencies. The six companion flaws in the same release, including the CVE-2026-82308 pre-authentication heap overflow in SSL-VPN, mean patching is not optional hygiene but the only fix.

There is no workaround, so the fix is the upgrade: SonicOS 7.3.4-7013 or later on Gen7 and 8.2.3-8015 or later on Gen8. Before and after patching, rotate passwords for every non-SAML account the firewall accepts, remove unused local accounts and SSL-VPN access from groups that should only use SAML, and restrict the management interface to trusted networks because the same release fixes the management-interface flaws. For hunting, SonicWall logs a successful SSL-VPN login as event ID 1080 and a logout as event ID 263, so enable both under Device then Log then Settings, forward them via syslog, and correlate 1080 events against identity-provider sign-ins, flagging SSL-VPN sessions with no matching IdP login within ten minutes. Run that correlation as far back as logs go, since neither SonicWall nor CISA has said when exploitation began, and end any SSL-VPN session after the upgrade that cannot be tied to a known user and device.

Watch for SonicWall or CISA to publish indicators of compromise or exploitation detail, which would turn the current result-based hunt into a signature-based one and likely reveal when attacks started. Also watch whether exploitation broadens beyond the reported potential exploitation into confirmed ransomware or intrusion campaigns, and whether CISA extends or enforces the 20 November 2026 deadline, either of which would raise the urgency for organizations still on vulnerable builds.
