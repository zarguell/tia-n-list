Adobe Commerce and Magento Open Source are under active exploitation via a zero-day dubbed StyleSmuggler. Sansec's forensics team traced first exploitation to September 4, targeting a store running the latest security patches on Magento 2.4.6-p15. The flaw is unauthenticated RCE: attackers inject PHP code into Magento's template system through styles properties, then trigger execution via the failed-payment email workflow. The recipient never needs to open the email because rendering happens server-side during template compilation. Sansec reproduced the full attack chain on clean installs of Magento 2.4.7, 2.4.8, and 2.4.9. All supported versions are affected.

The post-exploitation payload is a compact Rust-based backdoor installed as a background process. On older systems it masquerades as [kworker/u:8:0]; on newer ones it copies itself to ~/.cache/fontconfig/fc-cache. A cron job fires every 30 minutes for persistence. The malware communicates with C2 infrastructure using UDP packets to port 123 disguised as NTP traffic, though earlier samples used TLS over WebSockets. Sansec observed the backdoor receiving commands but did not document follow-on activity. With over 160,000 Magento installations online, including 14,000 in the top million sites, the exposure surface is significant. As of September 7, Adobe had issued no CVE, no advisory, and no patch. Organizations running Magento should isolate internet-facing instances and monitor for the kworker/fc-cache persistence indicators until a fix ships.
