Sansec's Forensics Team disclosed StyleSmuggler, an unauthenticated remote code execution zero-day affecting every supported version of Magento Open Source and Adobe Commerce, including 2.4.9 with the latest security patches. Exploitation began September 4, 2026. The attack abuses Magento's template system through PHP code injection, then triggers execution via the server-side rendering of a "Payment Transaction Failed" email. No recipient action is required; the code runs during template rendering, and execution succeeds even if the email bounces.

The exploit installs a Rust-based backdoor disguised as a kernel worker process (kworker/u:8:8:0) or, in newer variants, as fc-cache in ~/.cache/fontconfig/. Persistence is established through a cron job running every 30 minutes. The backdoor communicates with command-and-control infrastructure via TLS/WebSockets or, in later samples, UDP packets on port 130 disguised as NTP traffic. As of September 7, Adobe Enterprise Support confirmed a fix was in progress but provided no timeline, and no CVE had been assigned at that point. By September 8, the Canadian Centre for Cyber Security advisory AV26-888 assigned CVE-2026-75650 and confirmed in-the-wild exploitation.

The scale is significant: Magento powers over 160,000 websites including 14,000 in the top 1 million sites. Sansec identified at least one victim running Magento 2.4.6-p15 with both July and August 2026 security patches applied, with the system falsely reporting a clean patch status. This means standard patching does not protect against StyleSmuggler. Organizations running Magento or Adobe Commerce should monitor for the telltale process names and cron entries, and watch for Adobe's official patch release.
