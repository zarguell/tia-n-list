Dell disclosed an OS command injection flaw, CVE-2026-67261, in the IAPI component of Dell Virtual Storage Integrator (VSI) for VMware vSphere Client. It is a CWE-78 issue: externally influenced input reaches a shell command without proper sanitization. Versions before 10.11.1.0 are affected and the fix ships in Dell advisory DSA-2026-335. The CVSS v3.1 vector AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H works out to a critical 9.8, and the issue is also tracked as GHSA-q6r6-m9h6-qhjm in the GitHub Advisory Database.

The severity comes from access and privilege. The flaw is exploitable over the network with no authentication, low attack complexity and no user interaction, and the vulnerable process runs with root privileges, so a successful hit grants complete control of the VSI host. VSI sits between Dell storage arrays and vSphere environments, which makes a compromised deployment a natural pivot into virtualization and storage management infrastructure, with access to configuration data, storage settings and persistence.

No proof of concept or observed in-the-wild exploitation is reported, so this is a patch-now advisory rather than an active campaign. Defenders should inventory VSI deployments against 10.11.1.0, apply DSA-2026-335 through normal change control, and check whether management interfaces are reachable from untrusted networks. Watch for public exploit code landing for a 9.8 unauthenticated root-level injection; exposure reviews should happen before that.
