Two malicious releases of Microsoft's agent-framework Python package, versions 1.26.1 and 1.26.2, were published to PyPI on November 17, 2026, roughly 33 minutes apart. The package has about 190,000 downloads per month and is used to build AI agents and multi-agent applications. The malicious distributions kept the legitimate framework components and added code that steals credentials while allowing applications to keep working normally. Version 1.26.0 is the latest clean release, and both bad versions have been quarantined on PyPI. A Microsoft maintainer confirmed the removals in a GitHub discussion and said an investigation was underway.

Researchers at OX Security, Wiz, Endor Labs, SafeDep, Socket, StepSecurity and Aikido analyzed the malware. It exploits a Python startup mechanism so it runs whenever the interpreter starts, even when an application never imports the compromised package. Targets include secrets in environment variables and configuration files, cloud identities and CI/CD credentials. That execution trigger widens the blast radius beyond projects that directly call agent-framework: developer machines and build runners with the package installed can be exposed simply by starting Python.

Anyone who installed 1.26.1 or 1.26.2 should treat cloud keys, tokens and CI/CD secrets on those hosts as potentially exposed and rotate them, then check for persistence and outbound traffic from build environments. The incident follows a run of dependency supply chain compromises aimed at developer infrastructure rather than end users. Package integrity checks and pinning to known good versions would have limited this one, since the malicious releases carried the expected framework code alongside the stealer.
