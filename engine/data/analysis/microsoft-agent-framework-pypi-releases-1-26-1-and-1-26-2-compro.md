On November 17, 2026, attackers published two malicious releases of Microsoft's agent-framework package on PyPI: versions 1.26.1 and 1.26.2, posted 33 minutes apart and available for under an hour. SecurityWeek and BleepingComputer put the package at roughly 190,000 to 200,000 monthly downloads. Both releases were quarantined, version 1.26.0 remained the clean release, and Microsoft acknowledged the incident while an investigation was underway.

The malicious distributions kept the legitimate framework and agent-framework-core 1.26.0 dependency, so applications could continue to work while a credential stealer ran in the background. A .pth startup hook executed the stealer whenever Python started, even if agent-framework was never imported. Reported targets included environment variables, configuration files and process memory, plus credentials for Azure, AWS, GitHub, Docker, Hugging Face and OpenAI. Version 1.26.1 sought Azure managed identity and Azure DevOps OIDC tokens; version 1.26.2 added GitHub Actions OIDC requests and searches of GitHub runner directories. JFrog also warned that pip uninstall could trigger the .pth payload once more.

This is a high-impact supply-chain failure because the trusted package name and normal framework behavior concealed theft from developer and CI/CD environments. Teams should inventory installations and lockfiles for the two malicious versions, rotate exposed cloud and repository credentials from clean systems, and review cloud and CI logs for token use. Cleanup needs to account for startup-hook execution rather than assuming an ordinary uninstall is safe. Watch for Microsoft's final root-cause findings, PyPI's account-security response and any confirmed downstream compromises.
