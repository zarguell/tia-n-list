Microsoft's official agent-framework package on PyPI shipped malicious releases 1.26.1 and 1.26.2 on November 17, 2026. Both add a 23-byte `af_runtime_diag.pth` whose single `import af_runtime_diag` line runs during Python startup, before an application imports the framework. The companion module reads environment variables, credential files and other processes' environments, then requests fresh GitHub Actions, Azure DevOps and Azure managed identity tokens and POSTs zlib compressed, Base64 encoded JSON to a webhook.site endpoint using `?t=telemetry` and a `runtime-diagnostics/1` user agent. PyPI quarantined the publisher, but 1.26.2 appeared after 1.26.1 was quarantined and the actor is reported to retain publishing access.

The distinguishing risk is that neither a clean lock file, the trusted Microsoft publisher, nor avoiding an import of agent_framework protects a host once that .pth file is in site-packages. Because the collector mints new OIDC and cloud tokens, revoking only the secrets that sat on disk at install time leaves attacker-held short-lived Azure and CI tokens usable. Developers and build runners that installed either version should be treated as credential compromises, including secrets readable from other processes on shared runners. Public download totals for the package are not a count of installs of 1.26.1 or 1.26.2, and the reports give no victim count, so the exposed population cannot be numbered from them; the concentration is where cloud identities and CI secrets live. That is what separates this from the day's other supply-chain items: a legitimate publisher and a second malicious release after quarantine are evidence of an active account takeover, not a one-off bad upload.

Search dependency manifests, lock files, build logs, artifact caches and site-packages for 1.26.1, 1.26.2, `af_runtime_diag.pth` and `af_runtime_diag.py`; inspect every executable .pth line in affected environments and check for the `_AF_TEL` guard left by a prior run. Hunt egress telemetry for the UUID-specific path `webhook.site/d381fd80-ec62-42ad-8f5c-d1b15103c9bb?t=telemetry` and the `runtime-diagnostics/1` user agent rather than blocking webhook.site wholesale, since that domain is shared. Isolate affected runners, stop jobs using them, rebuild from a known-good image and dependency set, rotate Git, Docker, pip, npm, NuGet, cloud, AI service and application secrets exposed in environment variables or targeted files, revoke GitHub Actions and Azure DevOps runtime credentials, invalidate OIDC-derived sessions and review Azure managed identity activity for the affected workload. No fixed release is named in the reporting, so confirm a safe version from Microsoft or the PyPI project page before reinstalling.

The assessment changes if Microsoft or Socket publishes per-version install counts or confirmed victim telemetry, or if evidence appears of token misuse or a second-stage payload. Clean confirmation that publisher access has been revoked and a verified safe release would narrow the response, but the post-quarantine publication of 1.26.2 leaves the state of that account as the open question.
