Microsoft's official agent-framework Python package on PyPI was compromised on November 17, 2026. Malicious releases 1.26.1 and 1.26.2 carried a credential stealer aimed at cloud identities, developer secrets and CI/CD environments. Both the OpenSourceMalware post and the later GBHackers report name the same package and the same two versions, so the artifact to hunt for is an install of either release, not a vague warning about AI tooling.

An agent framework sits close to the tokens and configuration that let code call model APIs and cloud services. A stealer planted there can collect credentials from developer machines and build runners in one step, then use them against infrastructure that may not look like a typical endpoint target. GBHackers, citing Socket, places the incident in a wider run of AI dependency supply-chain compromises where a trusted package becomes the entry point into systems holding authentication material.

The available reports do not name a clean replacement version. Teams that pulled 1.26.1 or 1.26.2 should treat any host or runner that installed them as exposed, rotate cloud and CI secrets reachable from those hosts, and confirm the current safe release from Microsoft or the PyPI project page before reinstalling. Follow-up reporting that identifies the stealer's persistence or exfiltration endpoints would change the response scope; none is given in these accounts.
