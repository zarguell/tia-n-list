Microsoft's official `agent-framework` package on PyPI was compromised on November 17 with two malicious releases, 1.26.1 and 1.26.2, published 33 minutes apart. The package has roughly 190,000 to 200,000 monthly downloads and is used to build AI agents and multi-agent workflows. Both malicious builds kept the legitimate dependency on `agent-framework-core` 1.26.0, so applications continued to work while a `.pth` startup hook ran a credential stealer on every Python interpreter start, even when the compromised package was not explicitly imported.

The stealer in 1.26.1 harvested environment variables, local configuration files and process-accessible secrets targeting Azure, AWS, GitHub, Docker, Hugging Face and OpenAI, and attempted to obtain Azure managed identity access tokens and Azure DevOps OIDC tokens. Version 1.26.2 added GitHub Actions OIDC token requests and searches of GitHub runner directories. Aikido, Endor Labs, OX Security, SafeDep, Socket, StepSecurity and Wiz documented the packages. PyPI quarantined both releases, version 1.26.0 is the clean release, and GitHub advisory GHSA-764m-3ppc-5m73 records the compromise.

This is a developer-machine and CI credential exposure, not just a bad package version. The startup hook widens the blast radius to any Python process in an affected environment, and the OIDC and managed-identity targets mean a single install could yield short-lived cloud and pipeline access. A maintained package with Microsoft branding makes source provenance a weak control here.

Watch for the package maintainer's investigation findings on how the publishing credentials were obtained, and for indicators from the security firms that analyzed the stealer. Immediate checks are any environment that installed 1.26.1 or 1.26.2, rotation of cloud, GitHub and AI-service secrets visible to those environments, and review of GitHub runner and Azure DevOps token use during the roughly one-hour window the releases were live.
