Cycode researchers found a high-severity OAuth flaw in Anthropic's official MCP Python SDK, versions 1.9.1 through 2.1.1, affecting HTTP-based MCP clients. A malicious MCP server can return a 404 during authorization-server discovery to force the SDK down an unsafe fallback that accepts OAuth metadata straight from the server without validating the issuer. The attacker supplies metadata impersonating a real provider such as Okta, Google, or Microsoft Entra ID while pointing the token endpoint at infrastructure they control, capturing client secrets, authorization codes, and PKCE proof keys. The victim may still see a genuine provider login page, which makes the theft hard to spot.

Any deployment where users connect MCP clients to untrusted servers should treat this as account-takeover risk and upgrade past the vulnerable range. Watch for the patched release details, CISA or vendor severity confirmations, and any evidence that public MCP servers abused the pattern before disclosure.
