A high-severity flaw in Anthropic's official MCP Python SDK exposes HTTP-based MCP clients that authenticate with OAuth to malicious server takeover. In vulnerable releases, a malicious MCP server returns a 404 during authorization server discovery, pushing the SDK onto an unsafe fallback path where it accepts OAuth metadata supplied by the server without validating the issuer. The attacker supplies metadata impersonating a legitimate identity provider such as Okta, Google, or Microsoft Entra ID while pointing the token endpoint at attacker infrastructure.

The attack is deceptive because the victim still sees a genuine login page hosted by the real identity provider. After the user authenticates, the SDK sends the resulting authorization code to the attacker's token endpoint instead of the legitimate one. The flaw also exposes client secrets, authorization codes, and PKCE proof keys, which is enough for full account takeover of the MCP user.

Any deployment running HTTP-based MCP clients on a vulnerable SDK release against OAuth providers is exposed, and the malicious server only needs to be one the client connects to. Watch for a patched SDK release and its adoption, guidance from Anthropic on affected versions, and whether research demos show the attack working against real identity providers. Teams embedding MCP clients in agent workflows should treat server-controlled discovery metadata as untrusted until the fix lands.
