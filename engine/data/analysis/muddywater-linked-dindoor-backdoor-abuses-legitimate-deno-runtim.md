Researchers at Binary Defense identified Dindoor, a new Windows backdoor attributed to the Iranian APT group MuddyWater. The malware was found in infections at U.S. software and banking organizations and a Canadian non-profit starting in early 2026. Unlike most backdoors that ship a custom interpreter, Dindoor hijacks the legitimate Deno JavaScript/TypeScript runtime to execute its payload. If Deno is not present, the loader downloads it from deno.land using curl.exe. This makes the malware harder to spot because the runtime itself is signed and trusted.

The attack chain unfolds in three stages. Initial access comes through spearphishing. The loader checks whether Deno exists on the compromised Windows host, then launches it with a Base64-encoded script containing the backdoor. The first stage fingerprints the device, contacts a command-and-control server, and compiles a secondary payload. That payload retrieves and executes the final stage from the remote server. Before enabling its main functions, the final payload checks for virtual machine or sandbox artifacts to avoid analysis.

What makes Dindoor notable is its use of a legitimate developer tool as the execution layer. Security products that trust signed runtimes will not flag Deno itself. The Base64-encoded arguments further obscure the actual malicious scripts. This is a pattern worth watching: MuddyWater continues to evolve its tradecraft by hiding behind legitimate infrastructure rather than building custom tooling, and defenders need detection strategies that go beyond binary reputation.
