CVE-2026-32746 is a pre-authentication buffer overflow in GNU inetutils telnetd, disclosed by watchTowr Labs and discovered by the DREAM Security Research Team. The vulnerability has existed since 1994, residing in the LINEMODE SLC (Set Linemode Characters) negotiation handler. It allows an attacker to corrupt approximately 400 bytes of adjacent global variables through a BSS-based buffer overflow in the slcbuf buffer, which is sized at 0x6C bytes with no bounds checking on incoming SLC triplets.

The blast radius is substantial because most vendors based their telnetd implementations on the same codebase. watchTowr confirmed the vulnerability in inetutils-telnetd itself, Ubuntu, Debian, FreeBSD 13 and 15, NetBSD 10.1, Citrix NetScaler, Apple Mac Tahoe, Haiku, TrueNAS Core, uCLinux, libmtev, and DragonFlyBSD. The overflow data is constrained by SLC triplet format restrictions (each byte has specific validation rules), and the maximum overflow window is about 0x190 bytes within a single 0x200-byte subnegotiation packet.

Exploitation difficulty varies significantly by platform. On 64-bit x86 systems, consecutive NULL bytes in pointers make full overwrites nearly impossible; only partial overwrites targeting the least significant byte are feasible. On 32-bit Debian systems, the overflow can corrupt the def_slcbuf pointer, enabling an arbitrary free primitive when the deferred SLC processing calls free() on the overwritten pointer. watchTowr's proof-of-concept achieves a heap pointer leak on Debian 32-bit but stopped short of full RCE, noting that exploitation depends heavily on the specific libc version and binary compilation. As of disclosure, inetutils has not released a patched version (2.7 is still vulnerable); only Debian sid/forky carries a fix. Most Linux distributions have not yet shipped packages. The vulnerability is particularly dangerous for industrial control systems, embedded devices, and legacy infrastructure where Telnet remains the only supported remote access protocol.
