Wiz Threat Research ran honeypots impersonating LiteLLM, Flowise, LangChain, Langflow, ChromaDB, and Ollama for 90 days and recorded sustained exploitation of internet-facing AI infrastructure, with tooling tailored to each platform's internals. Against LiteLLM, attackers used CVE-2026-59822, an MCP authentication bypass in which a failed token check returns an empty UserAPIKeyAuth() object, so a single character Bearer token such as x grants full MCP access; the honeypots caught probes of model enumeration with GET /v1/models and Authorization: Bearer x. They also exploited CVE-2026-42271, command injection in the /mcp-rest/test/connection and /mcp-rest/test/tools/list preview endpoints, where the stdio command field reaches subprocess execution with no role check. The observed payload pulled a Monero miner from 185.62.1[.]8 into /tmp/.dbus-cache, launched the gmon binary detached, deleted the staging directory, and returned a valid MCP handshake so the connection test looked legitimate. CVE-2026-42271 also chains with CVE-2026-48710, a Starlette host header validation bypass, for fully unauthenticated RCE, and external researchers have linked that chain to the Qilin ransomware group.

A LiteLLM proxy is a credential chokepoint rather than an ordinary web app: it can hold API keys for OpenAI, Anthropic, Azure, and Gemini, run with cloud IAM permissions, and front MCP connections into databases, code repositories, Slack, and internal APIs. Wiz observed attackers reading the proxy master key out of Python module memory because it never exists on disk, fingerprinting backend models to choose between key theft and inference-quota abuse, and hiding miners as /usr/src/node-red/xmrig or a unicorn binary under /app/data/.claude/, where it blends with Claude Code artifacts. The exposure base is not niche: Wiz's State of AI in the Cloud 2026 report puts self-hosted AI software in 90 percent of cloud environments and self-hosted models in 63 percent. What the event list does not spell out is the timeline: NVD published CVE-2026-42271 on May 8, 2026, CISA KEV added it on June 8, 2026 with a June 22 federal remediation deadline, and the CVE-2026-59822 advisory landed on June 30, 2026. This late August story is therefore not a new bug but confirmation that months-old, already-patched flaws are still being worked in the wild, which makes the risk hygiene-driven rather than disclosure-driven, and it means a file-based IoC sweep will miss a miner whose binary was deleted at launch.

Patch LiteLLM to 1.84.0 or later, which covers both flaws: 1.83.7 fixed CVE-2026-42271 and 1.84.0 fixed CVE-2026-59822. Red Hat OpenShift AI bundles the vulnerable proxy and needs the fixed 2.25.8, 3.3.4, or current 3.4 builds. Where an immediate upgrade is impossible, block /mcp/ and the /mcp-rest/test/ endpoints at the reverse proxy, put authenticated AI services behind the same network controls as production cloud infrastructure, and treat any unauthenticated AI service reachable from the internet as already compromised. Concrete hunts: GET /v1/models requests carrying Authorization: Bearer x, python3 children spawned by the LiteLLM process, reads of /app/litellm_config.yaml, /etc/litellm/.env, and ~/.litellm/config.yaml, files at /tmp/.dbus-cache/gmon and /usr/src/node-red/xmrig, and DNS or egress to 185.62.1[.]8, 185.84.98[.]85, pool.hashvault[.]pro, or OAST-style callback domains. Verify the master key is not the default sk-1234 and rotate any provider keys an exposed proxy could have served.

Watch for CISA adding CVE-2026-59822 to KEV, which would put federal remediation deadlines on the authentication bypass the way June 8 did for the command injection. Watch also whether the Qilin-linked CVE-2026-42271 plus CVE-2026-48710 chain graduates from miners and credential theft to actual ransomware deployment, since unauthenticated RCE on a credential chokepoint is exactly the entry a ransomware operator pays for.
