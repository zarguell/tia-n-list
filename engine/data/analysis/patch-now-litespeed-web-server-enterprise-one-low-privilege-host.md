LiteSpeed Web Server Enterprise before version 6.3.7 contains a critical privilege escalation flaw that lets any low-privilege hosting account on a shared server reach root and bypass CageFS account isolation. The vendor emailed customers on September 14, 2026 with an urgent advisory urging immediate upgrade. The fix shipped as version 6.3.7 on September 11. No CVE has been assigned, no CVSS score exists, and no public exploit or in-the-wild exploitation has been reported. This means vulnerability scanners and CISA KEV will not flag affected servers.

The flaw is in the web server binary itself, not in the cPanel plugin that had two separate root-escalation bugs earlier in 2026 (CVE-2026-48172 in May and CVE-2026-54420 in June, both now on CISA KEV). A server can run the fully patched plugin 2.4.8 on top of an unpatched 6.3.6 core. The 6.3.7 changelog lists three security items: tighter authentication and validation of requests to lscgid (the CGI daemon), stronger validation of internal redirect URLs, and blocking internal-use environment variables from .htaccess. This is the third root-path in one hosting stack in a single year.

Operators should upgrade every node to 6.3.7 immediately, confirm the version on each box rather than trusting automatic update channels, and audit lscgid child processes, tenant .htaccess files setting environment variables, and root-owned files created under tenant home directories since September 1. Any root-privileged process originating from tenant input that is not a known piped logger warrants investigation.
