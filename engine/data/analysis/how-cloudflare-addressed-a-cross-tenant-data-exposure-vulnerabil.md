Cloudflare closed a cross-tenant data exposure in Containers on September 24, 2026, rooted in storage provisioning rather than a Firecracker escape: every container root disk, presented to the microVM as /dev/vdc, was backed by dm-thin thin pools using 64 KiB blocks configured with skip_block_zeroing, so a 4 KiB write to an unmapped region allocated a recycled physical block whose remaining 60 KiB still held a prior tenant's bytes, readable through a raw device read. Oren Yomtov of Accomplish reported it through Cloudflare's HackerOne program as report 3997565 on September 4, 2026, and a Workers Paid account was enough to reproduce it. Cloudflare Sandboxes and Browser Run, built on the same Containers disk implementation, were affected too, and no CVE identifier has been assigned.

This was a working break of the isolation guarantee the product sells, not a bounded information leak: the proof of concept identified 2,700 distinct foreign directory inodes through ext4 metadata_csum directory block checksums, saw residual material on 18 of 24 placements and 20 of 22 underlying hosts across four continents, and recovered directory structures, database pages, and structurally complete SQLite databases. Placement on a recycled host, not product choice, set the blast radius, and what a victim loses is whatever its workloads wrote to disk, which for real containers means .env credentials, database files, and browser profiles. The technique leaves no trace in any victim's own logs, so the no-exploitation finding rests entirely on Cloudflare's retained disk-I/O telemetry, and Accomplish's tally, six sandbox escapes published since July 2026 across Claude Cowork, Claude Code, Cursor CLI, Docker's VMM, and OpenAI Codex, marks a sustained research campaign against agent-sandbox isolation rather than a one-off.

Fleet remediation required no customer change, so the defender work is verification and rotation: skip_block_zeroing removal completed rollout on September 7, 2026 at 06:13 UTC, and pre-mitigation cached dm-thin snapshots of OCI image layers were cleared by September 19, 2026 at 15:03 UTC, which means any secret a Containers, Sandboxes, or Browser Run workload held on disk before September 7 should be treated as readable by an unknown prior co-tenant and rotated if still live. Operators running dm-thin themselves should audit pool table options for skip_block_zeroing, a common performance setting, and zero freed volumes before they return to shared pools. The hunt is the write-read asymmetry Cloudflare turned into detection signatures: small 4 KiB writes into 64 KiB-aligned ext4 free space followed by raw /dev/vdc reads returning far more bytes than were written, a rule any Firecracker plus dm-thin fleet can apply to its block-device telemetry.

Two developments would change this assessment. A CVE assignment or KEV listing would turn a vendor-posted issue into a tracked vulnerability with procurement and audit consequences, and generalization is the real risk, because skip_block_zeroing is a stock dm-thin option: a second provider disclosure, or a public PoC framed against any thin-provisioned multi-tenant host, would move this from a Cloudflare incident to an industry-class storage isolation flaw.
