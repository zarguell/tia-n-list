Cloudflare addressed a cross-tenant data exposure vulnerability in Containers that allowed one sandbox to read other customers' files. The root cause was dm-thin pools configured with skip_block_zeroing and 64 KiB blocks, combined with Firecracker presenting container root disks as /dev/vdc. Researchers recovered residual material on 18 of 24 placements and 20 of 22 nodes across four continents, including 2,700 distinct foreign directory inodes.

Recovered data included directory listings, SQLite databases, Chromium profiles, .env files, and credential files. Remediation removed skip_block_zeroing fleet-wide, retired running container disks, and cleared cached snapshots by September 19, 2026. No exploitation evidence was found in retained telemetry. Customers should rotate secrets that may have been present in affected containers and verify snapshot cleanup status.
