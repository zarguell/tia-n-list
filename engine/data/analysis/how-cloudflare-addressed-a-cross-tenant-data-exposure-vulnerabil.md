Cloudflare closed a cross-tenant data exposure flaw in its Containers platform, reported September 4, 2026 by Oren Yomtov of Accomplish through HackerOne (report 3997565). The same disk implementation backed Cloudflare Sandboxes and Browser Run, so all three were affected. The root cause was dm-thin thin-provisioning pools configured with skip_block_zeroing and 64 KiB blocks: when a container root disk (presented by Firecracker as /dev/vdc) was deleted, its physical blocks returned to a shared pool without being zeroed. A 4 KiB write to an unmapped region of a new container's disk forced allocation of a reused 64 KiB block, leaving roughly 60 KiB of the previous tenant's data readable.

The disclosure includes unusually concrete recovery numbers: residual material turned up on 18 of 24 placements and 20 of 22 underlying nodes across four continents, with 2,700 distinct foreign directory inodes identified via ext4 directory block checksums. Recoverable items included directory listings, SQLite databases, Chromium profiles, .env files, and credential files. Cloudflare says a review of retained disk-I/O telemetry found no sign of malicious exploitation. Remediation removed skip_block_zeroing fleet-wide, retired running container disks, and cleared pre-mitigation cached image snapshots; the rollout finished September 7 and snapshot cleanup on September 19, with no customer action required.

Two things make this worth tracking. First, the bug class is infrastructure-level, not a container breakout: multi-tenant storage reuse without deterministic zeroing can silently defeat tenant isolation on any platform that shares physical blocks across customers. Second, Accomplish counts this as the team's sixth published sandbox escape since July 2026, after SharedRoot (Claude Cowork), Beltdown (Claude Code), Beltdown2 (Cursor CLI), a Docker VMM issue, and an OpenAI Codex sandbox escape. Watch for equivalent skip_block_zeroing or thin-provisioning reuse patterns in other managed container and AI-agent sandbox offerings, and for whether Cloudflare's telemetry-based no-exploitation claim is challenged by third parties.
