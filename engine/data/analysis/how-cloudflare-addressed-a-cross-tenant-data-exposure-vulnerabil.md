Cloudflare closed a cross-tenant data exposure in Containers, disclosed September 24, 2026, that was rooted in storage provisioning rather than a Firecracker microVM escape. Every container root disk is presented to its microVM as /dev/vdc and backed by dm-thin thin pools using 64 KiB blocks configured with skip_block_zeroing. That option let a newly allocated physical block skip zeroing, so a 4 KiB write to an unmapped region left about 60 KiB of a prior tenant's residual bytes readable from the raw device. Oren Yomtov of Accomplish reported it on September 4, 2026 through HackerOne as report 3997565. Cloudflare Sandboxes and Browser Run shared the same disk implementation and were affected too.

The recovered material showed real exposure, not theory: residual data turned up on 18 of 24 test placements and 20 of 22 underlying nodes across four continents, including 2,700 distinct foreign directory inodes identified through ext4 directory block checksums, with directory listings, SQLite databases, Chromium profiles, .env files, and credential files among the recovered items. Placement on a recycled host set the blast radius, and the reads leave no trace in any victim's own logs, so the finding that no one exploited it rests entirely on Cloudflare's review of retained disk-I/O telemetry. It was Accomplish's sixth published sandbox escape since July 2026, after work against Claude Cowork, Claude Code, Cursor CLI, Docker's VMM, and OpenAI Codex sandboxes, which marks a sustained research campaign against agent-sandbox isolation.

Remediation required no customer action: Cloudflare removed skip_block_zeroing fleet-wide and retired running container disks with rollout complete September 7, 2026, then cleared pre-mitigation cached image snapshots by September 19, 2026. The defender takeaway is rotation and verification: any secret a Containers, Sandboxes, or Browser Run workload held on disk before September 7 should be treated as readable by an unknown prior co-tenant and rotated if still live. Operators running dm-thin elsewhere should audit pools for skip_block_zeroing, a common performance setting, and zero freed volumes before reuse.

The open risk is generalization, since skip_block_zeroing is a stock dm-thin option rather than a Cloudflare-specific misconfiguration. A second provider disclosure or a public proof of concept framed against any thin-provisioned multi-tenant host would move this from one vendor's incident to an industry-class storage isolation flaw, and a CVE assignment would add procurement and audit pressure. Detection can lean on the write-read asymmetry: small writes into 64 KiB-aligned free space followed by raw device reads returning far more than was written.
