Mitel's advisory MISA-2025-0009, first issued 2025-07-23 and later revised to version 2.0, fixes CVE-2025-67822, an unauthenticated authentication bypass in the Provisioning Manager component of MiVoice MX-ONE. The CVSS 3.1 base score is 9.4 with vector AV:N/AC:L/PR:N/UI:N/S:U/C:L/I:H/A:H, meaning the flaw is remotely reachable, needs no privileges and no user interaction, and hands an attacker write-level access to the system. Affected releases run from 7.3 (7.3.0.0.50) through 7.8 SP1 (7.8.1.0.14). The vendor patches are MXO-15711_78SP0 for 7.8 and MXO-15711_78SP1 for 7.8 SP1. Securityonline's coverage frames the same fix set as three flaws including a command injection issue and points 8.x deployments at the 8.2 SP1 HF2 build, and it reported no public exploit and no CVE assignment at the time it published; NVD did not publish CVE-2025-67822 until 2026-01-15, with status Analyzed.

The reason this outranks the other contact-center and telephony patches of the week is what the Provisioning Manager plane controls. Provisioning is where agent accounts, extensions, dial plans, routing tables and the credentials that tie the platform to CRM and workforce-management integrations are defined. An unauthenticated bypass into that plane is not a read of call records, it is administrative control of the switch: create or reset an agent or admin account, rewrite routing to send calls elsewhere, and inherit the trust the platform holds with downstream systems. The advisory scores confidentiality low but integrity and availability high precisely because the payoff is control, not disclosure, and MiVoice MX-ONE sits in the call path of the enterprises and service providers that run it.

Anyone on 7.3 through 7.8 SP1 should treat this as reachable until proven otherwise and confirm which instances expose the provisioning or management interfaces beyond the corporate edge. Apply MXO-15711_78SP0 or MXO-15711_78SP1 on the 7.x line, or the 8.2 SP1 HF2 build the trade coverage cites for 8.x, and verify the applied build rather than assuming the maintenance window covered it. Mitel lists no public exploit and no active exploitation, so the immediate task is patch and reachability reduction: restrict provisioning and management listeners to trusted networks and administrative jump hosts, then review management-plane authentication and provisioning-change logs for accounts, extensions or routing objects created outside known administrative sources.

Two developments would move this from a patch-now item to an incident-response item. The command injection issue and the other of the three flaws still need CVE identifiers and confirmed affected versions, which would tell defenders on 8.x whether 8.2 SP1 HF2 truly closes the full set. Any GreyNoise or vendor telemetry showing exploitation in the wild, or a CISA KEV listing for CVE-2025-67822, would change the priority from scheduled patching to immediate hunt for rogue provisioning changes and unexplained admin account creation.
