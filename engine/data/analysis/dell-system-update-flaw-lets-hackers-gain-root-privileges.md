Dell's advisory DSA-2026-324, published October 1, 2026, fixes five flaws in Dell System Update, the CLI tool that pushes BIOS, firmware, and software updates across PowerEdge fleets running Linux and Windows. The critical one, CVE-2026-86360, is a path traversal scored 9.6 (CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:C/C:H/I:H/A:H) that an unauthenticated remote attacker can exploit to run arbitrary code with root privileges; Dell's own wording says successful exploitation may allow complete compromise of the vulnerable application and underlying operating system. The remaining four, all in DSU versions prior to 2.3.0.0: CVE-2026-86361 and CVE-2026-86362, both 8.2, let a low-privileged local user escalate privileges, CVE-2026-71168 (7.3) is a local path traversal to code execution, and CVE-2026-63697 (7.6) is improper certificate validation requiring high privileges. Dell credits Ori Gabriel with CVE-2026-63697 and CVE-2026-86360, saltedfish with CVE-2026-86361 and CVE-2026-86362, and Nir Yehoshua of Cipher Security Labs with CVE-2026-71168.

The severity number understates the operational exposure. DSU holds root on every server it manages, so whoever owns DSU decides what firmware and updates the entire PowerEdge estate installs; the 9.6 bug converts that trust position into a fleet-wide distribution channel for an attacker, not merely one compromised host. Three of the five flaws need only a local low-privileged foothold, exactly what a commodity initial-access implant provides, so the set chains rather than standing alone. Timing matters too: the advisory went live October 1 and press coverage only landed October 5, and NVD still has zero records for all five CVEs, meaning most scanner stacks will report DSU hosts as clean until enrichment catches up. No exploitation is documented and the CVEs are absent from KEV, so this is the cheap-patching window. CISA and the FBI have called path traversal bugs unforgivable since at least 2007 and have pressed vendors to eliminate them since May 2024, which makes a 9.6 traversal shipping in 2026 a supply-discipline signal as much as a technical one.

Upgrade to DSU 2.3.0.0 or later, the advisory's fixed version, and treat anything older as vulnerable on both Linux and Windows. Inventory first, because DSU tends to live on admin workstations, jump hosts, and management servers where asset tracking is weakest. Restrict DSU-facing services to management VLANs, since the critical bug requires nothing more than network reachability. For hunting, rely on mechanism rather than published IoCs, because none exist yet: watch for the DSU process or its update service spawning unexpected children as root, filesystem writes outside the tool's normal update and cache directories, which is the traversal signature, and certificate validation failures originating from DSU hosts, which would line up with CVE-2026-63697.

Two developments would change the assessment. A KEV listing or credible telemetry of exploitation attempts against DSU endpoints would move this from patch-priority to incident-response, and the remote unauthenticated profile of CVE-2026-86360 makes that plausible once exploit code circulates. A Dell revision that raises severity or adds additional fixed versions would invalidate current remediation guidance and warrant a fresh pass.
