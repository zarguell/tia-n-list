Security researcher Sean Bales disclosed more than 30 alleged zero-day vulnerabilities in N-able's N-central remote monitoring and management platform late on Sunday, November 8, publishing proof-of-concept exploits in a GitHub repository called Able2Shell. Bales told BleepingComputer the discovery was AI-assisted and said the flaws were tested against N-central Appliance 2026.4.0.31, a pre-release build, with most if not all believed to affect earlier versions. The disclosed bugs include authentication bypasses, credential disclosure, arbitrary file writes, directory traversal, cross-site scripting, XML external entity injection, and remote code execution. One critical chain abuses an unauthenticated XXE vulnerability in N-central's service-import functionality to steal a trusted local session, reset an account password, and execute commands on the server as the nable user. N-able took its hosted N-central environments offline and told on-premises customers to shut their servers down; a later update cited by a government security report put the disclosed count at 33 zero-days.

The stakes here are downstream. N-central is the management plane an MSP uses to reach its customers' endpoints, so a single compromised server is a multi-customer incident rather than a single-victim bug. Public exploit code for more than 30 flaws against that plane, with the vendor taking its own cloud platform offline, makes this a trust-boundary event instead of another routine disclosure: an attacker who completes the XXE chain sits inside the tool MSPs rely on to manage customer devices and networks.

Defenders should keep on-premises N-central servers offline until N-able confirms they can return safely, and apply N-central 2026.4 HF1 (build 2026.4.0.32, released November 2) for the vulnerabilities it addresses (CVE-2026-98432 at CVSS 9.8, CVE-2026-111497, CVE-2026-114406) while awaiting N-able's hotfix for the Able2Shell zero-days. Restrict untrusted network access to the service-import function and the management interface in the meantime. Because no specific IoCs or log paths accompany the disclosure, hunters should key on behavior: unauthenticated service-import requests carrying XXE payloads, unexpected account creation and password resets, and activity executing as the nable user.

Watch for confirmed in-the-wild exploitation of the Able2Shell chains, official N-able patch or version guidance for the disclosed zero-days, and any sign that affected versions extend beyond the pre-release 2026.4.0.31 build. Any of those moves this story from urgent containment to active incident response.
