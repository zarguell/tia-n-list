The flaw is CVE-2026-30612 in the updater of Time4Popcorn, a closed-source fork of Popcorn Time that still phones home from an estimated 2.5 to 3.0 million Windows and 250,000 to 350,000 macOS hosts. The Windows and macOS updaters poll the abandoned domain popcorntimeupd.xyz over unencrypted HTTP, accept an unsigned executable named by a JSON response, and run it with elevated privileges: NT AUTHORITY\SYSTEM on Windows and root on macOS. Eye Security discovered the risk after an Updater.exe process on a client laptop tried to reach the unregistered domain, registered it, and observed roughly 50 requests per second and more than 3.8 million distinct hardware IDs over six months. Android clients are also affected but require user interaction to install an update.

The exposure is latent rather than actively exploited: none of the connecting hosts appeared to be running the app, so these are forgotten installations on residential, corporate, government, and military networks, which is exactly the population a ransomware or credential-stealing operator wants for an initial foothold. The real risk is not that Eye Security acted but that nobody had to: the same HTTP channel and missing signature check meant any party controlling one of the expired domains, or sitting on the path, could have pushed arbitrary code to millions of endpoints with no user prompt. That makes this less a vulnerability patch story than an abandoned-software governance failure, and the 2014 Chrome engine with the sandbox disabled that remains in the client means disabling the updater did not make the app safe to use.

Defenders should treat this as an inventory and removal task, not a patching task, because no vendor patch exists and the project is abandoned. On Windows, look for the service named "Update service" and the executable at `C:\Program Files (x86)\Popcorn Time\Updater.exe` or `C:\Program Files\Popcorn Time\Updater.exe`, disable the service with `sc.exe config "Update service" start= disabled`, and remove the software; on macOS, check `/Library/PrivilegedHelperTools/PT.updd` and `/Library/LaunchDaemons/PT.updd.plist` and run `launchctl unload -w /Library/LaunchDaemons/PT.updd.plist`. Hunt proxy and DNS logs for requests to popcorntimeupd.xyz and the 14 related domains Eye registered, and block those domains at the perimeter; endpoint vendors can flag Updater.exe and PT.updd as potentially unwanted. Android clients cannot be remediated remotely, so those require manual uninstall.

Watch whether any of the domains that Eye could not acquire are later used to serve updates, and whether Shadowserver sinkhole telemetry shows residual requests from the unremediated share of hosts. Also watch for renewed exploitation of the client's unpatched 2014 Chrome engine and disabled sandbox on systems where users keep running the app, since that path needs no update channel at all.
