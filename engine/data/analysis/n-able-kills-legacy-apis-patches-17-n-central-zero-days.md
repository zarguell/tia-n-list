N-able shipped N-central 2026.4 Hotfix 3, build 2026.4.1.39, on November 16 to close 17 CVEs numbered CVE-2026-129271 through CVE-2026-129287. Canadian Cyber Centre advisory AV26-1165 lists N-central before 2026.4.1 HF3 and the Patch Management component before 2.14.4.5829 as affected. The batch covers local privilege escalation, predictable passcode authentication bypass, missing authentication, command execution, audit log tampering, XXE, SSRF and path traversal to RCE, including CVE-2026-129271, CVE-2026-129272 and CVE-2026-129286. N-able says hosted servers are patched and on-premises servers, agents and probes all need the upgrade.

The disclosure timeline runs back to the November 9 upload to the MSPNightmare/CVEs repository, which N-able describes as non-responsible publication, followed by a second wave on November 12 that it grouped into Legacy API abuse and Agent Impersonation. The 4EverAble2Shell chain, tracked by Previdian as VULN-2026-0009, abused unsafe class instantiation in bundled Apache Axis during SOAP fault processing to execute commands as root when Legacy API mode was enabled. Huntback found XMRig on 21 N-central servers, 19 of them already on Hotfix 2, across the United States, South Africa, Canada, the United Kingdom, Germany, France and Sweden. Sean Bales published details for 24 CVEs on November 16.

This is an MSP control plane compromise, so a root foothold on the server reaches every managed tenant behind it. HF3 permanently removes the Legacy API configuration option, requires an SMBIOS ID or machine ID before a device can connect, and adds an Inactive Assets tab for spotting leftover agents. N-able also left remote control other than Take Control disabled and the Intune integration blocked until customers finish upgrading agents and probes, which remain impersonation-prone on older builds.

Watch for attempts against the new HF3 CVEs, especially any confirmed in-the-wild use, and for miner operators pushing scripts through managed agents rather than stopping at server root. Hunting leads already published include 157.20.241[.]16 on port 8080 and ports 19202 to 19418, 139.99.69[.]109 on port 10128, 79.76.51[.]56 on port 39100, plus jup.sh, xvgz, xmrig.tgz and ob/cronhit with jup_start. Re-enabling direct remote control or the Intune integration before tenant upgrades finish would widen exposure again.
