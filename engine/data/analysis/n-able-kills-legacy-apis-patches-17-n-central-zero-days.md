N-able shipped N-central 2026.4 Hotfix 3 on Monday to close 17 zero-day vulnerabilities tracked as CVE-2026-129271 through CVE-2026-129287, a batch that includes flaws already exploited in attacks. The range covers privilege escalation, predictable passcode, command execution, missing authentication and authorization, audit log tampering, user enumeration, XXE injection, SSRF, RCE and validation errors. Cyber Centre advisory AV26-1165, dated 17 November, names CVE-2026-129271, a local privilege escalation in N-central Patch Management, and CVE-2026-129272, an MMS3 appliance authentication bypass via predictable passcode. It lists affected builds as N-central before 2026.4.1 HF3 and N-central Patch Management Component before 2.14.4.5829.

Hotfix 3 builds on Hotfix 2 and adds hardening in authentication, Agent and Probe communication, file and XML import handling, request and outbound connection handling, and user management. N-able also improved Agent verification and inactive Agent management, and added a device identification requirement before devices can connect to N-central. A separate Offseq alert flags CVE-2026-129286 as a critical path traversal in N-central. Agent and Probe impersonation is the specific risk N-able calls out for deployments that stay on older versions.

N-central is a remote monitoring platform, so weaknesses in it reach the managed estates of MSPs and their customers rather than a single server. N-able says hosted environments are already patched, but on-premises customers must upgrade servers, and all customers must upgrade Agents and Probes to the latest version, since unupgraded Agents and Probes remain susceptible to impersonation. Watch for vendor detail on which of the 17 flaws were exploited before the fix, any confirmed targeting of CVE-2026-129286, and whether the legacy API removal changes behavior in existing customer integrations.
