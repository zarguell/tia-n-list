A supply-chain campaign dubbed wfx-loot has been probing GitHub repositories using stolen developer credentials since November 10, 2026. Aikido Security identified roughly 4,800 compromised accounts behind probe pull requests submitted to 61,764 repositories, with the stealer observed running in more than 1,800 of them. SafeDep separately counted 8,093 public repositories receiving malicious commits; these figures measure different things and are not directly comparable. The attacker does not exploit a GitHub Actions bug, instead relying on valid tokens belonging to developer and bot accounts.

The malware is inserted into existing or new GitHub Actions workflows, shell scripts run by CI systems, and npm installation hooks, and it harvests GitHub tokens, repository secrets, cloud credentials, and AI service keys. It also reads GitHub Actions runner process memory. The npm vector extends risk to developers who install dependencies while the malicious changes are present, and even legitimate projects become dangerous when a contributor account is compromised.

Defenders should treat this as a credential hygiene incident: audit GitHub accounts for unauthorized activity, rotate personal access tokens and secrets, and review Actions workflows and CI scripts for unexpected changes. The full scope is still being investigated, and malicious execution is confirmed in at least 1,806 repositories, so affected organizations should assume any secret reachable from a compromised workflow is exposed.
