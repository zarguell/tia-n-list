An attacker Aikido Security tracks as wfx-loot has, since about 12:45 UTC on November 10, 2026, used stolen tokens for 4,837 GitHub accounts to probe 61,764 repositories with pull requests titled "docs: dependency audit notes" from wfx-docs branches, then pushed a roughly 1,500-line credential stealer where the token and repository configuration allowed execution. The attacker does not exploit a GitHub Actions vulnerability; access comes from valid developer and bot tokens, including 173 probe pull requests opened through the Fly.io GitHub App (app ID 34557) from 19 accounts. The payload lands in one of four hiding places: an existing workflow injected with a "ci: refresh build cache" commit, a hidden .ci-*.sh script triggered by an npm postinstall hook, a throwaway chore/xxxxxxxx branch carrying a new workflow, or an existing CI shell script such as update.sh. It dumps all repository secrets via toJSON(secrets), reads GitHub Actions runner process memory, and collects cloud and AI service keys, then the attacker reverts the commit and deletes the workflow run, usually within a minute.

The exposure is not 60,000 repositories in the sense of 60,000 confirmed breaches: Aikido found signs the stealer ran in at least 1,806 repositories, StepSecurity's broader review found 1,835, and SafeDep counted 8,093 public repositories that received malicious commits, with the gap reflecting measurement differences rather than disagreement about severity. The more consequential point is that a successful run hands over every secret and cloud role the job can reach, not just the ones the workflow names, and the attacker then installs persistence that survives secret rotation, including AWS role trust policies granting Principal AWS *, IAM access keys created since November 10 with sessions named wfx- followed by the process id, Azure federated credentials named wfx-ci-*, and GCP token activity through the GitHub workload identity pool. Because the probe pull requests are about 92 percent still open and 10,431 of them landed in repositories the compromised account did not own through collaborator or organization access, many victims have not noticed, and the overlap with October's GhostAction wave means accounts already compromised once are disproportionately hit again. This story matters more than the other credential-theft items today because the cleanup deletes the evidence and turns a visible supply-chain event into a silent rotation-and-persistence problem.

Defenders should search pull requests since November 10 for "docs: dependency audit notes" and branches named wfx-docs or chore/ followed by eight characters, and commits for "ci: refresh build cache", "ci: restore", "ci: cleanup", "chore: add ci helper", and "chore: add dependency audit workflow", checking each hit for a gap in Actions run numbers that marks a deleted run. Any repository where the stealer ran must be treated as fully compromised: rotate every repository, environment, and organization secret, npm and PyPI publishing tokens, OIDC cloud access, and developer credentials for anyone who ran npm install during the one-to-two-minute window, and check published package versions between the malicious commit and its revert. Remove persistence by auditing AWS for wildcard trust policies and wfx- prefixed session names in CloudTrail, Azure app registrations for wfx-ci-* federated credentials, GCP GenerateAccessToken and SignJwt calls through the GitHub pool, and GitHub for leftover wfx-docs and chore/* branches. Block the collection endpoints 194.150.166.244, 18.143.168.96, and 153.75.82.159 plus api.telegram.org on an egress allowlist, since copies after about 05:30 UTC on November 12 send only to Telegram chat -1004340163187 through five bot tokens with the HTTP callback set to 127.0.0.1, and hunt runner-memory reads and deleted runs in audit logs.

The assessment changes if the attacker's token pool expands beyond the current 4,837 accounts, if the Fly.io GitHub App vector turns out to reflect a broader OAuth or app-token compromise rather than individual user tokens, or if the stolen secrets are used to publish malicious versions of the affected npm and PyPI packages, which would convert a CI secret theft into a downstream supply-chain event. Also watch for new collection infrastructure beyond the three published IPs and the Telegram chat, since the operator has already switched channels once to evade blocklists.
