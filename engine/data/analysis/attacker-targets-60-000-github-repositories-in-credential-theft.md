Aikido Security calls the campaign wfx-loot. It began on 10 November 2026 and used stolen tokens for roughly 4,800 developer and bot accounts to submit probe pull requests to 61,764 GitHub repositories. The pull requests did nothing by themselves. Where the stolen access allowed changes, the attacker added a credential stealer to GitHub Actions workflows, CI shell scripts and npm install hooks. StepSecurity stresses that no GitHub Actions bug was involved, only valid tokens.

Aikido saw signs of execution in more than 1,800 repositories. SafeDep separately counted 8,093 public repositories that received malicious commits, a measure of commits rather than successful runs. The stealer looks for GitHub tokens, repository secrets, cloud credentials and AI service keys, reads GitHub Actions runner process memory, and is designed to exfiltrate CI/CD data. The npm path also puts developers at risk if they install dependencies while the malicious changes are present.

Watch for more detail on which credentials were actually taken, since a malicious commit does not prove secrets were stolen. The response advice in the coverage is to audit accounts for unauthorized activity, rotate personal access tokens and repository secrets, and review Actions workflows and npm hooks. A newer roundup restates the SafeDep figure of about 8,000 repositories without adding evidence, so the underlying Aikido and SafeDep counts remain the ones to track.
