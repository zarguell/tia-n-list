An attacker running a campaign Aikido Security calls wfx-loot has tested stolen access against more than 60,000 GitHub repositories since November 10, using roughly 4,800 compromised developer and bot accounts to submit probe pull requests to 61,764 repositories. The probe requests themselves do nothing; they establish whether the stolen token permits changes. Where permissions and configuration allow, the attacker then deployed credential-stealing code, with Aikido finding signs the stealer ran in over 1,800 repositories and SafeDep counting 8,093 public repositories that received malicious commits, a figure that does not necessarily mean successful execution.

The attacker does not exploit a GitHub Actions vulnerability. Instead, valid tokens are used to plant malware in existing or new GitHub Actions workflows, CI shell scripts, and npm installation hooks, the last of which also endangers developers who install dependencies while the malicious changes are present. The payload hunts GitHub tokens, repository secrets, cloud credentials, and AI service keys, and reads GitHub Actions runner process memory. Radware's separate look at the same campaign adds command injection and attempts to exfiltrate CI/CD data, with evidence of execution in affected repositories.

The full scope is still being investigated, and even legitimate GitHub projects become dangerous when a contributor account is compromised, since attackers can steal credentials without requiring end users to download or execute malware. Defenders should treat any repository that received an unexpected pull request or workflow change around November 10 as potentially compromised and rotate exposed secrets.
