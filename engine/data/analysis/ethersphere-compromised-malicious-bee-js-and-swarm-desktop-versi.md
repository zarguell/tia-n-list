Ethersphere's own release automation was abused to publish malicious @ethersphere/bee-js 13.3.0 to npm and Swarm Desktop 0.56.2 to GitHub, both of which steal Swarm wallet keys and install a persistent backdoor. The bee-js release was cut from unsigned commit de2f74e by the bee-worker bot at 23:59:54 UTC on 2026-11-08 and published to npm at 00:09:50 UTC on 2026-11-09 with a valid provenance attestation, while Swarm Desktop 0.56.2 followed at 00:36 UTC as an "emergency patch release." The postinstall loader in bee-js and the equivalent hook in Swarm Desktop fetch a second stage from api.frameworkmetrics.xyz that exfiltrates config.yaml and data-dir/keys/swarm.key, where Swarm Desktop stores its keystore password in plain text.

The decisive point is that valid provenance did not mean trustworthy source: the malicious code never touched a protected branch, it went to npm through a GitHub release, and branch protection never fired because no branch was used. Anyone who can create a release in that repository could publish to npm with provenance, which turns the signature into a false comfort rather than a control. The exposure window was short on npm, where 13.3.0 lived from 00:09:50 to 01:24:58 UTC, but Swarm Desktop 0.56.2 remained the current GitHub release until 06:58 UTC and its Windows auto-updater recorded 17 downloads, so desktop users were at risk far longer than npm consumers. GitHub advisory GHSA-hh7j-5m3j-23pf treats any machine that installed or ran the affected versions as fully compromised, and downstream projects such as create-swarm-app had already bumped to 13.3.0, so the blast radius extends past direct users. This is the story to read today because the failure is in the publishing identity and workflow, not in the application code, which means dependency pinning and signature checks alone would not have stopped it.

Defenders should pin @ethersphere/bee-js to 13.2.0, remove any cached 13.3.0 tarballs from registries and CI, and rotate every wallet key, secret, and credential that touched an affected machine from a clean system. Hunt npm lockfiles, package caches, and build logs for @ethersphere/bee-js 13.3.0, and on Swarm Desktop hosts inspect config.yaml and data-dir/keys/swarm.key access plus the ~/.solidity directory, the solidity-langsupport-runner.service systemd unit, the com.solidity.langsupport.runner LaunchAgent, and the ScreenConnect client service on Windows. Block api.frameworkmetrics.xyz and its /v1/analytics, /v1/electron, and /v1/swarm/report endpoints, and remove the backdoor artifacts rather than merely uninstalling the packages, since the advisory warns that full control may persist after removal. Swarm Desktop should be moved to 0.56.3, which maintainers describe as the same code as 0.56.1.

What would change this assessment is whether Ethersphere's follow-up hardens the pipeline, since maintainers have already said signing jobs now wait for DevOps approval and run only from the main branch, and whether any other packages in the ecosystem were published through the same compromised bee-worker identity. Also watch for on-chain movement from wallets whose swarm.key and config.yaml were exfiltrated, because the operator's Ethereum contract has been active since 2026-03-14 and the current command-and-control hub at 193.57.9.155:4912 was set less than half an hour before the malicious commit.
