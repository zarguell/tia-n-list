SCKit is a self-propagating malware toolkit that Microsoft Threat Intelligence observed being deployed through legitimate ConnectWise ScreenConnect remote-support infrastructure against managed service providers and their customers. ConnectWise reported an active campaign on November 11, 2026 against cloud-hosted ScreenConnect instances belonging to MSPs, and Microsoft confirmed that activity while adding its own analysis of the worm. The intrusion starts with commands issued through ScreenConnect that silently install an identical client pointed at attacker-controlled infrastructure. A batch launcher then pulls a PowerShell decoder that decrypts and extracts SCKit using device-specific key material, persistence is established with scheduled tasks and registry Run entries, and RelayTrap, a malicious replacement for the ScreenConnect client, is positioned to deliver a payload to a connecting technician.

The targeting is what separates this from ordinary remote-access abuse. The worm uses the hijacked authenticated ScreenConnect session to go after IT support technician workstations, then uses the victim's own management console to push payloads to the downstream devices that technician administers. That converts a single compromised support seat into distribution across every customer endpoint behind it, and it means removing the unauthorized client from one machine neither clears the toolkit's persistence nor invalidates the exposed web sessions. On the server side, ConnectWise is investigating an authentication flaw in the RMM+ extension, versions 1.0.31 and 1.0.32, which accepted an empty access key when no key was configured, letting an unauthorized caller submit commands to the server API for delivery to managed endpoints without a normal ScreenConnect sign-in. Microsoft says the entry method for the reported campaign is still under investigation.

Defenders should treat technician workstations and every endpoint reachable from them as in scope, rotate ScreenConnect session and access credentials rather than just deleting the rogue client, audit RMM+ extension versions and access-key configuration, and hunt for RelayTrap and the scheduled-task and Run-key persistence Microsoft documented. The structural risk is that MSP tooling is trusted by design: a worm that rides an authenticated support session inherits that trust and reaches customers faster than any per-host compromise. Watch for ConnectWise publishing the CVE and fixed RMM+ versions, for confirmation of whether the empty-key flaw was the actual entry vector, and for the first reports of SCKit appearing at MSPs that were not part of the initial campaign.
