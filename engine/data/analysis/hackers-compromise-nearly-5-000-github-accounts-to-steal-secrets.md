Starting around 12:45 UTC on November 10, an actor using stolen GitHub credentials pushed a credential stealer that Aikido Security tracks as wfx-loot. The mechanism is a probe then payload: each compromised account opens a pull request titled "docs: dependency audit notes" from a branch named wfx-docs to prove write access, then delivers a roughly 1,500 line shell script by one of three routes, injecting it into an existing workflow under a "ci: refresh build cache" commit, adding a .ci helper script plus a package.json postinstall hook, or committing a throwaway build-audit workflow on a short-lived chore branch. The account count is 4,837; the probe reached 61,764 repositories; the payload is confirmed to have run and exfiltrated in at least 1,806 of them.

The reason this campaign outranks the October GhostAction wave it overlaps with is not the probe count, it is that the payload was built to survive the remediation everyone reaches for first. It mints GitHub OIDC tokens for AWS, GCP and Azure audiences and exchanges them for cloud sessions, calls iam:CreateAccessKey to create long-lived AWS credentials, and adds Azure federated identity credentials named wfx-ci-* that keep working after every token is rotated. It also posts forged success status checks using the repository's own required context names, so branch protection matches the context string rather than the posting app and merges proceed while the payload is still running. Rotating a leaked token does not evict this actor. The other number that matters is 10,431 of those pull requests landed in repositories the compromised account does not own, reached through collaborator or organization access, which means the exposed set is every project that granted a stolen personal account write access, not just the 4,837 account holders. Roughly 92 percent of the probe pull requests were still open at disclosure, so most repository owners have not looked yet, and the run logs were deleted in impacted repositories, leaving a missing run number as the more reliable trace than any log entry.

Treat every secret and cloud role available to the affected workflows as compromised, not only the ones named in the payload. Hunt for wfx-docs and chore/[a-z0-9]{8} branches, the three commit subjects above, pull requests titled "docs: dependency audit notes", and gaps in Actions run numbering on the attacker commit. In cloud control planes, look for AWS AssumeRoleWithWebIdentity or AssumeRole sessions from the impacted roles, IAM access keys created after November 10, trust policies rewritten to a wildcard AWS principal, and Entra ID federated credentials named wfx-ci-*. Network telemetry should carry POSTs to 194.150.166.244:8080 or 18.143.168.96:8080 on the /exfil path. Because the stealer also shipped through automated publishing triggers, pull Packagist digitalelvis/neuronai-studio 3.14.3 and Go module github.com/onuragtas/docker-env at v1.0.278 and v1.0.280, and assume compromise on any machine that installed them.

Two developments would change this assessment. The first is evidence that the actor has spent the stolen cloud sessions rather than banking them, since the long-lived AWS access keys and the wfx-ci-* federated credentials convert a secret theft into an active intrusion. The second is a wider package footprint: 50 compromised users publish across npm, Go, Packagist, PyPI and crates, and only a handful of malicious releases have been identified so far. The payload also carries disabled configuration for private repository exfiltration through the Actions Cache API, step summaries and artifacts, so a second run with those flags on would remove the public probe trail that currently makes this campaign visible.
