Attackers used stolen GitHub credentials from 4,837 accounts to probe 61,764 repositories in a supply-chain campaign aimed at software-development secrets and cloud access. Beginning November 10, the operation injected malicious GitHub Actions workflows into accessible repositories, with evidence of credential exfiltration from at least 1,806 repositories. At least 50 of the compromised users publish packages across npm, Go, and Packagist, widening the blast radius into downstream package ecosystems. Coverage ties this to a broader set of related reports, including a WFX campaign abusing GitHub Actions for cloud backdoors and an 8,000-repository push that planted a credential stealer and reverted the malicious commits afterward.

The injected payload steals repository secrets, scans GitHub runner memory for API keys, and requests OIDC tokens for AWS, Azure, and GCP. It also plants backdoors designed to survive secret rotation, which means simply rotating a leaked token may not evict the actor if the persistence mechanism remains. The campaign's use of stolen tokens against a large account pool, then reverting commits to reduce visibility, is the pattern defenders should expect from automated CI/CD credential theft at scale.

Because 50 of the victims are package publishers, treat this as a potential upstream poisoning event for npm, Go, and Packagist consumers, not just a GitHub problem. Audit Actions workflows and recent commits for unexpected changes or reverted pushes, review OIDC trust policies for AWS, Azure, and GCP roles that could have issued attacker tokens, and rotate credentials while also hunting for planted backdoors that outlive rotation. Watch for malicious package releases pushed through the compromised publisher accounts.
