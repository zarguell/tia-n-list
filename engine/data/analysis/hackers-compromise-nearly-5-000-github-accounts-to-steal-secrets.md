The wfx-loot campaign, tracked by Aikido Security, used stolen credentials for roughly 4,837 GitHub accounts to probe 61,764 repositories for write access beginning around 12:45 UTC on 10 November 2026. The actor opened pull requests titled "docs: dependency audit notes" to test permissions, with 92 percent of those PRs still open days later, then modified an existing GitHub Actions workflow to deliver a roughly 1,500-line credential-stealing shell script. The payload runs in CI runners, dumps repository secrets, scans runner memory for API keys, requests OIDC tokens for AWS, Azure, and GCP, and plants backdoors that survive secret rotation. Aikido confirms collection from at least 1,806 repositories.

The reach is broad because roughly 50 of the compromised accounts hold publishing rights across npm, PyPI, Go, crates, and Packagist, and some belonged to Fortune 100 organizations, the US General Services Administration, the French government, Nextcloud, and WebdriverIO. This November wave escalates the earlier GhostAction activity GitGuardian and Socket tracked in October, when 500-plus accounts pushed a fake security-audit workflow into tens of thousands of repositories. Aikido ties the campaigns through account overlap and shared GhostAction indicators, and lists hunter checks: PRs titled "docs: dependency audit notes," branches named wfx-docs or chore/, commits like "ci: refresh build cache" or "chore: add ci helper," and skipped or missing run numbers in the Actions tab.

Because the malware targets CI/CD secrets and cloud OIDC credentials rather than source code, the blast radius is every downstream system those tokens can reach, and the planted backdoors mean rotating a single leaked secret is not enough. Watch package registries for malicious releases pushed by the roughly 50 publishing-capable accounts, audit Actions run history for the indicator branches and commit messages, and revoke OIDC trust relationships and cloud keys exposed in affected runners.
