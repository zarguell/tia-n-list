CISA added four CVEs to its Known Exploited Vulnerabilities catalog on November 9, 2026, each backed by exploitation evidence and each already patched by its vendor before the listing. The batch spans four unrelated products: GPUStack CVE-2026-102895, an authentication bypass through a trusted loopback source or a forged X-GPUStack-Real-IP header giving unauthenticated admin access on GPU worker nodes, fixed in 2.2.0 after exploitation against a 2.1.1 deployment; SignalWire FreeSWITCH CVE-2026-116779, a SIP MESSAGE command injection rated CVSS 9.8 fixed in 1.11.3 under advisory GHSA-mg63-h38w-8p9p dated October 28, 2026; OpenSSH CVE-2026-123158, the sshole password authentication bypass on musl-based Alpine systems with PAM disabled, fixed in 10.6p2 on November 5; and IBM Aspera Faspex CVE-2026-123218, incorrect authorization in 5.0.0 through 5.0.19 rated CVSS 9.8 and fixed in 5.0.19 PL1. All four are known exploited.

A successful hit on any of these hands an attacker a foothold on a distinct class of infrastructure: AI GPU worker nodes for GPUStack, call-center and telephony media servers for FreeSWITCH, remote shell access through sshd on Alpine, and file-transfer administration for Aspera Faspex. Because the four bugs span unrelated product lines, no single patch or configuration change covers the batch, and a defender running more than one of these products must track four separate vendor advisory and update cycles in the same window. The event list records four CVEs and one source, but it does not state that the exposure is multiplicative: an organization using both FreeSWITCH and Aspera Faspex faces two independent remote exploitation paths different vectors, SIP media port traffic versus an authorized crafted message, within a single patch cycle, which is why this KEV batch warrants attention over the other thirty stories today.

Patch immediately: GPUStack to 2.2.0, FreeSWITCH to 1.11.3, OpenSSH to 10.6p2, and Aspera Faspex to 5.0.19 PL1. Where a patch cannot be applied yet, FreeSWITCH operators should leave enable-chat-api-proto off and restrict untrusted SIP traffic to the media port, while Aspera operators should review authorized accounts able to craft the affected message. Hunt for FreeSWITCH logs returning 403 to MESSAGE requests selecting the API protocol, GPUStack admin API calls presenting an X-GPUStack-Real-IP header from a non-loopback peer, and sshd authentication attempts carrying passwords between 257 and 1024 bytes against passwordless accounts on musl-based hosts with PAM disabled.

Watch for confirmed exploitation campaigns tied to each CVE beyond the single 2.1.1 GPUStack deployment already reported, and for federal agency patch status reports tied to the November 9 KEV batch since the CISA listing binds agencies to CISA's patch timeline. A second vendor confirming in-the-wild exploitation for OpenSSH or Aspera, or any public exploit code, would change the assessment.
