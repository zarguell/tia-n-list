On November 9, CISA added four vulnerabilities to its Known Exploited Vulnerabilities catalog based on evidence of active exploitation: GPUStack CVE-2026-102895, FreeSWITCH CVE-2026-116779, OpenSSH CVE-2026-123158 (nicknamed sshole), and IBM Aspera Faspex CVE-2026-123218. Each carries a CVSS score of 9.8 except the OpenSSH flaw, which is rated for its authentication-bypass impact on musl-based systems with PAM disabled. The additions mean federal agencies must remediate these flaws on fixed timelines, and they signal that exploit code is already in circulation.

GPUStack versions before 2.2.0 are vulnerable to an authentication bypass through a trusted loopback source or a forged X-GPUStack-Real-IP header, granting unauthenticated administrative access on GPU worker nodes; the vendor reported exploitation in the wild against a 2.1.1 deployment, fixed in 2.2.0. FreeSWITCH through 1.11.2 has a critical command injection (GHSA-mg63-h38w-8p9p) where an inbound SIP MESSAGE can select the API chat protocol and run FreeSWITCH API and OS commands, fixed in 1.11.3. OpenSSH on musl-based systems with PAM disabled lets an attacker authenticate to a passwordless account using any password between 257 and 1024 bytes, fixed in OpenSSH 10.6p2. IBM Aspera Faspex 5.0.0 through 5.0.19 has an incorrect authorization flaw letting an authorized user craft a message to gain full administrative privileges, fixed in 5.0.19 PL1.

What to watch is patching velocity across the affected stacks, particularly GPUStack and FreeSWITCH deployments exposed to untrusted networks, and whether the sshole flaw propagates into broader OpenSSH exploitation on musl-based distributions. Operators should prioritize the KEV-listed fixes, verify versions, and remove unnecessary exposure of SIP, SSH, and GPUStack management endpoints.
