Red Hat disclosed CVE-2026-18963, a critical vulnerability (CVSS 9.1) in the Red Hat Build of Keycloak that allows unauthenticated remote attackers to take over arbitrary user accounts by bypassing the password reset process. The flaw affects the keycloak-services component, the core engine behind authentication and identity functions. An attacker can trigger the reset-credentials flow for a chosen account and set a new password without completing the required email verification step, granting account control without credentials, prior access, or user interaction.

The vulnerability is rooted in improper state validation in Keycloak's reset-credentials authentication flow. Password recovery mechanisms normally rely on a time-limited, single-use verification link sent to the registered email address. In vulnerable deployments, this validation can be skipped entirely. Red Hat classified the issue as CWE-640 (Weak Password Recovery Mechanism for Forgotten Password).

Any organization running Red Hat Build of Keycloak should apply patches immediately. The flaw requires no authentication and no user interaction, making it trivially exploitable at scale. Verify that password reset flows are enforced with proper email verification and that Keycloak deployments are updated to the patched version.
