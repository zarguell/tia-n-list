The vulnerability is CVE-2026-64849, an unauthenticated full-read SSRF in MLflow webhook delivery that bypasses `_validate_webhook_url` via unvalidated HTTP redirects and DNS rebinding. The affected product is MLflow prior to 3.15.0, and the fix shipped in release v3.15.0 on GitHub. CISA added the CVE to the Known Exploited Vulnerabilities database on August 19, 2026, confirming active exploitation. A separate Zero Day Initiative advisory (ZDI-26-847) describes a related security flaw that could allow unauthorized access to sensitive internal data.

Because the webhook validation can be bypassed without authentication, any attacker who can trigger a webhook delivery gains full-read SSRF against internal targets. The CISA KEV entry and the Canadian Centre advisory (AV26-832) both apply government-level urgency, meaning exposure extends beyond development servers to production MLflow instances in critical infrastructure. The score of 7.7 and the KEV flag place this above routine patch-Tuesday noise, especially since exploitation telemetry is already confirmed rather than theoretical.

Patch to MLflow 3.15.0 immediately; the GitHub release closes the redirect and rebinding path in `_validate_webhook_url`. Until patching is complete, restrict webhook delivery network paths, audit webhook URL configurations, and hunt for unexpected redirect chains or DNS resolution logs tied to webhook delivery. Monitor for references to ZDI-26-847 and CVE-2026-64849 in incident telemetry, since both identifiers appear in separate disclosure tracks for the same product.

Watch for expanded exploitation scope beyond the initial CISA KEV scope and for additional CVEs tied to the same MLflow release cycle, since the advisory frames a broader vulnerability set rather than a single issue. Any new vendor advisory from Zero Day Initiative or an updated CISA KEV entry would change the assessment from contained to widespread.
