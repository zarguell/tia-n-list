GitHub Security Lab researcher Kevin Stubbings used the lab's open-source Taskflow Agent to find 24 vulnerabilities in Android applications, including covert location tracking in OsmAnd, a navigation app with more than 10 million installs, and account takeover flaws affecting Wikipedia's Android users. The findings were disclosed through the lab's normal coordinated process.

The method is the story here as much as the bug count. Rather than generic prompting, the Android taskflows steer the model through structured stages: separating mobile entry points from web and desktop components in mixed repositories, then reviewing exported activities, intents, deep links, confused-deputy conditions, insecure broadcasts, WebView issues, and JavaScript bridges. That structure lets the model connect components and reason about exploitable data flows instead of flagging superficially insecure code. GitHub itself cautions that a human researcher validated every one of the 24 results before disclosure.

This is a concrete data point that AI-driven discovery now reaches mobile logic vulnerabilities, the class that resists fuzzing and requires cross-component reasoning. It also shows the workflow packaging matters: the same model with unstructured prompts would not have produced this yield. Expect more vulnerability disclosure volume in mobile apps as these taskflows propagate.

Watch for the individual CVE assignments and patch releases for the 24 findings, whether OsmAnd and Wikipedia-class apps change their exposure of exported components, and how quickly attacker tooling borrows the same taskflow structure for bug hunting at scale.
