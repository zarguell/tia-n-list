Refitter 2.1.2 fixes a code injection flaw in generated API clients. According to the secquill write-ups in this story, a crafted or tampered OpenAPI description, including hostile header names, can slip code into generated clients that runs when the application starts. Three Mastodon posts from the same outlet describe the fix in slightly different wording; all point to the same 2.1.2 release and the same startup code-injection mechanism.

The practical risk sits in the build pipeline: a specification fetched or edited outside normal review becomes input to code generation, and the injected code executes before the application reaches its own controls. Watch for a CVE record and vendor advisory on the affected versions, for confirmation of which generators and languages are exposed, and for downstream projects pinning 2.1.2. No exploitation, victim count or exploit code appears in the event content, so treat this as a patch item rather than an incident.
