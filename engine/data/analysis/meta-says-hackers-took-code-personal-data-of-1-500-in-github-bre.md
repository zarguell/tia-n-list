Hackers accessed some of Meta's GitHub repositories using an employee's stolen credentials. The intrusion was detected a few weeks before notifications began going out on Tuesday to roughly 1,500 people, most of them US employees. Meta's security team cut off the attackers' access and brought in GitHub and law enforcement.

Of the data taken, Meta says 99 percent was business data, mostly software code related to some of its products. The remaining 1 percent was personal data that had been added to the repositories by mistake, against company policy. Meta has not said what types of personal information were involved, and notes that a significant portion of what looked like personal data was actually synthetic or anonymized test data, so the attackers may struggle to separate genuine records from test data. Meta does not believe the hackers were specifically after its data.

The story is less about the breach volume than the failure mode: personal data sitting in code repositories where it should never have been, reachable with one set of stolen credentials. Meta is notifying regulators and offering affected people credit and dark web monitoring. Watch for regulator findings on the misfiled personal data, and for whether the stolen code surfaces anywhere, since code leaks can expose internal logic and secrets long after the incident fades.
