Meta notified roughly 1,500 individuals, mostly U.S. employees, that personal data was impacted after attackers accessed some of Meta's GitHub repositories using a stolen employee credential. Meta's security team shut down the access and involved GitHub and law enforcement. The company stated that 99% of the taken data was software code, while 1% was personal data that had been added to repositories by mistake, violating company policy. A significant portion of the personal data appears to be synthetic or anonymized test data, making it harder for attackers to distinguish real records. Meta began notifications on October 13, 2026.

The incident highlights the persistent risk of hardcoded credentials and accidental data storage in source repositories. Even synthetic data in repositories can mislead attackers into overestimating breach impact. Organizations should enforce pre-commit scanning for secrets and personal data, rotate any credentials associated with the repositories, and audit repository access logs for unauthorized clone or download activity.
