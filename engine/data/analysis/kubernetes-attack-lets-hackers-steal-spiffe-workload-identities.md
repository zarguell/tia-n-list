Palo Alto Networks Unit 42 demonstrated a post-exploitation technique that lets attackers with root-level access to a Kubernetes node steal workload identities issued through SPIFFE/SPIRE and impersonate legitimate applications on the same host. The research targets the attestation step where a SPIRE agent verifies a workload's identity before issuing a SPIFFE Verifiable Identity Document (SVID). SVIDs can take the form of X.509 certificates for mutual TLS or JSON Web Tokens for application authorization.

The attack manipulates Linux control group, or cgroup, information that SPIRE relies on during workload attestation. An attacker with root access can modify cgroup data to trick the local SPIRE agent into issuing SVIDs belonging to other workloads running on the compromised node. Because SPIRE agents make trust decisions based on what the kernel reports about a process's cgroup membership, and root access allows arbitrary modification of that state, the identity boundary effectively collapses once node-level compromise occurs.

Unit 42 said it has not observed this technique exploited in real-world attacks. However, the findings have significant implications for environments using SPIFFE/SPIRE to replace long-lived credentials with short-lived cryptographic identity. The attack undermines the fundamental assumption that workload identities are protected by node-level isolation. Organizations relying on mutual TLS and identity-based authorization in Kubernetes should evaluate whether their SPIRE deployments are vulnerable to cgroup manipulation and consider additional attestation layers beyond node trust.
