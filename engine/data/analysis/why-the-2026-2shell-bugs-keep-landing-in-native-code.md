Five memory-safety bugs disclosed over about a month share a common shape: attacker-reachable code sits in C, C++ or hand-written assembly underneath a memory-safe language. The set covers PHP2Shell CVE-2026-109618 and CVE-2026-109619, Brotli2Shell CVE-2026-111497, Java4Shell CVE-2026-114938, nginx2root CVE-2026-123007 and Ruby2Shell CVE-2026-132825. Fixed builds are PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35, Brotli 1.0.10, 1.1.1 and 1.2.1, OpenJDK 17.0.21.1 and siblings, NGINX 1.31.9 and 1.30.7, and Ruby 3.3.14, 3.4.13 and 4.0.10.

The PHP bugs have the clearest exploitation record. GreyNoise logged the first successful use at 05:14:01 UTC on October 28, and Andrew Thompson said roughly fifty server configurations need tailored exploits. Unit 42 counted over 22.6 million potentially vulnerable instances and later saw attacks against internet-facing PAN-OS management interfaces, where about 0.02 percent of the installed base was exposed. Hunt.io found 616 PHP2Shell files in one open directory, including exploit kits, scanners and post-exploitation tooling, and a host at 130.94.67[.]235 serving a repackaged PAN-OS proof of concept.

Ruby2Shell is a one-byte heap overflow in case conversion for 14 single-byte encodings. The loop reserves one byte but writes two when upcasing the German sharp s. A multipart _method field tagged ISO-8859-1 reaches String#upcase inside Rack::MethodOverride before application code runs, and AddressSanitizer confirmed the write on Ruby 3.4.12; Censys counted about 3.8 million affected web properties. Java4Shell writes 62 bytes past a Base64 output buffer on CPUs with AVX-512 VBMI.

Brotli2Shell reaches more than Node.js: Harry Sintonen reported that git-remote-https is affected when libcurl is built with Brotli support, and older CURLOPT_ENCODING callers need the same review. The practical watch item is the native layer under each managed runtime, including bundled libraries in containers and appliances, rather than only the top-level language version.
