Five memory-safety bugs landed in foundational software inside about a month: PHP2Shell (CVE-2026-109618 and CVE-2026-109619), Brotli2Shell (CVE-2026-111497), Java4Shell (CVE-2026-114938), nginx2root (CVE-2026-123007) and Ruby2Shell (CVE-2026-132825). All sit in C, C++ or hand-written assembly underneath languages that are usually called memory safe. PHP2Shell is pre-auth on default configs; Unit 42 counted over 22.6 million potentially vulnerable instances and GreyNoise logged first successful exploitation at 05:14:01 UTC on 28 October. Hunt.io later found 616 PHP2Shell-related files in an open directory, including exploit kits and a repackaged PAN-OS chain hosted at 130.94.67[.]235.

The patch paths are specific. Brotli fixed CVE-2026-111497 in 1.0.10, 1.1.1 and 1.2.1, and Harry Sintonen showed git-remote-https is exposed when libcurl is built with Brotli. Java4Shell is a 62-byte out-of-bounds write in HotSpot's x86-64 Base64 intrinsic on AVX-512 VBMI CPUs, fixed in 17.0.21.1 and siblings; disabling Base64 intrinsics or capping AVX at level two was the temporary workaround. nginx2root CVE-2026-123007 is an HTTP/2 integer underflow fixed in 1.31.9 and 1.30.7. Ruby's 18 November advisory shipped seven fixes in 3.3.14, 3.4.13 and 4.0.10.

Ruby2Shell is a one-byte heap write in case_map for 14 single-byte encodings: upcasing the German sharp s writes two bytes where the buffer check reserved one. Veria Labs describes default Rails and classic Sinatra as reachable without authentication, and the concrete pre-auth path uses a multipart _method field tagged ISO-8859-1 through Rack::MethodOverride before application code runs. GitLab patched CVE-2026-132825 in 19.6.1. Watch for downstream patches in bundled runtimes and for exploit tuning per configuration, since GreyNoise found the same PHP exploit did not work across roughly fifty differently configured servers.
