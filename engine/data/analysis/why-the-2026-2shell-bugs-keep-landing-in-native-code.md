Five named memory-safety bugs landed in foundational software within about a month: PHP2Shell CVE-2026-109618 and CVE-2026-109619, Brotli2Shell CVE-2026-111497, Java4Shell CVE-2026-114938, nginx2root CVE-2026-123007 and Ruby2Shell CVE-2026-132825. Four are normally reached through a memory-safe language or framework, but all five sit in C, C++ or hand-written assembly. Fixed builds span PHP 8.5.12/8.4.27/8.3.36/8.2.35, Brotli 1.0.10/1.1.1/1.2.1, OpenJDK 17.0.21.1 and siblings, nginx 1.31.9/1.30.7 and Ruby 3.3.14/3.4.13/4.0.10.

Exposure data shows why the native boundary matters. GreyNoise recorded the first successful PHP2Shell exploitation at 05:14:01 UTC on 28 October and noted that roughly fifty server configurations need different exploit handling. Unit 42 counted over 22.6 million potentially vulnerable instances and later saw exploitation against PAN-OS management interfaces, where about 0.02 percent of the installed base exposed those interfaces. Hunt.io found 616 PHP2Shell files in one open directory, including exploit kits, scanners and post-exploitation tooling. Brotli2Shell reaches beyond Node.js: Harry Sintonen reported that git-remote-https is affected when libcurl is built with Brotli support.

Ruby2Shell is a one-byte heap overflow in case conversion for 14 single-byte encodings. The loop reserves one byte of room for each character but writes two for the German sharp s when upcasing. A multipart _method field tagged ISO-8859-1 reaches String#upcase inside Rack::MethodOverride before application code runs, and AddressSanitizer confirmed the write on Ruby 3.4.12. Censys reports about 3.8 million web properties running affected Ruby builds. Java4Shell writes 62 bytes past a Base64 output buffer on CPUs with AVX-512 VBMI. Watch bundled runtimes and native dependencies rather than only patched top-level languages.
