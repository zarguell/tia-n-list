Five named memory-safety bugs landed in foundational software in about a month: PHP2Shell CVE-2026-109618 and CVE-2026-109619, Brotli2Shell CVE-2026-111497, Java4Shell CVE-2026-114938, nginx2root CVE-2026-123007 and Ruby2Shell CVE-2026-132825. Four are usually reached through a memory-safe language or framework, but all five sit in C, C++ or hand-written assembly. The fixes span PHP 8.5.12/8.4.27/8.3.36/8.2.35, Brotli 1.0.10/1.1.1/1.2.1, OpenJDK 17.0.21.1 and siblings, nginx 1.31.9/1.30.7 and Ruby 3.3.14/3.4.13/4.0.10.

The newest entry is the Ruby bug. CVE-2026-132825 is a one-byte heap overflow in case_map: upcasing the ISO-8859-1 sharp s expands one byte into two while the loop checks for one byte of room. The Ruby advisory cites proof-of-concept code showing code execution in some scenarios. Researchers found a pre-authentication path through a multipart _method field tagged ISO-8859-1 into String#upcase inside Rack::MethodOverride, and ASan confirmed the write on Ruby 3.4.12. Ruby's 19 November update fixed seven string and regexp issues in total.

Several of these bugs are already operational. GreyNoise observed the first successful PHP2Shell exploitation at 05:14:01 UTC on 28 October. Unit 42 counted more than 22.6 million potentially vulnerable instances and saw exploitation against internet-facing PAN-OS management interfaces, while Hunt.io found 616 PHP2Shell files in an open directory and 130.94.67[.]235 serving a repackaged proof of concept. Java4Shell probes had reached more than 150 shaped requests from five IPs by early 19 November. Watch for pre-auth HTTP paths that reach native decoders, vendor bundles and container images that still carry old runtimes, and chains that pair one of these bugs with a privilege-escalation flaw.
