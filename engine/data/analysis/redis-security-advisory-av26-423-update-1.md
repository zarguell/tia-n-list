The Redis RESTORE command vulnerability CVE-2026-25243 allows an authenticated attacker to trigger invalid memory access and achieve remote code execution on affected Redis instances. The advisory AV26-423 (updated October 19, 2026) covers this alongside CVE-2026-23479, CVE-2026-25588, CVE-2026-25589, and CVE-2026-23631, with CVSS scores up to 7.7 for the RESTORE flaw. Open-source telemetry from Defused honeypots recorded exploitation attempts on October 16-17, 2026, confirming active in-the-wild use ahead of the update. The fixed version is Redis 8.6.3, and administrators running earlier releases remain exposed.

This story matters because Redis is commonly deployed as a session store and message broker in production stacks, which means a single unpatched instance can become a pivot point for broader compromise. The Canadian Cyber Centre advisory notes multiple affected versions across Redis Software and OSS/CE releases, and the exploitation evidence is concrete rather than speculative. Unlike generic RCE reports that lack confirmation, this case pairs a vendor advisory with observed honeypot hits, making the threat credible and immediate.

Defenders should upgrade to Redis 8.6.3 immediately, or block the RESTORE command at the network or configuration layer for instances that cannot patch quickly. Hunt for unexpected RESTORE calls in Redis logs and review access patterns from untrusted sources; telemetry fields mentioned include honeypot-caught attacker payloads targeting the RESTORE path. Confirm version levels across all clusters, restrict RESTORE to trusted clients, and treat any unpatched server as actively targeted.

Watch for additional vendor updates that expand the affected version matrix, and for any shift from targeted exploitation to broader scanning. If new CVEs are added to AV26-423 or if the RESTORE workaround proves insufficient, the assessment should be revised upward.
