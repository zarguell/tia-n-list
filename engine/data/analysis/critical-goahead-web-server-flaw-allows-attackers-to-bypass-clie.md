FoxIO disclosed three TLS issues in the GoAhead embedded web server, with CVE-2026-115881 the most serious. The CVSS 9.1 flaw affects GoAhead 3.4.5 through 6.1.0 when built with OpenSSL or a compatible library and configured for mutual TLS with a certificate revocation list. GoAhead loads the CRL but does not enable the OpenSSL flag that enforces it, so a revoked client certificate can still authenticate. GoAhead 6.1.1 fixes the issue.

The exposure is configuration-specific rather than universal. FoxIO said GoAhead is embedded in networking equipment, printers and industrial systems, but risk depends on the TLS backend and certificate-check settings. A stolen or compromised device certificate that an administrator has revoked may therefore retain access without an obvious startup warning. The other disclosed issues include weakened TLS 1.2 encryption on Mbed TLS builds in GoAhead 4.0.2 through 6.1.0 and a certificate-chain length limit problem.

Device owners should inventory GoAhead versions and TLS backends, identify mTLS deployments using CRLs and move to fixed firmware or 6.1.1 where supported. Because the server accepts the revoked certificate, exploitation may not produce a distinctive authentication failure. Watch for vendor advisories from appliance manufacturers and telemetry showing access by certificates that should have been blocked.
