CVE-2026-115881 is a critical vulnerability (CVSS 9.1) in the GoAhead embedded web server affecting versions 3.4.5 through 6.1.0 when built with an OpenSSL-compatible TLS backend and configured for mutual TLS with a certificate revocation list (CRL). GoAhead loads the CRL but fails to activate the OpenSSL flag required to enforce it, so revoked client certificates remain valid. The fix is GoAhead 6.1.1. A second bug (no CVE, CVSS 5.9) in GoAhead 4.0.2 through 6.1.0 built with Mbed TLS weakens TLS 1.2 encryption, and a third affects certificate chain length limits. The critical flaw requires a specific mutual TLS configuration, so not every GoAhead installation is affected; however, GoAhead is embedded in routers, printers, gateways, industrial controllers, and network-connected products across hundreds of millions of devices.

Why it matters is that embedded firmware updates lag upstream releases by months or years. The event content (rss:41a1bdcb9f8cc8ef) notes that exploitation requires a revoked certificate combined with active mutual TLS, which limits immediate exposure but makes detection hard because a revoked identity completes authentication without obvious failure. Security teams must combine software inventory, TLS backend identification, certificate telemetry, and monitoring of mutual TLS authentication to detect misuse.

What to watch: vendor firmware release timelines for affected network appliances, and whether any in-the-wild exploitation of revoked-certificate access is reported. There is no CISA KEV entry or confirmed exploitation event in the content; the risk is structural and long-tail rather than actively exploited at scale.
