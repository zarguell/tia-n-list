Google expanded access to Gemini 4 Carbon on November 10, 2026, moving the model from a Fairwind-program-only release to paying developers and businesses via the Gemini API and Gemini for business, plus Google AI Ultra subscribers, at $2/$10 per million input/output tokens through November 30 before prices double to $4/$20. The same day Google DeepMind published AlphaProof Code, an agentic formal-verification framework that used Carbon to generate over six million lines of Lean proof and verify key security properties of compiled libsignal code in four weeks, work that historically takes expert teams years. Google also disclosed that its Cloud Vulnerability Research team used Carbon to confirm two bugs in a popular open-source project were exploitable at severity comparable to PHP2Shell, and that Wiz found zero-days at two major SaaS providers in under two hours using Carbon for cyber.

The practical effect is that a model able to find and weaponize vulnerabilities is now reachable by any paying developer, while the only variant Google still gates is Carbon for cyber behind Fairwind membership; the Signal verification win does not make the model safer to distribute, it demonstrates the same capability turned inward. Exposure is broad: Carbon tops SEC-bench Pro at 88.2%, ExploitGym at 54.8%, and CWE-bench at 71.0%, and the PHP2Shell-class bugs it helped confirm were already being exploited in the wild, with GreyNoise observing at least six successful exploitations of CVE-2026-109618 and CVE-2026-109619. This story matters more than routine model-release coverage because it couples a capability jump with a named cryptographic verification and a documented path from model output to a critical patch, rather than a benchmark slide.

Defenders should treat November 30 as the cost cliff and plan usage accordingly; more important, patch the two CVR bugs once their responsible-disclosure window closes, since Carbon-built proof-of-concept code exists and severity is comparable to PHP2Shell. For Signal users, no action is required, but operators should track libsignal updates and confirm they run builds derived from the verified code. Hunt for the PHP2Shell-class exploitation already in progress: review web server and PHP error logs for unexpected process spawning from php-fpm or apache2, watch for XMRig miners and Cobalt Strike beacons, and monitor for the indicators GreyNoise tagged as php2shell tooling. Network restrictions should follow the standard playbook: keep PHP endpoints off the public internet where possible, require authentication on management paths, and alert on outbound connections from web server processes.

Watch whether the CVR bugs' disclosure names the affected project and whether exploit code leaks before patches land, which would convert a controlled finding into an active threat. Also watch for independent replication of the Signal verification claims and for whether other vendors adopt formal verification pipelines; if Carbon for cyber's Fairwind gate loosens, the dual-use balance shifts further.
