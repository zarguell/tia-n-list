CameraSwarm is not a single clean build but a 35-day operation between June 17 and July 22, 2026 that compromised 14,530 Dahua IP cameras through three parallel paths. The brute-force engine scanned TCP port 37777 and reached 12,324 unique IP addresses, capturing snapshots and sending results to Telegram. A second path chained CVE-2021-33044 and CVE-2021-33045 through the compiled tool p2pwn to install a persistent backdoor account (p2pwn / p2password) on 1,923 cameras; the account is stored independently of the admin password and survives both password changes and, on most firmware versions, factory resets. A third path abused Dahua's cloud P2P relay by serial number to reach 283 cameras behind NAT, with the operator's own logs showing 89.4 percent of live serials returned an open channel requiring no authentication at all. Hunt.io recovered the operator's entire working environment, 407 MB across 2,616 files in 234 directories, from an exposed HTTP directory at 154.86.119.60.

The strategic weight of this campaign is greater than a routine camera breach. The largest share of confirmed compromises concentrated in Ukraine, with significant hits in Russia, Mexico, and Vietnam, which places internet-exposed surveillance infrastructure in active conflict zones directly under the control of an actor whose toolkit includes transferable access: offline recovery codes, SMART PSS enterprise-format exports, and a persistent backdoor that outlasts standard remediation. The presence of a separate Windows malware payload (UPX-packed, tagged as SalatStealer) and a five-method Defender exclusion script targeting C: wholesale suggests the same host staged capabilities beyond camera exploitation, yet the event timeline does not confirm whether that payload activated. This gap between toolkit readiness and observed action is the critical uncertainty for defenders.

Defenders should treat any camera reachable on port 37777 during the campaign window as a potential compromise and audit device account lists specifically for p2pwn, removing it if found. The authentication-bypass chain requires unpatched firmware; Dahua advisory SA-2021-0130 (first published 2021-09-01) covers CVE-2021-33044 and CVE-2021-33045 with fixed versions such as DH_IPC-HX1XXX-Molec_MultiLang_PN_V2.820.0000000.33.R.210705 for the IPC-HX1XXX series, and corresponding builds for other affected families. Block TCP 37777 externally unless required. For hunting, inspect login requests carrying "clientType": "NetKeyboard" or "loginType": "Loopback" with "ipAddr": "127.0.0.1"; these are the exact payload structures from the recovered source. Monitor for Telegram exfiltration patterns, SMART PSS XML batch exports, and serial-prefix brute patterns matching the operator's thirteen prefixes (e.g., AH1058FPAG, 5E00107PAJ). Remove Dahua P2P relay where not actively used, since serial-based access is independent of device credentials.

Two developments would change the assessment materially. First, whether Dahua firmware updates are deployed to invalidate previously issued cloud recovery codes; Dahua states that updates block new code generation and cause existing codes to refresh and eventually expire, but until that process completes, previously recovered codes remain a live risk separate from the backdoor account. Second, whether the Windows pivot activates in the wild: the SalatStealer-tagged binary (hash de03a0ae5c7aa0c237ae36a649875f986fd9701ac06857dd214054367ce5090c) appeared on the same host and on a second address (185.132.53.56) two days later, and the Defender-evasion script includes Group Policy persistence, which points to enterprise targeting rather than opportunistic IoT exploitation. Confirmation of either event would elevate this from a camera-focused espionage operation to a broader infrastructure compromise.
