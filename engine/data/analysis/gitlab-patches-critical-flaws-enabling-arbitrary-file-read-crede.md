GitLab patched critical vulnerabilities in Community Edition and Enterprise Edition, with CVE-2026-85706 as the most severe flaw. The path traversal vulnerability in the repository commits API allows unauthenticated remote attackers to read arbitrary files from a vulnerable GitLab server under certain conditions. GitLab attributed the exposure to inadequate path confinement combined with missing authentication enforcement in the affected API path. The September 10, 2026 patch release fixes 18 security issues total across GitLab CE and EE.

The CVSS vector AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:N indicates the highest severity attack conditions: unauthenticated, network-accessible, low complexity, with high confidentiality and integrity impact and changed scope. An attacker exploiting the flaw could access application configuration data, secret material, tokens, or credentials stored in accessible paths on the server. The flaw affects GitLab versions from 18.7 before 19.1.8, 19.2 before 19.2.6, and 19.3 before 19.3.2.

This is a separate reporting from the Canadian Centre for Cyber Security advisory AV26-917 covering the same CVE. Self-managed administrators should upgrade immediately. GitLab.com is already running the patched code, and GitLab Dedicated customers do not need to take action. The unauthenticated nature of this flaw and its presence in the commits API, which is frequently accessed in CI/CD workflows, makes this particularly dangerous for organizations running self-managed GitLab instances.
