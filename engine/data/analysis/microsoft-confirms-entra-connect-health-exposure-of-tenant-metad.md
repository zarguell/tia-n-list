Microsoft confirmed that a flaw in the Entra Connect Health API gave unauthorized parties read-only access to tenant-level metadata. The flaw was introduced on July 23, 2026, detected on November 9, fixed server-side on November 19, and the investigation concluded on November 20. Microsoft said it found no unauthorized configuration changes.

The exposed fields included technical contact and administrator email addresses, tenant IDs, display names, initial domains, country codes, regions, license tiers, directory synchronization status and last sync timestamps, and Connect Health onboarding status. An expired certificate formerly used to register Connect Health agents with a Microsoft internal service decommissioned in late 2024 remained in storage and was returned in the pksCertificate field. Microsoft said passwords, password hashes, authentication tokens, valid keys, on-premises and Active Directory topology, and Azure subscription information were not exposed.

The material is useful for phishing and tenant reconnaissance rather than direct account takeover. Microsoft advised customers to verify the notice in Azure Service Health, run the GetTenant and GetTenantPksCertificateDetails scripts, review Entra audit and sign-in logs plus Azure Activity Logs, and require phishing-resistant MFA. Watch for a count of affected tenants and any evidence that the expired certificate was used in follow-on activity.
