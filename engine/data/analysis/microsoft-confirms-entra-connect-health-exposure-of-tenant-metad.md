Microsoft confirmed that a flaw in the Entra Connect Health API was exploited to give unauthorized parties read-only access to tenant-level metadata. The vulnerable API behavior was introduced on July 23, 2026 and discovered on November 9. Microsoft concluded its investigation on November 20, 2026 and told admins that it found no unauthorized configuration changes, although the flaw could have allowed changes to Connect Health monitoring configurations.

The exposed data included administrator email addresses and tenant and service-monitoring configuration information. One concrete artifact called out in the notification was an expired certificate that was no longer in use but remained in Connect Health storage and was still returned by the API. Microsoft said the flaw did not expose user passwords, password hashes, authentication tokens, or valid cryptographic keys. The affected service is the cloud-based Entra Connect Health monitor for on-premises identity infrastructure.

The timeline matters because the API was live for months before discovery. Organizations that used Connect Health should review tenant metadata and admin email exposure, check monitoring configurations for unexpected edits even though Microsoft reported none, and remove stale certificates from service storage. The confirmed read access distinguishes this from a speculative exposure notice; the open question is which tenants were touched during the window from July 23 to November 9.
