Microsoft confirmed that the Entra Connect Health API was exploitable from July 23 until a server-side fix on November 19, with detection on November 9 and the investigation closing on November 20. Unauthorized callers could read tenant-level metadata, including technical contact and administrator email addresses, tenant IDs, display names, initial domain names, country codes, region, Entra license tier, directory synchronization status with last sync timestamp, and Connect Health onboarding status. An expired legacy certificate left in Connect Health storage was still returned in the pksCertificate field after the internal service it once registered agents with was decommissioned in late 2024. Passwords, password hashes, authentication tokens, valid cryptographic keys, on-premises and Active Directory topology, and Azure subscription data were not exposed, and Microsoft reported no unauthorized configuration changes.

This is identity reconnaissance rather than credential theft, and that is why it outranks the absence of stolen hashes. The exposed set names the people who administer a tenant and pairs them with the tenant ID, initial domain, region, license tier, synchronization state and last sync time. That turns a contact list into a qualified target list for hybrid identity environments, and the 119 days between July 23 and the November 19 fix come with no disclosed first-access date, so defenders cannot bound risk by the November 9 detection. Microsoft has not published an affected-tenant count; more than a dozen administrators reported the notice publicly, including MSPs who received it for several customer tenants, which points to a blast radius spread through one monitoring service.

No customer patch applies because Microsoft says the service-side fix closed the API and no software update is required, leaving verification and hunting as the defender work. Confirm the tenant appears in Azure Service Health, review Connect Health configuration at aka.ms/EntraConnectHealth with the read-only GetTenant and GetTenantPksCertificateDetails scripts from aka.ms/ConnectHealth/scripts, and treat a populated pksCertificate field as a stale-record marker rather than a live key, since those scripts show current values and cannot reconstruct what was read before the fix. Hunt Microsoft Entra audit and sign-in logs together with Azure Activity Logs for anomalous administrator activity or Connect Health changes, enforce phishing-resistant MFA on Global Administrator and other privileged accounts with PIM just-in-time activation, and verify that technical contacts and notification recipients are current so the next vendor notice is not missed.

The assessment changes if Microsoft publishes the affected-tenant count, the date of the first unauthorized call, or an actor attribution, any of which would turn a broad exposure notice into a scoped intrusion. The other trigger is phishing that uses these specific fields, tenant ID, initial domain and sync timing, against the named technical contacts, or evidence of configuration changes outside the telemetry Microsoft reviewed.
