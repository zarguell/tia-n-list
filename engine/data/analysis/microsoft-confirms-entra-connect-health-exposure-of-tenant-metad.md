Microsoft confirmed that a flaw in the Entra Connect Health API gave unauthorized parties read-only access to tenant-level metadata. The flaw was introduced on 23 July 2026, found on 9 November, fixed server-side on 19 November, and the investigation closed on 20 November. Microsoft's notice, reproduced on r/sysadmin and reported by BleepingComputer, says no unauthorized configuration changes were identified.

The exposed fields include technical contact and administrator email addresses, tenant IDs, display names, initial domains, country codes, regions, license tiers, directory synchronization status and last sync timestamps, and Connect Health onboarding status. An expired certificate formerly used to register Connect Health agents with a Microsoft internal service decommissioned in late 2024 remained in Connect Health storage and was returned by the pksCertificate field. Microsoft says passwords, password hashes, authentication tokens, valid keys, on-premises and Active Directory topology, and Azure subscription data were not exposed.

This matters because the leaked fields map directly to targeting material: administrator addresses, tenant identifiers and sync state. Microsoft's advice is to check the notice in Azure Service Health, run the GetTenant and GetTenantPksCertificateDetails scripts, review Entra audit and sign-in logs plus Azure Activity Logs, and require phishing-resistant MFA.

Watch for scope statements on how many tenants were read and whether the expired certificate was used in any follow-on activity. Continued coverage through 23 November restates the same notification rather than adding new victim counts.
