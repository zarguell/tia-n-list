Threadlinqs Intelligence reported that North Korean actors bypassed npm's trusted publishing pipeline to distribute a malicious loader package (threat ID TL-2026-2588, attributed to "PolinRider"). The attack generated 9 detections and 24 indicators of compromise, and demonstrates that npm's provenance guarantees can be subverted.

npm's trusted publishing feature was designed to allow package maintainers to publish directly from CI/CD pipelines without storing long-lived access tokens, with the expectation that provenance attestations would help consumers verify package integrity. The DPRK actors found a way to slip a loader past this mechanism, meaning the package appeared to come from a legitimate, verified publishing pipeline while containing malicious code.

This is a significant escalation in supply chain attacks against the JavaScript ecosystem. Previous npm supply chain attacks relied on compromised credentials or typosquatting. By defeating the provenance system itself, attackers can deliver malware that passes automated integrity checks. Developers and CI/CD systems that rely on npm provenance as a trust signal need to re-evaluate this assumption. Additional controls should include runtime monitoring of package behavior, dependency review processes, and network-level detection for known DPRK infrastructure.
