ChainDrop, a self-propagating worm in the npm ecosystem tied to the Mini Shai-Hulud / TeamPCP cluster, entered the registry on August 4 through a compromised maintainer account. The attacker took over the GitHub account of the keyv maintainer and injected malicious code into the source repository, so the project's own GitHub Actions pipeline built and published poisoned versions of keyv, cacheable, flat-cache, and file-entry-cache. The malicious keyv@6.0.0 release carried valid SLSA Build Level 3 provenance attestations, making it indistinguishable from a clean build to automated security tooling.

The worm spread to more than 400 packages by stealing developer tokens and republishing infected versions of everything those tokens could reach, and it anchored its C2 in an Ethereum smart contract so domains can be rotated with a single transaction. This is the supply-chain scenario defenders least want: a poisoned release with authentic provenance, built by the trusted pipeline itself. Teams should verify package integrity beyond provenance checks, treat registry packages from compromised accounts as a live threat, and rotate any tokens that may have touched affected packages.
