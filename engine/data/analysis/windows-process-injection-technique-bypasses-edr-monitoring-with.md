A new Windows process injection method called console named-pipe injection places payloads inside a child console process without calling the heavily monitored VirtualAllocEx and WriteProcessMemory APIs. Published by researcher Two Seven One Three, the technique launches an interactive console child such as nslookup.exe or netsh.exe with standard input redirected through a named pipe; the parent writes payload bytes to the child’s stdin, then changes page protections and hijacks execution flow. MITRE ATT&CK tracks process injection under T1055; this variant evades EDR telemetry that relies on remote memory allocation patterns.

No CVEs or specific actors are tied to the technique, but the approach demonstrates how interprocess communication APIs can bypass endpoint defenses focused on traditional allocate-write-execute sequences. Defenders should correlate console process spawning, named pipe creation, stdin redirection, and thread execution across process boundaries rather than relying solely on memory-protection telemetry.
