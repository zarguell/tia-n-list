Researchers uncovered a cryptojacking campaign that compromised 3,562 internet-exposed Redis servers by abusing unauthenticated Redis replication. The attackers scanned 12,966 Redis hosts and used CONFIG SET commands to redirect the working directory, then instructed victim servers to replicate from a rogue Redis instance. During replication, the attackers wrote cron jobs that installed XMRig cryptocurrency miners with persistent execution.

The compromised systems ran Redis versions from 2.8.17 through 7.2.0, indicating the campaign did not exploit a specific CVE. The root cause is unauthenticated Redis instances exposed to the internet, a long-standing misconfiguration issue. Investigators recovered an exposed attacker-controlled directory containing 147 files: Python exploit scripts, campaign logs, portable Python runtimes, Windows registry hives, and infrastructure data, providing detailed operational visibility.

The campaign ran in two separate waves. Redis operators should ensure authentication is enabled (requirepass or ACLs), bind to internal interfaces only, and firewall port 6379. The use of Redis's legitimate replication protocol as an attack vector means traditional vulnerability scanning will not detect this activity. Monitoring for unexpected cron job creation and XMRig process execution on Redis hosts is recommended.
