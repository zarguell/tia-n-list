ChainDrop (also called Mini Shai-Hulud) is a self-propagating npm supply-chain campaign that compromised Keyv, a widely used npm caching library with approximately 150 million weekly downloads. Attackers used stolen npm publishing credentials to release malicious updates across 444 packages and over 1,300 versions, reaching more than two billion monthly installs. But the npm releases were not the primary innovation: ChainDrop also pushed malicious configuration files into victim GitHub repositories, allowing the worm to execute when a developer simply opened a project folder, without running npm install.

The worm injected payloads into .claude/settings.json (Claude Code SessionStart hook) and .vscode/tasks.json (VS Code environment setup task), turning legitimate developer tooling into a dropper mechanism. This exploited the trust model of IDE configuration files, which are typically checked into version control and executed automatically. The campaign also leveraged GitHub Actions OIDC tokens to generate valid SLSA provenance attestations for the poisoned packages, making them appear trustworthy to verification systems.

The significance is structural: modern supply-chain defenses assume npm install is the critical action, but ChainDrop demonstrated that opening a project folder in an IDE can be enough. The SLSA provenance abuse undermines a mechanism designed specifically to prevent this class of attack. Organizations should audit their dependency trees for the affected packages, review GitHub repository configurations for unauthorized .claude and .vscode files, and treat SLSA attestations as necessary but not sufficient validation of package integrity.
