eSentire has documented an intrusion in which a Microsoft Store application was used to deliver a remote access trojan the researchers call Vinci RAT. The chain starts with a redirection to a fake site for a snipping tool at snipp.codes-team[.]com, from where a Microsoft-signed installer named Snipping-Tool.exe is served. Signing matters here: the binary carries a valid Microsoft signature, so it inherits the trust that users and allow-lists extend to genuine tooling and is unlikely to be blocked on reputation alone.

The detail that separates this from routine trojan delivery is the distribution path. A signed installer pulled through the Microsoft Store ecosystem gives the operator a trusted update and app channel, which means the payload can arrive without the usual malformed attachment, crack or sideloaded executable that endpoint controls are tuned for. Vinci RAT's documented capability is remote control of the host, so once landed the exposure is whatever the user's session and the machine's network position allow.

Treat the domain as the primary hunting artifact while the vendor write-up is filled in: proxy and DNS logs for snipp.codes-team[.]com, then the process tree and file provenance for Snipping-Tool.exe wherever it was launched. Installs of a snipping utility that did not come from the genuine vendor page deserve a look at the signature chain and the signed identity, since a legitimate-looking cert is what carried this campaign. Watch for an expanded technical report from eSentire naming the RAT's command infrastructure and persistence, and for Microsoft's response on how a signed installer entered distribution in the first place.
