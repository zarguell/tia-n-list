The BlackNevas ransomware group destroyed an organization's entire virtualization estate over ten days without exploiting any hypervisor vulnerability. Kaspersky's Global Emergency Response Team documented the attackers wiping four ESXi hosts, every virtual machine on them, both vCenter Server Appliances, and all connected backup infrastructure, using only legitimate VMware management interfaces. The absence of a software flaw means the intrusion rested on credential or configuration weaknesses rather than a patchable bug.

The attack illustrates why ESXi environments are attractive targets: a single administrative foothold can reach hosts, guest VMs, vCenter, and backups simultaneously, and the Babuk ESXi locker source code leaked in 2021 has since lowered the barrier for ransomware groups to target virtualization. At least ten subsequent families have reused that leaked code. Routine admin gaps, such as exposed management interfaces and weak credentials, are what opened the door in these cases.

Defenders should treat vCenter and ESXi management planes as critical assets: segment them from user networks, enforce strong authentication, restrict backup infrastructure from the same trust boundary, and monitor for destructive actions such as mass VM deletion or vCenter changes. Because no CVE is involved, patching alone does not address this risk; hardening and detection do.
