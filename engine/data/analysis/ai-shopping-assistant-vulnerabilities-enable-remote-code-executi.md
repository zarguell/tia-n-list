Rein Security researchers Netanel Rubin and Dan Avraham demonstrated at Black Hat how flaws in a major US retailer's AI shopping assistant could be chained from a public mobile app to remote code execution on backend infrastructure. The unnamed retailer's assistant was built on Google Vertex AI Search and protected by SSL certificate pinning, an intent classifier, a scoped system prompt, and structured JSON output restrictions. The researchers bypassed all four layers.

They used Frida instrumentation to defeat SSL pinning, then crafted inputs that evaded the intent classifier. The assistant's underlying retrieval-augmented generation pipeline lacked consistent input validation, allowing the researchers to break out of the shopping context and execute arbitrary queries against backend services. The attack chain moved from the mobile app through the AI layer to server-side infrastructure.

This research highlights a systemic problem: AI assistants bolted onto enterprise systems often lack the defensive depth of the systems they connect to. Input validation, runtime controls, and application-layer security applied inconsistently across the AI and backend boundary create exploitable gaps. Organizations deploying AI assistants on customer-facing applications should treat the AI layer as a high-risk entry point requiring the same rigor as any other external-facing service.
