Two overlapping Rust supply chain compromises were disclosed. The first involves the onering crate, a high-throughput synchronous queue and channels library with over 18,000 downloads. A malicious update (version 1.4.1, detected June 10, 2026) exfiltrated source code changes from developers' machines during the build process. The second, broader campaign affected arrayref version 0.3.10, append-only-vec version 0.1.9, and internment version 0.8.7, collectively accumulating hundreds of millions of downloads. Researchers at Aikido Security identified the campaign through a suspicious package named proc-macro1 that impersonated the widely-used proc-macro2 crate.

The malicious crates performed build-time exfiltration, meaning source code, browser credentials, and cryptocurrency wallet data were stolen during application compilation rather than at runtime. This approach is harder to detect because the malicious behavior executes in the developer's build environment, not in production. The compromised packages were embedded as build dependencies, ensuring they ran during cargo build without direct user invocation.

This represents one of the largest Rust crate compromises by downstream exposure. The hundreds of millions of combined downloads for the affected packages mean any project that pulled these dependencies during the compromise window may have exposed developer credentials and source code. Teams should audit their dependency trees for the specific versions listed, rotate any credentials stored on affected build machines, and consider using cargo-audit or similar tooling to detect dependency tampering. The impersonation pattern (proc-macro1 mimicking proc-macro2) suggests the attackers understand Rust ecosystem naming conventions and targeted high-traffic packages deliberately.
