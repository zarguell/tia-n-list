The PolinRider campaign has added a Python loader to the JavaScript one it already plants in build files. The loader is 58 lines of standard-library Python, hidden in a small `utils` package or in `conftest.py`; importing the file queries the public Ethplorer API and an Ethereum RPC node for the newest self-addressed transaction from wallet `0x3b1574417524c11a7403c4b232CAcBb320CceBC6`, decodes JavaScript out of the calldata, follows a second wallet `0x1eEf0849EDa15d87f64e51C73C8442Cf3c8bCEF3` to the C2 address, and writes the next stage into a detached `node -i` process. SafeDep measured 375 repositories under 260 accounts on November 24, 2026, with 370 of them pushed that month; Apiiro puts the total at 7,609 repositories owned by 2,330 accounts. The chain records behind it date to February 2025, and SafeDep found no evidence of distribution through PyPI or npm.

The victim unit is not the repository, it is the laptop that ran `pytest`. Anyone who clones a poisoned repo and runs the test suite, or opens the folder in VS Code, executes the loader under their own credentials, and the later stages in the chain SafeDep followed took environment secrets, browser passwords, cookies and wallet data. Apiiro's finding that commits are rewritten under the original author, message and date, with the loader parked after hundreds of spaces in a build config, explains why review did not catch this: the diff looks like the developer's own work, and the account that opened more than 200 pull requests against AsyncAPI Generator, CircuitVerse and Open Food Facts held stolen access rather than a new identity. Because the C2 address lives in Ethereum transaction calldata, domain blocklists and sinkholes do nothing against it, and because nothing was published to a package registry, dependency scanning had nothing to match. The scope moved from 675 repositories in March to 1,951 in April to 7,609 now, which is the reason this story outranks the other supply-chain items: the infection path is a repo clone, the payload rotates wallets, and the same operator is reported behind the InvisibleFerret chain.

There is no vendor patch. Remediation starts with evidence collection on the repositories, not the repository host: Apiiro's pivot `git grep -nE ';[[:blank:]]{200,}[^[:space:]]'` finds the loader hidden behind a long run of spaces in build configs, and `git log --diff-filter=M` against a reflog or branch protection audit surfaces force-pushed commits that preserve author and date. Hunt on `conftest.py` and `utils` additions in repositories with recent unmerged branches, on `node -i` spawned as a child of `python` or `pytest`, and on CI or developer egress to `api.ethplorer.io` and public Ethereum RPC endpoints, which ordinary builds rarely need. Treat any host that imported a flagged file as compromised: rotate shell environment secrets, GitHub tokens and SSH keys, clear browser-saved passwords and session cookies, and check for theft of wallet material. Do not run the suite to confirm; clone into a throwaway container with egress denied.

Two developments would change the picture. A confirmed loader on PyPI or npm would move this from "repositories you chose to clone" to "packages installers pull automatically", and that is the failure mode no registry review currently catches for this family. The other is wallet rotation: SafeDep saw a new operator wallet between the September and November waves, so indicators tied to `0x3b1574417524c11a7403c4b232CAcBb320CceBC6` and `0x1eEf0849EDa15d87f64e51C73C8442Cf3c8bCEF3` should be treated as perishable, with the blockchain query pattern and the import-time execution path as the durable detections.
