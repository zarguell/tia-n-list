simple-git, the git-js npm library maintained by steveukx that lets Node.js applications run git operations from JavaScript, received two CVSS 8.1 (v3.1) vulnerability records on September 29, 2026, both assigned by GitHub as CNA and both fixed in version 4.0.0. The first, CVE-2026-102826 (EUVD-2026-89332, GHSA-g4wm-2vf7-vfgr), sits in the default blockUnsafeOperationsPlugin: before 4.0.0 it fails to fully reject configuration includes supplied through customArgs to git.clone(). The missing include.path classification lets Git load an attacker-controlled configuration file, and the initial remediation also left includeIf.<condition>.path uncovered, preserving the same file-loading primitive through a conditional include.

The loaded configuration matters because Git applies its options during the clone, so an executable option such as core.sshCommand runs a command of the attacker's choosing with the privileges of the Node.js process. Exploitation requires the application to pass attacker-influenced custom arguments and an attacker-controlled file the process can read. The second flaw, CVE-2026-102827 (EUVD-2026-89333, GHSA-858h-whjf-mvg5), is in the same plugin's flag detection: it compares parsed option names against literal dangerous spellings while Git accepts unambiguous long-option abbreviations. Abbreviated --receive-pack or --exec forms therefore bypass detectVulnerableFlags, reach git push against a local or file remote or an attacker-influenced receive-pack target, and cause Git to invoke an attacker-selected command in consumers that expose those arguments. The clone-side abbreviation handling does not protect the push path.

Both records score AV:N/AC:H/PR:N/UI:N with high confidentiality, integrity, and availability impact, so the bar is attack complexity rather than privileges or interaction. simple-git is a common dependency in build tooling, CI helpers, and git-backed web services, so the exposure concentrates in apps that forward user or repo-influenced arguments to clone or push. Watch how quickly pinning moves to 4.0.0, whether downstream wrappers sanitize customArgs in the meantime, and for any public exploit targeting abbreviated push flags, which would push this from patch-now to incident-hunt territory.
