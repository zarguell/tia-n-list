YesWeHack researcher Alex Brumen disclosed cache key injection, a cache poisoning technique targeting Nginx deployments that construct cache keys by concatenating multiple request components without delimiters. The flaw is in how cache keys are built, not in how they are hashed. When adjacent values in the key string are merged ambiguously, two distinct HTTP requests can produce identical cache keys. For example, a request for / with Accept: */* can generate the same key as a request for /* with Accept: /*, depending on the remaining key components.

This ambiguity lets attackers map their crafted requests to cached responses from legitimate users. The attack enables access control bypass by serving cached authenticated pages to unauthenticated requesters, denial-of-service by filling the cache with poisoned entries, and stored XSS by injecting scripts into cached content that subsequent visitors receive. The technique shifts attention from traditional web cache poisoning involving unkeyed HTTP headers to the fundamental construction of the cache key itself.

Nginx configurations using proxy_cache_key with concatenated variables like "$scheme$proxy_host$uri$is_args$args$http_accept" are vulnerable. The fix is to use delimiters between key components or hash each component separately before concatenation. Organizations should audit their Nginx cache key configurations and review whether cached sensitive pages are protected by keys that cannot be collision-matched by attacker-controlled input.
