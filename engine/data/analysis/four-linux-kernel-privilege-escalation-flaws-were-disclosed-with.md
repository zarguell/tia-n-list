The disclosure covers five Linux kernel local privilege escalation flaws, not four. The quartet tracked as CVE-2026-68121 (PPPoEject), CVE-2026-74469 (DiagSpill), CVE-2026-80844 (DirtyAH6), and CVE-2026-81000 (TUNderflow) are memory corruption bugs in networking subsystems, each with a public proof-of-concept exploit released by the same researcher. A separate, earlier disclosure tracked as CVE-2026-72018 adds an out-of-bounds write in the dibs_loopback driver of the SMC-D subsystem, discovered by XBOW. The quartet affects kernel networking paths from PPPoE and SCTP to TUN and IPsec AH6; the SMC-D flaw affects standard x86 Linux through the new loopback transport, a surface that did not exist before the dibs_loopback virtual device made SMC-D reachable without IBM Z hardware.

Local root on a shared server or multi-tenant cloud host is not a theoretical risk here. DiagSpill (CVE-2026-74469, CVSS 8.8) is the most dangerous of the quartet because it requires no unprivileged user namespaces: a 16-bit transport count wraps at 65,536 entries, and the SCTP diag code then spills roughly 8 MiB past the response buffer into adjacent kernel memory. DirtyAH6 (CVE-2026-80844) introduces a remote crash surface on IPv6 routers adding AH in transport mode through an unvalidated segments_left pointer in ipv6_rearrange_rthdr(), and its local exploit relies on namespaces that are disabled by default in some hardened configurations. TUNderflow (CVE-2026-81000, CVSS 7.8) requires an oversized TUN receive headroom passed through stacked network devices to trigger a size_t underflow in tun_get_user(), while PPPoEject (CVE-2026-68121) exploits a stale pointer kept across a dev_hard_header() callback in the PPPoE send path. The SMC-D vulnerability (CVSS 7.8) is distinct: it needs CAP_NET_ADMIN, affects a 16,384-byte Direct Memory Buffer, and writes exactly 16 zero bytes at an attacker-controlled offset through a missing bounds check in move_data(), with XBOW demonstrating a 22 percent success rate across 100 separate boots using a single primitive.

Defenders should treat the quartet as an immediate patching priority rather than a routine update cycle because public exploits are already available in repositories such as github.com/manizada/DirtyAH6, TUNderflow, PPPoEject, and DiagSpill. Upgrade to fixed stable releases (5.10.270, 5.15.221, 6.1.188, 6.6.157, 6.12.109, 6.18.50, 7.2.4) or apply distribution-specific backports covering all five CVEs. If patching is delayed, disable unprivileged user namespaces to block the first three quartet exploits (though DiagSpill remains reachable), restrict CAP_NET_ADMIN to only necessary containers to contain the SMC-D surface, and disable unused subsystems such as AH6, TUN, PPPoE, and SCTP where operational requirements allow. Hunting should focus on abnormal nfqueue rules using nftables NFQUEUE for packet interception, unexpected SMC loopback connections over standard x86 hosts, abnormal sctp_diag response sizes, and kernel crash patterns pointing to ipv6_rearrange_rthdr() or dibs_loopback memory corruption.

Watch for a CISA KEV listing for any of these five CVEs, which would shift the threat from proof-of-concept to commodity exploitation. Also monitor whether XBOW or other researchers extend the constrained SMC-D zero-write primitive into a fully reliable exploit using an additional infoleak or UAF chain, or whether mass-scanning telemetry picks up the quartet's PoC signatures in the wild. A delay in major distribution backports is another development that would extend the exposure window for shared hosting and container environments.
