CVE-2026-32475 is a critical file-upload vulnerability in Elementor Pro versions before 4.2.2 that permits unauthenticated remote code execution on WordPress servers. The flaw lives in the File Upload module's handling of multipart forms: the validation loop and the processing loop disagree on how to treat an empty filename entry (UPLOAD_ERR_NO_FILE). An attacker submits a crafted multipart upload with an empty first part followed by a PHP payload. The validator exits early after the empty part, never inspecting the payload; the processor skips the empty entry and moves the PHP file to wp-content/uploads/elementor/forms/. From there it can be accessed directly to execute arbitrary commands. The bug requires a published Elementor Pro Form widget with at least one File Upload field, a common configuration on the roughly 6 million sites running the plugin.

Exploitation began on August 19, the same day Elementor shipped the 4.2.2 fix. Wordfence reported blocking nearly 200,000 exploitation attempts against its customer base since patch day. Attackers are dropping webshell payloads and using them to run commands on compromised servers. The volume of blocked attempts indicates active mass scanning and automated exploitation across the WordPress ecosystem.

The fix is straightforward: update Elementor Pro to 4.2.2 or later. Sites that cannot patch immediately should ensure no Elementor Pro form widgets with file upload fields are published, or disable those forms entirely. Wordfence and Patchstack both flagged the issue with detailed writeups, and the vulnerability is assigned CVE-2026-32475.
