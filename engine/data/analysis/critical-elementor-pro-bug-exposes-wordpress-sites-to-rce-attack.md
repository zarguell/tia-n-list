A critical remote code execution vulnerability, CVE-2026-32475, affects Elementor Pro versions before 4.2.2. The flaw lives in the File Upload module, where two separate loops handle file validation and processing. They disagree on what to do with an empty filename entry (UPLOAD_ERR_NO_FILE in PHP): the validation loop skips it, but the processing loop does not. An attacker can exploit this mismatch to upload executable files directly to the server. Patchstack, which focuses on the WordPress ecosystem, reported the issue. A fix shipped in Elementor Pro 4.2.2, and site owners should update immediately.

Elementor Pro is one of the most widely deployed WordPress plugins, with more than 10 million active installations. The attack requires no authentication beyond being able to reach the upload endpoint, making it a high-value target for mass exploitation. No in-the-wild exploitation has been reported yet, but the simplicity of the flaw and the size of the install base mean weaponized payloads are likely to surface quickly. WordPress sites running Elementor Pro should verify their version and update to 4.2.2 or later as a priority.

The vulnerability does not carry a CVE score in the published advisory yet, but RCE on a web server is inherently critical. Watch for Patchstack and Wordfence to release additional technical details and detection signatures. Sites behind a WAF may get temporary protection, but the real fix is the plugin update.
