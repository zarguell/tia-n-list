A critical remote code execution vulnerability, CVE-2026-32475, affects Elementor Pro versions before 4.2.2. The flaw lives in the File Upload module, where two separate loops handle file validation and processing. They disagree on what to do with an empty filename entry (UPLOAD_ERR_NO_FILE in PHP): the validation loop skips it, but the processing loop does not. An attacker can exploit this mismatch to upload executable files directly to the server. Patchstack, which focuses on the WordPress ecosystem, reported the issue. A fix shipped in Elementor Pro 4.2.2, and site owners should update immediately.

Elementor Pro is one of the most widely deployed WordPress plugins, with more than 10 million active installations. The attack requires no authentication beyond being able to reach the upload endpoint, making it a high-value target for mass exploitation. Wordfence reported on September 3 that exploitation of CVE-2026-32475 began on August 19, the same day the patch released. Nearly 200,000 exploitation attempts have been blocked since then, with attackers submitting forms containing empty first file entries followed by malicious PHP payloads. The uploaded webshells land in wp-content/uploads/elementor/forms/ and grant remote command execution.

WordPress sites running Elementor Pro should verify their version and update to 4.2.2 or later as a priority. The volume of blocked attempts indicates automated mass exploitation is underway. Sites without a WAF or running older Elementor Pro versions are at immediate risk. Wordfence and Patchstack have published detection signatures for the webshell payloads being deployed in these attacks.
