ESET researchers documented Russia-aligned threat actor UAC-0099 deploying a technique they call GuardBreaker against an organization in Ukraine. The method targets LLM-powered security scanners that increasingly triage suspicious code in enterprise environments. UAC-0099 embeds safety-sensitive, weapon-related prompts directly into VBScript malware. When the LLM encounters these prompts, its safety training kicks in and it refuses to analyze the code, effectively creating a blind spot that lets the malicious script pass unflagged.

This is a meaningful shift in adversary tradecraft. Rather than evading signature-based detection or sandboxing, GuardBreaker exploits the behavioral constraints of the analysis tool itself. The approach is lightweight (a comment or string insertion) and generalizable: any LLM scanner with content-refusal policies is potentially vulnerable to similar prompt injection. UAC-0099 is a well-documented group tied to Russia's GRU-adjacent operations, so the technique is already in the hands of a capable state actor.

Watch for copycat adoption across other APT and cybercriminal groups. The defense implication is that LLM-based triage cannot be the sole analysis layer. Organizations relying on AI-assisted malware analysis need human-in-the-loop review and should treat LLM scanner outputs as one signal among several, not a definitive verdict. ESET's disclosure also raises the question of whether LLM vendors will harden refusal policies for security-analysis contexts, or if that creates its own risks.
