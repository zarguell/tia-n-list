Microsoft Threat Intelligence's September 24, 2026 profile names Storm-2570, a ransomware affiliate tracked since April 2025 that has deployed Qilin, DragonForce, Anubis, and BERT payloads across investigated intrusions in the United States, Canada, the United Kingdom, Spain, the Netherlands, and Puerto Rico, hitting healthcare, education, government, financial services, energy, retail, and at least eight other sectors. The chain Microsoft lays out is deliberately unremarkable: hands-on-keyboard operators install RMM tools (Atera, MeshAgent, ScreenConnect, Splashtop, NinjaRMM), run ntdsutil IFM dumps of NTDS.dit into C:\Windows\Temp, harvest credentials with Mimikatz, LaZagne, and pypykatz, move laterally with PsExec @ip.txt host lists and an rdp.bat that opens TCP 3389, tunnel out through ngrok or a Cloudflared service running as LocalSystem, and push documents, databases, and mail files to attacker S3 buckets with s5cmd or Rclone before encryption. No CVE anchors any of it, and the initial access vector remains unconfirmed.

The load-bearing finding is not the ransomware but the constancy underneath it. Four RaaS brands fragment this operation into what looks like four unrelated extortion events, each with its own tracker, its own leak-site cycle, and its own rapidly decaying payload IOCs; the affiliate beneath them reuses the same MeshAgent foothold, the same security tampering (real-time monitoring off, C:\PerfLogs excluded, DisableAntiSpyware, DisableRealtimeMonitoring, and WinDefend service keys edited), and the same s5cmd exfiltration in every family. A defender keyed to ransom brands meets this actor only at encryption, while a defender keyed to behavior can catch it at the RMM install days or weeks earlier, and one hunt set covers all four families plus whichever brand Storm-2570 joins next. It also cuts against negotiation math: an affiliate that shifts between programs opportunistically can re-enter under a different banner after a settlement, so paying one brand's demand does not remove the operator.

Defender actions here are unusually specific. Turn on tenant-wide tamper protection and, for Intune or Defender for Endpoint Security Configuration customers, DisableLocalAdminMerge so exclusions cannot be gutted via GPO; deploy the ASR rules Microsoft maps to this actor, including block credential stealing from lsass.exe and block process creations originating from PsExec and WMI commands. Inventory RMM installs and treat unapproved ones as incidents: reset the passwords of accounts used to install them and investigate any System-level service install. Run Microsoft's two Sentinel hunts on a 30-day lookback: psexec.exe or psexec64.exe command lines carrying @ip.txt or -accepteula, and the union query over DeviceProcessEvents, DeviceFileEvents, and DeviceRegistryEvents for meshagent, meshagent64, or meshcentral, which surfaces the renamed meshagent64-[organization name].exe pattern. Correlate any hit with a Cloudflared or ngrok tunnel process and with s5cmd.exe staged beside a credentials file, and let Defender's Ransom:Win32/Qilin, Ransom:Win32/DragonForce, and Ransom:Win64/Anubis signatures confirm rather than lead.

Two developments would move this assessment. Confirmation of the initial access vector, which Microsoft could not pin down, would let defenders close the door instead of sweeping the hallway, so watch for a follow-up report or third-party telemetry naming the entry tool. A fifth payload family landing on this identical tooling would confirm the affiliate model beyond doubt and further invalidate brand-only detections and brand-scoped incident response.
