A critical vulnerability in isolated-vm, a widely used Node.js sandboxing library, allows untrusted JavaScript to escape its V8 isolate and hijack control flow in the host process. The flaw, tracked as GHSA-864f-rcv7-6rh4 (CVE pending), affects versions before 7.0.1 and 6.2.0. The library receives more than 1 million downloads per week and is used by AI agents, automation platforms, and applications that execute user-supplied or model-generated code.

The vulnerability resides in ExternalCopy, a feature that moves serialized values between separate V8 Isolates using a transferList option for zero-copy ArrayBuffer transfers. Isolated-vm validated transfer-list entries during one pass and transferred them in a second pass. An attacker can use a JavaScript getter to return a real ArrayBuffer during validation, then return a different value when native transfer logic runs again, creating a time-of-check, time-of-use condition in the C++ binding layer. This allows sandboxed code to corrupt host memory or redirect execution.

Fixed releases are available in versions 7.0.1 and 6.2.0. Two outlets covered this story with overlapping detail. No exploitation has been publicly reported, but the library's ubiquity in AI and serverless runtimes makes this a high-priority patch. Organizations running isolated-vm in any capacity that processes untrusted input should treat this as urgent. Watch for CVE assignment and any reports of in-the-wild exploitation targeting AI agent infrastructure.
