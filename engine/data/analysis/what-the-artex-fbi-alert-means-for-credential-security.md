The FBI's November 13 FLASH alert on ARTEX says some intrusions went from initial targeting to privileged access in under three hours. ARTEX is an open-source LLM-driven penetration-testing framework released in 2026; its creator removed it on October 8, 74 days after the initial commit, and 102 forks or ARTEX-named repositories appeared within the same week. The FBI's concern is the speed at which the agents chain ordinary web exploitation and credential abuse, not a novel exploitation primitive.

GitGuardian tested an ARTEX build against a fake GitHub repository with nine planted credentials and recovered eight using git log --all, git show and grep, with activity starting 6 to 13 seconds into the task and no secret scanner installed. Only two canaries were at HEAD; one recovered AWS key had been deleted a commit after it was added. The model made no attempts to use what it found. Microsoft separately observed agents harvesting OAuth application credentials and AI service API keys from public GitHub repos, and in one case moving from a client secret to Azure Key Vault data exfiltration in five minutes, with service principal sign-ins from 199.19.77[.]84 from October 28.

Exposed infrastructure is part of the picture. Check Point counted 2,557 systems that hosted or had hosted ARTEX panels, 1,608 live public instances and ten exposing the full database; Censys counted about 1,400 exposed consoles on November 4 and Check Point more than 1,800 the next day, using different methods. NSS confirmed 24 additional consoles. The unauthenticated GET /api/health and GET /api/auth/status endpoints identify a console and whether setup is complete. GitGuardian's secret-sprawl figures give the underlying scale: 28.65 million new hardcoded secrets in 2025 and 64 percent of valid secrets leaked in 2022 still active in 2026. Continuous scanning and prompt revocation matter more here than console takedowns alone.
