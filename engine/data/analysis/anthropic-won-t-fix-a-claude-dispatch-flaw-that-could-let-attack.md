Anthropic's Claude Dispatch feature lets any browser extension that can control Claude Dispatch make Claude Desktop run code on the local machine, or on a different machine signed into the same Claude account, with no browser exploit and minimal user interaction. The issue is a browser-extension remote code execution path in Claude Desktop's integration with Claude Dispatch. No CVE has been assigned, and the reporting seen so far describes no observed in-the-wild exploitation. Anthropic has been aware of the problem since May and has declined to remediate it, leaving a malicious or compromised extension with Claude Dispatch access able to execute commands across corporate boundaries.

The exposure is not hypothetical: one compromised extension reaches the host and every other machine signed into the same Claude account, which is how the flaw crosses corporate boundaries. This story matters more than the other thirty because it is the third extension-mediated Claude disclosure in roughly six months, following LayerX's ClaudeBleed finding in late April and Manifold Security's Claude for Chrome flaw, reported May 21 and published July 14 against Claude for Chrome v1.0.72 and still present in v1.0.80. Anthropic's pattern is to acknowledge these reports and close them while leaving the underlying trust boundary open, so each new variant reaffirms that extension access to Claude equals code execution on the endpoint.

There is no patch and none is coming from Anthropic, so defenders should restrict which extensions can reach Claude Dispatch and treat any extension with that permission as a full code-execution risk. Turn off hands-off automation so forged tasks still hit an approval box, and audit extensions with permission to read or change data on claude.ai. Hunt for extension content scripts that synthesize clicks on the Claude panel, telemetry showing event.isTrusted as false, data-task-id values such as usecase-gmail, usecase-gdocs, and usecase-calendar, open_side_panel messages, and side-panel URLs carrying skipPermissions or skip_all_permission_checks. The earlier Claude for Chrome flaw scored CVSS 7.7 High in default mode and 9.6 Critical with hands-off automation on, which bounds the severity of this class.

Watch for a CVE assignment, any confirmed in-the-wild exploitation, or Anthropic reversing its no-fix decision and shipping a patch to Claude Desktop or the Dispatch integration. A reverse shell or silent command beacon from a Claude Desktop host, or a new extension-trust bypass reported against Claude Code, would change the assessment from unpatched-but-unexploited to active.
