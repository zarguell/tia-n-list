MITRE ATT&CK v20 introduces nine Enterprise techniques and sub-techniques that catalog how adversaries abuse LLM interfaces, bypass MFA without prompts, and compromise water-utility PLCs exposed to the internet. The framework explicitly splits prompt injection into direct malicious instructions typed straight into an LLM interface and hidden instructions embedded in material the model ingests, plus a separate technique for using an organization’s own AI agents to steal data. For ICS, the new entry covers attacks on internet-exposed PLCs at more than 30 water and wastewater utilities in Minnesota that left operators locked out, making this the first ATT&CK campaign to quantify water-utility exposure at that scale.

This is not taxonomy housekeeping; it is a defensive gap map. The addition of application-specific password theft and CAPTCHA-bypass sub-techniques signals that MFA and bot-check evasion is now routine enough to warrant distinct tracking, which means defenders who rely solely on MFA prompts as an access control are missing a documented adversary path. The Minnesota water-campaign figure (more than 30 utilities) gives defenders an exposure benchmark: any utility with internet-facing PLCs should treat that count as a lower-bound proxy for national reach, not an isolated incident. The framework update also covers compromised dependencies in IDE and coding-agent configuration files, linking supply-chain risk directly to AI-assisted development environments.

Defenders should map existing detection rules to the new sub-techniques, especially AI-agent abuse, application-specific password theft, and CAPTCHA bypass, rather than waiting for vendor signatures. For water utilities, hunt for internet-exposed PLC access logs and operator-lockout telemetry; for AI-facing environments, audit LLM input pipelines for embedded instructions and monitor agent actions that access data outside their intended scope. MITRE does not provide patch versions or IoCs here, so the immediate action is taxonomy alignment and exposure reduction, not patch deployment.

A change worth watching is whether MITRE or CISA elevates any of these new techniques into the Known Exploited Vulnerabilities catalog or publishes associated actor mappings, since the framework currently describes tradecraft without binding it to active exploitation campaigns.
