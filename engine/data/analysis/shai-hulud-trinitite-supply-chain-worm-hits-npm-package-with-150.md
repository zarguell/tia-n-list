The Trinitite campaign compromised @7nohe/openapi-react-query-codegen, a TanStack Query code-generation library with over 150,000 weekly downloads. The malicious releases deploy an evolved Mini Shai-Hulud worm through a hidden binding.gyp execution path and a large obfuscated JavaScript loader, using changed campaign strings, encryption keys, and install-time execution compared to earlier waves. The attack leverages a pull-request comment trigger that executes npm publish inside GitHub Actions via OpenID Connect without confirming maintainer identity, giving attacker-controlled releases legitimate npm provenance even though the provenance only proves the automated workflow ran, not that the published code was safe. The first prerelease versions included a preinstall command that installed Bun and attempted to execute a missing file named is_it_this_simple.js.

This is not a routine dependency poisoning: the worm steals developer, cloud, CI/CD, package-registry, Kubernetes, Vault, and source-control credentials before propagating to additional packages. With 150,000 weekly downloads and legitimate provenance tokens masking malicious versions, the exposure surfaces every CI pipeline and developer workstation that pulls the package without version pinning. The mechanism matters more than the count because the same GitHub Actions OIDC design flaw identified by Deep Specter Research in reports that GitHub closed without action is now actively exploited, meaning patching the package alone does not close the platform-level vector.

Defenders should audit installations of @7nohe/openapi-react-query-codegen against malicious prerelease versions, scan for the preinstall Bun installation and the missing is_it_this_simple.js reference, and hunt for the hidden binding.gyp loader and credential-access telemetry in CI logs. Rotate any npm, GitHub, Kubernetes, or Vault credentials that touched environments building with this package, restrict pull-request comment triggers in release workflows, and require explicit maintainer confirmation before any GitHub Actions OIDC publishing runs. The provenance token is not evidence of safety; treat any unverified prerelease as hostile until proven otherwise.

Watch for expanded exploitation of the GitHub Actions OIDC design flaws reported by Deep Specter Research, which GitHub has already dismissed; if those same patterns spread beyond Trinitite, the next wave will hit with the same trusted provenance and faster spread. Also track whether the full worm payload appears in later releases, since the initial prerelease contained only partial capabilities and the complete loader is already present in the malicious versions.
