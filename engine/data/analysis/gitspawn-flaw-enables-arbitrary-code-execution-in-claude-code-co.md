Manifold Security researchers disclosed GitSpawn, a vulnerability class affecting AI coding agents that automatically execute Git commands when opening a project directory. The core issue is Git's `core.fsmonitor` configuration option, which lets a repository define a file-system-monitor helper program. Git reads this value from the repo's local `.git/config` file, meaning an attacker can plant an arbitrary command in a malicious repository's Git config. When an AI agent opens the project and runs routine background commands like `git status` or `git diff`, Git launches the attacker's helper program as part of its index refresh.

The attack requires zero user interaction. No prompt, no approval click, no authentication step. In some cases the malicious command executes before the developer has even authenticated to the coding platform. Affected tools include Claude Code, OpenAI Codex, Cursor, Grok Build, Goose, Hermes Agent, and Qwen Code. Essentially every agent examined by the researchers performed these background Git operations automatically.

This is a supply-chain class attack vector. A poisoned repository, shared via a link or cloned by a developer, becomes a remote code execution trigger the moment an AI coding agent touches it. The `core.fsmonitor` mechanism is a legitimate Git feature designed for performance, but its trust model assumes the repository is benign. AI agents break that assumption by running untrusted repo contents in a privileged local context. No CVEs have been assigned yet. Watch for patches from the affected agent vendors and for guidance on whether `core.fsmonitor` should be disabled or sandboxed in agent environments.
