Researchers found 13 malicious NuGet packages aimed at Windows .NET developers through a fake take-home job assessment. Socket researcher Kush Pandya said most of the packages posed as WinUI 3 and WPF button controls, and that in the versions analyzed, building or running the project began the malicious behavior. Dark Reading described the lure as Home Assessment work in a fake recruitment campaign. The packages were published where developers normally fetch UI components, so the interview task itself became the delivery mechanism.

The reported outcome is malware on developer machines and attacker access. The use of a hiring workflow matters because candidates are expected to compile and execute unfamiliar code, often on machines with cloud tokens, repository credentials and signing material. Publishing as ordinary NuGet packages puts the payload in the build path rather than in an email attachment, which can bypass security advice focused only on phishing links.

The available reports do not list the package names, the actor or a specific payload, so those details remain open. No CVE is attached to the campaign. Watch for the package identifiers from Socket's write-up, NuGet takedown notices, and whether the same assessment lure is reused in other language ecosystems or against other hiring platforms.
