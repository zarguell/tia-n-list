Socket's November 23 write-up identifies 13 malicious NuGet packages, 28 versions and four publisher accounts behind a lure repository created on November 4 that asks Windows .NET candidates to build and run a Mini File Vault & Tracker assessment. The build half, `VS_Builder.MSBuildAnalyzer` 1.2.7 bundled in the repository and the republished `HappyOne.MSBuildAnalyzer` 1.2.9, ships a targets file with `AfterTargets="Build"` and an output named `ForceExecuteNonExistenFile.txt` that nothing creates, so `dotnet MSBuildAnalyzer.dll` runs on every build and stages `OskSupport.dll` beside a copied `osk.exe` under `%LOCALAPPDATA%\osk\`. The runtime half, `VS_Builder.WinUI3Controls` 1.0.7, starts that hidden copy when the first FileButton control is created. `WinUI.Button` 1.0.0 takes a separate path and downloads `avast.exe` through the GitHub contents API into `%TEMP%\Launcher.exe`. No CVE is attached and Socket does not attribute the operation.

The reason to track this is not the package count but the delivery contract: a hiring assessment persuades the target to clone an unknown repository, restore from a feed the project names and execute the result on a working machine, after they have already decided the code is harmless. The two-package split also survives partial cleanup. NuGet deleted the VS_Builder packages on November 2, yet within about 39 hours HappyOne republished the analyzer under new IDs, and the lure moved between the NuGet feed and `.nupkg` files committed in its first two repository revisions. The roughly 160 downloads reported for `WinUI.Button` 1.0.0 are not victims, since mirrors and scanners inflate that count, but they do show how far a convincingly named button control travelled before takedown. The relevant loss is browser cookies, saved logins and GitHub, registry or cloud tokens from developer hosts that often hold repository and signing access.

There is no fixed version to upgrade to. Remove all 13 package IDs from project files, `Directory.Packages.props`, lock files, `obj/project.assets.json` and `%USERPROFILE%\.NuGet\packages`, pin restores to approved feeds with package source mapping and reject repository-local sources. Any host that built or ran the assessment or `CryptoWalletAnalyzer.exe` should be isolated and reimaged after checking for `%LOCALAPPDATA%\osk\OskSupport.dll`, `%LOCALAPPDATA%\osk\osk.exe`, `%TEMP%\Launcher.exe` and `vcruntime146_cor2.dll` beside the wallet app, then browser passwords, cookies and developer tokens rotated from a clean device. Hunts should cover `dotnet.exe` spawned by MSBuild with a DLL under a NuGet package `lib` folder, hidden `osk.exe` outside System32, targets containing `ForceExecuteNonExistenFile`, GitHub contents writes with commit messages `downloading new version` or `Backup`, `MyUpdater` and `CppHttp/1.0` user agents, and PowerShell `Win32_ShadowCopy` creation on developer endpoints.

The assessment changes if the unavailable second stages at `stevenleedig-ux/fantastic-giggle`, `Carol-White-Super/cloud` and `Best-Seller-Dev/dexTrader` are recovered, or if endpoint telemetry confirms successful side-load and credential theft rather than staging alone. The other trigger is attribution: the take-home lures resemble Contagious Interview, but Socket found no shared code or indicator, so a code-level link to a named actor would turn an unattributed supply-chain campaign into a tracked actor operation.
