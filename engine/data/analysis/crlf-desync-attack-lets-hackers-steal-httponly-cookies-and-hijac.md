Security researchers Tom Stacey (PortSwigger) and Tobia Righi (TurtleSec) have introduced a new attack category they call "CRLF-Powered Desync Attacks." The technique exploits CRLF header injection, an issue typically rated low severity, to trigger HTTP request desynchronization. When a proxy and backend parse HTTP traffic differently, an injected newline can split or reorder headers in ways that cause the proxy to forward a poisoned request as part of a legitimate session. The result: HTTPOnly cookie theft, full account takeover, and in some configurations, self-propagating desync worms that automatically replicate the poisoning across subsequent requests.

The attack chain works by injecting encoded CRLF characters (%0d%0a) into inputs that are later decoded by a reverse proxy. Differences between how proxies, CDNs, and backend applications interpret the resulting header boundaries create the desynchronization. Stacey demonstrated that this can bypass the HttpOnly flag on cookies, which is normally designed to prevent JavaScript access. Once a poisoned request is in the proxy's response queue, the attacker can hijack the session of any user whose request is routed through the same proxy path.

This research matters because CRLF injection is ubiquitous in web applications and is frequently dismissed as low-impact. The PortSwigger and TurtleSec findings reclassify it as a potential gateway to request smuggling, which has historically been one of the hardest vulnerability classes to detect and mitigate. Organizations running reverse proxies or CDNs should audit their CRLF handling and input validation immediately, particularly where authentication cookies are in play.
