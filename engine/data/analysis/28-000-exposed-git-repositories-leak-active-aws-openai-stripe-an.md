Intruder's gitreaper tool scanned 3.5 million internet-facing hosts (down from 40 million domains found via Certificate Transparency logs targeting app, admin, and dev subdomains) and found 28,000 publicly accessible .git repositories. These repos leaked active credentials for AWS, OpenAI, Stripe, GitHub, and other services. Unlike traditional git tools, gitreaper processes Git objects in memory without downloading full repos to disk, which matters when repos can range from megabytes to tens of gigabytes.

The root cause is a common web server misconfiguration: serving a .git directory over HTTP. Attackers can reconstruct repositories from the exposed objects, extract secrets from code history, and gain access to cloud infrastructure, payment platforms, and internal documents. The finding is a reminder that source code history is often a higher-value target than the current codebase itself, because credentials committed and later removed persist in Git objects indefinitely.

For defenders, the actionable items are straightforward: block HTTP access to .git directories at the web server or CDN level, audit existing repositories for committed secrets using tools like git-secrets or truffleHog, and rotate any credentials that may have been exposed. Organizations with public-facing development or staging servers are the highest-risk targets here.
