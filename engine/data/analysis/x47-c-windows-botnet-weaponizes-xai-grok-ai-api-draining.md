Qrator Labs published its write-up of x47.c on September 23, three days before the story surfaced here, and the seller's own advertisement dates to August 3. x47.c is a Windows botnet sold by the actor WraithTools at $200 for the base package, $150 for the DDoS add-on, and $950 for the full set with credential theft, SOCKS5 proxying, and AI-assisted persistence. The panel exposes 18 DDoS methods, from HTTP floods, slow HTTP, TCP and UDP floods, and a TLS stresser to reflection and amplification. Two modules set it apart: an AI API drain that takes a model name and a valid key for the target's OpenAI, xAI, or compatible chat account and bills it directly at the provider, and an AI Stealth module that queries xAI's Grok to pick persistence and concealment actions on the infected host, including Windows Defender exclusions, with local fallbacks when model calls fail. The assessment rests on seller advertisements, technical documentation, and panel screenshots; no confirmed infections accompany it.

The financial module is the threat, not the DDoS menu. OWASP calls this pattern denial of wallet, and its defining property is direction of travel: billable requests leave the victim's environment straight for the provider, so WAF rules, web logs, and application-side controls see nothing while the site stays up and the credits behind it burn. The seller pitched the drain against chatbots, AI-connected CMS platforms, trading bots, and competitors, and suggested automatic top-ups to keep charges accruing after a balance hits zero, which turns a capped nuisance into uncapped loss. The stealer already lists AI-site tokens among its targets even though the documentation stops short of showing them converted into drain keys; that gap is one script wide. There is no CVE and no patch cycle here, so the entire control surface is key hygiene and provider-side spend telemetry, which most organizations do not watch the way they watch their own logs.

Concretely: put hard spend caps and low per-key quotas on OpenAI and xAI accounts, disable automatic credit top-ups, and alert on anomalous token consumption in the provider dashboards, because your own infrastructure will not see the requests. Restrict egress to AI API endpoints to the specific hosts that need it, so a compromised server cannot bill your keys. On endpoints, audit Windows Defender exclusion lists for unapproved entries, watch for browser password, cookie, and Discord token theft, and treat unexplained outbound SOCKS5 relaying as a compromise signal. When triaging the botnet's fast-flux domains, note that several can resolve to a single server, so pivot on IP before sizing the infrastructure.

Two developments would move this assessment. Independent telemetry of real x47.c infections, or a victim report of a drain executed through it, would turn a capability sale into an active campaign. Proof that the stealer's harvested AI tokens are being converted into working API keys would fuse the credential theft and billing chains into one pipeline; precedent for the loss side already exists, since earlier reporting documents a stolen METR API key used to burn roughly $600,000 in AI credits. Qrator found no test results behind the advertised protection-bypass modes, so the claimed capabilities deserve skepticism until demonstrated.
