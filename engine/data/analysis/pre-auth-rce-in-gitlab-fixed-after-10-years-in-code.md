GitLab shipped a fix for a pre-authentication remote code execution flaw that had lived in its codebase for roughly a decade, reported via Red Hot Cyber and The Register. The Register's headline frames it as a max-severity bug allowing remote code execution across more than 12 years of releases, so any internet-facing GitLab instance that has not been patched should be treated as exposed. The Italian source notes a high score and a dangerous pre-auth RCE, corroborating the severity.

The practical takeaway is patching: update GitLab to the fixed release and review instances that were reachable before the patch for signs of exploitation. Since the flaw is pre-auth and affects a long span of releases, unpatched self-hosted and cloud GitLab deployments are at risk of full compromise. Watch for follow-up advisories naming the CVE and affected version ranges, and for any in-the-wild exploitation reports.
