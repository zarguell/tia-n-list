GitLab patched CVE-2026-110264, a max-severity pre-authentication remote code execution flaw in regular-expression compilation affecting GitLab Community Edition and Enterprise Edition, with affected releases dating back to GitLab 7.0 from June 2014, roughly 12 years of code. The bug is an integer overflow triggered by a specially crafted regular expression and could allow an unauthenticated user to execute arbitrary code on the GitLab server under certain conditions. GitLab released fixed versions 19.5.1, 19.4.3, and 19.3.6, with backports to 19.2.9, 19.1.9, 19.0.10, and 18.11.13, and GitLab-managed infrastructure including GitLab.com and GitLab Dedicated is already patched.

The exposure is severe because the flaw is pre-auth and spans more than a decade of releases, so any self-managed instance running an unpatched version is a full-compromise candidate rather than a data-exposure case. GitLab repositories typically hold source code, CI/CD configuration, deployment secrets, access tokens, infrastructure definitions, and connections to production environments, so server-level compromise opens credential theft, repository manipulation, supply chain attacks, persistence, and lateral movement. The Register's framing as a perfect 10 CVSS combined with that reach is what separates this from the routine GitLab advisories in the same window: the attack requires no credentials and the affected population is every long-lived self-hosted deployment, not a subset.

Defenders should upgrade to one of the fixed versions 19.5.1, 19.4.3, 19.3.6, 19.2.9, 19.1.9, 19.0.10, or 18.11.13 as soon as possible, and treat any instance that was internet-reachable on an older release as potentially compromised pending review of server logs, CI/CD runner activity, and newly created access tokens or deploy keys. GitLab also released two threat detections reported through its HackerOne program, which should be deployed alongside the patch, and self-managed operators should verify their version string before assuming coverage.

Watch for in-the-wild exploitation reports and for a follow-up CISA or KEV listing, since another max-severity GitLab CE and EE flaw drew active exploitation just days after disclosure, and for any narrowing of the "under certain conditions" qualifier that changes which deployments are actually reachable.
