GitLab fixed a pre-authentication remote code execution vulnerability that had existed in the codebase for roughly ten years. The flaw, tracked as CVE-2026-110264, scores CVSS 10.0 and allows unauthenticated attackers to execute arbitrary code. The fix was released after researchers highlighted the severity. Organizations running self-hosted GitLab instances should upgrade immediately, since a pre-auth RCE of this magnitude exposes the entire development pipeline and any stored secrets to remote compromise.

The vulnerability is especially concerning because of its long residence time in the code. A ten-year exposure window implies that attackers may have already discovered and exploited it quietly. Defenders should review access logs and instance integrity, not just apply the patch. No in-the-wild exploitation count has been confirmed in the event text, so claims of active campaigns should be treated cautiously until vendor or threat-intelligence confirmation appears.
