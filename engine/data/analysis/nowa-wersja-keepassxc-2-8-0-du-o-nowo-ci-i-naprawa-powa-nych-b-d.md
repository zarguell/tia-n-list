KeePassXC 2.8.0 fixes a set of security bugs, including CVE-2026-69150, a heap use-after-free in the legacy KeePass 1 (.kdb) importer. The importer kept stale pointers to entries after metadata streams were deleted, so importing a crafted .kdb file could call parseCustomIcons4() on already-freed memory. The CVE record from GitHub's advisory database describes the flaw as CWE-416 with local attack vector, high complexity, low privileges required and active user interaction, affecting KeePassXC versions below 2.8.0-beta1. The practical impact is an application crash and, in the worst case, theoretical arbitrary code execution; no proof of concept has been published. The same importer module carried an integer overflow and an out-of-bounds read.

A second fix concerns the browser integration, where native messaging packets between the extension and the main application were not size-validated before encryption or decryption, letting data be written past the allocated RAM buffer, an out-of-bounds write that could crash the process or potentially run code. The release also addresses SSH key handling on Windows: when passing a private key to the Pageant agent, KeePassXC used predictable names for the shared memory mapping holding the key, which a local process with user rights could reconstruct and read. The fix generates a unique random name for each mapping. Four further bugs are reported as awaiting CVE assignment.

KeePassXC 2.8.0 also brings a Qt 6 interface, database synchronization, SSH key generation, Wayland autofill support and improved passkey handling and password strength estimation. Because the affected paths require importing an untrusted database, opening a crafted .kdb file, or having a local process already running as the same user, the exposure is narrower than a remotely reachable flaw, but the browser-integration and Pageant fixes matter for anyone relying on KeePassXC as a secrets store on a shared or multi-user host. Upgrade to 2.8.0 and treat database files from unknown sources as untrusted.
