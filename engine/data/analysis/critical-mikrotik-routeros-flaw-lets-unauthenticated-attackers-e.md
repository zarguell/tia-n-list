CISA published ICSA-26-272-06 on September 29, 2026 for CVE-2026-84411, an integer underflow (CWE-191) in the HTTP request body handling of the MikroTik RouterOS web management service. The parsing bug is reachable before authentication, and a single crafted request can either execute arbitrary code as root or crash the device. All RouterOS releases earlier than 7.24 are affected. CISA scores it CVSS v3.1 9.8 with the vector AV:N/AC:L/PR:N/UI:N and CVSS v4.0 9.3; an anonymous researcher reported it, and the agency states no public exploitation targeting this specific vulnerability had been reported at publication.

The exposure that matters is the management interface facing an untrusted network, because that is the only position this bug needs. Root on a gateway router is not one compromised host: the attacker reads and rewrites everything transiting the device, can persist in configuration, redirect traffic, and reach the internal networks the router fronts. CISA places MikroTik deployments across the communications and IT sectors worldwide, and the pre-auth single-request property makes the flaw mass-scanner material the moment a working exploit appears. Context sharpens the risk in a way the event list does not: on September 3, 2026 MikroTik disclosed a separate, actively exploited RouterOS cluster, reported by CERT.pl as CVE-2026-67276, CVE-2026-86060 and CVE-2026-67277 and fixed in 7.25 beta 3, 7.24.2, 7.23.4 and 6.49.21. Attacker investment in exactly this platform is therefore demonstrably current, and no known exploitation for this bug is a statement about the hours since disclosure, not about attacker interest.

Patch first: the advisory's vendor fix line is 7.23 or later against an affected range of everything below 7.24, and the current builds on mikrotik.com/download are 7.24.4 in the stable channel and 7.23.7 in long-term, released September 16, 2026. Until devices are upgraded, remove the web management service from untrusted interfaces and use VPN for remote administration, per CISA's exposure-minimization guidance. For hunting, RouterOS writes web service messages under the www logging topic visible in /log, so review those entries for requests or errors from unexpected sources. Under MikroTik's standing compromise guidance, also inspect the configuration for unknown users, scripts and scheduler entries, and check for a critical Flagged entry, which RouterOS uses to mark suspected compromise. Any device that was internet-reachable and unpatched when the advisory landed cannot be cleared by the upgrade alone: verify its config or re-image via Netinstall, which reformats the disk.

Two developments would change this assessment. A KEV listing or an EPSS climb from the current 0.0 would signal confirmed exploitation and collapse the patching timeline, as would internet telemetry showing crafted requests against RouterOS web interfaces; the only indicator-bearing post in the event trail is a low-reliability aggregator claiming 6 IOCs and 9 detections without listing them, so nothing reputable has published yet. A MikroTik security notice naming the exact fixed builds would also matter, because as of the vendor feed's September 16, 2026 build the newest entry was still the September 3 MikroTrick item and CVE-2026-84411 had no vendor notice of its own.
