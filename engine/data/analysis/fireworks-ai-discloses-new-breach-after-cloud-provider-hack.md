Fireworks AI disclosed a second security incident on November 9, 2026, in which attackers reached its development machines through a third-party cloud provider that hosted Fireworks research and development systems. The provider experienced a security incident on October 23, and an unauthorized party used it on October 24 to access Fireworks development machines and run an unauthorized workload. The exposed data includes resource metadata such as resource identifiers, display names, descriptions, and creation times, billing and shipping addresses, invoice and payment history, account balance, and credit usage, plus incomplete model weights and datasets for some customers. Fireworks states it does not store payment card numbers and says it could not access customer production inference workloads or customer data stored outside the affected development environment.

This follows an earlier breach on October 6, 2026, in which attackers used internal credentials to access environment variables containing API keys and tokens stored as secrets for a limited number of accounts, activity Fireworks links to a financially motivated group pursuing LLMJacking, meaning the resale of unauthorized access to large language models through illicit routing gateways. After revoking compromised credentials and API keys, Fireworks discovered the second incident on October 23. Notion, which uses Fireworks to run open-weight models for Notion AI, confirmed that chat transcripts from fewer than 1 percent of workspaces were exposed; Notion learned of an exposed dataset on November 2, cut off traffic to Fireworks, deleted data from the vendor's systems, and halted training runs by November 3, while Fireworks confirmed customer data access on November 8.

Customers should rotate any API keys or tokens that passed through Fireworks, review third-party credentials referenced in vendor notices, and treat billing and metadata exposure as a credential-spraying and phishing risk rather than a payment card breach. Watch for Fireworks' final incident report, any expansion of the affected customer list beyond the currently notified accounts, and whether the same third-party cloud provider incident surfaces in disclosures from other tenants. Because the two incidents were linked through the same financially motivated actor, assume that data from the first breach informed targeting for the second until Fireworks rules that out.
