TIKTOUK is a hub-and-worker credential harvester for WordPress hosting, built from three parts: the Python scripts wp2s_poll.py and wp2s_crack.py and a stripped Go crawler named jscrawl-amd64. Each worker pulls target lists from a central HTTP hub, runs its collection task, and reports back to /v1/ingest or /api/crack/report. The poller probes REST batch routes with a malformed http://: path carrying DELETE /wp/v2/categories/0 and POST /wp/v2/block-renderer/core/paragraph, retrying in multipart encoding after a JSON 403. The collector fetches wp-config.php.bak, .env, .git/config, backup.sql and wp-content/debug.log, then decrypts stored mail credentials for WP Mail SMTP, Easy WP SMTP and FluentSMTP using the plugins' own key material, while the crawler sweeps site JavaScript for SendGrid, Anthropic, Bedrock and AWS-shaped tokens. LevelBlue SpiderLabs published the analysis on October 1, 2026; the two CVEs the story attaches, CVE-2026-60137 and CVE-2026-63030, were fixed by WordPress on July 17, 2026 in 6.8.6, 6.9.5 and 7.0.2.

The CVE linkage is the weakest part of the story framing. LevelBlue never demonstrated exploitation of either bug; the target simulator returned prepared responses, and the record shows the SQL injection (CVE-2026-60137, CVSS 5.9) and the batch-route confusion that turns it into RCE (CVE-2026-63030, CVSS 9.8) as context for the toolkit's request structures, not a proven kill chain. The collection path needs no unpatched WordPress at all, only exposed backup and configuration files and secrets nobody rotated, so it works against fully patched sites. What makes this story matter is scale and end state: the leaked TIKTOUK panel LevelBlue examined held roughly 50k server-side credentials across about 37k domains, including hundreds of actor-validated live AWS keys, and the collector derives an SES SMTP password from a stolen AWS secret. The victim's outcome is not defacement but someone else's spam, compute and model inference billed to their cloud account. CISA listing both CVEs on July 21 with a four-day federal remediation deadline confirms the RCE door is already being knocked on.

Defenders should patch to 7.0.2 or 6.9.5, or 6.8.6 on the 6.8 line, and treat KEV presence as evidence of active exploitation. Deny web access to the exact file set the collector pulls: wp-config.php.bak, .env, .git/config, backup.sql and wp-content/debug.log. Rotate SMTP and AWS credentials found in any exposed dump and audit AWS accounts for keys created around the compromise window. The specific hunt: REST batch requests containing http://: with nested author_exclude or UNION ALL SELECT, especially a JSON 403 followed by a multipart 200 to the same route, correlated with same-host fetches of the exposed-file set and submissions to /v1/ingest or /api/crack/report. Match hosts against the LevelBlue sample hashes for the three components and watch for traffic to 31.56.58.59, 193.32.162.134 and 195.178.110.209.

Two developments would change the assessment. Confirmed in-the-wild chaining of the batch-route confusion would move TIKTOUK from a hygiene threat to an active unauthenticated RCE campaign against default WordPress. Infrastructure churn is the other signal: LevelBlue is tracking additional panels and a related Go botnet binary with remote command execution capability (SHA1 9903f4576980ff7cfd560ca57c665a4b59b3c30d), so new panel addresses or a takedown of the known ones would show the operator reacting and possibly retooling.
