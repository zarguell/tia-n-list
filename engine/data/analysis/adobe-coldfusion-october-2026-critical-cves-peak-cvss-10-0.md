Adobe ColdFusion carries five critical CVEs from the October 13, 2026 Priority 2 update: CVE-2026-105899 (CVSS 10.0, CWE-434 unrestricted upload RCE), CVE-2026-106624 (10.0, CWE-94 code injection), CVE-2026-106622 (10.0, CWE-918 SSRF privilege escalation), CVE-2026-106612 (9.9, CWE-863 incorrect authorization), and CVE-2026-105903 (9.9, CWE-94 code injection). All affect ColdFusion 2025.0.13 and earlier and 2023.0.25 and earlier; patches are 2025.0.14 and 2023.0.26. The unauthenticated upload flaw is the worst - no credentials or user interaction required - and Adobe reports no exploits in the wild, but ColdFusion's history of active RCE exploitation makes the window for patching short.

This story demands attention because three of five CVEs score 10.0 and provide independent paths to full server compromise. The source event notes a single source and no confirmed exploitation, yet the exposure profile is high: ColdFusion runs enterprise applications in government, healthcare, and finance, and internet-facing instances are frequent targets for opportunistic scanning. A defender reading only the event list sees five CVE IDs and version strings; the real exposure is that an attacker needs only one successful upload to gain arbitrary code execution with the ColdFusion service account privileges, then can pivot to internal networks via the SSRF path.

Patch immediately to 2025.0.14 or 2023.0.26. Apply Adobe's security configuration settings and serial filter documentation, restrict dangerous file uploads (block .jsp and .cfm where unnecessary), deploy WAF rules against upload endpoints, and keep the JDK/JRE LTS current. Hunt for unexpected file uploads in ColdFusion logs, anomalous outbound HTTP requests from the server (indicating SSRF), and unusual process execution under the ColdFusion service account. The event references no specific IoC names, so focus on behavioral telemetry rather than a fixed indicator list.

Watch for confirmation of public proof-of-concept release or CISA KEV inclusion. Any shift from "no exploits in the wild" to active exploitation would change this from a patch-now advisory to an emergency response.
