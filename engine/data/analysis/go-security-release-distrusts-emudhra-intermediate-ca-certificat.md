Go 1.27.3 and 1.26.10, released on October 19, 2026, patch CVE-2026-111943 by making crypto/x509 reject any certificate chain passing through eight specific eMudhra intermediate CA keys whose private keys were stolen. The compromise was first reported to Mozilla and the Chrome Root Program on October 17, 2026, meaning the vulnerability window spanned at least two full days before Go, Firefox 158.0.1, and Chrome updated their blocklists. Any attacker who possessed the stolen private keys could have issued fraudulent TLS certificates trusted by Mozilla, Microsoft, Apple, and Chrome root stores during that interval.

The exposure is not theoretical for anyone running Go services: the event list notes the filter cannot be disabled, so rebuilt applications on unpatched Go versions will break when they encounter a chain using the revoked intermediates, but attackers with the stolen keys could also have served malicious certificates to clients before revocation. Because the eight intermediates chain to widely trusted roots, the blast radius extends well beyond Go to browsers, email clients, and any TLS client relying on the same root programs.

Defenders should upgrade to Go 1.27.3 or 1.26.10 immediately, verify no pinned certificate chains rely on the eight blocked intermediates by auditing logs for `crypto/x509` verification failures, and restrict outbound TLS handshakes from critical endpoints until patches are confirmed. Monitor Mozilla OneCRL and Chrome CRLSet feeds for the same key fingerprints and watch for follow-up disclosures from eMudhra about whether additional intermediates were affected.

Watch for confirmation from eMudhra Technologies Limited about the full scope of the compromise and whether any fraudulent certificates were actually issued using the stolen keys before October 17, because that would change this from a preventive revocation event to an active certificate-abuse incident requiring broader incident response.
