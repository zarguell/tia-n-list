ConnectWise suspended its Cloud Backup (formerly SkyKick), SaaS Security, and Cloud Management services after attackers abused a compromised application identity credential to sign in to Microsoft 365 tenants. The intrusion began around October 15, 2026, according to Huntress; by October 17, 2026, the vendor disabled seven application identities at 07:00 UTC, revoked certificates, and expanded containment to SaaS Security and Cloud Management. The event notes at least 162 Microsoft 365 tenants were accessed, with Huntress later confirming 173, and the company published the intrusion IP addresses plus M365 review guidance. No CVE is assigned, but the mechanism is a vendor-managed API secret abuse rather than customer-side misconfiguration.

This is a supply-chain breach with direct MSP impact: the compromised Cloud Backup identity signed in across 162-173 M365 tenants, meaning defenders must treat every tenant backed by the service as potentially exposed rather than only the vendor's own infrastructure. The suspension of Cloud Backup continues to interrupt scheduled backups, archive access, and restores, creating an operational dependency failure even where no data exfiltration is confirmed. ConnectWise has not provided a restoration timeline, and the gap between intrusion start (October 15) and vendor containment (October 17) leaves a 48-hour exposure window for log review.

Defenders should audit M365 sign-in logs for the shared intrusion IPs and the seven disabled application identities listed in the ConnectWise advisory, review Microsoft Graph access tokens granted around October 14-15, and verify that revoked certificates are no longer trusted in tenant app registrations. Watch for confirmation of unauthorized backup access or a revised tenant count, which would shift the assessment from exposure-only to confirmed data-access breach.
