The FakeGit malware campaign has reactivated with 17,610 malicious GitHub repositories, according to deafnews.it reporting. The operation uses a re-aiming mechanism that bypasses traditional blocklist defenses by redirecting payload delivery to new repos, evading takedown efforts. The campaign pushes SmartLoader / StealC malware. Security teams should audit GitHub Actions and developer dependencies for unexpected workflow changes, enforce repository allowlists, and treat any unverified GitHub-hosted payload as high risk.
