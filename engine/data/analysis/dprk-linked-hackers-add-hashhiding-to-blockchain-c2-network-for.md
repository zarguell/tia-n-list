Operators linked to the DPRK have added a new channel, dubbed HashHiding, to the Cross-Chain TxDataHiding (XCTDH) command-and-control scheme. HashHiding hides an active C2 IP address and port inside the recipient address of ordinary Ethereum transfers, letting infected systems recover attacker infrastructure without domains, smart contracts, or transaction payloads that defenders can blacklist. GBHackers reported the expansion, building on Ransom-ISAC's original disclosure of the campaign.

The earlier XCTDH mechanics remain instructive: the payload shipped in a malicious private GitHub repository impersonating node-react-e-commerce with code hidden in tailwind.config.js (SHA256 16df15306f966ae5c5184901747a32087483c03eebd7bf19dbfc38e2c4d23ff8), delivered via fake LinkedIn job offers. TRON wallets TMfKQEd7TJJa5xNZJZ2Lep838vrzrs7mAP and TXfxHUet9pJVU1BgVkBAbrES4YUc1nGzcG acted as indexes into BSC transaction calldata carrying XOR-encrypted JavaScript, with C2 at 23[.]27[.]20[.]143:27017.

The key detail is continuity: BSC sender wallet 0x9BC1355344B54DEDf3E44296916eD15653844509 was still in use in September 2026 samples, tying current activity to the same operator roughly a year on. Blockchain-resilient C2 defeats takedowns by design, so detection has to focus on the delivery chain, fake recruiter personas and trojaned repositories, rather than on infrastructure. Watch whether other DPRK crews copy the recipient-address encoding trick now that it is public.
