The DPRK-attributed campaign tracked as XCTDH now runs command-and-control across four blockchains at once. In September 2026 samples, Ransom-ISAC found a JavaScript module named _Z inside the C2's /init response: 69,470 characters of base-91 and control-flow-flattened code that deobfuscates to 8,777 bytes with one job. It scans Ethereum mainnet through public RPC providers (publicnode.com, drpc.org, blastapi.io) for transfers from the operator wallet 0x33ff3edaf55a8e03dcbc7cb40d498a49cd499891, reads the first six bytes of the recipient address as four IP octets and a two-byte port, fetches /boot from the decoded endpoint, and rebuilds the infection chain. The channel runs unconditionally on every infection, alongside the hardcoded C2 and the TRON/Aptos-to-BSC payload chain that delivers the DEV#POPPER.js Node.js RAT, now roughly 2,500 lines against 530 in October 2025, and OmniStealer, a Python harvester covering 153 wallet targets, browsers, password managers and cloud storage.

The significance is not that blockchain C2 exists but that this design removes every lever defenders normally pull. There are no domains to sinkhole and no contracts to delist; the recipient address is fabricated, holds no funds and is never reused, and the RPC endpoints are shared public infrastructure that cannot be blocked without breaking legitimate cryptocurrency use. The on-chain record shows how long this ran ahead of disclosure: the first beacon is 23 June 2026, so the Ethereum channel carried 2,655 transactions over about 90 days before either public writeup, while the unchanged BSC contract 0x9bc1355344b54dedf3e44296916ed15653844509 and XOR key tie it to the campaign first documented in October 2025. This is also not one actor's private trick. OpenSourceMalware documented the identical recipient-address encoding as NullReceiver in August 2026 inside different npm packages (bianira-ui@1.27.0, fluid-type-ui@2.0.8) under a different wallet, so at least two DPRK campaigns already ship it. Exposure is defined by who executes the lure, not by version ranges: no CVE exists, no patch will ship, and the targets are developers taking fake job tasks that lead to weaponised GitHub repositories and trojanised npm packages.

Detection has to lean on behavior and the published indicator set. Alert on eth_getBlockByNumber or eth_blockNumber JSON-RPC calls to public ETH endpoints followed by HTTP to non-standard IPs, and on Node.js processes launched with -eval strings containing global.i= or global.r=require. Ransom-ISAC's YARA logic keys on the wallet prefix 33ff3edaf55a8e03dcbc7cb40d498a49, the RS260605 marker, and the decode substrings .to.substring(2,10) and (10,14); the campaign marker global.i = '5-3-132' and the spoofed Python-urllib/3.13 user agent carrying a custom Sec-V header against /$/boot are additional tells. Block the full rotated C2 set, not the latest value: 23[.]27[.]20[.]187 on ports 80 and 443, 181[.]214[.]149[.]147:443, and the current 181[.]214[.]149[.]148 on 443 and 80. The last rotation changed a single final octet, 0x93 to 0x94, which is easy to miss in manual review and defeats exact-match blocklists holding only the previous address. The beacon cadence averages about 29 transactions per day, and Ransom-ISAC published the full 2,655-row transaction CSV for on-chain pivoting.

Two developments would change this assessment. A new signal wallet or a new RPC provider set would void every wallet- and YARA-based detection published so far, so watch the wallet's outbound history on Etherscan for a successor address. And if the recipient-address encoding surfaces in tooling beyond this actor, NullReceiver-style signaling should be treated as the DPRK ecosystem default rather than one campaign's refinement; the operator's path from EtherHiding through TxDataHiding to HashHiding shows tradecraft hardened each time it gets named and published.
