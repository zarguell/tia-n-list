Mior and Skyfall are two attacks published this week that let a malicious host read data inside AMD SEV-SNP-protected virtual machines, which are built to keep the server's operator out. Mior goes further than read access: it can modify a VM's memory and forge the signed attestation report that confirms which software the VM runs. Both attacks require control of the server's hypervisor, and Mior additionally requires control of the server's BIOS.

The ETH Zurich paper "Mior: Breaking AMD SEV-SNP with Device-as-Memory" is the primary source behind the coverage, with The Hacker News also reporting. The attacks target the trust assumption that a confidential VM's memory stays private from a rogue or compromised cloud host, and they show that SEV-SNP's protections can be bypassed when the host controls the hypervisor and, for Mior, the BIOS.

Organizations relying on SEV-SNP for confidential computing should watch for AMD firmware and microcode updates, guidance from cloud providers that offer SEV-SNP instances, and any changes to attestation verification procedures. Treat a malicious or compromised host as a live threat to confidential VM memory until mitigations are confirmed.
