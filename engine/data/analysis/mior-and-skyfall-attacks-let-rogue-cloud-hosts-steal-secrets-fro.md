Two attacks published on November 10, 2026 let a malicious cloud host read data inside AMD SEV-SNP confidential virtual machines. Mior, tracked as CVE-2026-0462 with CVSS 4.0 5.9, is an access-control granularity problem in SEV firmware that lets a malicious hypervisor redirect MMIO access and leave RMP entries uninitialized. The ETH Zurich paper, accepted at ACM CCS 2026, shows the host reading and modifying guest memory and forging signed attestation reports. The test platform was an EPYC 9135 on Zen 5, with Zen 3 and Zen 4 considered potentially affected. The attack needs hypervisor and BIOS or UEFI control plus a PCIe device, and it was reported to AMD on February 12, 2026 under embargo.

Skyfall covers two separate leaks. AMD's CVE-2026-40671, CVSS 4.9, is incomplete cleanup during VMRUN error handling that exposes SEV-SNP guest register state through a Transient Scheduler Attacks side channel. The EDK II side is CVE-2026-18448, CVSS 5.6, where missing TSA mitigations let a ring-0 attacker infer residual SMM state. Researchers tested on EPYC 7313 Zen 3 and EPYC 9124 and 9334 Zen 4, but not Zen 5. Public PoC code for Skyfall has been reported.

AMD lists five EPYC lines, 7003, 8004, 8005, 9004 and 9005. SEV firmware mitigation for Mior is dated August 12, 2026, platform initialization firmware is targeted for December 2026, and embedded variants for February 2027. Skyfall microcode is dated August 12 for those lines, with MI300A patched September 21 and embedded fixes running into April 2027. Only SEV-SNP is affected, not SEV or SEV-ES. The concern is not just memory confidentiality: forged attestation undermines the evidence a tenant uses to trust what is running in a confidential VM. Watch firmware and TCB levels, host BIOS access, and fresh coverage such as the November 18 GBHackers write-up on Mior.
