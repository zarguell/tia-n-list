Two attacks published this week break the confidentiality guarantee of AMD SEV-SNP virtual machines by letting a malicious host read data inside guest VMs. Mior goes further: it can modify a VM's memory and forge the signed attestation report that confirms which software the VM runs. Both require control of the server hypervisor, and Mior also requires control of the server BIOS or UEFI and a PCIe device. The work was embargoed until November 10, 2026; Mior was reported to AMD on February 12, 2026 and is published as an ACM CCS 2026 paper by ETH Zurich researchers, while Skyfall is an IEEE S&P 2027 paper by an ETH Zurich and Google team.

Mior is tracked as CVE-2026-0462 with a CVSS v4.0 score of 5.9. AMD's advisory describes insufficient granularity of access control in SEV firmware that lets a malicious hypervisor redirect MMIO access, leaving RMP entries uninitialized so it can read or modify confidential VM memory and forge attestation reports. The attack was tested on an AMD EPYC 9135 (Zen 5) and Zen 3 and Zen 4 are considered potentially affected. Affected products are five EPYC server lines (7003, 8004, 8005, 9004, 9005); SEV firmware mitigation is dated August 12, 2026, platform initialization firmware is targeted for December 2026, and embedded models for February 2027. Only SEV-SNP is affected, not SEV or SEV-ES. The advisory lists TCB values for SNP attestation next to each fixed firmware version.

Skyfall is tracked as CVE-2026-40671 (CVSS v4.0 4.9) for a microcode leak caused by incomplete cleanup during VMRUN error handling that exposes SEV-SNP guest register state through a Transient Scheduler Attacks side channel, and CVE-2026-18448 (CVSS v4.0 5.6) assigned by the EDK II project for missing TSA mitigations that let a ring-0 attacker infer residual microarchitectural state left by SMM. Skyfall recovers guest register state and disk encryption keys, reads three fixed cache lines per targeted page, and leaks decrypted microcode and SMM state. It was tested on EPYC 7313 (Zen 3) and EPYC 9124 and 9334 (Zen 4), and was not shown on Zen 5. Five EPYC lines receive microcode dated August 12, 2026, the Instinct MI300A receives a patch dated September 21, 2026, platform initialization firmware is targeted for November 2026, and embedded EPYC fixes are targeted between January and April 2027. The EDK II project lists no patched version as of the advisory, with platform firmware already available for EPYC 4004 and 4005.

The practical risk falls on tenants of confidential VMs whose cloud provider or data center operator controls the hypervisor: such an operator could read or alter guest memory and recover secrets such as disk encryption keys. Defenders should apply the AMD microcode and firmware updates, verify SNP attestation TCB values against the fixed versions, and follow the previously published TSA mitigations (AMD-SB-7029) for the EDK II issue. Only SEV-SNP deployments are in scope, and systems not using SEV-SNP are unaffected.
