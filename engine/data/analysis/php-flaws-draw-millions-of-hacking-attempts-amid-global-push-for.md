CVE-2026-109618 and CVE-2026-109619, collectively dubbed PHP2Shell, are two critical remote code execution flaws in PHP itself rated CVSS v4.0 9.2, discovered by Ryan Austin of Calif, Wiz Research, and OpenAI. The bugs allow unauthenticated command execution on a website server via PHP's multipart and session-upload-progress surface, and they affect PHP versions from 5 onward. Details leaked on Hacker News on October 20, 2026 before the coordinated embargo, prompting an emergency release on October 21, 2026 of PHP 8.5.12, 8.4.27, 8.3.36, and 8.2.35.

The exploitation volume is the real story: Cloudflare detected thousands of attempts in the ten hours before formal announcement, hundreds of thousands within two hours, and millions overall, while the Wordfence Firewall intercepted over 74,000 exploit or probing attempts across its 5,000,000 protected WordPress sites. Cisco Talos saw attack attempts within hours of disclosure and Arctic Wolf observed targeted servers being pushed to download additional software. No confirmed compromises had been recorded as of the initial reporting, which Wordfence attributes to the exploit's complexity rather than lack of attacker interest, meaning the exposure window for unpatched internet-facing PHP remains open and dangerous.

Defenders should install PHP 8.5.12, 8.4.27, 8.3.36, or 8.2.35, or a vendor package explicitly confirmed to contain both fixes, and restart every PHP worker; updating WordPress or the application layer does not update PHP. Hunt the PHP multipart and session-upload-progress request paths in web server and WAF logs, review for unexpected outbound downloads or webshells, and treat pre-announcement scan spikes as the IoC window. Watch for the first confirmed compromise reports and any follow-on payloads, since the scanning volume suggests a transition from probing to exploitation is likely.
