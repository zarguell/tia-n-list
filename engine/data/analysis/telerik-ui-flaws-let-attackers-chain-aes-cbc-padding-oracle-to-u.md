Security researcher Marcio Almeida from Tanto Security disclosed a vulnerability chain in Progress Telerik UI for ASP.NET AJAX that turns an unauthenticated AES-CBC padding oracle into remote code execution. The affected component is RadAsyncUpload, which processes encrypted client-controlled state using AES-CBC with PKCS#7 padding. The server exposes different behavior for invalid padding versus valid padding that decrypts to malformed JSON, creating a classic padding oracle. Versions 2010.1.309 through 2026.2.519 are affected; Progress Software says version 2026.2.708 (2026 Q2 SP1) prevents exploitation.

The attack chain works by repeatedly modifying encrypted _serializedConfiguration and metaData fields, using server responses to infer plaintext and construct chosen ciphertext. Because CBC provides no integrity protection, researchers could recover intermediate block values, forge configuration objects, and ultimately achieve RCE without authentication. The practical impact is severe: any ASP.NET application running an affected Telerik version with RadAsyncUpload exposed is vulnerable to full compromise from the network.

This is the latest in a long series of Telerik deserialization and cryptographic vulnerabilities that have been actively exploited in the wild since at least 2017. Organizations running legacy .NET applications with Telerik UI should treat this as urgent, even though the fix requires upgrading to 2026.2.708. Many enterprise environments have difficulty updating third-party UI components quickly, which means exploitation windows can persist for months.
