A Checkmarx investigation revealed an ongoing npm supply-chain campaign centered on the package "indexed-btree," which impersonates the legitimate "sorted-btree" library and has accumulated over 2 million weekly downloads. The campaign also involved nine additional malicious packages (btree-core, btree-leaderboard, priority-slot-queue, and others) that were removed from npm after discovery. The attackers built a convincing GitHub repository with fabricated commit history and a curated developer profile to sell the disguise.

The key innovation is how the malware bypasses GitHub's June 2026 install-script defenses. Rather than using preinstall or postinstall scripts (which npm v12 now blocks by default), the loader hides inside the BTree.prototype.set() method. When a developer calls this function with a specific key value at runtime, it triggers sharedLoad.min.js, which executes the first-stage payload. This evades install-time scanning entirely, since installation appears clean. The malware collects system details (hostname, CPU, architecture, uptime) and exfiltrates them via hardcoded Slack and Telegram channels. A second-stage payload is retrieved from an Ethereum smart contract on the Sepolia test network, decrypted using X25519 key exchange.

The attackers' wallet holds 109 ETH. The malware includes a cleanup routine that can delete its files and remove the trigger from the package code to erase traces. Developers who installed any of the affected packages should rotate all secrets and restore their environment from a clean backup. This campaign demonstrates that install-time defenses alone are insufficient; runtime behavioral analysis is now essential for npm package security.
