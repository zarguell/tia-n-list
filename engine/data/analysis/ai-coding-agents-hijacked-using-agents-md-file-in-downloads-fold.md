Forever Security published its original disclosure on October 22, 2026, after finding a malicious AGENTS.md instruction file in a customer's ~/Downloads folder that was also the working directory of an AI coding agent. The agent tried to install a rogue npm package named function-color. The researchers reproduced the behavior against OpenAI Codex and showed a related Claude Code technique that leaks OAuth tokens and hijacks an account using only instructions placed in the working directory. AGENTS.md and CLAUDE.md files are plain text project instructions that agents read automatically, so the attacker needs no executable and no prompt injection in a chat session.

A later report describes a malware campaign using compromised GitHub content to target developers who use coding assistants. It says the malware can steal developer credentials, alter local agent configuration files and use stolen access to poison repositories that other developers may later open. That extends the risk beyond one machine: an agent that follows a poisoned instruction file can install packages or change settings with its existing permissions, and a compromised developer account can seed the same instructions into repositories that other agents read.

The design problem is the absence of a trust boundary between a directory's instruction files and the agent's tool access. As the Forever Security researchers put it, there is nothing for OpenAI or Anthropic to patch in the basic behavior, because loading the local instruction file is what the agent is built to do. Defenders should scan working directories and cloned repositories for unexpected AGENTS.md or CLAUDE.md changes, watch for installs of packages such as function-color, and treat agent configuration edits and OAuth token access as compromise indicators. Watch for vendor changes that add validation or sandboxing for instruction files in untrusted directories.
