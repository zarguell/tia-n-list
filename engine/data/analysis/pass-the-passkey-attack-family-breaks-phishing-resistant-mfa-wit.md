SpecterOps disclosed more than 20 Pass-the-Passkey techniques that undermine WebAuthn passkey protections across Windows 11, Microsoft Entra ID, browsers, password managers, and enterprise authentication workflows. The attacks do not break FIDO2 cryptography and do not extract private keys from hardware security keys or device enclaves. Instead they target the ecosystem around passkeys: endpoint logging gaps, weak server-side assertion validation, authentication prompts, and application interfaces. The result is that passkeys, marketed as phishing-resistant, can be replayed or abused without touching the private key.

The most serious chain combines a Windows event logging flaw with insufficient WebAuthn assertion validation in Microsoft Entra ID. Before Microsoft's remediation, Windows recorded complete WebAuthn assertion responses in the Microsoft-Windows-WebAuthN/Operational event log. An assertion is a signed authentication response containing the credential identifier, authenticator data, challenge-related information, user handle, and a cryptographic signature. It is not the private key, but it is sensitive authentication material that should not be reusable outside the original login transaction. SpecterOps found that users with local access to an affected system could retrieve these assertions, and a server that validates assertions too loosely accepts them in new sessions.

The research challenges the assumption that passkeys are inherently replay- and session-abuse-proof. Organizations rolling out passkeys should treat the protection as dependent on correct implementation on both endpoints and servers, not as automatic. Server-side assertion validation, event log hygiene, and prompt handling all need review. Microsoft has remediated the specific Windows logging issue, but the broader technique family remains relevant for any WebAuthn deployment.
