Workflow Identity Hijacking is a new attack technique disclosed by Noma Labs researcher Sasi Levi that lets external attackers exfiltrate data from enterprise AI automations without prompt injection or stolen credentials. The attacker submits seemingly benign requests to AI-powered workflows, but those requests inherit the workflow's own identity and permissions. The AI agent processes the request using its authorized access to internal data sources, then returns the results to the attacker through normal response channels.

The core problem is that AI workflows often execute with elevated privileges: database access, file system reads, API calls to internal services. When an external user can trigger those workflows, the data flows back to them through the workflow's output. The attacker never needs to bypass authentication because the workflow itself is doing the authenticated work. Levi's research shows this works across multiple enterprise AI platforms where workflow triggers are exposed to external input.

This is an identity and access management problem masquerading as an AI problem. Organizations deploying AI agents with data access need to treat every workflow trigger as an untrusted input boundary. The fix is not better prompt filtering. It is strict scoping of what data the workflow can access, rate limiting on external triggers, and output validation that prevents bulk data exfiltration through legitimate-looking responses.
