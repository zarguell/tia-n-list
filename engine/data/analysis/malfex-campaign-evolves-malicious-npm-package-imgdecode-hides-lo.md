The MALFEX-linked npm package `imgdecode`, published by `malfexteste8` on September 30, 2026, delivers a native-loader payload inside versions 1.0.0 through 1.0.3. Its compiled Node.js addon is triggered by a nine-line JavaScript file that loads a Windows DLL; the DLL then fetches an encrypted payload from GitHub and injects it into `dllhost.exe`. SafeDep documented the behavior on October 13, 2026, and additional coverage notes 979 downloads to date, confirming the package remained available on the registry after disclosure.

This story demands attention because it moves supply-chain malware out of pure JavaScript and into compiled native binaries, which bypasses many static-analysis and dependency-scanning tools. With only 979 downloads the infection footprint is small, but the technique scales: any build pipeline that installs native `.node` modules without inspection is exposed. The use of `dllhost.exe` injection links the loader directly to the broader MALFEX Windows stealer and remote-access tool chain, making this not just a malicious package but an active delivery mechanism for post-compromise payloads.

Defenders should audit all `node_modules` trees for the `imgdecode` package or its compiled `.node` artifact, hunt process-creation events involving `node.exe` spawning `dllhost.exe`, and restrict npm installs to pinned, verified versions. Remove any occurrence of `imgdecode` 1.0.0-1.0.3 immediately; network restrictions should block the GitHub payload URL referenced by SafeDep if telemetry shows outbound fetches. Log paths to inspect include Node.js `require()` traces for `imgdecode` and Windows process-monitor data around the DLL load sequence.

Watch for npm registry removal of `imgdecode` and suspension of the `malfexteste8` publisher, and for Checkmarx or CloudSEK updates linking this loader to additional MALFEX packages. A second native-addon loader appearing in a different npm publisher account would confirm the technique is being replicated rather than contained to a single actor.
