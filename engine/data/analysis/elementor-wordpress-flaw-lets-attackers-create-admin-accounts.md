A CSRF vulnerability in the Elementor WordPress plugin lets an unauthenticated attacker create administrator accounts. The attack needs a logged-in administrator to open a malicious link; the victim's then-authenticated session performs a REST API action the attacker chooses, and on default installations the result is a new admin account under attacker control. Elementor runs on 10 million sites, and the flaw affects only versions 4.3.0 and 4.3.1, which WordPress.org stats put on up to 2 million sites.

Patchstack, which reported it on September 22 after receiving it from hunter Saggre, traced the bug to Elementor's Editor Events module: it checks the raw request URI for the elementor/v1/events/ path and skips WordPress REST nonce validation when that string is present. Because the URI carries attacker-controlled query parameters, the path can be appended to requests aimed at other REST endpoints. Elementor shipped a fix in 4.3.2 two days after the report. No CVE identifier has been assigned yet.

Admins running 4.3.0 or 4.3.1 should update immediately, since a single logged-in admin click yields full site takeover. Watch for CVE assignment, proof-of-concept code, and exploitation reports given the plugin's install base, plus any similar nonce-bypass patterns where URI substring checks gate authentication.
