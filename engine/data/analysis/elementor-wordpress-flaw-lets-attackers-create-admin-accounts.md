A cross-site request forgery (CSRF) vulnerability in Elementor Website Builder plugin versions 4.3.0 and 4.3.1 allows an unauthenticated attacker to create administrator accounts by tricking a logged-in WordPress administrator into clicking a malicious link. The root cause is in Elementor's Editor Events module: the `bypass_nonce_check_for_own_routes` filter checks the raw `$_SERVER['REQUEST_URI']` for the literal substring `elementor/v1/events/` and, when found, returns `true` from `rest_authentication_errors` at priority 0. Because `rest_authentication_errors` is a shared filter, returning `true` asserts authentication success to every downstream handler, including WordPress core's `rest_cookie_check_errors`, which skips nonce verification entirely. The attacker-controlled query string means any REST endpoint can be weaponized simply by appending the bypass parameter, and WordPress's `_method` override allows a GET navigation to perform a POST action such as creating an admin user. This vulnerability has been assigned CVE-2026-62062 by Patchstack; the researcher who reported it is identified as Saggre; Patchstack received the disclosure on 22 September 2026; Elementor released the fix in version 4.3.2 on 24 September 2026.

The exposure is substantial: Elementor runs on over 10 million WordPress sites, and WordPress.org statistics show up to 2 million sites running the vulnerable 4.3.0 or 4.3.1 releases. A single malicious link delivered by email, chat, or comment is sufficient; no JavaScript, attacker-controlled page, or submitted form is required. Once the logged-in administrator clicks, the attacker can execute any REST API action permitted by the victim's account, not just the user-creation endpoint. The blast radius covers the entire site's REST surface, including endpoints from other plugins. The fix in 4.3.2 replaces the raw URI check with a read of `$wp->query_vars['rest_route']` (the resolved route after rewriting, with the query string already separated) and anchors the comparison with `0 === strpos(...)`, so the namespace must appear at the start of the route rather than anywhere inside it, and an `is_string()` guard prevents array-based injection.

Defenders should upgrade Elementor to 4.3.2 or later immediately. Network-level workarounds are limited because the attack is delivered through the victim's authenticated session and does not require a specific attacker-controlled hosting infrastructure. Hunting should focus on unexpected administrator-account creation events in WordPress audit logs (`/wp-json/wp/v2/users` POST responses with HTTP 201 and new `administrator` roles) and on REST API access patterns that include `elementor/v1/events/` in the query string against non-event endpoints. Review web server access logs for `GET` requests to `/wp-json/wp/v2/users` (or other REST endpoints) containing the bypass substring in query parameters, especially when paired with a `_method=POST` override. There is no evidence yet of in-the-wild exploitation telemetry specific to this CVE, but the mechanism is simple enough for rapid weaponization given the install base.

Watch for public proof-of-concept releases targeting the `elementor/v1/events/` bypass, for CISA KEV inclusion of CVE-2026-62062, and for any similar nonce-bypass patterns in other plugins that use unanchored `strpos()` checks on attacker-controlled URI strings inside authentication filters. The vulnerability demonstrates a broader design risk: `rest_authentication_errors` is a shared authentication channel, and returning a truthy value asserts success globally rather than opting out locally. Any plugin that hooks this filter should return `$result` unchanged unless it genuinely intends to override authentication for all downstream handlers.
