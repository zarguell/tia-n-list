A CSRF vulnerability in Elementor Website Builder versions 4.3.0 and 4.3.1, assigned CVE-2026-62062 with CVSS 8.8, lets an unauthenticated attacker create administrator accounts by tricking a logged-in admin into clicking a malicious link. The Editor Events module skips WordPress REST nonce validation when the raw REQUEST_URI contains the string elementor/v1/events/, allowing attacker-controlled query parameters to ride an authenticated session. Patchstack received the report from researcher Saggre on 22 September 2026; Elementor fixed it in version 4.3.2 released 24 September. The plugin is active on roughly 10 million sites, with WordPress.org statistics showing up to 2 million installations running the vulnerable releases.

The flaw is practical because it requires no authentication from the attacker, only a single click from an admin already logged into a WordPress site. The REST endpoint misuse is narrow but sufficient: the bypass relies on a literal string match against the raw URI rather than the resolved REST route, meaning any endpoint can carry the malicious payload as long as the URI contains the literal path segment. BleepingComputer and Patchstack both confirmed the mechanism and patch timeline on 25 September.

Site operators should upgrade Elementor to 4.3.2 or later, audit admin accounts for unexpected creations since 22 September, and treat any CSRF-triggered REST endpoint as suspicious until the plugin is patched. Watch for further Patchstack or Elementor changelogs covering related Editor Events module weaknesses.
