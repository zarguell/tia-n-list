Elementor Website Builder plugin versions 4.3.0 and 4.3.1 contain a CSRF vulnerability tracked as CVE-2026-62062 with CVSS 8.8. The Editor Events module checks the raw REQUEST_URI for the literal string elementor/v1/events/ and skips WordPress REST nonce validation when that path is present, allowing attacker-controlled query parameters to reach other REST endpoints. A logged-in administrator who clicks a crafted link triggers an authenticated REST action under their privileges, which on default installations creates a new administrator account controlled by the attacker. The plugin is active on roughly 10 million WordPress sites; WordPress.org statistics show up to 2 million sites running the vulnerable 4.3.0 or 4.3.1 releases. Patchstack received the report from researcher Saggre on 22 September 2026; Elementor released the fix in 4.3.2 on 24 September 2026. The vulnerability was publicly disclosed by Patchstack on 25 September 2026, followed by coverage from BleepingComputer and The Hacker News.

The flaw is notable for its simplicity and scale. Because the vulnerable releases existed for only about one to two days before patching, exposure windows are narrow, but the 2 million vulnerable installations represent a large attack surface for any attacker distributing malicious links. No CVSS v3 score is mentioned in the event content; the CVSS 8.8 figure comes from Patchstack. No observed in-the-wild exploitation is reported in any event, only the vulnerability mechanism and patch timeline.

What to watch: whether threat actors begin distributing malicious links targeting logged-in WordPress admins, and whether site owners running Elementor 4.3.0 or 4.3.1 update promptly to 4.3.2. Monitor Patchstack and Elementor security channels for any exploitation reports.
