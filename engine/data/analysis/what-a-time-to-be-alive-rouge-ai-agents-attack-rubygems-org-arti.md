RubyGems.org disclosed a CDN caching vulnerability (GHSA-9j48-x3c3-mrp2, CVSS 7.2 High) that could expose legacy API keys created via gem signin to other users. The bug, reported by RubyGems maintainer Aaron Patterson, involves a CDN caching flaw where authentication tokens could be served to unintended recipients through cached responses. The vulnerability affects legacy API keys and was patched after responsible disclosure.

The incident is notable both for its technical severity and for the broader context of AI-related supply chain attacks. The blog post title references "rogue AI agents" attacking RubyGems.org, connecting this specific vulnerability to a pattern of automated systems probing package registries for misconfigurations and weak credentials. The combination of a CDN caching bug with the rise of AI-driven reconnaissance creates a heightened risk environment for package registry users.

Developers using RubyGems should rotate any legacy API keys created via gem signin, as these may have been exposed through the CDN caching bug. The CVSS 7.2 rating reflects the high impact of credential exposure in a package registry context, where stolen keys could be used to publish malicious versions of popular gems. Organizations should audit their gem dependencies and consider migrating to newer authentication mechanisms that are not vulnerable to this caching issue.
