Apache's 23 November 2026 batch covers 33 flaws across nine projects, and the named critical is CVE-2026-86155, a CVSS 4.0 10.0 SSRF in Apache Jena Fuseki's SHACL validation service. The original advisory says SHACL SPARQL targets let a caller make the server issue HTTP requests, affects Fuseki through 6.2.0, and fixes the issue in 6.3.0; it credits MopMonk-AI and Immanuel Tikhonov. The same oss-security batch also carries CVE-2026-124324, a critical bypass of localhost-only administration controls through SERVICE operations, plus CVE-2026-86156 path traversal via SPARQL Update, CVE-2026-86154 in Turtle parsing and three other Jena advisories. All seven Jena issues affect 6.2.0 or earlier and are fixed in 6.3.0. No exploitation is reported.

The batch count matters less than the combination inside Jena. Fuseki's documented default leaves SPARQL endpoints open to the public while restricting administration paths under `/$/` to localhost. CVE-2026-86155 gives an unauthenticated caller a way to make the server issue requests, and CVE-2026-124324 says SERVICE operations can bypass those localhost-only administration restrictions. The advisories do not assert one chained exploit, but the two findings sit on the same query path and the same fixed release, so a reachable SHACL endpoint should be treated as a control-plane risk rather than only an outbound-request nuisance. Public-facing triplestores and internal knowledge-graph services running 6.2.0 or earlier are the exposed population, and an inventory that stops at HTTP Server will miss the other eight projects in this batch.

Upgrade Jena and Fuseki to 6.3.0, the version named in all seven advisories. Until that lands, restrict access to the SHACL endpoint at `/ds/shacl` and to SPARQL Update, keep `/$/` administration paths bound to localhost as documented in `$FUSEKI_BASE/shiro.ini`, and deny outbound HTTP from Fuseki hosts to internal metadata and administration services. Shiro restrictions alone are not sufficient while the bypass is unpatched. Hunt proxy and web logs for POSTs to `/ds/shacl` carrying SPARQL SERVICE terms in submitted shapes and for unexpected remote requests to `/$/` paths; review the `[urls]` rules in `shiro.ini` to confirm patterns such as `/**/query` are intentional, and change the documented default admin credential before exposing any endpoint. Restart after any Shiro change.

The assessment changes if telemetry shows SERVICE terms from SHACL validation reaching administration endpoints, or if a proof of concept appears for CVE-2026-86155 or CVE-2026-124324. The other development to watch is per-project mapping for the remaining fixes in the 33-flaw batch: no advisory in the available reporting assigns versions or severity to the nine-project total beyond the Jena advisories. Absent either signal, this remains an inventory and patching problem, not an incident response trigger.
