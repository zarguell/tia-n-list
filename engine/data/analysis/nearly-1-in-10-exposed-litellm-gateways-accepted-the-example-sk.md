Wiz Research scanned 3,074 internet-facing LiteLLM gateways on Shodan in February 2026 and found 294 (9.6%) accepted "sk-1234," the example admin key from LiteLLM's own setup guide. In 191 of those cases, no master key was set at all, meaning any credential would work. The remaining had the default value left in place. A second scan in August found over 85,000 instances, though Wiz says most appear to be honeypots or test systems. The default key grants full admin access to all stored API keys, every prompt and reply passing through the gateway, and the cloud IAM credentials of the host machine.

The attack path to cloud credentials is straightforward: an admin can create a pass-through endpoint pointing at the instance metadata service, and LiteLLM forwards x-pass-* headers with the prefix stripped, satisfying IMDSv2 requirements. This is not treated as a vulnerability by the project because its threat model considers administrators trusted. However, the combination of default credentials and the pass-through feature creates a realistic path from exposed gateway to cloud compromise. CISA added LiteLLM CVE-2026-59822 (CVSS 8.8) to its Known Exploited Vulnerabilities catalog on September 2, with federal agencies required to remediate by September 16.

Microsoft documented a real-world case where attackers exploited CVE-2026-42271 and CVE-2026-48710 to run commands inside a LiteLLM gateway, extract the master key and provider keys from environment variables, and access the underlying PostgreSQL database. The attackers gained access through an exposed gateway matching this exact attack chain. Upgrading to LiteLLM 1.84.0 or later addresses all known flaws, but changing the default key requires no upgrade and closes the most common entry point.
