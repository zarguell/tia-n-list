Over 8,300 Internet-exposed Gitea instances remain unpatched against CVE-2026-60004, a critical code injection vulnerability actively exploited in remote code execution attacks. Reported by Salesforce security researcher Shai Rod, the flaw allows authenticated attackers to execute arbitrary shell commands as the Gitea service account by submitting malicious patches via the diffpatch API endpoint. Gitea released version 1.27.1 on July 27 to address the vulnerability.

The exploitation barrier is low because Gitea ships with self-registration enabled by default. An unauthenticated visitor can register an account, create a repository, and gain the write access needed to trigger the vulnerability. The diffpatch endpoint can be abused to install and execute a Git hook from repository-controlled content, bypassing intended isolation controls.

Shadowserver's warning that nearly 8,400 instances remain unpatched weeks after the fix was released indicates slow patch adoption across the Gitea ecosystem. Organizations running self-hosted Gitea instances should immediately verify they are running version 1.27.1 or later, disable self-registration if not needed, and audit for signs of compromise. The combination of active exploitation, low attack complexity, and large unpatched population makes this a high-priority remediation target.
