CrowdSec disclosed that the May 2026 TanStack npm supply-chain compromise enabled attackers to clone approximately 170 private GitHub repositories, exposing internal source code, SaaS console components, data-science scripts, automation code, and limited sensitive contact data. The intrusion was traced to a former employee's GitHub OAuth token, which attackers obtained through the broader TanStack compromise attributed to TeamPCP (also tracked as UNC6780). CrowdSec emphasized that production infrastructure, databases, CI/CD pipelines, and open-source code were not altered.

The attack chain: TeamPCP compromised the TanStack npm ecosystem on May 11, backdooring 42 packages with credential-harvesting malware called Shai Hulud, which targeted GitHub tokens, cloud credentials, SSH keys, and other developer secrets. Between 05:52 and 06:01 UTC on May 22, an attacker used the compromised CrowdSec employee's OAuth token to download roughly 170 private repositories from an IP geolocated to Toronto (UTC-4 timezone). On September 16, the attacker published an archive of the repositories on a breach forum.

The incident illustrates the cascading risk of supply-chain compromises. The TanStack backdoor was designed to harvest developer credentials broadly, and CrowdSec was one of many downstream victims. The gap between May 22 (exfiltration) and September 16 (public leak) gave CrowdSec time to rotate credentials and assess impact, but the source code exposure is permanent. The breach forum posting suggests the attacker's primary motivation was reputational damage or extortion rather than immediate financial gain.

Supply-chain attacks on npm packages have become a primary vector for compromising downstream organizations. The CrowdSec case demonstrates that even security-focused companies are vulnerable when their developers' environments are compromised. Organizations should audit their dependency trees and implement token-scoping policies that limit the blast radius of individual OAuth tokens.
