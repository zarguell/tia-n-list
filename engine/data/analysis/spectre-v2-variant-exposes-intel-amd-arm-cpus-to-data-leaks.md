Researchers at the VUSec group at Vrije Universiteit Amsterdam and Scuola Superiore Sant'Anna disclosed Branch Target Reuse, a Spectre v2 variant that survives JIT code replacement on Intel, AMD, and Arm CPUs. When a JIT engine frees compiled code and writes new code into the same addresses, the CPU keeps stale indirect branch targets and speculatively jumps into the new code at obsolete offsets, a speculative execute-after-free primitive. The team built two end-to-end exploits against the Linux kernel's classic BPF engine, including one that leaks the root password hash from a running su process at 8 bytes per second on a modern Intel CPU with all enabled mitigations in place, and bypasses cBPF constant blinding (bpf_jit_harden) by encoding gadgets in jump offsets. Feasibility was shown for SpiderMonkey in Firefox and for Oracle GraalVM, with the full paper accepted at CCS in November 2026.

This is not one bug with one patch, and that is the argument for ranking it above the day's routine CVE churn: the researchers confirmed the desynchronized branch predictor on every CPU they tested, so mitigation exists only in software, engine by engine. The kernel fixes shipped quietly on 2026-07-25 as CVE-2026-64507 and CVE-2026-64508, two months before any public coverage connected them to a working attack, so fleets that defer hardening CVEs are the exposed population and most have already been running vulnerable 5.18-and-later kernels. The unprivileged surface is cBPF, which remains loadable by unprivileged users and underpins seccomp sandboxing in container runtimes, Chrome, and socket filtering, so the common posture of disabling unprivileged eBPF closes nothing here. The GraalVM result cuts at a different audience: BTR jumps past the arena masking that the sandbox's strictest Spectre-hardened mode relies on, meaning a deliberately hosted plugin or user script can reach outside its cage. A successful run reads arbitrary kernel memory, as the su password-hash demo shows, slowly and without tripping any current log-based detection.

Patch to kernel 6.1.183, 6.6.145, 6.12.97, 6.18.39, 7.1.4, or mainline 7.2, which carry both CVEs; on x86 verify the IBPB-on-BPF-JIT-reuse change from stable commits 25dbcd31781e and 1fbafd5235ca landed in your build. Update GraalVM to a build containing pull request 14261, which randomizes runtime code cache mappings. Keep bpf_jit_harden enabled: the researchers bypassed constant blinding via jump offsets, but race-free Indirect Branch Tracking plus blinding is the strongest stack they describe, with Intel Lion Cove the first race-free generation they found. Mozilla chose site isolation over predictor flushes, so until it fully ships, treat same-address-space tabs in Firefox as one trust domain. There is no log signature for speculative execution, so hunt exposure and mechanics instead: inventory kernels against the fixed versions, find hosts where unprivileged users can install seccomp filters, find GraalVM or GraalPy services running untrusted guest code, and review audit records for rapid seccomp filter install and remove cycles, which match the exploit's train-then-swap pattern.

Two developments would change this assessment. An end-to-end SpiderMonkey exploit would matter most, since only a proof of concept exists now, at an estimated tens of bytes per second, against a Firefox that has not fully deployed site isolation; that would turn a local-code-execution problem into a malicious-webpage problem. Second, any hardware vendor shipping predictor-coherence mechanisms, or any sign of in-the-wild use, would move BTR from conference research to emergency patch cycles.
