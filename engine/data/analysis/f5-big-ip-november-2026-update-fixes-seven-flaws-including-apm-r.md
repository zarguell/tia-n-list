F5's November 2026 out-of-band BIG-IP release addresses seven flaws, including the APM remote code execution issue CVE-2026-123637 and iRule stack overflows rated CVSS 9.8. The Hacker News describes six critical cases where an unauthenticated attacker can terminate the Traffic Management Microkernel and disrupt traffic until it restarts. Each one requires a specific virtual server setup, either an iRule that calls a particular command or an APM policy containing two particular agent types, so exposure depends heavily on local configuration rather than a default installation.

CVE-2026-123637 is a stack-based buffer overflow in BIG-IP APM when a per-request policy with the Client Information and Endpoint Security agents is applied to a virtual server. Undisclosed requests can crash TMM and may permit unauthenticated code execution. Rapid7 lists CVSS 3.1 at 9.8 and CVSS 4.0 at 9.3, and the NVD record published from F5 SIRT on 18 November 2026 calls the issue data-plane only with no control-plane exposure. Vendor advisory K000163937 and hotfix BIGIP-21.1.0.4.0.19.3-ENG are named as the fix path. Neither EPSS nor CISA KEV inclusion is listed, and the public records say the flaw is not known to be exploited.

The second named issue, CVE-2026-120722, is a CVSS 9.8 CWE-121 stack overflow triggered when a virtual server runs an iRule using DNS::scrape. It has the same TMM termination and possible unauthenticated execution impact, is data-plane only, and is also reported as not known exploited. Fixes given are BIGIP-21.1.0.4.0.19.3-ENG and BNK-2.4.2-EHF1 for BIG-IP Next for Kubernetes, under F5 advisory K000163945; F5 also published notification K000164058. What to watch is whether public exploit code appears for either overflow and whether any affected organization reports crashes matching these configurations. Internet-facing BIG-IP virtual servers using DNS::scrape iRules or the two APM agents should be checked first even without a KEV signal.
