Tensorlake SDK v0.5.144 was poisoned with the self-propagating Shai-Hulud credential-stealing worm. The attacker compromised the main branch and published the malicious release through the project's legitimate GitHub Actions pipeline, which produced valid SLSA provenance. The worm spread through the trusted release mechanism, making the package appear legitimate. Version 0.5.144 has been removed from npm; version 0.5.143 is clean. The incident highlights how supply-chain attackers abuse trusted CI/CD pipelines rather than injecting malicious artifacts manually. A basic YARA scan could have caught the known Shai-Hulud pattern before publication.

Developers who installed v0.5.144 should rotate any credentials exposed to environments where the package ran. The compromise of the release pipeline shows that provenance alone does not guarantee safety; pipeline integrity and pre-publish scanning are critical. Watch for further releases from the Tensorlake project and confirm that build infrastructure has been secured before trusting new versions.
