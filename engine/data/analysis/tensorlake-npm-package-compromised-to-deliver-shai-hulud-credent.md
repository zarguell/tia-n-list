The tensorlake npm package released version 0.5.144, poisoned with the Shai-Hulud credential-stealing worm. The attacker first poisoned the main branch, then let the project's trusted GitHub Actions pipeline publish the malicious release with valid SLSA provenance. Version 0.5.143 remains clean; 0.5.144 has been removed from npm. The package carries over 1,000 GitHub stars, so the poisoned release reached a meaningful developer audience quickly.

This is not just a compromised dependency - it is a supply-chain pipeline compromise that turns trusted provenance into an attack accelerator. Any developer who installed 0.5.144 exposed Kubernetes and Vault credentials to a self-propagating worm that writes directly to disk and propagates through CI environments. The incident stands out from the daily noise because the attacker did not need to forge a release; they poisoned the source and let the legitimate pipeline sign and publish it, which is harder to detect with standard dependency checks than a stolen npm token alone.

Defenders should treat version 0.5.144 as actively malicious and audit build logs for installations between its publication and removal. Confirm installed versions are 0.5.143 or earlier, and scan CI environments for Shai-Hulud indicators including Kubernetes and Vault credential harvesting behavior. A basic YARA scan flags this family in milliseconds, so adding that check to any pipeline that downloads npm artifacts closes the gap this attacker exploited. Network restrictions that prevent CI runners from reaching unexpected credential endpoints are also worthwhile.

Watch for additional packages published from the same compromised GitHub Actions pipeline and any reports of downstream infections in repositories that depend on tensorlake. If the attacker used the same technique elsewhere, the provenance files will still look valid, making pipeline-level YARA scanning the critical control rather than post-install dependency scanning.
