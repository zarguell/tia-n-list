The tensorlake npm package shipped a poisoned release, version 0.5.144, carrying a Shai-Hulud worm variant. Sonatype's review found a preinstall hook that launches an obfuscated JavaScript payload through Bun, downloading Bun 1.3.13 if needed, then searches the developer machine for credentials and accepts remote commands. A GitHub fallback path can create a public repository and commit collected data, including a stolen GitHub token, and can modify accessible repositories by committing .claude and .vscode files. The payload exits when common CI environment markers are present, so Sonatype does not assess broad CI infection, and it has not confirmed that stolen data was actually published.

Two details make this one worse than the average npm compromise. First, the malicious release went out through the project's legitimate GitHub Actions pipeline with valid SLSA provenance after the attacker poisoned the main branch, so provenance checking would not have stopped it. Second, ifin.network reports a booby trap: attempting to revoke or cycle the stolen token triggers deletion of the victim's home folder. Zubiqo adds that the malware targets Kubernetes and Vault credentials specifically. A basic YARA rule flags the payload on the first pass, which is cold comfort given that npm and GitHub do not run one before publishing.

Version 0.5.144 has been removed from npm and 0.5.143 is clean. Anyone who installed 0.5.144 should determine whether the hook ran, rotate Kubernetes, Vault, GitHub, and npm credentials available to that host, and audit their repositories for unexpected commits. Watch for the worm appearing in other packages and for npm adding pre-publication scanning.
