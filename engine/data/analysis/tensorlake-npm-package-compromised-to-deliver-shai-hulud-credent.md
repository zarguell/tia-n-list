The Tensorlake npm package shipped a poisoned release, version 0.5.144, carrying the self-propagating Shai-Hulud credential-stealing worm. The malicious version was published through the project's own trusted GitHub Actions release pipeline with valid SLSA provenance, meaning the attacker poisoned the main branch first and let the legitimate pipeline vouch for the payload. The release has been pulled from npm and version 0.5.143 is clean.

The worm targets developer secrets. Safedep describes it as a mini Shai-Hulud variant, and zubiqo reports it harvests Kubernetes and Vault credentials, writing them out for exfiltration. The most aggressive detail comes from ifin.network: the payload is booby-trapped against revocation. If the stolen token is cycled, the malware destroys the user's home folder, punishing victims who rotate credentials.

The Reddit discussion notes a single basic YARA rule flags this package immediately, which raises the uncomfortable question of why npm and GitHub do not run such scans before publishing. Anyone who installed 0.5.144 should treat all Kubernetes and Vault credentials on the machine as compromised, rotate them from a clean host, and check audit logs for use of the stolen tokens.

Watch for the worm appearing in other npm packages under the same playbook, downstream projects pinning the bad version in lockfiles, and any sign the home-directory booby trap becomes a standard feature of this worm family.
