OpenSSL patched nine vulnerabilities on August 25, 2026, affecting versions prior to 1.0.2zr, 1.1.1zi, 3.0.22, 3.4.7, 3.5.8, 3.6.4, and 4.0.2. Three flaws carry Moderate severity and six are Low. The most significant is CVE-2026-18798, a double-free in the QUIC server stack triggered by a malformed INITIAL packet with a Destination Connection ID shorter than eight bytes. The advisory considers remote code execution highly improbable, but the crash is easy to trigger with minimal effort.

CVE-2026-63072 affects CMS_decrypt() and produces a deterministic eight-byte out-of-bounds heap write during CMS key unwrapping. An attacker can manipulate a key-wrap OID in a legitimate CMS message to select AES-WRAP-PAD, causing heap corruption and denial of service despite subsequent integrity verification failure. CVE-2026-63076 targets CMP deployments, where a crafted protectionAlg parameter triggers an invalid-pointer dereference. Additional flaws affect DTLS, TLS Raw Public Key, and AEAD code paths.

All identified issues enable denial of service through malformed packets or cryptographic messages. No exploitation in the wild has been reported. Operators running affected OpenSSL versions across QUIC, CMS, CMP, DTLS, or TLS RPK configurations should prioritize patching, particularly for the QUIC double-free given its low barrier to trigger.
