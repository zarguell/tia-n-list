Cesanta advisory GHSA-4mgp-8m9m-q872, credited to Trend Micro's Zero Day Initiative as ZDI-CAN-29386, describes a heap overflow in read_conn() in Mongoose's MIP built-in TCP/IP stack. A TCP FIN carrying payload matches the FIN branch, skips the receive-buffer resize check in a later else-if, and falls through to a memcpy near net_builtin.c line 1527. CVSS 3.1 is 9.8 with AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H. Version 7.23 was the tested build, versions up to 7.23 are affected, 7.24 is patched, and the advisory includes a proof of concept. No CVE identifier is assigned.

This is a pre-protocol bug: it fires at the TCP layer before HTTP, MQTT, TLS, or WebSocket parsing, so application credentials and web-facing access rules never get a vote. ZDI notes that MIP targets bare-metal microcontrollers without ASLR, stack canaries, or heap integrity checks, and that the contiguous allocator gives deterministic adjacent object layout, which is what makes a controlled overflow a code-execution primitive rather than a simple crash. The coverage says 7.24 fixes this bug plus six others, while the release notes enumerate fifteen security items, so the seven-fix framing understates the amount of MIP, TLS, PPP, and HTTP hardening bundled into one firmware rebuild. No victim count is published. Exposure is a build property: every MIP image at 7.23 or earlier with any reachable TCP port is in scope, not only devices running a web server.

Upgrade to 7.24 and rebuild downstream firmware; the advisory lists no workaround. Until vendor builds land, restrict TCP reachability to MIP devices at the network edge, allowing only required sources and ports, because the trigger needs network access to any open TCP port rather than a valid application request. Hunt packet telemetry for TCP FIN segments with nonzero payload toward MIP hosts, especially the demonstrated shape: 400 bytes of prior data to fill the default 512-byte MG_IO_SIZE receive buffer, then a FIN carrying 400 bytes that writes 288 bytes past the buffer. An AddressSanitizer heap-buffer-overflow in read_conn() is the positive signal on instrumented builds; on deployed devices, correlate resets, crashes, and coredump records with the same traffic.

Two developments would change the assessment. A CVE assignment or a published ZDI bulletin for ZDI-CAN-29386 would make downstream scanners and OEM trackers pick up a flaw that currently has only a GitHub advisory identifier. Firmware notices naming 7.24 or a backport would turn an upstream fix into a deployable patch for embedded users, who rarely consume Mongoose releases directly.
