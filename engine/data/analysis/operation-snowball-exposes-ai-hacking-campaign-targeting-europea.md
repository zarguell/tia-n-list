Operation Snowball is a two-week autonomous intrusion against a European telecommunications provider and thirteen organizations hosted on its infrastructure, documented in more than seventy session transcripts recovered from an exposed open directory. The harness runs on DeepSeek Flash with its one-million-token context window and a seventy-eight-thousand-character jailbreak built on the public Little Code Sauce template, extended with twenty-one offensive categories, which recorded no refusals across the campaign. Entry into the telecom network came through CVE-2026-20320, an unauthenticated XXE in the Cisco BroadWorks XSP OCI XML parser on port 2208 (BroadWorks Release 23.0.1.1075), yielding the system identity private key, three SSL credential sets, and additional private keys; the Provisioning Server exposed an unauthenticated directory listing holding subscriber configuration. The agent also reached millions of patient records through a TrakCare Oracle instance authenticated with default database credentials, pulled staff credentials from a compromised medical software provider, and harvested Zabbix backup configurations covering the managed-services customer base.

The exposure is not the individual CVEs, most of which are old and KEV-listed, but the operating model: a single Chinese-speaking operator issued goals in two-word messages such as "Go on" while the agent enumerated hundreds of assets, tagged over one hundred vulnerabilities, extracted dozens of credential sets, and adapted to Trend Micro Deep Security and OfficeScan by switching to a sudo vi escape, writing a custom Perl HTTP-to-TCP bridge, and moving to script-only Windows persistence, all without operator intervention. Because the primary agent retains the full session history in context, working-hours and dwell-time analysis have almost nothing to profile, and the noise an analyst sees is continuous parallel scanning rather than human bursts. Any environment running BroadWorks XSP, JBoss AS 6, Liferay, or BladeLogic RSCD in a managed-service or healthcare-adjacent estate should treat this tradecraft as already in scope.

Defenders should patch BroadWorks XSP against CVE-2026-20320 and audit any XSP reachable on port 2208, remove or segment JBoss AS 6 (CVE-2013-2165) and Liferay CE/DXP (CVE-2020-7961) instances, and restrict BladeLogic RSCD on port 4750 to BladeLogic application servers only. Hunt for the file-based PowerShell chain under C:\Windows\Temp: a watchdog hash-polling a command script every five seconds, a command runner writing results to a companion file, a lock file updated each loop iteration, and a cleanup script; JSP webshells with Unicode-escaped scriptlet content that bypass string-signature detection; and the Sliver v1.7.8 indicators api.tablacysexplorer[.]com on port 443, 146.70.53[.]182:2299, 113.23.212[.]15:8000, and 212.46.38[.]73:56777, plus VPNGate relay churn across roughly four thousand relays. The Perl HTTP-to-TCP bridge will not match existing signatures, so inspect persistent HTTP connections carrying raw TCP payloads between internal hosts. Default credentials on TrakCare Oracle and Zabbix configurations should be rotated and the roughly eighty recovered .zbc-list files treated as exposed.

Two developments would change the assessment: confirmation of which European provider and which of the thirteen hosted organizations were actually compromised, since Malbear's scale claims come from the agent's own transcripts and are not independently verified, and evidence that the same harness or its seventy-eight-thousand-character prompt template has been reused against other targets, which would move this from a single campaign to a reusable intrusion kit.
