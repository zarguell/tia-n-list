No CVE tracks this one. Between 02:23 and 05:25 UTC on September 23, 2026, an attacker published three backdoored versions of the npm package @memtensor/memos-cloud-openclaw-plugin (0.1.21, 0.1.23, 0.1.25) and one of the PyPI package MemoryOS (2.0.34), each bundling a statically linked Go implant named sckit built for Windows, Linux and macOS on x64 and arm64. Access came through MemTensor's own GitHub Actions release pipelines: commits pushed under the Memtensor-AI account made the npm publish job hand its token to the implant through a BASH_ENV value written to GITHUB_ENV (commit 9b97ec6), and a forged Poetry build backend in commit b52958f captured the PyPI token before a recreated v2.0.34 tag let MemTensor's own workflow upload the malicious wheel. The npm plugin launches sckit at gateway start and again on every memory recall, passing the full process environment and the user's prompt text in SCKIT_EVENT_TEXT; on PyPI, importing memos is enough because the payload rides the logging initialization hook, so --ignore-scripts changes nothing.

A default install was the attack: 0.1.25 and 2.0.34 were tagged latest during the window, so a plain npm install or pip install MemoryOS pulled the backdoor, and the underlying MemOS project carries roughly 11,500 stars and 1,100 forks on GitHub. The implant inventories all of $HOME, reads .npmrc, .vault-token, id_ecdsa and credentials.db style files, regex-matches token formats for AWS, GitHub, GitLab, npm, PyPI, Hugging Face, Vault, Slack, Stripe and SendGrid, and reports to six skyleen.fr subdomains that resolved to 139.84.223.178. What elevates this above the day's other stealer drops is the compounding design: the workstations that run an AI memory plugin are the same ones holding registry publish tokens, and sckit ships npm, Python and GitHub Actions loader templates, including a runtime-update.yml workflow triggered on push, plus a recursivePublish path that turns stolen credentials into the delivery mechanism for the next ring of victims. Its Go module is named supplychain.local and its configuration expires October 22-23, 2026, the signature of a planned campaign rather than an opportunistic scrape.

Pin the plugin to 0.1.20 or the now-restored clean 0.1.24, and MemoryOS to 2.0.33; npm latest points at 0.1.24 and PyPI has purged 2.0.34 entirely, but latest is not a trust signal on a package with this history. Any host that loaded a bad version or imported 2.0.34 is compromised: kill sckit processes, delete $HOME/.openclaw/.cache/runtime and $HOME/.memos/.cache/runtime, and rotate every credential reachable from the account, publish tokens first. Block skyleen.fr and all its subdomains, then sweep DNS, proxy and egress logs back to September 23. The specific hunt: command line "sckit stage0 --config64", the SCKIT_EVENT_TEXT environment variable, files .sckit/<os>-<arch>/sckit, lib/sckit.js, memos/_stage0.py and sckit_poetry_build.py, the linux-amd64 binary hashes 381ac6dc1715d9298fe81b2a53a11f7b7d78e361ee3a6619ad54f8c4b062cc18 (npm) and c1b0998347b489582bae7b7f4930f9831d9ef4b6bc150cfd488ee1a43272dd36 (PyPI), the CI log strings "SCKit credential receipt acknowledged." and SCKIT_CI_RESULT_V2, and any unexpected runtime-update.yml or .sckit/ directory in repositories you can push to. Maintainers releasing from CI should move to PyPI trusted publishing, protected tags and a required release reviewer; neither MemTensor package had provenance attestations, so nothing flagged builds from commits never merged to main.

Two developments would change this assessment. Evidence that the worm escaped MemTensor, such as a third-party package carrying the same sckit binaries or a runtime-update.yml surfacing in an unrelated repository, converts a contained vendor incident into a self-spreading campaign, and both Aikido and SafeDep note the affected list can grow. Watch the C2 as well: the implant accepts signed tasks and loads modules at run time, and the configuration's not_after stamp expires around October 23, 2026, so infrastructure rotation near that date, or a second publishing wave under stolen MemTensor credentials, is the follow-on to expect.
