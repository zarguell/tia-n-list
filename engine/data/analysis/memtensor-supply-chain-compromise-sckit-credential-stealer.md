Two legitimate MemTensor publishing channels were compromised on September 23, 2026 to deliver sckit, a Go-based credential stealer, to users of the MemOS AI memory framework. On npm, versions 0.1.21, 0.1.23 and 0.1.25 of @memtensor/memos-cloud-openclaw-plugin were malicious, published between 02:23 and 04:37 UTC; interleaved versions 0.1.22 and 0.1.24 were clean and the latest tag now points at clean 0.1.24. On PyPI, a malicious MemoryOS 2.0.34 wheel appeared about a minute after a GitHub release published by the Memtensor-AI account at 05:24:20 UTC on commit 41bf5c7, preceded by a token-capture build under a since-deleted tag named v2.0.34-capture-1.

The intrusion path is the notable part: the attacker never pushed code to the repository. They got into the project's GitHub Actions release workflow, captured the publish tokens before the legitimate job ran, and shipped the malware under the maintainer's own credentials, so the packages appeared signed and trusted. GitHub user omeridel flagged that npm versions 0.1.21 and 0.1.23 correspond to no commit or tag in the repository and contain a credential-harvesting payload; SafeDep's analysis of the sckit worm built from that report.

This follows the 2025 pattern of trusted-maintainer publishing abuse, but aimed specifically at the AI developer ecosystem: anyone pulling MemTensor packages in CI consumes the stealer automatically. The deleted capture tag and the interleaved clean releases suggest deliberate opsec rather than a one-off token leak.

Teams using MemTensor packages should verify installed versions against the clean 0.1.24 line and audit for sckit, rotate npm, PyPI and GitHub tokens used in the affected workflows, and require OIDC-based publishing or provenance attestation so release credentials cannot be harvested from Actions runners. Watch for the same token-capture technique appearing against other AI-framework maintainers.
