Synology advisory Synology_SA_26_13, published 2026-09-18, fixes eight vulnerabilities in DiskStation Manager. Two are critical and unauthenticated: CVE-2026-13684 is an improper output-encoding flaw in the SCGI component and CVE-2026-13639 is an insufficient-entropy flaw in the login logic; both allow a remote attacker with no credentials to read or write arbitrary files and cause denial of service, each scored CVSS 9.8. The remaining six require authentication or an administrator, and include a path traversal in the Upload API (CVE-2026-6205, CVSS 8.1), an XSS in the Theme API (CVE-2026-13623) and a CRLF injection in the Sharing API (CVE-2026-13666). A single DSM update per branch closes all eight: 7.2.1-69057-12, 7.2.2-72806-9, 7.3.2-86009-4 or 7.4-90075 and above. Synology lists no mitigation beyond patching.

The risk is not the bug class alone but the target. DSM runs on NAS devices that often hold backups and shared data and are frequently exposed to the internet for remote access, so an unauthenticated file read/write primitive lands directly on high-value storage. The events in this desk already track C3RB3R ransomware encrypting Synology NAS data since October 2026 with the .L0CK3D extension and a read-me3.txt note, and Synology's own 29 October warning attributes that wave to the older flaw fixed by advisory Synology_SA_24_20 (CVE-2024-10441, CVSS 9.8), while Qihoo 360 attributes it to CVE-2026-13639 and CVE-2026-13684. Neither attribution is confirmed and neither CVE is in the CISA KEV catalog as of 2026-10-30, but the disagreement is itself the operational problem: a team that patches only for the CVE it believes is in use leaves the other door open. That is why this story outranks a routine advisory: it is an unauthenticated primitive on a platform under active ransomware pressure with an unresolved question about which flaw the criminals actually used.

Apply the DSM update that matches the installed branch and verify the build number reaches 7.2.1-69057-12, 7.2.2-72806-9, 7.3.2-86009-4 or 7.4-90075. Because Synology states no workaround, reduce exposure in parallel: keep the DSM management interface off the public internet, reachable only through a VPN or trusted network, and confirm backups are offline, immutable and tested. Hunt for signs of the ransomware campaign already in progress: files renamed with the .L0CK3D extension, read-me3.txt ransom notes, and any DSM instance reporting a build below the fixed thresholds above; a detection-only scanner published 2026-10-30 checks those build numbers without exploit code. Review accounts and sessions for the authenticated flaws too, since CVE-2026-13673, CVE-2026-6205, CVE-2026-13623, CVE-2026-13666 and CVE-2026-13683 can still be used by anyone who already has a login.

Watch for three developments that would change this assessment: a CISA KEV entry or confirmed in-the-wild exploitation of CVE-2026-13684 or CVE-2026-13639, a Synology clarification on whether C3RB3R used the 2024 flaw or the 2026 pair, and the publication of working exploit code. Any of the three would move this from urgent patching to active incident response.
