GitLab patched a maximum-severity path traversal vulnerability (CVE-2026-85706) that allows unauthenticated attackers to read arbitrary files from vulnerable servers. The flaw, discovered by researcher s3ntago via GitLab's HackerOne bug bounty program, stems from improper path confinement and missing authentication enforcement in the repository commits API. GitLab warned that under certain conditions, attackers can exploit this to access sensitive files without any credentials.

A second critical vulnerability, CVE-2026-87719, was also patched. This one affects GitLab Enterprise Edition and involves insecure deserialization in the GraphQL subscription serializer. Authenticated users with Duo Chat access can exploit it to steal sensitive credentials and Advanced Search instance configurations. Both flaws were fixed in GitLab CE/EE versions 19.3.2, 19.2.6, and 19.1.

GitLab.com is already running the patched version, but self-managed installations need to upgrade immediately. The company emphasized the urgency, noting these versions contain "important bug and security fixes." This is the second maximum-severity path traversal flaw GitLab has patched since CVE-2023-2825 in May 2023, which also exposed files through the commits API. The recurrence of similar vulnerability patterns in the same API endpoint suggests deeper architectural issues worth auditing.
