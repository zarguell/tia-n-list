Railway disclosed in an incident report that attackers used API keys stolen from railway customers to run up roughly $740,000 in AI charges. The abuse worked by taking legitimate customer credentials and pointing them at metered AI services, converting access into billable usage against the victims' accounts. The concrete loss figure and the credential-theft vector are the substance here: this was not an outage but unauthorized consumption of customer AI keys.

The case matters because stolen API keys have a direct financial payoff that is easy to overlook, and the per-incident cost can reach six or seven figures when the keys unlock high-rate inference or model services. Any organization that issues AI platform keys should treat them like payment credentials: short lifetimes, per-key spend caps, anomaly detection on usage spikes, and easy revocation.
