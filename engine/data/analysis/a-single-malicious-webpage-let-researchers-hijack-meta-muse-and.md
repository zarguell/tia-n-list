NebuSec demonstrated a lab exploit chain against Meta Muse that started with a single attacker-controlled webpage opened by the assistant's bundled Chromium during PDF export. The PDF-export process ran without an IPC sandbox. The researchers used V8 issue 554034656 for code execution inside the agent's runtime container, then used generated Linux kernel exploits against a 7.0.0-39-generic Hatch build to escape the container and reach root in the user VM. Observed Chromium builds were 152.0.7977.82 in early October and 155.0.8059.80 later.

Once inside, the chain abused weaknesses in Sentinel's outbound classification. Conversation history and stored memories could be sent to an external server without an approval prompt, and the researchers could alter those records. Sentinel is described in the write-up as a DNS and proxy service at 198.19.0.1 on ports 53 and 3128, with eBPF redirection, content screening, and 60-minute egress budgets of 2 MiB per originator and 5 MiB per domain. After VM root, processes outside the container could bypass Sentinel and reach the unlocked 100 GiB LUKS2/Btrfs volume, secure credential storage, and Sentinel itself. The demonstration stayed within one user's VM; NebuSec reported no hypervisor or cross-tenant escape, and Muse fixed the issues before publication.

Meta's launch material had said each Muse agent runs in a dedicated cloud VM, the harness does not see real credentials, and all outside interactions pass through a Sentinel the agent cannot override, with connected-service credentials kept outside the runtime cell. The bug bounty offers up to $300,000, including up to $130,000 for prompt-injection issues affecting one user. This research is worth tracking because it shows how a browser-triggered bug, a container escape, and weak egress enforcement combine into access to private chats and stored credentials without a user approval prompt. The fixed-before-publication detail means the value is in the architecture lessons, not in an active campaign.
