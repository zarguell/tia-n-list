Researchers showed that a single malicious webpage could hijack Meta's Muse assistant and pull a user's private conversations and stored memories out of the assistant without triggering an approval prompt. The same technique could be extended to reach credentials Muse stores for connected accounts. The work was a laboratory demonstration, not an attack on real users, and the reported access stayed within the individual user's own assistant context rather than moving across accounts.

The interesting detail is the absence of an approval prompt. If a page the user visits can drive an assistant through browser-mediated actions without a confirmation step, the assistant's memory becomes readable by whatever page can reach that session, and stored credentials raise the stakes beyond chat history. The available reporting gives no CVE, version, patch status or Meta response, so there is no fixed build to name and no evidence the technique has been used outside the lab.

Watch for Meta's response, a technical write-up naming the exact mechanism, and any change to how Muse requests approval for actions triggered from web content. Until then, the practical question for users is which connected accounts and stored credentials an assistant session can reach without a separate confirmation.
