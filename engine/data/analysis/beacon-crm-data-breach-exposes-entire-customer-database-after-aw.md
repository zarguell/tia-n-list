Beacon CRM, a customer relationship management platform used by more than 1,000 UK charities and non-profit organisations, confirmed that an attacker copied and exfiltrated its entire customer database. The compromise began with a leaked AWS access key that had been exposed in publicly accessible JavaScript build artifacts; the credential gave the attacker access to platform data and attachment files in Beacon's AWS environment. The updated disclosure from chief technology officer David Simpson on August 12 significantly expanded on earlier statements, and a forensic investigation with external specialists confirmed the full database was downloaded.

This is a supply-chain class breach for the charity sector. The exposed data covers all customer records stored on the platform, which for non-profits includes donor details, and the attacker is understood to have copied rather than merely touched the data. The breach happened through an infrastructure hygiene failure, a key committed to a public build artifact, which is a common and entirely preventable pattern.

Watch for victim notification timelines and any evidence the data is being traded or used for phishing, since charity donor lists are a known commodity for fraud. Affected organisations should assume donor personal data is out and prepare for targeted phishing against staff and supporters. The wider lesson is that AWS keys embedded in client-side JavaScript are an immediate full-account exposure: scan repositories and build artifacts for credentials, rotate anything exposed, and enforce short-lived credentials for cloud access.
