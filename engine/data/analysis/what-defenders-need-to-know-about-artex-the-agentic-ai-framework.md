ARTEX is a Go based, Next.js and PostgreSQL multi-agent penetration test framework, not a CVE or a flaw in a Microsoft product. The upstream repository appeared on July 26, 2026, went closed source on October 8 after abuse reports, and survives through forks with last upstream release v0.3.15 and maintained derivatives at v0.3.29, v0.4.5 and v0.5.1. Microsoft's November 25 report names Storm-0940, Storm-3358, Onyx Sleet, Pearl Sleet, Crystal Typhoon and Salt Typhoon integrating it for network reconnaissance, credential attacks and web application exploitation; Unit 42 says its observed cloud intrusions did not rely on a single software vulnerability. An operator supplies a goal, then planner and worker agents choose tools, log findings into graphs, fall back between model providers and retry when a control blocks them. Live use is established, from South Korean finance intrusions in late September to CrowdStrike's Vapor Panda tracking of more than 200 organizations in at least 14 countries over 11 days.

Successful attacks here convert exposed secrets and identity flows into cloud control rather than a single compromised host. Microsoft-linked Storm-0940 activity attempted sign-ins to more than 2,250 Microsoft 365 tenants after abuse of ConnectWise multi-tenant application credentials, and one spray against 327 accounts in eight organizations generated more than 151,000 failed logons peaking at 2,900 per minute; some intrusions reached privileged access in under three hours. The Record notes Microsoft's post followed reports hours earlier that alleged ARTEX use against the CIA, the National Geospatial-Intelligence Agency and the Office of the Director of National Intelligence, and the same report names Salt Typhoon, linked by US agencies to a 2024 breach of at least nine telecommunications companies. That mix of scale and target value is why this outranks another tool adoption story. The exploitable weakness is usually the victim's own exposure, so the defensive advantage is that ARTEX is loud and often badly hosted: Check Point found 1,608 live public panels and 10 databases exposing prompts and agent steps, while more than 1,400 consoles were counted in early November.

There is no fixed version to install and no CVE to patch, so start by removing default credentials, shutting internet-facing consoles and inference endpoints, and rotating secrets and application credentials found in code or public repositories; treat any ARTEX derived deployment from an unverified image as compromised and rebuild it. Restrict port 8787 and administrative interfaces, patch internet-facing web software, and enforce WAF, rate limiting and API schema checks on password reset, signup and API routes instead of trusting static signatures. Hunt CloudTrail for anonymous AWSAccount GetObject and ListObjects reads before key use, FilterLogEvents calls with limit 1000 searching Invoice, Billing, Fund and LLC, and placeholder probes such as /zzz-nonexistent-xyz123 or zzz_nonexistent_abc.txt before fuzzing bursts. Hunt identity logs for 2,900 failures per minute, user-agent markers pentest-recon and artex-enrich/1.0, and task labels such as pentest-iNNNNNN. On the network side, check for BLOODALCHEMY traffic to nginxmysql[.]com and 45.153.126[.]223, the wisp-agent download from 213.111.150[.]145:8099, and Azure credential collection from 43.98.196[.]73.

Two developments would change this assessment. Confirmed victims tied to the named campaigns, especially any use of the three certificates that Check Point saw pass validation out of more than 300 gathered from signing shops, would move the story from capability adoption to measurable downstream harm. Conversely, if forks strip self-labeled user agents, stop exposing consoles on default ports and drop the think-then-act pauses, the current hunts lose their best signal and the activity becomes a generic identity and edge-exposure problem with much less warning.
