CVE-2026-6471, dubbed PostGREShell, is a critical vulnerability in PostgreSQL's logical replication mechanism that existed for roughly 12 years across versions 9.4 through the August 2026 patch cycle. Discovered by Cyera Research, the flaw allows low-privileged accounts with the REPLICATION attribute to execute arbitrary code, escalate to database superuser, and establish persistent backdoors.

The vulnerability lies in the CREATE_REPLICATION_SLOT workflow, which lets replication users specify a logical output plugin. PostgreSQL loads these plugins as compiled shared libraries (.so on Linux, .dll on Windows, .dylib on macOS), and the plugin's initialization code runs inside the server process. Unlike the SQL LOAD command, which validates library names for safety, the replication slot creation path lacked this restriction. An attacker with replication privileges could point the plugin loader at a malicious shared library and achieve code execution on the database server.

Organizations commonly grant the REPLICATION attribute to service accounts for backups, standby databases, change data capture, and analytics pipelines. This means any compromised backup credentials or misconfigured service account could serve as an entry point. PostgreSQL patched the issue in its August 22, 2026 security release. Any deployment using logical replication should verify that replication accounts are tightly scoped and that the patch has been applied. The long dormancy period means many environments may have inherited this exposure without realizing it.
