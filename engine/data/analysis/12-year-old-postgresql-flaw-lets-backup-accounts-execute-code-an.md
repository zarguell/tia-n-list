CVE-2026-6471, dubbed PostGREShell, is a critical vulnerability in PostgreSQL's logical replication mechanism that went undetected for roughly 12 years, from version 9.4 (2014) through August 2026. Discovered by Cyera Research's Vladimir Tokarev, the flaw allows low-privileged replication accounts to execute arbitrary code and escalate to database superuser privileges.

The vulnerability lives in the CREATE_REPLICATION_SLOT workflow, which lets replication users specify a logical output plugin. PostgreSQL loads these plugins as compiled shared libraries (.so, .dll, .dylib) and executes initialization code inside the server process. The normal LOAD command has restricted-library-name validation, but the replication slot path bypasses this protection. An attacker with replication permissions can point the system at a malicious plugin to achieve code execution.

PostgreSQL patched the issue in its August 22, 2026 security release. The attack surface is broad: organizations commonly grant REPLICATION attributes to service accounts for backups, standby databases, change data capture, migrations, and analytics. Any environment with replication-enabled service accounts should assume compromise until patched. The long exposure window means historical backups and replication slots may carry malicious plugins.
