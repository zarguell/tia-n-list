OpenCode disclosed on October 17, 2026 that an intruder reached a legacy authentication subsystem in the OpenCode Console and that third-party provider API keys saved by approximately 1.4% of Console users may have been exposed. There is no assigned CVE; the event is an incident-response story rather than a vulnerability disclosure, with the impact concentrated on users who linked outside AI providers such as OpenAI and Anthropic. The guidance is precise: revoke the exposed key in the provider's own dashboard, never through an email link, create a new key, audit usage back to October 17, and enforce rotation intervals.

What makes this worth defending attention today is that exposed API keys grant persistent, unauthenticated access to downstream services long after the legacy intrusion is contained; one user reported unexpected spending of $40, and any attacker with the key can continue to call the provider until rotation completes. The 1.4% exposure figure sounds small, but the affected population is exactly the subset with linked providers, so any organization using OpenCode Console with external AI integrations is in the risk pool. The story is not another vulnerability patch cycle; it is a supply-chain hygiene failure where the defender's action is revocation and audit, not patching.

Defenders should treat October 17 as the start of the audit window, not the notification date, and check provider dashboards for unexpected usage going back to that date. Hunt telemetry should focus on provider-side API logs for the affected accounts rather than endpoint logs, since the exposure is credential-based, not malware-based. Watch for follow-up vendor updates clarifying whether the legacy system contained additional secret types beyond provider keys, and for reports of in-the-wild abuse that would confirm active exploitation.
