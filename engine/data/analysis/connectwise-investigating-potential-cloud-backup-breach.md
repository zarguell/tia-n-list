ConnectWise Cloud Backup, the product formerly sold as SkyKick that ConnectWise acquired in September 2024, is under investigation for unauthorized access that third-party intelligence says pivoted from compromised application credentials into live Microsoft 365 environments of managed service provider customers. The events reference the ConnectWise status advisory (status.connectwise.com, 2026-10-16), a Huntress report on credential-enabled unauthorized access in M365 tenants (huntress.com/blog/vendor-credential-enables-unauthorized-access, 2026-10-17), and Blumira guidance that MSPs disable the application across every tenant because the backup service holds read-level access to mail, SharePoint, and Teams. No CVE is assigned in the story record; the mechanism is application-level credential abuse, not a platform vulnerability, which changes how defenders should think about exposure.

This matters specifically because the supply chain target is the MSP itself, not a single end customer. The event timeline notes that the threat actor moved from SkyKick-derived access to customer M365 tenants, which means any organization relying on an affected MSP for backup has indirect exposure regardless of its own security posture. The story carries a score of 5.5 with three distinct sources and no CVE assignment, yet the impact profile is closer to a supply-chain breach than to a standard software bug. That is why this story earns focus over routine vulnerability reports: a confirmed pivot from backup credentials to live tenant data turns a vendor incident into a multi-tenant compromise with no single patch version that fully remediates it.

Defenders should disable the ConnectWise Cloud Backup application in every managed M365 tenant immediately and audit application sign-ins for the application ID mentioned in third-party reports, not just for the vendor advisory domain. Check M365 audit logs for unexpected application-level sign-ins around October 16, 2026, and review backup access scopes since the service typically operates with read access to mail, SharePoint, and Teams. There is no vendor patch version listed in the event files, so remediation remains procedural: rotate affected backup credentials, revoke the application registration where it is not required, and confirm no data removal events occurred through the backup application identity rather than an endpoint agent.

Watch for a confirmed scope statement from ConnectWise that quantifies affected MSP customers and whether data removal is verified, plus any updated advisory that specifies a fixed application version or a mandatory credential rotation deadline. A second development that would change this assessment is publication of the exact application ID and tenant-level IoCs from Huntress or ConnectWise, which would turn the current procedural guidance into targeted hunt queries.
