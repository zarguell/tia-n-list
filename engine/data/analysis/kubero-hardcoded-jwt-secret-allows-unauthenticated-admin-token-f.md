CVE-2026-125370 is a CVSS 9.8 authentication bypass in Kubero, an open-source Heroku-style PaaS for Kubernetes, affecting versions 3.0.0 through 3.1.1. The application signs session JWTs with a secret read from an environment variable and falls back to a hardcoded default when the variable is not set. Because Kubero is open source, that default value is public in the repository, so an unauthenticated attacker can forge a token for an administrative user, present it to the API, and receive admin access without a login step.

The blast radius is the Kubernetes cluster Kubero runs on, not just the PaaS: Kubero holds the RBAC and service-account material needed to deploy workloads, so a forged admin session is a position from which anything in the cluster can be deployed, modified, or read. ThreatAft, which published the write-up, says the fix is a release after 3.1.1 that refuses to start without a real secret, and notes that patching does not invalidate a forged token still within its expiry or undo deployments an attacker already created. No public proof-of-concept was indexed and no in-the-wild exploitation was confirmed as of November 10, 2026, but the mechanism is public in the source code.

Operators of Kubero should patch, rotate the secret, audit workloads and service accounts created during the exposure window, and verify the environment variable was actually set. The case is a reminder that a shipped default can be the vulnerability when the operator followed the installation guide.
