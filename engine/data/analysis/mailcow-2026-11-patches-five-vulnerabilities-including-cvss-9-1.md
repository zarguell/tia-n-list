Mailcow's 2026-11 release, published on 5 November 2026, fixes five mailcow-dockerized vulnerabilities, and the coordinated GitHub advisories carrying full proof-of-concept steps went public on 10 November, hours before this story was ingested. The most severe is GHSA-jgr3-fv33-x43c, a stored server-side template injection in the domain-wide footer rated CVSS 9.1 (AV:N/AC:L/PR:H/UI:N/S:C/C:H/I:H/A:H). A domain administrator stores footer HTML that rspamd's jinja and lupa engine renders on authenticated outbound mail; a macro default value reaches Lua os.execute, giving code execution in the shared rspamd container (rspamd 4.2.1-1) as the _rspamd user. The advisory states this is not a host-level breakout, but rspamd is one container for all tenants, so a single tenant admin can read, modify or inject every tenant's mail in transit and disable spam and AV filtering platform-wide. The other four 2026-11 fixes are GHSA-rpvp-3pw9-3vcw (7.4), GHSA-vv9q-w88c-j8h7 (3.1), GHSA-xvvm-8287-x8f9 (6.8) and GHSA-6v9c-2j28-pfhv (4.3); none of the five has a CVE ID yet.

The exposure argument is the role, not the score. A domain administrator is a delegated, lower-trust position on multi-tenant mail hosts, and the vendor's own workaround is to limit access to admin and domain admin accounts, which shows how much weight the vendor puts on that entry point. A successful exploit does not stay in the attacker's domain: the shared scanner sees every tenant's mail, and the advisory documents a post-exploitation path from the same code execution to container lifecycle actions through the internal MC_CHANNEL and dockerapi plane, a platform-wide denial of service. The other four fixes compound the risk rather than padding the count. Failed ActiveSync, DAV and autodiscover logins were reported to netfilter as 127.0.0.1 and never banned, while passwordless autodiscover named existing mailboxes, so an unauthenticated attacker had an unlimited guess-and-enumerate loop against mailboxes that have EAS or DAV enabled by default. The TOTP flaw removed the second factor for anyone holding a password, and the quarantine regex let one domain admin read another domain's subjects, senders and recipients. This story matters because the proof of concept is public, the entry point is a common delegated role, and the blast radius is the whole instance.

Update to 2026-11. The advisories name the fixing commits: 9eb3a79f3 for the quarantine regex, 085d10118 and e96fb24a6 for the netfilter and autodiscover handling, d5e3de3ae for the TOTP limits, and 44429fa0d for the app-password ACL; the footer fix ships in the same release. Until the update lands, the vendor's workaround is to limit access to admin and domain admin accounts, and administrators who do not need ActiveSync, CalDAV or CardDAV should restrict or disable those endpoints, since the brute-force path depends on them. Hunt the mailcow UI and netfilter logs for invalid-password events attributed to 127.0.0.1, which the flawed path produced instead of the real client address, and for repeated TOTP failures that were never counted. Review stored domain-wide footer values in data/conf/rspamd/dynmaps/footer.php for template syntax, and check the quarantine list for entries from domains the viewing admin does not manage. The release also sets a 64 MB request body limit for the UI and API, so raise NGINX_MAX_BODY_SIZE in mailcow.conf if a larger Postfix message_size_limit is required.

Watch for CVE assignment and the vendor's per-issue detail, which the release notes promised for early the following week, because defenders currently have to track five GHSA identifiers with no CVE mapping. Watch also for exploitation telemetry: the proof-of-concept steps are public, the entry point needs only a domain admin session, and a scan or abuse campaign against exposed mailcow installations would move this from a patching story to an incident story.
