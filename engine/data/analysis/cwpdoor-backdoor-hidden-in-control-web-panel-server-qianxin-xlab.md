cwpdoor is a passive backdoor built into cwpsrv, the web server that serves the Control Web Panel administration interface. QiAnXin XLab analyzed two samples targeting cwpsrv versions 1.15.10 and 1.24.0. The installer cwpsrv_update.sh, captured by XLab on June 29, 2026, downloads the malicious binary from 136.0.141.71 and overwrites /usr/local/cwpsrv/bin/cwpsrv, then restores atime and mtime and wipes the session history so the replacement looks unmodified. No CVE id exists for this issue, and XLab does not know the initial infection vector. The backdoor triggers only on requests carrying X-Ngx-Integrity-Time, X-Ngx-Integrity-Data, and X-Ngx-Integrity-Sig headers, validated within a 300-second window using an embedded RSA key.

A successful compromise gives the attacker the panel's own web server: arbitrary command execution on the hosting server and control over every site, mailbox, and database it serves. QiAnXin's Hunter Platform counted more than 340000 CWP instances exposed on the public web, and a cwpsrv.suspeito sample uploaded to VirusTotal from Brazil on September 30, 2026 had zero detections, which means real victims are likely already infected and invisible to most antivirus products. This story matters because a trojanized binary defeats version-number checks; a panel reporting 1.15.10 can still be backdoored, and log suppression erases the access-log evidence of each command, breaking forensic collection.

Defenders should hunt for the ngx_http_integrity_helper Unix domain socket with ss -axp | grep integrity, look for suspicious cwpsrv helper child processes with ps aux | grep cwpsrv, and scan the binary with strings /usr/local/cwpsrv/bin/cwpsrv | grep X-Ngx-Integrity. Where an attacker-created backup named cwpsrv.prev-* exists under /usr/local/cwpsrv/bin, restore the legitimate binary, then upgrade to the latest cwpsrv version and confirm the integrity socket no longer appears. Rotate all control panel credentials, treat the host as compromised, block 136.0.141.71 at the perimeter, and review proxy and WAF logs for the three X-Ngx-Integrity headers together with unexplained gaps in panel access logs.

The assessment changes if Control Web Panel issues an official advisory or publishes a fixed cwpsrv version, since neither exists today, or if researchers identify the initial-access vulnerability that delivers cwpsrv_update.sh to a root shell. Also watch for scanning or telemetry tied to 136.0.141.71 or to the signed header pattern, which would show whether exploitation is spreading beyond the victims already seen in the wild.
