QiAnXin XLab disclosed CWPdoor, a passive backdoor embedded in a trojanized cwpsrv binary, the web server behind Control Web Panel versions 1.15.10 and 1.24.0. The installer script cwpsrv_update.sh was captured on June 29, 2026 and downloads the malicious binary from 136.0.141.71. The backdoor stays dormant until the attacker sends a specially crafted HTTP request carrying X-Ngx-Integrity-Time, X-Ngx-Integrity-Data, and X-Ngx-Integrity-Sig headers, with commands and output encrypted under RSA. Trigger requests are suppressed from access logs, and the updater restores file timestamps, wipes command history, and deletes temporary files to hide the swap. A sample named cwpsrv.suspeito uploaded to VirusTotal from Brazil on September 30, 2026 had zero vendor detections and was found alongside an Ebury backdoor, which XLab cites as evidence of real victims. More than 340,000 CWP instances were exposed on the public web over the past month, though that figure reflects exposure, not confirmed infections. Control Web Panel, formerly CentOS Web Panel, is an open-source hosting administration solution comparable to cPanel and Plesk.

The stealth is the point of the design: passive triggering, log suppression, timestamp restoration, and encrypted channels remove most of the forensic trail that would reveal an active backdoor. A compromised hosting control panel gives an attacker control over websites, email, DNS, and databases on the managed server, so the blast radius extends well beyond the panel itself.

What to watch: administrators running CWP 1.15.10 or 1.24.0 should verify cwpsrv binary integrity, look for contact with 136.0.141.71, check for the three integrity headers, and hunt for Ebury co-infection. No vendor patch is mentioned in the disclosure, so mitigation centers on reinstalling a known-good binary and rotating credentials. The number of compromised servers remains unknown, so further victim disclosures and indicator-of-compromise updates are likely. The zero VirusTotal detections on the sample show signature-based tooling will not catch this on its own.
