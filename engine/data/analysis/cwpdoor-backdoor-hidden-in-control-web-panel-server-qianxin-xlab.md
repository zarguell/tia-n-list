QiAnXin XLab reported that the cwpdoor backdoor is hidden inside cwpsrv, the web server component of Control Web Panel. According to XLab, attackers swapped a core Control Web Panel component for a backdoored version using recompiled binary commands, so the panel's own web server carries the backdoor. Coverage so far comes from linuxmint.hu, itinsights.nl, and secquill.com, all pointing to the XLab finding. No CVE ID has been assigned in the events seen so far, and no patch or fixed version is mentioned.

The issue matters because Control Web Panel is a widely deployed hosting control panel. A backdoor in cwpsrv means the administration surface itself is untrustworthy: an attacker with the backdoor can issue commands through the panel's web server and potentially control the server and the sites it hosts. Because the malicious code arrives as a recompiled binary, a version number check alone will not reveal the swap; defenders need binary integrity checks or vendor-supplied indicators.

Control Web Panel administrators should watch for QiAnXin XLab's full indicator release and for official Control Web Panel advisories before applying any fix. Until then, they should verify the integrity of the cwpsrv binary, limit exposure of the panel's web interface, and review panel access logs for unexplained commands. The story remains thin on technical detail, so the concrete artifact to track is the cwpsrv component itself.
