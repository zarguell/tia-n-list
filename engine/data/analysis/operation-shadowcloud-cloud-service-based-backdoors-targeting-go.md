Kaspersky's two-part report describes Operation ShadowCloud, an active espionage campaign identified in early 2026 against government networks in Asia and Africa. The operator abuses the legitimate MeshAgent utility and sideloads loader DLLs such as `jli.dll` and `SbieDll.dll` to decrypt `config.ini` blobs into two previously undocumented backdoors, GitDoor (MD5 `552f0a9cc5fc3755721fa49be05e8035`) and GraphDoor (MD5 `14ec33ea808e697870d00c5e434c2952`). Both fetch plug-ins on demand and inject shellcode in memory, with command and control over Microsoft SharePoint, GitHub and Ably. The second installment, published 17 November 2026, documents GraphDoor's keylogger, process-listing and screenshot plug-ins (`kl.ts`, `pr.ts`, `scr.ts`), a patched Erfrp proxy client and Ably channel proxies. No CVE or vendor patch is attached to this activity.

The choice of C2 is the point. An organization that permits Microsoft Graph, GitHub and Ably for normal business has little network signal to block: GitDoor drops victim data into GitHub issues and repositories plus Ably channels, while GraphDoor writes files into a SharePoint tenant and pulls commands from a SharePoint list. Payloads stay encrypted on disk in `config.ini` and execute as in-memory COFF shellcode, so file hashing and static scanning alone miss the delivery, the same limitation Sophos described in October 2026 for the related BRONZE SANDCASTLE sideloading chain. Exposure is not a single host: Kaspersky found victims primarily in government networks across Asia and Africa, observed multiple backdoor builds in the wild, and found MeshCentral agent instances inside a Taiwanese organization, with the initial drop of that agent still unexplained. Sophos counted victims in five countries, the Philippines, Taiwan, Afghanistan, Namibia and likely the Republic of Korea, over incidents from August 2025 to August 2026. Because Kaspersky saw FamousSparrow and CopperTurtle staging on the same victim systems within one day of GitDoor deployment, removing GraphDoor alone can leave a second toolset in place, a risk the event list does not state.

There is no patch version to deploy, so remediation is eradication and detection engineering. Hunt for MeshCentral or MeshAgent installations without a change ticket, the sideloading pairs `javaw.exe` with `jli.dll` and `start.exe` with `SbieDll.dll`, adjacent `config.ini` payloads, `C:\ProgramData\Intel_Log` with a GUID-named subdirectory, the PID-derived pipe pattern `\\.\pipe\p` plus the process ID, and the shared memory segments `Local\sm`, `Local\pc` and `Local\pcs` with a PID suffix. Check for the keylogger artifact `%APPDATA%\Microsoft\SystemCertificates\Cache\logs.dat` and the output markers `bof-keylogger`, `bof-process` and `bof-screenshot` in process or pipe telemetry. Alert on Microsoft Graph writes to SharePoint tenants outside the estate, GitHub API writes to repositories `LatonyCharnleyaW/Trix` and `LatonyCharnleyaW/Havo`, traffic to `rest.ably.io` and `main.pusher.ably.net` from endpoints with no business need, and the reported C2 domains `ms[.]twnic[.]top` and `ekmt[.]tw` at `103[.]106[.]230[.]33` and `123[.]58[.]205[.]105`.

The assessment changes if Kaspersky or a vendor identifies how MeshCentral agent was delivered in the Taiwanese case, because that would turn a cloud-C2 detection problem into a blockable entry point. It also changes if the GraphDoor MD5, the `LatonyCharnleyaW` repositories or the `twnic[.]top` and `ekmt[.]tw` infrastructure appear in other government intrusions, or if the FamousSparrow and CopperTurtle overlaps are confirmed as shared development rather than shared staging.
