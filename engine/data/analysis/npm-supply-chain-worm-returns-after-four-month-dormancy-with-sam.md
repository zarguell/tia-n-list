The Shai-Hulud npm supply-chain worm has resurfaced after 111 days of dormancy, carrying the identical payload hash (e37e3ddeeaaa9e0c4fdbcb829b4895a6521031c80053fc436625b61e6ee5b1a6) that was publicly identified following the May 19 compromise of hundreds of @AntV package versions. Four new packages appeared on September 7 containing the same hash: feishu-docx-mcp@0.3.2, bmc-i18n-extract-cli@1.1.1, blueai-cli@0.7.0, and bmc-translate-utils@1.1.1.

The return is significant because the hash was known and flagged for months, yet the payload passed registry screening. The packages use a preinstall lifecycle hook that executes "bun run index.js" automatically on install, meaning any developer or CI/CD pipeline pulling the dependency triggers the malware without user interaction. The worm harvests npm tokens, GitHub tokens, cloud credentials, SSH keys, Docker authentication data, and CI/CD secrets, then validates stolen npm tokens to spread further.

This demonstrates that hash-based detection alone is insufficient for npm malware: the payload is byte-identical to a known threat, yet it was published and distributed without interception. The 111-day gap between activity bursts suggests the attacker may be cycling dormant accounts or maintaining a reserve of compromised maintainer tokens. Organizations with npm dependencies should audit lockfiles for the four flagged package names and the known hash.
