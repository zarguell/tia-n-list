TrustSink is a post-compromise credential-phishing technique against Microsoft Entra, documented by Varonis. An attacker holding Global Administrator or Authentication Policy Administrator privileges registers a rogue External Authentication Method (EAM), which needs only an app registration, a service principal, and a public HTTPS endpoint. Entra then treats the attacker-controlled service as the MFA provider for users assigned to it.

The flow abuses legitimate plumbing. The victim enters their password on Microsoft's real sign-in page, Entra redirects to the rogue provider for the second factor, and the provider shows a convincing copy of Microsoft's password page instead of an MFA challenge. If the user re-enters the password, the attacker's server records it in plaintext, then returns a signed token asserting the MFA check passed. Entra validates the token and completes the sign-in. In Varonis's test tenant, users reached their applications without errors while the researchers' server collected passwords, timestamps, and source IPs. The root cause is that a valid token proves nothing about what the provider actually showed the user; the PoC claimed a hardware-key check succeeded after capturing a password.

The precondition is elevated tenant access, so this is a persistence and collection tool for an attacker who is already inside, and the German coverage stresses that password resets alone do not evict it while the rogue EAM remains registered. Watch for Microsoft changes to the EAM trust model, detections keyed on new EAM registrations and Authentication Policy Administrator activity, and guidance on auditing assigned MFA providers per user.
