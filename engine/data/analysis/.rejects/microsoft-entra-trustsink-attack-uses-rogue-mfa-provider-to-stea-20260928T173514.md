Varonis researchers describe TrustSink, a post-compromise phishing technique against Microsoft Entra that abuses External Authentication Methods, the mechanism that lets tenants register third-party MFA providers. An attacker holding Global Administrator or Authentication Policy Administrator privileges registers a rogue EAM backed by an application registration, a service principal and a public HTTPS endpoint. Entra then routes affected users' MFA to the attacker-controlled service.

The flow preserves every appearance of legitimacy. The user enters their password on Microsoft's real sign-in page; when MFA starts, Entra redirects the browser to the rogue provider, which presents a convincing copy of the Microsoft password page instead of a second factor. If the user re-enters the password, the attacker records it in plaintext, then returns a signed token asserting the authentication check succeeded. Entra validates the token and completes the sign-in. Varonis proved the concept with a small OpenID Connect server, and its test tenant logged users in without errors while the researchers' server collected passwords, timestamps and source IPs. The core weakness is that a valid token proves cryptographic provenance, not that a genuine MFA challenge was shown.

The technique depends on prior tenant compromise, so it is a persistence and collection layer rather than an initial-access bug, but that is what makes it durable: password resets do not remove the rogue provider, and victims keep authenticating through it.

Defenders should audit External Authentication Methods and their underlying app registrations for anything unreviewed, alert on new EAM registration and on Authentication Policy Administrator role assignment, and treat any tenant where those privileged roles were abused as needing an EAM inventory sweep. Watch for Microsoft guidance tightening EAM token validation and for this technique appearing in real intrusion tooling.
