A Kubernetes YAML file can escalate from limited namespace access to full Google Cloud organization ownership when combined with the Google Kubernetes Config Connector (KCC) service account model. The report highlights how service-account keys create secret sprawl: JSON credential files that get copied, emailed, committed to repositories, and forgotten. KCC eliminates developer-level cloud credentials by running a controller inside the cluster that authenticates on its own. The risk arises when an attacker with namespace access abuses that controller authority to claim broader GCP permissions. This is not a new vulnerability but an operational design tension: removing developer credentials improves auditability but concentrates power in the controller. Organizations using KCC should restrict namespace permissions and audit controller service account bindings rather than relying solely on GitOps isolation.
