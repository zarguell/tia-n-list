Researchers from Graz University of Technology have described a new class of local side-channel attacks that abuse file-notification APIs: inotify on Linux, ReadDirectoryChangesW on Windows, and FSEvents on macOS. The paper, "File Notification Attacks: Templating and Exploiting Side-Channel Leakage from the File-Notification Systems on Linux, Windows, and macOS," targets the same event feeds that legitimate software such as file-sync clients, editors, antivirus tools, and file managers subscribe to. Those APIs report file access, creation, modification, deletion, opening, and closing to any local process that asks, with no administrator rights required.

The attack model assumes a malicious but unprivileged process running as a separate user, with no special hardware. The researchers built a templating method: they record which filesystem event patterns appear while a user performs a specific activity, then match later notification sequences against those templates to identify the action. The reported leakage includes keystroke timing, application launches, website visits, USB usage, VPN activity, and printing. Coverage so far comes from GBHackers and CyberPress summaries of the research; no CVE has been assigned and no in-the-wild abuse is claimed.

The reason this matters is that the side channel needs no privilege escalation and leaves the victim's files untouched, so most endpoint controls see nothing anomalous. Watch for the full paper's mitigations and whether OS vendors reduce notification fidelity, for example by restricting per-user event visibility. The template-matching approach is also a reminder that telemetry intended for convenience features can serve surveillance, so detections should not assume that read-only filesystem monitoring is harmless.
