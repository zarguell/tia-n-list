Researchers at Graz University of Technology have disclosed a class of side-channel attacks that abuse the file-notification APIs present in every major desktop OS: inotify on Linux, ReadDirectoryChangesW on Windows, and FSEvents on macOS. The paper, "File Notification Attacks: Templating and Exploiting Side-Channel Leakage from the File-Notification Systems on Linux, Windows, and macOS," assumes only a malicious unprivileged process running locally as a separate user, with no admin rights and no special hardware. The Android variant extends the model to mobile.

The technique is template matching against filesystem event streams. The researchers record notification patterns while a user performs specific activities, then correlate later event sequences against those templates to infer what the user is doing. Demonstrated inferences include keystroke timing, application launches, website visits, USB insertion, VPN activity, and printing. Because the notification APIs report access, creation, modification, deletion, opening, and closing events to any subscribed process, the surveillance works without touching protected files directly.

The significance is that this is a generic cross-platform design gap, not a bug with a single patch. The affected APIs exist to support file sync clients, editors, antivirus scanners, and file managers, so they cannot simply be locked down. Unprivileged malware that wants to profile user behavior has a free, high-resolution sensor built into the OS.

Watch for OS vendor responses, whether mitigations take the form of event coalescing, rate limiting, or ownership checks on subscription, and detection guidance for processes subscribing to filesystem events with no legitimate purpose. Until then, endpoint policies should flag unprivileged processes holding inotify, ReadDirectoryChangesW, or FSEvents watches outside known sync and security tooling.
