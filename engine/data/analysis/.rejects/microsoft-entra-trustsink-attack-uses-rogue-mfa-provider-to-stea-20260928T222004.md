TrustSink is a post-compromise credential phishing technique against Microsoft Entra that abuses External Authentication Methods, the extension point meant for third-party MFA providers. An attacker who already holds Global Administrator or Authentication Policy Administrator privileges registers a rogue EAM, which needs only an application registration, a service principal and a public HTTPS endpoint. Entra then treats the attacker-controlled service as a legitimate MFA provider for the users assigned to it.

The flow is the trap. The user enters their password on Microsoft's real sign-in page, then Entra redirects the browser to the rogue provider for the second factor. Instead of a challenge, the provider shows a convincing copy of Microsoft's password page, records the password in plaintext, and returns a signed token asserting the MFA check passed. Entra validates the token and completes the sign-in. Varonis built a working proof of concept with a small OpenID Connect server and captured passwords, timestamps and source IP addresses while users reached their applications without errors. The root weakness is that a valid token proves token signature, not that the provider ever showed a genuine challenge.

This is not a bypass an outsider can run remotely. It requires the elevated tenant privileges that follow a compromised admin account or a rogue insider, which places it in the same family as hostile OAuth app registrations and illicit token-farming tradecraft. The practical defense is control of the registration path: audit existing EAM providers, restrict and monitor the Authentication Policy Administrator role, and alert on new EAM or app registrations.

Worth watching: whether Microsoft adds consent or attestation requirements for EAM registrations, and detection guidance. As the German coverage notes, resetting passwords alone does not remove the persistence, since the rogue provider stays registered and re-triggers on the next MFA prompt.
