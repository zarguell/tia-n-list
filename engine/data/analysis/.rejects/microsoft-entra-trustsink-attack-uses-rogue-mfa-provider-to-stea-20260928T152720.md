Varonis researchers describe TrustSink, a post-compromise phishing technique that abuses Microsoft Entra External Authentication Methods. An attacker holding Global Administrator or Authentication Policy Administrator privileges registers a rogue EAM using an application registration, a service principal, and a publicly reachable HTTPS endpoint running a small OpenID Connect server. Entra then treats the attacker-controlled service as the MFA provider for users assigned to it. The user enters their password on Microsoft's genuine sign-in page, Entra redirects the MFA step to the rogue provider, and that provider shows a convincing copy of the Microsoft password page instead of a second factor. If the user re-enters the password, the attacker's server records it in plaintext, timestamps and source IP included, then returns a signed token asserting the authentication check passed. Entra validates the token and completes the sign-in, so in Varonis's test tenant victims reached their applications with no errors.

The core weakness is that a valid signed token proves nothing about what the provider actually showed the user, so Entra cannot distinguish a hardware-key check from a password harvest followed by a forged assertion. Because the technique requires tenant-level privileges, it is a persistence mechanism after an admin account is already lost, and it survives the obvious response: resetting passwords does not remove a registered rogue EAM.

Watch for Microsoft guidance on detecting and auditing EAM registrations, and check tenants now for unknown External Authentication Methods, unexplained app registrations with service principals, and MFA providers pointing at unfamiliar HTTPS endpoints. Conditional access over MFA registration and alerting on new authentication policy changes are the immediate mitigations.
