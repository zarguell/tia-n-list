Researchers from Graz University of Technology have described a class of side-channel attacks that abuse file-notification APIs to infer user and system activity on Linux, Windows, and macOS, with GBHackers also flagging Android exposure. The mechanisms abused are Linux inotify, Windows ReadDirectoryChangesW, and macOS FSEvents: OS features meant for file sync tools, editors, antivirus, and file managers that report file access, creation, modification, deletion, opening, and closing events to subscribed processes. The team's paper, "File Notification Attacks: Templating and Exploiting Side-Channel Leakage from the File-Notification Systems on Linux, Windows, and macOS", shows these routine events leak enough structure to reconstruct what a user is doing.

The attack model is a malicious but unprivileged local process running as a separate user, with no administrator rights and no special hardware. The researchers built a templating method: they record filesystem event patterns emitted while a user performs a specific activity, then match later notification sequences against those templates to identify the action. Reported inferable activities include keystroke timing, application launches, website visits, USB usage, VPN activity, and printing.

This matters because the required access level is low. No privilege escalation, no kernel exploit, and no CVE-assigned vulnerability are involved; the leakage is a generic design property of the notification APIs themselves, so patching in the usual sense does not apply. Any malware that gets a foothold under an unprivileged account can convert it into high-resolution activity surveillance, which is useful for profiling victims, confirming VPN usage before deploying destructive payloads, or timing interactions to steal credentials.

What to watch: publication of the full paper and any vendor response, since mitigations would likely mean API changes or event-coarsening in inotify, ReadDirectoryChangesW, and FSEvents rather than traditional patches. Defenders should treat already-common unprivileged malware as capable of this surveillance and prioritize keeping local execution out of user sessions entirely. There is no evidence yet of in-the-wild use; this is currently academic research.
