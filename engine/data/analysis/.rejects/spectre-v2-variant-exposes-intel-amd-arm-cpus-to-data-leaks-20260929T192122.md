Researchers from the VUSec group at Vrije Universiteit Amsterdam and Scuola Superiore Sant'Anna in Italy have disclosed Branch Target Reuse (BTR), a new variant of the Spectre v2 attack that works against Intel, AMD, and Arm CPUs. BTR targets just-in-time compilers in operating system kernels, web browsers, and language runtimes. The key observation is that while modern CPUs restore architectural code coherence after self-modifying code runs, they do not necessarily invalidate stale indirect branch prediction entries. In JIT engines those stale targets can outlive the code that created them and be reused once new code is written to the same memory, producing what the researchers call a speculative execute-after-free primitive that steers speculative execution into new code at obsolete offsets.

The impact is speculative leakage of sensitive memory to an attacker who can already run code on the machine, with password hashes cited as an example. The team analyzed Linux cBPF, Oracle's GraalVM, and SpiderMonkey, the JavaScript and WebAssembly engine in Firefox, and built two end-to-end exploits. Attacks launched from malicious web pages appear feasible, but the researchers have not yet built a complete browser exploit.

Watch for microcode and kernel mitigations from CPU vendors, and for whether anyone completes a browser-based exploit, which would move BTR from a local attack to a drive-by threat. JIT-heavy runtimes and eBPF-style kernel components are the immediate areas of concern. This is the second Spectre v2-side attack disclosure in recent months, after the Tontou attack in August, so the class is clearly active research territory again.
