GitLab's "Email work item to this project" feature generates incoming email addresses containing a long-lived token (format: incoming+project-id-glimt- -issue@incoming.gitlab.com). Security researcher Joe Leon (Aikido Security) found the glimt- token is account-scoped, not project-scoped, and does not expire by default. Changing the suffix from -issue to -merge-request lets an attacker submit a patch as a merge request using the victim's permissions. If the victim account can push to protected branches, the attacker can deliver code to those branches and trigger CI/CD pipelines. The incoming email mechanism is explicitly excluded from IP-based access controls. The event references GBHackers and CyberPress coverage, with no CVE assigned.
