Varonis researchers describe TrustSink, a post-compromise phishing technique that abuses External Authentication Methods in Microsoft Entra ID. An attacker who already holds Global Administrator or Authentication Policy Administrator rights registers a rogue EAM, which needs only an application registration, a service principal, and a public HTTPS endpoint. Entra then treats the attacker's service as a legitimate MFA provider for the users assigned to it.

The flow looks normal to the victim. The user authenticates on Microsoft's real sign-in page, then Entra redirects the MFA step to the rogue provider. Instead of a second factor, the provider serves a convincing copy of the Microsoft password page, records the password in plaintext, and returns a signed token asserting the MFA check passed. Entra validates the token and completes the sign-in. In Varonis's proof of concept, built on a small OpenID Connect server, test users reached their applications without errors while the attacker's server logged passwords, timestamps, and source IP addresses.

The root cause is that a valid token proves only cryptographic correctness, not that the user saw a genuine challenge. The provider attests to a hardware-key check that never happened, and Entra has no way to distinguish that from a real one. German coverage of the research stresses that password resets do not fix the problem, since the rogue provider stays registered and simply harvests the new credential on the next login.

Watch for Microsoft guidance on restricting who can register EAMs and whether tenant-level controls can block unvetted providers. For defenders the immediate check is inventory: enumerate registered external authentication methods and remove any that were not deployed deliberately.
