GitLab's "Email work item to this project" feature generates incoming email addresses that contain a long-lived authentication token (glimt- value). Security researcher Joe Leon at Aikido Security found the token applies account-wide, not just to the project that generated the address. The token does not expire by default. An attacker who captures a victim's incoming email address can change the suffix from -issue to -merge-request, attach a Git patch, and specify a source branch in the email subject. This causes GitLab to apply the patch to existing branches or create new branches under the victim's identity. If the victim has push access to protected branches, the attacker can introduce malicious code and trigger CI/CD pipelines. The feature also bypasses GitLab IP restrictions because incoming email is excluded from those controls. The vulnerability turns a convenience feature into an account-scoped code delivery mechanism.

What to watch: whether GitLab revokes the long-lived token design or adds expiration and scope restrictions, and whether Aikido or others publish IOCs for exploited incoming email addresses.
