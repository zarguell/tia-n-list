A single Kubernetes YAML file can escalate limited namespace access to full GCP organization ownership through Google Kubernetes Config Connector (KCC). Researchers explain that service account keys for cloud authentication spread across repositories, pipelines, and laptops, and that GitOps controllers authenticate on behalf of developers. The issue is that a malicious YAML applied to a controller with broad permissions can create cloud resources (databases, storage, VMs) under the controller's identity, which may hold organization-level roles. Google responds that the behavior is working as designed, placing responsibility on operators to restrict controller service accounts and YAML permissions.

This is not a vulnerability in Kubernetes or GCP but a design-level risk when controllers run with overprivileged service accounts. Defenders should audit KCC controller bindings, enforce least-privilege for service accounts used by controllers, and monitor for unexpected resource creation outside standard namespaces. Watch for updates on whether Google introduces additional guardrails or if threat actors begin weaponizing this path.
