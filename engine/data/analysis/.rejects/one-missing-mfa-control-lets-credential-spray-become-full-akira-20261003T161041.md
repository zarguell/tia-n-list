Akira ransomware affiliates continue to turn missing MFA on VPN appliances into full domain compromises. The August 2026 intrusion started with a credential spray against a SonicWall SSL VPN, succeeded at 03:52 UTC because the account had no MFA, and within two hours the attacker reached the domain controller via RDP. They enumerated Active Directory, archived file shares with WinRAR, exfiltrated data to S3 using s5cmd, and installed AnyDesk. A new anti-EDR tactic appeared: rebooting into Safe Mode with Networking to disable both Huntress and Microsoft Defender, though the constrained boot environment crashed the ransomware from memory exhaustion seconds after launch. The latest update adds a threadlinqs summary (low-trust) emphasizing the same playbook — VPN with no MFA, rapid data theft, backups wiped before encryption, with 9 detections and 31 IOCs — but without independent verification it remains unverified lead material rather than primary reporting. The persistent pattern is the absence of MFA on remote-access gateways, not a new vulnerability.
