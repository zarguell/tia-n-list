Varonis researchers describe TrustSink, a post-compromise credential-harvesting technique that abuses Microsoft Entra External Authentication Methods (EAMs). An attacker holding Global Administrator or Authentication Policy Administrator privileges registers a rogue EAM, which needs only an application registration, a service principal and a publicly reachable HTTPS endpoint. Entra then treats the attacker-controlled service as the MFA provider for the users assigned to it. The victim enters their password on Microsoft's genuine sign-in page; when MFA starts, Entra redirects the browser to the rogue provider, which instead of requesting a second factor displays a convincing copy of Microsoft's password page, records the plaintext password, and returns a signed token asserting the MFA check passed.

The failure is in the trust model: a valid token from an EAM proves nothing about what the provider actually showed the user. In Varonis's proof of concept, built on a small OpenID Connect server, the researchers' backend claimed a hardware-key check had succeeded after collecting nothing but a password. Users reached their applications without errors while the attacker's server logged passwords, timestamps and source IP addresses, so the compromise is invisible to both the user and the sign-in logs. Because registration persists at the tenant level, resetting a harvested password is not enough; the rogue provider keeps capturing every subsequent sign-in for its assigned users.

This is a post-compromise persistence technique, not an initial access vector: it requires an attacker who already holds top-tier directory roles. The defensive work is configuration hygiene. Audit existing EAM registrations and treat any unrecognized provider as an incident, alert on new EAM creation and on Authentication Policy Administrator role grants, verify redirect destinations during MFA flows, and fold EAM review into compromise recovery so an evicted attacker does not keep a credential tap behind. Watch for weaponized versions of the PoC appearing in adversary tooling, since the technique needs only stolen privileged access to become a durable password sink.
