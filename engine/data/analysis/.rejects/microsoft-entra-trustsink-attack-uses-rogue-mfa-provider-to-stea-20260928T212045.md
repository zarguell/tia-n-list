Varonis researchers describe TrustSink, a post-compromise credential phishing technique against Microsoft Entra ID that abuses External Authentication Methods, the mechanism normally used to federate third-party MFA providers into the sign-in flow. An attacker who already holds Global Administrator or Authentication Policy Administrator privileges registers a rogue EAM: an application registration with a service principal and a public HTTPS endpoint. Entra then treats the attacker's server as the MFA provider for users assigned to it.

The trap closes during a normal login. The victim enters their password on Microsoft's genuine sign-in page, then Entra redirects the browser to the rogue provider for the second factor. Instead of an MFA challenge, the attacker's page shows a convincing copy of Microsoft's password prompt. A second password entry is captured in plaintext, after which the provider returns a signed token asserting the MFA check passed. Entra validates the token and completes the sign-in, so the user sees no errors while the attacker's server logs the password, timestamp, and source IP. Varonis proved the flow with a small OpenID Connect server; the core weakness is that a valid token proves nothing about what the provider actually showed the user.

The barrier is the required privileged role, which makes this a persistence and lateral movement technique for attackers who have already taken over a tenant admin, not a way in by itself. German coverage of the research stresses that password resets alone do not evict an attacker who holds a registered EAM. Watch for auditing guidance on EAM registrations, tenant hardening around Authentication Policy Administrator, and whether Microsoft adds detection or restrictions for EAM providers that mimic sign-in pages.
