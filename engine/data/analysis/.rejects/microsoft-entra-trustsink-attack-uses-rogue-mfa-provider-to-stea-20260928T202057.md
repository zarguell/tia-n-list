Varonis researchers disclosed TrustSink, a post-compromise credential-phishing technique that abuses Microsoft Entra External Authentication Methods (EAMs) to place a rogue password prompt inside an otherwise legitimate Microsoft sign-in flow. An attacker who already holds Global Administrator or Authentication Policy Administrator privileges registers a rogue EAM, which needs only an application registration, a service principal, and a publicly reachable HTTPS address. Entra then treats the attacker-controlled service as the MFA provider for users assigned to it.

The flow is the trap. The user enters their password on Microsoft's real sign-in page; when MFA starts, Entra redirects the browser to the rogue provider, which shows a convincing copy of the Microsoft password page instead of a second factor. If the user types the password again, the attacker's server records it in plaintext, then returns a signed token asserting the authentication check passed. Entra validates the token and completes the sign-in, so the victim notices nothing. In Varonis's test tenant, users reached their applications without errors while the researchers' server collected passwords, timestamps, and source IP addresses. The root issue is that a valid token from an EAM does not prove the provider showed a genuine MFA challenge.

The prerequisite is the mitigation boundary: registering the rogue provider requires top-tier tenant privileges, so TrustSink is a persistence and credential-harvesting layer an attacker adds after an initial takeover, not a way in. German coverage of the research stresses that password resets alone do not evict an attacker who holds an EAM registration. Watch for Microsoft guidance or a service change on EAM registration controls and auditing, since tenant admins currently need to review their authentication policy administrators and registered external providers themselves.
