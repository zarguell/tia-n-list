A researcher publishing as NightmareEclipse, under the GitHub account MSNightmare, disclosed BigDiskBuster, a proof of concept that blocks Microsoft Defender from completing its platform and security intelligence updates by filling disk space. The result is a denial-of-service condition on endpoint protection freshness: Windows machines keep running Defender on stale malware definitions while the product believes it is healthy. No patch was available at disclosure, and the project is explicitly framed as a Defender update denial-of-service technique rather than an exploit.

Severity here comes from chaining, not from the bug itself. An attacker who can consume free space on a target, which is a trivial side effect of many intrusion playbooks, can quietly strip a fleet of current detections and then run any of the hundreds of public exploits that stale definitions no longer flag. The sources read for this story report no observed in-the-wild exploitation; it remains public PoC code.

Watch for three things: whether Microsoft ships a fix or reserved-space hardening for Defender's update staging, whether red team tooling absorbs the technique as a standard pre-encryption or pre-lateral-movement step, and any Defender advisory confirming the behavior and a remediation timeline.
