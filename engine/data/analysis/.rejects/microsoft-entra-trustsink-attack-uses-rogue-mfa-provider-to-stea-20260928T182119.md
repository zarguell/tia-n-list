Varonis researchers describe TrustSink, a post-compromise credential phishing technique that abuses Microsoft Entra External Authentication Methods. An attacker who already holds Global Administrator or Authentication Policy Administrator privileges registers a rogue EAM, which requires an application registration, a service principal, and a publicly reachable HTTPS endpoint. Entra then treats the attacker-controlled service as the MFA provider for the users assigned to it.

The flow starts on the genuine Microsoft sign-in page, where the user enters their password. When MFA begins, Entra redirects the browser to the rogue provider. Instead of requesting a second factor, the provider shows a copy of Microsoft's password page and records the password in plaintext. It then returns a signed token claiming the authentication check passed, Entra validates it, and the sign-in completes normally. In Varonis's test tenant, users reached their applications without errors while the researchers' small OpenID Connect server logged passwords, timestamps, and source IP addresses. The flaw in the design is that a valid token does not prove the provider presented a genuine MFA challenge: the PoC claimed a hardware-key check had succeeded while it collected a password.

The required privileges make this a follow-on attack after an admin or tenant takeover rather than a standalone bug, which is why German coverage of the research stresses that password resets alone do not fix it, since the rogue provider stays registered. Watch for unexpected EAM registrations, new service principals attached to authentication methods, and MFA providers pointing at unfamiliar HTTPS endpoints. Auditing External Authentication Methods should be part of incident response for any tenant where privileged accounts were compromised.
