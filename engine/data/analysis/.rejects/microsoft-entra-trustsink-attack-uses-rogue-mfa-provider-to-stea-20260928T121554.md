TrustSink is a post-compromise credential-phishing technique that abuses Microsoft Entra External Authentication Methods (EAMs). An adversary with elevated tenant privileges inserts a rogue password prompt inside an otherwise legitimate Microsoft sign-in flow. The victim sees what appears to be a standard MFA challenge, enters their plaintext password, and the attacker captures it while a valid signed token is returned to Entra. The login completes normally from the user's perspective, making the interception invisible.

The technique was reported by GBHackers and corroborated by German outlets baurnewmedia.de and winfuture.de. No CVEs are assigned; the flaw is not a code vulnerability but a design-level abuse of trust relationships in external MFA provider configurations. Organizations using Microsoft Entra with third-party EAM integrations should audit which external authentication providers are registered in their tenant and verify that all providers map to legitimate services.

There are no confirmed victim counts or in-the-wild exploitation campaigns reported in the coverage. The risk is elevated for environments where tenant-level administrators or service principals have been compromised, since the attack requires elevated privileges to register or redirect to a malicious EAM provider. Watch for Microsoft guidance or advisory updates addressing EAM provider validation, and review Entra audit logs for unexpected external authentication method registrations.
