GitLab's "Email work item" feature generates a long-lived incoming email token that is account-scoped rather than project-scoped, according to Aikido Security researcher Joe Leon. The token appears in addresses for multiple projects, including private repositories, and does not expire by default. An attacker with access to the address can change the suffix from -issue to -merge-request, submit a Git patch attachment, and specify a source branch. If the victim account has authorization to push to protected branches, the attacker can create branches or trigger CI/CD pipelines. Because incoming email is excluded from IP restrictions, the attack also bypasses those controls. The issue has existed for years and affects every project the token holder can access; users should rotate or disable incoming email tokens and restrict protected-branch permissions.
