The Mini Shai-Hulud worm continues to reinfect GitHub repositories through hijacked GitHub Actions. Two specific Actions, issues-helper and maintain-on, were re-enabled after earlier removal, exposing thousands of repositories to compromise. The infection mechanism uses malicious workflow triggers that inject malicious payloads into repository builds. This is a persistent supply-chain threat rather than a one-time breach: the worm has already demonstrated reinfection capability after initial cleanup efforts.

New reporting describes the exposure as critical, with thousands of repositories at risk. The original event from safedep.io documented the persistent infection pattern, while the update highlights the re-enabled Actions as the new infection vector. The story includes four events tracking the campaign from initial disclosure through reinfection. No independent vendor patch or GitHub-wide mitigation is mentioned in the event text, which implies the burden remains on repository maintainers to audit their Actions dependencies.

What to watch: whether GitHub disables the identified Actions globally or forces repository-level audits, and whether additional Actions are added to the infection chain as the worm evolves its persistence mechanism.
