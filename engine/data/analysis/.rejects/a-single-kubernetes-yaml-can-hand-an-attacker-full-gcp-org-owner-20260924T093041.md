A Kubernetes YAML file applied through Google Kubernetes Config Connector (KCC) can escalate from namespace-level access to full Google Cloud organization ownership. The mechanism exploits how KCC's controller authenticates on the developer's behalf: a malicious YAML describes cloud resources the attacker wants to control, and the controller creates them with its service identity. Google's assessment is that this works as designed, not a vulnerability. Security researcher Varonis documented the path; the event notes 9 detections and 7 IOCs associated with the technique. Organizations using KCC should treat any untrusted YAML input as an organization-level privilege escalation risk and restrict who can commit to GitOps repositories that feed the controller.
