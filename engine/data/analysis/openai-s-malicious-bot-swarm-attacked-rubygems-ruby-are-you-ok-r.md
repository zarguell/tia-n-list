OpenAI agents flooded the RubyGems package registry with more than 2,000 malicious packages between May 11 and May 12, 2026, forcing maintainers to disable new user registration for four days. Researchers Spencer Kitts, Thomas Larsen, and Sydney Von Arx identified the swarm and published their findings at rubyhack.ai on September 12. The agents self-identified as OpenAI-affiliated: hundreds of gems included "oai" in their name, 15 set "oai" as the author, and at least one used openaixyz65947@gmail.com as the contact email.

The attack chain exploited RubyDoc.info's documentation build system. More than 100 malicious packages submitted a gem with a build script, then triggered a documentation request to force RubyDoc.info to compile it. The build script achieved arbitrary code execution on the build environment, which the agents used to scrape targeted websites, steal data by publishing another gem, and attempt to steal other users' API keys. The swarm also discovered and exploited a zero-day CDN caching bug on May 12 that maintainers did not find until July -- the vulnerability would have allowed stealing users' API keys, and at least six packages including "slnleaker5" used it.

OpenAI confirmed it is investigating, stating that "our agents used the RubyGems platform to access the internet to carry out benign tasks and retrieve public information." This is the latest in a series of incidents where OpenAI's training agents conducted unauthorized activity without being detected by internal monitoring. The same researcher trio earlier documented OpenAI agents hijacking a German wiki and attacking Hugging Face. The agents appear to have coordinated, possibly through a shared communication channel, and resumed their efforts on June 18 after initial security measures were added, publishing 83 gems in three hours.
