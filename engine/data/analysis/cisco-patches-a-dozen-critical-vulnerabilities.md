Cisco's October 2026 patch batch fixed 35 vulnerabilities across the portfolio, more than a dozen rated critical. The hardest hit products: Meraki, where a hardening release groups multiple memory bugs under seven CVEs with CVE-2026-76464 (buffer overflows, out-of-bounds writes) the worst; License On-Prem, with eight fixes including five critical, among them unauthenticated unauthorized access in CVE-2026-20328 and unauthenticated denial of service in CVE-2026-76454; and NX-OS, with 14 fixes, seven critical.

The NX-OS set is the urgent one. Advisory cisco-sa-ngoam-rce-LWKQ4BU (October 7) covers three CVSS 9.8 flaws in the Next Generation OAM feature of Nexus 3000 and 9000 switches, CVE-2026-76485, CVE-2026-76486 and CVE-2026-76501, all exploitable by unauthenticated attackers for root code execution or device reload via crafted packets, with no workarounds. BleepingComputer's read of the advisories: five critical NX-OS bugs across NX-API, NGOAM and MPLS OAM, exploitation gated on features being active. CVE-2026-76486 additionally requires SRv6 or NV Overlay with an EVPN-mapped VNI and a learned VTEP peer, and CVE-2026-76501 requires SRv6, which only some Nexus 9000 models support. CVE-2026-76465 needs MPLS OAM explicitly enabled.

The Canadian Centre for Cyber Security's AV26-1020 summary shows the batch's long tail: UCS 6300 fabric interconnects, the full Meraki line, APIC, and contact-center products (Finesse, Packaged CCE, Unified CCX) where fixes land as late as February 2027. Meraki campus gateway fixes are dated late October and mid-November 2026, so Meraki estates stay exposed weeks after disclosure. Watch for public exploit code against the NGOAM trio, since disabled-but-present NGOAM on internet-reachable Nexus management planes is the likely first target, and for scanner traffic probing NX-API and MPLS OAM endpoints.
