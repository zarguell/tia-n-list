Cisco's October 7 patch batch covers 35 vulnerabilities, more than a dozen critical, across Meraki, NX-OS, License On-Prem, UCS, APIC and the contact-center line. The sharp end is advisory cisco-sa-ngoam-rce-LWKQ4BU, first published October 7 at 16:00 GMT: three CVSS 9.8 flaws, CVE-2026-76485, CVE-2026-76486 and CVE-2026-76501, in the Next Generation OAM feature of Nexus 3000 and 9000 switches running standalone NX-OS. An unauthenticated attacker who can reach the device sends crafted packets and gets arbitrary code execution with root privileges, or a process crash and reload. Cisco published the bugs under CSCwu19785 and CSCwu19823, says they came out of internal security testing, and reports no public announcements or malicious use so far. Exploitation is gated: NGOAM must be enabled, CVE-2026-76486 also needs SRv6 or NV Overlay with an EVPN VNI mapped to an NVE interface and at least one learned peer VTEP, and CVE-2026-76501 needs SRv6, which only some Nexus 9000 models support.

The quieter bug in the same batch is the bigger operational risk: CVE-2026-20328 in Cisco License On-Prem, the product better known as Smart Software Manager On-Prem. The advisory summary calls it unauthorized access; the underlying record is more specific, improper checks during the password reset process that let an unauthenticated attacker reset the password of any account, including high-privileged administrators, on the appliance's web management interface. That is full account takeover of the server that registers and brokers licenses for the rest of the Cisco estate, a box that has to be reachable for devices to do their job. A batch that lands root RCE on data center switches and unauthenticated admin takeover of the licensing plane at the same time concentrates risk exactly where downtime hurts most, which is why this story outranks the routine volume of the day. The feature gating on the NX-OS trio narrows the target set but does not neutralize it, because NX-API is commonly left on for automation and the forced-reload outcome alone is an availability lever on any switch with the features active.

Patch targets from the advisories: License On-Prem release 10-202609, Meraki campus gateways 32.2.5 (late October 2026) or 33.1.4 (mid-November 2026), UCS 4.3(6.260049) or later builds, and APIC 6.0(9h), 6.1(6g) or 6.2(3g); NX-OS fixed releases come from the Cisco Software Checker against advisory cisco-sa-ngoam-rce-LWKQ4BU, since Cisco lists no inline fixed versions and no workarounds for the trio. Until upgrades land, audit switch configs for `feature ngoam`, `feature nx-api` and `feature mpls oam`, disable the ones not in use, and restrict reachability of those planes to hosts that genuinely need them. Hunt on two fronts: NX-OS syslog for unexplained process crashes or reloads on Nexus 3000/9000 hosts where those features are enabled, and License On-Prem logs for password-reset requests against accounts the requester should not control, administrator resets above all, the signature of CVE-2026-20328. Calendar the contact-center fixes now, because Packaged CCE 15.0(1)ES202701 ships January 2027 and Finesse and Unified CCX follow in February 2027.

Two developments would change this assessment. Public exploit code or scanning traffic against NGOAM, NX-API or MPLS OAM endpoints, since Cisco found these flaws internally and any external exploitation would mark a pivot away from the current no-malicious-use baseline. Early KEV or EPSS movement on CVE-2026-20328, which would confirm attackers rate the licensing plane the way this assessment does.
