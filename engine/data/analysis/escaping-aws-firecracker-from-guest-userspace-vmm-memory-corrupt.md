Researchers published a coordinated-with-AWS study on escaping Firecracker microVMs, tracked as CVE-2026-122192 (with CVE-2026-122266 also named). The flaw arises when a microVM is restored from a snapshot using the File memory backend: a failed memory remapping operation can leave KVM referencing a stale host virtual address range. Firecracker may then reuse that memory for its own data while KVM still treats it as guest memory, letting a malicious guest read or overwrite Firecracker VMM process memory and cross the VM isolation boundary. The research demonstrates an exploit chain from guest userspace to controlled code execution on the host, affecting Firecracker 0.23.0 through 1.16.1 when restoring from a snapshot.

The mastodon pointer in the store adds only a link to the AWS security bulletin and no further technical detail. Operators running affected Firecracker versions with snapshot restore should review the AWS bulletin for patched releases and mitigations, since a guest-to-host code execution primitive in a VMM breaks the core isolation guarantee that microVMs provide.
