Researchers coordinated with AWS disclosed CVE-2026-122192, a VMM memory corruption flaw in Firecracker that lets a malicious guest escape the microVM boundary. The bug appears when a microVM is restored from a snapshot using the File memory backend: a failed memory remapping operation can leave KVM referencing a stale host virtual address range. Firecracker may then reuse that memory for its own data while KVM still treats it as guest memory, allowing the guest to read or overwrite Firecracker VMM process memory. The published exploit chain runs from guest userspace to controlled code execution on the host.

Affected configurations are Firecracker 0.23.0 through 1.16.1 when restoring from a snapshot with the File memory backend. AWS published the finding as security bulletin 2026-169. Operators running affected Firecracker versions should patch or avoid snapshot restore with the File backend until fixed builds are available, since a single malicious guest can compromise the host VMM.

The disclosure is single-source research rather than a CISA KEV entry, so there is no confirmed in-the-wild exploitation at this time. Watch for downstream consumers of Firecracker, including AWS Lambda and Fargate, to issue their own advisories and patched runtimes.
