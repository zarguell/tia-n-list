A Redis cryptomining botnet operator left their entire working directory exposed on a compromised server, including exploit code, campaign logs, a bundled Python runtime, and two Windows registry hives. The exposed logs revealed the campaign compromised 3,562 Redis servers out of 12,966 targeted. The operator used Redis replication abuse to deploy cron jobs running XMRig for Monero mining. SSH and MongoDB exploitation attempts returned zero results, confirming Redis replication is the only viable technique at scale.

Victim servers span eight years of Redis versions, indicating the root cause is missing authentication rather than unpatched vulnerabilities. Redis instances exposed to the internet without requirepass or ACLs are trivially exploitable. The same crypto wallet ties this campaign back to an earlier February 2026 operation, meaning the operator has been active for at least seven months.

Hunt.io published the original analysis on September 8, with securityonline.info providing follow-up coverage. Organizations should ensure Redis instances are not exposed to the internet, require authentication, and bind to localhost unless external access is explicitly needed.
