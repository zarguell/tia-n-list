Let's Encrypt is moving to 64-day default certificate lifetimes starting February 10, 2027, with staging tests opening October 14, 2026. The change is an intermediate step before a 45-day default planned for 2028, aligning with CA/Browser Forum Baseline Requirements that will apply to all publicly trusted CAs. The last 90-day certificate is expected to expire on May 11, 2027; authorization reuse shrinks from 30 days to 10 days now, then to seven hours in 2028.

Defenders should treat this as an automation stress test, not a headline attack. Any organization with hardcoded renewal windows like 83, 80, or 60 days in cron jobs, wrapper scripts, or runbooks risks service outage once 64-day certificates enter production. The events cite ARI support as the preferred path: clients that implement ACME Renewal Info will receive renewal prompts from Let's Encrypt automatically, while others must shift to renewing at roughly two-thirds of lifetime. Staging testing is explicitly recommended before February 2027.

Now is the time to audit renewal logic and test in staging. Search for static renewal thresholds in deployment repositories, verify ACME client documentation for ARI implementation, and add alerting for renewal failures. Network restrictions are minimal because this is a policy change rather than an active exploit, but operators relying on long-lived 90-day certificates for embedded devices or air-gapped systems should plan replacement schedules around the May 11, 2027 expiration boundary.

Watch for the staging rollout on October 14, 2026, and any updates from the CA/Browser Forum that could accelerate the 2028 45-day timeline. A second development to track is whether ACME client vendors complete ARI implementations ahead of production, since gaps there will determine which environments break first.
