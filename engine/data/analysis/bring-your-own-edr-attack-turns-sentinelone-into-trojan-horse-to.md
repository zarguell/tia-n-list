Akamai researchers presented a Bring Your Own EDR (BYOEDR) technique at DEF CON 34 that turns a legitimate SentinelOne endpoint agent into a privileged trojan on Windows. The attack abuses exposed COM interfaces in the SentinelOne stack, specifically the SentinelHelper.1 interface and a Dump method identified by researcher Shahak Morag, which can create process dumps for a supplied process ID. The operation runs through SentinelOne's protected context, so with local administrator privileges an attacker can dump PPL-protected processes including SentinelOne components and Microsoft Defender's MsMpEng.exe.

The researchers chained the dump primitive with prior public PPL research to extract COM-related secrets from protected targets, then refined an injection workflow to execute unsigned code inside a PPL process. The chain relies on statically compiled payloads and avoids unsigned runtime DLL dependencies; it needs no malicious kernel driver, no Windows kernel vulnerability, and no memory-corruption exploit. The research also demonstrated enrollment abuse: installer validation accepted fabricated registration data, producing an agent that looks secure but lacks management connectivity, and redirecting the configured management hostname to localhost can isolate the agent from cloud telemetry while it still reports healthy locally.

SentinelOne fixed the reported issue in Agent version 26.1.1, so the near-term mitigation is upgrading agents and restricting local administrator rights. The broader lesson is that EDR products are privileged attack surface: their local interfaces, installers, and trust relationships sit above the boundary PPL is meant to protect. Watch for weaponized versions of the dump or injection primitives against other EDRs, and audit agent enrollment events and management hostname changes as signs of this technique.
