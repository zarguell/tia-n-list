Apache HTTP Server 2.4.71 fixes CVE-2026-119618, a race condition in mod_http2's assign_headers() that can corrupt heap memory and give an unauthenticated remote attacker code execution. Red Hat scores it 9.8. Servers from 2.4.55 through 2.4.70 with HTTP/2 enabled are in scope, as are standalone mod_h2 2.0.8 through 2.0.42; HTTP/1.1-only servers are not on the known path. Anthropic's OSS Scanner reported the bug on October 26 and Google Cloud Vulnerability Research reported it independently on November 3.

Early coverage on November 13 said no active exploitation had been observed. That changed on November 17, when Singapore's CSA warned that exploitation was underway and a public proof of concept was available, and urged immediate patching without naming victims. Distribution packages have landed unevenly, so checking the installed version matters more than trusting the upstream release date. Where upgrading is delayed, disabling HTTP/2 removes the known attack path.

New guidance this hour repeats the same instruction: upgrade to 2.4.71 or disable HTTP/2 until the update is applied. Watch for vendor advisories that confirm which packages carry the fix, for any CSA detail on the exploited configurations, and for exploit attempts against exposed 2.4.55 through 2.4.70 servers. Older flaws in this cluster, including the 2.4.66 double-free fixed in 2.4.67, show the same pattern of HTTP/2 code producing repeated memory-corruption emergencies.
