Apache released HTTP Server 2.4.71 on November 11, 2026 to fix CVE-2026-119618, a critical race condition in mod_http2 rated CVSS 9.8. The flaw affects versions 2.4.55 through 2.4.70 and lets an unauthenticated remote attacker corrupt heap memory and potentially execute arbitrary commands, but only on deployments with HTTP/2 enabled through h2 or h2c. Anthropic's OSS Scanner reported the issue on October 26 and Google Cloud Vulnerability Research independently reported it on November 3. The same release also fixes CVE-2026-106023 and CVE-2026-109163, and follows the October 1, 2026 2.4.69 release that patched 20 CVEs, including a mod_vhost_alias stack overflow (CVE-2026-63292), a mod_http2 use-after-free via shared session bbtmp re-entrancy (CVE-2026-57941) affecting 2.4.17 through 2.4.68, and a mod_dav shared lock overflow (CVE-2026-42528) affecting 2.4.67 and earlier. A separate critical double-free in mod_http2, CVE-2026-23918 with CVSS 8.8, affects version 2.4.66 on multi-threaded MPM configurations and is confirmed to yield remote code execution on Debian-derived systems through the scoreboard shared-memory region.

The exposure is large because Censys observes roughly 166 million Apache HTTP Server web properties, and Wiz reports that 64 percent of cloud environments run an affected version. Red Hat notes that servers configured to serve only HTTP/1.1 are not vulnerable, so the risk is concentrated in HTTP/2-enabled deployments. Debian has released patches and standalone mod_h2 releases from GitHub are also available. Operators should treat any 2.4.55 through 2.4.70 build with HTTP/2 enabled as exposed until upgraded.

Upgrade to 2.4.71 or a vendor-patched build and restart the daemon, then verify the running version and that no stale mod_h2 module remains loaded. Where an immediate upgrade is not possible, disable HTTP/2 by removing h2 and h2c from the Protocols directive, or restrict HTTP/2 to trusted networks. Hunt access logs for unusual HTTP/2 request patterns and crash signatures in worker processes, and review any Debian-derived hosts running 2.4.66 for signs of compromise given the confirmed code execution chain for CVE-2026-23918. Watch for vendor errata, CISA KEV additions, and any public proof-of-concept code that would move this from a patching problem to an active intrusion problem.
