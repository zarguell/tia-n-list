Apache HTTP Server 2.4.69 shipped on October 1, 2026 with fixes for 20 CVEs: five rated moderate and fifteen low. The moderate set includes CVE-2026-63292, a stack-based buffer overflow in mod_vhost_alias that lets a remote client cause denial of service or potentially execute arbitrary code by sending a Host header exceeding 8192 bytes when VirtualDocumentRoot uses a hostname format specifier and LimitRequestFieldSize is raised above the default, credited to Hyojae Lee and Zhen Kong. Also fixed are CVE-2026-57941, a mod_http2 use-after-free via shared session bbtmp re-entrancy affecting 2.4.17 through 2.4.68, and CVE-2026-42528, a mod_dav shared lock overflow affecting 2.4.67 and earlier. The later 2.4.71 release addresses CVE-2026-119618, CVE-2026-106023, and CVE-2026-109163.

The risk is broad exposure rather than a single critical flaw. Apache HTTP Server is widely deployed, and several of the patched issues touch request handling, HTTP/2, and WebDAV paths that are reachable on internet-facing hosts. The code fix for CVE-2026-63292 landed in the 2.4.x branch on September 29, 2026, two days before the public advisory, so administrators who track the source tree had a short head start but most operators depend on packaged releases.

Administrators should move to 2.4.69 at minimum and 2.4.71 where available, then review configurations that raise LimitRequestFieldSize or use VirtualDocumentRoot with hostname specifiers. No in-the-wild exploitation is reported in the available coverage, but the public advisories and PoC-level detail on the mod_vhost_alias overflow make patching the priority, with configuration review as a compensating control.
