Apache HTTP Server versions 2.4.55 through 2.4.70 carry a critical race condition in mod_http2 tracked as CVE-2026-119618 (CVSS 9.8). An unauthenticated remote attacker can corrupt heap memory and execute arbitrary commands on the server process, but only when HTTP/2 is enabled via h2 or h2c; servers configured for HTTP/1.1 only are not exposed. Apache addressed the flaw in version 2.4.71, released November 11, 2026, and standalone mod_h2 releases 2.0.8 through 2.0.42 are also affected. The same release fixes additional mod_md and mod_vhost_alias weaknesses rated important and low.

The issue was reported independently, first by Anthropic's OSS Scanner on October 26 and then by Google Cloud Vulnerability Research on November 3. Cloud security firm Wiz estimates that 64 percent of cloud environments in its data run affected Apache versions and 51 percent have publicly exposed instances, though those figures do not account for HTTP/2 configuration. The broader Apache story also includes a separate set of Apache Struts vulnerabilities fixed in Struts 7.4.0 and 6.12.0 covering remote code execution, denial of service, and cross-user data disclosure.

Administrators should prioritize internet-facing Apache instances with HTTP/2 enabled, upgrade to 2.4.71 or later, and verify any standalone mod_h2 deployments. Because the flaw is unauthenticated and network-reachable, exposed management and edge servers are the highest-risk targets until patched.
