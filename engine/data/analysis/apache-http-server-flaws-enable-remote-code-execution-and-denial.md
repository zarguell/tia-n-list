Apache HTTP Server 2.4.71, released on November 11, 2026, fixes CVE-2026-119618, a critical race condition in the mod_http2 module that can let an unauthenticated remote attacker corrupt heap memory and execute arbitrary commands. The flaw affects Apache HTTP Server 2.4.55 through 2.4.70 when HTTP/2 is enabled, and Red Hat assigned it a CVSS 3.1 score of 9.8. Apache credited Anthropic's OSS Scanner with reporting the issue on October 26, while Anthony Weems and Simon Scannell of Google Cloud Vulnerability Research independently reported it on November 3. Standalone mod_h2 releases 2.0.8 through 2.0.42 are also affected, and Apache has not yet identified a separately fixed standalone mod_h2 version.

The 2.4.71 release is the latest in a busy patch cycle. Apache 2.4.69 shipped on October 1, 2026 with 20 fixes, five moderate and fifteen low, including CVE-2026-63292, a mod_vhost_alias stack overflow reachable through an oversized Host header, and CVE-2026-57941, a mod_http2 use-after-free. Cloud security firm Wiz reported that 64 percent of cloud environments in its data ran affected Apache versions and 51 percent had publicly exposed instances, though those figures do not account for server configuration or whether HTTP/2 was enabled. Servers configured to serve only HTTP/1.1 are not vulnerable to CVE-2026-119618, so disabling HTTP/2 via the Protocols directive is a workable interim mitigation when an immediate upgrade is not possible.

No in-the-wild exploitation of CVE-2026-119618 has been confirmed in the reporting, but the exposure is large and the flaw is network-reachable with low complexity. Administrators should upgrade to 2.4.71, which also addresses CVE-2026-106023 and CVE-2026-109163, and review HTTP/2 enablement across their fleet. Earlier HTTP/2 flaws such as CVE-2026-23918, a double-free in 2.4.66 with a published proof of concept, show how quickly Apache mod_http2 bugs can draw exploit development, so patching should not wait for confirmed exploitation.
