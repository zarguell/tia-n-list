Apache HTTP Server 2.4.71, released November 11, 2026, fixes CVE-2026-119618, a critical race condition in mod_http2 that allows unauthenticated remote code execution. The flaw affects versions 2.4.55 through 2.4.70 with HTTP/2 enabled; servers configured exclusively for HTTP/1.1 are not vulnerable. Red Hat assigned CVSS 3.1 9.8. The bug sits in the assign_headers() function, where concurrent threads access shared resources without proper synchronization and corrupt heap memory. Anthropic's OSS Scanner reported it on October 26 and Google Cloud Vulnerability Research independently reported the same issue on November 3. Wiz found 64% of cloud environments in its data running affected versions and 51% with publicly exposed instances, though server configuration affects actual exploitability.

The same 2.4.71 release also patches mod_md and mod_vhost_alias issues. Separately, Apache 2.4.69 shipped on October 1, 2026 with 20 CVEs, including CVE-2026-63292, a mod_vhost_alias stack overflow triggered by a Host header over 8192 bytes when VirtualDocumentRoot uses a hostname format specifier, and CVE-2026-57941, a mod_http2 use-after-free. An earlier critical flaw, CVE-2026-23918, a double-free in the HTTP/2 handler of 2.4.66 (CVSS 8.8), was fixed in 2.4.67 and has a confirmed remote code execution chain on Debian-derived systems via scoreboard abuse.

No active exploitation of CVE-2026-119618 has been observed to date, but patch availability across Linux distributions remains uneven. The only interim mitigation short of upgrading is disabling HTTP/2 (Protocols h2 h2c). Standalone mod_h2 releases from GitHub, versions 2.0.8 through 2.0.42, are also affected. Administrators should upgrade to 2.4.71, confirm distribution packages are not still marked vulnerable, and treat HTTP/2-enabled internet-facing instances as the priority.
