Apache HTTP Server 2.4.71, released November 11, 2026, fixes CVE-2026-119618, a critical (CVSS 9.8) race condition in mod_http2's assign_headers() that can lead to unauthenticated remote code execution on versions 2.4.55 through 2.4.70 with HTTP/2 enabled. The flaw is concurrent execution using a shared resource with improper synchronization: two threads handling HTTP/2 traffic can touch the same memory without coordination, producing heap corruption that an attacker who can shape request timing and content may steer to code execution. Only HTTP/2-enabled deployments are exposed; HTTP/1.1-only servers are not. Anthropic's OSS Scanner reported the issue on October 26 and Google Cloud Vulnerability Research (Anthony Weems and Simon Scannell) independently on November 3; Apache credited both. Standalone mod_h2 2.0.8 through 2.0.42 is also affected, and no fixed standalone version is identified. No active exploitation has been observed, but Wiz reported 64% of cloud environments in its data ran affected versions and 51% had publicly exposed instances, though configuration was not accounted for.

The 2.4.71 release also fixes CVE-2026-106023 and CVE-2026-28780 (mod_vhost_alias), following the 2.4.69 release on October 1 that shipped 20 CVEs including CVE-2026-63292, a mod_vhost_alias stack buffer overflow reachable via a Host header over 8192 bytes when VirtualDocumentRoot uses a hostname format specifier and LimitRequestFieldSize is raised above default. Earlier, 2.4.67 (May 2026) fixed CVE-2026-23918, a double-free in mod_http2 triggered by a crafted early-reset HTTP/2 frame that guarantees denial of service on all deployments and enables remote code execution on Debian-derived systems using the mmap allocator, with a public PoC available.

Operators should upgrade to 2.4.71 immediately, or disable HTTP/2 (Protocols h2 h2c) as an interim mitigation where patching is delayed. MPM prefork is not affected by CVE-2026-23918, but the current critical race affects threaded deployments. Patch availability across Linux distributions remains uneven, so verify installed package versions rather than assuming coverage.
