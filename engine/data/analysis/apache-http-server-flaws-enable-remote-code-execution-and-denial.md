Apache HTTP Server has shipped three security releases in six weeks, and the current priority is 2.4.71, released 2026-11-11. That build fixes CVE-2026-119618, rated 9.8, described in the CVE record as heap corruption and remote code execution in assign_headers in mod_http2. The flaw affects HTTP/2-enabled deployments across a wide 2.4.x range, reported as 2.4.55 through 2.4.70, so exposure is limited to servers with mod_http2 active and the HTTP/2 protocol negotiated. Debian shipped a patch, and Red Hat's CVE page tracks the same issue; coverage from securityonline.info and thecybersecguru.com calls it the headline item of the release. Alongside it, 2.4.71 carries CVE-2026-106023 in mod_md, rated important, and CVE-2026-109163 in mod_vhost_alias, rated low.

The earlier 2.4.67 release, published 2026-05-04, closed CVE-2026-23918, a double free in the HTTP/2 handler of 2.4.66 rated 8.8 by CISA-ADP. The trigger is one TCP connection and two HTTP/2 frames, a HEADERS frame immediately followed by RST_STREAM on the same stream before the multiplexer registers it, which pushes the same pointer onto the cleanup array twice. Denial of service is guaranteed on any deployment. Researchers at Striga.ai and ISEC.pl confirmed a working remote code execution chain on Debian-derived systems, including Ubuntu, Kali and the official Apache Docker image, where APR uses the mmap allocator and the exploit uses the fixed-address scoreboard shared memory region to place fake structs and reach system(). A public PoC exists at striga-ai/CVE-2026-23918. MPM prefork is not affected, and the only interim mitigation is disabling HTTP/2.

The 2.4.69 release on 2026-10-01 fixed 20 CVEs, five moderate and 15 low. The moderate set includes CVE-2026-63292, a mod_vhost_alias stack buffer overflow that allows denial of service or code execution via an oversized Host header when VirtualDocumentRoot uses a hostname format specifier and LimitRequestFieldSize is raised above the default, credited to Hyojae Lee and Zhen Kong and fixed by r1938676. Also present: CVE-2026-57941, a mod_http2 use-after-free through shared session bbtmp re-entrancy in 2.4.17 through 2.4.68, and CVE-2026-42528, a mod_dav shared lock overflow in 2.4.67 and earlier. One item in this story's event set concerns Apache Struts fixes in 6.12.0 and 7.4.0, not httpd, and should not drive httpd patch decisions.

What to watch is HTTP/2 patch coverage rather than the older items. Confirm which fleet hosts run 2.4.55 through 2.4.70 with mod_http2 enabled, verify the build is at 2.4.71 or has the assign_headers backport from distribution vendors, and treat any host still on 2.4.66 with HTTP/2 exposed as actively exploitable given the published double-free PoC. Disable HTTP/2 on hosts that cannot be upgraded quickly.
