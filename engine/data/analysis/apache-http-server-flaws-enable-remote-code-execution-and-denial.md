Apache HTTP Server 2.4.69, released 2026-10-01, fixed 20 CVEs: five rated moderate and fifteen low. The moderate set includes CVE-2026-63292, a stack-based buffer overflow in mod_vhost_alias that lets a remote client trigger denial of service or potentially execute arbitrary code by sending a Host header over 8192 bytes when VirtualDocumentRoot uses a hostname format specifier and LimitRequestFieldSize is raised above the default. It was credited to Hyojae Lee and Zhen Kong, reported to the security team on 2026-06-17, fixed in r1938676, and shipped in 2.4.69. Also in that release: CVE-2026-57941, a mod_http2 use-after-free via shared session bbtmp re-entrancy affecting 2.4.17 through 2.4.68, and CVE-2026-42528, a mod_dav shared lock overflow affecting 2.4.67 and earlier. The mod_vhost_alias code fix actually landed in the 2.4.x branch on 2026-09-29, ahead of the advisory.

The more urgent item is the 2.4.71 release on 2026-11-11, which fixed CVE-2026-119618, described in the CVE record as heap corruption and remote code execution in assign_headers within mod_http2, rated critical, alongside CVE-2026-106023 (important) and CVE-2026-109163 (low). Only HTTP/2-enabled deployments are exposed. Debian shipped a patch, and Red Hat's advisory lists the flaw against affected Apache builds, with early watcher chatter tracking patch availability.

What to watch is HTTP/2 exposure and patch coverage. Servers fronting public traffic with mod_http2 on are the priority: confirm the build is at 2.4.71 or has the assign_headers fix, and check vendor backports since many distributions ship older 2.4.x branches. The critical mod_http2 RCE is the one to close first; the 2.4.69 moderate DoS and code-execution items (CVE-2026-63292, CVE-2026-57941, CVE-2026-42528) are secondary but still patch-worthy, especially where LimitRequestFieldSize has been raised.
