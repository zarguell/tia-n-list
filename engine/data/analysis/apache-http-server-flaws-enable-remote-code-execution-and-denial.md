Apache HTTP Server 2.4.71, released November 11, 2026, fixes CVE-2026-119618, a critical flaw in mod_http2 that lets an unauthenticated remote attacker corrupt heap memory and potentially execute code. The bug is improper synchronization in the assign_headers() function, rated CVSS 3.1 9.8 by Red Hat, and affects httpd 2.4.55 through 2.4.70 plus standalone mod_h2 2.0.8 through 2.0.42. Only servers with HTTP/2 enabled, through h2 or h2c in the Protocols directive, reach the vulnerable path. Anthropic's OSS Scanner reported the issue on October 26; Anthony Weems and Simon Scannell of Google Cloud Vulnerability Research reported it independently on November 3.

The same story covers earlier patch trains. Apache 2.4.69 shipped October 1, 2026 with 20 CVEs, including CVE-2026-63292, a mod_vhost_alias stack overflow reachable with a Host header over 8192 bytes when VirtualDocumentRoot uses a hostname format specifier and LimitRequestFieldSize is raised. An older entry, CVE-2026-23918, is a double free in mod_http2 triggered by an early reset frame against 2.4.66, with public exploit code and a confirmed remote code execution chain on Debian-derived systems using the mmap allocator and the fixed-address Apache scoreboard.

Early coverage said no active exploitation had been observed, but the Cyber Security Agency of Singapore warned on November 17 that CVE-2026-119618 was being exploited and that public proof-of-concept code existed. Wiz reported affected Apache versions in 64 percent of the cloud environments it measured, with 51 percent having publicly exposed instances, while noting that configuration was not accounted for. Watch for distribution-level patch gaps, exploit attempts against HTTP/2 endpoints, and the question of whether the published PoC matches the CSA warning.
