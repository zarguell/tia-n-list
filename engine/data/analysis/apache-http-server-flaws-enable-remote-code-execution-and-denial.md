Apache's 2.4.69 release on October 1 carried 20 HTTP Server advisories, five moderate and 15 low. The most concrete moderate issue is CVE-2026-63292, a mod_vhost_alias stack overflow that can crash a server or potentially execute code when a Host header exceeds 8192 bytes, VirtualDocumentRoot uses a hostname format specifier and LimitRequestFieldSize is raised above its default. That release also fixed CVE-2026-57941, a mod_http2 use-after-free affecting 2.4.17 through 2.4.68. An earlier May update, 2.4.67, addressed CVE-2026-23918, a double-free in HTTP/2 handling rated 8.8 with a public PoC that uses a HEADERS frame followed by RST_STREAM.

The current focus is CVE-2026-119618, a critical race in mod_http2's `assign_headers()` fixed in 2.4.71 on November 11. It affects httpd 2.4.55 through 2.4.70 and standalone mod_h2 2.0.8 through 2.0.42, needs no authentication, and can corrupt heap memory leading to code execution only when HTTP/2 is enabled. Red Hat scores it 9.8. Anthropic's OSS Scanner reported it on October 26 and Google Cloud Vulnerability Research reported it independently on November 3. Wiz estimated that 64% of cloud environments in its data ran affected versions and 51% had publicly exposed instances, while noting those figures do not account for configuration.

The story changed from precautionary patching to incident response on November 17, when Singapore's CSA reported active exploitation and a public PoC for CVE-2026-119618. No victim details or exploitation scale were given in the available reporting. Servers restricted to HTTP/1.1 are outside the known path, but many deployments enable `h2` or `h2c` through the Protocols directive without tracking it centrally.

Prioritize internet-facing 2.4.55 through 2.4.70 hosts that negotiate HTTP/2, and move them to 2.4.71 rather than relying on distribution status pages that were still marking packages vulnerable or pending. Watch for vendor patches for the standalone mod_h2 builds, for IoCs tied to the CSA alert, and for any confirmation that the older 2.4.67 double-free PoC is being used alongside the new flaw.
