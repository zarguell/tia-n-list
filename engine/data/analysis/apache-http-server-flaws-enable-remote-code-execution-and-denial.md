Apache released HTTP Server 2.4.71 on November 11, 2026 to fix three vulnerabilities in mod_http2, mod_md, and mod_vhost_alias, rated critical, important, and low respectively. The critical flaw, CVE-2026-119618, is a heap memory corruption race condition in mod_http2's assign_headers function that allows unauthenticated remote code execution against servers running versions 2.4.55 through 2.4.70 with HTTP/2 enabled. HTTP/1.1-only deployments are not exposed. The issue was reported by Anthropic's OSS Scanner on October 26 and independently by Google Cloud Vulnerability Research on November 3, and Red Hat assigned it a CVSS 3.1 score of 9.8. Standalone mod_h2 releases 2.0.8 through 2.0.42 are also affected, and Apache has not published a fixed standalone mod_h2 version.

Exposure is broad: Wiz reported that 64 percent of cloud environments in its data contained resources running affected Apache versions, with 51 percent having publicly exposed instances, though those figures do not account for server configuration. The same release window also saw four Apache Struts vulnerabilities fixed in Struts 7.4.0 and 6.12.0 covering remote code execution, denial of service, and cross-user data disclosure. No active exploitation of CVE-2026-119618 had been observed as of the advisory, but patch availability across Linux distributions remains uneven, with some vendors shipping 2.4.71 quickly and others still marking packages as vulnerable.

What to watch: whether CVE-2026-119618 sees in-the-wild exploitation now that a public fix exists, whether distribution maintainers backport 2.4.71 promptly, and whether Apache ships a fixed standalone mod_h2. Defenders should upgrade to 2.4.71 or disable HTTP/2 where it is not required, and monitor for heap corruption crashes or unexpected child process activity on internet-facing Apache instances.
