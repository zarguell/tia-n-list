Apache HTTP Server 2.4.71, released 11 November 2026, fixes CVE-2026-119618, a critical race condition in mod_http2's assign_headers() that lets an unauthenticated remote attacker corrupt heap memory and potentially execute code. Red Hat scored it CVSS 3.1 9.8. Versions 2.4.55 through 2.4.70 with HTTP/2 enabled are affected, as are standalone mod_h2 2.0.8 through 2.0.42; HTTP/1.1-only servers are not on the known attack path. Anthropic's OSS Scanner reported the flaw on 26 October and Google Cloud Vulnerability Research independently reported it on 3 November.

Exposure was already broad. Wiz found 64% of cloud environments in its data running affected Apache versions and 51% with publicly exposed instances, though server configuration limits actual exploitability. Censys counted about 166 million Apache HTTP Server web properties on the internet. Distribution patches have been uneven, and Apache has not published the request sequence that triggers the race; disabling HTTP/2 with Protocols h2 h2c is the interim mitigation short of upgrading.

The picture changed on 17 November, when Singapore's CSA warned that exploitation was underway and that a public proof of concept was available. Coverage on 13 November had said no active exploitation had been observed, so the agency warning is the first in-the-wild confirmation carried in this story. Administrators should treat 2.4.71 as urgent for HTTP/2-enabled internet-facing servers and check distribution packages rather than assuming the upstream release has landed.

Earlier Apache HTTP/2 bugs in the same story include CVE-2026-23918, a double-free in 2.4.66 with a confirmed remote code execution chain on Debian-derived systems through the fixed-address scoreboard, fixed in 2.4.67, and CVE-2026-63292, a mod_vhost_alias stack overflow in 2.4.68 and earlier triggered by a Host header over 8192 bytes, fixed in 2.4.69. Both reinforce the same patching lesson: version currency matters more than attention to a single CVE.
