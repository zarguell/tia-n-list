Quarkslab researcher Eric Le Guevel published a detailed bypass of Android hardware attestation, the mechanism that lets apps prove a device is running a verified, unmodified boot chain. The technique does not attack secure hardware or extract keys. Instead, it relays a genuine attestation from a clean phone to a rooted device via Frida instrumentation, so the backend sees a healthy device it never actually communicated with.

The core insight is that hardware attestation binds a key to a device's boot state, but it does not bind that key to the specific device or process presenting it. A clean phone produces a valid certificate chain with a verified boot state, and a Frida hook on the rooted phone intercepts the attestation request, forwards the challenge to the clean phone, and returns the genuine chain to the app. The backend validates the chain and sees a locked, verified device. Nothing is forged; the chain is real, the hardware told the truth, and the challenge matches.

The bypass works against any backend that does not check the attestationApplicationId field in the certificate, which identifies the package name and signing certificate of the app that generated the key. This field lives in the software-enforced authorization list, meaning it is trustworthy only when the hardware-enforced boot state is verified. A backend that already validates the boot state can safely trust the app identity and reject cross-app relays with a single comparison. The research includes a companion repository with a demo backend, client apps, and instrumentation code. Organizations relying on Android attestation for security gating should verify their backends check attestationApplicationId and consider requiring proof of possession for the attested key.
