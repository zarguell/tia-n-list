Node.js shipped security releases for all three supported lines on November 11, 2026, fixing a pair of HTTP/2 flaws in the runtime's built-in implementation. The fixed builds are 22.23.5, 24.22.3, and 26.13.1, and the Canadian Centre for Cyber Security tracked the release as advisory AV26-1156.

One flaw lets an unauthenticated client crash a server that uses HTTP/2 on the 24.x and 26.x lines. The second lets a server send a client pieces of its memory, including responses that were meant for other connections, which turns a protocol-level bug into a cross-connection data disclosure rather than just a crash. Both are reachable without authentication, so any HTTP/2 endpoint that exposes the affected runtime is in scope, including internal services behind a load balancer that terminates TLS upstream.

Operators should confirm which runtime versions production images carry, because the fixed builds only exist on the three named lines and older end-of-life releases will not receive them. The practical check is whether an application enables HTTP/2 on the Node server itself rather than relying on a reverse proxy, since the vulnerable code path is the built-in module. Watch for CVE assignments and for public proof-of-concept code, neither of which had appeared in the advisories covered here.
