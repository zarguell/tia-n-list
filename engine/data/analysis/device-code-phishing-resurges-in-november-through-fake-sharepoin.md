Malware.news published an attack analysis on November 19 of device-code phishing against Microsoft 365. It points to a November 17 Microsoft analysis that used a controlled GitHub Copilot CLI simulation to show how the device authorization flow can be abused by AI coding agents. In that flow an attacker sends a short code, the user approves it, and the attacker gains an authorized session for the targeted account without taking the user through a normal password prompt.

The same report says the investigators are seeing the authorization mechanism in payment-themed attacks that use fake SharePoint documents as the lure. A German follow-up from all-about-security.de repeats the warning for Copilot CLI and describes the short code being sent to the victim for approval. The events give no victim counts, campaigns or CVEs, so the value here is the convergence of the Microsoft simulation with observed payment-document lures.

What to watch is approval of device-code prompts that the user did not initiate, new OAuth grants and token replay from unfamiliar locations, especially for developer machines running coding agents. Account telemetry around Microsoft 365 sign-ins and consent is a better detector than looking for a malicious attachment, because the lure only has to get the victim to approve a code.
