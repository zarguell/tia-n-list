CVE-2026-6460 is a type-confusion flaw in PostgreSQL, rated CVSS 8.8, that lets a database user with object-creation rights execute arbitrary code on the server with the rights of the operating-system user running PostgreSQL. The bug is roughly 22 years old and was uncovered through research into how prepared statements interact with SQL injection defenses. The trigger involves ALTER ... SET DATA TYPE, where type confusion in the executor can be turned into code execution. PostgreSQL's security update 18.7 fixes CVE-2026-6460 alongside 51 other flaws, 31 of them also code-execution issues, across supported versions. Full protection requires rebuilding any installed C-language extensions, and PostgreSQL 14 reaches end of life with this release.

The story matters because the flaw combines a low privilege bar (any user who can create objects) with high impact (OS-level code execution), and the underlying research shows a defensive mechanism (prepared statements) can be repurposed to reach the vulnerable code path. The fix is not a simple package upgrade: operators must rebuild C extensions to close the gap, which is easy to miss in automated patching. No in-the-wild exploitation has been reported in the available coverage, but the flaw's age and the public research lower the barrier.

Administrators should upgrade to PostgreSQL 18.7 or the corresponding fixed release for their branch, rebuild all C-language extensions, and plan migration off PostgreSQL 14 before support ends. Database accounts should be reviewed for unnecessary object-creation rights, since that is the exploitation precondition.
