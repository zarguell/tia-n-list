PostgreSQL published a security release on November 12, 2026, covering versions 18.7, 17.12, 16.16, 15.20 and 14.25 and fixing 52 security flaws, 32 of them rated 8.8. The headline bug is CVE-2026-6460, a type-confusion issue in PostgreSQL composite types that Mehmet Ince traced to the expanded-object pointer mechanism introduced in May 2015. A user who can create objects prepares a query, changes a field type and executes it; the prepared value is not rewritten, so bytea output code treats stale bytes as an expanded-object header and pointer. That crashes the backend from a lowest-privileged login role and can be developed into code execution with the database server's operating-system rights.

The patch has an operational catch: full protection against CVE-2026-6460 also requires rebuilding installed C-language extensions, not just updating the server packages. Earlier private proof-of-concept sharing with managed PostgreSQL providers around mid-August 2026 means the flaw was understood before the November release. The same update wave also ends support for PostgreSQL 14, so version 14 users face both a patch and a migration decision.

Watch for database fleets reporting the new minor versions but still carrying extensions built against older headers, and for managed providers that applied the server fix without the extension rebuild. The gap between the 2015 code origin, the August 2026 private disclosure and the November public release makes this a long-lived exposure rather than a fresh coding mistake. Later reporting, including The Register's November 17 coverage, added no evidence of in-the-wild exploitation in the material reviewed here.
