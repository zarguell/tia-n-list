CVE-2026-6460 is a PostgreSQL type confusion with a CVSS score of 8.8 that Mehmet Ince traced to behavior dating back to 2004. His writeup describes preparing a query, altering a field's type with ALTER SET DATA TYPE, then executing the prepared statement. The prepared value is not rewritten for the new type, so bytea output logic reads stale bytes as an expanded-object header and pointer. A lowest-privileged login role can crash the backend this way, and the researcher developed the primitive toward code execution running with the server operating-system account. The expanded-object pointer mechanism itself arrived in May 2015.

Ince says reproducible proofs of concept were shared privately with managed PostgreSQL providers around mid-August 2026. PostgreSQL's November 12 security release fixes CVE-2026-6460 among 52 vulnerabilities, with 32 of them rated 8.8. The releases named in the reporting are 18.7, 17.12, 16.16, 15.20 and 14.25, plus 19 RC 2; PostgreSQL 14 reaches end of life with this cycle. The advisory also says full protection requires rebuilding C-language extensions installed on the server, because the fix changes interaction with them.

The practical risk is that a role with CREATE privileges can turn a legal SQL feature into server-side code execution, and patching the server binary alone can leave extensions mismatched. Watch for packager guidance on rebuilding specific extensions, confirmation of exploitation outside the private proof-of-concept set, and whether managed providers report incidents from the August notifications. Database administrators should inventory both server builds and compiled extensions together.
