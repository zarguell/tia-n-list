A type confusion flaw in PostgreSQL, tracked as CVE-2026-6460 with a CVSS score of 8.8, allows a database user who can create objects to execute code on the server with the privileges of the PostgreSQL server process. The flaw is roughly 22 years old and was discovered by researcher Mehmet Ince, who found that prepared statements intended to prevent SQL injection also enabled the issue. PostgreSQL 18.7 and related updates fix it along with 51 other security flaws, but full protection requires rebuilding any installed C-language extensions.

The main risk comes from untrusted or over-privileged database users who can create objects, since they can escalate to server-level code execution. PostgreSQL 14 also reaches end of life with this release cycle. Administrators should apply the updates and rebuild extensions, and watch for further details on the other patched flaws and whether public exploit code appears.
