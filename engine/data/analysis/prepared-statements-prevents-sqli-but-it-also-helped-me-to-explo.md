PostgreSQL 18.7 fixes 52 CVEs, and the one that stands out is CVE-2026-6460, a remote code execution flaw the reporting describes as 22 years old. The researcher's framing is the point: prepared statements, the standard defence against SQL injection, did not prevent exploitation of this flaw and in fact helped reach it. The same release closes 31 other code execution flaws.

PostgreSQL 14 reached end of life with this release, which matters more than the CVE count for anyone still running it. A 22-year-old RCE that survives the prepared-statement habit means ordinary query hardening does not cover it. The only reliable fix is the version upgrade, and any instance that cannot take 18.x needs a migration plan rather than a configuration change.

Watch for exploitation attempts against internet-exposed PostgreSQL instances and for a CISA KEV or high-EPSS listing, since a long-lived RCE with public detail is the kind of flaw that gets swept up quickly. Apply 18.7, inventory anything still on 14, and check whether connection pools or ORMs depend on prepared-statement behaviour before assuming the upgrade is transparent.
