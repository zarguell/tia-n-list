CVE-2026-6460 is a PostgreSQL type-confusion bug with a CVSS score of 8.8. Mehmet Ince's writeup describes preparing a query, altering a field's type with ALTER SET DATA TYPE, then executing the prepared statement. Prepared values are not rewritten when the type changes, so bytea output functions interpret stale bytes as an expanded-object header and pointer. The primitive crashes the backend as a lowest-privileged login role and can be developed into code execution with the rights of the operating-system account running PostgreSQL.

The bug is described as 22 years old, dating to 2004, although the expanded-object pointer mechanism involved was introduced on May 14, 2015. The researcher says reproducible proofs of concept were privately shared with managed PostgreSQL providers around mid-August 2026. PostgreSQL published fixes on November 12 in 18.7, 17.12, 16.16, 15.20 and 14.25, along with 19 RC 2, as part of a release fixing 52 security vulnerabilities.

The operational catch is that full protection also requires rebuilding installed C-language extensions, because the patch changes expectations for them. PostgreSQL 14 reaches end of life with this release, which raises the pressure to move to a supported branch. Watch for vendor packages that pair the server update with rebuilt extensions, and for any public exploit that turns the prepared-statement type confusion into reliable code execution.
