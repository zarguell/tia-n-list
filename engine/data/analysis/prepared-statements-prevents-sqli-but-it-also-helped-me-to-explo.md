PostgreSQL's November 2026 security release fixes 52 vulnerabilities, including CVE-2026-6460, a 22-year-old type confusion flaw (CVSS 8.8) that lets any database role with CREATE privilege execute code as the server operating system. The bug sits in ALTER ... SET DATA TYPE handling and was reportedly known to maintainers before public disclosure. Full protection also requires rebuilding any installed C-language extensions, because the patch changes server-side behavior that extensions depend on; packagers are urging administrators to update the server and extensions together.

Thirty-two of the 52 fixed flaws score 8.8, and PostgreSQL 14 reaches end of life with this release cycle, so the update is a broad maintenance event rather than a single-CVE patch. The researcher who published the CVE-2026-6460 exploit chain ("wtfse") showed that prepared statements, normally a defense against SQL injection, helped turn the type confusion primitive into remote code execution. CISA has not been mentioned in the collected coverage, but the flaw is authenticated (requires CREATE privilege) rather than unauthenticated.

Administrators should upgrade to PostgreSQL 18.7, 17.12, 16.16, 15.20, or 14.25 and rebuild C extensions, then audit roles with CREATE privilege. The operational caveat about extensions is the key action item: patching the server alone leaves residual risk. PostgreSQL 14 users must also plan a migration path because that branch is now end of life.
