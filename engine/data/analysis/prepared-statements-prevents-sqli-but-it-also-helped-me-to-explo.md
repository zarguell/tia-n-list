CVE-2026-6460 is a type-confusion flaw in PostgreSQL that lets a database user able to create objects execute code on the server with the rights of the operating-system account running Postgres. It carries a CVSS score of 8.8. The bug reportedly sat in the codebase for about two decades, and a researcher showed how prepared statements, normally a defense against SQL injection, became the primitive that turned it into remote code execution. PostgreSQL 18.7 and related updates fix it alongside 51 other security flaws, for 52 CVEs in total, and PostgreSQL 14 reaches end of life with this cycle. Full protection also requires rebuilding any C-language extensions installed on the server, since the flaw can persist in compiled extension code.

The risk is conditional on an attacker already holding a database role that can create objects, so it is not an unauthenticated remote entry point on its own. Even so, any shared or multi-tenant database where untrusted users can create objects is exposed, and the 31 additional code-execution flaws patched in the same release widen the blast radius. Operators should apply the update, rebuild extensions, and treat end-of-life PostgreSQL 14 instances as unpatched.
