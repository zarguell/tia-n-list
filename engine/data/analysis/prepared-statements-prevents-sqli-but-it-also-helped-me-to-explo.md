PostgreSQL's 12 November 2026 security release fixes 52 vulnerabilities, including CVE-2026-6460, a type confusion flaw rated CVSS 8.8 that dates back 22 years. Mehmet Ince's writeup describes preparing a query, altering a field type with ALTER SET DATA TYPE, then executing the prepared statement. Prepared values are not rewritten after the type change, so bytea output functions read stale bytes as an expanded-object header and pointer, crashing the backend as a low-privileged login role and providing a path to code execution as the server operating system. The expanded-object pointer mechanism was introduced on 14 May 2015, and Ince says reproducible proofs of concept were privately shared with managed PostgreSQL providers around mid-August 2026.

Full protection requires rebuilding installed C-language extensions because the patch changes server-side behavior they depend on. Thirty-two of the 52 fixes score 8.8, and PostgreSQL 14 reaches end of life with this cycle. Fixed builds are 18.7, 17.12, 16.16, 15.20 and 14.25, with 19 RC 2 also carrying the fixes. Coverage across ten sources describes the same release, and no report in the store claims observed exploitation, so treat this as a disclosed, proved code-execution path rather than an incident.

The operational item is to update server and extensions together, then audit which roles hold CREATE privilege, since the flaw is authenticated rather than unauthenticated. PostgreSQL 14 users also need a migration plan. Watch for reports of exploitation in hosted PostgreSQL services and for extension vendors publishing rebuilt packages.
