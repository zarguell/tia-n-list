Docker patched two critical vulnerabilities in Docker Sandboxes that allow malicious guests to escape isolated microVM workspaces and interact with the host system. CVE-2026-77179 (CVSS 9.4) affects the virtio-fs host server on macOS versions 0.28.0 through 0.41.x. The server improperly follows symlinks when reopening unlinked files, allowing a malicious guest to replace a parent directory with a symlink and escape the shared workspace to modify arbitrary host files as the VMM user.

CVE-2026-79994 (CVSS 8.7) affects the guest-to-host Unix domain socket relay across platforms in versions 0.37.0 through 0.41.x. The relay verifies that a socket path resides inside an authorized workspace but reconnects using the original path name after validation. A malicious guest can exploit this time-of-check-time-of-use race condition by replacing an intermediate directory with a symlink before the connection occurs, forcing the host to connect to an arbitrary AF_UNIX socket outside the shared space.

Docker Sandboxes are used to run AI coding agents inside isolated environments with dedicated Docker daemons and filesystems. A compromised microVM could lead to host file manipulation or access to restricted capabilities, potentially enabling widespread enterprise network infiltration. Both vulnerabilities are fixed in version 0.42.0. If immediate patching is not possible, administrators should run sandboxes in clone mode and avoid adding read-write host mounts to the sandbox configuration. No active in-the-wild exploitation or public proof-of-concept exists for either flaw.
