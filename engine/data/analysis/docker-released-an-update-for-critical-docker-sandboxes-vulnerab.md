Docker patched two critical vulnerabilities in Docker Sandboxes that allowed malicious guest environments to escape workspace isolation and access host-side resources. CVE-2026-77179, the more severe of the two, affects Docker Sandboxes versions 0.28.0 through 0.41.x on macOS and involves a time-of-check-to-time-of-use (TOCTOU) race in the macOS virtio-fs host server. A guest process can replace a directory with a symbolic link between the authorization check and the actual file operation, redirecting host-side I/O to arbitrary paths. CVE-2026-79994 follows the same TOCTOU pattern on other platforms.

Both flaws were fixed in Docker Sandboxes version 0.42.0, released on September 7. Docker Sandboxes are used to isolate development agents, automated CI/CD workflows, and untrusted code execution environments. A guest escape in this context means that code running inside the sandbox can read or write files on the host machine, potentially reaching secrets, credentials, and source code outside the intended workspace boundary.

The TOCTOU weakness is a classic filesystem race condition: the sandbox validates that a requested path belongs to an approved shared workspace, but a malicious process can swap the directory with a symlink before the host completes the operation. This is not a Docker engine vulnerability but a flaw in the newer Sandboxes isolation layer. Organizations using Docker Sandboxes should upgrade to 0.42.0 immediately and review whether their sandbox configurations grant more filesystem access than necessary.
