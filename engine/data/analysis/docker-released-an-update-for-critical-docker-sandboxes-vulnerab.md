Docker patched two serious vulnerabilities in Docker Sandboxes that allow a malicious guest environment to escape workspace isolation and access host-side resources. CVE-2026-77179, rated Critical, affects the macOS virtio-fs host server in Docker Sandboxes versions 0.28.0 through 0.41.x. The flaw is a time-of-check-to-time-of-use race condition in filesystem path validation: the sandbox validates that a requested pathname belongs to an approved shared workspace, but a malicious process inside the guest can swap a directory for a symbolic link before the host performs the actual file operation, redirecting host-side reads or writes to arbitrary locations.

CVE-2026-79994 is a related TOCTOU weakness in the same path validation logic, also exploitable by a guest process to break out of its intended workspace boundary. Both were fixed in Docker Sandboxes version 0.42.0, released September 7. Docker Sandboxes are designed to isolate development agents, automated CI/CD workflows, and untrusted workloads while giving selective access to a host workspace, so a sandbox escape directly undermines that isolation guarantee.

The practical risk is that any environment running an older Docker Sandboxes version on macOS could be compromised by a malicious container or workload that manipulates filesystem paths during the authorization window. This is especially relevant for teams using Docker Sandboxes to run untrusted code, third-party dependencies, or AI coding agents. Operators should update to 0.42.0 immediately and audit whether any untrusted workloads have run under vulnerable versions.
