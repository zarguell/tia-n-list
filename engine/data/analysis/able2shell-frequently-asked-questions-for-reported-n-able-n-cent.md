N-able's N-central remote monitoring and management platform was hit by "Able2Shell," a set of 33 alleged vulnerabilities published with proof-of-concept code by a researcher operating as Oracle-Security. The write-up describes an unauthenticated command-execution chain tested against N-central Appliance 2026.4.0.31, with the earliest README commit dated November 9, 2026 at 04:14 UTC. N-able described the release as a public disclosure by an independent security researcher and did not state whether it was notified in advance.

N-able took its hosted N-central environments offline and advised on-premises customers to shut down servers until further notice. On November 10 it released N-central 2026.4 Hotfix 2, fixing seven CVEs: CVE-2026-86206, CVE-2026-86207, CVE-2026-86218, CVE-2026-90436, CVE-2026-125878, CVE-2026-125879 and CVE-2026-125883. runZero published guidance on an unauthenticated XML external entity issue chained with session confusion to remote code execution as the nable user.

Security firms reported exploitation attempts against N-central honeypots tied to the published exploit code, including scanning activity. Beazley Security observed overnight attempts after the proof-of-concept surfaced, and Huntress advised administrators to review authentication activity from November 8 onward and assess every client network managed by an N-central server. As of November 10, no confirmed compromise of a customer server had been reported, and N-able stated it had not seen active exploitation of the vulnerabilities.
