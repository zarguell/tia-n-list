N-able N-central, the remote monitoring and management platform managed service providers use to administer customer endpoints, has been under public exploit since November 9, 2026, when researcher Sean Bales published roughly 33 issues under the Able2Shell name, forcing N-able to take hosted N-central offline worldwide and tell on-premises customers to keep their servers down. N-able shipped 2026.4 Hotfix 2 (build 2026.4.1.26) on November 10 for seven of those flaws, including CVE-2026-86218 (CVSS 10.0 pre-auth RCE, in CISA KEV since September 8), CVE-2026-86206, CVE-2026-86207, and CVE-2026-125878, CVE-2026-125879 and CVE-2026-125883. Shadowserver still counted 218 unpatched N-central instances on September 12, and N-able restored hosted service only on November 13 after further investigation.

Two days after Hotfix 2, Bales released two more chains. 4EverAble2Shell chains Apache Axis deserialization CVE-2026-90436 (CVSS 9.8) with an unspecified N-central flaw to run commands as root from an unauthenticated position, and it works against fully patched servers when the Legacy API is enabled and reachable. Huntback's telemetry, relayed by SecQuill on November 14, puts the exploitation timeline in hours: the exploit and a companion landed in a public repository at 03:58 UTC on November 12, a note at 07:48 recorded the legacy-interface requirement, the first probe against a decoy came at 08:30, and the first weaponized SOAP request combining privilege escalation with a Monero miner install arrived at 09:16, then repeated on different callback ports. Huntback counted 21 live MSP production servers compromised, 19 of which had already applied Hotfix 2. Agent2Shell targets managed Windows endpoints for SYSTEM-level execution and has no reported exploitation.

N-able's response has been to restrict features rather than ship a fix: Legacy API and Intune integration were disabled, and the vendor says it has identified additional indicators of compromise and is working with specific customers. For defenders the Legacy API is the control point, since every reported compromise ran through a single SOAP endpoint on an internet-exposed appliance, and Huntback's advice is to treat any infected N-central as a full breach of every downstream customer rather than a single-host cleanup. Watch for a build that actually fixes the chain, for N-able publishing the CVE identifiers it has so far withheld, and for whether disabling Legacy API measurably drops the victim count.
