A researcher using the Oracle-Security account, later identified as Sean Bales, published Able2Shell on November 9, 2026 with proof-of-concept code for 33 alleged N-able N-central vulnerabilities. N-able took hosted N-central environments offline across regions and told on-premises customers to shut down. One chain paired unauthenticated XML external entity access in service import with session confusion to run commands as the nable user. N-central 2026.4 Hotfix 2, build 2026.4.1.26, fixed seven CVEs on November 10, and hosted servers were upgraded. An earlier September case, CVE-2026-86218, was a CVSS 10 pre-auth RCE fixed in 2026.3 Hotfix 4, build 2026.3.1.14, added to CISA KEV on September 8, with scanning from 23.234.64.0/18 and repeated Shadowserver counts of exposed servers.

The disclosure did not stop with the hotfix. On November 12, Bales released 4EverAble2Shell and Agent2Shell, tested against 2026.4 HF2. The first chains Apache Axis CVE-2026-90436, a CVSS 9.8 unauthenticated deserialization and reflection flaw in end-of-life Axis 1.x, with an N-central weakness that requires the Legacy API to be enabled and exposed to the internet. Attackers used it to get root and install XMRig miners on at least 21 servers, 19 of them already on Hotfix 2. Agent2Shell targets managed Windows agents with SYSTEM-level execution. N-able restricted Legacy API and Intune integrations, then shipped Hotfix 3 with fixes for 17 flaws.

CVE-2026-90436 also applies beyond N-able. Rapid7 detected exploitation against Atlassian Confluence Data Center on November 13, where the Remote API configuration enables the vulnerable Axis path, and CISA added the CVE to KEV on November 18. Watch for internet-facing N-central instances with Legacy API enabled, Confluence Data Center builds below 9.2.28, and any hosts where miner deployment followed an Axis SOAP fault request. Absence of a vendor fix for Axis 1.x makes disabling the exposed API path the immediate control.
