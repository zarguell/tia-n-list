The LiteLLM supply chain breach from March 2026 keeps expanding. CloudSEK's reconstruction puts the blast radius at more than 2,500 organizations and roughly 434,000 CI/CD pipelines worldwide. New forensics from Snyk, Trend Micro, and Cycode trace the entry chain: threat actor TeamPCP first compromised the GitHub Actions pipeline of Trivy, the open source vulnerability scanner LiteLLM developers used in their own CI/CD workflow. That foothold gave the attackers legitimate access to the LiteLLM runner environment, from which they stole PyPI publishing tokens and shipped malicious LiteLLM package versions 1.82.7 and 1.82.8. The packages were live for roughly 40 minutes before quarantine.

The exposure window outlives the takedown. Stolen credentials, cloud keys, API tokens, and internal configuration data stay valid after the malicious packages are removed, and the downstream risk runs through source repositories, Kubernetes clusters, package registries, and AI services built on the dependency chain. The newest reporting describes a credential stealer propagating into enterprise CI/CD environments at scale, so organizations that built on LiteLLM or its dependents should rotate cloud credentials, audit pipeline secrets, and review Kubernetes access as if the dependency chain was compromised.

Watch for vendor guidance on credential rotation and for which downstream organizations disclose. The notable part is the pivot through Trivy: a popular developer tool became the entry into a high-value AI infrastructure target, and similar scanner dependencies are common enough that other upstream compromises with the same shape are plausible.
