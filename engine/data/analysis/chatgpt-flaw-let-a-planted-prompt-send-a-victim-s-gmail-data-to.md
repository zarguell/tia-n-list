Check Point Research disclosed a cross-account data exfiltration vulnerability in ChatGPT's code execution environment. The attack abuses JFrog Artifactory, an internal package service that ChatGPT containers use to install Python and npm dependencies. Containers under different accounts can read and write named metadata properties on cached files stored in this shared Artifactory instance. Check Point demonstrated that a planted instruction in a conversation could cause ChatGPT to read a victim's connected Gmail account and pass the data to a second ChatGPT account via these shared properties, all while the visible reply to the user showed nothing suspicious.

The attack chain requires the attacker to first get a malicious instruction into the conversation. Three delivery vectors were identified: a prompt the user pastes in, a shared conversation the user opens, or custom GPT builder instructions not shown to users. Once planted, a single user message triggers two parallel work streams in ChatGPT's Thinking mode: one answering the user and one executing the hidden task. Gmail's default "Important actions" permission allows read access without prompting, so the user gets no indication beyond a small "Talked to Gmail" label.

OpenAI confirmed the internal Artifactory service has been taken offline. There is no user-side patch. This is the second channel out of ChatGPT's code execution environment that Check Point has reported, following a DNS-based data exfiltration bug fixed in February 2026. The pattern suggests that shared internal services used across isolated containers are a recurring attack surface in AI platforms. Organizations using ChatGPT with connected apps should review which apps are enabled and consider restricting sensitive integrations until OpenAI provides stronger isolation guarantees.
