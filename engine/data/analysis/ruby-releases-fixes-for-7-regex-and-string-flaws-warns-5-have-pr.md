Ruby's maintainers disclosed seven memory-safety flaws in the language's regular expression engine and string case-conversion code. They said they are aware of proof-of-concept exploits showing that five of the flaws can be used to trigger remote code execution when crafted input reaches the affected code. The report does not list CVE identifiers, and the event text cuts off before the fixed version numbers, so those details should be taken from the upstream Ruby advisory rather than assumed here.

The affected components process text that applications commonly accept from users, logs and network inputs. A memory-safety bug in regex or case conversion can therefore be reachable without an authentication step in some applications, with code running in the Ruby process context. The maintainers' explicit PoC warning puts five of the seven flaws above a theoretical bug class.

Watch the upstream fixed version list and upgrade interpreters that handle untrusted strings, especially web applications and services that compile user-supplied patterns or normalize user input. Watch also for public exploit code, since the maintainers have already confirmed PoCs exist for five issues.
