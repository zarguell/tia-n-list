Ruby shipped fixes for seven memory-safety flaws in its regular expression engine and string case-conversion code. The maintainers said proof-of-concept code shows five of the issues can trigger remote code execution with crafted input. Fixed releases are 3.3.14, 3.4.13 and 4.0.10. Affected bands are 3.3.13 and earlier, 3.4.0 through 3.4.12, and 4.0.0 through 4.0.9. Ruby 3.2 and older are end of life and get no upstream fix.

The headline flaw is CVE-2026-132825, also tracked as GHSA-34m4-m9fh-gqp5 and named Ruby2Shell. It is a one-byte heap overflow in case conversion. In single-byte encodings such as ISO-8859-1 and Windows-1252, uppercasing the German sharp s produces two bytes where Ruby reserved one, corrupting adjacent heap memory. Veria Labs says unauthenticated attackers can reach the defect from Rails and classic-style Sinatra in default configurations. WatchTowr frames the exposure as any Ruby application that changes the case of external text in a single-byte encoding. The GitHub advisory rates the issue Critical, while the CVE record carries CVSS 3.1 7.4. Veria Labs plans to publish a PoC after major vendors patch.

The new CVE number matters for tracking. Some advisories still cite only the GHSA identifier, so inventories keyed on CVE-2026-132825 can miss earlier notices. Watch for downstream advisories from bundled Ruby runtimes and for backports in appliances and self-hosted products. The fixed releases are the direct remedy for installations on supported branches.
