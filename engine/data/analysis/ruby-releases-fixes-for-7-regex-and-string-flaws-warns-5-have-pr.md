Ruby shipped fixes for seven memory-safety flaws in its regular expression engine and string case-conversion code. The maintainers said proof-of-concept exploits show that five of the issues can trigger remote code execution with crafted input. CVE identifiers were requested but not assigned, so the flaws are tracked as GHSA-34m4-m9fh-gqp5, GHSA-7x2q-68qv-6p8x, GHSA-87fm-7w84-j2px, GHSA-wpqw-5qxg-m68r, GHSA-3p8q-wmhx-vm2w, GHSA-7whj-cfh7-xgm4 and GHSA-pvgc-g7gj-pv6h. The affected ranges are 3.3.13 and earlier, 3.4.0 through 3.4.12, and 4.0.0 through 4.0.9; the fixed releases are 3.3.14, 3.4.13 and 4.0.10. Ruby 3.2 and earlier are end of life.

GHSA-34m4-m9fh-gqp5 is a one-byte heap buffer overflow in string case conversion, reported by Stephan Lipp of Ada Logics and Anthropic. Other issues include an integer overflow in case conversion, a double free during regular expression compilation and an out-of-bounds read in case-insensitive matching. Veria Labs disclosed the case-conversion flaw as Ruby2Shell on November 19 and describes unauthenticated code execution in applications running affected Ruby versions on Rails or classic-style Sinatra. The advisory wording is about demonstrated proof of concept, not observed exploitation, and no exploitation telemetry appears in the event material.

The practical watch items are which of the five PoCs become public exploit code and whether Rails or Sinatra stacks provide a reachable path to the case-conversion call in real deployments. Inventory Ruby 3.3.13 and older, 3.4.0 through 3.4.12 and 4.0.0 through 4.0.9 first; the three fixed releases are the straightforward remediation.
