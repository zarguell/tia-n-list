Ruby's 18 November advisory covers seven memory-safety defects in the regexp engine and string case conversion, with proof-of-concept code showing remote code execution for five. The case-conversion flaw `GHSA-34m4-m9fh-gqp5` is a one-byte heap overflow when Ruby changes the case of crafted strings in single-byte encodings such as ISO-8859-1 and Windows-1252; `GHSA-7x2q-68qv-6p8x` is a double free during regexp compilation, and `GHSA-87fm-7w84-j2px` is a case-conversion integer overflow that produces a heap overflow. CVE identifiers were requested but unassigned in the advisory, so the GHSA identifiers are the stable tracking keys. Affected interpreters are 3.3.13 and earlier, 3.4.0 through 3.4.12 and 4.0.0 through 4.0.9; the fixes are 3.3.14, 3.4.13 and 4.0.10.

The case-conversion bug is the one that changes the risk calculus: most regexp issues require an application to compile attacker-controlled patterns, while case conversion is an ordinary operation on user input and Veria Labs reports that default Rails and classic-style Sinatra reach it without authentication. UTF-8 strings take a different code path, so exposure concentrates in services that accept legacy single-byte encoded input or run frameworks that normalize it. Veria Labs listed six self-hosted products whose latest releases still bundled affected Ruby on 19 November: GitLab 19.6.0, GitHub Enterprise Server 3.22.5, Mastodon 4.7.5, OpenProject 17.9.7, Discourse 2026.10.1 and Chatwoot 4.20.0. That turns a runtime patch into a bundled-version tracking problem, and Ruby 3.2 and earlier receive no fix. No in-the-wild exploitation or victim count has been reported; five PoCs are not five compromised fleets.

Upgrade to 4.0.10, 3.4.13 or 3.3.14, restart application servers and background workers, and rebuild container images and anything pinning Ruby in Dockerfiles or `.ruby-version`; Ruby lists no workaround. Inventory the running interpreter rather than the PATH binary, including bundled Ruby in the six products above, and keep unpatched self-hosted instances behind a VPN or IP allowlist until their vendors ship updates. Hunt in application and access logs for requests that drive `upcase`, `swapcase`, `downcase(:fold)` or `casecmp?` on ISO-8859-x or Windows-125x input, and check child-process telemetry from Ruby workers for unexpected shell or network utilities. The advisory carries no IoC names, so anchor the hunt on version and input telemetry rather than invented indicators.

Watch for Veria Labs publishing its promised proof of concept, which would move this from maintainer-asserted reachability to easily tested exploitation, and for the first credible in-the-wild telemetry or vendor-fixed builds for the bundled products. CVE assignment would improve tracking, but only exploitation evidence would raise the defensive priority.
