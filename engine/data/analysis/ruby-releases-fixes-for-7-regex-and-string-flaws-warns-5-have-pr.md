Ruby's maintainers disclosed seven memory-safety flaws in the regular expression engine and string case-conversion code. They said they are aware of proof-of-concept exploits showing that five of the flaws can be used to trigger remote code execution when crafted input reaches the affected code. The report does not list CVE identifiers, and the event text cuts off before the fixed version numbers, so those details have to come from the upstream Ruby advisory rather than be assumed here.

GBHackers reported on 19 November that Veria Labs named the string case-conversion issue Ruby2Shell and published GitHub advisory GHSA-34m4-m9fh-gqp5, with CVE assignment still pending. The claim is unauthenticated remote code execution in applications running affected Ruby versions on Rails and classic-style Sinatra. Technical detail beyond the advisory name is thin in the event text, and no exploit code, victim count or observed attack has been reported, so the maintainers' PoC statement remains the strongest evidence of exploitability.

Regex and case conversion both process strings that applications commonly accept from users, logs and network inputs. A memory-safety bug there can be reachable without an authentication step in some applications, with code running in the Ruby process context. Watch the upstream fixed version list and upgrade interpreters handling untrusted strings, especially web services that compile user-supplied patterns or normalize user input. Also watch whether the GHSA is assigned a CVE and whether public exploit code appears for the five issues with confirmed PoCs.
