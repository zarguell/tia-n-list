Ruby shipped fixes for seven memory-safety flaws in its regular expression engine and string case-conversion code. The maintainers said proof-of-concept exploits show that five of the issues can trigger remote code execution with crafted input. The headline flaw is CVE-2026-132825, also tracked as GHSA-34m4-m9fh-gqp5 and named Ruby2Shell, with a CVSS score of 7.4. Veria Labs describes a one-byte heap overflow when upcasing strings in single-byte encodings: converting the German sharp s produces two bytes where Ruby reserved one, so uppercase handling of external text can corrupt adjacent heap memory. WatchTowr frames the exposure as any Ruby application that changes the case of external text in single-byte encodings such as ISO-8859-1 or Windows-1252.

Veria Labs says default configurations make the flaw reachable without authentication through Rails and classic-style Sinatra, and that GitHub Enterprise Server is affected; the report also names Chatwoot, GitLab and Mastodon among downstream projects. A PoC is planned after major vendors ship patches, so the current claim is demonstrated exploitability rather than observed attacks. The fixed releases are Ruby 3.3.14, 3.4.13 and 4.0.10. The affected ranges are 3.3.13 and earlier, 3.4.0 through 3.4.12, and 4.0.0 through 4.0.9.

The November 20 Veria Labs post ties the previously unnumbered Ruby2Shell issue to CVE-2026-132825, which changes tracking for downstream advisories that still cite only the GHSA identifier. Watch for the promised PoC, for bundled Ruby runtimes in appliances and applications, and for patch backports in the named downstream projects. Inventory the three affected release bands first; the fixed versions are the direct remedy.
