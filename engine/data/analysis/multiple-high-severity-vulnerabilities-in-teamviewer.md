TeamViewer disclosed two coordinated batches of high-severity flaws in Full Client and Host across Windows, Linux, and macOS. The first batch, bulletin TV-2026-1010 issued September 29, 2026, fixes five CVEs: CVE-2026-92370 (CVSS 8.8, remote session access-control bypass that can lead to remote code execution), CVE-2026-19743 (path traversal), CVE-2026-92368 (heap-based buffer overflow), CVE-2026-92369 (TOCTOU race), and CVE-2026-92371 (improper path validation allowing local code execution or privilege escalation to SYSTEM or root). The second batch, bulletin TV-2026-1011 issued October 27, 2026, adds CVE-2026-92372, CVE-2026-92374, and CVE-2026-111585 (CVSS 8.8), an integer overflow in the remote-control screen processing component affecting Windows, macOS, Linux, and Android clients. CVE-2026-111585 lets a malicious host force the viewer off the hardware video decode path and announce oversized screen dimensions such as 32768 by 32768 pixels at 32 bits per pixel, overflowing 32 bits and writing rows out of bounds.

The second batch inverts the usual trust direction: the machine being supported attacks the technician's PC, not the other way around. Any helpdesk or MSP technician who connects to an attacker-controlled or compromised host can have their viewer crashed or, depending on platform, arbitrary code executed with their privileges, and the precondition is only that the technician opens a remote-control session. With CVE-2026-92370 the exposure is broader but more conventional: an attacker who can establish or manipulate a session bypasses the permissions the victim configured and can reach remote code execution on the target endpoint. Between the two, the second is the one to fear more in practice because it requires no vulnerability in the target at all, only a lure that gets a technician to connect, and Remedio notified TeamViewer of that flaw on August 14, 2026 with confirmation on October 22.

Patch to TeamViewer 15.82 to close the first batch and to 15.83 for the second; the 15.83 update also covers CVE-2026-92372 and CVE-2026-92374. For the first batch, legacy branches have fixed builds at 15.64.8, 14.7.48855, and 13.2.x releases. Until patched, restrict remote-control sessions to trusted hosts, disable inbound remote-control from untrusted networks, and avoid connecting to hosts you do not control. For CVE-2026-111585 specifically, watch for sessions where the remote host refuses video codec negotiation and for viewer crashes during screen decompression; the decode surface is only exercised when no hardware video decoder is available, so forcing hardware decoding where possible reduces exposure.

The assessment changes if proof-of-concept code appears for CVE-2026-92370 or CVE-2026-111585, or if telemetry shows exploitation in the wild; both bulletins state TeamViewer is not aware of active exploitation at publication. Also watch whether Android Remote Control App users are patched, since CVE-2026-111585 affects that client and mobile endpoints are often missed in patch cycles.
