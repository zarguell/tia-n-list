Microsoft documented attacks against three AI infrastructure platforms: LiteLLM (an AI gateway), RAGFlow (retrieval-augmented generation), and Kestra (workflow orchestration). These platforms sit between applications and LLMs, holding sensitive model credentials, workflow permissions, database connections, and container access. A compromise at this layer grants access to cloud credentials, provider API keys, internal services, and compute resources. Additional reporting from GBHackers confirms the pattern extends beyond Microsoft's initial findings.

In the LiteLLM case, attackers likely exploited an exposed gateway surface linked to CVE-2026-42271 (command execution via MCP stdio test endpoints) and CVE-2026-48710 (Starlette host-header validation bypass). After gaining execution, the operators harvested environment variables from /proc/1/environ, which can contain model-provider API keys, LiteLLM master keys, database URLs, passwords, and access tokens. They also accessed the LiteLLM PostgreSQL database to collect model configuration and virtual-key records.

The targeting of AI middleware represents a shift from attacking models directly to attacking the plumbing that connects them to enterprise systems. AI gateways centralize OpenAI, Azure, Anthropic, and Gemini API keys, making them high-value targets for credential theft and cryptojacking. Organizations deploying AI infrastructure should treat these platforms with the same security rigor as other critical enterprise services: network segmentation, credential rotation, and monitoring for anomalous API key usage.
