CVE-2026-119077 is a CVSS 3.1 9.8 object injection flaw (CWE-502, AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H) in elextensions' ELEX WordPress HelpDesk & Customer Ticketing System through 3.3.9. The Wordfence record names the attacker-controlled ticket_label field inside the url-encoded form parameter as the entry to deserialization without a class allowlist or server-side authentication; a public GET on a page carrying the [wsdesk_support] shortcode leaks wsdesk_nonce and one unauthenticated POST to admin-ajax.php with action eh_crm_new_ticket_post completes code execution. CISA's SSVC entry dated 2026-11-13 records exploitation as none, automatable yes and technical impact total, so there is no confirmed in-the-wild use here. Patchstack assigned the same affected range and the same 9.8 score a second identifier, CVE-2026-125855, crediting a different finder.

This story outranks the rest of the queue because a public proof of concept from 2026-11-13 ships a threaded scanner, FOFA fingerprints and a validated bypass of ModSecurity CRS 4.30.0, which narrows the gap between a CVE record and routine scanning even while exploitation telemetry stays empty. The event list does not capture the exploitability precondition: that proof of concept reports that 3.3.9's custom-field allowlist strips the default slugs, so a clean install is not reachable through ticket_label, while 3.3.8 has no such allowlist, and custom slugs can be enumerated unauthenticated via action=eh_crm_new_ticket_form. Exposure is therefore a subset of installs, but any site with a public [wsdesk_support] page and one custom field has an unauthenticated path to a file write under wp-content/uploads/ and code execution as the web server user. Two CNAs tracking the same bug under separate CVE ids makes ID-only detection brittle.

Move to 3.4.0, the release the vendor changelog dates 12-Nov-2026 and Patchstack marks unaffected; it adds eh_crm_has_object_or_serialized_object() and eh_crm_safe_unserialize() ahead of 26 deserialization sinks. If patching is delayed, remove [wsdesk_support] from public pages, restrict anonymous calls to admin-ajax.php with action eh_crm_new_ticket_post, and inventory custom-field slugs. Hunt for POSTs to /wp-admin/admin-ajax.php with that action carrying serialized form data, for newly written files in wp-content/uploads/ with cookie-jar JSON around a PHP body, and for GETs to action=eh_crm_new_ticket_form used for slug discovery; the proof of concept's one-request build oracle returns `{"status":"error","message":"Invalid form data."}` on 3.4.0 and a success response on vulnerable builds.

The assessment changes if telemetry shows serialized POSTs to eh_crm_new_ticket_post at scale or CISA moves SSVC exploitation off none, or if the 3.4.0 guard is shown to be bypassable. It also changes if CVE-2026-125855 is merged into CVE-2026-119077 or stays live, since feeds keyed only to the Wordfence id will miss Patchstack-sourced detections.
