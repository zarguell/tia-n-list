Hex, the package manager for Elixir and Erlang, disclosed an intrusion against its hex.pm web servers on November 23. An attacker used a vulnerability to execute commands, sending 69 malicious requests between 18:16 and 18:29 UTC across six servers. Hex said the defect was fixed within 20 minutes, all servers were replaced with patched versions at 18:30, and a firewall rule blocked the traffic by 18:33. The company found no evidence of unauthorized package modifications, database changes or continued attacker access.

Hex cannot rule out access to email addresses, password hashes, API-key hashes, sessions, second-factor authentication secrets and audit logs. Reads of private packages appeared to originate from Hex servers, which would also be the expected pattern for reads made through a compromised server. Database and private-documentation reads are not logged, leaving a visibility gap around what data the attacker could have retrieved.

Because the attacker's commands could read server credentials, Hex replaced storage, CDN, email and database credentials as well as the keys used to sign sessions and access tokens, logging all hex.pm users out. The immediate containment and credential rotation reduce ongoing exposure, but users should watch for any revised Hex assessment of data access or package integrity.
