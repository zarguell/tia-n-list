ShinyHunters breached Clop's Tor data leak site on the evening of 18 September 2026 by exploiting an unauthenticated path traversal flaw in a Grav CMS installation that Clop itself later confirmed was not fully updated. The intrusion started as a single uploaded text file and escalated within hours to a full defacement carrying ShinyHunters' Umbreon artwork, and the group claims it walked away with source code, Grav CMS plugins, the entire /var/log directory, and the private keys of Clop's onion service. BleepingComputer confirmed the defacement but not the theft claims, and Clop responded on 25 September by moving to a new onion address while disputing any relationship with ShinyHunters. No CVE has been publicly confirmed for this specific exploit, but the mechanism matches CVE-2024-27921, the Grav file upload path traversal Riyush Ghimire disclosed on 9 October 2024, fixed in Grav 1.7.45 and chainable with CVE-2024-34082 (patched in 1.7.46) into unauthenticated admin and code execution.

The defacement is the least important part of this story. ShinyHunters' ransom notes, updated daily from 19 through 21 September, demand an eight-figure sum tied to Clop's Oracle E-Business Suite campaign built on CVE-2025-61882 and threaten to publish which companies paid Clop, how much, and to which Bitcoin address. That converts every Clop payer into a prospective ShinyHunters target: organizations that closed a ransomware incident on the assumption of deletion now face a second extortionist holding the receipts. Valid onion private keys would let ShinyHunters serve a convincing impostor at Clop's original .onion address, poisoning the negotiation channel for anyone still dealing with Clop, and /var/log theft exposes connection IPs that can unmask operators and visitors alike. There is also the discipline argument: a group whose entire revenue model is mass exploitation of unpatched MOVEit, GoAnywhere and Oracle EBS servers ran its own extortion infrastructure on a CMS with a two-year-old public patch, against a target class TantoSec measured at roughly 36,000 exposed Grav admin panels. Patch debt is not confined to the victims.

Defenders running internet-facing Grav should patch to 1.7.46 or later, since 1.7.45 closes CVE-2024-27921 and 1.7.46 closes CVE-2024-34082, enforce the Site Host directive in the Login plugin to blunt reset-link poisoning, and restrict exposure of /admin. The hunt is concrete: in web server access logs, look for POST requests to Grav upload endpoints where the filename parameter carries traversal sequences such as ../ or encoded variants, or a slash inside the filename used to shift the write path; on disk, flag any file beginning with ".." in upload directories and unexpected modifications to composer.json or new zip files in the backup directory, since the public exploit chain overwrites exactly those. Any organization that previously paid Clop should treat its negotiation records as compromised and brief the incident response team accordingly.

Two developments would change this assessment. Publication of the alleged Clop payer ledger, with company names, amounts and Bitcoin addresses, would create direct new victims and deserves same-day escalation. And confirmation of which Grav code path served as the entry point matters: if it was CVE-2024-27921 run against a stale 1.7.44, the lesson is patch hygiene; if researchers demonstrate a bypass of the 1.7.45 fix, every patched Grav administrator needs to move again the same day, and a functioning impostor at the retired onion address would confirm the key theft as fact rather than claim.
