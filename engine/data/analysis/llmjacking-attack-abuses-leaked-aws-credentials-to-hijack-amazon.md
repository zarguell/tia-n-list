FortiGuard Labs documented a cloud intrusion technique called LLMjacking, where attackers abuse leaked AWS credentials to access and run inference on Amazon Bedrock foundation models at the victim's expense. The attack started with a long-lived AWS IAM access key that had AdministratorAccess permissions. With that key the attacker created a new IAM user, then used it to subscribe to premium foundation models through AWS Marketplace by submitting CreateAgreementRequest and AcceptAgreementRequest calls. Once the agreements were active, the attacker invoked the models for inference, racking up charges on the victim's account.

This matters because it is a shift in cloud credential abuse economics. Instead of cryptomining (which requires compute) or data exfiltration (which requires a buyer), LLMjacking monetizes the target's existing relationship with the cloud provider. The attacker gets access to expensive AI services without provisioning their own infrastructure. Organizations with long-lived IAM keys and broad permissions are exposed, particularly those with Bedrock or similar managed AI services enabled.

What to watch: the prevalence of long-lived IAM keys in enterprise environments. AWS has pushed toward short-lived credentials and IAM Roles for years, but many orgs still rely on static access keys for integrations and automation. Any key with AdministratorAccess that is committed to a repo, pasted in a config file, or stored in an unprotected vault is a vector. Monitor AWS Marketplace agreement activity and unusual Bedrock API calls as potential indicators. FortiGuard Labs did not report victim counts or whether this technique is being used at scale, but the low barrier to execution suggests it will spread.
