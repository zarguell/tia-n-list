Fortinet's October 2026 advisory cycle fixed multiple flaws across FortiSandbox and FortiSIEM. CVE-2026-107656 is a CWE-288 authentication bypass using an alternate path or channel in the FortiSandbox GUI, scored CVSS 9.6, allowing a remote unauthenticated attacker to bypass authentication through crafted HTTP requests. It affects FortiSandbox 5.0.0 through 5.0.6, fixed in 5.0.7, and 4.4.0 through 4.4.9, fixed in 4.4.10; version 5.2 is not affected, while FortiSandbox PaaS 4.4 has all versions affected with guidance to migrate to a fixed release. CVE-2026-106173 is a CWE-22 path traversal in FortiSIEM allowing an unauthenticated attacker to execute unauthorized code or commands through specially crafted packets, scored CVSS 9.4, affecting only FortiSIEM 7.5.0 with fix 7.5.1 or above and a workaround of restricting access on TCP port 27918; FortiSIEM Cloud is not affected. The Canadian Centre for Cyber Security's rollup advisory AV26-1037 dated October 13, 2026 extended the scope to FortiAnalyzer before 7.6.5 and 7.4.8, FortiManager before 7.6.5 and 7.4.7, FortiMail before 7.6.4, 7.4.6, and 7.2.9, FortiSIEM before 7.5.1, and FortiSandbox before 4.4.10 and 5.0.7, covering flaw classes such as arbitrary file read and write via SQL injection, a file write in grpc phQueryMaster, SQL command injection in webmail, and improper access control and session management in a web management interface.

Both headline CVEs are marked as not known exploited, but their unauthenticated, high-severity nature and the breadth of affected products make prompt patching important, especially for internet-facing management interfaces. The FortiSandbox bypass at 9.6 and the FortiSIEM path traversal at 9.4 are the priorities, followed by the FortiAnalyzer, FortiManager, and FortiMail fixes in the Canadian rollup.

Administrators should upgrade affected products to the fixed versions, apply the port 27918 restriction where FortiSIEM cannot be patched immediately, and migrate PaaS 4.4 instances. Because FortiSandbox PaaS 4.4 is entirely affected, those deployments need the most urgent attention. Verification after patching should confirm management interfaces are no longer reachable from untrusted networks.
