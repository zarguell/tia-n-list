CERT Polska coordinated disclosure of four vulnerabilities in WidzialniCMS, a Polish-language content management system published by Fundacja Widzialni, tracked as CVE-2026-110468, CVE-2026-110469, CVE-2026-112204 and CVE-2026-112205. All versions before 2.5 are affected. CVE-2026-110468 and CVE-2026-110469 are unrestricted file upload flaws in `/panel/controllers/save_photo.php` and `/panel/upload.php` respectively: a client-controlled permission check parameter and insufficient validation of the `currentpath` or `uploadPath` parameter let an unauthenticated attacker upload arbitrary files to any location on the server, leading to remote code execution. CVE-2026-112204 is a reflected cross-site scripting issue in `/index.php` that can be triggered by a crafted URL to execute JavaScript in a victim's browser, including session cookie theft. CVE-2026-112205 is a brute-force protection bypass in the login functionality: the cookie-based lockout can be defeated by omitting the `login_count` and `login_timeout` cookies, allowing unlimited login attempts.

The two upload CVEs are the real risk here, because they convert an unauthenticated HTTP request into server-side code execution on any WidzialniCMS instance still running a pre-2.5 release, which is the entire installed base until administrators patch. The cross-site scripting and lockout bypass are lower-impact on their own, but they compose: an XSS payload can be used to steal a session, and the lockout bypass removes the only rate limit protecting the login form, which matters for a small CMS that rarely sits behind a WAF. The exposure is bounded by the product's niche, Polish-language, single-vendor footprint, but there is no telemetry suggesting the bugs are unexploitable, and the upload endpoints are unauthenticated by design. The CERT Polska advisory is the first public record of these issues, published 2026-11-09 at 10:55 UTC, ahead of the malware.news and radar.offseq.com reposts that surfaced them later the same day.

Upgrade to WidzialniCMS 2.5, which fixes all four issues; no hotfix or partial mitigation is documented. Until the upgrade is applied, restrict or disable the upload endpoints `/panel/controllers/save_photo.php` and `/panel/upload.php` at the web server or reverse proxy, and enforce authentication in front of `/panel/`. For CVE-2026-112204, treat any request to `/index.php` carrying unexpected query parameters as suspicious and review referrer and URL logs. For CVE-2026-112205, alert on login requests that lack the `login_count` and `login_timeout` cookies, or on sustained login attempt volumes from a single source. Hunt the filesystem for recently created PHP or script files under the upload directory and in web roots, and review web server access logs for POST requests to the two upload endpoints from unknown IPs.

Watch for public proof-of-concept code or scanning traffic against `/panel/upload.php` and `/panel/controllers/save_photo.php`, which would move these from advisory-level to actively exploited, and for a vendor statement on backported fixes for sites that cannot move to 2.5 immediately. A confirmed in-the-wild upload, or a CISA KEV listing, would change the assessment from patch-when-possible to emergency patch.
