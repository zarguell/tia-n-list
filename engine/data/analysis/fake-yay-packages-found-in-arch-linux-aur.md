A threat actor uploaded malicious packages to the Arch User Repository (AUR) that impersonated the popular helper tools yay and paru. The malicious uploads were detected on October 13 by a user named "marchos1as" using typosquatted package names. Community members confirmed on the Arch Linux mailing list that the packages combined legitimate upstream code with a malicious installation script that executed a remote shell script with root privileges. This is the latest in a series of AUR campaigns: an earlier attack in June distributed credential-stealing malware with rootkit capabilities through 400 packages, and a July campaign led Arch to temporarily disable package adoption. Because AUR is community-maintained and widely used by Arch Linux and derivative distributions, malicious packages reach users who rely on the repository for third-party and proprietary software not available through official channels. There are no CVEs assigned to this campaign; the risk is supply-chain compromise through malicious install scripts rather than a vulnerability in existing software.

This matters because AUR users often run install scripts with root privileges as part of the build process, so a malicious package grants immediate system-level access. The campaign targets well-known tools (yay and paru) to maximize installation volume, and the attacker reused the legitimate upstream source URL to make the packages appear authentic. The Arch community responded quickly, identifying the malicious uploads within minutes of the mailing list alert. Users should verify any recently installed AUR helpers and review package sources before running build scripts. The repository's recent history of malicious campaigns (June, July, October) indicates sustained adversary interest in this supply chain.

What to watch: whether Arch takes further steps to restrict package adoption or introduces additional verification for new uploaders; whether any of the malicious packages were installed by users and whether post-install indicators of the remote shell script have been observed; and whether the attacker uploads additional packages under different usernames or targets other popular AUR helpers.
