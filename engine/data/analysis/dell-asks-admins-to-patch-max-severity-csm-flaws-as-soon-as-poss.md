Dell patched two CVSS 10.0 flaws in Container Storage Modules Authorization v2.4.0, the security module that brokers authentication between Kubernetes and Dell storage arrays. CSM extends the standard CSI drivers for PowerStore, PowerScale, PowerFlex, PowerMax, and Unity XT, so it sits directly on the path from container workloads to enterprise storage. CVE-2026-63688 lets an unauthenticated remote attacker retrieve storage backend administrator credentials for all registered storage arrays and bypass authorization into full administrative control. CVE-2026-63692, in the authorization proxy and tenant service, grants admin privileges by bypassing authentication controls. Dell's advisory calls out the worst case in its own words: complete administrative control over the authorization service and manipulation of storage resources across all tenants.

The same advisory day Dell also fixed four additional critical-severity CSM issues that remote attackers can exploit without privileges, so the module took six critical fixes in one pass. The reference is Dell KB 000515771, with BleepingComputer and others covering the release. Nothing in the captured events reports observed exploitation; the urgency here is blast radius and exposure, not an active campaign.

The reason this rates attention beyond a patch notice is structural: whoever controls CSM Authorization holds live credentials for every array registered to the cluster, which maps directly to mass data destruction or encryption across tenants. Organizations running CSM should upgrade immediately and then rotate storage backend credentials, since a CVSS 10.0 credential-disclosure flaw means any pre-patch attacker could have already read them. Watch for Dell follow-up advisories on the four additional issues and for any exploitation reporting.
