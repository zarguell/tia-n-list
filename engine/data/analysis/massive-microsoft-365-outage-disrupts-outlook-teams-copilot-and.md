A global Microsoft 365 outage on November 12-13, 2026 disrupted Outlook, Teams, Microsoft 365, Copilot, Defender for Office 365, Exchange Online, Intune, and the Microsoft 365 Apps Admin Center, with Downdetector drawing roughly 50,000 reports and the incident running past 12 hours. Microsoft tracked it under incidents EX1550543 and MO1550821, first scoping mailbox access problems to the Americas before confirming any region could be affected. The company said the elevated load was not driven by increased traffic but by a number of servers becoming unexpectedly unavailable and straining the remaining infrastructure, and that it had found no recent change correlated with the start of the impact.

Microsoft's investigation pointed to failed automated service health checks originating from a specific component responsible for processing server health; a core process on some servers became overwhelmed, causing those servers to fail health checks and go offline. Engineers tested a configuration change and worked an alternate health check method to return affected servers to service, while Microsoft's status updates acknowledged that actions taken so far had not provided the anticipated relief. Microsoft excluded a cyberattack as the cause, attributing the failure to infrastructure health-check processing rather than malicious traffic.

The practical takeaway is that the blast radius was broad and long-lived: hosted productivity, security tooling, and administration consoles all went down together, and recovery stretched into a second day. Organizations dependent on Microsoft 365 for both communication and security operations should treat this as a single-vendor resilience lesson and plan for degraded-mode operation when Exchange, Teams, Defender, and Intune are unavailable at the same time. Until Microsoft publishes a final post-incident review, the health-check component remains the stated root cause.
