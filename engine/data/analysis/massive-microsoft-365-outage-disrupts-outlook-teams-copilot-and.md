Microsoft 365 suffered a broad outage that began on 12 November 2026 and continued into 13 November while Microsoft worked to restore affected infrastructure. The company confirmed that users in any region could hit connectivity problems, expanding an investigation that initially focused on Exchange Online mailbox access in the Americas. Reported impact spans Outlook, SharePoint, Teams, Copilot and Defender XDR, which makes this an identity and endpoint-visibility problem as much as a mail problem: when Defender XDR and the security telemetry pipeline are degraded, the detection and response tooling that customers rely on goes quiet at the same time as their collaboration stack.

Microsoft has not published a root cause, so the technical specifics of the failure are still unknown. The Financial Times reported Microsoft racing to restore services, quoting Charles Lamanna, executive vice president for Copilot, Agents and Platforms, which indicates executive-level ownership of the recovery rather than a routine service incident. Status page and admin center updates are the authoritative feed here, not the aggregate outage trackers that were already recirculating the story.

The security angle worth tracking is the shadow IT response. When Outlook goes down, users route around it with personal webmail, unsanctioned VPNs and browser extensions, and that workaround traffic leaves the managed tenant and its logging. Organizations should expect a spike in personal-account file sharing during the window and should check egress and DLP telemetry for data moving to consumer endpoints. For resilience planning the case is a reminder that a single vendor's control plane can remove mail, meetings and endpoint telemetry simultaneously, which breaks the assumption that a cloud outage is a productivity problem rather than a monitoring gap.
