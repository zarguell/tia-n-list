Microsoft attributes the ConnectWise Cloud Backup supply-chain compromise to Storm-0940, a China-state aligned actor active since 2021, which used the agentic AI penetration testing framework ARTEX to automate attacks against hundreds of organizations across aerospace and defense, energy, financial services, government, legal, manufacturing, semiconductors, and technology. The immediate prelude was a four-day password-spraying campaign ending October 14, 2026 that hit 327 Microsoft 365 and Exchange Online accounts across eight organizations with more than 151,000 failed logon attempts peaking at 2,900 failures per minute, after which Storm-0940 pivoted to ConnectWise Cloud Backup customers' Microsoft 365 tenants on October 15. Microsoft notes several ARTEX-driven intrusions reached privileged cloud access in under three hours, and that the actor abused already-granted application identities rather than needing fresh user credentials.

The exposure is not a single breached vendor but a trust chain: ConnectWise Cloud Backup, formerly SkyKick Backup, held application identities inside customer tenants, so one compromised vendor credential became a path into 173 Microsoft 365 tenants according to ConnectWise's own disclosure. Any MSP or partner that granted those application permissions inherits the blast radius, and the dwell time advantage is structural because agents run continuously and test multiple breach paths at once. This story matters more than the day's other items because it pairs a concrete, already-exploited supply-chain path with a measured speed record, under three hours to privileged access, rather than a theoretical AI risk.

Defenders should keep affected ConnectWise Cloud Backup application connections disabled until ConnectWise issues formal reconnection instructions, and review every managed Microsoft 365 tenant for unauthorized OAuth application registrations and consent grants tied to ConnectWise or SkyKick identities. Hunt Microsoft Entra ID sign-in and audit logs for application-identity sign-ins from unexpected IPs or user agents, review application credentials and permissions, and check for persistence such as new service principals or mailbox rules. ConnectWise has completed an account and credential reset in the affected environment and is restoring in controlled phases, but that reset does not remove access already established inside individual customer tenants, which require separate review using ConnectWise's technical investigation and remediation guide.

The assessment changes if ConnectWise confirms which specific tenants were touched beyond the 173 already reported, if Microsoft publishes a full indicator set for Storm-0940's ARTEX infrastructure, or if additional vendors beyond ConnectWise are tied to the same ARTEX campaign. Watch also for any CISA guidance and for evidence that the actor retained access after the credential reset, which would indicate a deeper persistence problem than the current containment suggests.
