Cisco Talos found that eight intermediate certificate authority certificates issued by eMudhra were generated with near-zero entropy. During an April 30, 2025 key-generation ceremony for 24 subordinate CAs, a flaw in eMudhra's key generation process created a second set of weak P-384 keys during a wrap/unwrap step, dropping entropy from 384 bits to 3-8 bits and making the private keys trivially recoverable. An attacker holding any compromised intermediate's private key could impersonate any website or service. Six of the TLS certificates, trusted by Chrome, Mozilla, and Apple, have been blocked by those vendors, and two code-signing certificates used by Microsoft have also been blocked. Microsoft subsequently released out-of-band Windows updates (KB5134133 for Windows 11 24H2/25H2/26H2 and KB5134125 for Windows 10 21H2/22H2) on October 26, 2026 to remove trust in the affected certificates on systems without automatic certificate trust updates, with the same removals applied to Microsoft Edge on October 27.

eMudhra has revoked the compromised certificates and stopped issuing new certificates under its G3 root. In a November 2026 incident report the CA traced both the weak keys and a further problem to a custom Python script it wrote to move private keys between hardware security modules (HSMs) across vendors after hardware-procurement delays. The script reduced eight ECDSA private keys to a single byte, and it also processed eight RSA private keys in the memory of the machine running the script rather than inside the HSM. Those RSA keys were not weakened, but eMudhra could not demonstrate they were handled under its certificate security policies. On November 11, 2026 it revoked eight additional intermediate certificates, bringing the total affected to 16. The CA has since shut down its public TLS business, attributing the decision to the bug that destroyed roughly 18 months of security-audit trust.

Additional patches are expected across a variety of technologies as applications remediate exposure. Organizations should verify their trust stores and certificate chains reflect the revocations and vendor blocks, and reissue any certificates chained to the affected intermediates. Defenders should confirm Windows systems received the out-of-band trust-list updates or automatic CTL refreshes, check that browsers and operating systems block all 16 intermediates, and reissue any certificates chained to them. Watch for further vendor advisories extending the block list and for any public tooling that automates recovery of the weak keys, which would make exploitation trivial against any system still trusting the affected intermediates.
