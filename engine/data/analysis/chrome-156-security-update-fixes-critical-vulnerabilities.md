Chrome 156 stable (156.0.8078.47 for Android, matching desktop builds for Windows, macOS, and Linux) arrived October 20, 2026, carrying 353 security fixes including six critical defects. The critical set spans memory corruption in Skia (CVE-2026-113341), Accessibility (CVE-2026-113279, CVE-2026-113271), CSS (CVE-2026-113072), Paint (CVE-2026-113280), and WebRTC (CVE-2026-113303), plus high-severity use-after-free issues in SiteIsolation, FileSystem, CacheStorage, ANGLE, WebUI, Network, Passwords, SVG, and V8. Google reports no active exploitation for this specific release, but the 353-fix volume and the six critical ratings mean defenders should not treat this as a routine maintenance cycle.

The exposure is universal: any endpoint running Chrome versions earlier than 156.0.8078.47 is exposed to remote code execution paths through crafted HTML pages that trigger Skia or WebRTC memory corruption. With no exploitation telemetry confirmed, the risk assessment hinges on patch velocity rather than observed attacker behavior. This story stands apart from the daily stream of browser updates precisely because of the critical density: six critical CVEs in a single stable promotion is well above the baseline, and the presence of sandbox-adjacent components (SiteIsolation, Accessibility) raises the stakes for any successful chain.

Defenders should upgrade to 156.0.8078.47 immediately and verify build numbers in managed environments rather than relying on the rolling deployment timeline. For hunt, focus on process crashes in renderer processes near the October 20 rollout window, unusual sandbox exits, and any telemetry referencing Skia or WebRTC failures. Workarounds are limited: restrict untrusted web access through network proxies or isolated browsing profiles until the patch is confirmed on all endpoints, and monitor for Google Chrome update completion events in endpoint management logs.

Watch for two changes: any CISA KEV entry or in-the-wild confirmation for CVE-2026-113341, which would shift this from a high-volume patch to an active-threat response, and the completion of the rolling deployment, which Google states will continue over the coming days. If exploitation telemetry appears before the rollout finishes, the patch gap itself becomes the exposure window.
