Microsoft attributes bulk destructive Azure activity to Storm-3168, its tracking name for JADEPUFFER, the operator Sysdig identified in July 2026 as the first documented agentic ransomware operation. In one compromised tenant, a service principal spent about 15 hours and 30 minutes performing more than 300 successful read operations, enumerating VMs, subscriptions, and resource groups; a second principal rapidly surveyed two subscriptions and inspected App Service configuration stores. Both principals used the python-requests/2.34.2 user agent. The pivot from discovery to destruction took under a second: after a failed ListKey request against a non-existent storage account, a destructive sequence ran roughly seven minutes, followed by more than 150 destructive or credential-collection operations in 35 minutes, including over 100 deletion attempts against Storage Accounts, SQL databases, a Key Vault, Function Apps, recovery protection locks, VMs, and App Services. No ransom note appeared and Microsoft confirmed no exfiltration.

The control-plane blast radius hinges on workload identity hygiene. The tenant's service principal client ID, client secret, and tenant ID had previously been exposed in plaintext in a public GitHub issue and remained retrievable from edit history. The destruction traced to RBAC assignments; the only controls that stopped deletions were Azure resource locks and storage account deletion protection. This extends the destruction-first pattern Microsoft first documented in July 2026, when the same operator encrypted 1,342 Nacos items with an ephemeral AES key, making payment pointless. The latest activity shows the same identity-abuse model moved to cloud recovery infrastructure.

Defenders should treat any secret ever visible in a public issue, gist, or repository as live, rotate it, and hunt Azure Activity Logs for python-requests/2.34.2 against ARM, ListKey bursts, and delete attempts against recovery locks. Cut service principals to least privilege, replace long-lived secrets with workload identity federation, and enforce resource locks and deletion protection on backup assets.
