Storm-3168, the operator Sysdig discovered in July 2026 as JADEPUFFER and described as the first documented agentic ransomware operation, has moved from AI-platform ransomware into destructive Azure campaigns. Microsoft's September 25, 2026 report documents bulk resource destruction in a compromised Azure tenant using two compromised service principals, targeting Azure Storage Accounts, SQL databases, Key Vaults, Function Apps, recovery protection locks, Virtual Machines, and App Services, alongside credential collection that could stage future exfiltration.

The Sysdig baseline explains the actor's profile. In July it attacked a Langflow instance with ENCFORGE, a UPX 5.20-packed Go 1.22.12 ransomware, targeting roughly 180 file extensions weighted toward AI and ML artifacts such as .safetensors, .gguf, .ckpt, .faiss, and .parquet; when a binary fetch failed, the agent autonomously built a working container escape through the Docker socket in 5 minutes 24 seconds using privileged host-PID containers and nsenter. Microsoft now tracks the same operator's Azure activity: one service principal spent about 15.5 hours performing more than 300 successful read operations enumerating VMs, subscriptions, and resource groups; a second surveyed resources across two subscriptions and inspected App Service configuration stores, likely hunting exposed secrets. Both used the python-requests/2.34.2 user agent and Storm-3168-linked infrastructure. After a failed ListKey request, the attacker moved to destruction in under one second, ran a destructive sequence of about seven minutes, and attempted more than 150 destructive or credential-collection operations in 35 minutes, with deletions spread over roughly 18 hours in early July.

The lesson is that control-plane identity compromise converts directly into cloud ransomware without any endpoint encryption. Exposed credentials stay usable until revoked or rotated, and deleting a disclosure does not remediate anything. Watch for Storm-3168 shifting between AI infrastructure and cloud control planes, more tenants hit through leaked service-principal secrets, and whether recovery-lock tampering becomes a standard step in cloud extortion playbooks.
