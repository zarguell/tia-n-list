Microsoft attributes bulk destructive cloud activity to Storm-3168, its tracking name for JADEPUFFER, the operator Sysdig identified in July 2026 as the first documented agentic ransomware operation. In one compromised tenant a service principal spent about 15 hours 30 minutes enumerating VMs, subscriptions, and resource groups with 300+ successful read operations, and a second principal ran discovery, a 7-minute destructive sequence inside a 35-minute window of 150+ destructive or credential operations, then issued 30+ successful ListKeys requests for storage account keys, including Azure Site Recovery accounts. The deletions included 100+ storage account attempts, most successful, plus one Key Vault, one Function App, and one App Service plan, while every Azure SQL deletion failed only because the attacker used an unsupported API version. Both principals shared the user agent python-requests/2.34.2 and Storm-3168 infrastructure. Microsoft could not confirm initial access but found the tenant's service principal client ID, client secret, and tenant ID previously exposed in plaintext in a public GitHub issue by an employee, still retrievable from the issue's edit history after redaction. No ransom note appeared and no exfiltration was confirmed.

The significance is that this is control-plane extortion where identity hygiene, not endpoint defense, decides the blast radius. The destruction traced exactly to RBAC assignments: a group-granted Storage Account Contributor role authorized the storage deletions and direct Contributor roles the application deletions, and the only controls that stopped deletions were Azure resource locks and storage account-level deletion protection, which held even against an identity with broad permissions. Cross-referencing Sysdig's reports shows Microsoft's three published indicators, 45.131.66.106, 34.153.223.102, and 64.20.53.230, are the same hosts Sysdig documented on July 1 and July 20, 2026 as C2, staging, and binary delivery for the Langflow CVE-2025-3248 campaigns that encrypted 1,342 Nacos configurations with an ephemeral key that was never stored, making recovery impossible even with payment. That infrastructure overlap links the September Azure activity to the same destruction-first operator, and the targeting of Site Recovery and Backup protection locks, the T1490 pattern, before any demand fits an actor that has already demonstrated payment buys nothing.

Defender actions follow from the mechanism. Revoke and rotate any client secret that ever appeared in a GitHub issue, gist, or repository file, and treat edit history as live copies. Inventory service principals for group-granted roles such as Storage Account Contributor and cut them to least privilege, then replace long-lived secrets with workload identity federation where supported. Apply Azure resource locks and storage account deletion protection to backup and recovery assets, which Microsoft documented as blocking deletions here, and enable Defender for Cloud plans for Resource Manager, Storage, Key Vault, App Service, and Databases. Hunt in Azure Activity Logs and sign-in logs for python-requests/2.34.2 against ARM, a service principal enumerating two subscriptions in five seconds, ListKey bursts following deletion waves, and any delete attempt against recovery protection locks; block 45.131.66.106, 34.153.223.102, and 64.20.53.230. Patch Langflow to 1.3.0 or later for CVE-2025-3248, in CISA KEV since May 2025, and keep /api/v1/validate/code off the internet, since Microsoft observed Storm-3168 infrastructure probing exactly that path on Azure App Service since the beginning of 2026.

Two developments would change the assessment. Confirmed use of the harvested storage keys for data exfiltration would turn the single-extortion read into double extortion and raise the stakes for every tenant with readable storage keys. A Microsoft-Sysdig correlation tying the June 2026 Azure tenant to Sysdig's July victims, or ENCFORGE artifacts such as mass .locked file creation, task IDs like gcp_h1, or lockd staging on cloud hosts, would confirm the pivot from on-premises database extortion to fleet-scale agentic cloud destruction, and model artifacts at $75,000 to $500,000 per rebuild would need to join databases in every backup and recovery plan.
