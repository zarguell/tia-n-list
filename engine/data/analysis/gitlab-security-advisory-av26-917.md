GitLab released critical security updates for Community Edition and Enterprise Edition on September 11, 2026, addressing vulnerabilities that could allow unauthenticated arbitrary file reads, credential exposure, and remote code execution. The Canadian Centre for Cyber Security issued advisory AV26-917, and CISA added CVE-2026-85706 to the Known Exploited Vulnerabilities (KEV) Database the same day. Self-managed administrators should upgrade to GitLab 19.3.2, 19.2.6, or 19.1.8 depending on their supported release branch.

CVE-2026-85706 is a path traversal vulnerability in the repository commits API affecting GitLab CE and EE. Under certain conditions, an unauthenticated remote attacker can read arbitrary files from a vulnerable GitLab server. The CVSS vector AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:N indicates unauthenticated exploitation with network access, low complexity, and high confidentiality and integrity impact. The flaw affects GitLab versions from 18.7 before 19.1.8, 19.2 before 19.2.6, and 19.3 before 19.3.2.

The September 10 patch release fixes 18 security issues across GitLab CE and EE. GitLab.com is already running the patched code, and GitLab Dedicated customers do not need to take action. The vulnerability is especially significant because it requires no credentials, no user interaction, and uses a network-based attack vector. An attacker who exploits the flaw could access sensitive server-side files including application configuration data, secret material, tokens, or credentials stored in accessible paths. The CISA KEV addition signals active exploitation in the wild.
