Claroty's Team82 disclosed 23 vulnerabilities in Copeland XWEB Pro commercial refrigeration controllers, 21 of them rated high severity. The affected family includes XWEB300D PRO and XWEB500D PRO. The reported combinations include an authentication bypass, predictable administrator credential generation and OS command injection in XWEB Pro 1.12.1 and earlier that can give an unauthenticated attacker root-level remote code execution. Copeland released firmware 1.13 to address the set. One of the severe issues, CVE-2026-25085, sits in the device's Lua-based web authentication logic.

Other identifiers in the reporting include CVE-2026-124002, a pre-authentication OS command injection in XWEB EVO, and CVE-2026-124010 with CVE-2026-124014, which security online coverage flags as unauthenticated root flaws exploited in the wild with public proof-of-concept detail. Those claims are separate from the 23-vulnerability Team82 disclosure, so inventory should cover both the XWEB Pro and XWEB EVO lines rather than assuming one firmware ticket clears every device.

The exposure matters because these controllers sit above the equipment that runs the refrigeration itself. An XWEB unit connects the enterprise network to field controllers over RS485 using Modbus, and those controllers manage compressors, cooling fans, defrost heaters, lighting and temperature sensors. A single exposed supervisory device can therefore reach many refrigeration units in a supermarket or distribution center. Watch for internet-facing XWEB panels, move devices to 1.13, segment the Modbus side from corporate networks, and look for command execution at root level on the controller.
