CVE-2026-98432 is a use-after-free in Linux IPv4 TCP connection handling that has drawn sharply different severity ratings: OSV and the kernel CVE team score it 9.8 with AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H, while Red Hat's CVE page says 5.9 and its machine-readable advisory later lists 8.1. The flaw is a race in which tcp_v4_syn_recv_sock() transfers ireq_opt to the child socket without copying it, allowing a retransmitted SYN to race SYNACK handling and free memory still in use. Kernels back to 4.4 are affected.

Anthropic reported that an unreleased internal Claude model built a working exploit against a server with a multipath TCP listener. The chain leaked a kernel pointer in about 48 minutes and reached root command execution roughly five minutes later. Other coverage says ordinary TCP listeners are affected but that remote code execution has not been publicly demonstrated without MPTCP. Fixes upstream were backported to maintained stable branches, with advisory lists naming 5.10.272, 5.15.223, 6.1.190, 6.6.159, 6.12.113, 6.18.56, 7.2.10 and 7.3. Debian patched early, Red Hat published RHSB-2026-016, and Ubuntu staged fixes in the -proposed pocket before wider release.

The main watch item is distribution coverage rather than exploit novelty. Amazon Linux shipped kernel6.18 on October 24 and kernel6.12 on October 29, while some packages stayed pending. Ubuntu's fixes sat in -proposed for days after Debian and Red Hat had updates. Veeam and Welotec later issued product advisories for the same kernel flaw. Defenders should confirm whether MPTCP listeners are enabled and verify that running kernels include the backport, not just that an advisory exists.
