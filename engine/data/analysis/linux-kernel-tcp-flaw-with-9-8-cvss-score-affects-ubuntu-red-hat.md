CVE-2026-98432 is a race-condition use-after-free in the Linux kernel IPv4 networking stack, in the TCP setup path, that can be triggered remotely without authentication on hosts running a multipath TCP listener. An unreleased internal Anthropic model found and exploited the flaw, leaking a kernel pointer in roughly 48 minutes and reaching root command execution about five minutes later; Anthropic reported the issue through coordinated disclosure and the vulnerability was patched upstream and backported to maintained stable kernel branches. The flaw was published on October 15, 2026 and modified on October 16, 2026. A separate report noted that an exploit has been claimed, though official fixes for Ubuntu and Red Hat were still pending as of the reporting.

The severity rating is disputed. The OSV record and several distributions carry a CVSS v3 score of 9.8, while Red Hat rates it Moderate at 5.9 on its CVE page and later lists Important impact at 8.1 in its machine-readable advisory. Amazon Linux assigns Important severity with a CVSS v3 base of 7.0. Red Hat notes RHEL 8, 9, and 10, including the Real Time kernel, are affected while RHEL 7 is not, and fixes were deferred to a future update as of October 29, 2026. Amazon Linux has shipped fixes for kernel6.18 (ALAS2023-2026-3251) and kernel6.12 (ALAS2023-2026-3335), with other packages pending. Debian, SUSE, Oracle, and Amazon Linux have patched; Ubuntu and Red Hat had not as of the reporting. Community mitigations circulating include an nftables rule set (table ip cve_2026_98432) for hosts whose distribution has not yet shipped a patched kernel.

What to watch: which distributions ship fixes and whether the 9.8 rating holds through NVD adjudication, since the score drives patching priority. Systems exposing multipath TCP listeners should be treated as the highest-risk population and patched or mitigated first, and administrators on Ubuntu or RHEL should monitor vendor advisories closely given the deferred fix status. Hosts behind Proxmox bridges where packets traverse only the bridge may need the nftables mitigation, since such traffic bypasses prerouting in the ip family.
