CVE-2026-98432 is a use-after-free in the Linux kernel's IPv4 TCP connection handling, introduced by a race condition in which tcp_v4_syn_recv_sock transfers ownership of ireq->ireq_opt to the child socket without copying it, allowing a concurrently processed retransmitted SYN to trigger a use-after-free. The kernel CVE team assigned it CVSS 9.8 (AV:N/AC:L/PR:N/UI:N), while Red Hat rates it 5.9 Moderate, a dispute that hinges on reachability conditions. The flaw affects kernels back to 4.4 across Ubuntu, RHEL, Rocky, and Debian.

Anthropic reported that an unreleased internal Claude model discovered the bug and built a working exploit that targets servers with a Multipath TCP (MPTCP) listener, leaking a kernel pointer in about 48 minutes and reaching root command execution roughly five minutes later. Remote code execution has been demonstrated only against MPTCP listeners; ordinary TCP paths are affected but no public RCE exists for them. The vulnerability is patched upstream and backported to maintained stable branches (5.10.272, 5.15.223, 6.1.190, 6.6.159, 6.12.113, 6.18.56, 7.2.10, 7.3), with fixes shipped by Debian and Amazon Linux while RHEL deferred fixes as of late October and Ubuntu's fixes sat in the -proposed pocket rather than the default updates channel as of November 2.

There is no evidence of in-the-wild exploitation; the demonstrated attack came from a lab. Even so, any host exposing an MPTCP listener on an unpatched kernel is at risk of unauthenticated remote root. Administrators on affected distributions should apply available kernel updates or, where patches lag, disable MPTCP listeners and apply the published nftables mitigation until fixed kernels arrive.
