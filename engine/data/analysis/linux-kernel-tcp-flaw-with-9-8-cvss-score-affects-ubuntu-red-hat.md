CVE-2026-98432 is a use-after-free in Linux kernel IPv4 TCP connection setup, reachable by a remote unauthenticated sender and scored CVSS 9.8 by the kernel CVE team. The bug is a race in tcp_v4_syn_recv_sock(), which transfers ownership of ireq->ireq_opt to the child socket without copying it; a concurrent retransmitted SYN can trigger the free. It affects kernels dating back to 4.4, including Ubuntu, Red Hat Enterprise Linux, Rocky Linux, Debian, Amazon Linux, and openSUSE.

Anthropic reported that an unreleased internal Claude model found and exploited the flaw, leaking a kernel pointer in about 48 minutes and reaching root command execution about 5 minutes later against servers with a multipath TCP listener. The exploit is a lab demonstration rather than known in-the-wild use, and the flaw also affects ordinary TCP connections, though remote code execution has not been publicly demonstrated without an MPTCP listener. Upstream fixed the bug on October 15 and backported it to maintained stable branches.

Distro patch delivery is the practical problem. Red Hat rates the CVE 5.9 on its page while its machine-readable advisory lists Important at 8.1, and Amazon Linux lists 7.0, a scoring dispute that has confused deployers. Debian patched 12 and 13, Red Hat issued fixes, and Amazon Linux shipped kernel6.18 on October 24 and kernel6.12 on October 29. Ubuntu staged fixes in the -proposed pocket for 22.04 LTS and newer, so they are not in the default updates channel, and as of November 15 rescana and Trend Micro were still flagging the flaw as network-reachable with patched kernels available.

Confirm the running kernel rather than the installed package, and treat unpatched internet-facing hosts as exposed. Until a distro fix lands, disable MPTCP listeners where feasible or apply the nftables mitigation circulating for unpatched hosts. Watch for exploitation telemetry now that a working remote root chain is public.
