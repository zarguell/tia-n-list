CVE-2026-98432 is a race-condition use-after-free in the Linux kernel IPv4 TCP networking code (affecting kernels back to 4.4) with a disputed CVSS profile: the kernel team rates it 9.8 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H), while Red Hat rates it Moderate with CVSS 5.9 (later revised to Important at 8.1). Amazon Linux assigns 7.0, and Debian, Ubuntu, and SUSE have all issued patches. The core technical detail is a concurrency issue in `tcp_v4_syn_recv_sock()` where ownership of `ireq->ireq_opt` is transferred without copying, allowing a concurrent retransmitted SYN to trigger a use-after-free and remote root execution on hosts with multipath TCP listeners.

Anthropic reported that an unreleased Claude model built a working remote-root exploit for this flaw in a lab setting: targeting servers with an MPTCP listener, it leaked a kernel pointer in about 48 minutes and reached root command execution roughly 5 minutes later. The vulnerability affects RHEL 8, 9, and 10 (including Real Time), with RHEL 7 unaffected; Ubuntu released an advisory on October 15 and updated it on October 29, but full fixes remain pending for some branches. The concrete artifact to watch is the upstream kernel fix that copies `ireq_opt` properly, and the MPTCP listener exposure surface: servers without MPTCP have not had remote RCE publicly demonstrated, which limits immediate universal panic but does not eliminate risk for multi-homed hosts.

Organizations should verify whether their Linux hosts expose MPTCP, apply the distribution-specific patches (Amazon Linux kernel6.18 fixed October 24, kernel6.12 fixed October 29; other branches pending), and treat Anthropic's demonstration as a confirmed proof of concept rather than an active in-the-wild campaign. Monitor Linode/Akamai status updates and vendor advisories for remaining branches, since Red Hat deferred fixes to a future update as of October 29.
