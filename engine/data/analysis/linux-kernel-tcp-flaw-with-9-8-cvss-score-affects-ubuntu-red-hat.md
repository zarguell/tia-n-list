CVE-2026-98432 is a use-after-free in the Linux kernel's IPv4 TCP handshake, introduced in the handling of TCP connection requests where tcp_v4_syn_recv_sock transfers ownership of ireq->ireq_opt to the child socket without copying it. A racing retransmitted SYN can trigger the freed object, and a remote unauthenticated attacker can reach it before any application code runs. The Linux kernel CVE team scored it 9.8, though Red Hat rates it Moderate at 5.9 and Amazon Linux 7.0, reflecting disagreement over whether the race is practically exploitable on ordinary TCP. In practice the demonstrated remote root path requires a Multipath TCP listener: Anthropic's unreleased internal model found and exploited the flaw in a lab, leaking a kernel pointer in about 48 minutes and reaching root command execution roughly five minutes later. No in-the-wild exploitation has been reported.

The vulnerability affects kernels back to 4.4 across Ubuntu, Red Hat Enterprise Linux, Rocky Linux, Debian, SUSE, Oracle, and Amazon Linux. Fixes shipped in stable kernels on October 11 and 15, 2026, and vendors have backported them: Debian patched 12 and 13, Red Hat issued RHSB-2026-016, and the Canadian Centre advisory lists affected ranges up to 7.3. Ubuntu's fixes remain in the -proposed pocket for 22.04 LTS and newer as of November 4, not yet the default updates channel, leaving a gap between available and deployed patches. Mitigations in the interim include disabling MPTCP listeners and filtering with nftables rules published by the community.

Defenders should treat any host with an MPTCP listener as the priority for patching and assume ordinary TCP exposure is lower but not zero until the vendor fix lands. The Anthropic demonstration shows the flaw is weaponizable by automated tooling, so the patch gap on Ubuntu in particular is the urgent item to close.
