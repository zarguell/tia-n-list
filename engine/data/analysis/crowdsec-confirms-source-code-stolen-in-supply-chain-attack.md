CrowdSec, the French vendor of open source crowdsourced threat intelligence and a lightweight intrusion detection engine, has confirmed that source code was stolen from roughly 300 of its GitHub repositories, about 170 of them private. The company learned last week that the exfiltration happened in May 2026, a gap of roughly six months between the theft and its discovery. Both public and private code was taken, so the repository history and internal tooling are now outside the company's control.

What was taken matters more than the raw count. CrowdSec says the private repositories contain the source for its SaaS console, some AWS Cloud routines, connectors and automations. The company also says it hunted for tokens, credentials and other secrets that could enable lateral movement and found none, and that no customer credentials or customer data were leaked. Its argument is that the private code cannot be used to cause harm out of context because it needs CrowdSec's own network, data and tools to run, and that the SaaS code had been audited regularly.

Treat the "no credentials" statement as the company's own assessment rather than an independent finding; it is plausible for a repository leak of this type, but the absence of a confirmed secret in a May compromise reviewed in November is not the same as proof. The practical risk sits in the private SaaS console and AWS routines, where an attacker with the code could study authentication flows and automation logic for months before CrowdSec even knew. Watch for a follow-up advisory with a concrete timeline, and for any downstream customer notices if the six-month quiet period turns out to hide more than source files.
