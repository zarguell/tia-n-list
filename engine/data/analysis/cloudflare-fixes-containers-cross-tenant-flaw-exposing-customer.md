Cloudflare fixed a cross-tenant data exposure in Cloudflare Containers and Sandboxes affecting Workers Paid plan customers. Researcher Oren Yomtov at Accomplish reported the flaw through HackerOne on September 4. The vulnerability allowed a customer with a Workers Paid account to recover residual data from other customers' containers on the same physical host. The root cause was a shared storage pool that skipped zeroing reused 64 KiB blocks; when a container's thin volume was deleted, its physical blocks returned to a multi-account pool. By writing only 4 KiB to an unused region of a new container disk, an attacker could cause a reused 64 KiB block to be allocated, leaving the remaining 60 KiB from a previous customer readable. Exposed data included directory listings, SQLite databases, Chromium profiles, .env files, and credential files. The issue is now patched. Organizations running containerized workloads on Cloudflare Workers Paid should verify no residual container instances from before the fix expose stale block data.
