Push Security documented a malvertising chain dubbed "Adception" that targets people searching Google for "claude mac". The sponsored result displayed the legitimate bing.com domain as its destination, then routed clicks through Google's ad redirect into Bing's bing.com/ck/a click-tracking endpoint, then to a compromised WordPress site belonging to a South American retailer (homeopatiaalemana[.]com), and finally to claude-desk-code[.]com, a fake Claude installer page that pushes macOS users toward ClickFix-style command execution. The embedded timestamp in the Bing click URL decodes to October 5, 2026, so the chain was staged days before disclosure. Multiple cloaking layers hide the payload from scanners and direct visitors.

Why it matters: the technique weaponizes trust in two brands at once. Advertising security checks see bing.com, not an attacker domain, and users see a credible search-result destination before a short redirect chain. Push Security links the fake installer infrastructure to a shared ClickFix toolkit it tracks as AcSig, with sibling domains cli-desktop[.]com and lake-90[.]com and published IoCs, which suggests a reusable kit rather than a one-off ad.

Watch for the same Bing-redirect pattern appearing against other software brands, since the toolkit is shared, and for Google and Bing responses such as ad takedowns or changes to how bing.com/ck/a URLs can be used as ad display destinations. Defenders should treat any sponsored result for popular developer tools as hostile until verified and block or alert on redirect chains that pass through unrelated compromised sites before a download page.
