Push Security disclosed a malvertising chain on October 9, 2026 that nests one search engine inside another's ads. A sponsored Google result for the query `claude mac` displayed `bing.com` as its destination; clicking passed through Google's ad redirect into Bing's `bing.com/ck/a` click-tracking endpoint, a JavaScript forward that answers HTTP 200 instead of 302 and hands the next hop a `bing.com` referrer. From there the victim crossed a compromised WordPress page on `homeopatiaalemana[.]com`, a South American homeopathy retailer, before landing on `claude-desk-code[.]com`, a fake Claude download page aimed at macOS users. Multiple cloaking layers mean the payload renders only if the chain is traversed end to end through this exact path, so scanners and anyone hitting the URL directly see nothing.

The argument is that every checkpoint in the delivery path inspected a URL and each one saw a brand it trusted, because the attacker's destination was simply another search engine that Google's ad review waved through. The ClickFix payload extends the same deception to the terminal: the pasted command prints `Downloading Claude: https://claude.ai/install.sh` while a base64 blob embedded in it hides the real script host, `lake-90[.]com`, whose output is piped straight into `zsh`, so a user who reads both the page and the terminal still sees only legitimate Claude URLs. The Bing click link carries an embedded timestamp decoding to October 5, 2026, which puts the redirect infrastructure in place days before disclosure. Push ties the fake installer to a toolkit it tracks as AcSig, fingerprinted by HMAC-gated command fetches, with the identical macOS command and install modal across at least seven more domains. That makes this a reusable kit rather than a one-off, which is why this story outranks routine malvertising: the technique and the tooling are both copy-paste ready.

Defenders should block and hunt on the full domain set: `claude-desk-code[.]com`, `lake-90[.]com`, `cli-desktop[.]com`, `clawddddd[.]com`, `fairpoint29[.]com`, `fine-byte2[.]com`, `rapid-craft567[.]com`, `turbowave45[.]com`, and unexpected `pages[.]dev` hosts. In macOS shell history and EDR process telemetry, look for `zsh` invocations piping `curl` output where the URL argument comes from an `openssl base64 -d` decode, and for fetches of `.dat` paths under a `/curl/` directory. In proxy or DNS logs, flag chains that pass through `bing.com/ck/a` and then land on an unrelated compromised site before a download page. The standing control is behavioral: install developer tooling only from vendor domains typed directly, and treat any install flow that asks for a paste into a terminal as hostile regardless of how legitimate the printed URL looks.

The two developments that would change the assessment are copycats reusing the Bing-redirect-as-ad-destination trick against other brand queries, which the AcSig kit's identical fingerprints make cheap to detect, and a platform response from Google or Microsoft tightening validation of ad destinations that resolve to another search engine's click-tracking links. Sustained sponsorship of these ads after disclosure, or AcSig domains rotating faster than blocklists update, would push this from a clever one-off to a persistent channel worth standing defenses up against.
