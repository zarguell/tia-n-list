Hackers have been draining hot wallets on BTCPay Server instances running version 2.4.1 or earlier, with the attack vector targeting instances on versions older than 2.4.2. The project urged operators to update to version 2.4.7 and initially advised shutting down servers pending investigation. The vulnerability was discovered via Anthropic's Frontier OSS scanner and disclosed on October 29, prompting the emergency 2.4.7 release, but the attackers appear to have used older flaws in versions before 2.4.2, which the project later confirmed.

BTCPay founder Nicolas Dorier said the attacks did not target public servers, and the investigation focused on how the threat actor obtained administrator login on affected instances. Because BTCPay is self-hosted and holds funds directly in merchant wallets, the exposure sits with operators who have not patched.

Self-hosted instances still on 2.4.1 or older should be treated as compromised: upgrade to 2.4.7 or later, rebuild, and audit wallet balances and access logs. Watch for the project's completed incident report and for any further detail on the admin-login vector.
