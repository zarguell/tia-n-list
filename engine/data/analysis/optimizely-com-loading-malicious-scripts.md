Attackers injected a one-line loader into customer-editable Project JavaScript served from cdn.optimizely.com, including cdn.optimizely.com/js/5113954737848320.js on an about.gitlab.com page. The loader fetched 1688360.cc/track.js, a roughly 30 KB script that checksum-validates and swaps ETH, BTC, TRX, TON, SOL, LTC, BCH and DOGE addresses, skims cards with Luhn and brand checks through fetch and XHR hooks, and exfiltrates cookies, page URL and a screenshot to /hit.php and /card.php. On iPhone and iPad user agents it also loads boot.js from .icu hosts and, on iOS 18.6 or earlier, a hidden stage tied by researchers to the Coruna and DarkSword exploit kits. Domain registration at 05:23 UTC on November 16 and public scans from 08:28 UTC put the activity hours ahead of the first alert, and no successful device exploitation has been confirmed.

The count that matters is not just the 21 web properties with verified poisoned responses or the 186 sites Scott Helme said were infected. Report URI checked 1,611 snippets and found 188 poisoned files across 178 organisations, including CNN, BBC, Zoom, Salesforce and GitLab. A victim's own web server can be pristine while every visitor's browser executes attacker code from a trusted vendor CDN, so compromise scoping limited to first-party repositories and hosts misses the incident entirely. Two captured sites blocked execution with CSP script-src and still logged the request, which means exposure counts must separate payload requested from payload ran. A file that is clean on recheck also proves nothing about the hours before cleanup: Helme reported at 21:32 UTC that 41 of 188 infected files were still live. This is mass payment-page and wallet theft with an unconfirmed mobile exploit branch, not a skimmer on one compromised shop.

No vendor patch or hotfix existed at publication: Optimizely had issued no statement, root cause or remediation guidance. Fetch each served snippet from cdn.optimizely.com/js/PROJECT_ID.js or cdn.optimizely.com/public/ACCOUNT_ID/s/NAME.js and search the live file for 1688360, 5vobauua3ojpklx, eil786npto9u5bq, je4ft3gn8vxudum and atob(, because CNN's copy carried a Base64 fallback and vendor files change when experiments are published. Remove the snippet from checkout, login and payment pages until the vendor explains what happened; enforce CSP script-src allowlists for those hosts rather than relying on consent gating, which controls when the vendor script runs, not what it contains. Hunt proxy, DNS and firewall logs for /track.js, /hit.php, /card.php, /html2canvas.min.js and the .icu boot.js paths, review CSP violation reports and client-side telemetry for sendBeacon calls on checkout pages and off-site html2canvas requests, then audit Project JavaScript edit history, rotate Optimizely credentials, enforce MFA and treat first-party card form fields as possible card data exposure for the payment processor.

The assessment changes if Optimizely publishes a root cause showing platform compromise rather than individual customer account abuse, because that moves every customer from checking a file to assumed exposure. It also changes if forensic evidence confirms that the iOS stages exploited devices rather than only being delivered to Safari user agents, or if the roughly $6,600 seen across the attacker wallets starts climbing.
