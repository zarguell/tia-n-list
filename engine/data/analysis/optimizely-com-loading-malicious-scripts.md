On November 16, 2026, attackers injected malicious JavaScript into Optimizely Web Experimentation customer projects and served it from cdn.optimizely.com. Report URI examined 1,611 Optimizely scripts, found 188 infected snippets tied to 178 organizations, and named sites including BBC, CNN, Zoom, GitLab, Salesforce, HSBC, IKEA, Equifax and Ledger. Optimizely said the entry point was a vulnerability in the Experimentation account signup flow; it blocked the path, removed injected code, ended sessions, revoked tokens and reset access for affected accounts.

The payload was a multi-part loader. Amirul Cyber saw bundles fetching 1688360.cc/track.js, with a wallet address swapper covering eight chains, a card skimmer using Luhn checks and sendBeacon to /card.php, and screenshot and cookie exfiltration to /hit.php. Report URI said the payload was rebuilt 26 times during the day. Beazley and Hudson Rock traced related poisoned scripts through Kissmetrics, StorifyMe and minute-ly, with earliest observations on November 13, three days before the Optimizely wave, and linked iOS stages to Coruna and DarkSword delivery infrastructure.

Two sites blocked the external payload with CSP script-src while the poisoned snippet still loaded, which shows why checking the vendor project file itself matters. Beazley recommended reviewing the served project code, removing snippets from pages with card fields and blocking 1688360.cc and named .icu hosts in CSP. Successful device exploitation and the volume of stolen card data remain unconfirmed in the event set. Watch for vendor root-cause updates, Censys work on the shared MCH control pane and any confirmed victim or loss reporting.
