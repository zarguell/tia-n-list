Attackers used a flaw in Optimizely Web Experimentation's account signup flow to add malicious JavaScript to customer projects, so sites loading their normal per-customer snippet from cdn.optimizely.com served the payload to visitors on 16 November. Report URI's Scott Helme found 188 infected snippets among 1,611 scripts, tied to 178 organizations including CNN, BBC, Zoom, GitLab, Salesforce, HSBC, IKEA, Air France and Ledger. BleepingComputer independently confirmed loads on affected sites through urlscan.io. One early indicator was cdn[.]optimizely[.]com/js/5113954737848320.js on about.gitlab.com, which pulled 1688360[.]cc/track.js.

The injected loader carried several revenue stages: a checksum-validating crypto clipper covering eight chains, a card skimmer using Luhn checks and sendBeacon to /card.php, and cookie and screenshot exfiltration posting to /hit.php, with an iOS second stage from two .icu hosts. Beazley and Hudson Rock traced related poisoned responses to Kissmetrics, StorifyMe and minute-ly, with archived activity on those services as early as 13 November, three days before the Optimizely wave. The iOS path is tied to Coruna and DarkSword delivery infrastructure, but researchers have not confirmed successful iPhone or iPad compromises or the value of card data taken.

Optimizely says it blocked the vulnerable signup path, removed the injected code, ended active sessions, revoked tokens, reset affected accounts and blocked code delivery in Cloudflare. Two sites blocked the external payload with CSP script-src while the poisoned snippet still loaded, which shows why checking the vendor-hosted project file matters. Watch for the root cause of the signup flaw, whether the other three script providers share an access path, visitor counts, and any confirmed theft or device exploitation. Blocking 1688360[.]cc and the named .icu hosts is the immediate containment step.
