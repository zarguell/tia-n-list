Optimizely confirmed that attackers exploited a vulnerability in its Experimentation account signup flow to inject JavaScript into customer projects. The company said it blocked the vulnerable path, removed the injected code, ended active sessions, revoked tokens, reset affected user accounts and blocked delivery through Cloudflare. Scott Helme's review found 188 infected scripts across 178 organizations among 1,611 Optimizely scripts examined, and the code was served to visitors on November 16. Reporting on November 17 by The Hacker News put CNN, the BBC and Zoom among the affected sites; other named brands included Fox News, Salesforce, GitLab, KLM, IKEA, HSBC, Equifax, Ledger and UNICEF USA.

The injected code loaded 1688360.cc/track.js, which Amirul Cyber breaks into a crypto clipper covering eight chains, a screenshot and cookie exfiltration module posting to /hit.php, and a card skimmer using Luhn checks and sendBeacon to /card.php. The payload also carried an iOS second stage from two .icu hosts, with reporting tying delivery infrastructure to Coruna and DarkSword. At least two sites blocked the external domain through CSP while the poisoned first-party snippet still loaded, so a domain block alone did not remove the execution path. Beazley reported poisoned project files from the same campaign at Kissmetrics, StorifyMe and minute-ly as early as November 13, three days before the Optimizely wave, and Hudson Rock noted that the access paths at those providers remain unresolved.

This is a high-reach supply-chain incident because visitors trusted established brands while the script came from a trusted experimentation CDN. Watch for the SHA-256 of track.js in web logs, requests to the named exfiltration endpoints and the .icu hosts, and any evidence that the iOS stages succeeded, which reporting says has not been confirmed. Card field exposure on affected pages deserves separate review from the cryptocurrency theft activity, and the visitor count and any losses have not been quantified.
