On 16 November 2026, attackers exploited a flaw in Optimizely Web Experimentation's account signup flow to add malicious JavaScript to customer projects. The code was served from the normal cdn.optimizely.com URLs, so pages loaded it as a trusted first-party script. Scott Helme of Report URI found 188 infected snippets belonging to 178 organizations after examining 1,611 scripts. Affected sites included Zoom, BBC, CNN, Fox News, Salesforce, GitLab, IKEA, HSBC, Equifax, Ledger and Peacock, with the malicious code present for close to 19 hours.

The injected loader pulled 1688360.cc/track.js, which researchers broke into several modules: a checksum-validating clipper covering eight cryptocurrency chains, a card skimmer using Luhn checks that posted through sendBeacon to /card.php, screenshot and cookie exfiltration to /hit.php, and an iOS second stage from two .icu hosts linked to Coruna and DarkSword delivery. One observed poisoned bundle was cdn.optimizely.com/js/5113954737848320.js on about.gitlab.com. Two sites blocked the external payload with a CSP script-src rule even though the poisoned Optimizely snippet still loaded. Hudson Rock also traced similar poisoned scripts through Kissmetrics, StorifyMe and minute-ly, with archived responses from 13 November.

Optimizely says it blocked the vulnerable signup path, removed the injected code, ended active sessions, revoked tokens, reset access for affected accounts and blocked code delivery in Cloudflare. The wider delivery picture is still unresolved, including the other three providers' access paths and the number of visitors hit. Watch for unexpected entries in the Project JavaScript field, block 1688360.cc and the named .icu hosts at the CSP layer, pull third-party scripts off pages that handle card data, and treat card fields on affected sites as possibly exposed.
