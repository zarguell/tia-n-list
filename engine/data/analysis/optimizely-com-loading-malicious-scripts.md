On 16 November 2026, malicious JavaScript was served through Optimizely Web Experimentation to visitors of websites run by 178 organizations. Report URI examined 1,611 scripts and found 188 infected snippets, including scripts used by BBC, CNN, Zoom, Salesforce, GitLab, IKEA, HSBC, Equifax, Ledger and Air France. Optimizely confirmed that an attacker exploited a vulnerability in the Experimentation account signup flow to add JavaScript to customer projects. The company blocked the path, removed the injected code, ended active sessions, revoked tokens, reset affected accounts and blocked code delivery through Cloudflare.

The loader sat in the optional Project JavaScript field and was served from cdn.optimizely.com, so affected sites delivered it as trusted first-party configured code. Researchers decoded a crypto clipper covering eight chains, a card skimmer using Luhn checks and sendBeacon to /card.php, and cookie and screenshot exfiltration to /hit.php. An iOS branch pulled a second stage from two .icu hosts and was linked to Coruna and DarkSword delivery infrastructure. Report URI saw the payload rebuilt 26 times during the day; StepSecurity recorded requests to the malicious infrastructure between 08:28 and 21:23 UTC. Verified cryptocurrency transactions to attacker wallets are reported, but successful iPhone exploitation is not confirmed.

The same delivery stack appeared with Kissmetrics, StorifyMe and minute-ly, with archived activity on 13 November, three days before the Optimizely wave. That widens the investigation beyond one vendor. Teams should review their Project JavaScript settings and account access, block infrastructure such as 1688360.cc and the named .icu hosts in CSP, and treat card fields and session cookies on affected pages as possibly exposed. Watch for updates on the other three providers and on how the signup-flow vulnerability was abused at scale.
