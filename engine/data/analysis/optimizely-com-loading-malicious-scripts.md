On November 16, 2026, attackers used a flaw in Optimizely Web Experimentation's account signup flow to inject JavaScript into the Project JavaScript field of customer projects, and the code was served from cdn.optimizely.com to visitors of 178 organizations. Report URI's Scott Helme found 188 infected snippets among 1,611 examined; named sites include BBC, CNN, Zoom, GitLab, Salesforce, IKEA, HSBC, Equifax, Ledger and Air France. Optimizely says it blocked the vulnerable path, removed the injected code, ended active sessions, revoked tokens, reset affected accounts and blocked delivery through Cloudflare.

The loader fetched 1688360.cc/track.js and carried several modules: a checksum-validating crypto clipper covering eight chains, a card skimmer using Luhn checks and sendBeacon to /card.php, and cookie and screenshot exfiltration to /hit.php. Report URI observed the payload rebuilt 26 times in one day, and StepSecurity recorded requests to the malicious infrastructure between 08:28 and 21:23 UTC on November 16. Some iOS traffic led to Coruna and DarkSword exploit kit staging on two .icu hosts, though successful iPhone compromise has not been confirmed.

Report URI observed verified cryptocurrency transactions to attacker wallets, but the amount of card data taken remains unquantified. Two sites blocked the payload with CSP script-src while the poisoned snippet still loaded, which is why simply blocking the external domain was not enough. Hunting guidance names 1688360.cc, 5vobauua3ojpklx.icu, eil786npto9u5bq.icu and webshell.lol as infrastructure to check.

Hudson Rock traced similar poisoned script delivery through Kissmetrics, StorifyMe and minute-ly, with archived vendor activity dating to November 13, three days before the Optimizely reports. That widens the incident beyond one vendor and makes third party script inventories, Project JavaScript review and session token revocation the practical follow-up for operators.
