Attackers exploited a vulnerability in Optimizely Web Experimentation's account signup flow on November 16, 2026, then used the access to edit the Project JavaScript field in customer projects. That field runs on every page loading the Optimizely snippet, and the resulting code was served from cdn.optimizely.com, so browsers treated it as normal vendor output. Report URI examined 1,611 Optimizely scripts and found 188 infected snippets tied to 178 organizations, including BBC, CNN, Zoom, Salesforce, GitLab, IKEA, HSBC, Equifax and Ledger. BleepingComputer independently confirmed loads on GitLab, KLM, Smartsheet and other sites through urlscan.io records.

The loader at 1688360.cc/track.js carried several modules. Amirul Cyber documented a checksum-validating clipper covering eight cryptocurrency chains, a card skimmer using Luhn checks and sendBeacon posts to /card.php, cookie and screenshot exfiltration to /hit.php, and an iOS second stage from two .icu hosts. Reporting from Beazley Security and Hudson Rock tied the mobile branch to Coruna and DarkSword, and found the same tooling in poisoned scripts from Kissmetrics, StorifyMe and minute-ly, with archived responses on November 13, three days before the Optimizely wave. StepSecurity saw requests to the malicious infrastructure from 08:28 to 21:23 UTC on November 16, and Report URI said the payload was rebuilt 26 times during the day.

Optimizely said it blocked the vulnerable path, deployed a fix, removed injected code from affected projects, ended active sessions, revoked tokens, reset access for affected accounts and blocked delivery in Cloudflare. It notified impacted customers. Those steps stop the known path, but they do not answer what visitors lost. Report URI observed verified cryptocurrency transactions to attacker wallets, while no count of skimmed card data and no confirmed iPhone compromise had been published. Two observed sites blocked the external payload with CSP script-src only while the poisoned snippet still loaded, which shows why response inspection has to cover the vendor file itself, not just outbound domains.

Watch for Optimizely's root-cause report and for customer notifications that quantify losses. The access paths behind the other three script providers remain unresolved, and the gap between the November 13 archived responses and the November 16 Optimizely reports needs explanation. Defenders with affected sites should review Project JavaScript history, account access and relevant logs, then look for the named exfiltration paths in client and endpoint telemetry instead of assuming removal of the snippet ended exposure.
