On 16 November 2026 an attacker exploited a vulnerability in the Optimizely Web Experimentation account signup flow to add malicious JavaScript to customer projects. The code sat in the optional Project JavaScript field, which runs on every page, and was served from cdn.optimizely.com inside otherwise ordinary Optimizely snippets. Scott Helme of Report URI examined 1,611 scripts and found 188 infected ones tied to 178 organizations, including CNN, BBC, Zoom, GitLab, Salesforce, IKEA, HSBC, Equifax, Ledger, Air France and Fox News. Reuters reported the same 178-organization wave as a campaign to steal cryptocurrency and target iPhone and iPad users. Optimizely says it blocked the vulnerable path, removed the injected code, ended active sessions, revoked tokens, reset affected accounts and blocked code delivery in Cloudflare.

The payload had several financial and mobile components. Researchers documented a loader fetching 1688360.cc/track.js, a crypto address swapper covering eight chains with checksum validation, a card skimmer that validates numbers with Luhn checks and sends data via sendBeacon to /card.php, and screenshot and cookie exfiltration to /hit.php. Two .icu hosts served an iOS second stage linked to the Coruna and DarkSword exploit kits, though successful device exploitation and confirmed financial losses have not been established. At least two sites blocked the external domain through CSP script-src while the injected code still loaded from the trusted CDN.

Hudson Rock and Kirk of Ohey traced similar poisoned scripts through Kissmetrics, StorifyMe and minute-ly, with archived vendor responses dating to 13 November, three days before the Optimizely wave. Watch for the full IOC set, including the SHA-256 of track.js and attacker wallet addresses, plus card-field exposure determinations at affected sites. The unresolved pieces are the access paths at the other three script providers, the number of visitors exposed and whether any iPhone exploits landed. Because only the Project JavaScript field changed inside a legitimate vendor script, the useful detection angle is content inspection of third-party script responses and CSP that accounts for code embedded in the trusted script itself.
