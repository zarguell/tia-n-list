On November 16, attackers used a flaw in Optimizely Web Experimentation to add malicious JavaScript to customer projects, and the code was served from the trusted `cdn.optimizely.com` path. Report URI examined 1,611 Optimizely scripts and found 188 infected snippets tied to 178 organizations, including BBC, CNN, Zoom, GitLab, Salesforce, IKEA, HSBC, Equifax and Ledger. Optimizely said the entry point was a vulnerability in the Experimentation account signup flow; it blocked the path, removed the injected code, ended active sessions, revoked tokens and blocked further code delivery in Cloudflare.

The payload looked like ordinary project JavaScript and was rebuilt 26 times during the day. It swapped cryptocurrency wallet addresses, skimmed payment cards with Luhn checks and `sendBeacon` posts to `/card.php`, and exfiltrated cookies and screenshots to `/hit.php`. A second branch targeted iPhones and iPads with Coruna and DarkSword exploit-kit staging from `.icu` hosts. Amirul Cyber documented a loader from `1688360.cc/track.js`; StepSecurity saw requests to the malicious infrastructure from 08:28 to 21:23 UTC on November 16, and Report URI observed verified currency transactions to attacker wallets. Hudson Rock and Beazley also found poisoned scripts served through Kissmetrics, StorifyMe and minute-ly, with observations from November 13, but the access path for those providers remains unresolved.

The incident is a third-party trust failure at scale. The affected sites were not individually compromised; browsers accepted the code because it arrived from an expected vendor CDN inside a normal Optimizely snippet. Strict CSP script-src would have blocked some outbound calls, and two observed sites did block the payload while the poisoned snippet still loaded. No public count of stolen card data exists, and successful iPhone exploitation was not confirmed in the available reporting.

Watch for Optimizely's root-cause report, for customer notifications that quantify payment or crypto losses, and for more detail on the shared infrastructure behind the four providers. Defenders with affected sites should review Project JavaScript history and account access, check browser and endpoint telemetry for the named domains and hunt for the card and cookie exfiltration paths rather than assuming vendor removal ended visitor exposure.
