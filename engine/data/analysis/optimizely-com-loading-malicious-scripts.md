On November 16, 2026, malicious JavaScript was served through Optimizely Web Experimentation to visitors of sites run by 178 organizations. Report URI examined 1,611 scripts and found 188 infected snippets affecting brands including BBC, CNN, Zoom, Salesforce, GitLab, IKEA, HSBC, Equifax, Ledger and Air France. Optimizely said an attacker exploited a flaw in the Experimentation account signup flow to write JavaScript into customer projects, then blocked the path, removed the code, ended sessions, revoked tokens and reset affected accounts.

The loader sat in the optional Project JavaScript field and was served from cdn.optimizely.com, which made it look like trusted configured code on each customer site. Report URI decoded a crypto clipper covering eight chains, a card skimmer using Luhn checks and sendBeacon to /card.php, cookie and screenshot theft to /hit.php, and an iOS branch tied to Coruna and DarkSword infrastructure. The payload was rebuilt 26 times during the day, and StepSecurity logged requests to the malicious hosts between 08:28 and 21:23 UTC. Verified cryptocurrency transactions to attacker wallets are reported; successful iPhone exploitation is not.

New coverage frames the attack as A/B testing of malware on major sites, and one outlet puts the number of compromised sites above 190,000 including CNN, Zoom and IKEA. That figure is higher than the 178 organizations counted by Report URI and should be read as a wider exposure estimate rather than a confirmed victim count. Heise's German report describes the same supply-chain delivery through well-known brands.

Review Project JavaScript settings and account access on any Optimizely customer, block known infrastructure such as 1688360.cc and the named .icu hosts in CSP, and treat card fields and session cookies on affected pages as possibly exposed. Watch for updates on the other delivery stacks seen alongside this wave, Kissmetrics, StorifyMe and minute-ly, and for any confirmation of iOS exploitation.
