Google shipped Chrome 154 to the stable channel on September 22, 2026: 154.0.8037.57 on Linux, 154.0.8037.57/.58 on Windows and Mac, carrying 108 security fixes of which 11 are Critical. The three CVEs this story tracks all sit in the graphics stack. CVE-2026-95350 is a buffer overflow in ANGLE carrying a $5,000 bounty, CVE-2026-95281 is a second ANGLE buffer overflow credited to Muhammad Alifa Ramdhan of STAR Labs SG with the report filed 2026-08-24, and CVE-2026-95357 is an out-of-bounds write in the GPU process, reported 2026-07-01 and paid at $2,500. Google states nothing about exploitation in the wild and keeps bug details restricted until a majority of users are updated. The same fix set reached Android in Chrome 154.0.8037.57 the same day, and an early stable 155.0.8059.16 build followed on September 23.

The delivery chain for these flaws is a URL. ANGLE translates graphics APIs for rendering, and the GPU and WebGL processes digest untrusted data from any page, so a drive-by visit is enough: no attachment, macro, or credential prompt. The report dates mean the July 1 GPU bug and the August 24 ANGLE bugs rode in shipping Chrome builds for roughly six to twelve weeks before the patch, and the advisory credits two further ANGLE criticals to the same STAR Labs SG lab, which reads as sustained research pressure on the browser's graphics attack surface rather than scattered one-off finds. Chrome is the most deployed application in most enterprises, so 108 fixes including a dozen high-severity use-after-free defects make an unpatched browser the cheapest initial-access path available, and the exposed population is effectively every Windows, macOS, Linux and Android endpoint in the fleet.

Version floors: 154.0.8037.58 on Windows and Mac, 154.0.8037.57 on Linux, 154.0.8037.57 on Android; users can force the jump at chrome://settings/help and admins should treat anything below these builds as exposed. Fleets on the Extended Stable channel are covered by 152.0.7977.140, released the same day. There is no workaround for memory corruption in the graphics stack, so version currency is the entire control. Hunt with what exists: pull Chrome version inventory from endpoint management or EDR process telemetry, prioritize hosts still on 153.0.8010.x builds, and watch for GPU-process crash bursts or unexpected child processes spawned by the browser as renderer-compromise tells. Google will publish detail under issue ids 551573368, 530045332 and 551708184 for the three tracked CVEs once restrictions lift, so those tracker entries are where exploit code will surface first.

Two developments would change the assessment. An amendment to the advisory adding the standard exploitation-in-the-wild line, or a CISA KEV listing and EPSS score for any of the 11 criticals, would move this from patch hygiene to incident triage for anyone not yet at the version floors. The second is the lifting of the access restriction on bug details, which Google applies until most users are patched and which historically coincides with public exploit code; if that lands for the ANGLE or GPU issues while fleets still straddle 153 and 154, the window for drive-by compromise is open.
