GhostAction is a continuing supply-chain intrusion that injects malicious GitHub Actions workflows into repositories to steal CI/CD secrets. The original campaign, documented by GitGuardian on September 5, 2025, compromised 817 repositories across 327 users and exfiltrated 3,325 secrets via a payload named `github_actions_security.yml`. The new wave that began around August 31, 2026 at 14:00 GMT uses the same file name and the same commit message (`Add Github Actions Security workflow`), but now hardcodes targeted secret names rather than dumping the full environment. The workflow triggers on `push` and `workflow_dispatch`, runs on `ubuntu-latest`, and sends stolen values in a single `curl` POST to the attacker's server. The event list shows 346 repositories affected in the October 8 sweep alone (two accounts, 27 and 318 repositories), including the active `uber/athenadriver` repository, which had moved under the Uber organization but retained the original author's write access.

A successful attack means full exposure of CI/CD secrets for any repository where the malicious workflow executes. The attack does not require package publication: even a workflow run that collects secrets creates a persistent breach, because removing the workflow does not revoke stolen credentials or invalidate the GitHub token used to push it. The October 9 OpenSourceMalware report shows the same infrastructure (`193.32.204[.]199`) is reused as an active malicious scanner with 11,286 probes to TCP/8080 recorded by SANS ISC, meaning the same server that collects secrets also scans for additional vulnerable services. This dual-use makes GhostAction more dangerous than a pure credential-theft campaign: the attacker can pivot from stolen publishing tokens to broader infrastructure compromise. The presence of unrelated cryptominer infections in some victims, noted in the Reddit update, suggests a shared pool of compromised credentials used by multiple threat groups, increasing the probability that any stolen token will be exploited by actors beyond the original GhostAction operator.

Defenders must assume exposure of active Actions secrets and credentials previously committed and later deleted. Remove malicious workflows from executable branches, rotate every named secret, and audit packages, releases, images, and deployments produced during the compromise window. Hunt for the exact payload filenames (`github_actions_security.yml`, `security-check.yml`, `security-audit.yml`), the commit message `Add Github Actions Security workflow`, and outbound HTTP POST connections to `193.32.204[.]199` or ports 3000 on that host. The October 2026 variant uses the route `?c=monami`; previous variants used port 3000 with `/api/workflow/receive?inj=`. Apply protected branches, workflow approval requirements, and runner egress allowlists, because StepSecurity reports that workflow approval was the control that stopped exfiltration in this wave.

Watch for new malicious workflow commits to prominent repositories and any direct reference to `my-github[.]com` or `my-gitlab[.]com`, both registered in October and September 2026 respectively and linked to the current collector IP. A shift from raw IP exfiltration to branded domain-based collection would change the hunting profile significantly.
