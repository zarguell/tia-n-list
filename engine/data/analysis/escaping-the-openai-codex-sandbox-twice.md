Security researchers at Accomplish AI documented two ways out of the OpenAI Codex sandbox, the isolation boundary around OpenAI's coding agent. The more serious one, named Heapjack, turns opening an untrusted repository into remote code execution: a developer opens someone else's repo in Codex Desktop, asks a question about the code, and the repo author gains unsandboxed command execution on that developer's machine from Codex's most locked-down mode, with no approval prompt and nothing visible on screen. The second technique, Overpatch, bypasses Codex's write restrictions to escape the read-only sandbox. Both were reported to OpenAI on August 12 and fixed within eight days, per Oren Yomtov of Accomplish AI.

The root cause is instructive. Codex Desktop silently writes a tool called node_repl into the global ~/.codex/config.toml at install time, with no opt-in and no setting to disable it, so plain Codex CLI users inherit it too. node_repl runs trusted OpenAI code and untrusted agent code as two JavaScript contexts in one Node.js process, and a vm context is a separate global object, not a separate heap. Heapjack exploits that shared heap to cross the trust boundary from the untrusted side.

This matters because coding agents are being pointed at untrusted code by design, and the sandbox is the only thing standing between a malicious repository and developer laptops with source code, cloud credentials, and signing keys. An attacker needs nothing more than a victim's curiosity about a repo.

Worth watching: whether other agent vendors run trusted and untrusted code in one process with the same pattern, whether OpenAI changes the config.toml side effects that silently widen the attack surface, and whether Heapjack-style heap-level escapes show up in public exploit collections the way prompt-injection chains already have.
