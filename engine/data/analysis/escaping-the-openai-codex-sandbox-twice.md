Security researchers from Accomplish AI demonstrated two sandbox escape techniques against OpenAI's Codex coding agent. The first, called Heapjack, turns a routine action into remote code execution: open someone else's repository in Codex, ask it a question about the code, and the attacker gets unsandboxed command execution on the developer's machine with no approval prompt and nothing shown on screen. The second technique, Overpatch, bypasses write restrictions in read-only sandbox mode.

Both flaws exploit the node_repl component that Codex Desktop writes into the global ~/.codex/config.toml at install time. There is no opt-in or setting to disable it, and CLI users inherit the same tool. The trusted and untrusted JavaScript execution contexts share memory, allowing the untrusted context to leak references and escape.

OpenAI patched both vulnerabilities within eight days of disclosure on August 12. The key takeaway for enterprises adopting AI coding agents: sandbox guarantees are only as strong as their implementation, and agents that run untrusted code from external repositories represent a new attack surface. Organizations should treat AI coding tools with the same threat model as build systems or CI/CD pipelines.
