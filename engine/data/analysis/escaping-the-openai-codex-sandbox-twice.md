Researchers at Accomplish AI found two sandbox escape paths in OpenAI's Codex coding agent. The more dangerous one, dubbed Heapjack, targets a component called node_repl that Codex Desktop installs into the global config file at install time. There is no opt-in and no way to disable it. The component runs a single Node.js process with two JavaScript execution contexts: one trusted (OpenAI code) and one untrusted (agent code). Heapjack bridges those contexts, giving an attacker unsandboxed command execution on the developer's machine.

The attack scenario is straightforward. Open someone else's repository in Codex, ask a question about the code, and the repository owner gets remote code execution on your computer with no approval prompt and nothing shown on screen. Both flaws were reported to OpenAI on August 12 and patched within eight days.

This is significant because coding agents are moving into enterprise workflows with elevated permissions. The sandbox is the primary security boundary, and two independent breaks in one product suggest the boundary needs harder scrutiny across the category. Watch for similar research targeting GitHub Copilot, Cursor, and other agentic coding tools.
