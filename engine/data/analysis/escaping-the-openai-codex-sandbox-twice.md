Security researchers at Accomplish AI found two methods to escape the OpenAI Codex sandbox, both reported August 12 and fixed within eight days. The more severe flaw, dubbed Heapjack, turns a routine action into remote code execution: open someone else's repository in Codex Desktop and ask a question about the code, and the repository owner gets unsandboxed command execution on your machine with no approval prompt and nothing displayed on screen.

Heapjack targets a component called node_repl, which Codex Desktop installs into the global ~/.codex/config.toml file at setup time with no opt-in and no way to disable it. The component runs a single Node.js process holding two JavaScript execution contexts, one trusted (OpenAI's code) and one untrusted (the agent's code). The escape breaks the boundary between these contexts, granting full host access from Codex's most locked-down mode.

The second escape method is less severe but still defeats the sandbox boundary. Both flaws are specific to Codex Desktop and its bundled node_repl component. OpenAI patched both within a week of disclosure. The research highlights a recurring pattern in AI coding agents: the sandbox is the primary safety control, and escapes from inside it bypass all downstream restrictions. Organizations running Codex Desktop should confirm they are on the patched version.
