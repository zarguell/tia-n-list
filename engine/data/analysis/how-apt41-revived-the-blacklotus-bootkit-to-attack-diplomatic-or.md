APT41 revived the BlackLotus bootkit framework as a new firmware implant called BlackX, exploiting the same Baton Drop vulnerability (CVE-2022-21894) to bypass UEFI Secure Boot and maintain persistence below the operating system. The campaign, first identified by Kaspersky GReAT in early 2026, targeted diplomatic agencies in Tajikistan, Uzbekistan, and Turkmenistan with a UEFI bootkit modeled after the 2023 BlackLotus design. Because the implant writes to the EFI System Partition and executes before Windows loads, removal requires firmware-level remediation rather than standard endpoint cleaning.

This story matters because it shows a state-linked actor (APT41) adopting boot-level persistence for espionage against diplomatic targets in Central Asia, a region where such low-level implants are rarely observed in public reporting. The event data indicates the attackers deployed new payloads alongside the bootkit, suggesting the campaign is active and evolving rather than a one-off reuse of old code. For defenders, the critical exposure is not just the targeted countries but any organization running unpatched UEFI firmware vulnerable to CVE-2022-21894, since the same Secure Boot bypass mechanism can be redeployed quickly.

Patch the UEFI firmware using the vendor updates that address CVE-2022-21894 (Microsoft released multiple updates beginning in 2023); verify ESP contents for unauthorized EFI executables and inspect boot logs for anomalies tied to Secure Boot bypass attempts. Hunt for indicators mentioned in the Kaspersky report: look for DLL sideloading drivers, firmware-level implants in ESP, and network connections matching the payload delivery infrastructure described for BlackX. Monitor for any new samples matching BlackX signatures, since the campaign is ongoing and the actor has demonstrated willingness to update the implant.

Watch for expanded attribution linking APT41 to additional BlackX variants beyond Central Asia, and for vendor patches addressing any follow-on Secure Boot bypasses that could revive the Baton Drop technique on newer firmware revisions. If exploitation telemetry or GreyNoise-style sensors detect renewed ESP modification activity, reassess exposure immediately.
