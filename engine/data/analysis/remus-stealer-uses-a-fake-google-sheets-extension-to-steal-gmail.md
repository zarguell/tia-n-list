Remus Stealer version 1.3.9 began advertising Gmail access that survived password changes and session revocation on November 8. Hudson Rock and Malwarebytes found no controlled proof of a Gmail zero-day. Independent work by Invoke RE and Gen Threat Labs instead identified a malicious Chrome extension disguised as Google Sheets. A native x64 DLL installs the extension, which reads mail through the browser's existing Gmail session and sends message contents to an attacker-controlled endpoint.

Invoke RE reported a ZIP expanded in the user's temporary directory by PowerShell, edits to Chrome's Secure Preferences and extension ID cfmepkojgnkahbmgablgdahdomjdppgf. The extension checks Gmail account slots 0 through 9 through the unread Atom feed every minute and exfiltrates to prem1um[.]onl/m. Its access can survive password changes because the extension remains in the compromised browser profile, but it stops when the Gmail session ends and resumes when the victim signs in again. That behavior explains the persistence claim without requiring a Gmail vulnerability.

The finding makes endpoint and browser cleanup as important as account recovery. A password reset alone leaves the collection component in place, and stolen mail can expose correspondence, financial information and reset messages. Users should clean the device from a trusted system, remove unexpected extensions and review Gmail forwarding, filters, delegation, recovery settings and connected apps. Defenders should watch for the extension ID, the exfiltration domain and the PowerShell-driven installation pattern.
