Remus Stealer version 1.3.9 advertised Gmail access that survived password changes and session revocation, but Hudson Rock and Malwarebytes found no controlled evidence of a Gmail zero-day or fresh mail retrieval after full account recovery. Invoke RE and Gen Threat Labs identified the browser component on November 24: a malicious Chrome extension disguised as Google Sheets that reads Gmail through the victim's existing signed-in session and sends message contents to an attacker-controlled endpoint.

Invoke RE described a ZIP in the user's temporary directory expanded by PowerShell and edits to Chrome's Secure Preferences to register extension ID cfmepkojgnkahbmgablgdahdomjdppgf. The extension checks Gmail account slots 0 through 9 through the unread Atom feed every minute and exfiltrates to prem1um[.]onl/m. GenDigital's reverse engineering found a native x64 DLL whose purpose was to install the extension.

This explains the persistence claim without a Gmail vulnerability. The extension remains in the compromised Chrome profile, loses access when the active session ends and resumes when the victim signs back in. Password changes alone do not remove that browser foothold. Exposed mail can include verification codes, recovery links and sensitive personal or workplace correspondence.

Response must cover both the endpoint and the Google account. From a trusted device, review Chrome extensions and signed-in access, secure the account, and check forwarding, filters, delegation and recovery settings. Hunt for the extension ID and endpoint, and watch for the same browser component in other Remus campaigns.
