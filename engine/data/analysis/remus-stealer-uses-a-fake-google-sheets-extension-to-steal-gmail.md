Remus Stealer version 1.3.9 advertised Gmail access that survived password changes and session revocation, but Hudson Rock's investigation did not prove a Gmail zero-day or demonstrate fresh mail retrieval after full account recovery. Invoke RE and Gen Threat Labs later identified the browser component: a malicious Chrome extension disguised as Google Sheets that reads Gmail through the victim's existing signed-in session and sends message contents to an attacker-controlled endpoint.

The reported installation chain used a ZIP in the user's temporary directory expanded by PowerShell and edits to Chrome's Secure Preferences. Invoke RE identified extension ID cfmepkojgnkahbmgablgdahdomjdppgf, checks of Gmail account slots 0 through 9 through the unread Atom feed every minute, and exfiltration to prem1um[.]onl/m. Because the extension remains in the compromised Chrome profile, it can survive password changes and session revocations. Its access stops when the active session ends and resumes when the victim signs back in, which explains the persistence claim without requiring a Gmail vulnerability.

The exposure includes unread mail, verification codes and sensitive correspondence from personal or workplace accounts. Response must cover both the endpoint and the Google account: use a trusted device, review Chrome extensions and signed-in access, secure the account, and check forwarding, filters, delegation and recovery settings. Watch for further samples and confirm whether the extension ID and endpoint appear in other Remus campaigns. The concrete artifacts are version 1.3.9, the extension ID and the defanged exfiltration endpoint.
