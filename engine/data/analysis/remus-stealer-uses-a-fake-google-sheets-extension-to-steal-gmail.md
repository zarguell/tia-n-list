Remus Stealer, a 64-bit Windows infostealer that Gen Threat Labs tracks as a Lumma successor, is installing an unpacked Chrome extension named Google Sheets to read Gmail through a victim's existing login session. Invoke RE observed a sample on November 23, 2026: Remus wrote a ZIP into %TEMP%, used hidden PowerShell Expand-Archive, and edited Chrome's Secure Preferences to register extension ID cfmepkojgnkahbmgablgdahdomjdppgf with developer mode enabled. The extension, version 0.5.4 with a minimum Chrome 120 build, runs a background worker holding storage, alarms, and `<all_urls>` host access. Every minute it checks Gmail account slots 0 through 9 through the unread Atom feed, fetches message bodies, and POSTs sender, subject, text, and mailbox address to prem1um[.]onl/m. Neither Invoke RE nor Gen Threat Labs found a Gmail vulnerability; the zero-day claimed in Remus version 1.3.9 advertising was marketing.

This is a persistence and resale problem, not a browser exploit. Password changes and ordinary session revocation do not remove the extension, so any Gmail slot still signed in inside the Chrome profile keeps producing mail for the collector after the executable exits. Malwarebytes said on November 11 that Hudson Rock's evidence never validated fresh-mail access after full account recovery, and the code shows why the worry persists without proving the seller's stronger claim. Mailbox contents include verification codes and recovery links, which turn each stolen log into a launch point for account takeover elsewhere, and CyberInsider reported the Mail feature sold in an Enterprise tier at $1,000 per month. A commodity service available to many affiliates deserves more weight than the three-outlet, 5.8-score pickup alone suggests.

No vendor patch applies because no Gmail flaw was demonstrated; the response is to remove the foothold and block the collector. Revoke Google sessions and application access from a clean device, review forwarding, filters, delegation, and recovery settings, remove the extension, then clean the Windows host because an x64 DLL installer can leave the profile modified after the stealer process ends. Hunt for cfmepkojgnkahbmgablgdahdomjdppgf.zip under %TEMP%, Secure Preferences.bak, the Chrome preference entry extensions.settings.cfmepkojgnkahbmgablgdahdomjdppgf, developer_mode set to true, hidden PowerShell Expand-Archive, extension version 0.5.4, the mail-forwarding alarm, mailForwardingV1 state, and POSTs to prem1um[.]onl/m carrying campaign ID d7e027cf1c9989bd45ceeb3429e49cf5. Block prem1um[.]onl at the proxy and check the native Remus C2 configuration for the same endpoint.

Watch for a controlled test showing newly delivered mail still readable after password reset, session and application-access revocation, and extension removal; that would overturn the current no-zero-day assessment. Also watch for a second MaaS family reusing Chrome preference tampering to register an unpacked extension, or victim telemetry tied to campaign ID d7e027cf1c9989bd45ceeb3429e49cf5, either of which would widen the assessment beyond one stealer service.
