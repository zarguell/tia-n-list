CVE-2026-14266 is a heap-based buffer overflow in the XZ decompression path of 7-Zip that lets specially crafted compressed data execute code as the current user. The Zero Day Initiative published it on July 15, 2026 as ZDI-CAN-30169 with a CVSS 3.0 score of 7.0 and the vector AV:L/AC:H/PR:N/UI:R/S:U/C:H/I:H/A:H, crediting Lunbun LLC researcher Landon Peng. The flaw sits in how 7-Zip processes XZ chunked data, and the fix adds output buffer boundary checks so the decoder cannot write past available space. The vendor changelog lists 26.02 as released June 25, 2026 with the CVE entry, and the ZDI advisory records the vendor report on June 5, 2026.

The attack needs user interaction, either opening a malicious archive or visiting a page that triggers extraction, so it is a local code execution path rather than a network service bug. That lowers urgency relative to an unauthenticated server flaw, but 7-Zip runs on developer and analyst workstations where archive handling is routine and untrusted input is common. The practical problem is distribution: 7-Zip has no automatic update mechanism, so every user has to download 26.02 from 7-zip.org by hand. Endpoints will keep running older builds indefinitely without deliberate IT action, and the version spread that results is wide.

The same release line shows how much archive-handling code has moved recently. Version 26.01, released April 27, 2026, fixed eight other archive handler CVEs, and 26.03, released September 3, 2026, fixed CVE-2026-58052, a Mark-of-the-Web preservation failure. Archive tools have a track record of being weaponized: a 7-Zip flaw was exploited as a zero-day by Russian hackers in early 2025, and WinRAR CVE-2025-8088 was used in phishing to deliver RomCom. No active exploitation of CVE-2026-14266 has been reported. What to watch is whether public exploit code appears for the XZ path, since the ZDI advisory is currently the only public technical record and Peng's site carries no write-up for this bug.
