OpsShield's cPGuard update infrastructure was compromised on November 2 at 02:06 UTC, when an attacker used compromised credentials to access the CDN and serve malicious updates. Affected versions 5.88.12 through 5.88.19 carried a backdoor and data-stealing script that executed as root on servers polling the update infrastructure during the roughly 70-minute window. The vendor detected the compromise within 12 hours and released cPGuard 5.88.25 to remove the backdoor and leftover files.

The attacker first registered a customer account and ordered a free trial to study cPGuard's communication with the licensing system, then sent crafted requests to the billing and licensing server to gain command execution. From there they uploaded the fake update using a stolen access key and copied three of the company's cloud servers. Stolen data was routed to an endpoint on OpsShield's licensing server under a compromised account, which was later secured.

Hosting firms and server administrators running cPGuard on Linux web servers, including those using cPanel, DirectAdmin or Plesk panels, should verify they are on 5.88.25 or later and audit for the malicious script's artifacts. Namecheap customers on VPS and dedicated servers are among those potentially affected.
