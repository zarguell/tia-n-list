On 2 November 2026 at 02:06 UTC an attacker used compromised OPSSHIELD distribution credentials to push malicious cPGuard updates through the vendor CDN. The affected versions are exactly 5.88.12 through 5.88.19 inclusive; the malicious script `cpguard-v58812-i91511.sh` installed a backdoor and staged an archive before exfiltrating `/etc/shadow` password hashes and other secrets to an attacker-controlled endpoint on OPSSHIELD's own licensing server. The vendor released 5.88.25 to remove the known backdoor and staged files, and confirmed in its 3 November advisory that 32 collected files were retrieved by the attacker, a preliminary count of affected customer servers rather than total exposure.

This is not a generic update glitch: a firewall and malware-protection product turned its own distribution channel into a supply-chain weapon, meaning every Linux server that installed 5.88.12-5.88.19 and executed the script gave an adversary root-access-equivalent hashes and a persistent backdoor. The 32-file retrieval figure is concrete, not speculative, and the script's explicit targeting of `/etc/shadow` means password reuse on other systems amplifies the breach well beyond the cPGuard host. Among the thirty-plus supply-chain stories circulating, this one demands priority because the attacker retrieved data from the vendor's infrastructure (not just pushed payloads) and the affected product is deployed on hosting servers that protect the rest of the stack.

Defenders should verify installed version with `cpgcli --version` and upgrade to 5.88.25 or later immediately; check update history for entries such as `[02-11-2026 02:46:04]: Successfully updated to 5.88.12` or any 5.88.12-5.88.19 entry. If any match, treat the server as compromised: reset root and all local Linux account passwords from a trusted recovery environment, rotate reused credentials, hunt for the script filename `cpguard-v58812-i91511.sh`, and inspect for the archive the script staged. The advisory notes that absence of these files after cleanup does not prove the script never ran, so rotation and log review are mandatory regardless.

Watch for the vendor's final scope confirmation beyond the 32 retrieved files and for any additional malicious activity the attacker may have performed beyond the backdoor and data collection described in the 3 November advisory; also watch whether further compromised accounts or credential-reuse patterns are identified in the licensing-server retrieval.
