On November 22, 2026 an actor put the same remote-control module into backdoored releases of six WP connect plugins, including Air WP Sync 2.9.1 through 2.9.4, WP Sync for Notion 1.7.4 and Add-on Brevo for Gravity Forms 2.6.3. Wordfence tracks this as CVE-2026-135202 at CVSS 9.8. The module calls tascredit-pay.com from a WP-Cron event, sends the site URL, PHP, WordPress and OS versions and the server user, then executes PHP returned by that server, with commands for shell execution, hash theft and webshell planting. The WordPress plugins team, Wordfence's PRISM monitoring and independent reporter Computeronfire each identified it, and WordPress.org's Protect The Shire hold stopped the builds before sites received them.

The important result is negative: more than 3,600 active installs were the intended audience, but the release was cut before distribution, so this is a build-pipeline breach with no confirmed exploitation, not a mass-compromise count. Because all six plugins carried one module and one command server, a single hunt covers the portfolio, and any site that had loaded the code would have faced unauthenticated WordPress-level PHP execution. Blocked is not the same as patched: Wordfence lists no known patch, and the residual exposure sits in out-of-band copies of those exact builds obtained through mirrors or manual sideloading, which is a narrower problem than a 3,600-site incident but harder to rule out site by site.

Defenders should inventory the six plugins and remove any install matching the listed versions rather than wait for a fix, then check WP-Cron entries for airwp_tick and airwp_persist_tick and any unfamiliar hourly hook. Block egress to tascredit-pay.com at the web tier and review outbound web logs for that host, and check wp-content/uploads/ for PHP files that were not placed there by a known deployment. Since the beacon carried the server user and WordPress, PHP and OS versions, a matching outbound request should be treated as a possible precursor to hash theft or webshell follow-on activity, not a benign plugin check-in.

The assessment changes if WordPress.org restores the plugins with clean releases or makes the closures permanent, or if telemetry confirms that a backdoored build was served outside the official release path or exploited on a live site. Until then the defensible claim is one blocked supply-chain attempt with a shared, testable indicator set, not an active campaign against the 3,600 installs.
