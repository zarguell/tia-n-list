Security researcher Christopher Domas released a proof-of-concept project, skitter-creek-bath-salts, demonstrating a memory-controller attack that exposes highly protected DRAM regions on certain older AMD processors. The technique targets AMD Family 15h and 16h systems where configuration registers controlling memory address translation may not be lockable. Rather than inducing bit flips like Rowhammer, it changes the final mapping between a physical address and the bank, rank, row, and column coordinates selected in memory, creating a temporary alternative view of DRAM in which an address accessible to privileged software resolves to memory the platform intended to protect. On Family 16h the technique reaches data protected from the operating system, the kernel, and even ring-0, with implications for the PSP, SMM, and microcode.

The significance is that it attacks the hardware isolation boundary itself, not a software permission check. AMD's memory scrambling was meant to obfuscate DRAM contents, and the DRAM controller configuration sits beneath every software trust layer. Because it changes the address translation at the memory controller, the exposure does not depend on a kernel bug or an OS weakness, which makes it invisible to endpoint defenses and largely unfixable in software on affected silicon.

Watch for AMD's response, whether the affected register state is confined to the disclosed families or extends to newer parts, and any follow-on research that converts the address-remapping primitive into a practical exploit against PSP or SMM secrets. The practical near-term risk is limited to systems running Family 15h or 16h processors with untrusted code already executing at elevated privilege; for those platforms, firmware updates and hardware refresh are the only real mitigations.
