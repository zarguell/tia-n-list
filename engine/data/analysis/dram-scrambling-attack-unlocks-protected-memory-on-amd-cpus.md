Security researcher Christopher Domas has demonstrated a memory-controller attack that bypasses hardware-enforced memory isolation on older AMD processors. The technique, released as the open-source skitter-creek-bath-salts project, targets AMD Family 15h and 16h CPUs where configuration registers controlling memory address translation may not be lockable. Unlike Rowhammer, this attack modifies the DRAM controller's address-translation behavior rather than inducing bit flips, creating aliases between ordinary memory addresses and protected regions.

The attack operates below the level of page tables, IOMMUs, and firmware protections. By altering the controller's DRAM swizzle, an attacker with privileged software access can redirect a legitimate physical address request to unintended memory cells. Domas calls this "spaghettifying" memory, and the proof-of-concept demonstrates access to AMD Platform Security Processor data, System Management Mode regions, and microcode. This affects only older AMD Family 15h/16h processors and requires local privileged access, limiting real-world exploitation scope.

The research matters because it targets a layer of the security stack that software mitigations cannot easily address. Organizations running legacy AMD systems in sensitive environments should evaluate exposure. AMD has not issued guidance on whether these older families will receive patches, and the research highlights ongoing challenges in hardware-level memory protection.
