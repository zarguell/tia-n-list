Threat actor compromised the adminmenueditor.com website on September 14 and pushed malicious Admin Menu Editor Pro versions 2.35 and 2.36 to paying customers. The trojanized update contained an includes/wp-user-consent.php file that installed a web shell and created a hidden wp_ user account in the WordPress database. At least 230 customers installed the malicious versions, affecting an estimated 1,500 sites (many customers manage multiple sites). The attacker had root-level server access, and the developer took the site offline until it could be restored.

This is a textbook WordPress supply chain attack: the attacker targeted the plugin's own update infrastructure rather than exploiting a vulnerability in the plugin code itself. The malicious versions were live for roughly seven hours (06:00 to 13:00 UTC on September 14), and a second compromise occurred after the developer pushed what was supposed to be a clean version 2.36. Customers running versions 2.35 or 2.36 should check for the indicators listed by the developer (the wp-user-consent.php file, a new /wp-content/object-cache/ directory, hidden wp_ users, and wp_ocache* options) and restore from a backup prior to September 14.

This incident fits a broader pattern of WordPress plugin supply chain compromises seen throughout 2026, including BdThemes and WooCommerce plugin attacks. The key lesson is that plugin update mechanisms are high-value targets: a single compromised developer account or server can seed backdoors across thousands of sites before anyone notices. Site operators should treat plugin update servers as part of their trust boundary.
