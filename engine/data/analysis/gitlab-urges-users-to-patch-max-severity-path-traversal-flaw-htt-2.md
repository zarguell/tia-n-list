GitLab disclosed and patched two critical vulnerabilities on September 11, urging immediate upgrades to versions 19.3.2, 19.2.6, or 19.1. The higher-severity issue, CVE-2026-85706, is a maximum-severity path traversal in the repository commits API discovered by researcher s3ntago via HackerOne. It allows unauthenticated attackers to read arbitrary files from vulnerable GitLab servers under certain conditions, potentially exposing credentials, SSH keys, and other sensitive data. CVE-2026-87719 is a critical insecure deserialization flaw in the GraphQL subscription serializer affecting GitLab EE only, allowing authenticated users with Duo Chat access to steal credentials and Advanced Search instance configurations.

Within a day of disclosure, watchTowr reported active scanning for CVE-2026-85706 against internet-exposed GitLab instances. The researcher warned that based on past GitLab vulnerabilities, full exploitation is likely imminent. Defenders should audit logs for HTTP POST requests to /api/v4/projects/{id}/repository/commits/ containing file.path parameters, which would indicate exploitation attempts. GitLab.com is already patched; self-managed installations need to upgrade immediately.

GitLab has over 30 million registered users and is used by more than 50% of Fortune 100 companies. Since November 2021, CISA has flagged four GitLab CVEs as actively exploited. The pattern of critical path traversal flaws recurring in GitLab's commits API (CVE-2023-2825 was the previous maximum-severity instance) suggests this attack surface remains under sustained pressure from threat actors.
