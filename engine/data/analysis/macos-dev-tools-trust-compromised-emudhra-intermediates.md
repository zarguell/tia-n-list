As of late October 2026, Apple-shipped developer tools on macOS, including git, curl, and python3, still trust eight compromised eMudhra intermediate CA certificates whose private keys were exposed. Apple was notified on October 17, and the October 26 macOS 27.2 update neither fixed the issue nor preserved user-applied manual mitigations, instead reverting them. Apple's support documentation confirms it has been blocking the compromised intermediates in Safari, Mail, and apps using Apple's networking framework since October 19, but the command-line toolchain remains affected.

The gap between browser-level blocking and developer-tool trust means a man-in-the-middle attacker can still serve malicious repository clones or alter pushes to developers using default macOS tooling, even after users manually patched. Because git and curl underpin most software supply chains, the exposure extends beyond individual developers to build pipelines and automated fetches. Microsoft's emergency Windows update for the same eMudhra key vulnerability shows the issue crosses platforms, though macOS command-line tools lag.

Developers on macOS should re-apply manual trust-store mitigations after any system update and verify certificate chains for git and curl. Watch for an Apple update that actually removes the compromised intermediates from the command-line trust store, and for any reports of malicious clones or altered pushes attributed to this window. Organizations should inventory macOS build hosts that fetched dependencies during the exposure period.
