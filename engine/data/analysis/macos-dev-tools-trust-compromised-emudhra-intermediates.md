macOS developer tools including git, curl, and python3 reportedly continue to trust eight compromised eMudhra intermediate CA certificates whose private keys were exposed, allowing a man-in-the-middle attacker to serve malicious clones or alter pushes. Apple's support document published 19 October 2026 states that since that date it has been blocking the compromised intermediates in Safari, Mail, and apps using Apple's networking framework, confirming the compromise spans multiple intermediates. As of 28 October 2026, however, Apple-shipped developer tools on macOS still trusted the affected certificates; Apple was notified on 17 October, and the 26 October macOS 27.2 update did not fix the issue and undid user-applied manual fixes. TechPlanet reported the same exposure on 28 October 2026.

The risk is supply-chain rather than a new vulnerability: any attacker positioned on a network path to a macOS developer could substitute a backdoored copy of core tools without triggering standard code-signature warnings. Partial mitigations have shipped elsewhere. Microsoft released an emergency Windows update to address the eMudhra key vulnerability, and Cloudflare updated cloudflared to prevent server spoofing across enterprise deployments. macOS command-line tooling remains the exposed surface until Apple ships a corrected update.

What to watch: whether Apple issues a fix specifically for git, curl, and python3 trust stores; whether the 26 October update that reversed manual fixes gets corrected; and developer-side auditing of endpoint certificate stores. Teams should not assume default trust chains are sufficient and should verify revocation status of eMudhra intermediates manually.
