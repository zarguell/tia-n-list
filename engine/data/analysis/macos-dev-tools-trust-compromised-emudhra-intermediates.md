A compromised eMudhra intermediate certificate is still trusted by common macOS developer tools, including git, curl, and python3, leaving those tools open to man-in-the-middle attacks that could serve malicious repository clones or alter pushes and pulls. Separately, Microsoft shipped an emergency Windows update to address a severe eMudhra key vulnerability that allowed attackers to forge digital certificates. Both reports point at the same underlying failure: trust in a compromised certificate authority propagating into the tooling developers rely on to fetch and build code.

The practical risk is supply-chain flavored rather than a single endpoint bug. A developer whose toolchain silently trusts a bad intermediate can be handed attacker-controlled source, build artifacts, or dependency updates without any warning from the tool itself. The macOS side is a trust-store hygiene problem in shipping dev tooling; the Windows side is a certificate-forgery issue severe enough to warrant an out-of-band patch. Together they suggest the eMudhra incident has not been fully contained across platforms.

Watch for a fuller accounting from eMudhra and from Apple and Microsoft on which intermediates are revoked, whether the forged-certificate capability was actually exercised, and whether package managers and CI runners beyond the named tools are also affected. Developers should verify the certificate chains their tools actually validate and pin or update trust stores until the vendor guidance is clear.
