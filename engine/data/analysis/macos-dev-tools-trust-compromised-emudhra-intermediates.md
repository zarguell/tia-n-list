macOS development tools including git, curl, and python3 reportedly continue to trust compromised eMudhra intermediate certificates, allowing a man-in-the-middle attacker to serve malicious clones of these binaries. The issue stems from stale or improperly revoked intermediate trust anchors that have not been fully removed from macOS keychains used by developer workflows. Users should verify current certificate revocation status and consider manual removal of the affected intermediates.

This is not a new vulnerability but a persistent trust-management failure with direct supply-chain implications. Any attacker positioned on a network path to a macOS developer could substitute a backdoored copy of core tools without triggering standard code-signature warnings. Security teams should audit endpoint certificate stores and enforce strict binary verification beyond default trust chains.
