Drupal core carries a critical remote code execution tracked as CVE-2026-108097 inside SA-CORE-2026-014; the flaw lives in the Field UI module and hits core versions prior to 11.4.10, 11.3.19, and 10.6.19. The advisory notes core alone is not directly exploitable, yet the Mastodon update confirms multiple exploit paths exist when contributed modules or custom configurations interact with field_ui. That distinction is the key defensive pivot: patching is non-optional even without confirmed core-only triggers, because a site with common extensions can complete the RCE chain.

This is worth a defender's attention over the routine advisory noise today because critical Drupal RCE with existing patch releases means exposure is immediate for any unpatched instance. There is no in-the-wild telemetry cited in the events, but the combination of a critical CVSS-rated RCE, released fixes on all three active branches, and confirmed multi-path exploitation conditions creates a high-probability compromise window for exposed sites running contributed modules. Organizations should treat this as a same-day patch event rather than a weekly cycle item.

Patch to 11.4.10, 11.3.19, or 10.6.19 depending on branch; verify core version via `drush status` or `composer show drupal/core`. Hunt for unexpected field_ui route access in web server logs, and inspect contributed module configurations that expose admin-side field editing. Monitor drupal.org for updated exploitation conditions, since proof-of-concept details could shift this from theoretical multi-path to active weaponization quickly.

Watch for a revised SA-CORE-2026-014 that removes the "not exploitable with core alone" caveat, or for GreyNoise/Shodan telemetry showing scanning for Drupal field endpoints tied to this CVE. Either development would move the assessment from preventive to incident-response posture.
