Attackers compromised high-profile open-source maintainer accounts, including the author of the pyxel package, and pushed malicious GitHub Actions workflows that steal credentials. The supply-chain campaign began no later than October 7 and has involved more than 500 GitHub accounts committing malicious workflows to tens of thousands of repositories, according to Socket reporting cited by The Hacker News in an article published on 2026-10-09 at 22:29:10 UTC. The three Mastodon events (masto:117413311322921674, masto:117416196428368939, masto:117418118570769321) all reference the same source URL (https://thehackernews.com/2026/10/credential-stealing-github-actions.html) and confirm the attack remains active through the latest update. There is no assigned CVE for this campaign; the mechanism is repository contamination via compromised maintainer credentials rather than a product vulnerability.

A successful attack gives the adversary direct access to repository secrets, CI/CD tokens, and any downstream credentials the malicious workflow exfiltrates, which for tens of thousands of repositories means a massive exposure footprint rather than a single-target breach. The story matters more than routine supply-chain noise because the attacker specifically targeted established maintainers with trusted packages, using their reputation to propagate malicious actions into dependent builds at scale. The events note that the incident is ongoing, which means repositories that have not audited their recent workflow commits since October 7 remain at risk of silent exfiltration.

Defenders should audit every repository's `.github/workflows` directory for commits made by maintainers since October 7, looking specifically for new actions that reference external URLs or encode unexpected base64 payloads. Review the Mastodon-linked source (thehackernews.com article dated 2026-10-09) for the list of affected repositories and the names of the malicious workflow patterns that Socket identified. Rotate any secrets accessible to CI pipelines that have executed workflows in the last 72 hours, restrict workflow execution permissions to required scopes only, and enforce branch protection with required reviews for any `.github/workflows` changes.

Watch for an expanded victim list from Socket or GitHub security, and for any confirmation that the compromised maintainer accounts have been fully recovered or revoked. A second development that would change the assessment is the appearance of a CVE or GitHub advisory naming the malicious action patterns, which would confirm official tracking and likely trigger broader scanning by enterprise security tools.
