The Hacker News reports a supply-chain attack on GitHub Actions in which attackers compromised maintainer accounts, including the author of the Python game library pyxel, and pushed credential-stealing workflows into 34 projects. The malicious workflows ran inside the victims' CI pipelines, where they could harvest secrets automatically on the next build.

GitHub Actions workflows routinely hold repository tokens, cloud credentials, and publishing keys, which makes the CI layer a high-value target: one compromised account converts a project's own automation into an exfiltration tool. If stolen secrets enabled further package or container releases, downstream users inherit the compromise, which is the pattern that turned earlier Actions and npm incidents into multi-ecosystem events.

This is currently single-source reporting, so treat the project count as provisional until GitHub or the affected maintainers confirm scope. Watch for the full list of affected repositories, confirmation of which secrets were exposed, GitHub's response and any forced token revocations, and maintainers' rotation guidance. Teams running self-hosted or mirror setups of affected projects should audit their pinned workflows and rotate CI secrets.
