Double Counter, a Discord bot used for server verification and channel counters, was breached through a forgotten server hosted at OVH that was running an exposed Metabase instance. Reporting that surfaced on October 7 puts the confirmed exposure at roughly 275,000 email addresses paired with Discord usernames, while one outlet's coverage frames the potential blast radius at up to 2.8 million Discord users. The records also included user IDs, IP address data, and payment-customer details. No CVE, no named actor, and no vendor advisory is in evidence yet, which is itself a finding: the mechanism as described is an unauthenticated analytics dashboard left reachable on an abandoned host, not an exploited software flaw.

The pairing is what makes this worth attention over the other breach news of the day. A verification bot is a gatekeeper that sees who joins which server, so the combination of Discord username, email, IP address, and payment-customer ID converts an anonymous handle into a person with a network location and a billing relationship. That map is the durable asset for the attackers, and it is raw material for targeted phishing against the moderators and admins who run gaming communities. The two numbers also do not agree: 275,000 emails against a claimed 2.8 million users implies either a partial export or a user table far larger than the email set, so the real scope is not pinned down and nobody should quote a single figure as settled.

For defenders, the concrete actions track the failure mode. Anyone running Metabase should confirm no instance is internet-reachable, that authentication is enforced, and that the service is bound to localhost or a VPN path, then sweep cloud consoles, OVH included, for forgotten instances still billing and still listening; the event record describes exactly this kill chain, an exposed dashboard on a server nobody remembered. Operators of servers using Double Counter should assume member-join telemetry may be in the dump, treat any email tied to a moderation role as phish bait, and verify breach notices only through the bot's official channels before acting on lookalike security messages. No patch version applies here until the vendor publishes one; exposure removal and credential hygiene are the controls that exist today.

Two developments would change the assessment. A Double Counter incident notice that confirms whether the exposed Metabase instance was the sole entry point, and that resolves the 275,000 versus 2.8 million discrepancy, would settle scope and severity. Separately, if payment-customer records are confirmed to include transaction data tied to a processor integration, this moves from credential-and-IP leak toward financial fraud exposure, and once the dump circulates, secondary phishing against exposed addresses should be expected within days.
