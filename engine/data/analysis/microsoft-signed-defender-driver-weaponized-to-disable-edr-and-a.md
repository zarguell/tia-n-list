Check Point Research disclosed how Microsoft Defender's BTR.sys driver can be weaponized for kernel-level file and registry operations. BTR.sys is a legitimate Microsoft-signed remediation component embedded in MpEngine.dll as the BOOTTIMETOOL resource. Defender deploys it after reboots to delete locked files. The driver operates under a randomly generated name, installs as a temporary service, and uses an Alternate Data Stream called :changelist for configuration. Check Point reverse-engineered the proprietary transaction format and built a proof-of-concept demonstrating abuse before endpoint protections initialize.

Security researcher Jiri Vinopal published "BTR Reforged," a detailed analysis showing how the driver enables attacker-controlled file and registry operations from kernel mode. The technique does not rely on memory corruption or privilege escalation vulnerabilities. Instead, it leverages the driver's legitimate remediation architecture, which normally removes its own files and service entries after completing queued operations. The overlap with kernel-level malware loader techniques complicates incident response attribution.

The Rapuncel infostealer campaign represents a related but distinct abuse of Microsoft-signed drivers. LastPass Threat Intelligence identified Rapuncel terminating up to 145 AV and EDR processes using a Microsoft-attested kernel driver. The campaign steals browser credentials, cryptocurrency wallet data, chat tokens, and Windows credentials. Both incidents highlight the systemic risk of trusting signed kernel components that can be repurposed for offensive operations without triggering traditional vulnerability detections.
