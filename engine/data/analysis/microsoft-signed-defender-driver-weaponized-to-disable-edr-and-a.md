Check Point Research and security researcher Jiri Vinopal independently disclosed how Microsoft Defender's Boot-Time Removal driver (BTR.sys) can be weaponized to bypass EDR and antivirus products. BTR.sys is a legitimate Microsoft-signed driver embedded in MpEngine.dll as the BOOTTIMETOOL resource. It executes kernel-level file and registry operations before endpoint protections fully initialize during remediation after a reboot. The attack does not exploit a memory corruption or privilege escalation bug. Instead, the researcher reverse-engineered the undocumented transaction protocol and reproduced it, turning a trusted signed remediation component into a Living-off-the-Land driver capable of arbitrary file deletion and registry manipulation from kernel mode.

The technique is operationally significant because the driver carries a valid Microsoft signature and loads during boot before most security products initialize their hooks. An attacker who can trigger BTR.sys execution gains kernel-mode file and registry access at a point in the boot sequence where defenses are not yet active. This eliminates the need to bring a vulnerable third-party driver or exploit a kernel vulnerability. Both disclosures (Check Point's analysis and Vinopal's "BTR Reforged" study) describe the same underlying mechanism from independent research perspectives.

Microsoft has not yet issued guidance on hardening BTR.sys against misuse. Defenders should monitor for unexpected deployment of the BOOTTIMETOOL resource outside Defender remediation flows and for kernel-mode file operations targeting security product binaries or registry keys during early boot. The absence of a traditional CVE makes this difficult to patch via standard vulnerability management. This is a design-level issue in how the signed driver's protocol can be reproduced by anyone who has reverse-engineered it.
