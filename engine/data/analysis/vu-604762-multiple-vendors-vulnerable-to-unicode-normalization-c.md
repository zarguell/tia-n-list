CERT/CC published VU#604762 on November 16, 2026, covering a mismatch between APFS path resolution and the way several applications compare file paths. An alternative Unicode spelling or case-folded variant, such as ß versus ss, can slip past an application's file-write checks. A local attacker who can reach a path the process is allowed to write may overwrite files outside the intended exclusion, with outcomes ranging from data corruption and configuration hijacking to code execution.

The coordinated disclosures include CVE-2026-14978 in HashiCorp go-slug, where improper Unicode handling during path matching can bypass .terraformignore exclusions and cause sensitive files to be included in Terraform slug uploads, and CVE-2026-49401 in Denos, whose permission system compares requested paths against filesystem and execution restrictions. Multiple vendors assigned CVEs and issued patches. The affected class includes archive tools, packaging systems and runtimes, which puts backup tools, forensic workflows and CI/CD pipelines in scope.

GBHackers covered the finding on November 17 using the ß versus ss filename trick as the headline example. The reporting describes a local overwrite and exclusion-bypass condition, not an observed campaign, and it gives no victim count or exploited version list. Follow the CERT note and vendor advisories for affected releases, and watch whether telemetry shows real abuse of these Unicode variants against build or backup workflows.
