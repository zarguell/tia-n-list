GitLab patched CVE-2026-85706, a CVSS 10.0 path traversal in the repository commits API that lets an unauthenticated attacker read arbitrary files from self-managed servers, in CE and EE versions 19.3.2, 19.2.6, and 19.1.8. The flaw, found by researcher s3ntago through HackerOne, stems from improper path confinement and missing authentication enforcement. Exploitation needs no account, only a reachable instance with at least one public project. Because the body-upload helper processes the file.path parameter before authentication, an attacker can bypass GitLab Workhorse route handling with a single URL-encoded character in the commits route, such as %63ommits, and read files accessible to the GitLab service process, including logs, database.yml, and gitlab-secrets.json. Leaked secrets can yield authenticated access and potentially full instance compromise, per OffSec and Truesec analyses.

Escalation was fast. watchTowr observed in-the-wild probes one day after the September 10 patches, and internet-wide scanning was underway by roughly 06:00 UTC on September 11. CISA added the CVE to the KEV catalog based on evidence of active exploitation. Defenders can hunt for HTTP POST requests to /api/v4/projects/{id}/repository/commits/ URIs containing file.path parameters.

The companion fix, CVE-2026-87719, is Enterprise-only: an insecure deserialization flaw in the GraphQL subscription serializer letting authenticated Duo Chat users steal credentials and Advanced Search configuration. It is the second recent critical GitLab flaw to draw immediate exploitation, after the CVE-2026-19478 GraphQL code backup. GitLab runs on more than half of the Fortune 100, so unpatched self-managed instances are high-value. Watch for mass exploitation of the file-read primitive, credential leaks surfacing from stolen secrets files, and follow-on compromises chained through CI/CD tokens.
