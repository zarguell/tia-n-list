GitLab emergency patches addressed two critical vulnerabilities in self-managed installations. CVE-2026-85706, rated CVSS 10.0, sits in the repository commits API and allows unauthenticated attackers to read arbitrary files from the server due to improper path confinement and missing authentication. CVE-2026-87719, rated 9.9, affects only Enterprise Edition and lets authenticated Duo Chat users leak Advanced Search configurations and credentials via crafted GraphQL subscriptions.

Exploitation of CVE-2026-85706 began within hours of disclosure. Internet-wide scanning started around 06:00 UTC on September 11, 2026. CISA added the CVE to its Known Exploited Vulnerabilities catalog based on confirmed in-the-wild exploitation. watchTowr researchers noted the primary prerequisite is that the GitLab instance has at least one public project, making internet-facing self-managed installations particularly vulnerable.

Affected versions span GitLab 18.7 through 19.3.x (before the patch release). The flaw exposes CI/CD secrets, deployment credentials, tokens, source code metadata, and any file readable by the GitLab service account. With 19 sources covering this story across security outlets and developer platforms, the breadth of coverage reflects the severity. Self-managed GitLab operators should patch to 19.1.8, 19.2.x, or 19.3.x immediately and audit logs for anomalous file access.
