GitLab patched two high-severity vulnerabilities on September 11, one of them carrying the maximum CVSS score of 10.0. CVE-2026-85706 is a path traversal flaw in the repository commit interface that allows unauthenticated attackers to read any file on the server. It affects self-managed installations running versions 18.7 through 19.3 (before the patch). The second flaw, CVE-2026-87719, affects only Enterprise Edition and allows a logged-in user with Duo Chat access to extract Advanced Search configuration settings via a crafted request.

A security firm reported internet-wide scanning activity targeting CVE-2026-85706 within hours of the disclosure. The no-auth requirement and file read capability make this a prime target for mass exploitation. GitLab's hosted SaaS service is already patched, and Dedicated customers are not affected. Self-managed instance operators should upgrade immediately to the fixed releases in the 19.1.9, 19.2.4, and 19.3.1 lines.

The path traversal bug is particularly dangerous because it bypasses authentication entirely. An attacker can read configuration files, SSH keys, and database credentials from the server filesystem. Combined with the active scanning, this has the profile of an imminent mass-exploitation event. Any organization running self-managed GitLab should treat this as emergency patching.
