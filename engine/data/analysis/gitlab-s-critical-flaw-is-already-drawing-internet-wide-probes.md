GitLab released emergency patches for two high-severity vulnerabilities in its self-managed platform. CVE-2026-85706, a path traversal bug in the repository commit interface, carries a CVSS 10.0 score and allows an unauthenticated attacker to read arbitrary files on the server without credentials. It affects Community Edition and Enterprise Edition from version 18.7 through 19.1.8, plus the 19.2 and 19.3 lines before this week's patches. The second flaw, CVE-2026-87719, is Enterprise-only (CVSS 9.9) and allows a logged-in user with Duo Chat access to trigger a server-side request that leaks Advanced Search configuration settings. GitLab's hosted SaaS and Dedicated customers are not affected.

The situation escalated rapidly. CISA added CVE-2026-85706 to its Known Exploited Vulnerabilities catalog, and security firms including Suriq and CyberWorldOps reported active internet-wide scanning for the path traversal within hours of disclosure. The exploit requires no authentication, making internet-facing GitLab instances prime targets. Exposed files could include application configs, secrets, API credentials, deployment tokens, private keys, and environment variables, enabling follow-on attacks including GitLab account compromise, cloud-environment access, source-code theft, or lateral movement into connected CI/CD infrastructure.

Eleven independent outlets covered the story within 24 hours, signaling broad awareness across both the security community and threat actors. The CISA KEV listing means federal agencies face a remediation deadline, and the exploitability bar is effectively zero. Self-managed GitLab operators should patch to 19.1.8+ or the fixed 19.2/19.3 releases immediately and audit for signs of file-access anomalies in their commit API logs.
