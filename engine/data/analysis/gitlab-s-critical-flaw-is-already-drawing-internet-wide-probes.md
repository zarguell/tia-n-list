GitLab has released emergency patches for two critical vulnerabilities in its self-managed platform, both affecting Community Edition and Enterprise Edition. CVE-2026-85706, rated CVSS 10.0, is a path traversal flaw in the repository commits API that allows unauthenticated attackers to read arbitrary files from a vulnerable server. The second flaw, CVE-2026-87719, rated 9.9, affects only the Enterprise Edition and is linked to GitLab Duo Chat and the Advanced Search feature, enabling an authenticated user to leak server settings. GitLab patched these in versions 19.3.2, 19.2.6, and 19.1.8, with a three-day patch window confirmed in event narratives. CISA added CVE-2026-85706 to its Known Exploited Vulnerabilities catalog after confirming active exploitation in attacks.

For analysis, the CVSS 10.0 path traversal in CVE-2026-85706 is the critical case. The flaw is pre-authentication and affects all GitLab installations from 18.7 to 19.1.8, 19.2, and 19.3 before the patches. An attacker could read arbitrary files, including configuration files, secrets, API credentials, and environment variables. The CISA KEV listing confirms active exploitation, and event narratives report internet-wide scanning. CVE-2026-87719 is a separate CVSS 9.9 issue affecting only the enterprise edition, with a narrower attack surface. All self-managed GitLab instances should patch immediately. GitLab.com and Dedicated customers are not affected. The story remains active and evolving, with the most recent event (masto:117264654802531371) posted on Sept. 13, indicating continued monitoring.
