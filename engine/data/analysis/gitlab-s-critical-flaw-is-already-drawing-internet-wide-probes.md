GitLab CE/EE vulnerability CVE-2026-85706, rated CVSS 10.0, allows unauthenticated arbitrary file read through the repository commits API via improper path confinement. The flaw has drawn internet-wide scanning activity since disclosure, with multiple research groups and threat actors probing for exposed GitLab instances. A second CVE, CVE-2026-87719, has also been associated with the broader GitLab security advisory. The combination of a perfect CVSS score and no authentication requirement makes this one of the most dangerous GitLab flaws in recent memory.

The vulnerability enables attackers to read arbitrary files from the GitLab server without credentials by crafting malicious requests to the commits API endpoint. This can expose configuration files, secrets, SSH keys, and database credentials stored on the GitLab host. With 35 events tracked across sources including BleepingComputer, Rapid7, NVD, and multiple security research outlets, the story has significant breadth and velocity. The high volume of internet-wide probes suggests that exploitation tooling is already circulating.

Organizations running GitLab CE or EE should patch immediately. The unauthenticated nature of this flaw means that any exposed GitLab instance is a target. GitLab instances behind VPN or network restrictions have reduced exposure, but internal network attackers could still exploit the vulnerability. Review access logs for anomalous commits API activity and check for unauthorized file access. This flaw will likely be added to CISA KEV if it is not already there, given the confirmed scanning activity.
