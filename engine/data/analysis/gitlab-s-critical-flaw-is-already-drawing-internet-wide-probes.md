GitLab released emergency patches for two high-severity vulnerabilities. The critical one, CVE-2026-85706, scored CVSS 10.0, sits in the repository commits API and allows unauthenticated attackers to read arbitrary files on the server in a single HTTP request. It affects GitLab CE/EE from version 18.7 through 19.1.7, 19.2.x before 19.2.6, and 19.3.x before 19.3.2. The second flaw, CVE-2026-87719, is a CVSS 9.9 issue in GitLab EE's Duo Chat feature that lets an authenticated user leak Advanced Search configuration and credentials via a crafted GraphQL subscription.

WatchTowr reported internet-wide scanning for CVE-2026-85706 within a day of the patch release. CISA subsequently confirmed active exploitation and added the CVE to the Known Exploited Vulnerabilities catalog. GitLab is used by over 50 percent of Fortune 100 companies and has more than 30 million registered users, making unpatched instances a high-value target for both opportunistic and targeted attackers.

The arbitrary file read in CVE-2026-85706 is especially dangerous because it requires no authentication and no special conditions beyond reaching the commits API endpoint. Attackers can extract secrets, credentials, and source code from self-managed installations in a single request. GitLab's hosted SaaS and single-tenant Dedicated offerings are already patched. Self-managed operators should upgrade immediately and hunt for HTTP POST requests to /api/v4/projects/{id}/repository/commits/ containing file.path parameters in their logs.
