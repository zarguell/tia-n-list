GitLab released emergency patches for two high-severity vulnerabilities in its self-managed platform. The critical flaw, CVE-2026-85706, is a path traversal bug in the repository commit interface carrying a CVSS 10.0 score. An unauthenticated attacker can read arbitrary files on the server without credentials. It affects Community Edition and Enterprise Edition from version 18.7 through 19.1.8, plus the 19.2 and 19.3 lines before this week's patches. The second flaw, CVE-2026-87719, is Enterprise-only (CVSS 9.9) and allows a logged-in user with Duo Chat access to trigger a server-side request that leaks Advanced Search configuration settings. Both require self-managed upgrades; GitLab's hosted SaaS and Dedicated customers are not affected.

The situation escalated quickly. Security firm Suriq reported active internet-wide scanning for the path traversal within hours of disclosure, and CISA added CVE-2026-85706 to its Known Exploited Vulnerabilities catalog. The exploit requires no authentication, making internet-facing GitLab instances prime targets. Nine distinct outlets covered the story within 24 hours, signaling broad awareness across both the security community and threat actors.

Watch for mass exploitation attempts against exposed GitLab instances in the coming days. Organizations running self-managed GitLab should prioritize patching to 19.1.8+ or the fixed 19.2/19.3 releases immediately. The CISA KEV listing means federal agencies face a remediation deadline, and the exploitability bar is effectively zero.
