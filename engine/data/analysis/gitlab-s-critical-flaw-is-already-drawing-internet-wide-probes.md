GitLab shipped emergency patches for CVE-2026-85706, a CVSS 10.0 path traversal in the repository commits API of self-managed Community and Enterprise Editions. Missing authentication enforcement plus improper path confinement let an unauthenticated attacker read any file on the server with a single HTTP request, including configuration files, secrets, API credentials, deployment tokens, and private keys. Affected lines are 18.7 before 19.1.8, 19.2 before 19.2.6, and 19.3 before 19.3.2; the same patch release fixed CVE-2026-87719, a CVSS 9.9 Enterprise Edition flaw where an authenticated Duo Chat user can leak Advanced Search settings and credentials through a crafted request. GitLab's hosted platform was already running fixed code; self-managed installs were told to upgrade immediately.

Exploitation started fast. watchTowr observed in-the-wild probes one day after disclosure, and CISA later added CVE-2026-85706 to the Known Exploited Vulnerabilities catalog. Censys counts more than 86,000 GitLab hosts exposed to the internet, and GitLab claims over 50 percent of Fortune 100 companies and 30 million registered users as customers, so the victim pool is large. watchTowr framed it as the second critical GitLab flaw in recent weeks, after the GraphQL code injection CVE-2026-19478 was exploited almost immediately. OffSec has since published an exploitation analysis of the file read.

Defenders should prioritize patching self-managed instances and hunt for exploitation: watchTowr recommends looking for HTTP POST requests to /api/v4/projects/{id}/repository/commits/ URIs carrying file.path parameters. Stolen secrets and tokens from a GitLab server can lead to account compromise, source code theft, cloud environment access, and lateral movement into CI/CD infrastructure. Watch for confirmed mass exploitation beyond probing, and for whether the OffSec disclosure accelerates weaponization.
