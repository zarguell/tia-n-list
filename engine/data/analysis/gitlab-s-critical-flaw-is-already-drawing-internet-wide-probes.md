GitLab released emergency patches for two high-severity vulnerabilities in its self-managed platform. CVE-2026-85706 is a CVSS 10.0 path traversal in the repository commits interface that lets unauthenticated attackers read arbitrary files from the server, including config files, secrets, API credentials, and private keys. It affects Community Edition and Enterprise Edition versions 18.7 through 19.1.8, and the 19.2 and 19.3 lines before the patches. CVE-2026-87719, rated 9.9, is an Enterprise-only Server-Side Request Forgery via Duo Chat that could expose Advanced Search settings. CISA added CVE-2026-85706 to the Known Exploited Vulnerabilities catalog after confirming active exploitation.

Security firms including the one that first reported the flaws are seeing internet-wide scanning and probing activity already. The path traversal enables follow-on attacks: account compromise, cloud environment access, source code theft, and lateral movement into CI/CD infrastructure. GitLab's own hosted service and single-tenant Dedicated customers are not affected. Self-managed installations need to upgrade immediately to the patched versions.

This is one of the more dangerous GitLab flaws in recent memory. The combination of no authentication required, file read capability across the entire server, and confirmed in-the-wild exploitation makes this a patch-now situation. Organizations running self-managed GitLab should check for indicators of compromise and rotate any credentials or tokens that may have been exposed through the vulnerable commits API.
