GitLab released emergency patches for two high-severity vulnerabilities, with CVE-2026-85706 carrying the maximum CVSS score of 10.0. The flaw exists in the commits API interface, where missing authentication and insufficient path confinement allow unauthenticated attackers to read arbitrary files on the server. Every GitLab CE/EE release from 18.7 through 19.1.8, plus affected 19.2 and 19.3 versions, is vulnerable. A second flaw, CVE-2026-87719, affects only Enterprise Edition and involves Duo Chat access being abused to exfiltrate Advanced Search configuration.

CISA confirmed active exploitation within days of the patch release. Security researchers observed internet-wide scanning activity targeting exposed GitLab instances, and multiple outlets including BleepingComputer, CyberScoop, and The Hacker News covered the vulnerability. The attack requires no credentials, making every unpatched self-managed installation a target.

GitLab's hosted service and single-tenant Dedicated offering are already patched. Self-managed installations must upgrade immediately. If patching cannot happen quickly, restrict access to the commits API endpoint and ensure the GitLab instance is not exposed to the public internet. The combination of unauthenticated access, arbitrary file read, and confirmed exploitation makes this one of the highest-severity GitLab vulnerabilities in recent memory.
