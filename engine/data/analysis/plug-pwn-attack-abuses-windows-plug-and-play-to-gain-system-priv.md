Researchers Alejandro Hernando (0xedh) and Borja Martinez presented "Plug and Pwn" at DEF CON 34, a family of attack chains that turns Windows Plug and Play driver installation into a SYSTEM-level code execution primitive. The key insight is that PnP is not merely enumerating USB devices. Windows automatically resolves a connected device's hardware IDs, downloads a matching signed driver package, and runs its installation components as NT AUTHORITY\SYSTEM. An attacker who can emulate a targeted vendor and product ID gets trusted vendor code installed at the highest privilege, with no administrator rights, no user interaction, and in some scenarios no physical USB hardware at all.

The physical proof of concept runs a Linux attack machine with FaceDancer hardware against a fully patched Windows 11 host with no active user session. It first emulates a Sierra Wireless device, which installs a SYSTEM service exposing a named pipe writable by Everyone, through which the attacker can redirect the victim's DNS settings. A second stage emulates a Sony FeliCa device whose signed co-installer fetches configuration files over unencrypted HTTP, extending the chain further. Later coverage confirms the attack surface reaches any vendor package Windows will auto-install, with some demonstrated chains requiring no user interaction at all.

What matters here is that the abuse surface is the driver delivery ecosystem, not a single vendor's bug. Windows trusts signed driver packages from Windows Update, and that trust is the delivery mechanism. Defenders should treat signed-but-insecure driver packages as a genuine attack vector, review which vendor drivers are allowed to install on managed endpoints, and watch for unexpected device emulation during incident response. The research also reinforces that "fully patched" does not protect against abuses of trusted installation paths.
