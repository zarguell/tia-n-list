1Password disclosed on November 25 that an attacker compromised an employee's corporate GitHub account and used it to push malicious code into the company's backend services. Those services then downloaded customer account records. Investigation began on November 19 after the company detected signs that the account had been taken over. The intruder also read private source repositories, copied internal source code, and reached the CI/CD environment, where infrastructure credentials may have been exposed.

The stolen customer data included tokens embedded in links that 1Password had emailed for account provisioning invitations and account recovery. The company said those tokens cannot be used alone: completing either flow still requires SSO authentication or a six-digit verification code sent to the registered email address. It said only a small number of users were affected and notified individually, and that customer password vaults and the keys protecting them were not touched. The disclosure says verification codes were being strengthened from six digits as a precaution against brute-force attempts.

The significant detail is the path from a single developer identity into the software delivery pipeline and then into production data retrieval. A compromised GitHub account was enough to reach private code, build systems, and customer records, with emailed invitation and recovery links adding a second credential layer that held. Watch for follow-up on which internal credentials were exposed, how the GitHub account was taken over, and whether any of the strengthened verification steps change customer recovery flows.
