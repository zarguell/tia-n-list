1Password began investigating on November 19, 2026 after signs that an employee's corporate GitHub account had been compromised. The attacker used that account to read private repositories, push malicious code into backend services that downloaded subsets of customer records, and access the CI/CD system. Stolen fields include names, email addresses, account and user identifiers, creation and last sign-in times, public keys, SRP parameters and tokens from invitation, provisioning and recovery emails.

The company says vault contents and the keys protecting them were not accessed, and that no account takeover has been observed. A community post said the authentication data included SRP verifiers derived from passwords and Secret Keys. Tokens from emailed links cannot be used alone because completion requires SSO or a code sent to the registered email. The Verge reported that 1Password lengthened those codes from six digits to 10 alphanumeric characters and added detection for similar attacks.

1Password disabled the account, revoked the stolen token, removed attacker-created access and rotated potentially exposed internal credentials, and it engaged outside experts. SecurityWeek and BleepingComputer report that internal source code and possible infrastructure credentials were also exposed. Watch for targeted phishing that references invitations or recovery, and for any clarification on the number of affected customers or the CI/CD credential scope.
