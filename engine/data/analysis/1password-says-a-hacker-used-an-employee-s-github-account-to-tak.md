1Password disclosed on November 25 that an attacker used an employee's corporate GitHub account to read private source code, push malicious code into backend services and download administrative customer records. The investigation began on November 19. The intruder also accessed the CI/CD environment, potentially exposing internal infrastructure credentials, and copied company source code.

The affected customer subset included names, email addresses, account and user identifiers, creation and last sign-in times, public keys, Secure Remote Password parameters, and tokens in invitation, provisioning and recovery emails. 1Password said vault contents and the keys protecting them were not accessed. The workflow tokens could not be used alone: completing an invitation or recovery required SSO or an emailed verification code. The Verge reported that those codes were lengthened from six digits to 10 alphanumeric characters. A small number of users were notified, but no total victim count was disclosed.

The incident exposed development material and valid account-workflow tokens while creating a verified list of password-manager users for targeted phishing. The intact vault boundary limits direct credential exposure, but it does not remove the risk from source-code knowledge, CI/CD access or convincing follow-on messages. Watch for further detail on infrastructure credential exposure, downstream token use and additional notifications. Unexpected invitation or recovery mail warrants verification even though 1Password said no account action was required.
