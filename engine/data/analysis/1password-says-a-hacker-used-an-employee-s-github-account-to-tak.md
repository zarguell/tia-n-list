1Password said it began investigating on November 19, 2026 after an attacker gained access to an employee's corporate GitHub account. The attacker read private repositories, pushed malicious code into backend services and used that code to download administrative records for a subset of customers. The records included names, email addresses, account and user identifiers, creation and last sign-in times, public keys, SRP parameters, and tokens in invitation, provisioning and recovery emails. The company described the affected group as small and said those users were notified, but did not disclose a total.

The company said customer vault contents and the keys protecting them were not accessed, and it reported no evidence of account takeover. The stolen email-link tokens could not be used alone because completing an invitation or recovery required SSO authentication or a six-digit code sent to the registered email address. 1Password lengthened those codes to 10 alphanumeric characters and added detection for similar attacks. It also warned customers about phishing that references invitations or account recovery.

The attacker copied internal source code and accessed the CI/CD system, potentially exposing infrastructure credentials. 1Password said it disabled the compromised account, revoked the stolen token, removed attacker-created access, rotated potentially exposed internal credentials and engaged independent experts. The immediate risk is targeted phishing against a verified set of password-manager users. The longer-term question is whether any CI/CD secret was used, so watch for that finding and for a final affected-customer count.
