Plex disclosed multiple undisclosed security issues affecting Plex Media Server 1.43.2 and earlier and Plex Desktop below 1.115.0, urging owners to update to Plex Media Server 1.43.3 (released May 19) and Plex Desktop 1.115.0 (released August 13). The company has not published technical details, severity, or exploitation conditions, and said CVE identifiers were requested but not yet assigned. The vendor advisory appeared on the Plex forum on September 1, 2026, and QNAP separately told NAS owners to install Plex Media Server 1.43.3.10861 or later as Plex2Shell attacks spread, even though Plex itself had not confirmed exploitation of the newly patched flaws at that time.

The danger is the information asymmetry rather than the version gap alone. Defenders must patch blind while attackers can reverse-engineer the difference between 1.43.2 and 1.43.3, and exposed instances hand over account authentication, media library access, and administrative functions. This notice deserves more attention than a routine patch bulletin because it targets a ubiquitous media server commonly run on home servers, NAS appliances, Linux machines, and Docker containers, and QNAP tied the same 1.43 baseline to active attack activity against NAS-hosted servers. Waiting for CVE publication before acting leaves internet-facing systems exposed to both reverse-engineered exploits and the follow-on Plex2Shell campaign.

Administrators should update Plex Media Server to 1.43.3 or later and Plex Desktop to 1.115.0 or later, verifying that automatic updates actually completed. NAS owners should install 1.43.3.10861 or later manually where the vendor package manager lags, since QNAP's notice sets that build as the floor. For servers that do not need remote access, disable it under Settings, Remote Access, and avoid forwarding port 32400 directly unless required. If remote access is needed, restrict it at the firewall and confirm the installed build string rather than relying on the 1.43.3 label alone.

The assessment changes if Plex publishes CVE assignments and technical detail, confirms in-the-wild exploitation of the September flaws, or if NAS package managers catch up and close the remaining version gap. A public proof of concept or a surge in scanning against 1.43.2 and earlier would also raise urgency, as would evidence that the 1.43.3 baseline is insufficient without the 1.43.3.10861 build. Until then, treat any internet-facing Plex server older than the fixed baseline as unpatched.
