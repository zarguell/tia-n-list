A newly disclosed Docker vulnerability, tracked as CVE-2026-17106, allows a malicious container to break out of the destination specified by docker cp and overwrite files on the host running the Docker CLI. The flaw does not automatically grant unrestricted host control. It converts a copy-out operation into a host-side write primitive, operating with the permissions of the user or automation process that launched it.

Imperva researchers identified the issue in Docker's archive pipeline, and Docker lists it as a destination-escape flaw in the docker container cp command. The copy path is indirect: the daemon walks the requested container path during the copy, and the flaw lets a malicious container redirect that walk outside the intended destination. Anyone running docker cp against untrusted containers, especially in CI pipelines, should treat this as a container escape risk and update Docker promptly.
