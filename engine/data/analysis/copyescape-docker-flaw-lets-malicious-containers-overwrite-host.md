CopyEscape, tracked as CVE-2026-17106, is a destination-escape flaw in the docker cp copy-out path, identified by Imperva researchers and listed by Docker as affecting the docker container cp command. During a container-to-host copy the daemon walks the requested container path, builds a tar archive, and hands it to the CLI on the host for extraction. A process inside a malicious container can race that walk: Ron Masas showed Docker may first record a path as a directory and then see it as a symbolic link while writing archive metadata, producing a tar stream that holds a symlink followed by entries resolving outside the destination.

The result is a host-side file write primitive, not automatic full host control. It runs with the permissions of the user or automation that executed docker cp, and the reporting notes this can mean code execution as the local user and, on Linux systems where copy operations run elevated, as root.

No in-the-wild exploitation appears in the coverage. The practical exposure sits in CI systems, backup jobs, and admin workflows that copy data out of containers they do not fully trust. Watch for a fixed Docker release, public PoC code, and guidance on restricting docker cp against untrusted images until then.
