CERT-In's CSIRT-Fin team has named the campaign draining Indian financial firms CRAFTY FALCON and describes it as an active, ongoing operation against NBFCs, digital lenders, fintechs, payment aggregators, payment service providers and crypto exchanges. The advisory updates an earlier one from October 9, 2026 and carries the reference CIAD-2026-0058. The defining detail is that entities which received the earlier restricted advisory and remediated were deliberately hit again, some after incomplete cleanup, with attacks timed for holidays and weekends.

The monetization path abuses the victims' own payment and disbursement APIs, calling them to move money out rather than relying on card data or customer credentials. The weaknesses the actor exploits are unglamorous and familiar: hardcoded API tokens, staging servers sharing credentials with production, and IP allow-lists that trust shared third-party fetchers. What the AI-assisted label changes is the interval between discovery and cash-out, which now runs shorter than most remediation cycles, so the practical exposure is time-to-fix rather than any novel technique.

For Indian fintechs and lenders, the actionable items are concrete: rotate any API token found in code or configuration, separate staging credentials from production, and stop allowing shared third-party fetchers to satisfy IP allow-lists on payment endpoints. CERT-In has also confirmed that firms which remediated only the specific weakness named in the October advisory were re-compromised, so a point fix is not a fix.

Watch for the next CERT-In advisory, for named payment aggregators or PSPs appearing as victims, and for whether the actor's tooling or infrastructure gets attributed to a known group. If a holiday-weekend pattern holds, the next window is the most likely time for a fresh wave.
