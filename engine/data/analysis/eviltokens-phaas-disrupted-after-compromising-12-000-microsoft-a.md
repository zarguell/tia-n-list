Microsoft's Digital Crimes Unit and industry partners disrupted EvilTokens on a federal court order executed Sept 15, 2026, seizing the 50 websites the service ran on and disabling more than 175 supporting domains. Microsoft tracks the operator as Storm-2992 and links the platform, active since February 2026 and sold to roughly 1,000 criminal customers, to more than 12,000 compromised Microsoft 365 inboxes across over 10,000 organizations. The mechanism is OAuth 2.0 device code phishing: the victim types an attacker-generated code into Microsoft's genuine devicelogin page and completes real MFA, authorizing the attacker's session, and the kit times code generation to the victim's page load because codes expire within 15 minutes. Captured refresh tokens roll for 90 days and the backend converts them into a Primary Refresh Token for silent single sign-on across the tenant's apps.

The takedown closed a seven-month operation that public reporting had already mapped in full: Sekoia identified the service on Telegram on March 3 and published its analysis March 30, Unit 42 recorded the earliest observed page on Feb 18, and Huntress measured a 16-day wave from March 2 hitting 344 organizations in five countries, with device-code indicators in 87.4% of cases. MFA never failed and no password was stolen, which is why the lures passed Cisco, Trend Micro and Mimecast with clean URLs; perimeter telemetry had nothing to catch. The differentiator was automation after capture: a pipeline that pulled inbox rules, contacts and calendars over Graph, ingested up to 5,000 emails through Groq-hosted llama-3.1-8b-instant, and drafted thread-hijacking BEC replies with llama-3.3-70b-versatile in minutes. The implication the event list does not spell out: seizing 50 sites evicts no one, because every one of those 12,000 mailboxes was taken with tokens that survive password resets and keep renewing for 90 days, so the victim pool stays exposed for months after the press release.

Treat this as an identity incident, not a phishing one. Block the device code flow via Conditional Access wherever no printer, Teams Room or conferencing hardware needs it, and for any user phished since February revoke sessions and refresh tokens rather than resetting passwords alone. Hunt in Entra sign-in logs for AuthenticationProtocol == "deviceCode", alert on first-time device code use per user (Paul Newton's hunt-2025-043 pattern: 30-day lookback, successful sign-ins only), on new device registrations, and on covert inbox rules; Microsoft's Sept 22 threat intelligence post ships matching Defender XDR detections and hunting queries. Sweep mail gateway and proxy telemetry for Sekoia's markers: the X-Antibot-Token HTTP header, requests to /api/device/start, and workers.dev hostnames shaped like docusign-xxx or onedrive-xxx with a "-s-account" suffix; the YARA rule phishing_eviltokens_phishing_page catches the pages themselves, and phishing-resistant FIDO2 or passkeys closes the technique.

Two developments would change this assessment. First, residual infrastructure: Sekoia counted over 1,000 EvilTokens domains while Microsoft disabled about 175, and Talos has already documented an affiliate panel, ARToken, exposing 80+ API endpoints with shared contracts, so watch for kit rebrands, the operator's promised Gmail and Okta phishing pages, and fresh Railway or Cloudflare Workers deployments. Second, dispersal: roughly 1,000 affiliates trained on automated BEC did not stop existing on Sept 15, and their migration into other PhaaS ecosystems would turn a successful disruption into a diffusion problem.
