Microsoft Threat Intelligence investigated two human-operated intrusions that began with help-desk impersonation over Microsoft Teams, where attackers socially engineered users into granting remote access via Quick Assist. Once connected, they staged portable Python, Bun, or Java runtimes, performed host and network discovery, and assessed Active Directory Certificate Services for certificate-based authentication paths. In Case 1, the attacker abused an ESC1-vulnerable certificate template to obtain authentication certificates for privileged accounts and performed DCSync. In Case 2, the attacker used PetitPotam to relay a domain controller's NTLM authentication to AD CS Web Enrollment (ESC8) and obtained a certificate for the domain controller identity. Microsoft published the investigation on October 30, 2026.

The two cases show that the same social-engineering entry point can lead to different certificate-layer outcomes depending on CA configuration. Defenders should review certificate templates for the ESC1 configuration (enrollee-supplied subject, client-authentication EKU, no manager approval) and disable NTLM on AD CS Web Enrollment to block ESC8 relay, alongside monitoring for portable runtime staging and Quick Assist sessions initiated by unknown callers.
