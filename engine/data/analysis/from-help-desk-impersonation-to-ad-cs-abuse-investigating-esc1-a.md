Microsoft Threat Intelligence documented two human-operated intrusions in which attackers impersonated IT help desk staff over Microsoft Teams calls and messages, socially engineering users into granting remote access through Quick Assist. Once on a workstation, the operators staged portable Python, Bun, or Java runtimes, ran host and network discovery, and assessed Active Directory Certificate Services for certificate-based authentication paths. The intrusions did not rely on a Teams vulnerability; they exploited approved support workflows.

The two cases diverged at the certificate layer. In Case 1, the attacker abused an ESC1-vulnerable certificate template to obtain authentication certificates for privileged accounts and performed DCSync. In Case 2, the attacker used PetitPotam to coerce a Windows server to authenticate to an attacker-controlled system, then relayed the domain controller's NTLM authentication to AD CS Web Enrollment (ESC8) to obtain a certificate for the domain controller identity. The contrasting outcomes show how the same initial access can lead to different privilege-escalation paths depending on AD CS configuration.

Defenders should treat unsolicited help desk contact followed by Quick Assist sessions as a high-risk pattern, and audit AD CS for ESC1-vulnerable templates and ESC8 web enrollment endpoints. Monitoring for portable runtime staging, DCSync activity, and NTLM relay to certificate enrollment services can catch the later stages before domain compromise.
