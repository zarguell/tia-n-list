Google shipped Chrome 151 to the Stable channel on August 20, patching seven security flaws. The critical fix, CVE-2026-76017, is a use-after-free bug in Chromoting (the remote desktop component) reported by Google's own team on June 11. A successful exploit could let an attacker hijack a remote-access session or execute code on the host system. The remaining six are all high severity: privilege elevation in Import (CVE-2026-76018), incorrect authorization in Workers (CVE-2026-76019), a race condition in V8 (CVE-2026-76020), use-after-free in DOM (CVE-2026-76021), a buffer overflow in Networking (CVE-2026-76022), and improper resource control in Linux ToolKit Themings (CVE-2026-76023).

The Chromoting use-after-free is the most operationally significant. Remote desktop components handle active session state, so memory corruption there maps directly to session hijack or code execution on the machine running Chrome. The V8 race condition (CVE-2026-76020) is worth watching too: V8 bugs historically chain well with renderer exploits for sandbox escape. No reports of in-the-wild exploitation for any of these seven, and the fixes came from internal audits rather than external reports.

Chrome updates roll out automatically. Organizations with managed deployments should verify the version bump to 151.0.7922.173/174 has reached their fleet. The seven CVEs span browser internals from the JS engine to networking, so this is a broad patch cycle rather than a single-component fix.
