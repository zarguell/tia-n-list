Attackers are weaponizing Windows Volume Shadow Copy Service for both credential theft and ransomware preparation. VSS creates point-in-time file snapshots that administrators rely on for recovery, but adversaries with sufficient access can abuse the same mechanism to extract Active Directory credentials and delete recovery points.

The attack chain targets NTDS.dit, the Active Directory database file containing hashed credentials for all domain accounts. By creating a shadow copy and copying NTDS.dit from it, attackers avoid directly accessing a live database. Combined with the SYSTEM registry hives also recoverable from shadow copies, this enables offline credential cracking. Threat actors also delete shadow copies before ransomware deployment using built-in tools like vssadmin or WMI, mapping to MITRE ATT&CK technique T1490 (Inhibit System Recovery).

This dual-purpose abuse is particularly dangerous because shadow copy operations generate minimal noise in standard security monitoring. Organizations should audit VSS usage, restrict who can create and delete shadow copies, and consider monitoring for unusual vssadmin or wmic commands. The technique is not new but is seeing renewed adoption as ransomware groups refine pre-encryption routines.
