FastUnlock is an unpatched Windows 11 lock-screen bypass published by Abdelhamid Naceri, who uses the handles MSNightmare and Nightmare Eclipse, on 19 November 2026. The trigger is Narrator's new interface running in the context of the lock-screen account WsiAccount: from the "I forgot my PIN" flow, Win+U and Caps Lock navigation reach a hidden Narrator window, then Settings and File Explorer, where a binary on an inserted USB drive can be run without entering the user's credentials. The researcher reproduced it on Windows 11 26H2 with the November patch installed and reports code execution as WsiAccount, a limited non-administrator account, with physical access and at least one Microsoft-linked account required; there is no CVE and no Microsoft patch in the reporting.

The security argument is narrower than the "BitLocker bypass" label, and that is why this story matters more than its 7.0 score alone suggests. With TPM-only BitLocker the drive is already unlocked before Windows shows the sign-in prompt, so WsiAccount code execution does not break disk encryption; Will Dormann places it in the physical-access class described by CERT/CC VU#789985, and the technique echoes ZDI-21-1053 (CVE-2021-26431), Naceri's 2021 lock-screen bypass. What is new is the reliability claim: the author says it worked on every machine tested, took about five minutes from discovery to a fully encrypted machine, and needs only keystrokes and a USB stick. The exposure is therefore every unattended laptop or kiosk with a Microsoft-linked account, not a remote fleet; three outlets carried it within a day, but the practical threat is opportunistic access to a single device rather than mass exploitation.

There is no patch version to deploy yet, so the immediate controls are physical and local. ThreatLocker reproduced the path and says a BitLocker preboot PIN mitigates it on powered-off or hibernated machines because the drive must unlock before Windows starts; require that PIN on portable devices and deny unattended physical access to signed-in but locked workstations. Restrict removable storage and block execution from USB mounts, and use application control to stop unknown binaries launched from Explorer under WsiAccount. For hunting, focus on process creation tied to the lock-screen sequence: SystemSettings.exe and Explorer spawned in the WsiAccount context, the Narrator toggle through Win+U, and Explorer autoplay of a newly attached drive. Absent vendor guidance, those are the observable fields to collect; no Microsoft log channel or named IoC is published with this disclosure.

The assessment changes if Microsoft assigns a CVE, ships a fix in a Patch Tuesday release, or states that supported Windows versions besides 11 26H2 are affected, since the researcher did not test Windows 10. It also changes if telemetry shows real-world use beyond the proof of concept, or if the USB execution step is independently demonstrated rather than inferred; ThreatLocker confirmed access to WsiAccount, while the public demo stops short of showing a payload run.
