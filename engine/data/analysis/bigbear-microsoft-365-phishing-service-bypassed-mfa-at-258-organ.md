CloudSEK researchers gained access to the control panel of BigBear 2.0, a phishing-as-a-service framework, and documented its operations against Microsoft 365 tenants. The service deployed 42 VPS nodes running an Evilginx2-based adversary-in-the-middle proxy that sits between the victim and Microsoft's legitimate login infrastructure. When a target authenticates, BigBear captures the password, MFA token, and session cookies in transit, then replays them through an API to hijack the authenticated session. The configuration, internally labeled "offy," handles the full AiTM flow without requiring the victim to install any software.

CloudSEK's audit of the panel showed BigBear compromised credentials at 258 organizations and collected over 5,000 Microsoft 365 accounts. Because the framework steals session tokens post-authentication, traditional MFA provides no defense against it. A hijacked Microsoft 365 session can expose Exchange Online email, Teams messages, SharePoint files, and any application reachable through Entra ID single sign-on. Organizations should enforce continuous access evaluation, session token binding where available, and conditional access policies that restrict token replay from unfamiliar devices or locations. Phishing-resistant MFA such as FIDO2 hardware keys remains the most effective countermeasure against AiTM proxies, since the cryptographic challenge never traverses the attacker's relay.
