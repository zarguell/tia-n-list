Calif researcher Andrew Griffiths published the "Big Fish" research on October 16, 2026, disclosing an OpenBSD kernel exploitation chain that combines a ~37-year-old shared-memory integer overflow with a separate out-of-bounds write to achieve local root. The oldest bug traces back decades in the kernel's shared memory accounting. Griffiths released public proof-of-concept code demonstrating exploitation with multiple kernel protections enabled. The chain affects OpenBSD 7.9 and requires local access, but the PoC confirms reliable root escalation. No CVE has been assigned yet. Organizations running OpenBSD should apply patches as vendors distribute fixes and audit kernel configurations that expose shared memory interfaces.

This is a high-quality local privilege escalation with working public exploit code, making it a practical risk for multi-user OpenBSD servers. The age of the underlying flaw highlights long-lived kernel debt rather than a new supply-chain or authentication vulnerability. There is no evidence of in-the-wild exploitation, but the availability of the PoC raises the likelihood of targeted use. Watch for vendor advisories assigning a CVE and for patch timelines from the OpenBSD project.
