The vulnerability is CVE-2026-39987, a pre-authentication remote code execution flaw in the reactive Python notebook platform marimo. Affected versions are 0.20.4 and earlier; version 0.23.0 patches it by adding the missing authentication validation to the /terminal/ws WebSocket endpoint. The endpoint skips validate_auth() entirely, granting any unauthenticated remote client an interactive PTY shell. During the nine-hour intrusion observed by Sysdig Threat Research Team, the attacker opened a WebSocket session at 18:57:22 UTC, recovered AWS credentials from the notebook environment and its Redis-backed application data by 18:57:26, wrote an SSH private key retrieved from AWS Secrets Manager to /tmp/bastion_key, and authenticated to an internet-facing bastion host at 18:57:30. That eight-second pivot from initial access to bastion entry shows the attack is fully scripted. The operator relied on hand-built automation rather than LLM-generated tooling, dropped base64-encoded Python scripts into /tmp/, and iteratively refined boto3 and SSH routines over the intrusion.

A successful compromise means full cloud pivot, not just notebook access. The attacker does not stop at the marimo process; they harvest AWS keys, call Secrets Manager, retrieve SSH keys, and establish persistent access to bastion hosts. Any organization running marimo instances with cloud integrations, environment files, or database connections is exposed regardless of whether the instance is public-facing by design, because the WebSocket endpoint requires zero credentials. This story matters more than generic notebook RCE reports because the timeline is compressed to seconds rather than hours, the target is a niche data-science tool that security teams often miss in asset inventories, and the attacker behavior shows deliberate cloud-pivot planning rather than opportunistic scanning. The GitHub advisory GHSA-2679-6mx9-h9xc was published April 8, 2026, and exploitation began 9 hours and 41 minutes later, with no public proof-of-concept available at the time of first observed activity.

Upgrade immediately to marimo 0.23.0 or restrict the /terminal/ws endpoint at the network layer. If the endpoint cannot be disabled, block inbound WebSocket traffic to it at the reverse proxy or firewall. Rotate all AWS credentials, SSH private keys, and application secrets stored in .env files or environment variables on any instance that was reachable before patching. For hunting, inspect logs for WebSocket connections to /terminal/ws without preceding authentication events, look for file writes to /tmp/bastion_key, scan /tmp/ for base64-encoded Python payloads, and review process trees for boto3 or SSH child processes spawned from the marimo server process. The Sysdig Threat Research Team observed exploitation from source IP 49.207.56.74 during their honeypot campaign.

Watch whether CISA adds CVE-2026-39987 to the Known Exploited Vulnerabilities catalog, since the NVD entry already lists EPSS at 99.564 percent and the advisory was published without a CVE number initially assigned. Also monitor for publication of a public exploit script; the GitHub advisory included a proof-of-concept demonstrating a single WebSocket connection yielding a root-level interactive shell, so weaponization by additional actors is probable. If exploitation expands beyond the single source IP observed by Sysdig, expect broader scanning of internet-facing marimo endpoints.
