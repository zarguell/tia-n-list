CVE-2026-39987 is a pre-authentication remote code execution flaw in marimo, an open-source Python notebook framework. The bug lives in the /terminal/ws WebSocket endpoint, which ships without authentication in versions through 0.20.4. Any client that can reach the endpoint gets an interactive PTY shell. Version 0.23.0 adds the missing auth check.

Sysdig documented a real intrusion where an attacker exploited this to pivot from a compromised notebook to an internet-facing bastion host in eight seconds. The operator opened a WebSocket session, extracted AWS credentials from the notebook environment and its Redis-backed data store, called Secrets Manager for an SSH private key, wrote it to /tmp/bastion_key, and authenticated to the bastion. The entire credential-to-SSH sequence took eight seconds (18:57:22 to 18:57:30 UTC). Over the following nine hours the attacker dropped base64-encoded Python scripts and iteratively refined boto3 and SSH routines. Unlike prior operators who used LLM-generated tooling, this actor relied on hand-built automation.

The severity comes down to three factors: no authentication required, direct code execution, and marimo's typical deployment alongside cloud credentials. Notebook environments commonly store or reference AWS keys, database tokens, and API secrets, making them high-value targets for initial access. Any marimo instance exposed to the internet or accessible from a compromised network segment should be upgraded to 0.23.0 immediately and audited for signs of credential harvesting.
