Apiiro researchers Shmulik Cohen and Matan Giladi found that Claude Code's "Yes, and don't ask again" approval persists the entire approved shell command, including embedded passwords or API keys, verbatim into the project file .claude/settings.local.json. Their November 5 scan of public GitHub found 104,185 copies of the file across 103,617 repositories, with 1,122 files holding at least one secret and 1,379 distinct values in the current copies. Counting Git history, shared settings and saved agent transcripts, the exposure rose to 2,539 secrets across 1,994 repositories. Reported examples include a database vendor's admin-level cloud key, a production Azure Postgres password, a Square production token and the owner password of a medical-records database, affecting 63 organizations.

A later GitGuardian scan expanded the measurement to 31,088 distinct secrets in settings.local.json files across 23,276 public repositories, of which 5,343 were still valid when detected. The same research found 613 secrets, 99 of them valid, in 559 public Docker Hub image tags because COPY . . carried the working tree into images, including one Cloudflare API token repeated across all 559 tags. Monthly leaks of this file peaked at 12,535 occurrences in April 2026 and fell to 959 by October, a 92 percent drop with no confirmed explanation.

The November 24 InfoQ report says Apiiro found over 2,200 exposed secrets in public repositories linked to Claude Code. That figure sits between the published Apiiro counts and is best treated as a restatement until the methodology is confirmed, not as a third measurement. The actionable detail is unchanged: the approval file is a credential store that developers commit by accident. Watch for changes to how Claude Code persists permanent approvals, wider scans of .claude/settings.local.json in public repos and images, and rotation of any live token that appeared in the published samples.
