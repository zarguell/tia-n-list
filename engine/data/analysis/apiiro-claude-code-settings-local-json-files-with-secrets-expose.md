Apiiro researchers Shmulik Cohen and Matan Giladi disclosed on 5 November 2026 that Claude Code's "Yes, and don't ask again" approval option writes the entire approved shell command, including any embedded password or API key, verbatim into the project file .claude/settings.local.json. Their scan of public GitHub found 104,185 copies of that file across 103,617 repositories, with 1,122 files holding at least one secret, totaling 1,379 distinct secret values in current copies and 2,539 secrets once git history, shared settings, and saved agent transcripts are included, spread across 1,994 repositories.

The exposed material was not trivial: Apiiro cited production database passwords, cloud credentials, API tokens, and SSH root logins, including a database vendor's own admin-level cloud key, a production Azure Postgres password, a Square production token, and the owner password of a medical-records database, affecting 63 organizations. The root cause is a workflow feature persisting credential-bearing commands in plain text inside a file that developers routinely commit, with no review step.

The immediate risk is secret leakage through version control rather than a remote exploit, so remediation centers on repository hygiene: revoke and rotate the exposed credentials, purge the file from git history, and add .claude/settings.local.json to ignore rules. Teams using Claude Code should avoid approving commands that contain secrets, since the approval is stored indefinitely. Watch for Anthropic changes to how approved commands are persisted and for follow-up scanning tools targeting agent configuration files.
