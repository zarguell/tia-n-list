Claude Code's "Yes, and don't ask again" approval option persists the entire approved shell command, including any embedded secrets, verbatim into the project file .claude/settings.local.json. Apiiro researchers Shmulik Cohen and Matan Giladi published the finding on 5 November 2026 after scanning public GitHub: 104,185 copies of the file across 103,617 repositories, of which 1,122 files held at least one secret (1,379 distinct values in current copies, 2,539 secrets across 1,994 repositories once git history and saved agent transcripts are counted). Exposed material included production database passwords, cloud credentials, API tokens, and SSH root logins; among the confirmed leaks were a database vendor's admin-level cloud key, a production Azure Postgres password, a Square production token, and the owner password of a medical-records database, affecting 63 organizations.

GitGuardian's independent scan, published 9 November, found 31,088 distinct secrets across 23,276 repositories, of which 5,343 were valid when tested. Because "COPY . ." ships the working tree rather than the git index, 613 secrets (99 valid) reached public Docker Hub images, including one valid Cloudflare API token appearing in 559 tags. Monthly leaks of settings.local.json peaked at 12,535 occurrences in April 2026 and fell to 959 by October 2026, a 92% drop whose cause is not yet known.

The exposure is structural rather than a single bug: the approval mechanism writes credential-bearing commands in plain text into a project-local file that developers routinely commit, and agent permission files are rarely reviewed. Teams should audit repositories and git history for .claude/settings.local.json, rotate any exposed credentials, and avoid approving commands that contain secrets; watch for changes to how "don't ask again" rules are stored and for secret-scanning coverage of this file path.
