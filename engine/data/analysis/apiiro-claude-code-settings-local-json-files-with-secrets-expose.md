Apiiro researchers Shmulik Cohen and Matan Giladi found that Claude Code's "Yes, and don't ask again" approval option persists the entire approved shell command, including any password or API key, verbatim into the project file .claude/settings.local.json. A scan of public GitHub found 104,185 copies of that file across 103,617 repositories, with 1,122 files holding at least one secret (1,379 distinct values in current copies) and 2,539 secrets across 1,994 repositories when git history and saved agent transcripts are included. Exposed material included database passwords, cloud keys, API tokens, and SSH root logins, including a database vendor's admin-level cloud key, a production Azure Postgres password, a Square production token, and the owner password of a medical-records database. Sixty-three organizations were affected.

The root cause is that the permanent approval writes credential-bearing commands in plain text into a settings file that is easy to commit to a repository, and agent transcripts and shared settings compound the exposure. Because the file behaves like an unreviewed .env, secrets leak quietly.

Teams using Claude Code should audit repositories for .claude/settings.local.json, rotate any credentials that appeared in approved commands, remove the file from git history, and add it to .gitignore. Watch for follow-up tooling or vendor guidance and for attackers scanning GitHub for these files to harvest live credentials.
