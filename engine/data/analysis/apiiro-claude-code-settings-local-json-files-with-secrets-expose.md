Apiiro researchers Shmulik Cohen and Matan Giladi published research on 5 November 2026, updated 8 November, showing that Anthropic's Claude Code can persist secrets to disk when a user selects the "Yes, and don't ask again" option for a shell command. That approval writes the entire approved command string, credentials included, verbatim into the project file .claude/settings.local.json. Because that file sits inside the project tree, it is routinely committed to version control, leaking the embedded secrets.

A scan of public GitHub found 104,185 copies of .claude/settings.local.json across 103,617 repositories, with 1,122 files holding at least one secret (1,379 distinct values in current copies) and 2,539 secrets across 1,994 repositories once git history, shared settings, and saved agent transcripts are counted. Exposed material included production database passwords, cloud credentials, API tokens and SSH root logins; cited examples include a database vendor's own admin-level cloud key, a production Azure Postgres password, a Square production token and the owner password of a medical-records database, spanning 63 organizations.

The underlying issue is a design choice in the permanent-approval flow rather than a vulnerability with a CVE, so the fix is operational: review .claude/settings.local.json before commits, rotate any credential that may have been captured, and avoid approving commands that embed secrets. The exposure is ongoing as long as existing files remain in public repositories and git history.
