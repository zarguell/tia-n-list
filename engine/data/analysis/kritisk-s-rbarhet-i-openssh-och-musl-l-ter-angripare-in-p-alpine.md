A decade-old authentication bypass in OpenSSH on musl-based Linux lets attackers log into accounts that should never accept a password. The flaw is tracked as CVE-2026-123158 and dubbed *sshole. Any password between 257 and 1,024 characters works to authenticate against password-disabled accounts. Affected distributions include Alpine Linux, OpenWrt, Buildroot, and Yocto, any system running sshd built with musl libc.

The OpenSSH team shipped version 10.6p2 on November 5, 2026 to address the issue. The vulnerability exists because of improper validation of password length in the authentication routine, allowing an overly long password to bypass the password-disabled check entirely. This is a pre-authentication issue, meaning an attacker does not need prior access to exploit it.

Organizations running musl-based Linux systems should upgrade to OpenSSH 10.6p2 or later immediately. Systems using glibc are not affected by this specific flaw. The issue has been independently reported by GBHackers, Ars Technica, and suriq.io, with the Swedish security site redaktionen.net also covering it under the title "Kritisk sårbarhet i OpenSSH och musl låter angripare in på Alpine Linux."
