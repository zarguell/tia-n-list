A flaw in Telegram for Android's tgcalls library let an attacker run code on a victim's phone after the victim answered a voice call, according to NebuSec, which disclosed it on October 29, 2026. The bug sits in the code that parses MediaState call-setup messages: when a rotation value is present, the code checks it but then reads the video-state field even if the message never contained one, accessing memory it should not. NebuSec confirmed the behavior on ARM64 devices and chained it with a separate information-leak bug to escape the Telegram app, then with an Android root exploit for full device control, including messages, microphone, and camera. Affected versions run from 8.6.2 through 12.10.3, released between March 2022 and September 2026; Telegram fixed it in 12.10.4, shipped in late September 2026. No CVE identifier exists as of October 29, and NebuSec reports no in-the-wild exploitation.

The exposure window is the story: roughly four and a half years of Android releases share one vulnerable code path, and the fix arrived as an ordinary September update with no advisory, no CVE, and no user-facing warning, so most victims have no way to know they are exposed. The attack needs only an ordinary Telegram account and a call the victim answers, which removes the usual phishing and link-clicking steps and makes it viable against anyone whose call privacy is left at the default. NebuSec says it has seen no real attacks and believes no one else had turned the bug into remote code execution, but that assessment rests on a single vendor's visibility and on an undisclosed attack chain; the company has published no technical write-up, only a video. What makes this more than another mobile bug is the asymmetry: the defender gets no CVE feed entry, no detection signature, and no patch label, while the attacker gets a silent, call-triggered code-execution primitive.

Defenders should treat version inventory as the primary control: require Telegram for Android 12.10.4 or later, verified at the bottom of the app's Settings page, and enforce it through MDM or app-management policy on managed devices. Where patching is not immediate, set Telegram's call privacy to "Nobody" or decline unsolicited calls, which blocks the trigger entirely. No public indicators of compromise or detection rules exist as of October 29; hunting should rely on crash and ANR telemetry for the Telegram process, unexpected child processes or privilege escalation after a call, and post-call network or microphone and camera access anomalies. Telegram's iOS and desktop apps share the tgcalls library but received the same correction earlier, in iOS 12.7 (May 2026) and desktop 7.0.1 (July 2026); whether those builds were exploitable has not been shown.

Watch for three developments that would change the assessment: publication of a technical write-up or proof of concept, which would convert a vendor claim into a reproducible bug; any confirmation of in-the-wild use, which would move the story from theoretical to active exploitation; and a CVE assignment or bug-bounty outcome, which would finally give defenders a trackable identifier and signal whether Telegram accepts the issue as real. Also watch whether NebuSec or others demonstrate exploitability of the earlier iOS and desktop builds, since those platforms shipped the same flawed logic months before Android's fix.
