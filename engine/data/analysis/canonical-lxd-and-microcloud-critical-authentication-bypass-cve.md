Canonical LXD and MicroCloud have a critical authentication bypass tracked as CVE-2026-112816 with CVSS 10.0, caused by improper certificate validation in the HTTPS listener. An attacker with network access to the HTTPS API can present any trusted client's public certificate and impersonate a trusted identity without the private key, gaining full cluster and VM access. The event text names affected versions 4.0.14 through 6.10.1 and the fixed releases 4.0.15, 5.0.11, 5.21.9, 6.10.1. Ubuntu rates it medium priority, but the CVSS score and full-cluster impact make it severe in practice.

Sources include cve.org, the Ubuntu security page, a GitHub security advisory (GHSA-99jp-jwmc-65p4), NVD, thehackernews.com, and thecybersecguru.com, giving broad corroboration. The concrete artifact is the certificate-chain validation failure: the mTLS check only validated the leaf certificate, so a crafted chain with a trusted client's public cert succeeds. No active exploitation count is cited, but the ease of authentication bypass at CVSS 10.0 makes it a priority patch.

Monitor the Ubuntu and Canonical advisory pages for updated fixed versions, check whether CISA adds CVE-2026-112816 to the KEV catalog, and verify that any LXD/MicroCloud deployments have upgraded past 4.0.14/5.0.10/5.21.8. The event's detailed version mapping is the most useful operational data.
