CVE-2026-112816 is a critical authentication bypass in Canonical LXD and MicroCloud's mutual TLS handling, carrying a CVSS score of 10.0. The flaw stems from improper validation of client certificate chains: instead of authenticating only the leaf certificate for which the client proves possession of the private key, vulnerable implementations compare every certificate in the client-supplied chain against trusted certificates. An unauthenticated attacker who can reach the HTTPS API and obtain the public certificate of an already trusted client can append that certificate behind an attacker-controlled leaf and be accepted as the trusted identity. Fixed versions are 4.0.15, 5.0.11, 5.21.9, and 6.10.1, published by Canonical on October 30, 2026.

Successful exploitation grants API access with the privileges of the impersonated identity, which on a cluster-admin identity means full access to the cluster, managed virtual machines, and potentially root on the underlying host. No valid credentials or trusted private key are required, only network reachability to the HTTPS listener and a trusted client's public certificate. The issue was referred by the Incus project, and Incus is also affected by a related certificate-validation flaw. Ubuntu rates its own advisory as Medium priority despite the CVSS 10.0, a discrepancy worth noting when prioritizing.

Administrators should update LXD and MicroCloud immediately and treat any instance exposed to untrusted networks as urgent. Because the bypass relies on a trusted client's public certificate, environments that publish or reuse client certificates broadly are at higher risk. After patching, review cluster membership and API audit logs for impersonation, and restrict HTTPS listener reachability to known management hosts.
