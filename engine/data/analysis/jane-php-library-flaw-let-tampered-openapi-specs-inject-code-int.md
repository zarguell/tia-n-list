Jane's open-api-3 generator before 7.12.0 could let a tampered OpenAPI specification inject code into generated API clients. SecQuill's two reports describe a crafted query parameter in a modified spec reaching the code-generation path, so the malicious output lands in client code that developers then build and ship. The library itself is a development dependency, which puts the flaw in the software supply chain rather than in a running web service.

The practical risk is in who controls the spec. Teams that generate clients from third-party or externally hosted OpenAPI documents inherit whatever the generator emits, and a poisoned client can carry attacker-chosen code into every downstream deployment. There is no CVE identifier attached in the available reporting, so this is a generator-version and input-trust problem, not a patchable runtime vulnerability with an exploitation telemetry trail.

Update to open-api-3 7.12.0 or later and check generated client code when it is produced from specs outside the organisation's control. Watch for unexpected changes in generated files and for specs whose query parameters differ from the upstream API definition. No exploited-in-the-wild confirmation or IOC list is published in the reporting available here, so the assessment rests on the injection path and the fixed version.
