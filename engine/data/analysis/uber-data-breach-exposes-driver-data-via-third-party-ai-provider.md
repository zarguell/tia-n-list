Uber confirmed that a third-party AI provider, Fireworks AI, suffered an October 2026 breach that exposed personal and driver's license information for thousands of US drivers. The incident was not a compromise of Uber's own systems: hackers used compromised Fireworks internal credentials to reach environment variables used in evaluation jobs, and Uber's records held by the vendor were among the data taken. Uber learned of the intrusion on October 9, 2026, severed its data connections with the provider, and determined on October 13 that personal information had been accessed. The exposure was disclosed through breach notices filed with several state attorneys general, including California, and Fireworks separately acknowledged a follow-on compromise on October 23 and 24 via a third-party cloud provider hosting its R&D machines.

The stolen set is exactly what identity fraud and targeted phishing against drivers require: government-issued license numbers paired with the personal data that accompanies them. The blast radius extends beyond Uber drivers because Fireworks serves roughly 10,000 enterprise customers, and the same credential compromise that reached Uber's data also exposed account and billing information, secrets, datasets, and incomplete model weights for a limited set of other accounts. What makes this story matter more than a routine vendor breach is the LLMJacking angle: the financially motivated actor was monetizing stolen access to large language models through illicit routing gateways, meaning the same foothold could have been used to run up fraudulent model charges against Fireworks customers, not just exfiltrate data. Uber's exposure is a supply-chain failure where the vendor, not the customer, held the keys.

Defenders should treat this as a credential and data-exposure response, not a patching exercise, since no CVE is assigned. Organizations using Fireworks should rotate all Fireworks API keys and service-account tokens, audit evaluation-job environment variables for secrets, and revoke any keys created by the attacker; Fireworks states it rotated employee API keys on October 9 and completed a credential review by October 10. Network-side, restrict egress to Fireworks endpoints and review cloud billing and token-consumption dashboards for anomalous spikes that indicate LLMJacking-style abuse. For affected Uber drivers, license numbers and associated PII should be treated as compromised: monitor credit files and watch for phishing that references license details. Hunters should look for unauthorized workloads or model invocations from unfamiliar IPs and unexpected changes to account and billing records.

Two developments would change the assessment. First, whether Fireworks held anything beyond driver's license and personal data for Uber, such as authentication or payout details, or records for other Uber cohorts beyond drivers, which would widen the victim set and the fraud exposure. Second, whether additional Fireworks customers report similar data impact from either the October 6 credential compromise or the October 23 cloud-provider incident, and whether the threat actor is publicly identified; either would move this from a single-vendor notification event to a broader supply-chain incident with shared indicators.
