Erica Windisch of Cyberdione Labs published the Tailworm assessment on 2026-10-24, testing unmodified Tailscale v1.104.2 and headscale v0.29.5. The report catalogs 11 unpatched findings centered on Tailscale SSH Unix-socket forwarding (gliderssh streamlocal), where a compromised tailnet device that satisfies an SSH access policy can pivot to root-level access on other reachable servers. No CVE has been assigned, no vendor patch exists, and the GBHackers roundup confirms the same high-severity profile across both products.

This is not a theoretical chain: it requires only that Tailscale SSH is configured to allow port forwarding and that the attacker already controls one permitted node. Once inside, the attacker uses local Unix sockets exposed by tailscaled to escalate without stolen keys or passwords, turning a single endpoint compromise into full tailnet root exposure. Among the 30+ vulnerability headlines today, this one stands apart because it targets the remote-access layer itself - the tool that defenders rely on to reduce blast radius - and remains entirely unpatched.

Immediate actions: audit every `tailscale ssh` policy rule and disable SSH forwarding where it is not strictly required; treat nodes running v1.104.2 as high-risk until a vendor fix arrives. Hunt for unexpected connections to `streamlocal` sockets and review logs for tailscaled access events referencing `gliderssh`. Monitor tailworm.com and the Tailscale security bulletins for emergency patches.

Watch for two changes: release of an official Tailscale advisory with patch versions (currently none), and any in-the-wild exploitation telemetry tied to the F1-F5 finding labels referenced in the Tailworm reproduction kits.
