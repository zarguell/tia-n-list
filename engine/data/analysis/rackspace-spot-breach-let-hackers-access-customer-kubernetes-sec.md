Rackspace told customers that attackers used leaked credentials to enter its Rackspace Spot managed Kubernetes platform on November 17, 2026, during roughly 00:20 to 22:00 UTC. The company learned of the intrusion on November 18 through a customer report and confirmed that same day that the reporting organization was affected. SC Magazine's follow-up describes the attackers as impersonating legitimate users on the platform.

Inside customer organizations, the intruders could create pods in Kubernetes clusters, read Kubernetes Secrets, and list nodes and volumes. Rackspace warned that any Secret in an affected user's clusters could have been read, along with Spot API tokens and refresh tokens held by that user. Those Secrets can contain passwords, authentication tokens, and API keys for databases and cloud services, so the exposure reaches beyond the Spot platform itself.

Rackspace said it revoked affected tokens. Customers should treat Secrets and Spot tokens in use during the intrusion window as exposed, rotate them, and review cluster audit records for pod creation and Secret reads. The public notification does not state how many organizations were affected or how the credentials were obtained.
