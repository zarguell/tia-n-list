Rackspace told customers that an unauthorized party used leaked credentials to access parts of its Rackspace Spot cloud platform on November 17, 2026, between roughly 00:20 and 22:00 UTC. The notification, obtained by BleepingComputer, says Rackspace learned of the intrusion on November 18 after a customer report and confirmed that the reporting organization was affected the same day.

The attacker could act as a legitimate user in some customer organizations. That access allowed creation of pods in Kubernetes clusters, reading of Kubernetes Secrets, and listing of nodes and volumes. Rackspace warned that any Secret in an affected user's clusters could have been read, along with Spot API tokens or refresh tokens held by that user. Secrets of this kind can contain passwords, authentication tokens, and API keys for databases and cloud services. Rackspace says it revoked affected tokens after the incident.

The useful hunting targets here are pod-creation events and Secret reads during the November 17 window, plus any use of Spot API or refresh tokens tied to affected users. Token revocation limits further use, but it does not by itself show what an attacker already extracted from a cluster.
