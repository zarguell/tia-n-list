Rackspace told customers that leaked credentials were used to access parts of its Rackspace Spot cloud platform on November 17, 2026, between roughly 00:20 and 22:00 UTC. Attackers acted as legitimate users in some customer organizations, creating pods in Kubernetes clusters, reading Kubernetes Secrets, and listing nodes and volumes. Rackspace learned of the intrusion on November 18 after a customer report and confirmed that customer's exposure the same day. Kubernetes Secrets can hold database passwords, authentication tokens, and API keys for other services.

The company warned that attackers could have read any Secret in an affected user's clusters, along with Spot API tokens and refresh tokens held by that user. Rackspace says it revoked affected tokens, and the notice said service was restored. The customer count was not disclosed. Security magazine and BleepingComputer reported the same notification on November 21 and 22.

Watch for cluster audit entries showing pod creation or Secret reads around November 17, and rotate credentials stored in affected clusters rather than only the Spot tokens. Unauthorized workloads and token reuse are the concrete risks described in the notification.
