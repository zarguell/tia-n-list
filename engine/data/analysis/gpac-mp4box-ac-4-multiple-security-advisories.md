GPAC MP4Box carries four AC-4 parser vulnerabilities tracked as CVE-2025-60469, CVE-2025-60470, CVE-2025-60476, and CVE-2025-60480. The events reference GitHub issues 3292 through 3295, all filed by researcher sigdevel on 14 July 2025 and resolved in commit e02d1fd on 15 July 2025. CVE-2025-60480 is the heap buffer overflow at odf/descriptors.c:1899 in `gf_odf_ac4_cfg_alternative_info`, triggered by a crafted AC-4 stream against MP4Box 2.5-DEV-rev1593. The other three cover NULL pointer dereference, out-of-bounds read, and heap use-after-free in the same descriptor family.

This cluster matters because GPAC underpins media-processing pipelines that ingest untrusted audio, and a remote attacker who can deliver a malicious AC-4 file reaches the parser through `MP4Box -info` or any pipeline using the same `gf_filter_process_task` path. The events note a 784-byte heap allocation that the overflow exceeds, and the AddressSanitizer trace shows the read propagates through `ac4dmx_process` and `gf_media_import`. There is no mention of in-the-wild exploitation, but the long gap between the July 2025 disclosure and the October 2026 story timestamp suggests these fixes have been available for over a year; defenders running older GPAC bundles are exposed.

Patch by pulling commit e02d1fd or upgrading GPAC past the 2.5-DEV master that includes it. For hunting, inspect logs for `gf_odf_ac4_cfg_alternative_info` crashes or ASan reports mentioning `odf/descriptors.c`, watch `ac4dmx_check_pid` and `filters/reframe_ac4.c` in telemetry, and scan for malformed AC-4 streams processed through MP4Box. Network restrictions should block untrusted media ingestion where GPAC is embedded until the build includes the fix.

Watch for vendor re-releases that bundle GPAC, since the original fix is upstream but integration lag varies. A second signal would be exploitation telemetry linking these CVEs to active campaigns targeting media servers, which the current events do not show.
