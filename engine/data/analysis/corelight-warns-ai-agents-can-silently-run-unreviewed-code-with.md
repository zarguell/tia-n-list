Corelight's investigation began as a blast-radius exercise using an AI agent on an administrator's workstation. The agent found other AI agents on that machine. Nothing there was compromised, but the setup led Corelight to look at how coding assistants launch MCP servers. The reported risk is that an MCP server can be pinned to a specific release and commit while its dependencies still change without any configuration edit, and the server may run with administrator credentials.

Corelight's own post gives the concrete measurement: one MCP server pinned to one release and one commit ran on 15 different dependency sets in five weeks, even though its author pinned all seven direct dependencies. The GBHackers write-up frames this as unreviewed code running with privileged access through AI coding assistants. What to watch is dependency resolution at MCP launch time rather than only the server version or commit hash, especially where the server holds administrative tokens or network access.
