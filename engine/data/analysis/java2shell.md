Java4Shell is CVE-2026-114938, a heap overflow in the hand-written x86-64 assembly that OpenJDK's C2 JIT uses for Base64 decoding on hosts with AVX-512 VBMI. Calif's research shows a 64-byte padding case writing 62 bytes past a 50-byte array, or 128 A's on JDK 17, which can leak heap contents and enable pre-auth code execution in Java services such as Jira, Jenkins and Keycloak. Oracle and OpenJDK shipped fixes on November 17, and CISA urged immediate patching; no in-the-wild exploitation has been reported.

Exposure depends on the CPU as well as the Java version. The vulnerable path needs x86-64 chips with AVX-512 VBMI and Java 17.0.6 or later on the 17 line, plus affected 21, 25 and 27 builds; standard Java 8 and 11 lack the code, while the 8u511b33-perf performance build and recent GraalVM builds carry it. Fixed builds are 17.0.21.1, 21.0.13.1 and 25.0.5.1, with -XX:-UseBASE64Intrinsics as a stopgap.

New reporting keeps circling the question of coverage, including whether Oracle's November batch of 11 Java fixes actually includes this flaw and what hospital systems running Java face. The technical claim stays the same: patch or disable the intrinsic, then rotate credentials exposed in the heap of affected services. Watch for a CISA KEV entry, reliable exploitation reports, and clarification on the perf and GraalVM builds.
