CVE-2026-114938 is a reported unauthenticated remote code execution flaw in Java 17 and later, described by Rapid7 on 17 November as a memory corruption issue with CVSSv4 9.2. Rapid7 calls the CVE-specific details preliminary pending confirmation in Oracle or OpenJDK advisories, and shipped an authenticated exposure check for Exposure Command, Vulnerability Management and Nexpose in content release 1.1.4115. Oracle's pre-release notice dated 12 November lists 652 security patches for 17 November, 11 of them for Java SE, all remotely exploitable without authentication, with a maximum CVSS v3.1 score of 8.1. Listed affected Java SE versions are 8u511, 11.0.33, 17.0.21, 21.0.13, 25.0.5 and 27.0.1.

watchTowr said on 17 November at 10:22 UTC that it knew of public reports of CVE-2026-114938 affecting OpenJDK 17.0.6 and later, but called the details unconfirmed and named no exploit code, vulnerable component, fix or observed exploitation. Other posts in the same window use the names Java4Shell and Java2Shell, and a Reddit item refers to a South Korean NIS inspection advisory to public institutions. The 9.2 figure and Oracle's 8.1 ceiling do not reconcile in the published material, so the CVE should stay separate from the Java SE batch until a vendor advisory maps it.

Watch for a published CVE description, a component and version mapping in Oracle's final advisory, and an OpenJDK advisory that names the defect. No exploit code, log artifact, port, victim telemetry or fix version appears in the available events. Inventory JVM vendor and build across servers, embedded runtimes and container images, reduce external exposure on internet-facing Java services, and treat any claim of confirmed exploitation as unsubstantiated until a primary source carries it.
