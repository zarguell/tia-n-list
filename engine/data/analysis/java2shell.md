CVE-2026-114938, nicknamed Java4Shell, is a heap-based buffer overflow in the AVX-512 accelerated Base64 decoder in OpenJDK. Calif disclosed it on November 17, 2026 and rates it CVSS 4.0 9.2; Oracle uses CVSS 3.1 8.1. The buggy assembly path runs on x86-64 CPUs with AVX-512 VBMI, including Intel Xeon Ice Lake through Granite Rapids and AMD EPYC Zen 4 onward. ARM64 and older x86 systems are not affected. Calif's trigger is 128 'A' characters plus '=' on JDK 17, which writes 62 bytes past the end of a buffer before the input is rejected.

Researchers demonstrated memory corruption and unauthenticated code execution on default installs of Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate. A separate reconstruction confirmed the out-of-bounds write and a corrupted array length but did not build a code-execution chain. Tenable said on November 17 it knew of no exploitation, and Cisco Talos reported no in-the-wild use; GreyNoise is monitoring scanning and attempts. Treat public PoC code as the current state, not confirmed attacker use.

Oracle and OpenJDK shipped fixes on November 17. Fixed builds called out in the event set are 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1. The upstream fix is a four-line guard in stubGenerator_x86_64.cpp. Until patching, limiting exposure on internet-facing identity, CI/CD and collaboration systems matters most, along with inventory of JVMs in container images; dependency scans alone will not find affected runtimes.
