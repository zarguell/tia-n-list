CVE-2026-114938, named Java4Shell, was disclosed on November 17, 2026, after Calif reported a heap out-of-bounds write in the hand-written AVX-512 VBMI Base64 decoder in the OpenJDK HotSpot x86-64 path. The vulnerable path runs on x86-64 CPUs with AVX-512 VBMI, including Intel Xeon from Ice Lake and AMD Zen 4 onward; ARM64 hosts are not affected by this code path. Calif rated it CVSS 4.0 9.2, while Oracle's CVSS 3.1 score is 8.1. OpenJDK 17.0.6 and later and downstream builds from Java 17, 21, 25 and 27 are in scope.

The trigger is a malformed padded Base64 tail: 64 'A' characters plus '=' in one writeup, 128 'A' characters on JDK 17 in another, producing a 62-byte overwrite past a buffer. Calif demonstrated pre-authentication code execution on default installs of Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate, and authenticated execution on Kafka, Solr, Elasticsearch, Gerrit and Spinnaker. Oracle and OpenJDK shipped fixed builds 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1 the same day. The upstream guard adds a check of output length below four before the tail handler in stubGenerator_x86_64.cpp.

Cisco Talos and Tenable reported no observed in-the-wild exploitation at disclosure, while GreyNoise began monitoring scanning and exploitation attempts. CISA urged immediate patching. Where patching waits, disabling the intrinsic with -XX:-UseBASE64Intrinsics or limiting AVX with -XX:UseAVX=2 removes the vulnerable path. Watch for confirmed intrusions on internet-facing identity and CI systems and for downstream Java distributions that lag Oracle's builds.
