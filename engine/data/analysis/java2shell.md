CVE-2026-114938, nicknamed Java4Shell, is a heap buffer overflow in the AVX-512 accelerated Base64 decoder in OpenJDK. Calif disclosed it on November 17, 2026 and scores it 9.2 under CVSS 4.0; Oracle uses 8.1 under CVSS 3.1. The buggy assembly path runs on x86-64 CPUs with AVX-512 VBMI, including Intel Xeon Ice Lake through Granite Rapids and AMD EPYC Zen 4 onward. ARM64 and older x86 systems are not affected. Securityweek reports that invalid Base64 strings can write past the output buffer before Java rejects the input, and Calif calls the memory disclosure capability JavaBleed because heap data such as personal information, secret keys and tokens can leak.

Calif demonstrated pre-authentication remote code execution on default installs of Keycloak, Jira, Confluence, JFrog Artifactory, Jenkins and PingFederate, plus authenticated code execution on Kafka Broker, Solr, Elasticsearch, Gerrit and Spinnaker. A separate reconstruction reproduced the out-of-bounds write and a corrupted array length by emulating AVX-512 with Intel SDE but did not build a code-execution chain. Cisco Talos reported no observed in-the-wild exploitation as of November 17 while GreyNoise said it was monitoring scanning and attempts. The Canadian Cyber Centre issued alert AL26-029 on November 17 classifying the bug as CWE-122, and RaiNews reported a US CISA alert the same day.

Oracle and OpenJDK shipped fixes on November 17. Fixed builds named in the events are 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1; the upstream fix is a four line guard in stubGenerator_x86_64.cpp that sends short padded Base64 tails to the Java path. Reports also describe a JVM option to disable the Base64 intrinsic as a stopgap where patching must wait. Oracle's November update carried hundreds of patches, with an advance notice citing 652 and Tenable counting 655 security updates, so the Java fix sits inside a much larger patch load.

What to watch is public reachability rather than headline severity. Any Java service that decodes untrusted Base64 on an affected runtime and CPU can be exposed without an application bug, with identity, CI/CD and collaboration systems the first priority. Public PoC code exists while Calif is withholding application-specific exploits, and reporting says AI coding tools did much of the discovery work. Watch for Talos or GreyNoise moving from no observed exploitation to confirmed probing or victim telemetry, and verify installed JVM versions and CPU features on hosts and in container images since dependency scans alone will not find affected runtimes.
