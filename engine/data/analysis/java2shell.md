Java4Shell is CVE-2026-114938, a heap out-of-bounds write in the x86-64 AVX-512 VBMI Base64 decoder that OpenJDK's C2 JIT substitutes for the Java decoder. Calif disclosed it on 17 November 2026, the same day Oracle and OpenJDK shipped fixes. The hand-written assembly underflows the output length on a short padded Base64 tail, then writes a full 64-byte mask and overshoots the buffer by 62 bytes. Calif scores it 9.2 under CVSS 4.0; Oracle scores 8.1 under CVSS 3.1. Exposure needs both an affected runtime, from OpenJDK 17.0.6 onward plus the 21, 25 and 27 lines before their November fixes, and a CPU with AVX-512 VBMI, which covers Intel Xeon Ice Lake through Granite Rapids and AMD Zen 4 and later. ARM64 hosts and standard Java 8 and 11 do not hit this path, though the Java SE 8u511b33-perf build does.

Calif demonstrated pre-authentication remote code execution on default installs of Jira, Confluence, Jenkins, Keycloak, JFrog Artifactory and PingFederate, and authenticated execution on Kafka Broker, Solr, Elasticsearch, Gerrit and Spinnaker. The researchers also describe a heap read they call JavaBleed, so keys, tokens and personal data can leak even when the code execution attempt fails. Oracle's fixed builds are 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1. Where patching has to wait, -XX:-UseBASE64Intrinsics or -XX:UseAVX=2 closes the vulnerable path, and GitGuardian advises revoking credentials held by any exposed service. CISA urged immediate patching; Cisco Talos reported no observed in-the-wild exploitation at disclosure, while GreyNoise began tracking scanning and exploitation attempts.

The patch decision depends on the host CPU as much as the JVM version, so a container image can be inert on one node and exploitable on another. Inventory runtime builds on hosts and in images, then prioritize internet-facing identity, CI/CD and collaboration services that decode attacker-supplied Base64. Talos noted that the tested applications are a starting set rather than the full surface, and Calif has withheld the per-application exploit chains, so additional confirmed targets are likely as other researchers reproduce the work. Canadian, Swiss and US government alerts and New York Times coverage of hospital exposure show how broadly the runtime is deployed, but each application still needs its own working chain rather than a single universal exploit.
