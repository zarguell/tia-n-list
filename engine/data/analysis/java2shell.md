Java4Shell is CVE-2026-114938, a heap out-of-bounds write in the AVX-512 accelerated Base64 decoder of the OpenJDK HotSpot runtime. Calif disclosed it on 17 November 2026, the same day Oracle and OpenJDK shipped fixes. A malformed padded Base64 tail makes the decoder write past its output buffer. The researchers describe a memory read they call JavaBleed that can expose keys and tokens, and they demonstrated unauthenticated remote code execution on default installs of Keycloak, Jira, Confluence, JFrog Artifactory, Jenkins and PingFederate.

Exposure depends on hardware and build, not just the CVE. The vulnerable x86-64 assembly path requires AVX-512 VBMI, found in Intel Xeon Ice Lake and newer and AMD Zen 4 and newer. Affected builds include JDK 17.0.6 through 17.0.21, Java 21, 25 and 27 before their .1 fixes, and the Java SE 8u511b33-perf build. ARM64 hosts and standard Java 8 and 11 are not affected. Oracle rates the flaw 8.1 under CVSS 3.1, while Calif gives it 9.2 under CVSS 4.0.

Fixed builds named in the coverage are 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1. The upstream change is a four-line guard in stubGenerator_x86_64.cpp that sends short padded tails to the Java decoder. Interim options are -XX:-UseBASE64Intrinsics and -XX:UseAVX=2. Cisco Talos and Tenable report no in-the-wild exploitation so far, though GreyNoise is tracking scanning and attempts. Watch for downstream Java vendors shipping their own builds and for application-specific exploit chains, which Calif has withheld.
