CVE-2026-114938, nicknamed Java4Shell, is a heap out-of-bounds write in the AVX-512 accelerated Base64 decoder in OpenJDK. Calif disclosed it on November 17, 2026, the same day Oracle and the OpenJDK project shipped fixes. Calif scores it 9.2 under CVSS 4.0, Oracle 8.1 under CVSS 3.1. The vulnerable path runs on x86-64 processors with AVX-512 VBMI, including Intel Ice Lake through Granite Rapids and AMD EPYC Zen 4 onward. ARM64 hosts and standard Java 8 and 11 are not affected. The reported trigger is malformed padded Base64 input, as little as 64 A characters plus an equal sign on some branches, which writes past the end of a heap array before Java rejects the data.

The flaw is in the Java runtime rather than an application library, so any service that decodes attacker-supplied Base64 on affected hardware can be exposed. Calif reported pre-authentication remote code execution against default installs of Keycloak, Jira, Confluence, JFrog Artifactory, Jenkins and PingFederate, and authenticated code execution against Kafka Broker, Solr, Elasticsearch, Gerrit and Spinnaker. The researchers also describe a Heartbleed-like memory leak they call JavaBleed, which could expose tokens and keys from heap memory. Fixed builds named in the research are 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1. Where patching has to wait, disabling the Base64 intrinsic through JAVA_TOOL_OPTIONS is the interim mitigation discussed in the reporting.

Cisco Talos said on November 17 that it had not observed in-the-wild exploitation, and Tenable was not aware of exploitation then, although a public PoC triggers the bug and a second researcher reported building a working exploit. GreyNoise is monitoring scanning and exploitation attempts. CISA and the Canadian Centre for Cyber Security have urged immediate patching. The practical watch items are unpatched runtimes inside container images, internet-facing identity and CI systems such as Jenkins and Keycloak, and vendor-specific backports, because dependency scans alone will not find every affected JVM.
