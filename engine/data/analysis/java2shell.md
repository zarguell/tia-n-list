Java4Shell is CVE-2026-114938, a heap out-of-bounds write in the HotSpot JVM's x86-64 Base64 decoder intrinsic. Reporting on the flaw describes a malformed padded Base64 tail that writes 62 bytes past the end of the output buffer, with outcomes ranging from JVM crashes and leakage of heap secrets such as private keys and tokens to unauthenticated remote code execution. Exploitation depends on AVX-512 VBMI support; OpenJDK 17.0.6 and newer on affected CPUs are in scope. OpenJDK published an advisory and Oracle shipped a fix on 17 November 2026.

Oracle's pre-release notice dated 12 November listed 652 new security patches, 11 of them for Java SE, all remotely exploitable without authentication, across versions 8u511, 11.0.33, 17.0.21, 21.0.13, 25.0.5 and 27.0.1, with a highest CVSS v3.1 base score of 8.1 for Java SE. watchTowr said on 17 November that public reports of an unauthenticated RCE, then unconfirmed, named CVE-2026-114938 and OpenJDK 17.0.6 and later. Red Hat published a critical update for OpenJDK 17 on Windows, 17.0.21.1, and CISA urged organizations to patch immediately, prioritizing internet-facing systems.

GreyNoise reported monitoring scanning and exploitation attempts against the CVE, which is a signal of activity rather than a count of confirmed victims. Interim mitigations in the reporting are the JVM flags -XX:-UseBASE64Intrinsics or -XX:UseAVX=2 until patching is possible. Watch for downstream distributions that have not yet shipped the fixed builds, and for confirmed exploitation against internet-facing Java services.
