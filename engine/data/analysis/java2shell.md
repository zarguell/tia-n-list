CVE-2026-114938, called Java4Shell, is an out-of-bounds write in the x86-64 HotSpot Base64 decoder intrinsic. The flaw affects JDK 17.0.6 through 17.0.21 and branches 21, 25 and 27 before their .1 fixes, and requires AVX-512 VBMI hardware on newer Intel and AMD processors. Fixed builds include 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1; ARM and older x86 hosts are not affected. A technical rebuild reproduced the write and array length corruption without building a code execution chain.

Reachability comes from ordinary Base64 inputs such as HTTP Basic headers, JWTs and SAML artifacts. Calif reported unauthenticated code execution against default installs of Jira, Confluence, Jenkins, Keycloak and other enterprise applications, with a separate chain needed for each target. On JDK 17 the documented trigger uses 128 "A" characters plus a padded equals sign. Disclosure and fixes landed on 17 November.

By early 19 November GreyNoise had logged more than 150 requests shaped like Java4Shell attacks from five IP addresses, with no successful intrusions on its sensors. WatchTowr reported "java4shell-recon" User-Agent strings and blind attempts with correctly shaped requests. New reporting repeats the interim options of patching OpenJDK or turning off UseBASE64Intrinsics. Watch for successful callbacks, unpatched downstream Java products and vulnerable runtimes in container images.
