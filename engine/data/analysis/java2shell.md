Java4Shell is CVE-2026-114938, a heap buffer overflow in the hardware-accelerated Base64 decoder in OpenJDK. Calif Research rates it CVSS 4.0 9.2 and Oracle CVSS 3.1 8.1. The bug lives in hand-written AVX-512 VBMI assembly used on x86-64 CPUs, so ARM64 systems are not affected. Reporting describes a trigger of 64 'A' characters followed by a single equals sign that writes 62 bytes past the end of a buffer. The affected range is OpenJDK 17.0.6 and later, including Oracle Java SE, Amazon Corretto, Eclipse Temurin, Microsoft Build of OpenJDK, Azul Zulu and Red Hat OpenJDK builds.

Reachability is broad because the decoder handles authentication headers, tokens and file uploads inside the runtime itself. Calif demonstrated pre-authentication code execution on default installs of Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate. Oracle shipped 11 Java fixes on November 17 as part of its November update, and a single JVM flag can close the path where patching is delayed. Early watchTowr and Rapid7 notes called the CVE details preliminary, so the operator question is which released builds actually map to the flaw; the pre-release Oracle notice listed the Java fixes without naming Java4Shell. The New York Times reported the same day that AI coding tools did much of the work in finding the bug.

The Canadian Cyber Centre issued AL26-029 on November 17 and CISA urged immediate patching. GreyNoise is monitoring scanning and exploitation attempts, and Cisco Talos says it has not observed in-the-wild exploitation yet, so the researcher demonstrations are capability evidence rather than a confirmed intrusion campaign. Inventory runtimes on hosts and container images rather than relying on dependency scans, then prioritize internet-facing identity, CI/CD and collaboration services. Watch for vendor mapping changes, additional application confirmations and any move from demonstration to exploitation.
