The SANS Internet Storm Center diary (2026-10-28, updated 2026-10-29 00:42:15 UTC) documents another ClickFix social-engineering campaign that presents a fake Cloudflare verification screen to users on both Windows and macOS. The lure instructs the victim to copy and run a command from the page, a well-known ClickFix pattern. The delivery chain observed in this case runs through the domain js-static[.]cfd, with endpoints including embed.js and several tracking API calls. The final payload could not be retrieved: the malware host returned HTTP 403 for Windows requests, and the macOS delivery domain did not resolve at the time of analysis.

This campaign is significant because ClickFix has become a reliable delivery mechanism that bypasses traditional malware download detection by relying on user-executed clipboard commands rather than binary attachments. The fake Cloudflare verification page targets both major desktop platforms simultaneously, expanding exposure beyond a single OS. The researcher (Brad Duncan, malware-traffic-analysis.net) observed the campaign actively, yet the unconfirmed payload and failed resolution mean defenders should treat the infrastructure indicators as high-confidence but the end-state malware family as unknown. With no CVE assigned and no confirmed exploitation telemetry from GreyNoise or Shodan-style sources, this story demands defensive attention for its delivery method rather than a named vulnerability.

Defenders should block the known delivery domain js-static[.]cfd and watch for user-executed clipboard commands following visits to verification-style landing pages. Hunting should focus on process creation events where a browser or clipboard process spawns a shell or command interpreter shortly after a user interaction with a page referencing Cloudflare verification. Log paths for endpoint telemetry should include browser process trees and clipboard access events, specifically monitoring for instances where `cmd.exe` or `powershell.exe` (Windows) or terminal applications (macOS) launch with arguments derived from copied text. Network restrictions targeting the endpoint paths embed.js and the API tracking domains mentioned in the diary provide immediate containment value even without confirmation of the final payload.

The assessment would shift if the delivery domain begins resolving payloads consistently or if exploitation telemetry from sensor networks confirms active delivery of a named stealer or remote-access tool. A change in the verification page design or new domain rotation by the campaign operators would also alter the defensive posture, as would publication of a confirmed malware family linked to the js-static[.]cfd infrastructure.
