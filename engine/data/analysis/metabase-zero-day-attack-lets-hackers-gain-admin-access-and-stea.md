The Metabase zero-day campaign continues to escalate. The original vulnerability, a maximum-severity (CVSS 10.0) unauthenticated SQL injection in the password-reset endpoint (GHSA-vwf4-m7j8-wcjf), was actively exploited against Metabase Cloud starting around August 3, 2026. Attackers gained full administrator access to compromised instances, harvesting credentials for every connected database. Metabase confirmed exploitation against its own Cloud infrastructure before patching, with Framework and Tally customers among reported victims.

CISA subsequently assigned CVE-2026-72898 and added it to the Known Exploited Vulnerabilities catalog on August 11, with a remediation deadline of August 14. The vulnerability affects the database layer supporting Metabase itself, meaning an attacker who exploits it can access user accounts, authorization settings, session records, and stored connection details for all linked data sources. This is not a backend-query-level injection; it compromises the application's own administrative database.

A new WordPress Pods plugin vulnerability (CVE-2026-19598, CVSS 9.8) was also recently clustered into this story by the mechanical merge, but it is an unrelated flaw in a different product and should be tracked separately. The Metabase story now spans four events from two sources with a combined score of 7.5. All internet-facing Metabase deployments should be patched immediately. Watch for additional victim disclosures and whether the SQL injection vector is reused in other analytics platforms.
