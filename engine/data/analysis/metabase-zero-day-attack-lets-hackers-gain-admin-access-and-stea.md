Attackers exploited a maximum-severity SQL injection zero-day in Metabase, the open-source analytics platform, starting around August 3, 2026. The flaw, CVE-2026-72898, carries a CVSS 10.0 rating and targets the unauthenticated POST /api/session/reset_password endpoint. No valid credentials are needed: a remote attacker sends crafted input to inject arbitrary SQL into Metabase's own application database, then escalates to full administrator access. From there, the attacker can read and export data from every connected data source, harvest stored database credentials, and alter application configuration. Metabase confirmed its Cloud infrastructure was targeted before the patch shipped, and CISA added the CVE to the KEV catalog on August 11 with a remediation deadline of August 14.

The scope of compromise is broader than a typical SQL injection because this flaw hits the application database itself, not just a backend query. That database holds user accounts, authorization settings, session records, and connection details for every data source Metabase touches. Reported victims include Framework and Tally customers, where unauthorized access exposed names, emails, addresses, phone numbers, and company details. Organizations running self-hosted Metabase 1.58 or later on internet-facing ports remain exposed if they have not applied the patch or blocked the affected endpoint.

This story illustrates the danger of authentication bypass in administrative functions. The password-reset endpoint was designed for legitimate account recovery but lacked sufficient input validation, creating an unauthenticated code path directly into the database layer. Metabase's rapid patch and endpoint blocking contained the Cloud fallout, but self-hosted deployments are the organization's own responsibility. Watch for secondary exploitation: attackers who harvested database credentials during the initial window may have pivoted into downstream systems long after Metabase itself was patched.
