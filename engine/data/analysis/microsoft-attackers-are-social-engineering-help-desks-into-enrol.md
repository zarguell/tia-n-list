Attackers are social-engineering help desk personnel into enrolling passkeys that they control, then using those passkeys to hijack Microsoft cloud accounts and access SharePoint resources. The technique bypasses traditional MFA by tricking employees via SMS-based alerts into registering attacker-controlled passkeys as a legitimate authentication device. Microsoft's security teams and external sources have documented the activity, which is being used to gain access to cloud tenants and drain SharePoint data.

Threat actors appear to be using a combination of social engineering and phishing to target help desk staff, often via fake passkey alerts that prompt victims to add a new passkey or sign-in method. Once the attacker succeeds in enrolling their passkeys, they can bypass MFA and gain access without triggering additional security alerts. This is a significant evolution of the passkey phishing techniques that have been documented in recent months, and it highlights the risk of passkeys not yet being fully understood or defended against by help desk teams.

The attackers are specifically targeting Microsoft cloud environments, and the attacks have been linked to storm-related or state-aligned threat actors. The campaign appears to involve first acquiring valid credentials, then using social engineering to enroll attacker-controlled passkeys. This allows the attacker to maintain persistent access without raising alerts for traditional MFA bypass. Organizations should review their passkey enrollment processes, restrict who can enroll new passkeys, and monitor for help desk-initiated changes to authentication methods.
