BlackX is a UEFI bootkit deployed in an early-2026 espionage campaign against diplomatic organizations in Tajikistan, Uzbekistan, and Turkmenistan. It revives the Baton Drop vulnerability (CVE-2022-21894), a Secure Boot bypass from January 2022, by abusing an unrevoked vulnerable boot manager binary to load a malicious driver below the operating system. Kaspersky GReAT attributes the activity to APT41 with medium confidence based on PDB path overlaps, and the malware closely mirrors the BlackLotus bootkit that circulated since October 2022.

A successful infection grants persistent control beneath Windows and survives OS-level remediation, which is precisely why diplomatic targets in Central Asia are attractive: the victim base is concentrated, the espionage value is high, and fully patched systems that miss revocation updates remain exposed. The events carry no victim count or CISA KEV entry, but the campaign scope is bounded to diplomatic agencies rather than mass exploitation, distinguishing this from commodity malware and making targeted network hygiene the decisive factor.

Defenders should verify Secure Boot revocation updates are applied (not merely OS patches) and audit EFI System Partition integrity for unexpected drivers or MOK enrollments associated with BlackX. Hunting should focus on ESP artifacts referencing the unrevoked bootmgfw.efi binary tied to CVE-2022-21894, UEFI firmware events showing unauthorized boot chain modifications, and any telemetry matching the APT41-linked identifier `xdd` mentioned in Kaspersky's analysis. Patch validation and MOK registry review should be prioritized on endpoints in the reported geographic footprint.

Watch for expanded victim reporting beyond Central Asian diplomatic networks and any CISA or vendor update that revokes the remaining vulnerable binaries used by BlackX. If the bootkit appears in wider telemetry or the APT41 attribution strengthens, the assessment should shift from targeted espionage to a broader supply-chain or regional threat.
