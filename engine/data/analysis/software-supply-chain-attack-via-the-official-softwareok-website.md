ASEC confirmed trojanized installers for Q-Dir 12.83.0.0, 12.84.0.0 and 12.85.0.0 and DesktopOK 12.82.0.0 and 12.85.0.0 on SoftwareOK's official download and update paths. Each wrapper runs the genuine signed utility from `C:\Users\Public` while fetching `7zr.exe` and `dsv2_py39_agent.7z`, then installs a self-contained Python RAT under `C:\ProgramData\Microsoft\DeviceSync\b2` that beacons to `8.210.69.51:9876`. This is confirmed malicious delivery with a first-hand infection report, not a theoretical vulnerability; no CVE, named actor or proven replacement mechanism has been published.

The trust failure is more serious than a convincing fake download: the vendor's own distribution and updater supplied the payload, while the visible application and its valid embedded signature concealed a separate RAT. A November 19 Scoop Extras report says a Q-Dir 12.84 build was accepted during a November 13-15 hash change and infected a machine, with remote shell, file transfer, screenshots and tunneling; exposure therefore predates ASEC's November 25 advisory. ASEC also found a list of 1,206 security-product process names sent to the C2, so a clean antivirus result does not clear a host. Every Windows host that installed or updated the five listed builds is in scope even without Python, but ASEC provides no victim count and warns that the distribution window may extend beyond those versions.

No CVE fix or version-specific hotfix is identified. SoftwareOK currently lists Q-Dir 12.85 and DesktopOK 12.88, but a version label is not proof of safety because ASEC found clean and malicious files under the same labels; uninstall and reinstall only after the downloaded SHA-256 matches the vendor-posted hash and ASEC's legitimate-file table. Hunt separately for scheduled task `\UPnp\MicrosoftEdge_dcntel`, Run value `DeviceSyncUpdate_b2`, `pythonw.exe` with `py_client_dsv2.py` beneath both `C:\ProgramData\Microsoft\DeviceSync\b2` and `C:\ProgramData\DeviceSync\b2`, and `%TEMP%\vmbt_guard.log` or `%TEMP%\Py39_install.log`. Block `mail.c1a2.top` and TCP `8.210.69.51:9876`, inspect process creation, task registration, DNS and network telemetry, isolate matches, preserve evidence, rotate credentials used on infected hosts and run a full scan; never accept a new package hash merely to clear a mismatch.

Watch for a SoftwareOK root-cause statement that establishes the replacement window, and for endpoint telemetry showing new affected versions, C2 addresses or follow-on payloads. A later start date or narrower build set would reduce scope; evidence of earlier delivery or more infrastructure would increase it.
