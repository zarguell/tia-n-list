ServiceNow's September 2026 advisory, KB3159623, issued five CVEs against the ServiceNow AI Platform on September 24, 2026, with hotfixes across the Yokohama, Zurich and Australia release branches. Two are critical at CVSS v4.0 9.3. CVE-2026-13016 is an unauthenticated SQL injection, tracked under product problem PRB2036897, that under certain circumstances lets an attacker run arbitrary SQL statements against an instance's underlying database. CVE-2026-86860 is a missing authorization flaw that exposes sensitive instance data to unauthenticated users and opens a path to privilege escalation. The rest are high severity: CVE-2026-86858, unauthenticated privilege escalation via GraphQL at 8.7; CVE-2026-86859, arbitrary record disclosure at 8.7; and CVE-2026-86857, an authorization bypass at 8.4. ServiceNow says it found no evidence of malicious exploitation, that the issues surfaced through internal testing, customer assessments and bug bounty reports, and researchers have not yet published proof-of-concept code.

What separates CVE-2026-13016 from routine web injection is the layer it lands on: roles, ACLs and scoped-application boundaries in ServiceNow all sit above the database, so arbitrary SQL against the instance database bypasses every permission check the platform enforces for its own users, putting workflow records, case-management data, authentication material and configuration within reach in a single step. The exposure also splits in a way the event coverage never spells out: ServiceNow pushed the fix to its hosted fleet automatically, so the population still exposed after September 24 is almost exactly the self-hosted and partner-hosted instances whose operators must pull hotfixes themselves, often while running older patch levels. That turns a five-flaw advisory into a short, auditable list of responsible parties rather than an internet-wide countdown, and with industry telemetry putting ServiceNow in over 80 percent of Fortune 500 firms, the data concentration behind five pre-auth flaws makes the vendor's clean exploitation record a deadline rather than a relief.

Hosted instances were already updated on the vendor side, so the work belongs to self-hosted and partner operators: verify the running build and move to Yokohama Patch 13 Hot Fix 5a, Zurich Patch 10 Hot Fix 3b, Zurich Patch 10 Hot Fix 4a W32, Zurich Patch 11 Hot Fix 3, Australia Patch 2 Hot Fix 4b W32, Australia Patch 4 Hot Fix 3 or Australia Patch 5 as applicable. Until patched, keep instance UI and API surfaces off the public internet or behind allowlists, since every flaw in the set requires no valid session or bypasses authorization. The hunt is in instance audit and transaction history: unauthenticated sessions reading or updating records outside role scope, GraphQL endpoint traffic from sources with no session, which is the CVE-2026-86858 path, and unexpected privilege or record changes consistent with CVE-2026-86860. Any such hit predating the patch window would indicate private exploit research given the absence of public code.

Two developments would change the assessment. The advisory itself notes that researchers who reported issues through responsible disclosure may publish their findings, so a PoC release is a foreseeable near-term event, and public code for a pre-auth SQL injection on a platform this widely deployed typically reaches mass scanning within days. A KEV listing or vendor escalation for any of the five CVEs would falsify the current no-exploitation footing and convert the self-hosted patch backlog into incident response.
