Radware says an unauthorized party accessed an internal-only Cloud WAF management API that was reachable from the public internet without authentication on 19 November 2026. The company detected the access roughly ten hours after it began, blocked the originating IP address and shut down access to the API, then revoked and replaced internal account credentials. Details come from a root cause analysis shared anonymously with BleepingComputer.

The exposed data was customer contact details and, for a subset of customers, credentials configured for log export into self-managed AWS S3 buckets, Azure Blob Storage or SFTP servers. Radware says the breach did not touch WAF traffic inspection, certificates, end-user data, customer application traffic or cloud DDoS services and data. It strongly advised affected AppSec customers to rotate Cloud WAF log export credentials, including Azure Blob Storage keys and SAS tokens.

The direct risk is not the contact data but the storage keys: they can grant access to log archives held outside Radware, so rotation scope depends on which customers used self-managed exports. With one reported source and no published victim count or attribution, the useful follow-up is customer telemetry from those storage services and confirmation that the API is no longer internet reachable.
