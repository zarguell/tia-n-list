Radware disclosed that an unauthorized party reached an internal-only Cloud WAF management API on 19 November 2026 while it was exposed to the public internet without authentication. The company detected the access about ten hours after the initial request, blocked the originating IP and shut down API access, then revoked and replaced internal account credentials. Radware serves more than 12,500 enterprise and telecom customers, and the incident was described in a root cause report shared with BleepingComputer.

Potentially accessed data includes customer contact details and, for a subset of customers, credentials configured to export logs to customer-controlled AWS S3, Azure Blob Storage or SFTP storage. Radware said WAF traffic inspection, certificates, end-user data, customer application traffic and cloud DDoS data were not exposed. Affected AppSec customers were told to rotate Cloud WAF log export credentials, including Azure Blob keys and SAS tokens. Watch for confirmation of how many customers held export credentials in the affected API and for evidence of downstream use of the keys.
