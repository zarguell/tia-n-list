The Node.js project shipped a coordinated security release on 2026-11-11 across the 22.x, 24.x, and 26.x lines, fixing 16 vulnerabilities (7 high, 6 medium, 3 low) in builds v22.23.5, v24.22.3, and v26.13.1. The batch is unusual for how tightly it clusters in the network stack: most flaws sit in HTTP/2 and TLS handling and are reachable remotely by unauthenticated clients, and the fixes were driven by named researchers including Chris Rohlf with Claude and Anthropic Research (CVE-2026-123863, CVE-2026-123864, CVE-2026-123865) and pimterry (CVE-2026-123872). Dependency bumps to llhttp 9.4.4 and sqlite 3.54.1 accompany the C++ fixes.

The most consequential bug is not the headline crash. CVE-2026-123866 is a use-after-free in HTTP/2 stream teardown that writes freed or unrelated heap memory, including other connections' response buffers, to a peer; combined with CVE-2026-123864, where a zero-length TLS write re-enters the parser and copies the server's own heap, including TLS private keys and other users' request bodies, into a response, this batch hands a remote unauthenticated client a confidentiality break on any shared Node.js process. That is why this deserves priority over the routine patch cycle: a single multi-tenant HTTP/2 or HTTPS terminator on default configuration can leak another tenant's traffic or key material, and on 26.x and 24.x the teardown leak is driveable purely by a remote peer sending RST_STREAM once the window-size change from 26.9.0 and 24.22.0 is present. CVE-2026-123872 adds an mTLS bypass, where a client changes the servername during TLS 1.2 renegotiation and carries its existing authentication to a stricter host.

Upgrade to v22.23.5, v24.22.3, or v26.13.1 based on your active line and restart every Node.js process that terminates TLS or serves HTTP/2 for untrusted clients. Cleartext node:http is unaffected by CVE-2026-123864, but the HTTP/2 flaws hit both TLS and cleartext, so plain HTTP/2 servers are in scope. Prioritize hosts that share one runtime across tenants, and audit any mTLS deployment that applies per-host client-certificate policy or relies on ca: [] versus an omitted ca in https.Agent (CVE-2026-123877). Hunt for the crash signature of CVE-2026-123863, a CHECK_EQ(current_nghttp2_memory_, 0) assertion failure in the HTTP/2 session destructor, and for sockets stuck in CLOSE_WAIT from CVE-2026-123865, which leaks file descriptors and memory without further attacker cost. Because the fixes live in the http2 and tls C++ layer, confirm the running binary reports the patched version rather than trusting the package lock.

Watch for public exploit code against the HTTP/2 crash and heap-leak paths, since the trigger conditions are documented and a default server qualifies, and for downstream advisories from frameworks and gateways that embed Node's HTTP/2 stack. Watch whether CVE-2026-123863, described as an incomplete variant of the older CVE-2024-27983, spawns further variants as researchers retest the stream-detach logic.
