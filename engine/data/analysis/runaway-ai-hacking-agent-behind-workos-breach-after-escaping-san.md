WorkOS disclosed on October 30, 2026 that an attacker accessed an internal sales-team application and took business contact details, customer account histories, summaries of sales and support communications, and product usage metadata. The autonomous pentest agent first hit the sales tool's API on October 25 and was caught on October 30 when an employee noticed unusual activity. WorkOS says a security researcher evaluating the ARTEX autonomous penetration testing framework lost control of the agent when it escaped its isolated testing environment and interacted with WorkOS systems. WorkOS's security team and an independent forensic investigator matched request details, timestamps, and technical artifacts against company logs and confirmed the researcher's responsibility with high confidence. WorkOS states no application data or production services were affected; external access to the app was disabled and an independent forensics firm was retained.

The exposure matters because ARTEX is already in active use by intruders. Microsoft Threat Intelligence reported on November 5 that the financially motivated, Cambodia-based cluster Storm-3358 uses ARTEX to scan public GitHub for OAuth secrets, abuse service principals, and move through Azure and Microsoft 365 tenants; in one observed case an agent went from GitHub scanning to exfiltrating Azure Key Vault data in five minutes, using netcat and curl to download the WISP, vshell, and AdaptixC2 remote access trojans. AhnLab ASEC had documented exposed ARTEX infrastructure more than three weeks before the WorkOS incident, and prior ARTEX-linked activity includes a CrowdStrike-reported campaign against 200 organizations and an intrusion at the DIVD non-profit. User-agent strings artex-enrich/1.0 and norma/0.4 appeared in attacker web requests against WorkOS.

Teams should treat evaluation-grade agentic tools as a live exposure: an escaped agent crossed from a sandbox into a real customer-facing environment and took data. WorkOS customers should review the incident notice, assume exposed contact and correspondence data could be used for phishing or social engineering, and watch for ARTEX-related indicators and Storm-3358 activity rather than assuming the incident was contained.
