Symantec and Carbon Black researchers tie a run of Warlock ransomware intrusions to a China-linked actor they track as Longlegs and Microsoft tracks as Storm-2603, now confirmed against a water utility, a telecom provider, a regional government body, and a university. Initial access comes from exploiting on-premises SharePoint through the ToolShell chain, CVE-2025-49704, CVE-2025-49706, CVE-2025-53770, and CVE-2025-53771, the same zero-days Microsoft saw in state-backed use by Linen Typhoon and Violet Typhoon in August. The group surfaced in June 2025, drops a web shell built to run across multiple SharePoint versions, and deploys an AV/EDR-killing tool before encryption. In the intrusion that began July 22, that tool disabled protection software on at least 40 hosts within about two hours, after which Warlock encrypted at least 33.

The victim set argues the actor selects by language cluster, not by sector: two months of activity concentrated on Portuguese and Spanish-speaking countries across Europe, Africa, and Latin America, which means exposure is a function of unpatched on-premises SharePoint estate in those regions rather than of any critical-infrastructure targeting list. The ToolShell CVEs are KEV-listed and fixes have shipped since July 2025, so this is neglect exploitation, and every org still running internet-facing SharePoint is a candidate victim regardless of industry. For water and telecom operators the damage case is worse than data loss: the corporate network that got encrypted is the same one that schedules crews, billing, and in many deployments the supervisory support tooling, so regional service continuity rides on an asset Microsoft has been begging people to patch for a year. The multi-version web shell also means patching alone does not evict the actor; persistence and stolen key material survive an update, so any SharePoint that was exposed before patching must be treated as compromised until swept.

Apply the July 2025 Microsoft security updates for SharePoint Server Subscription Edition, 2019, and 2016, and rotate ASP.NET machine keys on every SharePoint server, because the ToolShell shells are built to exfiltrate MachineKey material and a patch does not invalidate keys already stolen. Pull on-prem SharePoint behind a VPN or WAF instead of direct internet exposure. Hunt in IIS W3SVC logs for POST requests to /_layouts/15/ToolPane.aspx, look for shells such as spinstall0.aspx under TEMPLATE\LAYOUTS in Web Server Extensions\16, and diff machineKey entries in web.config against change control. Because the actor blinded EDR on 40 hosts in two hours before encrypting 33, also alert on mass protection-service stop events and driver-based tampering; once file encryption starts, the detection opportunity is already spent.

Two developments would change the assessment. If the Portuguese and Spanish-language victim concentration extends into Iberian or Latin American utilities and government networks, the campaign is scaling along its language seam and regional operators should assume targeting. If the EDR-killing tool moves from selective deployment to fleet-wide use across intrusions, Warlock is optimizing for speed over stealth and the effective window between first access and encryption will shrink below the two hours observed on July 22.
