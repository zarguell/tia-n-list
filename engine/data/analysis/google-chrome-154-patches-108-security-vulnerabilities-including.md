The headline and the tracked CVEs describe two different advisories a week apart. Google promoted Chrome 154 to stable on September 22, 2026 as 154.0.8037.57/.58 for Windows and Mac with 108 security fixes, 11 of them critical, all memory-safety defects and seven in the graphics path: three ANGLE buffer overflows including CVE-2026-95350, a $5,000-bounty bug reported by STAR Labs researchers on 2026-08-24, two GPU out-of-bounds writes, and two WebGL bugs. The September 29 point release, 154.0.8037.92/.93 on Windows and macOS and 154.0.8037.92 on Linux, fixed 32 more with one critical, CVE-2026-102331, an ANGLE buffer overflow reported by @mfx on 2026-08-24, alongside V8 type confusions CVE-2026-102323, CVE-2026-102326, and CVE-2026-102328 credited to OpenAI Codex Security researcher amyb, who filed five bugs across the two releases. Neither advisory flags anything as exploited in the wild.

The count in the headline belongs to the promotion build, while all four CVEs this story tracks belong to the September 29 release, so a fleet that patched to 154.0.8037.57 on day one still runs a browser vulnerable to CVE-2026-102331. Severity is not uniform across the 108 either. Tenable's plugin for the point release scores CVE-2026-102331 at CVSS 9.6 and describes arbitrary code execution outside the sandbox from a crafted HTML page, while the V8 type confusions execute inside the sandbox and the PictureInPicture and GPU bugs CVE-2026-102324 and CVE-2026-102301 presuppose a renderer the attacker has already compromised. That makes the ANGLE overflow the drive-by risk that breaks Chrome's containment model on its own, and the amyb V8 bugs the natural renderer foothold to pair with it in a chain. Tenable lists no known exploits for either release, which is the window defenders get.

The patch target is 154.0.8037.92 or later on Windows, macOS, and Linux, and 154.0.8037.92 on Android, which Google states carries the same security fixes as the corresponding desktop release. Fleets on Extended Stable should ride 152.0.7977.149, shipped September 29, and managed ChromeOS runs a separate train: LTS 144.0.7559.264, shipped September 28, carries the same Fullscreen use-after-free, CVE-2026-95313, as the desktop promotion. Google may keep bug details restricted until a majority of users are updated, so working exploit code for the graphics bugs historically surfaces in the days after rollout peaks, which is the argument against deferring this to the next patch cycle. For hunting, every critical here is reachable from crafted web content: watch for Chrome GPU and renderer process crashes correlated with user browsing, and pull the 15 IOCs and 9 detections published with Threadlinqs report TL-2026-2803 on this release.

Two developments would move this from patch story to incident. Google lifting the access restrictions on the September 29 bugs once its update majority is reached signals that public proof-of-concept code is imminent. A KEV listing or a vendor note that CVE-2026-102331, or any of the three promotion criticals in ANGLE, has been seen exploited would flip this from routine browser hygiene to emergency patching.
