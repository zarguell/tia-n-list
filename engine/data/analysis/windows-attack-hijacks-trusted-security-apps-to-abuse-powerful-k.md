Researcher Xusheng Li documented a new Windows attack technique called Bring Your Own Trusted Caller (BYOTC) that abuses the trust relationships between signed security applications and their kernel drivers. Unlike the familiar BYOVD approach where attackers exploit a vulnerable signed driver, BYOTC targets drivers that are working correctly but trust specific user-mode applications. The attacker compromises or injects code into the trusted application, then the driver accepts malicious requests because they appear to come from an approved client.

The proof-of-concept used Malwarebytes' mbamchameleon.sys driver, which includes a legitimate ZwTerminateProcess capability restricted to processes signed by Malwarebytes. BYOTC bypasses this by impersonating the trusted caller rather than exploiting the driver itself. This is significant because the entire class of security software, anti-cheat, and inspection tools that restrict driver operations to specific signed binaries is potentially affected. The technique requires no memory corruption and no vulnerable driver, just the ability to execute code within the trusted process's context.

Defenders should audit which drivers on their systems enforce caller-based restrictions and whether those restrictions hold under process injection scenarios. The attack surface is broad because BYOTC does not depend on a specific CVE. Security vendors that gate driver capabilities by checking the signing identity of the caller need to verify that their trust checks cannot be circumvented through process hollowing, DLL injection, or child process manipulation.
