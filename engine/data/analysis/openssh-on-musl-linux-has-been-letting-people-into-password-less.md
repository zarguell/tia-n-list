OpenSSH on musl-based Linux systems has shipped an emergency fix for a decade-old authentication bypass that lets a remote attacker log into accounts configured to reject password logins. The flaw, tracked as CVE-2026-123158 and nicknamed sshole, carries a CVSS score of 8.1. It affects OpenSSH servers running on the musl C library with PAM disabled, the default build of the openssh-server package on Alpine Linux, and also OpenWrt, Buildroot, and Yocto. Accounts whose password field in /etc/shadow holds only an asterisk can be accessed with any password between 257 and 1,024 characters. Researcher Ozgun Kultekin disclosed the issue on November 5-6, 2026, and said the flaw has existed since 2016.

The bug traces to OpenSSH's 2016 patch for CVE-2016-6210, a username-enumeration fix that made sshd run password hashing even for accounts with no usable password hash. On musl systems, the crypt function returns an asterisk when hashing fails, including when a submitted password exceeds musl's 255-character limit, so the server mistakenly treats an overlong password as a valid match. OpenSSH developer Damien Miller released version 10.6p2 on November 5, 2026, citing rapid rediscovery of bugs by AI agents as the reason for the fast timeline. Alpine Linux published fixed packages for every branch from 3.16 to edge the same day. No exploitation in the wild had been reported at release time, but the bug is simple to trigger once its conditions are met.

Administrators on affected systems should apply OpenSSH 10.6p2 or the Alpine fixed packages and restart sshd, or set PasswordAuthentication to no as an interim mitigation. The watch item is whether in-the-wild exploitation or a CISA KEV entry appears, given how easily the bug can be triggered and how many musl-based devices and containers are exposed.
