OpenSSH "sshole" (CVE-2026-123158, CVSS 8.1) is a decade-old authentication bypass affecting OpenSSH servers on musl-based Linux distributions such as Alpine, OpenWrt, Buildroot, and Yocto, when PAM is disabled, which is the default for Alpine's openssh-server package. Accounts configured to block password logins by storing an asterisk (*) in /etc/shadow can be accessed with any password of 257 to 1,024 characters: musl's password-hashing function returns "*" on error for oversized input, and OpenSSH misinterprets that as a match. Researcher Ozgun Kultekin discovered and disclosed the flaw. OpenSSH shipped an emergency release, version 10.6p2, on November 5, 2026, and Alpine published fixed packages for all branches from 3.16 to edge the same day.

The flaw reaches containers, routers, and IoT devices running musl-based distributions, potentially exposing root and other locked accounts. Exploitation attempts began November 5, the day a proof-of-concept became available, with successful exploitation recorded the following day. Multiple firms confirmed attacks in which adversaries executed commands, stole credentials, and established persistent access. SANS ISC honeypots are now seeing scans for the vulnerability, though their data is limited because they capture only the first 255 characters of SSH passwords.

Patch immediately to OpenSSH 10.6p2 or the corresponding distribution packages, and hunt for SSH sessions using passwords of 257 or more characters. Watch for CISA adding CVE-2026-123158 to the KEV catalog and for slow patching in container images and embedded devices, which are the most likely to remain exposed.
