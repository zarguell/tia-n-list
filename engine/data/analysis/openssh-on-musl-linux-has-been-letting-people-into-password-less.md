CVE-2026-123158, nicknamed "sshole," is a high-severity authentication bypass in OpenSSH rated CVSS 8.1 that affects Linux distributions using the musl C library with PAM disabled, including Alpine Linux, OpenWrt, Buildroot, and Yocto. Accounts whose password field is set to an asterisk (*) to block password logins, including root and key-only users, accept any password between 257 and 1,024 characters. The flaw traces to a 2016 patch for CVE-2016-6210: OpenSSH began hashing passwords even for accounts with no usable hash, and musl's crypt() returns "*" on failure for oversized inputs, which OpenSSH then treats as a match.

OpenSSH 10.6p2 shipped on November 5, 2026, the same day as Alpine's fixed packages for branches 3.16 through edge, and exploitation began within hours of a proof-of-concept release. Multiple firms have confirmed active exploitation, including GreyNoise and Defused, with honeypots recording scan attempts; SANS notes its honeypots only capture the first 255 characters of passwords, which may undercount attempts. OpenSSH maintainers cited rapid AI-driven bug rediscovery as the reason for the short embargo.

Affected systems should be patched to OpenSSH 10.6p2 or later and sshd restarted, or password authentication disabled. Watch for exploitation against containers, routers, and IoT devices running Alpine or other musl-based distributions, and for any spread beyond the accounts with asterisk password fields.
