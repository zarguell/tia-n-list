OpenSSH on Linux systems built on the musl C library has been letting attackers into password-less accounts since 2016. On musl-based systems where sshd checks passwords itself instead of using PAM -- Alpine Linux is an example -- accounts that should never accept a password will accept any password longer than 256 characters. OpenSSH 10.6p2, released November 5, 2026, ships a workaround for the critical flaw, and OpenSSH developer Damien Miller advised administrators to set PasswordAuthentication to no or disable SSH entirely.

The story record tracks CVE-2016-6210 and CVE-2026-123158. CVE-2026-123158 was added to CISA's Known Exploited Vulnerabilities catalog on November 9 based on exploitation evidence, and BleepingComputer reported hackers exploiting the SSHole OpenSSH flaw to breach Linux systems. Seventy-one events across forty sources feed this story, which scores 10.0 and carries the KEV flag.

What to watch: the federal patch deadline tied to the KEV listing, confirmation of in-the-wild exploitation campaigns, and whether musl-based distributions ship fixed OpenSSH builds beyond the 10.6p2 workaround. Until then, disabling password authentication is the effective mitigation.
