CVE-2026-123158, nicknamed "sshole," is a high-severity authentication bypass in OpenSSH on Linux systems that use the musl C library with PAM disabled, the default openssh-server build on Alpine Linux, OpenWrt, Buildroot, and Yocto. Disclosed on November 5, 2026 by researcher Ozgun Kultekin, the flaw lets a remote attacker log in to accounts whose password field is set to an asterisk to block password logins by sending any password between 257 and 1,024 characters. The root cause traces to a 2016 change introduced to fix CVE-2016-6210, a username enumeration issue: OpenSSH began hashing passwords even for accounts without a usable password hash to keep response times uniform, but musl's crypt() returns an asterisk on failure, including when a password exceeds 256 bytes, and sshd treats that returned asterisk as a match against the stored asterisk. Affected accounts include root, key-only users created with adduser without a password, the Alpine user in official tiny-cloud images, and users coming from a directory service through musl-nscd. The flaw does not affect glibc-based distributions such as Ubuntu or Debian, and it does not affect accounts that have a valid password hash.

OpenSSH 10.6p2 shipped on November 5, 2026 as an emergency fix, the same day Alpine published fixed packages for every branch from 3.16 to edge, and exploit code became available roughly four hours after disclosure. CISA added CVE-2026-123158 to the Known Exploited Vulnerabilities catalog on November 9 with a federal due date of November 12. Threat intelligence firms recorded exploitation beginning on November 5, with GreyNoise and SANS ISC honeypots observing password lengths beyond the usual 255-character limit, and BleepingComputer reported successful breaches the following day. OpenSSH maintainer Damien Miller said the team accelerated the release because of recent cases of rapid bug rediscovery by AI agents, and OX Security's review found the flaw by building sshd across glibc, musl, PAM, and no-PAM combinations and running roughly 17,600 deliberate tests.

Upgrade to OpenSSH 10.6p2 or the Alpine fixed package and restart sshd to replace the running daemon, or set PasswordAuthentication=no and restart sshd as an interim measure. Inventory accounts with an asterisk in the password field, especially root and key-only service accounts, and verify that no long-password authentication attempts succeeded before patching. Watch for CISA's November 12 deadline, any change in exploitation volume, and whether additional musl-based distributions publish advisories, since the affected combination is common in container and embedded images that may not be covered by standard patch management.
