OpenSSH 10.6p2, released 5 November 2026, addresses CVE-2026-123158, a password authentication bypass dubbed "sshole" affecting OpenSSH built against the musl C library with PAM disabled, the default openssh-server configuration on Alpine Linux. An attacker who can reach the SSH port can log in to accounts configured to reject passwords, such as root with an asterisk in /etc/shadow, by sending any password between 257 and 1,024 bytes. The flaw affects Alpine Linux, OpenWrt, Buildroot, Yocto, and other musl-based distributions, and has existed since 2016.

The root cause traces to a patch for the 2016 username enumeration flaw CVE-2016-6210: OpenSSH began performing password hashing even for accounts with no usable hash to avoid timing side channels, and musl's crypt() returns "*" on failure including when an input exceeds its 256-byte limit, causing the comparison to succeed. Researcher Ozgun Kultekin (Wakefield) discovered and published the issue; OX Security noted it was located by building sshd across glibc, musl, PAM, and no-PAM combinations and running roughly 17,600 tests. Alpine shipped fixed packages for every branch from 3.16 to edge the same day. No in-the-wild exploitation had been reported at release, although SANS ISC honeypots later saw an increase in attempts, with data limited to the first 255 characters of passwords.

The CVSS score is 8.1 and the bug is trivial to trigger once conditions are met, so the exposure window for unpatched systems is the main concern. Administrators should apply OpenSSH 10.6p2 or the Alpine fixed packages, restart sshd, or as an interim mitigation set PasswordAuthentication=no and restart sshd, or disable SSH entirely. Watch for continued scanning activity and for rediscovery by automated tooling, which OpenSSH cited as a reason to shorten embargo periods.
