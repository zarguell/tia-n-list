A vulnerability nicknamed sshole affects OpenSSH on musl-based Linux systems such as Alpine Linux, OpenWrt, Buildroot, and Yocto. Researcher Ozgun Kultekin disclosed the flaw, which has existed since 2016. On systems where sshd checks passwords itself instead of through PAM, accounts with a disabled password hash (an asterisk in /etc/shadow) accept any password longer than 256 characters, because musl's crypt() returns an asterisk when hashing fails on long input and OpenSSH compares the two asterisks as a match.

The issue traces to a 2016 patch for CVE-2016-6210, a username-enumeration fix that made OpenSSH run password hashing even for accounts without usable password hashes. glibc-based distributions such as Debian and Ubuntu are not affected. OpenSSH 10.6p2, released November 5 2026, fixes the issue; OpenSSH developer Damien Miller advised setting PasswordAuthentication to no or disabling SSH entirely on affected systems. Alpine Linux has shipped fixed OpenSSH packages.

What to watch: confirmation that the new flaw is tracked as CVE-2026-123158, any reports of active exploitation, and updated packages from other musl distributions. Administrators should verify whether password authentication is enabled on musl-based hosts with shadow-disabled accounts and rotate credentials for any accounts that may have been accessed.
