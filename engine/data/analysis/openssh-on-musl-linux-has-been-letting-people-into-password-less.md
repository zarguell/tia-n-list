A decade-old flaw in OpenSSH on musl-based Linux, dubbed *sshole and tracked as CVE-2026-123158, lets attackers log into accounts explicitly configured to block password authentication by submitting an oversized password. Researcher Ozgün Kultekin of Wakefield disclosed the flaw on November 5 and said it has existed since 2016. It affects OpenSSH servers on musl libc distributions including Alpine Linux, OpenWrt, Buildroot, and Yocto under certain authentication configurations, and any password between 257 and 1,024 characters works.

The root cause traces to a 2016 OpenSSH patch for username enumeration flaw CVE-2016-6210, which made OpenSSH run password hashing even for accounts with no usable password hash, the mechanism meant to block password logins via an asterisk in /etc/shadow. On musl systems the crypt() function returns an asterisk when hashing fails, including for passwords beyond its limit, so the guardrail misfires and the oversized password is accepted. OpenSSH 10.6p2, shipped November 5, contains the workaround; OpenSSH developer Damien Miller advised affected administrators to set PasswordAuthentication=no or disable SSH entirely in the meantime.

What to watch: any musl-based device with SSH exposed and password authentication nominally disabled (Alpine, OpenWrt, Buildroot, Yocto deployments) is potentially reachable with a 257-plus-character password, so inventorying affected hosts and enforcing the workaround is the immediate priority. Expect exploitation reports now that disclosure details are public.
