A flaw in OpenSSH on musl-based Linux, dubbed *sshole and tracked as CVE-2026-123158, lets attackers log into accounts that are configured to reject password authentication. Researcher Ozgun Kultekin says the flaw has existed since 2016 and affects OpenSSH servers on Alpine Linux, OpenWrt, Buildroot, and Yocto under certain authentication configurations. The issue is limited to Linux distributions using the musl C library.

Accounts locked by replacing the password hash with an asterisk in /etc/shadow should reject every password. However, a 2016 OpenSSH patch for username enumeration CVE-2016-6210 made OpenSSH perform password hashing even for accounts without a usable hash. On musl systems the crypt() function returns an asterisk when hashing fails, including for passwords longer than 255 characters, so OpenSSH treats them as matching the stored asterisk. Any password between 257 and 1,024 characters works.

OpenSSH shipped version 10.6p2 on November 5, 2026 with a workaround for the issue. OpenSSH developer Damien Miller advised administrators of affected systems to set PasswordAuthentication to no or disable SSH entirely until patched.
