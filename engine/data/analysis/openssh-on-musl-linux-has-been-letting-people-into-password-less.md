OpenSSH 10.6p2, released on 2026-11-05, contains an emergency workaround for a critical authentication bypass in sshd affecting Linux systems built on musl libc with PAM disabled, such as Alpine Linux. On these systems sshd performs its own password checks, and accounts that should reject every password instead accept any password longer than 256 characters, letting an attacker who can reach the SSH port log in to password-disabled accounts.

The flaw, dubbed *sshole by researcher Ozgün Kultekin of Wakefield, has existed since 2016 and comes from how OpenSSH handles password verification errors. OpenSSH developer Damien Miller advised administrators to set PasswordAuthentication to no or disable SSH entirely and restart sshd. Alpine Linux published fixed packages for every supported release back to version 3.16.

Systems running musl-based OpenSSH without PAM should be patched or have password authentication disabled immediately. Because the bug is old and simple to exploit, exposed instances are likely already in scanning or attack traffic.
