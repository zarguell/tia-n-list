A decade-old authentication bypass in OpenSSH running on the musl C library lets remote attackers log into accounts that have password logins disabled. Dubbed sshole and tracked as CVE-2026-123158, the flaw affects Alpine Linux, OpenWrt, Buildroot and Yocto systems where PAM is disabled, including the default Alpine openssh-server package. Researcher Ozgun Kultekin disclosed the issue, which has existed since 2016.

The bug traces to a 2016 OpenSSH patch for username enumeration vulnerability CVE-2016-6210, which made sshd perform password hashing even for accounts with no usable hash. Accounts marked with an asterisk in /etc/shadow to block password logins can be accessed by submitting an oversized password, because musl's crypt() returns an asterisk when hashing fails; any password between 257 and 1,024 characters is accepted. OpenSSH shipped fixed version 10.6p2 on November 5, 2026, and Alpine published fixed packages for every branch from 3.16 to edge the same day.

No in-the-wild exploitation had been reported at release, but the OpenSSH team said the bug is simple to trigger once its conditions are met. Administrators running musl-based OpenSSH with PAM disabled should upgrade immediately.
