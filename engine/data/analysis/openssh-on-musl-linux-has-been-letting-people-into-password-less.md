OpenSSH 10.6p2 shipped on November 5, 2026 as an emergency release for CVE-2026-123158, nicknamed "sshole," an authentication bypass in sshd on Linux systems built on the musl C library with PAM disabled. That combination is the default openssh-server packaging on Alpine Linux, and the same class of systems includes OpenWrt, Buildroot, and Yocto. Researcher Ozgun Kultekin of Wakefield disclosed the flaw and released details; it has existed since 2016. Accounts whose password field contains only "*" (no password set, often root or service accounts) accept any password between 257 and 1,024 characters. The root cause traces to a 2016 change made for CVE-2016-6210: OpenSSH began hashing passwords even for accounts with no usable hash, to avoid username enumeration via timing. On musl, crypt() returns "*" when hashing fails, including when the input exceeds its 256-character limit, so an overlong password hashes to the same "*" stored for the locked account and authentication succeeds.

No in-the-wild exploitation was reported at release, but the bug is trivial to trigger once its conditions are met, and SANS ISC honeypots later saw increased scan activity for it. OpenSSH developer Damien Miller noted the team shipped quickly because AI agents have recently rediscovered bugs within hours, making long embargoes risky. The exposed population is broad but specific: containers, routers, and IoT or embedded devices running musl-based distributions with SSH reachable, not mainstream glibc distributions with PAM enabled. Attackers need only a reachable SSH port and a valid account name.

Remediation is available now: upgrade to OpenSSH 10.6p2, or apply Alpine's fixed packages (branches 3.16 through edge). Immediate mitigations are PasswordAuthentication=no or disabling SSH entirely, followed by restarting sshd. Watch for unpatched embedded and container images that rarely get updates, plus authentication logs showing unusually long passwords or logins to accounts that should never accept one. CVE-2016-6210 is the historical trigger, not a separate active issue.
