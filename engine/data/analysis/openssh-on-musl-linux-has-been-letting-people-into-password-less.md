A decade-old authentication bypass in OpenSSH on musl-based Linux, dubbed *sshole and tracked as CVE-2026-123158, lets attackers log into accounts that should never accept a password by submitting any password between 257 and 1,024 characters. It affects Alpine Linux, OpenWrt, Buildroot, and Yocto, all of which use the musl C library. The OpenSSH team shipped version 10.6p2 on November 5, 2026 to address it.

The root cause traces to a 2016 patch for CVE-2016-6210, a username enumeration vulnerability. To prevent timing-based username enumeration, OpenSSH was modified to perform password hashing even when an account had no usable password hash, including accounts configured with an asterisk in /etc/shadow to block password logins. On glibc systems this is harmless, but musl's crypt() function also returns an asterisk when password hashing fails, including when a submitted password exceeds its 25-byte limit. The oversized password causes crypt() to fail and return *, which matches the stored * and authenticates the account.

Administrators running musl-based distributions should upgrade to OpenSSH 10.6p2 and review accounts configured with * in /etc/shadow for unexpected access. Watch for distribution-specific advisories for Alpine, OpenWrt, Buildroot, and Yocto, and for any reports of in-the-wild exploitation against internet-facing embedded or container hosts.
