OpenSSH 10.6p2 patches CVE-2026-123158 ("sshole"), a high-severity authentication bypass (CVSS 8.1) affecting sshd on Linux systems built against musl libc with PAM disabled, notably Alpine Linux, OpenWrt, Buildroot, and Yocto. The flaw lets a remote attacker authenticate to accounts whose /etc/shadow password field holds only an asterisk (including root on affected distros) by submitting any password between 257 and 1,024 characters. Researcher Ozgun Kultekin disclosed it on November 5-6, 2026; the bug has existed since 2016, tracing to OpenSSH's earlier fix for CVE-2016-6210.

The root cause is an interaction between OpenSSH password validation and musl's crypt(): when a password exceeds musl's 255-character limit, crypt() returns an asterisk, which matches the asterisk stored for password-less accounts, so sshd treats the overlong password as valid. OpenSSH developer Damien Miller cited rapid rediscovery of bugs by AI agents as the reason for the fast release without a long embargo. Alpine Linux published fixed packages for branches 3.16 through edge. Mitigations: apply OpenSSH 10.6p2 or Alpine fixed packages and restart sshd, or set PasswordAuthentication no.

New telemetry from SANS ISC honeypots (Cowrie) shows an increase in attempts to exploit the vulnerability since its disclosure, indicating active scanning and likely exploitation attempts in the wild, though no confirmed compromises or victim counts have been reported. Watch items: whether CISA adds CVE-2026-123158 to KEV, whether confirmed in-the-wild compromises or implants appear, and patching of the many musl-based containers and embedded devices that may lag Alpine's fixes.
