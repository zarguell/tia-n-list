A decade-old authentication bypass in OpenSSH on musl-based Linux, dubbed SSHole (also written *sshole) and tracked as CVE-2026-123158 with a CVSS score of 8.1, lets an attacker log into accounts that should never accept a password by submitting any password between 257 and 1,024 characters. It affects OpenSSH sshd built against the musl C library with PAM disabled, which covers Alpine, OpenWrt, Buildroot, and Yocto. The OpenSSH team shipped the fix in version 10.6p2 on November 5, 2026, the same day Alpine published updated openssh packages. Researcher Özgün Kültekin is credited with the discovery.

The root cause is a 2016 change made for CVE-2016-6210, a username-enumeration fix. To blunt timing-based enumeration, OpenSSH was altered to hash the submitted password even when an account has no usable hash, including accounts locked with an asterisk in /etc/shadow. On glibc that is harmless, but musl's crypt() also returns an asterisk when hashing fails, and it fails for any password longer than roughly 256 bytes. The returned asterisk then matches the stored asterisk, and sshd treats the login as valid. In Alpine the reachable accounts include root, any key-only user created without a password, the alpine user in the official tiny-cloud images, and users arriving through musl-nscd. Damien Miller, explaining the rushed release, said the team had observed multiple cases of rapid bug rediscovery by AI agents within hours and now considers long embargoes dangerous.

This is no longer theoretical. Public exploit code appeared within hours of the patch, exploitation attempts began November 5, and successful intrusions were recorded November 6. Defused observed a small number of actors attempting the bypass, GreyNoise tracked scan activity, and the SANS ISC saw increased exploitation attempts in its Cowrie honeypots. CISA added CVE-2026-123158 to the KEV catalog, and reporting describes attackers using access to install a Python backdoor for persistence. Administrators running musl-based distributions should confirm they are on OpenSSH 10.6p2 or later, restart sshd to replace the running daemon, and prefer disabling password authentication entirely. Watch for distribution advisories from Alpine, OpenWrt, Buildroot, and Yocto and for follow-on intrusions against internet-facing embedded and container hosts.
