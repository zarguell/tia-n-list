SSHole (CVE-2026-123158) is an authentication bypass in OpenSSH that affects Linux systems running the musl C library with PAM disabled, including Alpine Linux, OpenWrt, Buildroot, and Yocto. Accounts configured to block password logins by storing an asterisk in the shadow password field can be accessed by supplying any password between 257 and 1024 characters. The flaw traces to a 2016 change made to address CVE-2016-6210: to prevent username enumeration, sshd hashes supplied passwords even for accounts with no usable password hash. On musl, crypt() returns "*" when hashing fails on oversized input, which matches the stored "*" and causes authentication to succeed. On Alpine this affects root, key-only users created without a password, the Alpine user in official tiny-cloud images, and directory-service users via musl-nscd. The vulnerability has existed since 2016.

SecurityWeek reports that threat actors have started exploiting the flaw in the wild. OpenSSH 10.6p2 was released with a workaround, and OpenSSH developer Damien Miller advised administrators of affected systems to immediately set PasswordAuthentication=no or disable SSH entirely. The risk is concentrated in minimal and container-oriented distributions where root and service accounts often have no password hash, so internet-reachable sshd instances on those platforms are the priority for patching.

What to watch next is the rollout of fixed packages across Alpine, OpenWrt, Buildroot, and Yocto, whether additional exploitation campaigns appear before patching completes, and whether organizations discover unauthorized access to accounts that were assumed passwordless. Interim mitigations should be verified on every musl-based host, not only on systems explicitly identified as Alpine.
