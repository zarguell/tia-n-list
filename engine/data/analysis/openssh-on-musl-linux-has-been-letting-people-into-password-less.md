CVE-2026-123158, nicknamed 'sshole,' is an authentication bypass in OpenSSH's sshd that affects Linux systems running OpenSSH on the musl C library with PAM disabled, the default configuration on Alpine Linux. The flaw, rated CVSS 8.1, lets a remote attacker log in to accounts whose password field is set to '*' (no password ever set) by submitting a password between 257 and 1,024 characters. On affected distributions such as Alpine, OpenWrt, Buildroot and Yocto, that includes privileged accounts like root.

The bug traces to a 2016 change made to defeat username enumeration (CVE-2016-6210): OpenSSH began hashing passwords even for accounts without usable hashes, and musl's crypt() returns '*' on hashing failure, including for overlong inputs, which OpenSSH then misread as a successful match. Researcher Ozgun Kultekin disclosed the issue; OpenSSH shipped an emergency 10.6p2 release and Alpine published fixes for branches 3.16 through edge on November 5, 2026. OpenSSH's Damien Miller cited rapid AI-driven bug rediscovery as the reason for skipping a long embargo.

No exploitation was reported at release, but the trigger is trivial once conditions are met, and CISA has since added CVE-2026-123158 to its KEV catalog. Operators of Alpine-based and other musl systems should patch and restart sshd or disable password authentication. Expect follow-up scanning and opportunistic exploitation against internet-facing Alpine hosts and embedded devices.
