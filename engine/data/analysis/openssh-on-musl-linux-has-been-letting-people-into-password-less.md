CVE-2026-123158, nicknamed SSHole, is a high-severity authentication bypass (CVSS 8.1) in OpenSSH's sshd on musl libc systems with PAM disabled, the default configuration on Alpine Linux, OpenWrt, Buildroot, and Yocto. A remote attacker can log in to accounts whose password field is "*" (including root on Alpine, key-only users created without a password, and certain directory-service users) by supplying any password between 257 and 1,024 characters, because musl's crypt() returns "*" on failure for overlong inputs and sshd matches it against the stored value.

The flaw traces to a 2016 change made to defeat username enumeration (CVE-2016-6210), which made sshd hash passwords even for accounts with no usable password hash. Researcher Ozgun Kultekin disclosed it on November 5, 2026; OpenSSH shipped an emergency fix in 10.6p2 and Alpine released patched packages for branches 3.16 through edge the same day. OpenSSH developer Damien Miller cited rapid AI-driven rediscovery as the reason for the short embargo.

CISA subsequently added CVE-2026-123158 to the Known Exploited Vulnerabilities catalog, indicating in-the-wild exploitation despite none having been reported at release. Affected systems should patch and restart sshd, or disable password logins and restart the daemon. Containers, routers, and IoT devices built on musl-based distributions are broadly at risk, so defenders should verify sshd versions, confirm PAM status, and audit for accounts with "*" password fields.
