OpenSSH on musl-based Linux carries an authentication bypass dubbed *sshole, tracked as CVE-2026-123158 with CVSS 8.1, that lets anyone log into accounts configured to block password logins by submitting any password between 257 and 1,024 characters. Researcher Ozgün Kültekin of Wakefield disclosed it November 5 and dates it to 2016. Affected targets are sshd on musl libc distributions without PAM, including Alpine Linux, OpenWrt, Buildroot and Yocto, where accounts locked with an asterisk in /etc/shadow accept the oversized password. The root cause is a 2016 OpenSSH fix for username enumeration flaw CVE-2016-6210 that made sshd hash passwords even for unusable hashes; musl's crypt() returns an asterisk on hashing failure, so the guardrail misfires. OpenSSH 10.6p2, shipped November 5, contains the fix.

Vendor and official guidance hardened on November 6. Alpine Linux urged immediate patching with an sshd restart to replace the running daemon, or disabling password logins with a restart as a workaround, and clarified the attacker needs the name of an account whose password is locked. SecurityWeek's follow-up quotes OpenSSH developer Damien Miller saying the flaw is not in sshd itself but is exploitable through it, and that the release was rushed because AI agents have repeatedly rediscovered bugs within hours, making long embargoes a practice that mainly benefits attackers. Hungary's NBSZ NKI also flagged the flaw at high severity under the same CVE and CVSS.

Inventory every musl-based host with SSH reachable, especially Alpine containers, routers and embedded builds, and confirm 10.6p2 plus a daemon restart rather than assuming a package install is enough. Watch for exploitation reports now that the 257-byte trigger is public and AI-assisted rediscovery is explicitly in play.
