OpenSSH on musl-based Linux systems with PAM disabled, including Alpine, OpenWrt, Buildroot, and Yocto, accepted any password between 257 and 1,024 bytes as valid for accounts whose /etc/shadow field is '*'. The flaw, CVE-2026-123158 and nicknamed SSHole, was disclosed by security researcher Özgün Kültekin and fixed in OpenSSH 10.6p2 on November 5. It has been present since 2016.

The root cause is a mismatch in password-hash handling. When an account has no password hash, sshd borrows the salt from another account's hash to process the login. For passwords longer than 256 bytes, musl's crypt() fails and returns '*' instead of NULL, which matches the '*' stored for the target account, so sshd treats the login as successful. Affected accounts include root, key-only users created with adduser, the Alpine user in official tiny-cloud images, and directory-service users reached through musl-nscd.

Exploitation began on November 5, the same day a proof-of-concept became available, and successful exploitation was recorded the following day. Attackers used the bypass to execute commands, steal credentials, and establish persistent access. CISA added CVE-2026-123158 to its Known Exploited Vulnerabilities catalog on November 9, with a US federal due date of November 12. Defused reported a small number of actors attempting exploitation, and GreyNoise recorded honeypot hits.

Update OpenSSH to 10.6p2 and restart sshd on every musl host, and check authentication logs for "Accepted password" entries on accounts that should reject password logins.
