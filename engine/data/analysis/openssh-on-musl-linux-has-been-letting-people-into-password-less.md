OpenSSH and Alpine Linux warned of a severe but narrow authentication bypass tracked as CVE-2026-123158, affecting sshd on Linux systems built on the musl C library where sshd checks passwords itself instead of through PAM. On affected hosts, accounts that should never accept a password will accept any password longer than 256 characters. The underlying behavior reportedly dates to 2016, which is why coverage calls it the hole that let people into password less accounts for a decade. Standard glibc distributions with PAM are not affected.

The fix status is a workaround release rather than a full root cause patch. OpenSSH 10.6p2 shipped on November 5 with an emergency mitigation, and developer Damien Miller advised administrators of affected systems to set PasswordAuthentication=no and restart sshd, or disable SSH entirely, until properly patched. Alpine published its own advisory, and scanner coverage including a free sshole scanner from pentest tools now lets owners check exposure.

The concrete artifact to act on is the 256 character threshold combined with musl without PAM, which makes this fingerprintable in audits. Owners of Alpine and other musl based images, especially containers and embedded builds with sshd enabled, should inventory for the combination and apply the Miller workaround now. Watch for Alpine and OpenSSH follow up releases carrying the permanent fix and for exploit attempts repurposing the public scanner logic.
