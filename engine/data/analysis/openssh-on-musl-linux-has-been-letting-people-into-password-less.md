OpenSSH on Linux systems running the musl C library without PAM has contained an authentication bypass since 2016. On accounts blocked by an asterisk in /etc/shadow, an oversized password longer than 256 characters is accepted, because musl's crypt() returns an asterisk when hashing fails. The behavior traces to an OpenSSH patch from 2016 for username enumeration CVE-2016-6210, which made OpenSSH hash passwords even for accounts with no usable hash.

Researcher Ozgun Kultekin disclosed the flaw, dubbed *sshole, on November 5, 2026. It affects Alpine Linux, OpenWrt, Buildroot and Yocto systems and other musl-based images. OpenSSH 10.6p2 was released the same day with a workaround, and OpenSSH developer Damien Miller advised setting PasswordAuthentication=no or disabling SSH entirely.

Alpine's own advisory and multiple vendor confirmations appeared on November 5. Watch for patches beyond the workaround and for evidence of exploitation in the wild. Concrete artifacts: CVE-2016-6210, OpenSSH 10.6p2 workaround.
