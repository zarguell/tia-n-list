SSHole (CVE-2026-123158, CVSS 8.1) is an authentication bypass in OpenSSH that affects Linux systems running on the musl C library with PAM disabled, including Alpine Linux, OpenWrt, Buildroot, and Yocto. Accounts configured to block password logins by storing an asterisk in the shadow password field accept any password between 257 and 1,024 characters. The flaw traces to a 2016 change made to address CVE-2016-6210: to prevent username enumeration, sshd hashes supplied passwords even for accounts with no usable password hash. On musl, crypt() returns "*" when hashing fails on oversized input, which matches the stored "*" and causes authentication to succeed. Researcher Ozgun Kultekin of Wakefield disclosed the issue last week; it has existed since 2016. OX Security reproduced it by building sshd across glibc, musl, PAM, and no-PAM combinations and running roughly 17,600 deliberate tests. Affected accounts include root, key-only users created without a password, the Alpine user in official tiny-cloud images, and directory-service users via musl-nscd.

The issue has moved from disclosure to active exploitation. Exploitation attempts began on November 5, 2026, the day a proof-of-concept became available, with successful exploitation recorded the following day. Defused observed a small number of actors attempting exploitation over the weekend, and GreyNoise recorded activity. SANS ISC honeypots running Cowrie report an increase in attempts, noting that passwords longer than 255 characters are highly unusual in normal brute-force traffic. The risk concentrates in container, router, and IoT environments built on Alpine, where root and service accounts often have no password hash. OpenSSH 10.6p2, released November 5, contains the fix, and Alpine published fixed packages for every branch from 3.16 to edge the same day. Interim mitigation is to set PasswordAuthentication=no or disable SSH entirely and restart sshd. OpenSSH developer Damien Miller cited recent cases of rapid rediscovery by AI agents as the reason for the short embargo.

What to watch is the rollout of fixed packages across Alpine, OpenWrt, Buildroot, and Yocto, whether additional exploitation campaigns appear before patching completes, and whether organizations discover unauthorized access to accounts that were assumed passwordless. Every musl-based host should be checked for the mitigation and the patch, not only systems explicitly identified as Alpine. Accounts arriving through directory services via musl-nscd deserve particular attention, and honeypot telemetry on long-password attempts remains a useful early signal.
