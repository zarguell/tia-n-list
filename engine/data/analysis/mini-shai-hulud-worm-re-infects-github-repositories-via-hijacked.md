The Mini Shai-Hulud worm is still active. Safedep and Socket both reported on September 24 that the worm persists by reactivating compromised GitHub Actions, using hijacked workflows inside repositories to reinfect them and to reach new victims. Socket's assessment puts the exposure in the thousands of repositories, and Safedep characterizes the campaign as continuing rather than a residue of the original wave.

The reactivation mechanism is what makes this one hard to close out. An organization that removes malicious npm packages or revokes tokens can still be re-exposed if a compromised Actions workflow sits dormant in a repository and is triggered again, so cleanup that stops at dependency manifests leaves the persistence layer in place. This matches the pattern of the earlier Shai-Hulud self-replicating supply chain worm, which spread through trusted maintainer contexts rather than exploits.

Practical steps follow from the mechanism: audit GitHub Actions workflows for unexpected or modified steps, rotate Actions tokens and secrets that were reachable from CI, and treat any repository that was part of the earlier infection wave as still suspect until its workflows are reviewed. Watch for reports of reinfections after maintainer cleanup, which would confirm dormant workflow persistence is the main survival strategy, and for any expansion of the worm's payload behavior beyond the current reproduction pattern.
