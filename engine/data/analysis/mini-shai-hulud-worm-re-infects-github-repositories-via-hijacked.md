The Mini Shai-Hulud re-infection story is about containment that quietly reversed. In the May 2026 campaign, Socket tracked 1,055 compromised package versions across 502 packages on npm, PyPI, and Composer, with 639 malicious npm versions tied to the atool maintainer account, concentrated in @antv packages and echarts-for-react, roughly 1.1 million weekly downloads; SafeDep's analysis of the same wave found 637 malicious versions published across 317 packages in a 22-minute automated burst, including size-sensor, echarts-for-react, and timeago.js. Two GitHub Actions used in the campaign, actions-cool/issues-helper and actions-cool/maintain-one-comment, had all their tags moved to unsigned payload commits on May 18, 2026. GitHub disabled both repositories on May 19. On September 16, 2026, they became downloadable again with the malicious tags untouched, and The Hacker News confirms the two compromised Actions were re-enabled that day and immediately resumed executing malicious code in CI pipelines. GitHub disabled them again on September 25.

The payload is byte-identical to May: a 498KB obfuscated Bun build that harvests CI and developer credentials, exfiltrates RSA-plus-AES encrypted data to t.m-kosche[.]com disguised as OpenTelemetry traces, and installs a kitty-monitor backdoor that skips CI and waits for a developer to open the project through a Claude Code SessionStart hook or VS Code folderOpen task, polling GitHub commit search for RSA-PSS signed commands tagged firedalazer. issues-helper alone has about 15,000 dependent repositories, so workflows calling these actions by tag executed the payload on their next scheduled run. SafeDep confirmed six fresh infections between September 20 and 24, including jd-opensource/micro-app with 6,254 stars, and five of the six triggers were unattended issue bots, meaning the infections repeated on schedule with no attacker present. Socket could not determine who requested the re-enablement.

The operational lesson is that disablement is not remediation. GitHub's block stopped downloads in May but left every malicious tag in place, so one unexplained re-enablement restored the attack with zero new attacker infrastructure. Any project that ran a tag reference on or after September 16 must rotate every secret the workflow could reach. Search all workflows for uses: actions-cool/issues-helper@ and actions-cool/maintain-one-comment@, pin to a clean commit SHA or remove the actions, and audit runner logs for the May pattern of fast failures at Set up job followed by 5 to 11 minute runs after September 16. On endpoints, block t.m-kosche[.]com and check developer machines for the kitty-monitor artifacts. Sequence token rotation before host cleanup, because the payload's wiper fires when the stolen token starts failing.

Two things would move this assessment. Any explanation of the September 16 re-enablement, or a third accessibility flip, would settle whether this was maintainer error or deliberate actor action; the malicious tags remain in both repositories either way. And SafeDep's six-repository victim list is explicitly a floor built from GitHub code search, so new infections surfacing after the September 25 re-disablement would show the exposure is still growing.
