The Mini Shai-Hulud supply-chain worm continues to reinfect GitHub repositories through hijacked Actions. Two previously compromised actions, actions-cool/issues-helper and actions-cool/maintain-one-comment, were re-enabled by their maintainer on September 16 and remained active through September 25 without cleaning malicious release tags. According to Socket researchers, the tags still point to the same commit containing an obfuscated payload inside index.js, meaning any workflow referencing these actions by version tag resumes downloading and executing malware. The original May campaign affected 323 npm packages and 639 versions, stealing developer tokens, credentials, and CI/CD secrets.

The reactivation highlights persistent supply-chain risk when compromised repositories are restored without auditing release tags or removing malicious artifacts. Organizations using GitHub Actions should audit pinned actions for unexpected commit hashes, avoid floating version tags for unmaintained actions, and rotate CI secrets after any dependency update involving these repositories. Monitor Socket and GitHub Security advisories for additional indicators.
