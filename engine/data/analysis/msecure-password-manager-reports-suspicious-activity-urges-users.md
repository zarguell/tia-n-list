mSeven Software, developer of the mSecure password manager, is warning current and former customers to change every stored password, reset two-factor authentication, and remove passkeys after detecting suspicious activity tied to the application. The notice went out on November 3, 2026 and provides minimal technical detail. A subsequent BleepingComputer report says the incident reportedly exposed an encrypted customer database, which is the only concrete artifact available so far; no CVE, no attacker, and no scope of access have been published.

The gap between "suspicious activity" and "encrypted database exposed" is the whole story for a password-manager vendor. An encrypted vault database is not a plaintext breach, but the same database plus the master-password derivation scheme determines whether offline cracking is realistic, and mSeven has not said which. Until that is clarified, the safe assumption for any user is that their vault file is in attacker hands and that weak or reused master passwords are at risk. The remediation advice mSeven did give, rotate everything and re-enroll 2FA and passkeys, is the correct conservative response and implies the company cannot rule out credential reuse.

Watch for a follow-up that states whether the encrypted database was exfiltrated or merely accessed, which KDF and iteration count protected it, and whether the incident was a backend compromise, a third-party integration, or a localized event. The absence of a CVE or regulatory filing so far suggests this has not been reported as a formal breach, but that can change quickly, and password-manager incidents tend to draw follow-on scrutiny from researchers looking for the actual technical cause.
