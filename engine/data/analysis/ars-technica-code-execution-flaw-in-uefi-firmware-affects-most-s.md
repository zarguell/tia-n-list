CVE-2026-97631 is a 16-year-old buffer overflow in the PXE-Base Code driver (`NetworkPkg/UefiPxeBcDxe`) inside TianoCore EDK II, rated CVSS 9.5. The bug lives in ICMP error-handling logic: an incorrect buffer copy lets an attacker corrupt DXE-phase memory during PXE boot over IPv4 or IPv6, yielding arbitrary code execution before the operating system or Secure Boot activates. Ars Technica reported it affects most servers built on this reference firmware, and the GitHub advisory (GHSA-99cj-7hg9-mp4m, published 22 October 2026) notes EDK II master as of 14 September 2026 remains unpatched; the fix PR (#13200) exists but is not yet merged upstream.

The exposure is not theoretical. Because EDK II is the reference codebase used by server, storage, and desktop firmware vendors, a single upstream flaw propagates across the entire server fleet. The event sources list no specific vendor bulletins yet, which means defenders must assume every PXE-boot-capable server in their environment is vulnerable until their OEM publishes a patched BIOS image. The score of 5.0 and velocity of 1.0 reflect broad authority pickup, not niche interest; this is the kind of pre-boot flaw that survives OS reinstalls and undermines every downstream security control.

Defenders should hunt for PXE-boot network telemetry: look for abnormal ICMP error traffic directed at booting hosts, monitor DHCP/PXE server logs for unexpected clients, and inspect firmware version strings against vendor advisories for CVE-2026-97631. Patch when vendors release updated UEFI images incorporating PR #13200; until then, restrict PXE-boot interfaces to isolated VLANs and disable network boot on non-essential systems. Watch for vendor advisories and a merged upstream EDK II release, either of which would change the remediation timeline sharply.
