Two critical vulnerabilities in the miniOrange SAML 2.0 Single Sign-On WordPress plugin (CVE-2026-61979, CVE-2026-15981, CVSS 9.8) let unauthenticated attackers forge SAML assertions and log in as any user, including administrators. The plugin turns WordPress into a SAML service provider for corporate IdPs like Microsoft Entra ID, Okta, and Google Workspace. CVE-2026-61979 is a signature-algorithm confusion flaw: the plugin accepts HMAC-SHA1 from incoming SAML responses, then treats the RSA public key (which is public) as the HMAC secret, allowing an attacker to generate a valid signature. CVE-2026-15981 causes the plugin to interpret an OpenSSL error return (-1) as truthy in PHP, so malformed signatures pass validation.

DigitalOcean's security team detected and blocked an anomalous WordPress admin session attempt on its infrastructure and then reproduced both bypasses on miniOrange Standard edition version 16.1.9. Patchstack coordinated vendor follow-up and expanded its database coverage after finding that the plugin's distribution model (seven plugins, free version with 10,000 downloads, 30,000 paid customers) obscured actual exposure. The vendor fixed the issues in Standard edition version 17.0.5, but Patchstack reported that a blanket "actively exploited" attribution should not flag all CVEs indiscriminately.

Active scanning for these flaws is confirmed. Any WordPress deployment using miniOrange SAML SSO for SSO with corporate IdPs should verify they are on version 17.0.5 or later and review authentication logs for suspicious admin sessions.
