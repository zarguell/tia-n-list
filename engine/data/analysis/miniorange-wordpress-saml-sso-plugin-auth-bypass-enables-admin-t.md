Attackers are actively exploiting two critical authentication bypass vulnerabilities in the miniOrange SAML 2.0 Single Sign On plugin for WordPress (CVE-2026-15981 and CVE-2026-61979). The plugin, built by Xecurify, lets WordPress sites accept logins through corporate identity providers like Microsoft Entra ID, Okta, Google Workspace, or OneLogin. The free version has 10,000 downloads, and the paid tiers cover 30,000 customers. The two CVEs chain together to fully bypass authentication. CVE-2026-61979 forces the plugin to accept HMAC-SHA1 as the signature algorithm instead of the configured RSA, which causes it to treat the identity provider's RSA public key as a shared secret. Since the public key is known, an attacker can forge a valid SAML response signature. CVE-2026-15981 compounds this by treating an OpenSSL verification error (-1) as a success, letting malformed signatures pass validation unchecked.

Both vulnerabilities were disclosed and patched in July, but the vendor advisory appears to have gotten little attention. Attackers are now chaining these flaws to forge SAML responses and gain administrator access to WordPress installations. Patchstack, the security firm tracking the exploitation, notes that the plugin's wide install base across corporate environments makes this a high-value target for initial access campaigns.

The attack requires no authentication. A threat actor crafts a malicious SAML response with a forged signature, sends it to the WordPress SSO endpoint, and the plugin accepts it as legitimate due to the broken signature validation. The result is full admin login, giving attackers control over the site including the ability to install backdoors, modify content, or pivot to other systems in the network. Any WordPress site using the miniOrange SAML SSO plugin should verify they are running the patched version immediately.
