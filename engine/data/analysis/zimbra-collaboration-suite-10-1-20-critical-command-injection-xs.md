CERT Polska issued Alert 145/2026 on August 17, confirming that CVE-2026-73570, an unauthenticated OS command injection vulnerability in Zimbra Collaboration Suite, is being actively exploited in the wild. The flaw resides in the SNMP monitoring path, specifically in the swatchdog service which processes SNMP trap notifications. It affects deployments where the snmp_notify parameter is enabled and the zimbra-snmp functionality is installed. Swatchdog is enabled by default, making many installations vulnerable without explicit configuration.

The vulnerability allows unauthenticated remote attackers to deliver specially crafted SMTP requests that execute arbitrary commands as the zimbra user. Although limited to that account, the impact is severe: the zimbra user has access to mail data, application directories, configuration files, and service processes. An attacker could deploy web shells, harvest credentials, steal mailboxes, or stage lateral movement.

Zimbra released patches in ZCS 10.1.20 alongside fixes for four XSS flaws in the Classic Web Client, a mail forwarding restriction bypass (CVE-2026-50055), an EWS extension access control bug (CVE-2026-10631), and a mailbox delegation authorization issue (CVE-2026-50054). The active exploitation, confirmed by CERT Polska, makes this the highest-priority item in the Zimbra advisory. Administrators should update immediately and disable SNMP notifications if not required.
