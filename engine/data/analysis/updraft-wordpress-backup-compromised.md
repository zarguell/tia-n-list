TeamUpdraft disclosed unauthorized access to teamupdraft.com over the weekend of October 17-18, 2026, with its customer database believed accessed; that database held connection keys for UpdraftCentral, UpdraftVault, and UpdraftClone plus customer account data. Attackers used valid UpdraftCentral keys to send signed remote commands to connected WordPress sites, uploading, activating, and deleting malicious plugins, and because the requests carried trusted keys an UpdraftPlus install that already contained the CVE-2026-10795 fix still accepted them as legitimate instructions. Nethemba first documented the campaign on their own sites and Patchstack confirmed and extended it, reporting 99 distinct backdoor plugin names installed between October 18 15:32 and October 19 09:23 UTC from attacker IP 43.250.53.42, with a second IP 2a09:bac5:4e21:2e3c::49b:9.

The mechanism turns a backup plugin's remote-management channel into a code-execution path: UpdraftCentral client ships in both UpdraftPlus Free and Premium, but only accepts commands when a connection key exists on the site, so the more than 4 million active installations are not all exposed; the vendor's own estimate for the June flaw put fewer than 10 percent of users, roughly 400,000 sites, as holding an UpdraftCentral or Migrator key. The exposure is concentrated on sites connected to TeamUpdraft's cloud-hosted UpdraftCentral, and the risk is higher than a normal plugin bug because signed commands bypassed the earlier CVE-2026-10795 fix entirely rather than exploiting it. The campaign is also still live: stolen keys keep working until the site deletes them, and attackers were observed swapping broken backdoors for working variants hours after initial install.

Defenders should update to UpdraftPlus 1.26.13 or 2.26.13, since 1.26.12 and 2.26.12 ship a broken key-deletion routine that removes nothing, then manually delete any UpdraftCentral Cloud keys created between 12:07 and 21:00 UTC on October 18. Rotate the teamupdraft.com password, re-enable two-factor authentication, audit installed plugins for names like "Load Stack 35C" or "Boost Kit", and check the user list for accounts named "Site Tools" or with addresses at example.org or example.com. Hunt in /var/log/nginx or /var/log/apache2 access logs with grep for class-udrpc.php without a library version in the User-Agent, and run the Nethemba checking script with wp eval-file check-updraftcentral.php using --skip-plugins and --skip-themes. An optional mu-plugin named block-updraftcentral.php in wp-content/mu-plugins can block further UpdraftCentral commands until keys are removed.

The assessment changes if TeamUpdraft confirms broader key exposure beyond the cloud service, if a working vendor-side revocation lands that covers keys created in the full October 18 window, or if follow-on telemetry shows the backdoor variants spreading beyond the initially observed connected sites. Watch for emergency releases beyond 1.26.13 and for any confirmation that self-hosted UpdraftCentral dashboards were affected, which the vendor currently denies.
