Meta's new AI assistant Muse has a zero-day vulnerability that gives locally run apps and terminal commands complete control of the agent. Discovered by macOS security expert Patrick Wardle, the flaw allows any app or terminal command to gain access to the token that authenticates users to their Muse account. Meta developers designed the assistant so that any locally installed app or executed code, regardless of macOS permissions, can change a long list of undocumented settings. Most are innocuous, but one allows changing the endpoint where transcription occurs. Normally this is a Meta server, but attackers can redirect it to their own endpoint and capture the authentication token.

The attack works through a simple ClickFix variation. Wardle demonstrated that a single terminal command can surreptititiously send a prompt to the Meta endpoint, with the attacker's server acting as a proxy between the user and Meta. Once the user enters a voice prompt, the attacker's server adds a malicious command, such as sending an archive of all WhatsApp messages. The attacker then gains permanent control because the token is automatically sent to the malicious server. Wardle developed several proof-of-concept attacks that write malicious files to disk and snap pictures, in many cases with no indication to even alert users.

The vulnerability stems from two design decisions: processing dictation in the cloud (where Meta can log it) rather than on-device using macOS's built-in secure dictation, and allowing any app to control all undocumented settings. Amazon began blocking Muse from its site roughly 12 hours before Wardle's disclosure, calling it an "unauthorized AI agent" that violates Amazon's Conditions of Use. Meta has published two blog posts documenting security design decisions for Muse, but has not responded to questions about this vulnerability. Wardle plans to present further details at the Objective by the Sea security conference in November.
