CVE-2026-109518 is a flaw in APT on Debian, Ubuntu, and derivative distributions that lets an on-path attacker replace a verified package and execute arbitrary code as root. APT can merge two different package downloads after an HTTP redirect gives them the same URI, and improper file handling when resuming an HTTP download lets the attacker substitute content after APT has already verified it. The issue depends on Acquire::Retries being set, which has been the default since APT 2.3.2, and was discovered by Max Justicz. Debian fixed it in DSA-6607-1 (trixie apt 3.0.4) and DLA-4880-1 (bookworm apt 2.6.2), with sid fixed at 3.3.6, while Ubuntu issued USN-8996-1; the Debian advisory also bundles several out-of-bounds access fixes.

The real exposure is not a remote, unauthenticated exploit but the update channel itself: any system that installs or upgrades packages over an untrusted network hands a network-positioned attacker root through a mechanism that defeats APT's signature verification after the fact. Vulnerable versions include apt 2.6.1 on bookworm, 3.0.3 on trixie, and 3.3.5 on forky, so the blast radius spans current stable and testing users plus derivatives. This story matters more than a routine CVE because the primitive turns a trusted package manager into the delivery mechanism for root-level code, and it lands on infrastructure where patching the package manager is itself the remediation path. Systems that cannot easily upgrade apt, such as immutable or offline images and containers built from stale bases, remain exposed even after the advisory, and the bundled out-of-bounds fixes also affect third-party tools that parse .deb files as root, such as PackageKit and aptdaemon.

Administrators should upgrade apt to the fixed versions (trixie 3.0.4, bookworm 2.6.2, sid 3.3.6) or apply USN-8996-1 on Ubuntu, then run apt update and apt upgrade apt. Prefer HTTPS mirrors, and avoid installing or upgrading packages over public or untrusted networks until patched. As an interim mitigation where an immediate upgrade is impossible, set Acquire::Retries to 0, which removes the retry condition the attack depends on but may break scripts that rely on retries. For hunting, verify the installed version with dpkg -l apt, review /var/log/apt/history.log and /var/log/apt/term.log for unexpected installs or upgrades, and check network and proxy logs for unexpected redirects and retries during apt operations; no public indicators of compromise have been published for this flaw.

The assessment changes if a proof of concept or exploitation in the wild appears, since the attack only requires a man-in-the-middle position that is cheap on untrusted networks. It also changes if Max Justicz publishes technical details, which would lower the barrier to exploitation, or if Debian and Ubuntu extend fixes to additional suites and derivatives. Watch for any addition to the KEV catalog or for revised advisories that add workarounds for systems that cannot update apt directly.
