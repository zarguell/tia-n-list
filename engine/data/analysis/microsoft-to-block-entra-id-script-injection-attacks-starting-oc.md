Microsoft will start enforcing a Content Security Policy on Entra ID browser sign-ins in mid-October 2026, with the rollout completing by late October, per message center update MC1481309. The policy allows only scripts served from trusted Microsoft CDN domains during authentication and blocks externally injected code, closing the sign-in page to XSS-style script injection used to steal credentials. The change is enabled by default, requires no tenant configuration, and applies only to browser-based sign-in at login.microsoftonline.com; MSAL and API-based flows are unaffected. Users can still sign in even when injection tools stop working.

This is a Secure Future Initiative deliverable first announced in November 2025, part of the hardening program Microsoft started after Chinese hackers breached Exchange Online mailboxes of dozens of organizations in 2023. It removes a class of credential-harvesting techniques rather than patching a specific exploited flaw, which is why it matters: sign-in pages are the one surface every user in a tenant touches.

Enterprise admins should inventory browser extensions and tooling that inject code or scripts into sign-in pages and retire them before the enforcement date, since those will silently break. Test sign-in scenarios beforehand and check the browser developer console for CSP violations, which appear as red entries naming the blocked scripts. Watch for a second wave of support tickets blamed on the policy, and for attackers shifting from sign-in injection toward device-code and consent phishing, which this change does not touch.
