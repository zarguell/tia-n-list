CVE-2026-21962 is a CVSS 10.0 flaw in the Weblogic Server Proxy Plug-in for Apache HTTP Server and for IIS, the front-end components of Oracle Fusion Middleware, affecting Oracle HTTP Server versions 12.2.1.4.0, 14.1.1.0.0, and 14.1.2.0.0 (the IIS plug-in only at 12.2.1.4.0). Oracle patched it in the January 20, 2026 Critical Patch Update, rating it remotely exploitable over HTTP without authentication. The Cyber Centre recorded a public PoC on January 21, 2026, and CISA added the CVE to the Known Exploited Vulnerabilities catalog on August 24, 2026, confirming exploitation in the wild.

The mechanism deserves more attention than the CVE label suggests. The flaw lives not in WebLogic Server itself but in the proxy plug-ins deployed on separate Apache and IIS web-tier hosts, and Oracle flags changed scope, meaning a compromise at the plug-in layer reaches the additional products those front-ends exist to shield, namely the WebLogic backends behind them. That is the failure mode patch programs miss: teams patch the WebLogic admin and managed servers and overlook the standalone plug-in hosts, which by design sit on the internet-facing tier. The public exploit signal was also noisy from the start, since a GitHub PoC repository for this CVE was publicly accused of shipping fake exploit code on January 22, 2026, yet the August 24 KEV entry settles the exploitation question seven months after the patch. The lesson for the other thirty stories that day is that a dubious PoC and a quiet feed footprint did not mean safe.

Inventory every Apache and IIS host running the WebLogic Server Proxy Plug-in (the mod_wl module on Apache, the iisproxy extension on IIS) and confirm each received the January 2026 CPU or a later patch set for 12.2.1.4.0, 14.1.1.0.0, or 14.1.2.0.0, rather than assuming the WebLogic server patch level covers the tier. Restrict HTTP exposure of front-ends to trusted networks where the business allows it. Hunt in front-end HTTP access logs for unauthenticated request sequences against WebLogic-proxied locations followed by unexpected data creation or modification, since Oracle scores confidentiality and integrity loss at high with no availability impact, and treat any KEV-driven scan spikes against the plug-in endpoints as candidates for review. Federal agencies face BOD 22-01 remediation timelines from the August 24 designation.

Watch for a working public exploit or vendor-exploitation detail replacing the discredited January PoC, which would move this from catalog entry to active campaign, and for further KEV additions or telemetry against sibling vulnerabilities from the January 2026 CPU, since a batch that produced one actively exploited plug-in flaw is a shortlist for attackers.
