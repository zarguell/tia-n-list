PamStealer's Wavel variant shifts from embedded RC4 decryption to a live server-assisted chain: the compiled JXA carrier pipes a base64 zsh dropper into /bin/zsh -s, which downloads pkgunpack from wavel.apple03cloudstore[.]com and performs an X25519 key exchange before the AES-256-GCM payload (SNP1 envelope) can be unwrapped. The second stage, r8afup9un0, is a FAT Mach-O Swift binary (project name MacClient) that validates passwords through PAM using _pam_verify_login, unlocks the login keychain with security unlock-keychain, and targets seventeen browsers including Arc, Zen, Waterfox, LibreWolf, Yandex Browser and Coc Coc, noticeably beyond commodity macOS stealers. Persistence is four-layered: a LaunchAgent labeled com.apple.finder.agent running every 15 seconds, a repair script at ~/Library/Application Support/System/.repair-run backed by .sysnotif-backup.tgz, a ~/.zshrc hook marked # sysnotif-repair, and global Git hooks copied to ~/Library/Application Support/System/.githooks/post-checkout and pre-commit with core.hooksPath redirected there.

The design's defensive implication is that the attacker controls payload availability at decryption time. A fresh ephemeral keypair is generated per execution (ephemeral public keys observed include base64-encoded values like sK2+KZYoZvdLRuLsID7OBopfce4n1fJqjVuML0SEC0Y=) and the server holds the private key required to complete the X25519 exchange; without it, the Data Encryption Key cannot be recovered and static payload recovery fails. Because any routine git checkout or terminal session triggers repair logic, partial cleanup (removing only the LaunchAgent or payload bundle) is insufficient; the malware will restore itself from the local backup tarball without network contact. This makes the infection significantly more durable than single-persistence families and shifts operational control to the server operator, who can disable delivery by taking wavel.apple03cloudstore[.]com offline.

Defenders should hunt for the exact file artifacts and network indicators the events and original Jamf Threat Labs analysis (published September 22, 2026) document: block and inspect traffic to wavel[.]app and wavel.apple03cloudstore[.]com, scan endpoints for Wavel.dmg and /tmp/.pkgunpack-<PID>, inspect ~/Library/LaunchAgents/com.apple.finder.agent.plist, check ~/.zshrc for the # sysnotif-repair marker, verify git config --global --get core.hooksPath points to ~/Library/Application Support/System/.githooks, and search ~/Library/Application Support/System/ for Finder.app (the renamed Wavel.app bundle), .repair-run, and .sysnotif-backup.tgz. The Swift stealer also kills browser helper processes before copying credential databases and collects the user's JPEGPhoto via dscl . -read, so keychain changes and session revocation should be performed from a clean device after full persistence removal.

What would change the assessment: confirmation that the server applies geo or execution-count filtering before responding with the 65-byte SNWK1 DEK wrap blob, or evidence that the payload has been redeployed through a new lure site replacing wavel[.]app. Watch also for additional per-browser helper binaries (KcHelper inside Helper_<Browser>Storage.app) being updated, since the binary resolves these at runtime via NSBundle.mainBundle.bundleURL and launches each with environment variables KC_PASS, KC_STAGING, KC_SERVICE and KC_ACCOUNT to bypass keychain ACL prompts without cross-app authorization.
