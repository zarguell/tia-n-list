Binary Ninja researcher Xusheng Li used AI-assisted reverse engineering (Codex via the Binary Ninja MCP) to break encrypted USB drive products. NetacFileLock protected files with a fixed 32-byte AES-256 key embedded in the executable while checking the user password separately, so anyone can decrypt without the password. The same product also wrote passwords to diagnostic logs, used ECB-style block encryption with no IV, verified passwords with MD5, and used an unkeyed MD5 digest as a file signature; fast mode only encrypted files larger than 1,024 bytes across common formats.

KakaSoft USB Copy Protection 5.6.0.299 was no better. Its "Normal" mode did not encrypt at all, "High" mode XORed at most the first 16,385 bytes with a single byte key (256 possibilities, revealed by known file signatures), and "Highest" mode used Blowfish CBC with an 8-byte salt, 8-byte IV, and a 75-byte trailer stored in a hidden exFAT tree (HPSafeBox). The research shows client-side decryption cannot keep data safe when the attacker controls the machine handling the files.

This is a research and awareness story, not a vulnerability advisory with CVEs. Defenders should treat encrypted USB products as obfuscation rather than protection, and verify any such tool's key derivation and encryption mode before relying on it.
