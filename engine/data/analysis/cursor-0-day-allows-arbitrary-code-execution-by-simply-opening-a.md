A binary-planting vulnerability in the Cursor IDE for Windows, tracked as CVE-2026-63093, allows arbitrary code execution simply by opening a malicious repository. AI security firm Mindgard discovered the flaw in December 2025 and disclosed technical details in July 2026. Cursor resolves Git-related executables during workspace initialization, running commands like `git rev-parse --show-toplevel` to locate Git. On affected Windows configurations, this lookup resolves a `git.exe` placed in the repository root before the legitimate system Git binary. An attacker can distribute a repository containing a malicious `git.exe`, and when a victim opens that folder in Cursor, the planted binary executes under the victim's user privileges with no prompt injection, no AI-agent interaction, and no approval dialog required.

Subsequent research by Maland showed the attack surface extends beyond Git binary resolution. Cursor's executable resolution behavior could also resolve other attacker-controlled executables, including `hatch.exe`, under specific project conditions. The vulnerability targets the fundamental way Cursor discovers and runs local binaries during project load, making the attack vector broader than initially scoped to a single executable name. This matters because the only user action needed is opening an untrusted workspace, a routine operation for any developer working with external code.

The exploit chain is notable for its stealth and low interaction requirement. Unlike prompt injection attacks that target the AI agent layer, CVE-2026-63093 operates at the IDE's native binary resolution level before any AI features engage. Cursor should be updated to a patched version, and organizations should treat untrusted repositories as hostile by isolating them in disposable environments. Until a patch is universally deployed, developers should inspect repository contents before opening them in Cursor on Windows, paying particular attention to executable files at the workspace root.
