ASUS Control Center Express is the central console that IT teams and service providers use to monitor and remotely manage fleets of business PCs, with ASUS listing support for more than 200 business, workstation and Corporate Stable Model motherboards. Version 1.7.29 fixes three critical flaws credited to researcher 0x0dee. CVE-2026-114202 is the maximum-severity case: a hard-coded cryptographic key (CWE-321) rated CVSS 4.0 10.0 with AV:N/AC:L/AT:N/PR:N/UI:N, letting an unauthenticated remote user forge an authentication token and become an administrator. CVE-2026-114204 is a second hard-coded key, scored 9.0 with AT:P/PR:L, which forges a session token for an account with a recent valid login. CVE-2026-114205, scored 9.4, is an authorization flaw that lets a low-privileged authenticated user create an administrator account. CISA's ADP enrichment records exploitation as none for all three, technical impact as total for each, and automatable as yes only for CVE-2026-114202.

The editorial distinction here is not the critical labels but the preconditions, because all three roads end at the same place: administrative control of the console and the clients it manages. Two require a low-privileged account, which turns a compromised seat or an over-permissioned operator into fleet-wide control. CVE-2026-114202 removes that step entirely, needs no user interaction, and is the only one CISA marks automatable, so a reachable console is a single-request path to the remote-management capabilities ASUS markets across those 200-plus board families. That is a different blast radius from a vulnerability in one endpoint agent. With exploitation still rated none on 18 and 19 November 2026, this is a window to close before scanners find it, not an incident already in progress, but the exposure ordering is unforgiving: patch the unauthenticated path first and treat the other two as follow-on privilege escalation.

Inventory Control Center Express installations and compare each build with v1.7.29 before doing anything else. ASUS's bulletin covers versions earlier than v1.7.29, while the CVE affected-product fields stop at through v1.7.27, so v1.7.28 sits in a gap that should be closed by upgrading rather than by arguing about scope. Install v1.7.29, then update client agents on managed devices through Select Function > Client Agent Updater and verify the agent version displayed in the console, as the bulletin instructs; patching the server alone leaves the managed clients on the old agent. Keep the console off general user segments and public reachability until the upgrade is confirmed. For the hunt, enumerate console administrator accounts for additions that nobody authorized, consistent with CVE-2026-114205, and review administrator authentication events for sessions tied to accounts with a recent valid login, the prerequisite named in CVE-2026-114204. The available material names no log path, scanning signature or IoC for this campaign, so collect that evidence from the console itself instead of guessing at indicators.

Two changes would move this assessment: a CISA exploitation change from none to known or a KEV listing, and any telemetry report showing scanning or exploitation attempts against these CVEs. A vendor correction reconciling the v1.7.27 and v1.7.29 affected-version boundary would also change the exposure count. Until then the case rests on an automatable, unauthenticated administrative path in software whose whole purpose is remote control of many machines.
