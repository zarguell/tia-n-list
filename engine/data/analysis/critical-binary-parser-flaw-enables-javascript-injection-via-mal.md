CVE-2026-134814 is a code injection flaw in keichi's Node.js binary-parser library before 2.3.1, scored 9.2 under CVSS v4 and 8.1 under v3.1. String-typed options (length, lengthInBytes, key, tag, offset and the namely() alias) are passed unvalidated through Context.generateOption() and interpolated into parser source at compile time, so anyone who controls a parser definition can run JavaScript in the host Node.js process. The maintainer advisory GHSA-xmxc-6c22-m377 and release 2.3.1 appeared on November 11, before the CVE record on November 22 and the November 23 news item; the finder is Zachariah Mithani.

The headline score overstates reach. Parsing untrusted binary data with a trusted parser definition is explicitly not affected, so the exposed set is services that compile parser definitions from user, partner or external schema input, not every application that reads binary files. The events give no install base, victim count or exploitation telemetry, only the 9.2 and 8.1 scores, the CVE id and 2.3.1 as the fixed version, so sizing this from download numbers would be false precision. This story earns attention over other high scores because it is a repeat failure at the same boundary: 2.3.0 fixed CVE-2026-1245 by validating field names and encodings in the fix reported by Maor Caplan, but left the second set of string options injectable, so a team that patched the January CVE and stopped at 2.3.0 remains exposed.

Upgrade to 2.3.1, the only version named as fixed; 2.3.0 is not sufficient for this issue. Treat any path that turns a schema or JSON document into parser options as untrusted input, and check every call that feeds length, lengthInBytes, key, tag, offset or namely() aliases from outside the codebase. The upgrade is a breaking change: 2.3.1 accepts only identifier paths such as foo or $parent.len, rejects expressions such as len - 1 at compile time, and requires a function instead. Network filtering does not interrupt compilation of a malicious definition, and the reporting names no ports, log paths or IoCs, so the hunt is code-level: search for Context.generateOption() call sites and generated parser source assembled from non-static strings.

Watch for downstream advisories from projects that bundle binary-parser and for a published exploit or telemetry report; neither appears in the events, and there is no observed exploitation claim to rely on, so one credible sighting would move this from patch-and-audit to incident response. Also watch for operators discovering they stopped at 2.3.0 after the CVE-2026-1245 advisory, because that residual population, rather than the 9.2 score, is where the real exposure sits.
