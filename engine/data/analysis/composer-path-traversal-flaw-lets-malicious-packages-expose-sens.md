A path-traversal vulnerability in Composer, the PHP package manager, allows malicious or compromised packages to change file permissions outside their own installation directory. Tracked as CVE-2026-59944 and GHSA-96h3-5x6v-m776, the flaw affects Composer versions 2.3.0 through 2.10.2 and versions 1.0 through 2.2.29. Patches are available in versions 2.10.3 and 2.2.30.

The vulnerability is rated Moderate with a CVSS v3.1 score based on the vector AV:L/AC:L/PR:N/UI:R/S:U/C:H/I:L/A:N. It is classified under CWE-22 (path traversal), CWE-59 (improper link resolution), and CWE-732 (incorrect permission assignment for critical resources). Composer packages can declare executable binaries made available through the vendor/bin directory. A malicious package could provide a binary path that escapes its package directory or use a symbolic link resolving to a file outside that directory. During installation, Composer may change permissions on the target file and create a runnable vendor/bin command pointing to it.

If the external target file is normally readable only by its owner but remains modifiable by the Composer process, the flaw could make it world-readable and executable. This creates a confidentiality risk on shared and multi-tenant systems, where other users could read previously restricted files. The issue does not enable remote code execution or direct file overwrite. Organizations using Composer in shared hosting environments should update immediately.
