    Red Hat has disclosed a critical privilege-escalation vulnerability in Red Hat Advanced Cluster Management for Kubernetes (ACM) that could allow a user with limited namespace-level editing permissions to obtain full cluster-admin access across a Kubernetes environment. Tracked as CVE-2026-10090, the vulnerability affects the Application Subscription controller, also known as multicluster-operators-subscription . Red Hat assigned the issue an Important severity rating and a CVSS v3.1 score of 9.9 out of 10. The flaw was made public on August 5, 2026. Red Hat ACM Flaw The issue is especially significant because it violates a core Kubernetes authorization boundary: the separation between permissions granted within a namespace and permissions that apply across the entire cluster. In a vulnerable ACM hub, an attacker does not need pre-existing cluster-wide administrative rights. Namespace-scoped edit access in an ACM hub namespace is sufficient. The vulnerable workflow involves ACM’s Channel and Subscription custom resources. A user with namespace-level edit privileges can create a Channel resource that points to a Helm repository under their control. They can then create a Subscription resource referencing that Channel. The Application Subscription controller retrieves the Helm chart and applies its content using the controller’s own elevated permissions. This vulnerability is tracked as CVE-2026-10090 and affects the Application Subscription controller, specifically the multicluster-operators-subscription. It has a CVSS v3.1 score of 9.9 out of 10. Red Hat Kubernetes Flaw The issue arises from an authorisation gap in ACM’s application-subscription workflow. A user with namespace-scoped edit permissions in an ACM hub namespace can create a Channel object that points to an attacker-controlled Helm repository. They can then create a Subscription that refers to that Channel. The vulnerable controller retrieves and deploys the chart using its own elevated permissions. Importantly, the controller does not verify whether the creator of the Subscription has the open-cluster-management:subscription-admin role, nor does it enforce the proper namespace boundaries on resources delivered through the Helm chart. This creates a “confused deputy” problem: a user with delegated namespace rights can cause a privileged controller to perform cluster-wide actions on their behalf.
