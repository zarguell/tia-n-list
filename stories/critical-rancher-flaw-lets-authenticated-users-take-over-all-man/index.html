    Critical Rancher Flaw Lets Authenticated Users Take Over All Managed Kubernetes Clusters

    cyberpress.org · 9h ago · August 11th, 2026

    SUSE has fixed a critical privilege-escalation vulnerability in Rancher that could allow a low-privileged authenticated user to seize administrative control of the Rancher management plane and every downstream Kubernetes cluster it manages. Tracked as CVE-2026-44945 and GitHub advisory GHSA-v584-7w32-jwpq, the issue carries a CVSS v3.1 score of 9.1 and is classified as CWE-441, or an unintended proxy/confused-deputy weakness. The flaw resides in Rancher’s impersonation middleware , specifically pkg/auth/requests/impersonate.go . Rancher supports Kubernetes API impersonation by processing headers such as Impersonate-User , Impersonate-Group , and Impersonate-Extra-* . Critical Rancher Flaw However, the vulnerable implementation checked authorization in one Kubernetes cluster while ultimately sending the request to another: Rancher’s local management cluster. This creates a cross-cluster authorization mismatch. When a request arrived, Rancher parsed a cluster identifier from the URL and performed a Kubernetes SubjectAccessReview (SAR) against that specified downstream cluster. The request was then handled by Rancher’s management API, which uses the privileged scaledContext service account to operate against the local Rancher cluster. The Norman proxy store forwarded impersonation headers to that local Kubernetes API.
